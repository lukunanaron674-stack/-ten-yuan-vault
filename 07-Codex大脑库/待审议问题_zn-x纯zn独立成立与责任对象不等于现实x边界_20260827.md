# 待审议｜pure `zn` 独立成立与责任对象不等于现实 `x` 边界

## 1｜问题

当前火轴已经出现 3 部独立作品、同一 criterion 下的 pure-`zn` 高纯控制：

1. 《水浒传》鲁智深·野猪林救林冲，99/97；
2. 《红楼梦》鸳鸯·贾赦强纳压力下持续拒绝并公开誓绝，99/96；
3. 《三国演义》刘备·携民渡江，在追兵和军事效率压力下持续拒绝弃民，99/96。

三案均满足：`zn` 独立通过内部原则、无奖励、冲突排序、未来调用与让渡代价门；同一被测对象层的 `x` 不独立过门。

现已新增第一份反向护栏：《水浒传》杨志押送生辰纲，99/98。该案表面具有高责任、强执行与高代价，但外部委任、功名/恩遇与失职后果足以解释当前行为；拿掉这些外因后，缺少同一责任原则跨情境保留未来指导资格的证据，因此不得锁 pure `zn`。

本文件只提出 L4 待审议命题，不修改 L2 canonical。

## 2｜三份控制的共同结构

```text
明确内部原则
→ 外部奖励/认可不是必要来源
→ 现实利益或安全与原则发生冲突
→ 原则仍进入最终排序
→ 原则跨多个压力窗口继续可调用
→ 同一被保护/被拒绝/被负责对象并未因此自动进入主体现实掌握 x
```

共同候选命题：

> **pure `zn` 可以在没有同对象层现实 `x` 的情况下独立成立。原则可以规定“我必须怎样对待某人/某关系/某群体”，但被保护、被负责、被拒绝进入的对象，不因此自动成为“归我占有、调用、处分或排除”的 `x`。**

反向护栏同时要求：

> **承担责任、执行强硬、愿意付出代价，本身不是 `zn`。若高强度行为主要由外部委任、职业收益、恩遇、问责、惩罚或即时策略解释，而拿掉这些外因后缺少同一原则跨情境的未来指导资格，应判伪 pure-`zn`。**

## 3｜三种不同正向机制

### A｜鲁智深：他者救护 / 关系责任原则

- 受害者处于持续危险；
- 主体认为既然承担救援，就不能只做一次性表面动作；
- 无奖励、有个人风险仍继续护送；
- “保护林冲”不等于“林冲归鲁智深掌握”。

### B｜鸳鸯：主体自我决定边界

- 外部权势试图替主体规定婚姻关系；
- 利益、家族压力与现实威胁均不能换取原则撤回；
- 原则扩展到未来婚配窗口；
- “我绝不接受强纳”不等于“现实婚姻关系已经进入我的稳定处分 x”。

### C｜刘备：领导 / 公共责任原则

- 百姓自愿相随并形成现实托付；
- 更快撤退、更高生存概率与原则直接冲突；
- 多次有人建议弃民，主体仍拒绝；
- “我不能为了自己先走而抛下他们”不等于“这些百姓归我掌握或处分”。

三案分别覆盖：个人救护责任、自我决定边界、群体领导责任。

## 4｜候选边界

### 4.1 pure `zn` 的最低门

要计 pure-`zn`：

1. 原则命题或意义对象明确；
2. 无奖励、认可与观看仍进入判断；
3. 与利益、安全、身份收益或现实便利冲突时仍影响最终排序；
4. 在后续压力窗口继续保有未来调用资格；
5. 有可观察的边界或让渡代价；
6. 同一被测对象层的 `x` 不独立过门。

### 4.2 责任对象不自动是 `x`

以下事实均不足以单独证明 `x`：

- “我必须保护你”；
- “我不能抛下你”；
- “我拒绝进入这段关系”；
- “你把安全托付给我”；
- “我对你负有道德/关系责任”。

`x` 仍须另证对象进入主体实际占有、调用、调配、处分、否决或排除边界。

### 4.3 拒绝关系也不自动是 `x`

主体对一段关系拥有内部最终拒绝原则，只证明 `zn` 候选；若现实社会关系仍受外部高位节点、制度或他人否决控制，不能把内部原则偷换成现实 `x`。

### 4.4 高责任执行不自动是 `zn`

以下表现都只能作为候选显影，不能直接锁 `zn`：

- 受命后极度尽责；
- 为任务承担风险或代价；
- 害怕失败并高强度控制流程；
- 因恩遇、职业上升、身份收益而加码投入；
- 因问责、惩罚、羞耻或失职后果而不敢松懈。

必须继续执行拿掉门：去掉委任、奖励/认可、制度责任与惩罚后，同一原则是否仍进入判断并保留未来调用资格。

## 5｜反向护栏

### N1｜杨志押送生辰纲：高责任执行 ≠ pure `zn`

- 外部委任明确；
- 当前职业上升、提携恩遇与报答关系明确；
- 任务失败带来强现实后果；
- 杨志确实高强度设计、催行、约束队伍，行为很“负责”；
- 但拿掉外部任务、功名/恩遇与失职压力后，缺少另一个独立情境证明“受托财物必须不计代价护到底”仍作为不可让渡原则重复调用。

因此：

```text
外部任务 + 身份收益/恩遇 + 问责压力
→ 高责任执行
≠
内部 zn 已独立成立
```

该护栏只增加 negative guard，不增加 positive 或 positive cross-work。

## 6｜与 strict `zn↔x` 的隔离

pure-`zn` 只说明 `zn=true` 且同对象层 `x=false/not locked`。

它不能用来证明：

- `zn+x` co-occurrence；
- `zn→x` 单向补；
- `x→zn` 落点补；
- strict `zn↔x` complement。

strict 仍必须按 `zn补x_补卡_v0.1` 独立做双向拿掉。
