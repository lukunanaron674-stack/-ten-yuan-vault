# 运行记录｜孙悟空借四海龙王施雨失败后退出旧 nx 通道窗口控制

## 0｜本轮问题

上一轮已锁定：主体把当前问题真实接到外部已有关系、权限或解决通道上，并实际沿其继续，即可形成 nx 行为功能。

本轮继续压一个更窄的问题：

> 主体已经主动接入一个外部方案并真实执行，但该方案被现实证明不能解决当前瓶颈；主体随后停止沿该方案推进，转入另一条解决通道。旧 nx 是否只能锁在它真实有效的执行窗口，而不能污染后续？

结论：是，99/98。

## 1｜剧情事实

红孩儿以三昧真火阻断孙悟空正面救师。孙悟空明确判断“水能克火”，主动前往东洋水晶宫，请东海龙王帮助降雨灭火。

龙王说明正式行雨本有玉帝与风云雷电等制度限制，但在孙悟空只需水力的条件下，提出召集其余三海龙王共同助力。孙悟空接受该解决路线，要求撞钟击鼓召集三海龙王。

四海龙王到齐后，孙悟空不是只取得信息，而是实际把他们接进战斗流程：他让龙王停在空中，自己继续与红孩儿交战，并明确规定“妖怪放火时，听我呼唤，一齐喷雨”。

红孩儿再次放火，孙悟空呼叫龙王，四海龙王真实执行降雨。但雨水不能扑灭三昧真火，反而使火势更盛。孙悟空继续尝试后又被烟火重创。

到第四十二回，孙悟空向观音复述这一失败链，明确说明“请到四海龙王，施雨水，又不能胜火”。随后当前解决通道转向观音。

因此时间切片应写成：

```text
A｜自身直接路径受阻
救师最高方向仍由孙悟空维持
= zx方向端

B｜主动接入四海龙王
请求 → 接受龙王方案 → 现场调用 → 龙王真实施雨
= nx真实激活

C｜现实验证失败
龙王雨不能灭三昧真火
= 旧解决通道对当前瓶颈失效

D｜退出旧通道
不再继续把“龙王施雨”作为当前执行路线
→ 转入观音解决接口
= 旧nx执行窗口结束
```

## 2｜zx 判断

本轮不重锁人物稳定 zx 本体，只锁当前最高方向端：

- 救唐僧与突破红孩儿的最高方向并非龙王生成；
- 龙王方案失败以后，孙悟空没有放弃最高目标；
- 他只是更换解决通道。

因此：

`zx_current_direction_stage: evidence-locked`

但“方向仍由自己维持”不能把龙王施雨阶段的 nx 抹掉，因为具体灭火能力确实在外部。

## 3｜nx 判断

龙王施雨阶段满足 nx v2.5：

1. 当前直接灭火能力不在孙悟空稳定调用边界；
2. 孙悟空主动进入龙王既有权限/能力网络；
3. 明确提出请求；
4. 接受龙王提出的四海协同路线；
5. 实际把该路线接入现场执行；
6. 龙王按约定在孙悟空呼叫后真实施雨。

所以：

```yaml
nx_dragon_route_behavior_function: evidence-locked
nx_dragon_route_relation_position: evidence-locked
subject_requests_external_help: true
subject_accepts_external_solution_route: true
subject_executes_external_route: true
```

这里不是“孙悟空整体没主见”，而是强主体在一个具体瓶颈上真实调用外部现成能力接口。

## 4｜核心新增：nx 不是一次激活后永久粘住

真正新增的边界发生在方案失败之后。

当四海龙王的雨被事实证明不能扑灭三昧真火时，继续写：

```text
孙悟空后面仍在沿龙王通道推进
```

就已经不符合事实。

后续的当前执行路线改为：

```text
观音专属法力 / 收伏权限接口
```

因此正式锁：

`nx_dragon_route_after_failure: rejected_as_current_execution_route`

最窄纪律：

> **nx 必须按当前实际续接的通道判。曾经请求、曾经接受、甚至曾经真实执行某个外部方案，都不能让该 nx 通道永久覆盖后续阶段。**

> **若现实已经证明该通道对目标瓶颈失效，而主体停止沿其推进并转用另一通道，则旧 nx 的执行窗口结束。**

## 5｜最近邻排除

### nx vs xn

孙悟空会设定“我交战、你们等我呼叫再降雨”的局部协同，但决定性的灭火资源与行雨能力仍来自四海龙王这一已有外部接口。

本窄请求/调用层仍以 nx 为主，不因为有现场配合安排就升级为 xn。

### nx vs x

龙王水权和降雨能力并未成为孙悟空可长期独立处分的资源，因此不是 x 内化。

### nx vs zx

孙悟空保留救师最高方向，不影响“具体解决能力外置”形成 nx。反过来，龙王方案失败也没有消灭孙悟空的 zx 方向。

### 当前 nx vs 历史 nx

本轮最重要：

```text
历史上用过某接口
≠
当前仍沿该接口推进
```

必须按时间窗口重新切片。

## 6｜拿掉测试

### 拿掉龙王 nx

孙悟空救师最高方向仍存在，但第二次对三昧真火的“外部水力灭火尝试”消失，因此龙王 nx 在 B 窗口是真实功能，不是装饰。

### 拿掉方案失败事实

如果龙王施雨能够稳定扑灭三昧真火，且孙悟空后续继续围绕龙王水力推进，则该 nx 窗口应继续，不能提前判退出。

### 拿掉后续转观音

即使不考虑观音，只要文本已经证明龙王雨无效，而孙悟空不再继续调用这条路线，就足以锁“旧 nx 执行窗口结束”。

观音只把新的通道替换显示得更清楚。

## 7｜反向测试

### nx 持续版本

```text
主动请龙王
→ 龙王施雨有效
→ 主体继续依赖龙王水力推进
→ 当前仍沿同一外部通道
= nx继续
```

### nx 退出版本（原文）

```text
主动请龙王
→ 接受并实际执行
→ 现实证明方案无效
→ 不再沿该路线推进
→ 转入新的外部解决接口
= 旧nx执行窗口结束
```

### 只是“换方法”但仍同一外部通道

若主体只是让同一龙王改用另一种仍由龙王掌握的有效能力，则应继续检查是否仍属于同一个 nx 关系通道，而不能机械地把“方案变化”写成 nx 退出。

因此真正门槛是：

> **当前是否仍沿原外部权限/能力接口续接。**

## 8｜第三因素冻结

冻结：

- 孙悟空主角身份与稳定人物标签；
- 龙王与孙悟空旧交；
- 三昧真火的神话设定趣味；
- 最后观音是否成功；
- 取经终局。

只保留：

1. 主体是否主动接入外部通道；
2. 是否接受并真实执行；
3. 该通道是否被当前现实验证为有效；
4. 失败后主体是否仍沿原通道推进；
5. 是否切换到新的解决接口。

结论仍稳定为 99/98。

## 9｜结论

本轮最窄可靠纪律：

> **“接入外部通道”与“当前仍沿该通道续接”必须分开。**

> **nx 可以在一个明确执行窗口内高纯成立；当原外部通道已被现实证明无效，主体停止续接并转入新路线时，旧 nx 不应继续覆盖后续阶段。**

这不是人物换芯，也不否定孙悟空在观音阶段重新出现新的 nx；它只是要求每一个 nx 都追踪到具体、当前、仍被实际使用的外部通道。

本轮不修改 L1、zx/nx 信息卡、准度卡或补卡；也不新增 pending-review，因为目前是《西游记》内部的高纯时间切片控制，等待跨作品最小差异复验。
