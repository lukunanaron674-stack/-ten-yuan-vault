# 待审议｜zx↔nx 严格补：对象层一致性

## 1｜仍然成立的边界

跨三部作品的反向控制仍然有效：

- 《水浒传》林冲：早期“我如何入梁山”的 nx，与后期“谁决定寨主/准入结构”的 zx 不是同一对象层。
- 《西游记》孙悟空：弼马温职务承接 nx，与后续身份等级/凌驾位置 zx 不是同一对象层。
- 《三国演义》曹操：七星刀秘密刺董资源 nx，与陈留公开起兵 zx 不是同一现实变量。

因此继续保留：

> **时间连续、因果连续、人物连续，都不能替代同一对象层/同一现实瓶颈。**

## 2｜旧“正向严格补”控制已撤回

此前用于反证“对象名必须相同”的两个正向严格补控制：

- 宋江高唐州；
- 曹操陈留借卫弘家资；

均已按 2026-08-26 新双向拿掉门降为 `nx→zx` 单向补缺。

原因相同：旧记录把“没有主体 zx，外部资源/能力不会自动生成共同结果”当成 `zx→nx` 缺口；新规则要求反向缺口必须打到 `nx` 自身核心功能，而不是共同结果缺少行动/触发端。

所以当前：

```yaml
verified_strict_positive_control_count: 0
```

这意味着“对象标签不同但仍能构成真严格补”目前**没有已复验高纯正例**，不能继续当作已锁结论。

## 3｜旧严格补时间窗口统计归零

此前保留的：

- 宋江高唐州；
- 孙悟空红孩儿；

也已按新门槛重审为 `nx→zx` 单向补，只保留“nx 当前窗口会随任务/瓶颈结束而关闭”的动态观察。

因此：

```yaml
verified_strict_temporal_window_control_count: 0
```

时间窗口纪律仍有价值，但现在应归入：

> **nx 当前执行窗口 / 单向补完成后的接口退出**

而不是“严格补闭环”。

## 4｜当前可保留的对象层方法

严格补尚未找到新门槛下的高纯正例，但以下方法仍可靠：

1. 两端必须先独立成立；
2. 两端必须指向同一当前现实瓶颈；
3. 对象名称是否同名不是充分条件；
4. “同一个大结果”也不是同一瓶颈的充分证据；
5. 拿掉 nx 后必须打到 zx 自身缺口；
6. 拿掉 zx 后必须打到 nx 自身核心功能缺口；
7. 反向缺口不能只是“没有人调用/触发/兑换 nx”。

## 5｜下一步

暂停继续积累“看起来双方合作得很紧”的严格补候选。

优先寻找：

```text
zx 与 nx 各自独立成立
+
同一现实瓶颈
+
nx→zx 核心缺口成立
+
zx→nx 也确实损伤 nx 自身核心功能
+
第三因素冻结后仍然成立
```

在出现高纯正例以前，本文件继续保持 pending-review，不修改任何正本。
