# 待审议｜zn-x x scope：权限类型、范围、期限与最终归属必须分层

## 0｜候选命题

同一 `x` 不能只用一个粗糙的 `true/false` 描述。

当前 3 部独立作品、4 个高置信正向控制共同支持：

> **`x` 必须至少写清：被测对象、权限类型、权限范围、期限/返还义务、原节点是否保留覆盖/撤回权、最终裁定层。某一窄 scope 的现实 `x=true`，不能自动倒灌为邻近更宽 scope 的 `x=true`。**

当前另有 16 条、13 部独立作品的高置信反向边界护栏共同支持：

> **更宽 scope / 永久最终归属未成立，也不能反向把已经直接生效的窄 current `x` 抹成 `x=false`。formal/source authority、单次现实 compliance、接口持有、作品原生 ownership 标签、稳定 possession/use 或成功启动过程，都不能跨 permission type 自动升级成 stable current control / full disposition / verified target disposition。**

另有 8 条、6 部独立作品的高置信动态迁移控制支持：

> **`x` 的生命周期不只有 off→on / on→off。它可以发生 scope expansion / contraction、permission-type expansion、single gate → parallel independent gates、joint-threshold → delegated unilateral execution，以及 external override insertion。迁移后部分低层 current `x` 可以继续保留。**

核心结构门继续保持：

- future whole-block revocation ≠ same-layer pre-effect veto；
- source decision structure ≠ consultation structure ≠ final decision structure ≠ current execution structure；
- shared permission ≠ joint-threshold；
- hierarchical superiority ≠ permission-type universality；
- formal/source authority ≠ current realized x；
- one-shot successful invocation ≠ stable current x；
- control-interface possession ≠ verified target disposition；
- source-native ownership/title/status label ≠ 十元 x permission bundle。

本文件只到 L4 `pending-review`，不得覆盖 current canonical。

## 3｜decision-structure 判据校准｜1 control｜不计 ordinary works

多数/固定 k-of-n 等结构中，individual same-layer veto 是 genuine joint 的充分证据之一，但不是必要条件。只要 final result 必须跨越预先存在的 mandatory multi-node approval threshold，且任何单一主体都不能独立让同一 final decision 生效，即可支持 `joint-threshold`。

因此：`absence of individual veto ≠ unilateral`；`joint-unanimous ≠ joint-threshold ≠ unilateral`。

## 6｜统一测试协议

1. 窄 scope 拿掉：拿掉后相关当前行为不再可能直接生效，说明该窄 scope 有现实作用。
2. 宽 scope 反向门：升级更宽 `x` 时另证原节点是否退出、上位是否仍可同层覆盖、期限/返还条件是否跨越、局部决定是否扩展到最终裁定。
3. future revocation 不是 current x 反证；重点查 same-layer pre-effect veto。
4. shared/joint → unilateral 必须证明同层节点不保留 mandatory co-approval / blocking threshold。
5. 共同授权或广泛咨询不得预设最终裁决和执行结构。
6. 多个 co-holder 若任一可独立生效，不得写成 joint-threshold。
7. 广域 senior-command 不得跨 permission type 倒灌特殊对象层 unilateral final-disposition。
8. 正式授权/签署文件只证明 source layer；必须继续观察被测 current permission 调用时现实节点是否响应。
9. 一次成功 compliance 只锁该次 local act；同窗 competing anchor 仍持续控制相同 execution node 时，不得升级 stable command x。
10. 持有可操作接口只锁 contact/use opportunity；目标处分权需另证 causal mapping，且 local mapping 与 global override 分账。
11. possession/use 与 destruction-disposition 分账；对象在手不自动证明不可逆销毁处分权。
12. process lifecycle permissions 分账；invoke/start 不自动推出 stop/terminate/revoke/veto。
13. 作品原生 owner/title/status 词不得直接替代十元 x 判定；先逐项验证 current permission bundle。
14. scope / permission expansion：不能把迁移前窄 `x` 写成 `x=false`，也不能把迁移后宽 `x` 倒填到迁移前。
15. scope contraction：迁移后高层 scope 上移/外置时，继续逐层检查低层 current `x` 是否保留。
16. 当前 dynamic `8 controls / 6 works`，停止普通扩张/收缩堆量。

禁止倒灌：

```text

拿着印信 → 代表权力

作品称 owner → 所有十元 x 权限自动为真
作品称 non-owner → 所有十元 x 权限自动为假
共享治理 → 个人单方最终处分
共同授权 → 后续必须逐项共同执行
广泛咨询 → shared/joint final decision
多人持有同类权限 → mandatory joint approval
最高层级/广域 command → 特殊对象层 unilateral final-disposition
正式授权/签署文件 → current realized control
一次命令执行成功 → stable organizational command x
拿到控制接口 + 敌对方声称映射 → verified target-disposition x
迁移后宽 x → 迁移前已经拥有同样宽 x
```

## 8｜下一步高信息增益

1. **permission-type 动态镜像**：同一对象上 `possession/use x=true` 但 `irreversible disposition=false` 的约束节点被解除后，是否首次形成真实 disposition；或 `start=true/stop=false` 后获得 termination permission。

5. **真正 decision-structure 迁移**：`unilateral -> mandatory threshold/joint` 或共同 gate 被撤销后的反向迁移。
