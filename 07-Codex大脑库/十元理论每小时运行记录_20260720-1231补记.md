## 源端点、目标端点与变量

### 源端点 x

主体实际掌握：

- 对象或作品载体；
- 署名、所有权、推荐权；
- 引见关系；
- 发布与传播通道；
- 进入认可场景的权限；
- 对象归因与解释界面。

### 目标端点 z

必须明确：

- 认可主体是谁；
- 被认可的是能力、作品、身份、选择、发现或精神存在中的哪一项；
- 为什么该认可位置重要。

### 被改变变量

- 认可主体接触目标对象的概率；
- 对象能否正确归因给真正主体；
- 主体能否进入重要认可位置；
- 回应与确认能否发生；
- 确认是否被他人冒领或替换。

### 成立阶段与体量

- 看见前门控：控制推荐、展示、传播、进入；
- 看见后归因劫持：控制署名、所有权和作者身份；
- 回应隔离：认可者已有回应可能，但确认无法返回主体；
- 低体量为一次推荐或署名被扣；
- 中体量为持续控制展示与归因；
- 高体量为长期垄断完整认可环境。

## 候选机制

### A：认可入口门控

```text
x掌握进入重要认可场景的权限或关系
→ 不引见、不推荐、不展示、不转交
→ 认可主体看不到z主体或其对象
→ 确认关系无法成立
```

理论后果：改变“能否被认可主体接触”。

### B：归因与署名劫持

```text
作品或能力已经进入公共界面
→ x掌握署名、所有权或解释权
→ 对象被归给自己或第三人
→ 认可发生但不落到真正主体
→ z被克制
```

理论后果：无需阻止对象出现，只需控制“这是谁的”。

### 排除机制：一般资源封锁

```text
不给钱、设备或场地
→ 项目无法完成
```

若没有认可主体、认可对象和确认接口，只能证明x控制生产条件，不能充分证明x克z。

### 正式统一机制

> x掌握认可关系所依赖的入口与归因界面，使看见、回应或正确确认无法落到z主体。

## 正例

### 《大眼睛》玛格丽特与沃尔特·基恩

- x源端点：沃尔特掌握画作销售、署名和作者身份叙述；
- z目标端点：玛格丽特希望公众、买家和艺术界确认她的创作能力与作品；
- 结果：作品被看见和认可，但作者身份被错误归因给沃尔特。

这是归因与署名劫持的高纯人物案例。

### 《寻梦环游记》赫克托与埃内斯托

- x源端点：埃内斯托掌握歌曲公开归属、传播和明星身份界面；
- z目标端点：赫克托的创作应被家人、公众和历史正确确认；
- 结果：歌曲获得认可，但认可长期错误归给埃内斯托。

本例混有暴力与x并z明星壳，但x克z的目标变量仍独立清楚。

### 编辑扣署名结构例

编辑掌握终审、发表与署名，将真实作者改成“资料协助”，主署名给负责人。拿掉署名控制，认可立即可正确归因。

## 反例

1. 设备被扣导致作品未完成：没有认可主体与确认对象，只是生产条件受控。
2. 作品公开后观众不喜欢：看见与正确归因已发生，只是负面回应。
3. 平台算法自然降低曝光：若无明确主体掌握并针对性关闭接口，更接近xn系统流程。
4. 导师公开批评学生：若核心是公开压制，优先检查zx。
5. 本人拖延未投稿：认可接口可用，失败来自主体未进入接口。

## 最近邻排除

- 与zx克z：公开压制、羞辱、以权威姿态否定主体，改变的是权能与回应位置；x克z强调谁掌握接口、署名与归因。
- 与xn克z：流程、规则和算法系统性限制展示，改变的是运行结构；x克z要求具体掌握边界。
- 与x并z克z：身份壳使认可对象被错误读取时，要检查壳本身是否是直接作用源；x克z强调谁控制壳、署名或入口。
- 与普通失败：项目没完成、观众不喜欢或主体未投稿，都不足以构成确认接口被掌握。

## 拿掉测试

1. 拿掉x主体对入口、署名或归因的掌握，认可能否正确发生？两个人物案例均会恢复。
2. 拿掉认可主体与认可对象，只剩资源控制，z目标端点消失。
3. 拿掉暴力与公开压制，署名和归因劫持仍成立，支持x直接作用。
4. 拿掉错误归因，作品即使仍被看见，真正主体能获得确认，克制消失。
5. 拿掉作品正面评价，只保留正确署名与明确回应，z仍可能成立；说明关键不是赞美，而是正确确认。

## 反向测试

交换为：

```text
z克x
```

被看见与认可本身不必然缩小掌握边界。认可者可能确认主体，却不改变署名权、发布权、对象归属或接口控制。因此反向不能解释本轮案例，方向未写反。

## 动态链后果

```text
我的作品或存在本可进入重要认可位置
→ 入口、署名或归因被他者掌握
→ 世界可能看见对象
→ 却看不见“这是我的”
```

改变的是认可关系的可达性与正确归因，不机械生成作品失败、主体无价值、公众敌意、永久沉默或人物稳定本体变化。
