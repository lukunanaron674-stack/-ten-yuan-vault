# 生克补关系语义验收协议 v0.1

> 本协议不新增生克补位置，也不替任何未确认关系编写漂亮解释。它只规定：旧几何位置怎样重新获得当前语义资格。

## 1. 使用前提

关系验收只能在以下条件同时满足后开始：

```text
两个端点均完成十元点位审核
+ 人物本体、状态、行为、场景、时间、视觉已拆开
+ 两个端点均达到 A 级
+ 关系没有被题材词、角色职业或结局反推
```

任一端点为 B 或 C 时，只能记录候选关系，不得写成正式生克补结论。

## 2. 几何位置与内容语义分离

```text
标准位置盘：保留“哪两个位置相连”的几何事实。
内容语义：重新证明这两个当前定义下的十元为何构成生、克或补。
```

旧库已有位置，不等于旧解释继续有效。

若端点定义已经升级，例如 zx、xn、nx，必须按当前信息量卡重做语义验收；不得因为旧案例数量多，就让旧口径反过来压住新正本。

## 3. 三类关系的最小验收问题

### 3.1 生

必须证明：

```text
A 的稳定运行会结构性推出 B，
而不只是 A 之后碰巧出现 B。
```

至少回答：

- 没有 A，B 是否仍会以相同方式出现？
- A 推出的究竟是 B 的人物本体、状态、行为，还是外部场景？
- 推出过程是否跨两个以上案例重复成立？

### 3.2 克

必须证明：

```text
A 持续压缩 B 的成立条件、行动路径、显影空间或方向，
迫使 B 降低、转向、延迟或改用别的结构继续。
```

“发生冲突”“角色讨厌另一个角色”“画面形成反差”均不足以证明克。

### 3.3 补

必须证明：

```text
A 与 B 分别保留对方单独运行时缺失的一极，
二者合在一起后，结构更完整且能跨压力继续成立。
```

“性格相反”“两人关系亲密”“轮流做事”均不足以证明补。

## 4. 对象层不得混接

关系两端必须标明对象层：

```text
人物本体 ↔ 人物本体
人物本体 ↔ 外部时间结构
人物状态 ↔ 人物状态
行为功能 ↔ 行为功能
场景 ↔ 人物状态
```

不同对象层可以发生关系，但不能省略层级。

例如：

```text
五行山：外部高体量时间结构 xn
孙悟空：人物稳定本体中的 zx
关系：外部 xn 克人物本体 zx 的当下行动路径
结果：zx 低显影，原有 nx 高显影
```

不得简写成“孙悟空变成 xn”或“xn 生成 nx”。

## 5. 每条关系的最低证据包

一条旧关系要恢复为当前正式语义，至少需要：

```text
2 个纯正例
+ 1 个最近邻反例
+ 1 个对象层混淆反例
+ 1 个体量或阶段变化例
```

### 纯正例

端点均为 A，关系动作清楚，拿掉其中一端后关系立即崩塌。

### 最近邻反例

看似是该关系，实际只是相邻十元或普通剧情冲突。

### 对象层混淆反例

明确展示：场景、光影、行为或长期状态为什么不能越级替人物本体作端点。

### 体量或阶段变化例

检查同一关系在不同强度、不同阶段下，是保持同类关系，还是只改变显影程度与动态链顺序。

## 6. 验收等级

| 等级 | 条件 | 可执行动作 |
|---|---|---|
| R-A | 证据包完整；端点均为 A；反例能切开最近邻；对象层明确 | 可写正式关系语义与动态链 |
| R-B | 正例基本成立，但反例、体量或层级仍缺一项 | 保留候选解释，不进入全库自动调用 |
| R-C | 主要依赖旧比喻、题材词、单角色或单剧情 | 冻结语义，只保留几何位置 |

## 7. 当前优先待验收关系

以下只登记任务，不在本协议中擅自给出新解释：

```text
nx 生 x
nx 克 x并z
nz 生 nx
zx ↔ nx 的通用补位机制及体量分型
```

处理顺序建议：

```text
先做 zx ↔ nx
→ 因已有孙悟空稳定锚，可建立对象层清晰的第一组证据
再做 nz 生 nx
→ 检查依恋、停靠是否真的结构性推出“不占方向”
最后做 nx 生 x、nx 克 x并z
→ 这两条最容易被旧 nx 的“暗流、记账、隐性判断”口径污染
```

## 9. 封存句

```text
点位通过，只代表端点可能为真；
关系通过，才代表两端真的以该方式运动。
旧位置可以保留，旧解释必须重新举证。
```
