# xz↔nz 水轴待审议问题｜单接口减少不等于 path-set 收窄：拓扑影响门

## 0｜本轮只解决一个问题

本轮只问：

> **同一路径集合里只减少一个接口，是否已经足以构成 current xz 的“路径收窄”证据？**

结论：**不自动成立。**

接口数量 `k → k-1` 只是数量变化；要成为 current xz 的强收窄证据，还必须证明该接口损失改变了剩余 path-set 的现实拓扑、可调用性或通向前置终点的汇流程度。

本轮不修改 L1/L2，只建立 L4 判别 guard。

## 1｜current canonical 锚点

L1 v1.6：

```text
水 = 阳水 xz ↔ 阴水 nz
广义变量 = 可逆性与对象特异回返空间
xz = 持续收窄
nz = 保存、恢复或重建
```

current `xz 信息量卡 v2.2` 的主骨仍是：

```text
终点前置
+ 方向被未来规定
+ 路径/选择持续收窄
+ 路径汇流
+ 临界逼近
```

因此，本轮不把“路径数量减少”直接等价成“路径收窄”。

## 2｜核心新门：TOPOLOGY-IMPACT-GATE-v0.1

### 2.1 失败型：redundant-interface-loss

```text
path_set = {A1, A2, B, C}
A1 关闭
但 A2 与 A1 属于同一可替代路径类别
且 B/C 仍保持独立可调用
且未来终点汇流程度没有显著上升
```

则：

```text
interface_count: 4 → 3
xz_narrowing_strength: weak / insufficient-alone
```

这种变化只能证明“少了一个接口”，不能单独证明“未来被压成更少结局”。

### 2.2 强支持型：topology-changing-interface-loss

如果一个接口关闭同时满足至少一种：

1. **path-class collapse**：它是某一独立路径类别的最后现实入口；
2. **bridge loss**：它是连接当前状态与另一可逆区域的唯一桥；
3. **bottleneck creation**：关闭后，多个剩余路径必须共用同一狭窄瓶颈；
4. **shared-dependency exposure**：关闭后暴露出多个剩余路径实际依赖同一脆弱节点；
5. **endpoint convergence increase**：关闭后，原本分散的未来显著更集中到同一前置终点；
6. **reentry-right reduction**：它直接削弱真实退出/回返资格，而非只删除一个同类按钮；

则该 `k → k-1` 可以成为 current xz 的实质收窄证据。

最短写法：

```text
数量 -1 ≠ xz
拓扑自由度 -1 / 路径类别 -1 / 回返资格 -1 / 汇流度上升 → 才强支持 xz
```

## 3｜结构字段

```yaml
actor: current path-set holder / affected subject
object: current relevant future path set
object_layer: reality-level path availability and topology
current_window: before one interface is lost -> after loss -> next reachable state
changed_variable: topological_future_freedom_not_raw_interface_count
relation_source: external_closure_or_real_condition_change
relation_shape: interface_loss_with_or_without_topological_effect
decision_right: tracked_separately_from_environmental_closure
path_set:
  enumerated_interfaces: required
  path_classes: required
  shared_dependencies: required_if_known
reentry_right: whether lost interface changes real exit/return qualification
future_endpoint: whether a prior endpoint becomes more dominant after loss
reality_anchor:
  - interface existed in reality, not merely imagined
  - loss is externally or structurally real, not merely unchosen
  - remaining alternatives are audited for substitutability
```

## 4｜与关羽麦城反控的关系

关羽麦城已经锁定：

```text
大路、小路都被文本枚举
→ actor 主动选小路
→ 小路连续受阻并走到 0
→ 大路未被实证关闭
```

因此，麦城至少说明：

```text
chosen_path -> 0
≠
complete path_set -> 0
```

本轮进一步补一层：即便后续再证明“大路中的某一个支路”关闭，也不能只凭 `接口数 -1` 宣布 xz 增强；还要问该支路是否是独立 path class、唯一 bridge 或真实 reentry interface。

## 5｜与吕布下邳正控的关系

吕布下邳的价值不只是“接口越来越少”，而是多个不同 path class 被依次压缩：

```text
主动军事方案
→ 守城
→ 外援
→ 送女突围
→ 剩余城防控制
→ 0（避免失守/被擒这一对象层）
```

这些路径不是一个大类里的多个同质门口，而是不同现实功能类别；并且外援被条件化、突围实际失败、水攻压缩城防、内部背叛切断剩余控制接口，最终都提高了“失守/被擒”这一前置终点的汇流度。

### 吕布正控判定

```yaml
sample: 吕布下邳
object_layer: siege-level survival/escape/control-retention path set
current_window: 曹操攻下邳 -> 吕布被擒
changed_variable: available_path_classes_and_topology
path_set:
  - active_military_alternatives
  - city_defense
  - external_aid
  - breakout
  - internal_control
reentry_right: progressively_reduced
future_endpoint: city_fall_and_capture_increasingly_dominant
reality_anchor:
  - 外援实际被调用
  - 突围实际执行并失败
  - 城防受水攻实质退化
  - 内部控制被背叛切断
xz: PASS
single_interface_loss_as_narrowing: PASS_only_when_it_changes_path_class_or_topology
confidence: 97
```

## 6｜nearest-neighbor

### z

一次节点裁定可能只是在 A/B 中选 A；它会使“实际走的路径”唯一化，但不证明 B 客观失效。

所以：

```text
chosen-path uniqueness
≠ environment-level path-set narrowing
```

### zx

主体主动放弃某路径，会让实际轨迹变窄，但这是 subject-side direction/exclusion；若环境并未关闭替代路径，不能全归给 xz。

### xn

多个节点、流程、接口存在与否只说明结构被组织；只有流程变化实际减少可行未来类别或制造汇流，才进入 xz 审计。

### x

某一接口被当前控制/封闭，可能是局部 x；只有该封闭改变更大未来路径拓扑时，才成为 xz 收窄证据。

## 7｜removal test

拿掉：

- 危险题材；
- 包围、战争、死亡；
- 情绪压力；
- 最终失败；

只保留抽象结构：

```text
原有 A1/A2/B/C 四个接口
→ A1 关闭
→ A2 与 A1 完全可替代
→ B/C 独立可用
→ 终点分布没有改变
```

则 current xz 不应因 `4→3` 自动上升。

反之：

```text
原有 A/B/C 三类现实路径
→ C 是唯一回返桥
→ C 关闭
→ A/B 都必须经过同一瓶颈 D
→ D 指向已前置终点 E
```

则即使只关闭了一个接口，xz 证据可以显著上升，因为变化的是拓扑自由度而不是裸计数。

## 8｜reverse test

如果关闭接口后又出现一个现实可调用的新独立 path class，且它恢复原先丢失的退出/回返能力，则：

```text
raw count 可能仍比最初少
但 topology freedom 可恢复
```

因此 xz 不应只根据历史累计关闭数继续单调上升。

这也提示后续与 nz 生命周期对接时必须区分：

```text
接口数量恢复
vs
对象特异真实回返资格恢复
```

两者不能互相代替。

## 9｜third-factor freeze

- 主体偏好：决定“选不选”，不等于环境“有没有”；
- 职位/身份：不生成路径类别；
- 情绪焦虑：不生成收窄；
- 最终失败：不能事后回填此前所有替代接口都已关闭；
- 物理门数量：不能直接代表现实 future freedom；
- 同质冗余接口：多个入口可能只属于一个 path class。

## 10｜正控 / 反控 / 失败类型

### positive control

`吕布下邳`：多个独立 path class 被现实条件逐步压缩，并最终汇流至失守/被擒。

### negative control

`关羽麦城`：实际小路耗尽，但文本仍保留未实测大路；不能写 complete path-set exhaustion。

### failure types

```text
RAW_INTERFACE_COUNT_FALLACY
  只看接口数量 k→k-1，就自动写“路径收窄”。

CHOSEN_PATH_AS_ENVIRONMENT_CLOSURE
  主体没选某路，被误写成该路客观关闭。

REDUNDANT_INTERFACE_OVERCOUNT
  同一 path class 的多个冗余入口被当成多个独立未来。

OUTCOME_BACKFILL_CLOSURE
  因最终失败，倒推出此前所有未走路径都已失效。

LOCAL_X_AS_TRAJECTORY_XZ
  一个局部接口被封闭，未经拓扑审计就升级成整个 future trajectory 的 xz。
```

## 11｜本轮锁定最小判别式

```text
单接口减少本身 ≠ xz 路径收窄

单接口减少
+ 独立 path class 消失 / 唯一 bridge 消失 / 瓶颈形成 / reentry-right 降低 / endpoint convergence 上升
= xz narrowing evidence 上升
```

更短：

> **xz 看的是 future topology 变窄，不是按钮少了一个。**
