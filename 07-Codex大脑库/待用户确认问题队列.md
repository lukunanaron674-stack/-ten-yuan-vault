# 待用户确认问题队列

## 用途

本页是每小时理论任务与早晚用户确认之间的持久交接区。

每次自动任务必须先读取本页，再读取 GitHub 当前正本与最近提交；不得依赖上一轮对话中的临时记忆。

## 进入队列的门槛

只有满足以下条件的问题才可进入：

```text
助手已经完成正本核对、对象分层、候选机制、反例与最近邻排除；
助手判断用户给出不同答案的概率超过 5%；
该分歧会真实改变十元定义、关系语义、五大主题边界或动态链规则；
问题已经改写成具体人物、阶段、关系和可观察差异；
问题不能仅靠继续查文档或清理旧库独立解决。
```

入口、索引、旧文污染、重复规则、对象层混淆等可独立解决的问题不得推给用户。

## 提问格式

每项必须包含：

```text
ID：
状态：待确认 / 已回答待写回 / 已解决
抽象问题：
具体人物情境：
助手已完成的推理：
剩余的两个或三个具体差异：
为什么必须由用户判断：
相关正本与提交：
最后更新时间：
```

不得直接问：

```text
A 生不生 B？
A 克不克 B？
它是不是本体？
```

必须问成用户可以凭人物感觉回答的具体情境。

## 早晚确认规则

早间与晚间任务每次最多提取 1—2 个最高价值问题。

优先级：

```text
会改变底层定义或关系盘
> 会改变动态链母型
> 会改变五大主题边界
> 只影响单一案例
```

若本页没有达到门槛的问题，明确报告“当前无须用户确认”，不得制造问题。
