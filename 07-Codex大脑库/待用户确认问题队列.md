# 待用户确认问题队列

## 用途

本页是自动任务与用户确认之间的持久交接区。每次自动任务必须先读取本页，再读取 GitHub 当前正本与最近提交；不得依赖上一轮对话中的临时记忆。

## 进入队列的门槛

只有满足以下条件的问题才可进入：

- 助手已经完成正本核对、对象分层、候选机制、正反例、最近邻排除、拿掉测试与理论后果。
- 助手判断用户给出不同答案的概率超过5%。
- 该分歧会真实改变十元定义、关系语义、五大主题边界或动态链规则。
- 问题已经改写成具体人物、阶段、关系和可观察差异。
- 问题不能仅靠继续查文档或清理旧库独立解决。

入口、索引、旧文污染、重复规则、对象层混淆等可独立解决的问题不得推给用户。缺资料但可由实读解决的事项优先标为待补证，不冒充理论分叉。

## 提问格式

每项必须包含：ID、状态、抽象问题、具体人物情境、助手已完成的推理、剩余具体差异、为何必须由用户判断、相关正本与提交、更新时间。

抽象问题必须改写成用户可以凭人物感觉回答的具体情境，不直接问“A生不生B”“A克不克B”或“它是不是本体”。

## 确认规则

每次最多提取1-2个最高价值问题。优先级：

会改变底层定义或关系盘 > 会改变动态链母型 > 会改变五大主题边界 > 只影响单一案例。

用户回答后，先写回正本与受影响案例，再把项目移入已解决记录。不得重复加入已解决问题。

### UQ-20260717-002

- **状态**：待用户确认
- **抽象问题**：低事件共居作品中，“住处使漂流者拥有可返回之处”何时足以让命运达到结构性显影，并启动五主层的 空间克命运；何时只属于 空间生时间、关系位置变化或十元层 n克xz。
- **具体人物情境**：夏美带着上京和创作压力暂住平屋。她不断外出、失败、再回到共享饭桌；平屋让她从“没有地方容纳失败”变成“失败后仍有地方回来”。需要判断的是：这是否已经压缩她未来去向与归宿的可能性，还是只改变当前状态和关系位置。
- **助手已完成的推理**：
  - 对象分层：夏美稳定本体未锁定；焦虑、暂住和失败属于当前状态；外出创作与返回属于行为；平屋属于场景；重复往返和共同生活属于时间结构；饭桌同框与晾衣构图属于光影、镜头和显影辅助；“可返回者”属于关系位置。
  - 候选机制：空间若持续压缩“继续漂流、离开、无处返回”的实际路径，并在关键选择或结局中改写归宿答案，可候选 空间克命运。若平屋主要让重复日常积累关系，则更直接的是 空间生时间。
  - 正例：人物面临“离开东京、放弃创作、回故乡”与“继续留下”的真实分叉；因为这个住处及其中的关系，离开路径被压缩，后续人生方向改变，结局回答“哪里是归宿”。
  - 反例：人物只是每次失败后回来休息，学校、职业和去留选择均未被住处改变；换成另一间同样可居住的房子，成长路径仍成立。此时只确认 n克xz、关系位置变化或 空间生时间。
  - 最近邻排除：空间生时间解释容器让重复得以积累；n克xz解释承载降低漂流状态；“从临时来客变成可返回者”解释关系位置变化。三者都比主题级克制更低层，不能混写。
  - 拿掉测试：拿掉最终去向与归宿收束，只保留共居空间和重复日常。若作品核心仍完整，命运不是结构主题；若关键选择、高潮或结局失去回答对象，支持命运显影。
  - 理论后果：答案将确定低事件作品启动命运主题的最低阈值，并防止把所有“回家、留下、返回”自动升级成命运，同时保持五主关系与十元 n克xz 分层。
- **供用户直接判断的三个强度情境**：
  - A（弱）：她受挫后回平屋吃饭、睡觉，第二天继续原计划；住处没有改变任何去留选择。
  - B（中）：她认真准备放弃创作或离开东京，但因为平屋提供的关系与返回资格，最终选择留下，人生路径发生一次明确转向。
  - C（强）：平屋是否存在、能否返回，成为高潮与结局的中心条件；拿掉平屋，人物最终去向、关系归宿和作品答案同时改变。
- **剩余具体差异**：A、B、C从哪一级开始算“空间克命运”；还是即使到C，也应只写空间承载命运，而不用“克”。
- **为何必须由用户判断**：这不是《Hirayasumi》事实核验本身，而是低事件作品中“归宿收束”达到五主克制的阈值，会影响后续大量空间型漫画。
