# 待审议｜zx↔nx 严格补的时间窗口闭环与旧 nx 接口退出

## 0｜待审议问题

当前已有三部独立作品完成同一类双阶段审计：

```text
阶段 A：初始 zx↔nx 严格补按 current canonical 独立成立
阶段 B：当前瓶颈或权限结构发生真实变化
阶段 C：旧 nx 接口不再是完成同一结果的当前必经门
```

共同支持一个候选纪律：

> **严格补是当前现实瓶颈上的关系，不应因历史来源而永久追挂。初始 strict 成立以后，若当前命名瓶颈真实消失，或外部 nx 条件稳定内化为主体 x，使原外部接口不再是同一结果的必经门，则旧 strict 关系当前窗口应关闭；后续新任务必须重新判新的 zx、nx 与瓶颈。**

该纪律已跨 3 部独立作品，但仍只是 `pending-review`，不得直接改 L1、信息卡、准度卡或补卡。

## 1｜三份独立作品控制

闭环：红孩儿被收伏、唐僧获救后，原“观音收伏红孩儿”接口不再是完成同一救师结果的必经门。

```yaml
closure_type: bottleneck_resolved_old_interface_exits
resource_internalized_into_x: false
```

### 1.2 《水浒传》宋江·高唐州｜瓶颈解决 / 专业许可接口退出型

```yaml
closure_type: nx_resource_internalized_into_x
```

## 2｜共同变量

三例表面完全不同：

- 高位收伏接口；
- 专业破解 + 许可接口；
- 外部军力资源接口。

共同变量不是人物或资源类型，而是：

```text
初始 strict 已成立
+
旧 nx 对当前瓶颈真实必要
→ 后续任务/权限结构变化
→ 旧 nx 不再是同一结果的现实必经门
```

因此时间窗口不应机械按章节、时间长度或“曾经求过谁”判断，而应检查**当前瓶颈和当前接口是否仍然活着**。

## 3｜两种已观察到的 closure 机制

### A｜瓶颈解决 / 接口退出型

```text
初始 strict
→ 当前命名瓶颈解决
→ 同一任务完成或进入下一阶段
→ 旧专业/许可/处分接口失去当前必要性
→ strict 当前窗口关闭
```

当前控制：红孩儿、宋江高唐州。

### B｜nx 外部资源内化为 x 型

```text
初始 strict
→ 外部资源进入主体持续统辖
→ 调用不再逐次经过原外部批准
→ 资源状态从 nx 外置转成 x 内化
→ 原 strict 当前窗口关闭
```

当前控制：孙策质玺借兵。

## 4｜拿掉与反向测试

### 闭环成立的必要检查

1. 初始 strict 必须先按 current canonical 独立成立；
2. 后续必须明确是同一对象层/同一任务窗口的状态变化；
3. 拿掉“历史来源”后，当前结果仍可独立成立；
4. 补回历史来源只增加因果背景，不能重新制造当前依赖；
5. 若原外部节点仍可在结果生效前真实拒绝、撤回或卡住同一结果，则 closure 不成立。

### 反向情形

若任务尚未完成、瓶颈仍在，或者资源只是暂借/代管且原外部节点保留稳定收回与逐次批准权，则旧 nx 仍应保持当前活跃。

## 5｜最近邻排除

### vs nx→x

不是所有 closure 都等于 `nx→x`。红孩儿、高唐州是“任务瓶颈解决 + 旧接口退出”，外部能力没有进入主体 x；孙策才是资源内化型。

### vs 普通阶段切换

“过了一段时间”“换了章节”都不是证据。只有当前瓶颈、权限边界或接口必要性发生真实变化，才支持窗口关闭。

### vs 人物换芯

旧 nx 退出不等于人物本体从 nx 变成 zx，也不等于稳定副元消失；这里只判断**这一具体关系功能是否仍处于当前执行窗口**。

### vs xn

后续流程组织可以有 xn，但不能用“主体会组织”代替“原外部接口是否仍是必经门”的权限判断。

## 6｜第三因素冻结

冻结作品主题、人物善恶、胜负、章节距离、关系好坏与象征意义。

必须保留：

```text
初始 strict 是否成立？
当前命名瓶颈是否仍在？
原 nx 权限/资源是否仍外置？
当前调用是否仍须经过原节点？
后续是否还是同一结果对象？
```

若所谓冻结把当前瓶颈或端点一起删掉，则无效。

## 7｜当前置信与边界

三份控制均达到正式研究记录阈值：

- 红孩儿：事实 99 / 分类 98；
- 宋江高唐州：事实 99 / 分类 98；
- 孙策质玺借兵时间窗口：事实 99 / 分类 98。

因此足以形成待审议问题，但不足以直接改 canonical。

当前尚需优先补的反例：

1. **资源表面内化但原节点仍保留撤回权**：验证 B 型 closure 的真正权限阈值；
2. **任务表面完成但同一瓶颈很快复发**：检查 A 型 closure 是否只是暂时休眠；
3. **旧接口退出但立即被等价外部接口替代**：区分“具体节点退出”与“nx 接口层仍然外置”。

## 8｜暂定待审议句

> **zx↔nx 严格补应按当前现实瓶颈与接口状态设定有效时间窗口。初始 strict 成立不保证历史永久追挂；当命名瓶颈真实解决，或外部 nx 条件稳定内化为主体 x，使旧接口不再是同一结果的必经门时，应关闭旧 strict 当前窗口，并在新任务中重新判断 zx、nx 与补关系。**
