# 运行记录｜关羽土山受困：归刘行动窗口被外部条件封住，但旧义 zn 未退场；得知刘备消息后按原硬门复位

## 1｜本轮问题

本轮不重新判“关羽整个人是什么”，也不把“忠义关公”标签当结论，只测试火轴此前为空的 pressure-display 槽：

> **此前已独立成立的 `zn`，在外部条件使其直接行动表达暂时无法完成时，是原则本身退出，还是当前表达/行动窗口被封住；当条件解除后，同一 `zn` 是否按原硬判据重新完成现实排序？**

本轮严格区分：

```text
zn 原则本身
≠
zn 当前最强行动表达是否可执行
```

## 2｜剧情事实链

### 阶段 A｜压力进入前/初段：旧义已明确进入关系边界

第25回土山受困时，关羽不是无条件把最终归向交给曹操，而是提出“降汉不降曹”、奉养二嫂、**一旦得知刘备去向即可离开**等条件。

因此在最强离曹行动尚未发生前，被测原则已经明确：

> **刘备旧盟 / 旧义不能被当前受困与暂居曹营自动作废；若刘备去向明确，旧义仍保留决定最终归向的资格。**

### 阶段 B｜压力中：直接“归刘”行动窗口被条件封住

暂居曹营期间，至少存在两个现实条件：

1. 刘备去向未明，直接归刘缺少明确现实去向；
2. 关羽仍处于护送二嫂、暂居曹营并报答曹恩的当前关系安排中。

这使“立即离曹归刘”这一最强现实表达暂时不能完成。

但文本没有显示旧义被删除或改写。相反，土山阶段已预先保留“知刘备去向即离开”的未来调用条件；曹操后续厚待、金银、爵禄增加，也没有把该条件撤销。

因此压力中更准确是：

```text
zn_current_guidance_qualification = retained
strongest_action_expression = temporarily_blocked
```

而不是：

```text
zn = off / erased
```

### 阶段 C｜压力解除：得知刘备去向后，同一 zn 按原硬门复位

第26回一旦刘备消息明确，关羽没有重新发明一套原则，而是兑现土山阶段已经预先声明的条件：辞曹、封存金银、悬回侯印、不带曹拨人役，离开曹营寻找刘备。

这一步按 current `zn` 硬门重新出现：

```text
现实留曹收益仍高
+
旧义继续参与最终排序
+
旧义压过留曹收益
+
未来调用条件兑现
→ zn 高强度行动显影恢复
```

所以本轮压力链成立：

```text
已成立 zn
→ 外部条件封住最强行动表达
→ zn 未来指导资格仍保留
→ 条件解除
→ 同一 zn 按原硬判据再次完成现实排序
```

## 3｜zn 证据

沿 current `zn_准度卡_v0.1`：

1. 原则对象明确：刘备旧盟 / 旧义与最终归向；
2. 不依赖后续曹操赞许才成立；
3. 曹方奖励、爵禄与留用利益存在时仍进入判断；
4. 得知刘备消息后影响最终选择；
5. 土山阶段已经预先写出未来调用条件；
6. 让渡边界明确：可暂居、可报曹恩，但不能让曹恩替换最终归向。

因此本轮不重新增加 `zn vs x` positive 计数，只复用已锁 `zn` 作为 pressure-display 前提。

## 4｜x 检查

本轮不把“暂居曹营”或“汉寿亭侯”名位自动判 `x`。

已有火轴记录分别证明：

- 曹赐金银、赤兔马等具体资源可按现实占有另查 `x`；
- 爵位 / 称号 / 印信本身不足证明完整现实 `x`。

pressure-display 本轮只测同一 `zn` 的压力前/中/后表达窗口，不把隔壁对象层的资源 `x` 抓来凑 `zn+x` 或 strict。

因此：

```yaml
x_increment: false
zn_x_cooccurrence_increment: false
strict_increment: false
```

## 5｜关键压力变量

本轮关键压力不是“曹操很强”这种人物评价，而是两个可观察条件：

```text
刘备去向未知
+
当前护送二嫂 / 暂居曹营 / 报恩关系安排仍在
```

它们封住的是：

> **“立即离曹归刘”这一最强现实行动表达。**

它们没有自动删除：

> **“一旦刘备去向明确，旧义仍应决定最终归向”的未来指导资格。**

## 6｜拿掉测试

### 6.1 拿掉“刘备去向未知”压力

若土山之后立即获得刘备明确去向，按关羽自己预设条件，直接离曹行动窗口会提前打开。

→ 支持当前压力确实作用在行动表达窗口。

### 6.2 拿掉旧义 zn，只保留现实压力

若关羽并无“知刘备去向即离开”的预设原则，那么刘备消息后来出现并不能解释为什么必须放弃高留曹收益、辞曹归刘。

→ 说明解压后的行动不是压力自动制造，而是旧 `zn` 重新取得现实表达机会。

### 6.3 拿掉解压后硬证据

如果刘备去向明确后，关羽继续因爵禄长期留曹，或者只口头怀念刘备而不让旧义进入最终选择，则不能锁 pressure-display 复位。

原著并非如此。

## 7｜反向测试

真正的 `zn` 退出 / lifecycle 改写应表现为：

```text
压力窗口过去
+
同类冲突重新出现
+
主体已有现实能力按旧原则行动
但旧原则不再进入最终排序
且后续不复位
```

那应判 lifecycle 退出/替换，而不是 pressure-display。

本例相反：条件解除后，旧原则按先前同一硬门立即重新完成排序。

## 8｜最近邻排除

- `zn vs z`：曹操后续赞许不是原则来源，旧义先成立。
- `zn vs xn`：护送、车马、离开路线回答“怎么执行”，不解释最终归向标准。
- `zn vs x`：具体资源掌握另验，不参与本轮同一原则 pressure-display 统计。
- pressure-display vs lifecycle：本轮没有证据表明旧 `zn` 真退出；解压后同一原则按原硬门复位，因此优先 pressure-display，而非 lifecycle 替换。
- 稳定人物本体：不锁，只锁该原则当前功能的压力显影变化。


结论不变。

## 10｜结论与成熟度

本轮可靠结论：

> **外部条件暂时封住 `zn` 的最强现实行动表达，不等于 `zn` 的未来指导资格被删除。只有在条件解除后，同一原则仍能按原 canonical 硬门重新进入冲突排序，才允许锁 pressure-display，而不能凭“人物后来又做了类似事”泛化。**

最短：

```text
expression window blocked
≠
zn erased
```

```text
解压后按原硬门复位
→ pressure-display

同类冲突中旧原则明确不再回来 / 被新排序替代
→ lifecycle exit / replacement
```
