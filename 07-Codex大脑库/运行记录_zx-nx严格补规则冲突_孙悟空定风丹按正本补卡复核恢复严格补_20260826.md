## 1｜研究问题

2026-08-23 旧记录在一个比 current canonical 更严的候选门下，把本例判为 `nx→zx` 单向补：要求拿掉 zx 后，必须让 nx 自身资源/能力本体受损，才算 `zx→nx`。

重新读取当前 `zx补nx_补卡` 后确认，正本并不要求“nx 自身功能本体受损”。正本明确允许：

```text
nx 补 zx
= 补入间接路径、外部权限接口、救兵、关系通道与非正面解决方案

zx 补 nx
= 把借到的资源、关系与通道重新转成实际行动、公开决定和结果推进
= 改善 nx 单独运行时“有路径却缺落地权能”的缺口
```

因此本轮按 current canonical 重验，不沿用旧的非正本门槛。

## 2｜剧情事实

1. 火焰山阻断西行，孙悟空寻找铁扇公主借芭蕉扇。第一次交手时，罗刹女用芭蕉扇将孙悟空扇离现场，直接打断其当前取扇路径。
2. 孙悟空被扇到小须弥山附近，进入灵吉菩萨这一外部解决接口，说明自己当前被芭蕉扇强制位移、无法稳定留在冲突位置的问题。
3. 灵吉说明定风丹由如来所赐，一直未曾使用，并明确把它交给孙悟空，使芭蕉扇“扇你不动”。
4. 灵吉同时明确把现实后续交回孙悟空本人：定风丹只解决“被扇走”的问题，仍需孙悟空自己回去“要了扇子，扇息火”，把外部条件兑现成过山结果。
5. 孙悟空随后辞别灵吉，立即返回翠云山，重新公开叫阵并进入罗刹女的芭蕉扇作用范围；定风丹使其不再被强制送离现场，当前取扇行动得以继续。

## 3｜zx 判断

本轮 `zx` 不由“孙悟空很能打”推出，而由以下当前行动结构支撑：

- 过火焰山、取得能灭火的芭蕉扇这一最终行动方向始终由孙悟空自己占据；
- 第一次被扇离后，他没有把最高方向交给灵吉，而是把外部解决条件重新接回自己的取扇方向；
- 得到定风丹后，他亲自返回翠云山、公开叫阵、再次进入冲突现场，使被打断的行动重新压回现实。

因此本轮锁当前行为/状态 zx，不锁稳定人物本体。

## 4｜nx 判断

定风丹在接入前不属于孙悟空稳定调用边界：

- 资源由灵吉持有；
- 其定风效果不是孙悟空当前自行生成的等价能力；
- 孙悟空必须真实进入灵吉这一现成外部资源/能力通道；
- 灵吉交付后，直接解除“芭蕉扇一生效就把主体送离现场”的现实阻断。

因此本阶段 nx 关系功能独立成立。

## 5｜关键压力与同一现实瓶颈

本轮不能把问题粗写成“孙悟空打不过铁扇公主”。真正的窄瓶颈是：

> 芭蕉扇一旦生效，孙悟空会被强制移出冲突位置，无法稳定留在现场继续实施取扇方案。

`nx` 的定风资源解决“不能留在现场”；`zx` 则把这条外部资源路径重新兑现为“回到现场、公开对抗、继续取扇”的现实推进。

两端直接咬住同一当前瓶颈的两个缺口：
- 路径/条件缺口；
- 现实接入与落地权能缺口。

## 6｜双向拿掉测试

### 6.1 拿掉 nx

保留孙悟空的过山/取扇方向与公开行动能力，去掉灵吉/定风丹或等价抗风条件：

```text
zx 仍成立
→ 但芭蕉扇再次生效时主体会被送离现场
→ 当前取扇链再次中断
```

因此 `nx→zx` 成立：外部资源补“稳定留在当前冲突位置”的路径条件缺口。

### 6.2 拿掉 zx

保留：
- 灵吉拥有定风丹；
- 定风丹确有抗芭蕉扇强风的功能；
- 外部路径可以被提供。

但拿掉孙悟空把这条外部条件重新转成公开行动、返回翠云山、叫阵、持续取扇的现实落地端：

```text
定风路径仍存在
→ 但不会自行生成“回到冲突现场并继续取得芭蕉扇”的当前结果
→ nx 单独运行出现“有路径却缺落地权能”的缺口
```

而这正是 current canonical `zx补nx_补卡` 明文允许的 `zx→nx` 缺口。

因此 `zx→nx_landing_power_gap_filling = true`。

## 7｜反向测试

若原著是：

```text
灵吉亲自携定风丹到翠云山
→ 亲自压住芭蕉扇
→ 亲自夺得芭蕉扇
→ 亲自熄灭火焰山
→ 孙悟空只旁观或最低参与
```

则 `zx→nx` 的落地权能缺口会明显下降，本例不应锁严格补。

原著恰好相反：灵吉提供外部抗风条件后，明确让孙悟空本人继续“要扇子、扇息火、立功”，并由孙悟空实际返回执行。

## 8｜最近邻排除

- `nx vs xn`：孙悟空怎样再次接近罗刹女、后续如何变虫入腹可有 `xn` 邻近，但定风丹这一关键条件不是主体自己搭出的运行节点，而是外部现成资源接口。
- `nx vs x`：定风丹交付前不属于孙悟空稳定调用边界；本轮不因一次交付就自动判长期 x 内化。
- `zx vs x`：本轮不是平静调用已有权，而是在明确受阻后重新把自身行动方向公开压回现实。
- `strict complement vs 普通支援`：关键不是“灵吉帮得很大”，而是两端先独立成立，并分别通过路径缺口与落地权能缺口测试。
