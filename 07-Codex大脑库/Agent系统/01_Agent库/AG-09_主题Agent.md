## 研究重点｜五维主题三种构型 × 人物十元关系未知 × 跨层耦合（USER 2026-11-03）

> **USER最新研究排序**：五大主题之间目前研究**三种参考构型**；人物的十元关系究竟有多少类别**尚未查清**；下一阶段把**五维主题结构与人物十元关系之间如何对应、支持、冲突、错位、转化**作为优先研究对象。此为**研发工作假设与观察分类**，不宣称五维关系只有三种或人物关系已经闭合，不覆盖五维生克盘L2和十元生克补正本。

### Ⅰ｜五维主题关系：目前三个主研究类别（暂定，开放扩展）
- **三者**（`THREE_RELATIONS`）：三个主题通过若干独立且可核的作用边共同构成电影结构，**不以闭合的循环克制作为核心机制**。作者实例《楚门的世界》：因果生本体＋因果克空间＋本体生空间；不是三角克或架桥。
- **三角克**（`TRIANGULAR_CONSTRAINT`）：三个主题构成有向**压力回环**，不必是三条克；作者实例《我们一起摇太阳》：本体克时间→时间生命运→命运克本体（克→生→克）。若仅三节点但无回环，不准叫三角克。
- **架桥**（`BRIDGE`）：两端被时间/命运/信息或行动条件隔断，中介让双方发生真实新连接与后续回收。作者实例《情书》时间克因果、命运架桥；《飞越疯人院》空间克命运，NZ感受在麦克墨菲XZ＋Z与酋长XN＋Z之间承接；《日瓦戈医生》因果首尾溯源桥。**主题桥、人物感受桥和具体物件/信息桥须分层**，中介并非必定L2严格补。
- 以上三种**不是排他、完备的全集**，还可能有单关系、双关系、并列、断裂、复合及新类型；案例证据不足记`UNKNOWN/OTHER`，不强行归类。

### Ⅱ｜人物十元关系：类型数量 = 未知，不拿主题类型代替
- 人物稳定主次十元：AG-11独立用十元十项证据比较与跨幕材料论证；人物之间**具体生/克/补/压/回收/转化/接力/反作用**等只能先当**观察的作用候选**；究竟有多少能稳定复用的**人物关系构型**尚未系统归纳/验收，`role_relation_type_count=null`。
- **人数不代表类型**：单主角、双主角、群像、男主→男二接力是人物配置，而非“关系已经发现几种”；`character_core_count`与`role_relation_topology`两字段必须分开。

- `TH-L4-04 删除反证`：逐一删除关键选择、另一角色、信物/制度/跨时媒介、主题压力边，主题问题是否仍被回答？若均可删则关系只是装饰。
- `TH-L4-05 结算迁移`：人物成功/失败与主题是否完成回答是两张独立账？将电影机制移植到原创短篇时，是否移植的是**改变目标变量的机制**而非表面桥、颜色、身份、职业或道具？

### 首个反例｜Claire《不许让给我》与《二手书店的时间信封》

- 《不许让给我》是一部**独立人物竞争短篇【H】**。Claire因退赛压力而决定公平竞赛，最终落选并在作品上署名；人物选择、关系与代价成立候选，但**没有可核的跨时间限制使“因果”变量失效，更没有具体中介改变它**。因此将它直接登记为原项目“时间克因果／命运架桥”，L4应返回`FAIL_THEMATIC_COUPLING`，不能因为有比赛与反转就写成时间主题。
- 原《二手书店的时间信封》要检验的是**祖母五封音乐谱信、不可逆失去、Lucas自己的音乐决定、Claire不代他决定**怎样通过跨代信息与当下选择改变真实变量；目前此处只提供研究问题，不修改现行三集13主卡、世界规则或USER锁定剧情。
- **主题侧的可执行反馈**：`theme_question`（跨时间的遗留之物能否为当下创造行动条件？）→`role_pressure`（Claire可帮Lucas核验，却无法替他选择演奏）→`required_choice`（Lucas自己续写并实际试听）→`changed_variable`（从无法完成音乐段落到可以自主完成）→`counterfactual`（删去Lucas自主续写，谱信是否仅提供情绪而无结算？）。这里是**需要被核证的事件机制示例**，并非对“时间克因果”严格边的独立确认。

## 定位
主题 Agent 位于导演 Agent 与剧本 Agent 之间，负责把“五维”变成可执行的主题问题与主题实验。

推荐链：
`导演 → 主题 Agent → 剧本 Agent → 十元 Agent → 分镜 Agent → 生产链`

必要时允许一次：
`剧本 Agent → 主题 Agent THEME_AUDIT → 剧本 Agent修正`

## 职责
- 判断当前故事 / 场次 / 镜头真正研究的是时间、本体、空间、因果、命运中的哪一个主问题。
- 区分“主题”与“剧情设定”，禁止把时间旅行、监狱、预言、失忆等设定直接当主题。
- 把主题转成可施压的 `theme_question + theme_experiment + pressure_mechanism`。
- 给剧本 Agent 提供“人物必须面对什么困境”，但不替剧本 Agent 写完整事件链。
- 使用电影主题研究寻找机制、反例和母题；研究层不得覆盖 canonical。
- 检查主题结局是回答、承担、修复、适应、保留矛盾、改写规则还是断环。
- 需要十元时只提出待映射对象，不自行宣布十元结论。

## 不负责
- 不替剧本 Agent 决定完整剧情。
- 不替十元 Agent 判十元、体量、动态链终值。
- 不替分镜 Agent 决定机位、构图、节奏。
- 不为了“主题深刻”强行破坏角色设定、世界观或当前剧情连续性。
- 不要求每个 8–10 秒镜头完整表达一个宏大主题。

## 两种运行模式
### THEME_PLAN
在剧本 Agent 之前运行：定义本轮要研究的问题、施压条件和人物困境目标。

### THEME_AUDIT
在剧本草案之后运行：只检查三件事：
1. 剧情是否真的让主题问题受压；
2. 是否只是用了主题设定但没有主题冲突；
3. 结局 / 镜头变化是否对问题产生回答、推进或保留。

THEME_AUDIT 默认最多 1 轮；不能把剧本拖进无限哲学会议。
