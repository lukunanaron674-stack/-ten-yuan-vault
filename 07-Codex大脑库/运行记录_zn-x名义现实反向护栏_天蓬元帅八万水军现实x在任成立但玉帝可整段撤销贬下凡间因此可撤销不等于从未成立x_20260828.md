# 天蓬元帅八万水军｜“可撤销 ≠ 从未成立 x”边界护栏

## 1｜被测对象层

只测试天蓬元帅阶段对“天河八万水军 / 天河军务”的现实掌管是否构成当前 `x`，以及玉帝后来能够整段收回该位置，是否会反向否定此前 `x`。

不测试猪八戒整个人物本体，不从“元帅”“神仙”“受罚”“猪胎”等身份标签倒推十元。

## 2｜剧情事实

- 《西游记》第63回由沙僧回述：二师兄昔为天蓬元帅，曾“掌管天河八万水兵大众”。这不是只有称号，而是有明确被管理对象与规模。
- 《西游记》第8回猪八戒自述：因酒后违法，玉帝将其重责并“贬下尘凡”。
- 被贬之后，他不再处于天河水军的现实指挥位置，原天河军务掌管窗口实际终止。

## 3｜x 证据

按 `x_准度卡_v0.1`：

1. 被掌握对象明确：天河八万水军 / 天河军务；
2. 掌握主体明确：天蓬元帅；
3. 权限类型明确：掌管、统领军务；
4. 不是单纯职位名：文本明确给出实际“掌管八万水兵大众”；
5. 被贬后该现实掌管关系真实断开，说明拿掉掌管关系会改变案例核心。

因此在天蓬元帅任内的窄对象层：

```yaml
x_current_while_in_office: true
x_object: 天河八万水军及其军务
```

## 4｜关键边界：可撤销不等于当前 x 为假

玉帝后来可以通过上位处分把天蓬元帅整段贬出天庭，实际结束其天河军务掌管。

但这不能倒写成：

```text
因为上位节点最终能撤销
→ 所以前面从来没有现实 x
```

更准确是：

```text
阶段 A：
外部授予来源存在
+
主体对明确对象已有稳定现实掌管
→ current x = on

阶段 B：
上位节点实际行使整段撤销 / 剥离
→ 原 x lifecycle 结束
→ current x = off
```

所以本例新增护栏：

> **“权限可由上位节点撤回”是 `x` 的稳定性 / 生命周期问题，不是自动否定当前现实 `x` 的充分条件。**

## 5｜与杨志、探春两类 P6 护栏的区别

### 杨志

```text
正式授权 + 部分管理
但同层关键决定仍被原节点现实压回
→ 被测同层稳定 x 不足
```

### 探春

```text
局部 x 真实成立
但上位节点仍可在更高范围发动覆盖性全局命令
→ local x 不得倒灌 global x
```

### 天蓬元帅

```text
当前被测范围内 x 真实成立且稳定运行
上位节点平时不需要逐次替代其单次军务决定
但仍拥有整段撤销 / 剥离位置的现实按钮
→ current x 可成立
→ 永久归属不能由 current x 倒推
```

三者共同要求把：

```text
当前可用权
同层最终决定权
权限范围
整段撤销权
永久归属
```

分开审计。

## 6｜拿掉测试

拿掉“天蓬元帅”称号，只保留“确实掌管天河八万水军”的事实，任内 `x` 仍能成立。

拿掉真实掌管，只保留元帅称号，则不能锁 `x`。

拿掉后来被贬这一事件，不影响任内 `x` 是否真实成立，只会失去“上位整段撤销”的生命周期证据。

## 7｜反向测试

如果文本只有：

```text
授予元帅称号
+
上位节点随时逐次替他决定所有军务
+
主体没有稳定调用 / 管理 / 处分能力
```

则不能锁现实 `x`，应重新检查名义位置与外部通道。

反之，只要任内同一对象层的管理决定真实稳定生效，后来发生撤职、剥夺或改派，不应把过去的 `x` 追溯性抹除。

## 8｜最近邻排除

- `x vs nx`：权限来源外部，不等于主体任内没有局部现实掌握；入口来源与当前对象掌握分别判断。
- `x vs xn`：军务如何组织持续运行属于 `xn` 邻近；本轮只锁“八万水军是否归其现实掌管”。
- `x vs z`：元帅名位与尊位不是核心证据，真正证据是实际掌管对象。
- `x vs zx`：本轮不是扩权或公开凌驾，只测试既有掌管边界。

## 9｜第三因素冻结

冻结猪八戒后来的取经身份、战力、性格、调戏嫦娥的道德评价、投猪胎等剧情，只保留：

```text
明确掌管对象
→ 任内现实掌管
→ 上位节点处分
→ 整段位置终止
```

结论不变。

## 10｜zn 检查

本轮没有足够证据锁定同一对象层 `zn`。是否存在“军人责任”“忠于天庭”等内部原则，不能从元帅身份、受罚或后续经历倒推。

因此：

最短纪律：

> **现实可用 `x` 与永久不可撤归属不是同一个东西。上位节点能在未来整段撤销，并不能追溯性否定主体此前已经稳定拥有的当前 `x`；应把 current-x、scope、override 与 revocation lifecycle 分开审计。**

## 12｜第二研究用途：x scope 反向边界

本记录同时作为 `current-x-scope-distinction-v1_20260830` 的第二独立作品边界护栏，不新增剧情事实，也不重复计算普通 positive control。

与《红楼梦》王熙凤协理宁国府共同支持：

```text
future whole-block revocation
≠
current same-layer non-possession
```

但必须与“同层当前决定在生效前可被原节点逐次压回”分开：

```text
A｜future revocation
任内同层决定可以稳定直接生效
→ current x 可成立
→ 后续整段撤回记为 lifecycle end

B｜same-layer pre-effect veto
主体当前决定在同一对象层、同一结果生效前
仍需上位逐次放行或可被现实压回
→ current stable x 需降级 / 重新审计
```

因此，本例在 x-scope 专项中的新增用途不是证明“授权越高越像 x”，而是禁止另一种过度修正：

> **不能因为权限未来可撤，就把撤回发生以前已经真实生效的 current `x` 追溯性抹掉。**

统计用途：

```yaml
x_scope_boundary_guard_increment: true
x_scope_boundary_guard_index: 2
x_scope_boundary_guard_cross_work_index: 2
x_scope_positive_increment: false
strict_increment: false
```

本记录只作为 L4 边界证据，不增加 strict、pure-zn、zn+x 共现统计，不修改 L1、准度卡或 `zn补x_补卡`。
