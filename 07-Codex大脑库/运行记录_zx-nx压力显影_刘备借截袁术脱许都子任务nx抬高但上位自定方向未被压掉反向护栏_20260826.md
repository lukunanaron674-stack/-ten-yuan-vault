# 《三国演义》刘备借截袁术之命离许都｜压力显影反向护栏

## 0｜结论先行

本轮专门检验：

> 曹操强控制许都环境下，刘备真实使用曹操授予的“截袁术”任务与兵力接口离开许都，能否计作“稳定 zx 被压力压住 → nx 高显影 → 解压后 zx 复位”的第二份直接压力显影控制？

结论：**不能。**

原因不是 nx 不成立，而是对象层没有对齐：

- “截击袁术 / 正式出兵 / 五万人马授权”这一子任务层，`nx` 高纯成立；
- “我要借这个机会脱离许都”这一更高最终目的，始终由刘备自己生成，没有被曹操改写；
- 刘备把外部任务嵌入自己的脱身计划，`xn` 邻近明显；
- 离许都这个微阶段又没有公开扩权硬门，因此不能把“更高目的自定”直接写成当前 zx 高显影。

所以本例是：

```text
强压力存在
+
子任务 nx 抬高
+
更高最终方向仍由主体自定
+
主体用 xn 把外部通道工具化
≠
同一对象层的 zx 被克后 nx 显影
```

本轮新增价值，是给“压力显影 ≠ 换芯”研究增加一条**对象层一致性护栏**。

## 1｜剧情事实

第二十一回中：

1. 刘备身处许都，曹操控制力强，刘备已把此前环境比作“笼中鸟、网中鱼”。
2. 得知袁术将经徐州投袁绍后，刘备暗自判断“我不就此时寻个脱身之计，更待何时”。
3. 刘备主动向曹操提出领军截击袁术。
4. 曹操同意，并令刘备总督五万人马，朱灵、路昭同行。
5. 刘备得到正式出兵接口后迅速离许都，并对关羽、张飞明确把此次出行比作“鱼入大海、鸟上青霄”。
6. 曹操后来后悔，派许褚追赶；刘备以已经取得的出征命令拒绝返回。
7. 袁术死后，刘备遣朱灵、路昭回许都，却留下军马守徐州，继续形成脱曹局面。

## 2｜zx 检查

### 2.1 为什么不能把“自有脱身目标”直接等同 zx

刘备的更高目的确实由自己生成：

```text
许都被视为笼网
→ 主体自己寻找脱身机会
→ 主动提出利用截袁术任务离开
```

但现行 zx 还要求：主体自身权能公开压入现实，并让外部秩序围绕新增决定范围真实响应。

本窄离许都微阶段：

- 刘备真实目的主要隐藏；
- 五万人马首先来自曹操正式授权；
- 没有在许都当场公开建立新的“刘备说了算”的处分接口。

因此：

`zx_in_departure_microstage: rejected_as_primary`

这防止把“自己很有目标 / 成功逃脱”偷换成 zx。

## 3｜nx 检查

“截击袁术”的任务、正式出兵许可和五万人马调用入口都不由刘备自行生成。

```text
曹操批准出征
→ 给兵、给正式任务接口
→ 刘备真实接受并使用
= mission-layer nx
```

因此：

`mission_layer_nx: evidence-locked`

但这个 nx 只能锁在任务/授权对象层，不能向上覆盖“刘备为什么要离开许都”。

## 4｜nx vs xn

刘备并非机械领命。他：

- 识别袁术路线是脱身机会；
- 主动提出出征；
- 把外部军令嵌入自己的脱身计划；
- 得令后星夜整备、催军速行；
- 曹操追召时利用已成事实的出征状态拒绝回返。

所以更高运行方法有明显 `xn`：

```text
外部任务 / 授权入口
= nx

把该入口组织成脱身节点
= xn 邻近
```

“沿外部通道”与“自己组织如何利用该通道”可以同时存在，不能互相覆盖。

## 5｜为什么不是直接压力显影控制

孙悟空五行山控制的结构是：

```text
同一脱困对象层：
自身权能无法进入现实
→ 外部解除接口成为必经门
→ nx 高显影
→ 压力解除后原自身权能快速复位
```

刘备本例却是：

```text
高层对象：脱离许都
→ 最终方向一直由刘备自己生成

子层对象：截袁术 / 正式出兵
→ 外部任务与兵力接口真实 nx

运行方法：
→ 刘备自己把子层接口嵌入脱身计划
→ xn
```

因此不能写成：

> 曹操压力把刘备 zx 压掉，于是 nx 抬高。

因为“被压掉的 zx”与“抬高的 nx”没有在同一对象层完成直接替换证明。

## 6｜拿掉测试

### 拿掉曹操出兵授权

保留刘备想离开许都的更高目的：

- 脱身方向仍存在；
- 但“带五万军队以正式任务身份离开”的现实接口消失。

说明任务层 nx 是真功能。

### 拿掉刘备自己的脱身目的

只保留：曹操命其截袁术 → 刘备执行 → 完成后回许都。

此时事件会显著向纯任务 nx 靠近，说明上位自定方向是独立变量。

### 拿掉曹操强控制压力

如果刘备本来就可自由离开许都，则“借任务脱身”的必要性明显下降；但只要仍使用曹操授予的军队完成截袁术，任务层 nx 仍可成立。

所以压力强化了“为什么要工具化这个接口”，但不是 nx 定义本身。

## 7｜反向测试

### 真正的同层压力显影版本

若材料变成：

```text
刘备原本能自己决定并公开执行“离开许都”
→ 曹操压力直接封住这一同层自主出口
→ 刘备无法再以自身权能完成离许结果
→ 只能承接曹操预设的离许通道
→ 压力解除后同层自主离许权快速复位
```

才更接近“zx 被克后 nx 同层高显影”。

原著不是这个纯结构，因为刘备自己主动发现、设计并工具化外部任务入口。

## 8｜最近邻排除

- `nx vs xn`：任务/兵力入口来自曹操 = nx；如何把它变成脱身计划 = xn。
- `nx vs x`：授权完成后本次出征内部有局部兵权 x，但上位任务来源仍可 nx。
- `zx vs 自有目标`：自己想脱身不等于公开扩权 zx。
- `压力显影 vs 对象分层`：不同对象层一端抬高、另一端仍自主，不能冒充同层阴阳显影切换。

## 9｜第三因素冻结

冻结：

- 刘备忠汉评价；
- 曹操奸雄评价；
- 衣带诏；
- 袁术强弱；
- 后续是否长期占徐州；
- 关张武力。

只保留：

1. 谁生成脱身最终目的？
2. 谁掌握截袁术任务与兵力接口？
3. 刘备是否真实使用该接口？
4. 该接口是否被刘备组织进自己的计划？
5. 被压低的一端与抬高的一端是否属于同一对象层？

结论不变。

## 11｜本轮新增方法护栏

> **压力显影必须优先要求对象层一致：被压力压低的一端与因压力抬高的另一端，应直接作用于同一个当前对象/瓶颈。若只是高层方向仍自定、子任务层 nx 抬高，或主体以 xn 把外部接口工具化，则优先记“对象分层 + nx/xn 共存”，不得凑成“zx 被克后 nx 显影”。**

当前只有这一份直接反向护栏，不建立新的 pending-review，不修改 L1、信息卡、准度卡或补卡。

## 12｜下一证据目标

继续寻找《三国演义》《水浒传》或《红楼梦》的真正第二份同层压力显影：

```text
同一对象层
→ 原端现实入口被强压力封住
→ 对端真实外部功能抬高
→ 压力解除
→ 原端快速复位
```

优先排除“只是不同对象层”“只是自有目标 + 外部子任务”“只是 xn 工具化接口”的伪显影。
