```text
ZN → z → ZX → x并z → N → NZ → XN → NX → XZ → X
```

## 2026-07-30｜x并z 第一轮

【启动记录】  
- starting main SHA：`ecf26ff2e0a2e4de62907502a668211866f4512d`  
- mandatory preflight：`v9.20`  
- 信息卡总览：`v1.2`  
- 涉及端点信息卡：`【x并z信息量卡v2】` 正文 `v2.0`  
- 涉及端点准度卡：`x并z_准度卡_v0.1` 路径正文 `v0.2`  
- 候选：`十元广义本体层候选_v0.1_2026-07-30.md`，status=`pending-absorb`  
- 本轮不审生克补机制，不修改现行 `01-十元系统` 正本。

【本轮对象】x并z 广义候选“壳化接口”。

【当前候选】  
> x并z 是把内部对象、结构或能力映射为稳定外部形式，使外部能够持续识别、进入、调用、归因、代表或保护它。

【去人物测试】通过。  
删去人物、身份欲望、心理、认可、对错与台词后，仍可表述为：`对象与一个公共形式之间建立稳定映射，使第三方可以跨时间、跨场景寻址、识别或调用该对象。` 这一操作不依赖人物领域。需要注意，“内部/外部”是最常见空间隐喻，不是所有领域都必须具有实体内外层。

【跨领域测试】六类通过，其中构图与音乐需防止把普通可见性误当接口。  
1. 人物：姓名、职业、艺名、制服、账号或代理前台，使同一人物跨场景被指认、归因或调用；内外一致与否都不影响主骨。  
2. 人际关系：他人通过称谓、关系身份、联系方式或公开角色找到并进入互动；这只建立关系入口，不自动生成认可、亲密或承载。  
3. 叙事：标题、署名、章节身份、角色代号、反复出现的叙事标签，使复杂内容获得稳定索引和归因入口；单次提及或普通曝光不足。  
4. 构图：反复稳定的轮廓、徽记、框体、色块编码或界面位置可以成为对象的视觉寻址接口；单纯醒目、面积大、居中或好看只是可见性，不是稳定映射。  
5. 音乐：稳定的音色签名、主题动机或声响标识可以让听者跨段落识别角色、阵营、地点或功能；但动机具有重要意义属于 ZN 候选问题，主导全曲属于 ZX/z 邻域，不应混入。  
6. 游戏系统：角色名、职业图标、技能按钮、资源图标、地图入口、存档槽与账号标识，把内部状态、能力或地点映射为可识别、可操作的接口；UI 可用性不等于系统内部承载。  
7. 社会结构：法人、职位、证件、品牌、门牌、登记、官方账号与公共服务前台，使责任、权限、服务与对象可被稳定归因、代表、进入或调用。

【生成测试】通过，且现行人物层与领域载体能由同一操作生成。  
- `稳定映射`生成身份、名称、职位、署名、品牌、作品形式与视觉/声音标识。  
- `第三方可持续寻址`生成现行卡的识别、调用、归因和代表。  
- `接口中介接触`可以生成进入与保护：第三方不必直接暴露或接触内部，而通过受控前台、匿名接口、代理或包装发生互动。  
- 伪装与内外不一只是映射内容与对象真实状态不一致的高张力子型，不是必要条件。  
- “保护”不是每个 x并z 都必须出现的独立必要条件，而是接口控制暴露方式时产生的功能结果；“进入”同样是部分接口的功能，不应反写成所有壳都必须允许进入。

【最近邻排除】  
- x并z vs 普通可见性：可见只要求被看到；x并z要求外部形式与对象之间存在稳定、可重复的指认或调用映射。  
- x并z vs ZX：x并z建立公共接口；ZX要求对象自身权能外部有效并迫使周围结构重排、决定范围扩大。职位、徽章和公开账号可以有壳而无显权。  
- x并z vs z：x并z使认可对象可被找到和归因；z 的现行人物层还要求重要认可位置完成确认。曝光、署名与舞台不是认可本身。  
- x并z vs X：X回答对象、资源、权限或关系归谁掌握；x并z回答外界通过什么形式指认、调用或代表该掌握。门牌不等于所有权，所有权也不自动生成公共接口。  
- x并z vs N：x并z提供外部可读入口；N要求内部真实接收、处理和承担负荷。漂亮界面可以连到空壳，强承载系统也可以没有友好接口。  
- x并z vs XN：目录、名册、账号和记录只有在构成公共身份或调用接口时偏 x并z；若核心是顺序、保存、续期和跨阶段运行，偏 XN。

【拿掉测试】  
1. 拿掉视觉包装、面具、服装、欺骗与秘密，若名称、制度身份、署名、接口或稳定标识仍可供第三方寻址，x并z 仍成立。  
2. 拿掉稳定映射，只保留一次曝光、一次换装、一次签署、一次口令或短时醒目，跨场景指认与调用消失，不能判稳定 x并z。  
3. 拿掉第三方可寻址性，只剩对象自称、内部分类或无人能调用的私有标签，不足以生成现行公共壳。  
4. 拿掉“进入”功能，纯归因型署名、作品标题、视觉标识仍可成立；因此进入不是普遍必要条件。  
5. 拿掉“保护”功能，真实姓名、公开职位、品牌和普通 UI 仍可成立；因此保护不是普遍必要条件。

【反向测试】  
1. 对象高度可见但每次形式不同、无人能稳定归因，只是曝光或视觉显影，不是稳定 x并z。  
2. 对象完全不公开，但通过匿名账号、代理前台或受控 API 可被稳定调用与归因，仍可成立保护型 x并z；公开可见不是必要条件，公共可寻址才是。  
3. 权能公开生效并迫使环境重排，但没有稳定身份、名称或调用映射，优先 ZX，不自动判 x并z。  
4. 有稳定名称和接口但无人认可、关系不亲密、内部也不承载，x并z 仍可独立成立。  
5. 一次口令或签署中断只影响当次互动，不能证明稳定壳整体下降；须先区分事实索引壳、制度壳、构成性认证壳、持续表演壳与单次令牌。

【证据变化判断】  
本轮没有击穿候选核心。“稳定外部映射”能稳定生成现行信息卡与准度卡，并跨人物、叙事、构图、音乐、游戏与社会结构复现。出现的是两项边界收紧而非替代定义：  
1. 更高层的共同核应优先表述为`建立稳定公共寻址/代表映射`；“壳”与“内部—外部”是主要显影模型，不是所有领域的实体必要条件。  
2. 识别、调用、归因、代表是主干功能；进入与保护是特定接口的条件性功能，不能逐项设为所有 x并z 的必要条件。  
候选原文已使用“映射为稳定外部形式”并以“或”连接功能列表，尚未被反例击穿，因此不足以触发候选文件升版。

【本轮结论】  
- 候选文件：`v0.1 → v0.1`，不升版。  
- “壳化接口”保留为工作名；调用时优先召回：`对象与公共形式建立稳定映射，使第三方能够跨时间、跨场景寻址、识别、归因、代表或调用对象。`  
- “外部可见”不是必要条件，“公共可寻址”才是核心；匿名接口也可成立。  
- “进入、保护、伪装、内外不一”全部保留为条件性功能或子型，不上提为普遍必要条件。  
- 状态：`pending-absorb / 待二审`。

【最低置信项】  
构图与音乐中的稳定映射仍容易被解释者事后赋码。后续需要预注册：映射形式、被映射对象、第三方识别者、跨段落/跨场景窗口，以及识别或调用失败时的可观察下降；否则只能算视觉或听觉联想。

【下一审议点】  
按轮转审议 N“内部承载”。重点检查“进入内部、获得持续位置、由结构处理长期负荷”是否能跨叙事、构图、音乐、游戏和社会结构成立，并排除普通容纳、暂存、背景存在、x并z 的入口接口与 XN 的持续流程。
