# 运行记录｜孙悟空被逐后回归：关系恢复 与 追溯撤销边界

## 结论先行

本轮不重复创建“孙悟空三打白骨精被逐”人物正式案例，而是复用已有 99/98 `evidence-locked` 案例，专门检查当前待审议下一步要求的 C 类结构：

> **一个已经生效的决定，后来关系恢复，是否就等于原决定被追溯撤销？**

结论：**不等于。**

第二十七回唐僧逐走孙悟空以后，逐出决定当时真实生效：孙悟空接贬书、离开取经队伍、返回花果山。第三十一回出现的新结构则是：唐僧已经遭遇新的重大危机，八戒重新赴花果山求援，孙悟空自主决定回援，救回唐僧并恢复同行。原“逐出期间”并没有被追溯判定为无效，也没有出现“此前离队从未成立”的制度性回滚。

因此本轮锁定：

```text
关系/职位/许可后来恢复
≠
先前处分被追溯撤销
```

本轮不锁新的稳定人物本体，不锁严格 `zx↔nx` 补关系。

## 1｜剧情事实

### 1.1 原处分先真实生效

第二十七回中，唐僧最终写下贬书并明确解除孙悟空当前徒弟/同行关系。孙悟空虽反复申辩、不愿离开，最终仍接下贬书并实际离队。

已有正式案例已锁：在“是否继续作为徒弟同行”这一窄关系对象层，孙悟空最终接受唐僧的关系处分，因此 `nx_current_relation_position` 与 `nx_behavior_function_in_expulsion_stage` 成立。

### 1.2 中间存在真实离队阶段

孙悟空不是当场转身又继续同行，而是实际回到花果山；取经队伍在没有他的情况下继续前进，并先后遭遇黄袍怪、唐僧被变虎等新危机。

这说明原逐出不是一句没有现实效力的口头话，而是真正改变了关系与队伍结构一段时间。

### 1.3 后来发生新的条件与新的接入动作

第三十一回，八戒专程回花果山请求孙悟空援救。孙悟空一开始并不把“重新加入”当成已经自动恢复，而是经过新的信息、关系劝说与激将以后决定回去救师父。

他回援后主动降黄袍怪、查奎木狼，并使唐僧恢复原身。

### 1.4 唐僧随后重新接受孙悟空继续同行

唐僧恢复原身后认出孙悟空，听沙僧说明求援、降妖、救师全过程，对孙悟空感谢并称其为“贤徒”，随后四众重新一同西行。

因此后段发生的是：

```text
旧逐出真实生效
→ 中间离队期真实存在
→ 新危机与新求援出现
→ 孙悟空重新回援
→ 唐僧重新接受其徒弟/同行位置
→ 关系恢复
```

而不是：

```text
旧逐出真实生效
→ 更高节点事后宣布旧逐出自始无效
→ 离队期间在制度上被抹除
→ 原关系状态追溯恢复
```

## 2｜nx 判断

### 2.1 原被逐阶段 nx 结论不被后来的恢复冲掉

已有正式案例锁定：唐僧撤回当前师徒/同行许可后，孙悟空虽然不同意，但最终接受处分并离开，因此当时关系位置存在 `nx`。

第三十一回重新同行，不能倒推成：

> “既然后来又回来了，所以第二十七回其实从来没有真正被逐。”

这是把后续新关系状态倒灌回旧阶段。

### 2.2 后来恢复关系不自动说明旧处分存在可追溯撤销权

本轮只锁边界：

```text
后来重新接纳
≠
以前的退出决定被追溯撤销
```

要证明真正 C 类，必须看到上级/关系主体对已经生效的旧决定作出具有回溯效力的撤销，使旧结果在权限上失效或恢复原状。

本例没有。

## 3｜zx 判断

第三十一回孙悟空回援、降妖非常主动，也有强战斗显影，但本轮不因此新增 `zx` 分类。

当前研究对象是“关系处分是否被追溯撤销”。孙悟空救师成功并没有让他取得一个新的“任何时候都不可被逐”的稳定关系处分权，也没有让唐僧失去以后解除师徒关系的资格。

因此：

`zx_in_reinstatement_boundary_question: not_newly_locked`

强能力与重大救援结果不替代权限回溯结构。

## 4｜关键压力

新条件包括：

- 唐僧被黄袍怪变虎；
- 沙僧被擒；
- 白龙马受伤；
- 八戒主动赴花果山求援；
- 孙悟空重新提供不可替代的降妖能力。

这些条件都在第二十七回原逐出之后出现。

所以本例最关键的纪律是：

> **如果后来的“恢复”发生在明显的新条件、新请求或新交换结构下，必须先检查它是不是重新授权/重新接纳，而不是把它误写成追溯撤销。**

## 5｜拿掉测试

### 拿掉黄袍怪危机

如果唐僧并未遭遇新的危机，八戒没有重新求援，孙悟空也没有重新返回，那么后续关系恢复的触发链直接消失。

这说明后段恢复高度依赖新条件，而不是一个无条件的“旧处分自始错误并回滚”。

### 拿掉中间真实离队期

如果唐僧写贬书后立刻收回、孙悟空从未真正离队，那才更接近“原处分未完成生效/即时撤回”。实际文本不是。

### 拿掉唐僧重新称贤徒并继续同行

若孙悟空只是临时救援，救完仍回花果山，则连“关系恢复”都不能锁。

因此当前证据足以锁“重新接纳”，但不足以锁“追溯撤销”。

## 6｜反向测试

真正的 C 类反例应更强：

```text
原处分/任命/许可已经生效
→ 更高或同级合法撤销节点后来明确宣布该原决定无效/撤销
→ 原对象、职位、资源或许可被恢复
→ 恢复不是一次新的重新申请/新条件下重新授予
```

例如：

- 已生效处分被正式撤销并恢复原职位；
- 已生效许可取消被上级复核撤销，许可恢复；
- 已完成的局部任命被法定上级追溯撤销，原任职状态恢复。

孙悟空本例不满足，因为它是**新危机后的重新接纳**。

## 7｜最近邻排除

### 重新接纳 vs 追溯撤销

```text
重新接纳：旧状态真实结束，后来建立一个新的有效关系状态。
追溯撤销：旧决定本身被更高权限宣布失效/回滚。
```

本例属于前者。

### nx vs nz

师徒感情、孙悟空“身回水帘洞，心逐取经僧”、一日为师终身为父，都说明关系价值很高，可作为 `nz` 邻近材料；但本轮不越轴正式锁水轴。

### nx vs x

孙悟空没有因此取得师徒关系的最终单方处分权；唐僧重新接受他，也不等于该关系许可从此稳定归孙悟空掌握。

### xn

八戒激将、孙悟空降妖策略属于行动组织邻近，不回答“旧处分是否被追溯撤销”。

## 8｜第三因素冻结

冻结：

- 孙悟空战斗力；
- 黄袍怪强弱；
- 唐僧是否应当道歉；
- 八戒是否说谎激将；
- 师徒感情深浅；
- 后续取经成功；
- 孙悟空稳定 `zx+nx` 锚。

只看：

```text
旧处分是否真实生效？
中间状态是否真实存在？
后来是“撤销旧决定”还是“新条件下重新接纳”？
原决定是否被赋予回溯失效效果？
```

## 9｜对 pending-review 的增量

当前“nx：事前批准 与 事后回报边界”在寻找 C 类反例时，必须新增一道排除门：

```text
C1｜真正追溯撤销
旧决定被撤销/判失效
→ 原对象状态恢复
→ 可说明更高最终权限仍存在

C2｜重新授权 / 重新接纳 / 新任命
旧决定曾真实有效
→ 后来条件变化后建立新状态
→ 不能冒充追溯撤销
```

本轮正式增加 C2 负控制。

## 11｜本轮最小结论

> **恢复 ≠ 撤销。**
>
> 一段关系、职位或许可后来重新建立，只能证明“现在又有效”；除非文本明确证明旧决定本身被追溯判失效并发生回滚，否则不能把“重新接纳/重新授权”冒充 C 类追溯撤销。
