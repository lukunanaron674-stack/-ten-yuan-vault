# 待审议｜strict zn↔x 中 x 是否为 zn 不可替代现实落点的边界

## 1｜当前状态

strict 压力测试已从“只有反例”推进到：

```text
1 positive control / 1 work
+
4 negative guards / 3 works
+
2 strict-precondition guards
```

仍为 L4 `pending-review`，不得自动改写 L2 `zn补x_补卡`。

## 2｜首份 strict 正向｜诸葛亮卤城换班｜99/95

被测对象层：诸葛亮对直属蜀军换班、留营、放行的现实军令/处分边界。

### zn

窄原则：

> **对直属军队已经由自己正式发布并形成期待的轮换军令，主帅不得因为临时战术利益单方破例；统军信用反过来约束掌令者本人。**

魏军急攻时，多留四万熟兵显然更有即时战术利益，但诸葛亮仍坚持既有轮换令，原则真实进入冲突排序。

### x

`x` 不是“丞相”头衔，而是：

- 可设定轮换；
- 决定留营或放行；
- 军令由杨仪与全军现实执行；
- 魏军急攻时，“是否留下四万应换班军”直接交由诸葛亮裁决。

所以当前留放处分 `x=true`。

### zn→x

拿掉该 `zn`，`x` 仍成立，但失去一个可命名缺口：

> **已经对部属形成确定期待后，什么时候即使有权强留也不应强留；临时军情能否无限覆盖已发布军令信用。**

因此 `zn→x=true`。

### x→zn

拿掉被测 `x` 后，原则作为抽象“统军应守信”仍可存在，但本轮窄原则会失去不可替代现实结构：

```text
我的直属军队
+
由我发布并可由我保持/撤回的轮换军令
+
我现实决定强留还是放行的对象
```

本窗口没有刘禅、杨仪或其他节点能够等价提供这组“我方直属军队—我的军令—我的留放处分对象”关系；士兵后来自愿留下发生在诸葛亮先决定放行之后，也不能倒填为 `x` 来源。

因此首份正向锁定：

```yaml
zn_to_x_gap_filling: true
x_to_zn_gap_filling: true
strict_zn_x_complement_locked: true
```

## 3｜首份正向带来的边界修正

此前 4 份负控制让“不可替代现实落点”门变得很硬；诸葛亮说明这道门不是“不可能通过”，但必须满足一个更窄的结构：

> **`zn` 的命题本身就索引到“我的某项现实 `x` 边界”，而不是只把该 `x` 当作原则执行工具。**

因此现在要区分：

```text
执行接口型 x
→ 拿掉后 zn 还能通过别的对象/行为落地
→ strict x→zn 失败

对象构成型 x
→ 被测 zn 本身规定“我如何对待我所掌握的这一对象/权限”
→ 拿掉该 x 后，原则失去其当前不可替代对象结构
→ strict x→zn 可成立
```

这只是 L4 候选边界，不自动升格为 canonical。

## 4｜既有 strict 负控制｜4 controls / 3 works

### 关羽｜资源 x
旧义 `zn→x=true`；曹赐资源不是旧义不可替代现实落点，拿掉后仍可通过归刘、护送二夫人、离曹行动落地。

### 晁盖｜组织武力 / 处分 x
“不伤无关者”原则限制山寨处分 `x`，但拿掉该 `x` 后原则仍可指向客商、百姓并约束晁盖自身。

### 唐僧｜关系处分 x
“不轻伤人命”原则可约束师徒处分 `x`，但拿掉该关系权限后仍可约束唐僧自身和其他现实生命对象。

### 严颜｜真实 x 丢失生命周期旁证
巴郡军政 `x` 真正失去后，拒绝威逼屈降 `zn` 仍继续排序，说明该 `x` 不是不可替代落点。

共同护栏：

> **`x` 能帮助、扩大、便利或强化 `zn` 的现实执行，不等于 strict `x→zn`。**

## 5｜strict 前置门｜新增两类护栏

### 跨阶段端点洗钱｜刘备｜99/98
徐州 pure-x 与长坂 pure-zn 分属不同阶段、不同对象层；两个强端点不能因为“都是刘备”就拼成共现或 strict。

### 第三方否决结果对齐｜鸳鸯｜99/98
鸳鸯 `zn=true`，最终强纳结果也与原则同向，但现实否决由贾母完成；主体婚姻关系 `x` 未独立过门，因此 strict 不允许启动。

strict 合法启动门至少为：

```text
same_current_window
+
same_object_layer
+
zn independently true
+
x independently true
+
result causality belongs to tested x
+
no equivalent third-party veto / anchor
```

## 6｜当前反误判纪律

- co-occurrence ≠ strict。
- 同一人物跨阶段的两个强端点 ≠ 当前共现。
- 最终结果与 `zn` 同向 ≠ 主体拥有使结果生效的 `x`。
- 第三方现实否决必须归第三方。
- 原则保护/评价谁 ≠ 谁必须进入主体 `x`。
- `x` 扩大原则执行范围 ≠ `x→zn`。
- 现实执行接口 ≠ 不可替代现实落点。
- 首份 strict 正向不能反过来降低后续门槛；99/95 只说明该窄对象结构值得复验。
