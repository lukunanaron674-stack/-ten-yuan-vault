# 刘备权领徐州｜第三份 pure x 控制

## 1｜本轮只测试什么

本轮不重复“牌印/官民推举 ≠ 现实 x”的旧用途，只复用同一最小差异材料，测试：

> 刘备真正接受“权领徐州事”以后，徐州军政治理 `x` 能否独立成立，而不需要额外假设一个当前治理窗口的 `zn`？

结论：**可以。** 本轮只锁窄治理对象层，不判刘备稳定人物本体。

## 2｜剧情事实

陶谦死后，徐州官员捧牌印、百姓哭拜推举，刘备仍先固辞。之后刘备明确同意“权领徐州事”，文本立即给出现实治理动作：

- 使孙乾、糜竺为辅；
- 以陈登为幕官；
- 尽取小沛军马入城；
- 出榜安民；
- 处理陶谦丧事并申奏朝廷。

因此阶段B不是只有名位，而是现实治理节点开始围绕刘备的决定运行。

## 3｜x 证据

current `x` 必须看到：对象明确、主体明确、权限类型明确，而且不是纯名义或一次接触。

本例被测对象：徐州军政 / 治理范围。

```text
刘备真实接受权领徐州
→ 可配置辅佐/幕官
→ 可调入军马
→ 可发布安民命令
→ 现实行政节点响应
→ 徐州治理对象进入直接调用/调配/处分边界
= x
```

拿掉“皇叔”“仁义”“百姓拥戴”“牌印”这些名义/认可因素，只保留真实用人、调兵和命令生效，`x` 仍成立。

## 4｜为什么本轮不锁 zn

当前治理窗口里，刘备接州可以同时由百姓安危、现实责任、政治收益、汉家城池、官民推举等多种因素解释。现有窄桥段不足独立证明某一原则同时通过：

- 无奖励/认可仍进入判断；
- 冲突中保有最终排序资格；
- 跨阶段保留未来调用资格；
- 有明确边界和让渡代价。

因此本轮记录：

```yaml
x_current: true
zn_current: not_locked
```

`not_locked` 只针对这个治理窗口，不等于刘备其他阶段没有 `zn`。

## 5｜拿掉与反向测试

### 拿掉外部承认/牌印

只保留：

```text
刘备已经实际接管
+ 用人
+ 调兵
+ 安民命令现实生效
```

徐州治理 `x` 仍成立。

### 拿掉现实掌握动作

若只有牌印、推举、称号，却不能用人、调兵、发令，或每一步都必须重新请示原节点，则不锁稳定 `x`。

### 反向

若要把当前窗口升级为 `zn+x`，必须另证一项内部不可轻易让渡原则，在拿掉官民认可、职位收益和当前政治利益后仍能进入冲突排序。当前材料不足。

## 6｜最近邻排除

- `x vs z`：官民推举属于外部认可，不是本轮 `x` 支柱；
- `x vs nx`：权力入口来自陶谦/徐州体系，不妨碍接管后治理对象形成局部现实 `x`；
- `x vs xn`：如何配置人员与流程是 `xn` 邻近，但“这些对象当前归谁直接调配”仍是 `x`；
- `x vs zx`：接管既有治理位置不因规模大自动等于主动扩权；
- `x vs zn`：治理责任、政治理由和仁义评价都不能自动生成内部最终原则。

## 7｜第三因素冻结

冻结：刘备仁义/虚伪评价、皇叔身份、百姓拥戴、陶谦评价、后续守徐州成败。

只保留：

```text
被测治理对象明确
+ 直接调兵/用人
+ 命令现实生效
+ 行政节点响应
```

`x` 结论不变。

## 8｜与前两份 pure x 的机制差异

```text
《红楼梦》刘姥姥：
私人物品/资源完成交付 → 直接占有与处分 x

《西游记》孙悟空：
公共职事真实接管 → 园务管理 x

《三国演义》刘备：
稳定地区军政治理真实接管 → 治理/权限 x
```

三种机制共同支持：

> **`x` 可以独立成立，不需要附带一个宏大 `zn`；真正证据是具体对象进入主体稳定的实际掌握、调用或处分边界。**

同时保留：

> **资源用途、工作职责、治理责任、身份名位与外部认可，都不能自动补出 `zn`。**
