# xz ↔ nz 水轴方法卡｜跨对象层可共存，但同 scope 不得互相倒灌 v0.1

## 0｜本轮只解决一个问题

本轮不继续堆“路径变少”案例，只压组合层缺口：

> 同一事件中，如果高层对象正在发生 endpoint-governed xz 收束，而局部对象特异关系仍保存真实 nz 回返空间，两端能否同时成立？

结论：

```text
YES, if and only if tested scope differs.

same sentence
+ different object_layer / object token / relation ledger
→ xz and nz may coexist
→ MUST SPLIT_IR
```

但：

```text
local nz return path
≠ escape path from global xz endpoint

global xz endpoint
≠ proof that local nz relation is closed
```

新增 guard：

```text
WATER-SCOPE-SEPARATION-GATE-v0.1
GLOBAL-XZ-LOCAL-NZ-SPLIT-IR-GATE-v0.1
NO-CROSS-LAYER-EVIDENCE-BACKFILL-v0.1
```

水轴“相反”必须在相同 tested scope 上解释；不能把一个对象层的 xz 和另一个对象层的 nz 强行做成零和。

## 2｜完整 IR

本轮采用“旧平台整体退役 + 特定合作关系仍可恢复”的结构化压力测试，不冒充外部事实。

```yaml
actor:
  system_actor: 平台迁移系统A
  relation_actor_A: 开发者甲
  relation_actor_B: 开发者乙

object:
  global_object: 旧生产平台P_old
  local_object: 甲↔乙的对象特异协作关系R_ab

object_layer:
  xz_layer: global_operational_return_space_to_P_old
  nz_layer: bilateral_reentry_and_repair_space_of_R_ab

current_window:
  shared_window:
    migration_T1
    -> migration_T2
    -> decommission_cutoff

changed_variable:
  xz:
    - independent_return_paths_to_P_old
    - endpoint_binding_strength
    - convergence_to_decommission_cutoff
  nz:
    - bilateral_reentry_eligibility
    - object_specific_return_path
    - reciprocal_response_capacity
    - repair_capacity

relation_source:
  xz:
    fixed_decommission_endpoint_progressively_invalidates_old_platform_return_paths
  nz:
    standing_bilateral_reentry_protocol_preserves_repairable_return_to_R_ab

relation_shape:
  xz:
    multiple_platform_return_paths
    -> progressively_expire
    -> same_decommission_cutoff

  nz:
    A_or_B_exit
    -> qualified_bilateral_reentry_path
    -> mutual_consent
    -> repair_and_resume_R_ab

decision_right:
  xz:
    operators may choose among remaining platform paths
    but cannot cancel the binding decommission endpoint
  nz:
    A and B each retain free accept/refuse rights
    neither side can unilaterally fabricate mutual reentry

path_set:
  xz:
    - snapshot_restore_to_P_old
    - switchback_to_P_old
    - legacy_redeploy_to_P_old
  nz:
    - direct_recontact_for_R_ab
    - qualified_mediation_for_R_ab

reentry_right:
  xz:
    decreases as P_old return classes expire
  nz:
    remains nonzero and bilateral for R_ab during the tested window

future_endpoint:
  xz:
    P_old_decommission_cutoff
  nz:
    no forced terminal endpoint inside R_ab itself;
    relation may exit and reenter by mutual choice

reality_anchor:
  - P_old 的真实回退路径按同一退役终点持续失效
  - 换平台回退方案仍绕不开同一退役 cutoff
  - 甲乙关系曾真实成立
  - 甲乙均可自由退出，不因退出永久失去对象特异重入资格
  - 甲乙存在现实可执行的重入与修复路径
  - 甲乙恢复协作并不能让 P_old 退役终点失效
  - P_old 退役也不能自动证明甲乙协作关系永久关闭
```

判定：

```text
IR-XZ(global platform layer): PASS / strong candidate
IR-NZ(local bilateral relation layer): PASS / stable candidate
whole sentence: SPLIT_IR REQUIRED
```

最小差异变量不是事件内容，而是：

scope_resolution

## 4｜最小判别式

```text
IF
xz evidence targets object_layer_A
AND
nz evidence targets object_layer_B
AND
A != B in the tested return relation

THEN
run independent water ledgers
AND
SPLIT_IR
AND
forbid mutual erasure
```

更具体：

```text
local nz may negate global xz
ONLY IF
its return path actually bypasses / cancels / reopens
that same global future endpoint.
```

```text
global xz may negate local nz
ONLY IF
its endpoint actually closes the same object-specific bilateral
reentry/repair relation being tested.
```

短式：

> **一条“还能回来”的路，必须先问回来的是哪个对象；一个“必然收束”的终点，也必须先问它收束的是哪一层。**

## 5｜removal tests

### Removal A｜拿掉局部 nz

保留 P_old 的：

```text
fixed endpoint
+ path narrowing
+ convergence
+ critical approach
```

但让甲乙对象特异协作重入资格归零。

结果：

```text
xz(global) remains PASS
nz(local) -> OFF
```

证明 global xz 不依赖 local nz。

### Removal B｜拿掉 global xz

取消 P_old 的强制退役 cutoff，让各回退路径长期稳定存在。

同时保留甲乙：

```text
bilateral reentry
+ reciprocal response
+ repair capacity
```

结果：

```text
xz(global) -> insufficient/OFF
nz(local) remains PASS
```

证明 local nz 不依赖 global xz。

### Removal C｜保留“还能联系”，拿掉 relationship reentry

甲乙仍可聊天，但不能回到原对象特异协作位置。

结果：

```text
nz(local) -> FAIL
xz(global) unchanged
```

再次锁定 contact ≠ nz。

## 6｜reverse test

### Reverse A｜让局部 nz 真正成为 global xz 的逃逸路径

如果甲乙恢复协作后，现实上获得一条：

```text
可永久绕开 P_old decommission cutoff
+ 恢复同一 global object layer
```

的新路径，则它不再只是 local nz 证据，而会进入 global xz 的 `path_set` 审计。

此时：

```text
如果该路径真正独立且长期绕开 endpoint
→ global xz 必须下降
```

说明“local nz 不影响 global xz”不是绝对规则，而是 scope 规则。

### Reverse B｜让 global endpoint 真正关闭 local relation

如果平台退役同时现实取消甲乙在 R_ab 上的：

```text
重入资格
互相回应资格
修复位置
```

且不存在替代关系载体，则：

```text
nz(local) 必须下降/OFF
```

也就是说，两端只有在 endpoint 真正跨层作用到同一 tested relation 时才发生直接冲突。

## 8｜positive / negative controls

### Positive control P1｜制度域

```text
某许可证体系将在法定日整体废止（global xz）
但某两机构之间的合作协议允许双方自由退出、重新加入并修复协作（local nz）
```

若合作重入不能取消许可证体系废止：

```text
xz + nz across layers
→ SPLIT_IR
```

### Positive control P2｜创作流程域

```text
项目版本已进入不可逆 final-lock 收束（project-layer xz）
但导演与某画师之间仍保留对象特异的返工合作入口和修复机制（relation-layer nz）
```

只要返工关系不能重开已锁死的项目版本：

```text
两端可并存
```

### Negative control N1｜假 nz 逃逸

```text
甲乙还能聊天
```

但聊天不能恢复 P_old，也不能恢复 R_ab 原协作位置。

→ 既不能削弱 global xz，也不能锁 stable nz。

### Negative control N2｜global xz 误杀 local nz

```text
平台必然退役
```

但甲乙可以在新平台继续原对象特异关系并自由退出/回返/修复。

→ 不得因平台 xz 自动判关系 nz OFF。

### Negative control N3｜同 scope 真冲突

如果声称：

```text
同一 P_old 回退空间
一方面所有路径持续汇流至不可绕开的退役终点
另一方面存在长期稳定、自由可回的同一 P_old 路径
```

则不能简单同时 PASS。

必须触发：

```text
SAME_SCOPE_WATER_CONTRADICTION_AUDIT
```

核查“稳定回返路径”是否真的绕开 endpoint；若是，xz 应下降；若不是，则它不是有效 nz/global-return evidence。

## 9｜失败类型

```text
GLOBAL_XZ_ERASES_LOCAL_NZ
整体收束直接抹掉局部对象特异回返

LOCAL_NZ_ERASES_GLOBAL_XZ
局部关系还能回来就否定整体终点收束

SAME_SENTENCE_SINGLE_WATER_LEDGER
同一句含两层返回结构却只建一个IR

SHARED_WINDOW_AS_SHARED_OBJECT_LAYER
时间窗相同就误认为对象层相同

LOCAL_RETURN_AS_GLOBAL_ESCAPE
局部回返路径被错算成绕开全局终点的路径

GLOBAL_ENDPOINT_AS_LOCAL_RELATION_CLOSURE
全局终点被错倒推成局部关系永久关闭

CROSS_LAYER_EVIDENCE_BACKFILL
一个object_layer的证据倒灌给另一个layer

SAME_SCOPE_DOUBLE_PASS_WITHOUT_AUDIT
同一scope同时强判xz+nz却不做矛盾审计

MEMORY_AS_LOCAL_NZ
仍记得/纪念对象被误当现实回返空间

DEADLINE_AS_GLOBAL_XZ
只有截止日名词而无路径收窄、汇流与临界逼近
```
