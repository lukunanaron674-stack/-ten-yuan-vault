# 候选关系可观察化与用户判别接口协议 v1.0

## 1. 协议目的

候选三元、十元关系不得直接以抽象术语向用户提问。

以下问法禁止直接作为用户判定题：

```text
A 是否生 B；
A 是否克 B；
A 是否补 B；
这是生成、显影、放大、放行还是诱发；
双方是否真正互补。
```

原因是这些问题要求用户同时完成：

```text
对象分层；
端点判定；
因果归属；
第三因素排除；
时间前后比较；
关系方向判断；
术语映射。
```

这些工作应由研究流程先完成，不得把未完成的理论劳动转嫁给用户。

## 2. 正式研究顺序

每条候选关系必须按以下顺序运行：

```text
1. 锁定源端点与目标端点；
2. 分开人物本体、当前状态、具体行为、关系位置、场景限制、时间阶段与光影显影；
3. 找到关系介入前的目标基线；
4. 找到关系介入后的目标变化；
5. 检查目标是否原本已存在；
6. 检查变化是否只出现在特定关系、场景或时间窗口；
7. 排除权力差、资源差、威胁、疲劳、信息不足、创伤与剧情强制等第三因素；
8. 执行拿掉测试与替代解释测试；
9. 形成两个以上具体、互斥、可观察的解释；
10. 只有在仍存在关键歧义时，才向用户提交最小判别题。
```

不得跳过前九步，直接要求用户判断抽象关系。

## 3. 可观察化标准

抽象关系必须被改写为人物层面的可观察差异。

合格问题必须满足：

```text
用户不需要理解“生克补”术语也能回答；
两个选项描述的是不同的人物运行方式；
选项之间尽量互斥；
选项不混合人物本体与暂时状态；
问题指向具体阶段、具体关系对象或具体行为；
问题允许回答“都不像”或“证据不够”。
```

不合格：

```text
nx 生 x 是真正生成深欲，还是只是不阻止原有 x？
```

合格：

```text
这个人物在长期把选择交给别人以前，是否已经稳定表现出强烈欲望？

A. 以前已经存在，只是后来更明显；
B. 以前没有，长期让渡选择后才逐步形成；
C. 只在某次受压场景中短暂爆发；
D. 现有材料无法区分。
```

## 4. 五类机制的操作性区分

### 4.1 生成

```text
关系介入前：目标结构长期不存在或证据显著不足；
关系介入后：目标结构逐步建立；
离开单一场景后：目标仍可持续；
替代因素：不足以解释变化。
```

### 4.2 显影

```text
关系介入前：目标已经存在；
关系介入后：目标更容易被看见；
目标核心结构：没有被关系创造。
```

### 4.3 放大

```text
关系介入前：目标已经存在；
关系介入后：目标体量、频率或作用范围增加；
离开关系后：可能回落，但不等于消失。
```

### 4.4 放行

```text
源端点没有阻止目标运行；
但没有证据证明源端点创造或增强了目标；
拿掉源端点后，目标仍可能按原强度运行。
```

### 4.5 状态诱发

```text
目标只在特定关系、场景、时间窗口或压力条件下出现；
离开该条件后明显恢复；
不得上升为人物稳定本体变化。
```

## 5. 生、克、补的最低可观察要求

### 5.1 生

必须观察到：

```text
源端点介入
→ 目标内部结构建立或稳定增加
→ 变化不能仅由显影、放行或第三因素解释。
```

### 5.2 克

必须观察到：

```text
源端点介入
→ 目标原有运行变量持续下降、受阻或失去关键接口
→ 不是目标主动退出、暂时沉默或场景无机会显影。
```

### 5.3 补

必须观察到：

```text
目标单独运行时存在稳定缺口；
源端点提供了该缺口所需条件；
加入源端点后，目标完成度提高；
源端点不是仅仅服从、陪伴、共现或被带走。
```

双向互补还必须分别通过两个方向的拿掉测试。

## 6. 拿掉测试

每条关系至少回答：

```text
拿掉源端点后，目标变化还会不会同样发生？
拿掉目标端点后，源端点是否仍以同样方式运行？
换成另一种关系对象，变化是否仍然出现？
变化是跨场景持续，还是只在当前场景成立？
变化落在人物本体、状态、行为、关系位置、时间阶段还是光影显影？
```

若拿掉源端点后结果基本不变，不得判“生”或“补”。

若目标只是沉默、不接招或暂时退让，不得自动判“克”。

## 7. 用户判别接口

只有当研究者已经把问题压缩到两个或三个具体人物解释，且任一解释仍有超过 5% 的可能被用户否定时，才提交用户判别。

用户判别题必须采用：

```text
具体人物；
具体阶段；
具体关系对象；
具体可观察差异；
最少选项；
允许“都不像”。
```

推荐格式：

```text
这个人物更像：

A. 原本就有该倾向，只是当前关系让它更明显；
B. 原本没有，当前关系逐步改变了他的稳定处理方式；
C. 只在这个场景里暂时如此；
D. 都不像／证据不够。
```

用户只负责人物感觉与边界校准，不负责替研究流程完成因果证明。

## 8. nx 四条待审关系的当前接口

以下关系继续保持未确认：

```text
nx 生 x；
nz 生 nx；
nx 克 x并z；
zx 与 nx 互补。
```

它们不得直接以抽象术语询问用户，必须分别转换为：

```text
nx 生 x：原有欲望显影／放行，还是长期让渡选择后形成新欲望；

nz 生 nx：安全关系中的暂时依赖，还是跨关系持续的选择外包方式；

nx 克 x并z：包装失去施力接口，还是人物因不主动判断而被包装带走；

zx 与 nx 互补：nx 是否提供 zx 单独运行时真实缺失的完成条件，还是仅跟随既定方向。
```

上述四条目前只构成研究分叉，不构成关系结论。

## 9. 人物核心锚点规则

故事和剧本研究中：

```text
人物稳定本体优先保持；
变化优先记录到状态、行为、关系位置、场景限制、时间阶段、光影显影与动态链；
单次服从、依赖、沉默、失败、跟随或不接招，不得直接改写人物核心；
只有跨阶段、跨场景、跨关系对象持续主动反向选择，并达到人物本体层 C-A，才允许提出核心变化。
```

三元与十元必须并行判断，不得互相代答，也不得写成父子派生关系。

## 10. 当前冻结结论

```text
抽象候选关系不得直接交给用户判定。
研究流程必须先完成对象分层、基线比较、第三因素排除、拿掉测试与替代解释测试。
用户只处理已经可观察化的最小人物差异。
生成、显影、放大、放行和状态诱发必须分开。
人物本体优先稳定，变化优先落在状态、关系、场景、时间、光影与动态链。
nx 四条候选关系继续保持未确认，不因本协议获得正式生克补资格。
```
