# 24小时自主巡航计划

## 核心理念

不是让 Codex 24小时乱跑内容，而是让它每天跑数据清洗、语义训练、缺口发现、任务生成、归档自检。

## 六大固定工位

| 工位 | 目标 | 输出 |
|------|------|------|
| 1. 数据体检 | 扫空文件/重复/YAML缺字段/路径错误 | `data_audit.md` |
| 2. 语义样本 | 从库中抽十元片段生成弱标签 | `pending_review.jsonl` |
| 3. 废矿清理 | 标记重复/低价值/过时 → 降权不移除 | `delete_candidates.md` |
| 4. F12任务生成 | 根据缺口生成下一批 task | `tasks_next.txt` |
| 5. 归档承载 | 每5轮生成 CarryPacket | `carry_packet.md` |
| 6. 自我优化 | 完成率/废话率/重复率/污染风险自检 | `self_review.md` |

## 安全铁律

1. 不直接删除 → 只生成 delete_candidates
2. 不直接写 gold_dataset → 只写 pending_review
3. 不直接改核心十元理论 → 只生成 proposed_changes
4. 不直接推 main → 只开实验分支或 handoff
5. 检测重复/空输出 → 停止
6. 每天必须生成 daily_report

## cruiser-daemon.js 设计

- 纯 Node 内置模块（fs/path/http），不依赖 npm
- 每 10-15 分钟一轮
- 心跳每 5 分钟写 `heartbeat_*.json`
- 停条件：8h 到达 / 全部批次完成 / 3 次连续空产出
- 每文件五维打分：结构性(0-3) + 十元密度(0-3) + 链接完整度(0-3) + 可复用度(0-3) + 污染风险(0-3)

## F12 集成规则

- daemon 不依赖 F12（不可靠依赖）
- 每批后检查 `http://127.0.0.1:17312/status`
- F12 idle 时投递单轮语义任务
- F12 不可用 → 继续本地工作，不阻塞
