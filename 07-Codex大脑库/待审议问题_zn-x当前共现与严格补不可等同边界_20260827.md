# 待审议｜zn + x 当前共现不等于 strict zn↔x 补

## 1｜已锁正向共现

同一 criterion_version 下已有 3 部独立作品达到 ≥95%，并在同一当前窗口中让 `zn`、`x` 两端分别独立过门：

1. 《三国演义》关羽·挂印封金，99/98：旧义 `zn` 与曹赐资源 `x` 同窗存在，`zn` 决定部分 `x` 的让渡。
2. 《水浒传》晁盖·梁山劫掠处分，99/98：不伤无关者 `zn` 限制已成立组织处分 `x` 的使用方式。
3. 《西游记》唐僧·三打白骨精 / 草寇事件，99/97：不轻伤人命 `zn` 规定师徒处分 `x` 的惩戒、保留与终止条件。

候选命题只到 L4：

> **在同一当前对象窗口中，`zn` 与 `x` 可以同时分别独立成立；原则不要求现实掌握权消失，现实掌握权也不自动吞掉原则。**

## 2｜伪共现护栏｜6 controls / 4 works

### Guard A｜x 真，但 zn 不独立成立
- 《西游记》孙悟空·弼马温，99/98：御马监现实管理 `x=true`；弃职主要受官阶、受辱与地位比较驱动，`zn` 未独立过门。

### Guard B｜zn 真，但所谓 x 只是名位 / 印信
- 《三国演义》关羽·汉寿亭侯名位，99/98：旧义 `zn=true`；爵位、称号与侯印不足证明对应现实处分 `x`。

### Guard C｜zn 真，但所谓 x 只是保护 / 责任对象
- 《水浒传》鲁智深·野猪林，99/97：救人须救彻 `zn=true`；林冲被保护、被负责，不等于林冲进入鲁智深现实掌握 `x`。

### Guard D｜第三因素足以解释表面 x
- 《三国演义》刘备·携民渡江，99/98：百姓自主选择 + 战时协同足以解释共同移动与保护结果，不需要假设百姓进入刘备稳定处分 `x`。

### Guard E｜跨阶段端点洗钱
- 《三国演义》刘备·徐州 pure-x ↔ 长坂 pure-zn，99/98：两个高纯端点分属不同阶段、不同对象层；“同一个人物”不能把它们粘成当前共现。

```text

+
阶段 B pure-zn
≠
同一当前窗口 zn+x
```

### Guard F｜第三方否决导致结果与 zn 同向
- 《红楼梦》鸳鸯抗婚，99/98：鸳鸯 `zn=true`，最终强纳路径确实停住，但关键现实否决来自贾母；结果与原则同向不能倒推鸳鸯本人拥有该婚姻对象层的稳定 `x`。

共同支持：

> **共现不是“人物两端都曾出现过”，也不是“最终结果符合原则”；必须证明同一窗口、同一对象层，两端各自独立成立，而且现实结果的因果作用确实属于被测主体自己的 `x`。**

## 3｜strict 与共现必须分账

current canonical `zn补x_补卡_v0.1` 要求：

- `zn→x`：补用途、守护/放弃标准与否决原则；
- `x→zn`：补现实落点、可保护对象范围与明确我方边界；
- 拿掉任一端，另一端必须仍成立但重新出现可命名缺口。

所以：

```text
co-occurrence
≠
strict complement
```

当前 strict 状态已更新为：

```text
1 positive control / 1 work
+
4 negative guards / 3 works
```

首份正向为《三国演义》诸葛亮·卤城换班，99/95：军令信用 `zn` 与对直属换班军的现实留放处分 `x` 同窗同对象独立成立；`zn→x` 补军令使用/变更边界，`x→zn` 则提供“我方直属军队—我的军令—我的留放处分对象”这一不可由第三方替代的现实落点。

既有反向护栏仍是关羽、晁盖、唐僧与严颜旁证：它们都说明“`x` 有帮助 / 执行接口”不等于 `x→zn` 的不可替代现实落点。

## 4｜strict 合法启动前置门

现在至少必须同时满足：

```text
same_current_window
+
same_object_layer
+
zn independently true
+
x independently true
+
result causality belongs to tested x
+
no third-party equivalent veto / anchor substitutes x
→ only then strict test may start
```

两份新增前置护栏：

1. **cross-stage endpoint laundering**：刘备不同阶段 pure-x / pure-zn 不能跨阶段拼接。
2. **third-party-veto result congruence**：鸳鸯结果与 `zn` 一致，但现实否决属于贾母，主体 `x` 不成立。

这两份只增加 strict 前置门护栏，不增加 strict negative guard，因为双向 strict 测试根本没有合法启动。

## 5｜固定判定协议

1. 先独立验 `zn`：原则是否通过无奖励、冲突排序、未来调用资格等门。
2. 再独立验 `x`：具体对象是否真实进入占有、调用、处分、否决或排除边界。
3. 验同窗与同对象层，禁止跨阶段、跨对象拼接。
4. 冻结第三因素，确认现实结果的作用权属于被测主体而非外置节点。
5. 两端都过门后才计 co-occurrence。
6. 最后才做 strict 双向拿掉，检查不可替代缺口。

## 6｜反误判纪律

- 强烈坚持、受辱、一次牺牲不能替 `zn`。
- 爵位、职位、印信、代理、保护对象、责任对象、共同移动不能替 `x`。
- 两个 99% 端点不在同一窗口，也不能相加成共现。
- 同一人物身份连续不能充当对象层胶水。
- 最终结果与 `zn` 同向，不等于主体拥有让结果生效的 `x`。
- 第三方现实否决必须归第三方，不能记到主体 `x` 账上。
- 第三因素冻结必须是真实存在且足以解释同一结果的因果变量，不能当万能逃生口。
- co-occurrence 统计、strict 前置护栏、strict 正反控制必须分账。
