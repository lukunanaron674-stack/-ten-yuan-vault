## 3｜最重要的红线

**co-occurrence ≠ strict complement。**

当前 canonical `zn补x_补卡_v0.1` 对 strict 补还有额外双向缺口要求：

- `zn → x`：掌握对象缺用途、守护/放弃标准与否决原则；
- `x → zn`：意义缺现实落点、可保护对象范围与明确我方边界；
- 拿掉任一端，另一端必须仍成立但重新出现可命名缺口。

所以三部作品只能证明“同段共现可以成立”，不能自动证明 strict `zn↔x`。

## 4｜当前最小判定协议

先分别独立验端点：

```text
zn：内部原则是否通过无奖励、冲突排序、未来指导资格等门？
x：具体对象是否真实进入占有、使用、调用、处分或排除边界？
```

再验同一窗口：

```text
两端是否在同一当前对象层真实同时存在？
```

最后才允许进入 strict 补测试：

```text
拿掉 x → zn 是否出现现实落点/对象范围缺口？
拿掉 zn → x 是否出现用途/守护/放弃标准缺口？
第三因素是否能替代其中一端？
```

## 5｜反误判护栏

- “有原则的人也有资源”不是自动 `zn+x`，两端必须分别过门。
- “原则限制权力”不能反推 `x` 不成立。
- “资源被放弃”不能反推 `zn` 一定成立。
- 同作品不同桥段不能冒充独立作品。
- 局部共现不能倒灌成稳定人物本体。
- 共现统计与 strict 补统计必须分开。
