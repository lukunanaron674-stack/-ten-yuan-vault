## 2. 当前可直接调用的已锁定关系

- `xn 克 zx`
- `zx 补 nx / nx 补 zx`
- `zx 克 n`
- `xn 生 xz`
- `x并z 生 z`
- `x 生 x并z`
- `x 克 z`
- `n 克 xz`
- `zn 补 x / x 补 zn`
- `n 补 x并z / x并z 补 n`

`n 补 x并z / x并z 补 n` 红线：必须分别证明真实内部承载与公共识别入口。`n` 不是房间、楼板或“里面”；`x并z` 不是漂亮装修或“外面”。前者改变壳能否承受真实负荷，后者改变承载结构能否被识别、进入和持续指认。

其他关系只有在核心表“已锁定关系语义”或专项正本索引明确列为 `canonical-current` 时才能直接调用。

## 3. 当前不得擅自锁定

| 关系 | 当前核心缺口 | 下一步必须寻找的证据 |
|---|---|---|
| `z 克 nx` | 认可是否真正恢复主体方向位置，仍易混入 `zx/x` | 重要认可主体出现前后，主体具有真实选择，且外部方向合法性明确下降 |
| `nx 生 x` | 旧欲望累积口径已撤回，尚无新机制 | 无压迫、无资源授予、无既有占有欲时，沿外部方向如何新增掌握边界 |
| `nz 生 nx` | 关系余温与照护、职位、年龄、任务混杂 | 双方平等可选、无现实依赖时，主体因不愿关系结束而明确让出方向 |
| `nx 克 x并z` | 不认领身份壳与失去资源、权力压制混杂 | 壳必须依赖主体持续背书；拿掉 `x/zx` 后，拒绝认领仍使壳解释接口下降 |
| `zx 生 zn` | 英雄显权与原有意义、宣传、胜方追随混杂 | 甲离场、失败、无奖励后，乙仍把原则从“他的”变成“我的” |
| `zn 生 n` | 意义动机与 `zx/xn/x` 中介无法分开 | 低权能、低制度、低资源条件下，意义直接扩大持续承接边界 |
| `xz 生 zx` | 更像潜在 `zx` 被迫显影 | 证明危险前目标端点不存在，危险造成决定空位后才新增公开权能位置 |
| `z 生 nz` | 认可前已有关系厚度、共同时间与奖励 | 无既有 `nz/n/xn` 时，明确认可本身使关系获得不愿结束的时间厚度 |
| `xz 克 zn` | 行为妥协、意义排序与原则正确性改判混杂 | 危险解除后仍持续认为原原则不再正确，而非仅无法实践或优先级下降 |

## 4. 通用红线

1. 几何位置锁定不等于机制锁定。
2. 共现、先后、对照和视觉相似不等于关系启动。
3. 每条关系必须写源端点、目标端点、机制、被改变变量、阶段、体量、显影条件与第三因素。
4. 必须做拿掉测试和反向测试。
5. 稳定本体、状态、行为、光影、场景、时间关系、关系位置、显影与动态链分层。
6. 三元与十元并行，不构成父子派生。
7. 禁止依赖记忆重画关系表。
8. 建筑内外、门面与房间、样板间与楼板只证明视觉或物理层次，不自动构成 `n ↔ x并z`。
9. 无新证据时不得重复扩写整份审计，只更新该关系的“最新缺口”和“下一证据目标”。
10. 旧电影卡、视觉卡与案例卡只作证据，不得冒充本轮理论推进。

### 6.3 每小时回写规则

每小时任务结束时必须原位更新本文件，而不是只更新运行账本：

1. frontmatter：`version`、`updated`、`relation_table_version`、`last_hourly_run`、`next_priority_relation`。
2. 若有新锁定关系：加入“当前可直接调用的已锁定关系”，并补一条最关键红线。
3. 若关系未锁定：更新“当前不得擅自锁定”对应行的最新缺口与下一证据目标，不重复粘贴完整审计。
4. 更新“当前接续点”和“下一轮目标”，保证下一小时从真实断点继续。
5. 完整对象分层、候选机制、正反例、最近邻、测试和动态链写入唯一运行账本；本文件只保留可直接启动下一轮的压缩结论。
6. 本文件与核心表发生版本漂移时，先同步本文件，不能带着旧关系盘继续跑。
7. 写入前重新读取本文件 blob SHA；提交后重新读取提交与文件，核验成功才能报告完成。
