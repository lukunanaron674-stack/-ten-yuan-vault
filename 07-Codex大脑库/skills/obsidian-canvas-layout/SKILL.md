# Obsidian Canvas｜多中心左右双向自动排版

## 触发与权力

用户说「Canvas排版、左右展开、整理思维导图、缩小空白、多个中心、一个分支一种色、验证可视化、缩小看不见标题」时调用。**执行前读取仓库根 `AGENTS.md`、`00-中枢索引/AI文件权力与任务总览.md`、`00-中枢索引/总入口.md`，并遵守 Linear 674-77 的 XN-CANVAS-01 现行规则**。Canvas 只做可视化，不能改变理论正本或岗位事实。不要新增重复Canvas总入口。

## 布局硬约束

1. **多中心独立**：先识别至少两个顶层 group 底盘，各底盘的文字、子 group 和内部边属于一个中心。跨中心边存在时 **FAIL CLOSED**，不猜归属。
2. **左右分流**：按既有子分组顺序交替放置 hub 左右两侧；同侧子树按实际宽高纵向紧凑堆叠。**子分组内部的公司、岗位、作品、证据等坐标相对关系先保持不动**，不凭算法重写语义。
3. **森林装箱**：各中心排好后，比较 2 列和 3 列矩形打包方案，综合总面积和目标长宽比，选择更紧凑的整体版面。自动更新顶层底盘外包框。
4. **继承颜色**：底盘/中心色、一级方向色、所有下级卡片颜色和关系边颜色**一字不改**。同处左侧不代表必须同色；颜色标示语义分支，不由物理左右位置决定。
5. **尺寸与文字**：默认几何整理保留卡片宽高；但用户明确反馈卡片过大、空白过多、正文不可读时，按 XN-CANVAS-01 的 `AUTO_WIDTH` / `AUTO_HEIGHT` 先估算渲染行数，再原位调整目标文本卡尺寸。短卡优先 300–600px，长卡设阅读宽度上限（通常不超过 950px）；按换行行数、段间距和内边距给高度，不能用 3300×2050 等固定大尺寸套所有文本。保留 text/file/url/color、节点ID及所有原边；不得裁字或改写事实。缩放卡片后必须就近重排受影响的相邻节点并复算局部边界，避免把卡片变小却留下更大的节点间空洞。
6. **安全验收**：ID唯一、边端点存在、无跨中心边、无文本卡重叠、顶层底盘互不重叠；原 text/file/url/color 和全部原 edge 数组相同。视觉预览是辅助，**不代表已在 Windows Obsidian 实际PASS**。

**禁止**退回旧版或重建新的“公司十元证据.canvas”。公司主次十元应原位显示于对应求职卡，单公司直接标签，混合公司逐名标签；详细材料通过公司标题链接到原有MD的对应章节。

## XN-CANVAS-READABILITY-01｜缩放标题与双层阅读（在同一张Canvas内）
1. 缩小整体查看中心主题色、方向名称和公司标题；放大后查看公司卡正文、十元候选、原始JD与证据链接。**两个阅读层级并不意味着要生成两张Canvas。**
2. 公司卡标题固定明显，紧随标题的第二行即可显示 `十元预测（AI，非真人实测）：主元→次元` 和来源证据内链。多公司的共用JD卡需分别标明每家公司，不得只放组链接。
3. 对较长JD作自适应宽高和局部无重叠排版，不裁字、不重写事实。禁止把某单一NZ研究问题替代完整十元判断。
4. 在 Obsidian 真机缩放及连线截图验收前，不要宣布USER视觉PASS；结构合格也不能代替阅读合格。

## XN-CANVAS-TEXT-FIT-01｜内容自适应文字卡

1. 用户指出“几行字占很大一张卡”“字小看不清”或截图可见大面积卡内空白时，视为明确的可读性修复授权；不得用“保留现有尺寸”的默认规则拒绝修复。
2. 先估算 Markdown 标题、段落、列表、中文与英文混排的实际换行，再设卡片宽高。短说明不保留千像素以上横向空白；长正文控制在可阅读列宽内并增加高度，全文原样保留。
3. 局部尺寸变化后，重排直接相连的上下游卡片，维持短间距、既有层级与边的语义；重新核对局部文本卡不重叠、边端点有效、所有原文和边仍在。
4. JSON 结构验收不能替代 Windows Obsidian 的字体、缩放和截字验收。未在 Obsidian 实屏确认时标记 `WAIT_LOCAL_UI`，不能声称视觉已通过。

## DONE / STOP

- **DONE（程序）**：报告树数量、节点、边、布局列数、既有路径和Git回滚点；GitHub如有提交则回读 SHA；保留原内容、颜色、所有边；全图检查通过。
- **WAIT_LOCAL_UI**：在Obsidian里看局部卡片可读性、箭头走向、跨区空白，人工确认通过后才将原位排版达到用户验收。
- **STOP**：存在跨中心边、无明确顶层分组、子树相互重叠、文本内容变化、原图片资产/引用缺失、用户已有文件被错误重建或工作树冲突时立即停，不自动修造资料。


## v1.3.0｜已有Canvas原位改版、评分/课程多中心兼容（2026-10-17）

**适用对象：** 布局中已经有多个中心、但没有子group的放射图，以及尚未建立group的旧单中心长图。

1. **先 `--audit-only`**：对所有已有Canvas做只读节点/边/归属/重叠/跨中心边审计。旧图没有group时只报告`ungrouped`，不擅自猜测中心。
2. **两种已有布局兼容：** CLASSIC（每个顶层group有至少2个子group）继续左右双向重排；RADIAL_GROUP_FREE（至少2个顶层group，没有子group）**保留原中心内部径向布局不动，只对多group外框做2/3列装箱**。只有一个子group而归属模糊仍FAIL_CLOSED。
3. **首次从旧单中心转换为多个中心是内容编排任务，不是geometry-only算法。** 先按USER明确要求定主题和边归属；需要断开跨中心**导航型**视觉线时，必须获得该任务明确的重组授权、在**原Canvas内**列出旧edge id与原两端点、改成文本跳转/工单引用，保持原卡片文字和同中心关系。**理论生克补/材料论证边不得作为导航线删除。** 未授权则STOP，不自动动边。
4. **评分表不代替评分正本：** 案例的`TECH_PASS`、`F_pred/S/T` AI候选、`F_human`真观看和USER个人作品分必须分开存；`F_human`无实测填`null`。原有评分来源参考674-106与作品管理674-308，不擅自改官方评分。
5. **READABILITY**：沿用USER确认的多中心/独立主色/多层环绕；画布图例缩小后可见中心标题，放大阅读细节。脚本只做结构审计和可安全识别的几何移动，**不宣称完成Windows Obsidian实屏验收**。
6. **单一文件入口：** 同一对象只更新现有Canvas，保留Git提交与旧blob SHA回滚点，不生成`_v2`、`_标题总览`、`_预览.canvas`等平行正本。

## XN-CANVAS-REFERENCE-01｜按用户指定的真实参考 Canvas 定尺寸

当用户点名另一张 Canvas 作为排版参照时，先直接读取该文件的真实节点宽高分布和文字长度，不根据截图空白区域猜尺寸。参照 `15-总思路/BOSS求职方向与岗位线索_左右双向_十元证据接入版.canvas` 时，常规文字卡以 **520px 阅读列宽**作为默认基准；该文件存在少量 490–570px 等相近宽度，不能把异常标题/超长正文尺寸误认为常规卡尺寸。

1. 卡片宽度跟随参照 Canvas 的常见正文列宽；卡片高度按正文长度、显式换行、标题/列表结构与参照样本拟合。禁止把长文压成同一固定短高，也禁止让少量文字占用千像素级空框。
2. 文本字数相近时优先对齐参照卡片的宽高量级；字数不同则以估算换行和段落数调整高度，全文原样保留。
3. 仅变更目标卡片和必要的相邻几何位置，保持原项目分区锚点、文本、颜色、ID与边；外框按重排后内容收紧。
4. Obsidian Canvas JSON 不提供节点级字体大小字段；不得伪造字号属性。用户反馈“字看不清”时，使用参照 Canvas 的实际卡片比例和局部阅读截图判断，未在 Obsidian 实屏检查则标记 `WAIT_LOCAL_UI`。
