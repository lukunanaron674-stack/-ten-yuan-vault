# Canvas 概念库参考图补全｜运行覆盖规则

本文件是 `SKILL.md` 的运行时纠错层。发生冲突时，以本文件、状态文件和 GitHub `main` 的真实内容为准。

## 路径与唯一真相源

- 唯一写入分支：`main`
- Canvas 根目录：`09-给674（我）用的库/概念库/`
- 参考笔记目录：`09-给674（我）用的库/画画理论/assets/<Canvas名>/`
- `codex/pirate-r2-architecture-github` 仅作为历史恢复源，不得继续作为生产分支。
- Skill 中旧的 `画画理论/*_is-a名词素材库.canvas` 扫描路径失效，不得据此新建重复 Canvas。

## 先修一致性，再处理新概念

每轮先以 `main` 远端读回检查：

1. 参考笔记真实存在；
2. Canvas 中存在对应 `ref_<nodeId>` file 节点；
3. Canvas 中存在对应 `e_ref_<nodeId>` 的 text→file 连线；
4. 状态的 `remoteVerified`、`canvasLinked`、commit 和 blob 与 `main` 一致。

若账本或旧分支声称完成，但 `main` 缺少上述任一证据，视为“恢复任务”，必须停在该节点：

- 优先从历史分支恢复原参考笔记，不重新搜索、不重复制造内容；
- 只补缺失的 file 节点或连线；
- 完成远端读回前不得进入新概念。

## 候选扫描修正

- 扫描所有符合条件的概念叶子，不得只处理每列第一项。
- 稳定顺序：`y → x → node id`。
- “叶子概念”按文本语义判定：第一行是明确概念名、含 `is-a` 与镜头描述，并排除标题、分类、统计、说明和“更多”。Canvas 用于排列同级概念的链式边，不得被误判为非叶子。

## 错误场景区保护

在全库场景重写尚未真实提交并远端验证前，跳过旧模板场景区：

- 场景总标题仍含 `v2状态侵蚀`、`v3内部功能` 或 `v4复合场景`；或
- 场景总标题不含 `可绘制场景类目`。

这些旧节点不得继续找参考、生成图片或新增连线。服装、建筑、构件、元素等未受污染区域可以继续处理。

## 参考优先，禁止误生图

- 默认且优先使用许可、作者、来源页可核验的真实参考图。
- 本 Skill 不调用任何 AI 生图工具，不生成替代图片。
- 搜索不到可靠参考时，仅创建 `prompt-reference` 提示词参考笔记，清楚标记“无外部图片”，然后停在当前节点等待后续决定。
- 禁止搜索缩略图、Pinterest、无作者转载或不可核验搬运图作为最终来源。

## 安全写入 Canvas

- 必须读取完整 Canvas blob 并验证 JSON 后再写入。
- 每个概念只新增一个 file 节点与一条参考连线。
- 保留全部旧节点、旧边、坐标、颜色和 metadata。
- 写入前后验证节点 ID 与边 ID 唯一；远端读回同时确认参考笔记、节点、连线、commit 与 blob。

## 单轮边界

一次运行严格只完成一个概念或一个历史节点恢复。当前断点未完成时，不搜索或处理下一概念。
