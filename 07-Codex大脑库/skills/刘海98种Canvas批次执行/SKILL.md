# 刘海98种 Canvas 批次执行 Skill v0.1

## 目标

建立一套可验证、可追溯、可继续扩展的女性刘海视觉词库。

当前目标：

- 总量：98种
- 批次：14批 × 每批7种
- 当前进度：7/98
- 主 Canvas：`05-银矿库/角色库/刘海98种/98种流行女性刘海.canvas`
- 目标仓库：`lukunanaron674-stack/-ten-yuan-vault`
- 默认分支：`main`

本 Skill 是批次执行器，不是最终理论定稿。98种完成并二审后，升级为 v1.0 正式建库 Skill。

---

## 核心原则

### 1. 真实资料先于十元映射

必须按以下顺序执行：

```text
真实发型资料
→ 名称规范化
→ 视觉差异核验
→ 去重与家族归类
→ 十元映射
→ Canvas 入库
```

禁止倒序：

```text
十元分类
→ 为凑数量编造发型名称
→ 用相似图片伪装成不同类型
```

### 2. 找图优先，生图后置

第一层资产使用真实参考图与来源链接。

统一角色重绘只在以下条件满足后进行：

- 该批7种真实条目已经核验
- 每种刘海结构差异明确
- 名称与来源已记录
- 十元映射已完成

禁止用 AI 生图证明某种刘海真实存在。

### 3. 不平均分配十元

十元数量允许自然失衡。不得为了画面对称或凑数，强行让每个十元各占9至10种。

### 4. 不把状态当基础类型

必须区分：

- 基础刘海结构
- 长度变体
- 密度变体
- 分线变体
- 卷度变体
- 造型状态
- 搭配发型
- 环境状态

“风吹、湿发、睡醒、运动、工作”等只能作为状态字段，不能单独冒充基础刘海类型，除非行业中确有稳定命名且结构可辨。

## 每批输入

每次执行默认处理7种刘海。

输入可以是：

- 一个刘海家族名称
- 7个候选名称
- 一组参考图片
- 当前 Canvas 中尚未完成的批次
- “继续下一批”

若用户只说“继续”，直接读取当前进度并执行下一批，不反问可自行判断的问题。

## 每批标准流程

### 步骤1｜检索真实资料

优先检索：

1. 专业美发媒体
2. 发型师或沙龙官网
3. 韩国、日本、中文、英文发型目录
4. 主流时尚媒体的发型专题
5. 可核验的原作者社交账号或作品页

每个候选至少记录：

- 中文规范名
- 英文、韩文或日文原名
- 常见同义词
- 来源页面
- 参考图地址
- 来源类型

不要把搜索结果缩略图当永久来源。优先记录原页面。

### 步骤2｜名称规范化

把名称分为：

- 规范主名
- 地区称呼
- 同义词
- 营销别名

同一结构仅因营销文案不同，不得重复计数。

例如：

```text
韩式空气刘海
See-through bangs
Air bangs
透视刘海
```

这些名称可能部分重叠，必须根据实际结构参数判断是否合并或保留为变体。

### 步骤3｜视觉差异核验

每个候选按以下参数记录：

| 参数 | 可选值示例 |
|---|---|
| 长度 | 眉上、齐眉、过眉、眼下、颧骨、下巴 |
| 密度 | 极薄、轻薄、中等、厚重 |
| 分线 | 无分线、中分、三七、二八、偏侧 |
| 边缘 | 平直、圆弧、羽化、锯齿、缺口 |
| 卷度 | 直、内扣C卷、外翻、S卷、自然卷 |
| 宽度 | 窄三角区、标准、宽版、延伸至鬓角 |
| 遮挡 | 全露额、透额、半遮、遮眼 |
| 连接 | 与鬓角断开、自然连接、长侧帘连接 |

7种之间至少要在两个结构参数上形成可见差异，或在一个核心参数上形成显著差异。

若差异只能靠标题解释，而画面看不出，判为重复候选。

### 步骤4｜家族归类

目标14个家族，每家族7种：

1. 空气与透薄
2. 齐线与厚刘海
3. 帘幕刘海
4. 八字刘海
5. 瓶颈刘海
6. 斜扫刘海
7. 中分与长刘海
8. Baby 与 Micro 刘海
9. 碎剪与羽化
10. 法式与 Birkin
11. 宽版与几何切割
12. 框脸与长侧束
13. 卷曲与纹理
14. 复古与造型型

家族表只是工作框架。若真实资料证明某项归类不合理，允许调整，但必须在 Canvas 和审计记录中说明。

### 步骤5｜十元映射

每种刘海独立判断，不按整组统一贴标签。

必须记录：

```yaml
主十元:
副十元:
体量: 1-10
纯度: 0-100
五维归属:
视觉证据:
误判项:
```

十元视觉参考：

- `x`：边界、锋利、自我轮廓、拒绝混入
- `z`：节点、截断、切口、瞬间变化
- `n`：承载、连接、包裹、脸侧关系
- `zn`：原生、自然、贴近本来状态
- `nz`：停靠、柔软、归属、余波
- `xn`：秩序、分线、等距、规整节拍
- `nx`：让位、留白、退后、弱化存在
- `zx`：行动、功能、清晰视野、操作便利
- `xz`：漂流、不定方向、临界、风迹
- `x并z`：遮蔽、外壳、表面与内里分离

五维：

- 时间 = `xn + z`
- 本体 = `zn + x`
- 空间 = `x并z + n`
- 因果 = `zx + nx`
- 命运 = `xz + nz`

映射理由必须来自刘海结构本身，不能主要依赖模特表情、服装、背景、风雨或文案气氛。

### 步骤6｜Canvas 节点写入

每种刘海至少包含两个节点：

1. 真实参考图或来源链接节点
2. 说明文本节点

说明节点格式：

```markdown
## 编号｜中文规范名
**原名：** English / 한국어 / 日本語
**家族：**
**类型层级：** 基础 / 密度 / 长度 / 分线 / 混合变体

**结构参数**
- 长度：
- 密度：
- 分线：
- 边缘：
- 卷度：
- 宽度：
- 遮挡：
- 连接：

**十元映射**
- 主：
- 副：
- 体量：
- 纯度：
- 五维：
- 视觉证据：
- 误判：

**来源**
- 页面：
- 图片：
- 来源类型：
- 核验日期：
```

Canvas 排版规则：

- 每批一个 group
- 每批7种横向或2×4排列
- 图节点在上，说明节点在下
- 同类用 group 包围，不用整张信息图代替节点
- 保留总入口、进度、家族索引和十元索引
- 在线图片必须保留来源链接

### 步骤7｜批次审计

每批完成后逐项检查：

- [ ] 恰好7种
- [ ] 每种有真实来源
- [ ] 名称无乱码
- [ ] 没有明显重复结构
- [ ] 没把整体发型或配饰当刘海
- [ ] 每种有主、副十元
- [ ] 映射理由来自刘海本身
- [ ] Canvas 可编辑，不是单张海报
- [ ] 进度数字已更新
- [ ] GitHub 已提交

任一关键项失败，本批不得标记完成。

### 步骤8｜提交与进度

每批单独提交一次。

推荐提交信息：


完成后汇报：

## 失败模式与禁止事项

### 禁止1｜凭空发明行业名称

“边界型刘海、命运型刘海、承载型刘海”等只能作为十元解释标签，不能冒充真实行业发型名称。

### 禁止2｜让字幕承担全部差异

如果删掉标题后，7张图无法被视觉区分，说明批次失败。

### 禁止3｜换脸制造差异

统一重绘阶段必须固定：

- 同一角色
- 同一脸型
- 同一发际线
- 同一后发
- 同一光线
- 同一表情
- 同一服装
- 同一裁切

只替换刘海区域。

### 禁止4｜整张PNG冒充Canvas

Canvas 必须是 Obsidian `.canvas` JSON，包含可编辑节点和连线。PNG只能作为辅助总览。

### 禁止5｜用场景气氛代替结构

风、雨、旅行、疲惫、温柔等只能作为辅助状态。十元映射首先看长度、密度、分线、边缘、卷度、宽度和遮挡。

### 禁止6｜为凑98保留重复项

宁可本批不足7种并继续检索，也不能把同一刘海换同义词重复计数。
