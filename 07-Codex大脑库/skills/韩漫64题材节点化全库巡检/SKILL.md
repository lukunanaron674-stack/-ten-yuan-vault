# 韩漫64题材节点化全库巡检 Skill v1.0

## 1｜目标

把 `28_64题材完全节点化重构/` 下 A—H 八区、64个题材全部按同一套真实标准走完：

```text
题材入口
→ 主对象与关联对象
→ 主体分层
→ 权限与关系功能分账
→ 触发行为
→ 前后状态与不可逆变量
→ 阶段十元端点
→ 生克补关系状态
→ 对子动态链
→ 主题显影门槛
→ 具体反证
→ 可复用输出
```

本 Skill 的任务不是给旧模板换措辞，而是把“看似完整的12节点”改成能运行、能反证、能继续回填的分析骨架。

## 2｜单轮粒度

**每次运行严格只处理一个题材。**

一个题材完成时必须同步：

1. 对应分类的 `*_节点化.md` 中该题材完整12节点；
2. 对应 `R4_<区>_*.canvas` 中该题材 Group 的12节点；
3. 对应 `R4_<区>_*_视觉总览.canvas` 中该题材摘要卡；若视觉总览不存在则先建立最小可用总览；
4. `state.json`；
5. `run-ledger.md`。

不得一轮批量复制多个题材，不得只改 Markdown 后声称 Canvas 已完成，也不得只造视觉总览而不修详细节点。

## 3｜固定启动顺序

每轮先读取最新 `main` SHA，再按顺序读取：

1. `AGENTS.md`；
2. `00-中枢索引/AI文件权力与任务总览.md`；
3. `00-中枢索引/总入口.md`；
4. 本 `SKILL.md`；
5. `state.json` 与 `run-ledger.md`；
6. `28_64题材完全节点化重构/00_R4总控.md`；
7. `28_64题材完全节点化重构/01_节点化十元重构协议.md`；
8. 当前分类 Markdown、详细 Canvas、视觉总览 Canvas；
9. B区 R4.1 文件作为格式样板，但不得机械复制B区结论；
10. 当前题材涉及的十元信息卡、准度卡、单条关系卡、`十元生补克表.md` 与关系专项索引，只读。

仓库正本与本 Skill 冲突时：流程服从 L0/L1，知识判断服从现行 L2。不得用本 Skill 覆盖理论正本。

## 4｜扫描顺序与断点

分类顺序：

```text
A 恋爱与关系
→ B 身份阶级与社会位置
→ C 命运改写与信息优势
→ D 能力成长战斗与竞争
→ E 悬疑犯罪与危险
→ F 家庭日常与疗愈
→ G 执念控制与危险关系
→ H 职业现实与行业
```

每区按 `01 → 08`。

B01—B08 已作为本 Skill 的校准样板完成 R4.1，初始状态可标记为已完成；其余题材从 `T-A01` 开始。若后续发现B区文件与现行正本冲突，重新加入修复队列，不因“已完成”免审。

## 5｜12节点修正标准

### 0 入口

- 写“初始候选主/辅十元”，不得写成固定主导；
- 标明 `骨架候选 / 案例待回填 / 待二审 / blocked`；
- 题材名不得继承十元。

### 1 对象

- 必须选一个可记录前后状态的主对象；
- 股份、职位、证据、婚约、名誉、能力、渠道等异质对象必须拆成关联对象；
- 不得用“资源”“身份”“权力”一词吞掉全部变量。

### 2 主体

分别写清：

- 稳定本体主体；
- 当前阶段行动者；
- 控制者；
- 确认者；
- 承载者；
- 制度或公共接口。

“客观上是谁”与“被谁采用成谁”必须分账。

### 3 关系

拆成两层：

```text
权限：定义权 / 退出权 / 资源权 / 解释权 / 调用权 / 否决权
功能：承载 / 认可 / 保护 / 采用 / 对外代表
```

每项必须落到具体主体，不能只保留检查菜单。

### 4 触发

至少保留待回填字段：

```text
行动者 / 对象 / 目的 / 对方回应 / 短期收益 / 长期代价 / 第三因素
```

不得只写“舞会发生”“证据出现”“开始创业”。

### 5 状态

写清：

```text
前态 → 触发 → 后态 → 不可逆变量
```

至少有一个可观察变量改变，例如准入、否决、署名、表决、采用范围、确认主体、停留资格或控制范围。

### 6 十元端点

- 按阶段逐段重判；
- 允许辅助十元接管主导；
- 每段写主体归属、对象层、体量与顺序；
- 不得从头到尾只重复入口标签。

### 7 生克补

每条关系必须标状态：

```text
已锁定可候选
条件调用
研究中未锁定
本题材不成立
```

并写：源端点、目标端点、启动机制、被改变变量、成立阶段、第三因素和失败条件。

关系卡未锁定时，禁止在题材库中写成正式关系。关系只因几何位置存在，也不得冒充机制已锁定。

### 8 动态链

动态链必须是“对子与对子之间的变化”，而不是剧情摘要。

最低格式：

```text
【阶段A：主符号体量｜次符号体量｜内部关系/none】
  ──触发、条件、被改变变量──▶
【阶段B：主符号体量｜次符号体量｜内部关系/none】
  ──接管条件/失败边──▶
【结算：主体、对象、稳定锚点】
```

必须包含：

- 主、次十元；
- 箭头方向；
- 对象层；
- 触发与接管条件；
- 被改变变量；
- 分支与失败边；
- 最终结算和稳定锚点。

不得把共现、先后、进入舞台、维持、接管、获胜或打脸自动画成生克补。

### 9 主题

主题后置。只有中心问题、转折、高潮和结局共同显影，才登记时间、本体、空间、因果或命运候选。十元共现不能反推主题。

### 10 反证

至少完成一项具体失败条件，并保留：

- 拿掉测试；
- 反向测试；
- 最近邻误判；
- 替代解释；
- 场景、身份、职业、情绪、视觉表象不继承十元。

### 11 输出

只输出已回填内容。缺失字段必须标 `topic_node_incomplete`，不得用整齐排版掩盖空缺。

## 6｜z、nx、xn等高风险边界

- `z` 必须分账认可主体、认可内容、采用范围与成立阶段；流量、热搜、惊叹、胜利不自动是z。
- `nx` 是主体不占据本可拥有的方向决定位置，沿他人、关系、流程、秩序或现状推进；不是“现实落地”“考虑市场”或普通配合。
- `xn` 必须是主体主动组织时间、规则、信息、计划和资源使结构持续运行；被动遵守制度、忙碌、加班、行业流程不自动成立。
- `x` 必须落到具体掌握、调用、调配、否决或控制边界；有钱、有身份、有职位不自动成立。
- `x并z` 必须是可识别、可进入、可持续指认的公共壳；换装、称号、秘密和视觉符号不自动成立。
- `zx` 必须有公开权能显现或扩大；愤怒、反击、胜利、打脸不自动成立。

其他十元同样服从现行信息卡与准度卡，不得由题材气质类推。

## 7｜跨区治理

题材可跨区，但每区只保留自身研究变量：

- B区保留身份、准入、公共名位、认可与控制边界；职业生产转H，能力升级转D。
- 其他分类同理。发现重叠时写明“本区保留什么、转交哪一区复核什么”，不删除题材。

## 8｜Canvas写入规则

### 详细 Canvas

- 保留原 Group、node id、坐标、尺寸、颜色和无关边；
- 只改当前题材对应的12个节点文本及必要的内部箭头；
- 不移动其他题材；
- JSON必须可解析，node/edge id唯一，file路径有效。

### 视觉总览 Canvas

每区必须包含：

1. 顶部状态、纪律和12节点流程；
2. 8个题材摘要卡；
3. 每卡至少写候选主符号、主对象、阶段链、核心反证和跨区提示；
4. 对已锁定、条件调用、研究中关系做视觉分账；
5. 视觉总览只导航，不产生理论权力。

## 9｜写入、并发与恢复

1. 写前记录最新 main SHA，并重读全部目标 blob SHA。
2. 优先使用原子多文件提交。
3. 若执行环境没有原子 Git Data 能力，可采用安全顺序写入，但每个文件写前必须重读 SHA，写后立即远端读回。
4. 顺序写入时，任一步失败：
   - 停止本轮；
   - 不推进 `currentTopic`；
   - `phase` 标记为 `PARTIAL_RECOVERY_REQUIRED`；
   - 下轮先核对当前题材各文件是否一致，再继续或回滚到最新完整状态；
   - 不得覆盖并发修改。
5. 不删除旧文件，不移动分类目录，不修改 `01-十元系统/` 理论正本。
6. 发现理论冲突时，只在账本与状态的 `pendingIssues` 登记，并把题材状态标成 `blocked-theory-conflict`。

## 10｜完成门

一个题材只有同时满足以下条件才算完成：

- Markdown 12节点已修正；
- 详细 Canvas 对应12节点已同步；
- 视觉总览题材卡已同步；
- 三份文件均远端读回；
- JSON可解析，节点与边ID唯一；
- 关系状态与现行L2一致；
- 动态链包含主次、箭头、条件、分支、结算和稳定锚点；
- 账本写入真实 commit/blob 证据；
- 状态推进到下一题材。

只完成其中一部分时，状态必须保留在当前题材。

## 11｜状态字段

`state.json` 至少维护：

- `planId`
- `skillVersion`
- `status`
- `phase`
- `currentCategory`
- `currentTopic`
- `scanOrder`
- `completedTopics`
- `completedCategories`
- `lastRunId`
- `lastStartingMainSha`
- `lastVerifiedCommit`
- `lastVerifiedPaths`
- `retryCount`
- `lastError`
- `pendingIssues`
- `nextAction`
- `updatedAt`

## 12｜账本格式

每轮向 `run-ledger.md` 追加：

```markdown

- 起始 main SHA：
- 读取正本：
- 发现问题：
- Markdown：
- 详细 Canvas：
- 视觉总览：
- 关系状态核验：
- 动态链核验：
- 修改路径：
- 提交 SHA：
- 远端读回：true/false
- 本轮状态：VERIFIED_SUCCESS / PARTIAL_RECOVERY_REQUIRED / BLOCKED
- 当前断点：
- 下一动作：
```

不得伪造SHA，不得只记“完成”。

## 13｜全部完成条件

当64个题材全部完成远端验证：

1. `status = completed_remote_verified`；
2. `currentTopic = null`；
3. 八区均拥有文字正本、详细 Canvas、视觉总览 Canvas；
4. 总控更新覆盖状态，但不把运行骨架升格成理论正本；
5. 最终账本列出64题材完成数、阻塞数、待二审数和最后提交SHA；
6. 后续每小时任务进入轻量巡检，只在正本变化或文件断链时重新打开题材。

## 14｜每轮汇报

固定标题：

```text
韩漫64题材节点化巡检｜本轮实际工作明细
```

只汇报：当前题材、发现问题、实际修改文件、动态链与关系状态、提交SHA、远端读回、当前进度、下一题材。没有实质修改时写明阻断原因，不制造空提交。
