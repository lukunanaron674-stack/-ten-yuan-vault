# 韩漫64题材节点化全库巡检 Skill v1.1

## 1｜目标

把 A—H 八区、64个题材改成真正能学习、能创作、能反证的对象行为库。

固定顺序：

```text
题材涉及的真实对象知识
→ 主对象与关联对象
→ 主体、权限与关系功能
→ 对象的前后状态变化
→ 用十元解释对象变化
→ 生克补与对子动态链
→ 主题、反证与创作输出
```

本 Skill 不负责重新解释十元。十元是下游分析工具，不是每个题材文件的主要学习对象。

## 2｜最高门禁：对象知识优先

### 2.1 必须先解释对象

每个题材在进入十元判断前，先解释该题材真实涉及的专业对象。

例如：

- 财阀继承先解释股份、表决权、否决权、董事会席位、继承资格、法人代表；
- 娱乐圈先解释作品、发布权、署名权、渠道、人设、专业认可、公众认可、流量；
- 宫廷继承先解释皇位、军权、任免权、诏书、官僚体系、财政和继承合法性；
- 商战创业先解释股权、融资、控制权、治理结构、运营结构、市场采用和团队承载。

对象解释至少回答：

```text
它是什么
它由哪些权利、资格、关系或机构组成
它与相邻对象有什么区别
它在故事中能改变哪些可观察变量
它最常被误解成什么
```

### 2.2 十元只解释对象，不替代对象知识

正确写法：

```text
股份是公司所有权份额。
只有当股份带来表决、否决、收益或处置边界时，才进入x；
股东与董事身份另查x并z；
股权结构与投票程序另查xn。
```

错误写法：

```text
x就是股份、军权、表决权、发布权、署名权。
```

禁止把专业对象压扁成十元标签。一个对象可包含多个十元层面；同一十元也可解释多个不同对象中的相同机制。

### 2.3 禁止用题材文件教用户十元基础定义

不得在每区反复建立“十元便读词典”“十元中文名词表”作为主体内容。用户已有十元知识，题材库应提供新的对象知识。

只有在避免误判时，才可用一两句说明某符号在该对象中的具体作用；不得把一整章写成十元自我介绍。

### 2.4 文件阅读结构

每个题材至少按以下结构呈现：

```text
本题材要学的对象
→ 每个对象的独立解释
→ 用十元解释这些对象内部的不同层面
→ 12节点
→ 对象链
→ 十元链
→ 稳定锚点与反证
```

动态链必须先有对象变化链，再有十元解释链。不能只给符号串。

## 3｜单轮粒度

每次运行严格只处理一个题材。

一个题材完成时必须同步：

1. 对应分类 `*_节点化.md` 中该题材完整对象知识与12节点；
2. 对应详细 Canvas 中该题材 Group；
3. 对应视觉总览 Canvas 的题材摘要卡；
4. `state.json`；
5. `run-ledger.md`。

不得只改 Markdown 后声称 Canvas 完成，也不得只画总览而不修对象知识。

## 4｜固定启动顺序

每轮先读取最新 main SHA，再依次读取：

1. `AGENTS.md`；
2. `00-中枢索引/AI文件权力与任务总览.md`；
3. `00-中枢索引/总入口.md`；
4. 本 `SKILL.md`；
5. `state.json` 与 `run-ledger.md`；
6. `00_R4总控.md`；
7. `01_节点化十元重构协议.md`；
8. 当前分类 Markdown、详细 Canvas、视觉总览 Canvas；
9. 当前题材涉及的真实对象知识与现行十元信息卡、准度卡、单条关系卡、十元生补克表。

十元理论文件只读。题材对象知识不能仅凭十元体系内部类推，缺乏对象知识时必须标记 `object_knowledge_incomplete`。

## 5｜扫描顺序

```text
A 恋爱与关系
→ B 身份阶级与社会位置
→ C 命运改写与信息优势

→ H 职业现实与行业
```

每区按 `01 → 08`。B区 R4.3-object-first 作为阅读结构样板，但不得机械复制对象内容或十元结论。

## 6｜12节点标准

### 0 题材入口

列出题材涉及的真实对象和初始主辅十元候选。题材名不继承十元。

### 1 对象

- 必须选择一个可记录前后状态的主对象；
- 先解释对象本身；
- 股份、职位、证据、婚约、名誉、能力、渠道等不得混成“资源”或“权力”。

### 2 主体

分别写清行动者、控制者、确认者、承载者、执行者、制度与公共接口。

### 3 权限与关系功能

```text
权限：定义 / 退出 / 调用 / 调配 / 解释 / 否决 / 任免 / 处置
功能：承载 / 认可 / 保护 / 采用 / 执行 / 对外代表
```

每项落到具体主体，不保留空菜单。

### 4 触发行为

写行动者、对象、目的、回应、收益、代价和第三因素。不得只写事件名。

### 5 状态变化

```text
前态 → 触发 → 后态 → 不可逆变量
```

至少改变一项可观察变量，如准入、表决、否决、署名、任免、采用范围或控制范围。

### 6 十元端点

按阶段逐段重判主次十元，写主体归属、对象层、体量与顺序。十元端点必须建立在对象知识已经明确的基础上。

### 7 生克补

每条关系标记：已锁定可候选／条件调用／研究中未锁定／本题材不成立。

写清源端点、目标端点、机制、被改变变量、阶段、第三因素与失败条件。

### 8 动态链

必须同时保留：

```text
对象链：具体对象A怎样变成对象B
十元链：哪个阶段对子在什么条件下接管另一个对子
```

最低格式：

```text
【阶段A：对象状态｜主符号体量｜次符号体量】
  ──触发、条件、被改变变量──▶
【阶段B：对象状态｜主符号体量｜次符号体量】
  ──接管条件／失败边──▶
【结算：主体、对象、稳定锚点】
```

### 9 主题

主题后置。中心问题、转折、高潮和结局共同显影后才登记候选。

### 10 反证

至少完成一个具体失败条件，并检查拿掉、反向、最近邻与第三因素。

### 11 输出

优先输出：

- 对象知识卡；
- 权利与资格结构卡；
- 主体权限卡；
- 对象状态变化卡；
- 对象链与十元链；
- 创作母型；
- 反证卡。

缺项标记 `topic_node_incomplete` 或 `object_knowledge_incomplete`。

## 7｜高风险边界

- 股份不等于控制权；职位不等于实权；资格不等于取得；名位不等于军权；流量不等于认可；称号不等于公共壳；婚约不等于真实关系。
- `z` 必须分账认可主体、认可内容、采用范围和阶段。
- `nx` 是主体不占据本可拥有的方向决定位置，不是现实落地或普通配合。
- `xn` 必须是主体主动组织结构，不是忙碌或被动遵守。
- `x` 必须落到具体调用、调配、否决、任免、处置或控制边界。
- `x并z` 必须承担识别、准入、代表、调用或保护功能。
- `zx` 必须有公开权能显现或扩大，不由胜利和打脸自动成立。

## 8｜跨区治理

题材可跨区，但每区只保留自身研究对象。例如B区保留身份、准入、名位、控制与认可；职业生产转H，能力升级转D。

## 9｜Canvas写入规则

### 详细 Canvas

- 保留原Group、ID、坐标、尺寸、颜色和无关边；
- 当前题材必须增加对象解释，不得只放十元标签；
- 节点文字按“对象知识 → 十元分析 → 状态变化”组织；
- JSON可解析，节点与边ID唯一。

### 视觉总览 Canvas

每张题材卡至少包含：

```text
要学的对象
对象的一句话区别
对象链
十元链
核心反证
跨区提示
```

视觉总览只导航，不产生理论权力。

## 10｜写入、并发与恢复

写前记录最新 main SHA并重读目标blob。写后立即远端读回。

任一步失败：

- 不推进 currentTopic；
- 标记 `PARTIAL_RECOVERY_REQUIRED`；
- 下轮优先核对和恢复；
- 不得覆盖并发修改；
- 不得因单轮失败、工具错误或额度顾虑停用任务。

不得修改 `01-十元系统/` 理论正本。

## 11｜完成门

一个题材只有同时满足以下条件才算完成：

- 专业对象已有独立解释；
- Markdown 12节点已修正；
- 详细 Canvas 已同步对象知识与十元分析；
- 视觉总览已同步；
- 对象链与十元链均存在；
- 关系状态符合现行L2；
- JSON、提交和远端读回全部通过；
- 状态与账本推进一致。

## 12｜账本与汇报

账本每轮记录：起始SHA、题材、对象知识新增、十元判断、对象链、十元链、修改路径、提交SHA、远端读回、状态和下一断点。

固定汇报标题：

```text
韩漫64题材节点化巡检｜本轮实际工作明细
```

不得用“补充解释”“完成优化”代替对象级工作明细。
