# 韩漫64题材节点化全库巡检 Skill v1.4

## 1｜最高体系口径

### 1.1 五行就是十元

正确结构：

```text
五行就是十元。
木、火、土、金、水各自分阴阳，形成十个直接的十元位置。
每个十元本身就是明确的阴阳五行位。
```

不得写成：

```text
五行与十元是两套系统
五行在上、十元在下
单个十元只是不完整五行的下位标签
两个十元必须先交补才构成一行
```

当前固定映射：

| 五行轴 | 阳极十元 | 阴极十元 |
|---|---|---|
| 木 | `zx`＝阳木 | `nx`＝阴木 |
| 火 | `zn`＝阳火 | `x`＝阴火 |
| 土 | `n`＝阳土 | `x并z`＝阴土 |
| 金 | `xn`＝阳金 | `z`＝阴金 |
| 水 | `xz`＝阳水 | `nz`＝阴水 |

### 1.2 阴阳首先是相反两极

```text
木：阳木zx ↔ 阴木nx
火：阳火zn ↔ 阴火x
土：阳土n  ↔ 阴土x并z
金：阳金xn ↔ 阴金z
水：阳水xz ↔ 阴水nz
```

在应用教学中必须说明：

1. 两端在该题材中分别出现什么具体对象、行为、权限或关系；
2. 两端为什么构成同行相反；
3. 人物或对象是否发生从一端滑向另一端的真实变化；
4. 两端冲突如何产生剧情；
5. 是否存在第三因素导致表面像一端、实质落在另一端。

`↔`只表示静态阴阳相反轴，不表示时间、因果、生克补、自动转化或必然共现。不得把“阴阳相反”偷换成“两个方面已经互补”。交补、平衡、共存、压制、转化或接管必须由具体案例另行证明。

## 2｜三种工作层

```text
理论本体层
十元即阴阳五行、五组相反轴、对子、五维、生克补和动态规律

应用教学层
用阴阳五行十元拆解外部知识，建立名词、区别、对象链和创作联想

分析验证层
用12节点、主体权限、体量顺序、生克补、反证和动态链验证具体案例
```

韩漫64题材库同时保留应用教学与分析验证，但不得混成一篇难读的审计报告。

## 3｜三个载体职责

### 3.1 分类 Markdown：应用教学正本

对应 `A_..._节点化.md` 至 `H_..._节点化.md`。

固定结构：

```text
题材学习目标
→ 核心专业名词
→ 相邻名词区别
→ 五行五组相反轴
→ 每组阴阳十元的具体名词联想
→ 对象从一端到另一端的真实变化或不变化
→ 对象连接链
→ 剧情、角色和场景应用
```

Markdown不得以十元基础定义、12节点审计、关系卡核验或动态链验证为正文主体。

### 3.2 详细 Canvas：分析验证载体

负责：

- 12节点；
- 主对象与关联对象；
- 主体、权限和关系功能；
- 前后状态与不可逆变量；
- 五行主轴与阴阳两端；
- 阶段主次十元；
- 体量和顺序；
- 生克补关系状态；
- 对子到对子的动态链；
- 拿掉、反向、第三因素和失败边；
- 结算与稳定锚点。

### 3.3 视觉总览 Canvas：教学导航

负责：

- 8题材导航；
- 每题材核心专业名词；
- 五行五组相反轴；
- 阳端与阴端的具体名词；
- 最重要的名词区别；
- 对象连接链；
- 创作入口；
- 指向详细分析 Canvas 的链接。

视觉总览不得只显示十个孤立符号，也不得把阴阳画成两条毫无关系的并行清单。

## 4｜最高教学门禁：十元用于拆知识

### 4.1 学习对象是外部知识

题材库要教会：

- 股份、表决权、否决权、控制权；
- 血缘、法律身份、家族承认、资源准入；
- 发布权、署名权、版权、流量和专业认可；
- 皇位、军权、诏书、财政和官僚体系；
- 以及其他题材中的具体制度、技术、关系和行为对象。

阴阳五行十元负责拆开、对照和连接这些对象，不是题材文件重新讲授的主角。

### 4.2 禁止直接贴标签

禁止：

```text
股份 = x
制度 = xn
危机 = xz
家庭 = n
```

必须先解释对象：

```text
股份包括哪些权利
股份与控制权有什么区别
表决联盟、董事席位和章程怎样改变控制
随后再放入对应五行相反轴观察
```

### 4.3 每题材必须做五组相反轴

最低格式：

| 五行轴 | 阳端具体对象 | 阴端具体对象 | 相反冲突 |
|---|---|---|---|
| 木 | `zx`具体名词 | `nx`具体名词 | 按信息卡验证，不得只写主动↔被动 |
| 火 | `zn`具体名词 | `x`具体名词 | 按信息卡验证，不得只写精神↔物质 |
| 土 | `n`具体名词 | `x并z`具体名词 | 按信息卡验证，不得只写内部↔外部 |
| 金 | `xn`具体名词 | `z`具体名词 | 按信息卡验证，不得只写制度↔个人 |
| 水 | `xz`具体名词 | `nz`具体名词 | 按信息卡验证，不得只写危险↔安全 |

不是每一端都必须在案例里成立，但必须明确：常见、条件出现、缺席或容易误判。相反轴的具体语义必须回到现行十元信息卡与准度卡，不能用一句方便口号替代。

### 4.4 必须有具体名词

禁止只写：

```text
资源、权力、身份、关系、认可、制度、危机
```

必须下钻：

```text
资源 → 股份、现金流、军饷、账号、排期、教育基金
权力 → 表决、否决、任免、发布、署名、军令
身份 → 董事长、法人代表、继承人、皇帝、艺名、正式配偶
```

### 4.5 必须做名词区别

每个题材至少区分三组相邻概念，例如：

```text
股份 ≠ 控制权
继承资格 ≠ 已经继承
流量 ≠ 认可
皇位 ≠ 军权
婚约 ≠ 真实关系
变美 ≠ 社会位置上升
```

1. 分类 Markdown 应用教学；

## 8｜分析验证标准

详细 Canvas 的动态链必须是对子到对子，而不是剧情摘要：

```text
前阶段五行主轴／阴阳端点
──触发、被改变变量、体量与条件──▶
中阶段五行主轴／阴阳端点
──接管或失败条件──▶
结算阶段对子、关系和稳定锚点
```

必须写明：

- 主符号或主次符号；
- 直接五行身份；
- 阴端或阳端；
- 主体与对象；
- 被改变变量；
- 生克补关系状态；
- 失败边和替代解释；
- 最终结算。

研究中关系只能标记为研究中，不得写成正式机制。

## 9｜写入与恢复

写前：

1. 重读最新 `main`；
2. 重读目标文件 blob SHA；
3. 检查并发写入；
4. 检查当前 state 断点。

写后：

1. 远端读回 Markdown；
2. 远端读回详细 Canvas；
3. 远端读回视觉 Canvas；
4. 校验 state 和 ledger；
5. 五份成果一致后才推进下一题材。

任一步失败：

- 保留当前断点；
- 写入 `PARTIAL_RECOVERY_REQUIRED`；
- 记录阻断路径和最后成功 SHA；
- 下一轮优先恢复；
- 不得停用每小时任务。
