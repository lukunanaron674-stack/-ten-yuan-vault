# 静态文字横纵构图 Skill｜USER范式

## 唯一方法正本

先读 `黎黎隆项目/20_Agent系统/04_协议/STORY_TENYUAN_CROSS_VERTICAL_PROTOCOL.md` 的 `静态文字横纵构图｜默认呈现规范` 章节。此 SKILL 是调用入口，不另定义竞争关系理论。涉及十元判定，仍需读取现行 L2 关系正本；涉及 Obsidian 节点布局则另调 `07-Codex大脑库/skills/obsidian-canvas-layout/SKILL.md`。

## 什么时候用

- 用户说“文字横纵构图”“就照静态视觉线那样画”“横向对象纵向因果”“给我一张文字关系图”“反馈/依赖链”“这个故事太难看懂”。
- 剧本/电影/角色十元研究：把同一事件的多方关系、物件、动作、后果和跨阶段因果合进同一张文字网。
- 任务/工单系统：画生产链、审核回流、正式依赖、未接入输入与待核阻塞。

## 强制输出

1. **第一屏就是等宽纯文字主图**，固定顺序：`标题分区────────`、同层多列、`──→`流向、跨层`│/↓/└──→`、反馈/回收区、待核区。
2. 横向必须同事件同时间窗，列出谁能做什么、谁知道什么、物件/制度如何限制、具体改变的变量；避免将不同角色写成彼此独立的年表。
3. 纵向用明确输入/输出箭头连接，不能仅把多个“事件E1/E2/E3”堆起来。
4. **反馈必须有指向**：例如`审核 FAIL ──→ 制作重跑`或`祖母旧事 ──→ 当下人物改变决定`；不画无根据的回路。
5. 用户确认、可核事实、AI假设和未判定分别标 `【USER】`/`【事实】`/`【H】`/`【待核】`；十元符号不代替事件因果，补位位置不等于已启动。
6. 一张主图优先，不拆成大量卡片、长表或几十行讲解；图后只用短句点出最大的因果漏洞。

## 验收

能顺着横线追踪谁作用于谁，顺着纵线追踪上一层的输出如何成为下一层的前提，顺着回流线看见反馈返回何处。三种追踪任一断裂则 `FORMAT_FAIL`，不得宣称完成文字横纵构图。

## 与 Obsidian Canvas 几何排版区分

本 Skill 生成**纯文字视觉网络**，不会移动/改写 `.canvas` 节点；用户明确要求改 Canvas 时才另调用 JSON Canvas 排版 Skill。
