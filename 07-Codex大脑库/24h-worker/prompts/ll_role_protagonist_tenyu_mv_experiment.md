# 《黎黎隆》角色主角实验｜十元魅力 MV｜Codex 执行文案 v1.0

## 任务目标

把《黎黎隆》角色库当作“角色主角实验场”：每个角色卡都可以当本轮主角，包括尚未完成的角色。用 GitHub 中真实可核验的角色图、场景图和设定，测试：

`十元结构 → 生/克/补关系 → 可观察变量变化 → 角色行动 → MV镜头 → 角色魅力`

本任务不是等待角色全部定稿，也不是写空泛故事或漂亮概念图，而是积累可跑 H3、可剪 MV、可回收为动画资产的实验记录。

## 每轮执行顺序

1. 读取仓库 `lukunanaron674-stack/-ten-yuan-vault` 的最新 `main`。
2. 扫描并核对：
   - `黎黎隆项目/03_角色`：角色卡、角色图、已确认造型；
   - `黎黎隆项目/04_场景` 与 `黎黎隆项目/场景视觉参考`：场景卡、场景图；
   - `黎黎隆项目/十元应用实验室.md`、动态链规则和已有角色实验记录。
3. 每轮只选一位主角；优先轮换最近较少使用的角色。其他角色只能作为对位对象，不能抢走本轮主角中心。
4. 每个角色完成三类实验：
   - 单人魅力；
   - 角色 × 场景；
   - 角色 × 他者 / 怪物 / 物件 / 制度。
5. 每类实验先写三条明显不同的候选，再选一条形成 3 镜头、约 9–15 秒的微故事：初始状态 → 生/克/补发生 → 主角独特回应与魅力落点。
6. 另外给出 5 条独立的 3–5 秒 MV 镜头词，总计 8 条。

## 证据与十元规则

- 必须标出实际角色图路径/链接、实际场景图路径/链接、读取分支或版本。
- 找不到文件、无法读取二进制、十元未确认时，写 `待配图`、`未读到设定`、`候选解释`；禁止编造。
- 分开记录：
  1. 角色卡已确认十元；
  2. 场景/对位对象已确认十元；
  3. 本轮候选解读；
  4. 尚待验证关系。
- 先回答“谁改变了谁的什么变量”，再设计动作和镜头。每条关系必须写：
  - 主十元 → 次十元；
  - 生 / 克 / 补及作用方向；
  - 施力方 → 承受方；
  - 起点 → 作用 → 终点；
  - 被改变的具体权利、路径、空间、身体状态、关系接口、信息或选择变量。
- 不得只用颜色、表情、音量、快慢、抽象气氛证明十元关系；不得把既有十元定义擅自改写。

## 每条镜头必填

- 编号、主角、实验类型；
- 角色图路径/链接、场景图路径/链接；
- 角色十元、场景/对位对象十元，并标明“已确认 / 候选 / 待验证”；
- 生克补关系与方向；
- 本条要检验的魅力（灵、稳、狠、慢、古怪、纯粹、承担、疏离、温柔、不服输等，不能只写“好看”）；
- 景别、机位、唯一主要运镜；
- 3–5 秒内的单一主要动作与肢体/视线表演；
- 起始画面 → 变化 → 结束画面；
- 音乐节拍、动作落点、前后镜头切点；
- 可直接复制的自然中文 H3 提示词；
- 负面约束。

可吸收 Eve《ファイトソング（Fight Song）》MV 的音乐性、动静反差、形状匹配、动作接力和景别跳切思想，但不得照搬具体镜头、角色、故事或歌词。单镜头不塞多个复杂转场，真正的蒙太奇留给后期。

## 角色一致性

黎黎隆若被选中，必须保持已确认的基础比例、脸型、两片头盔卡扣、长机械龙尾上/中/下节奏、机械龙爪脚和服装主体剪影；Z 必须表现为古灵精怪、机灵、跳脱、出其不意、灵活变通，不能被缩成“追查/接口化”。其他角色只锁定仓库中已确认部分，未完成部分标为待定，不擅自补完。

## 交付与验收

输出顺序：先给 8 条可直接使用的 H3 镜头词及素材对应，再给精炼研究记录。

末尾写《十元实验记录》：
- 本轮主角、三类实验、三个候选及选中理由；
- 8 条镜头编号与小故事；
- 十元关系的可检验假设；
- 一个竞争性解释 / 失败原因；
- 预期观众记住的魅力；
- 需要从实际视频检查的证据；
- 下一轮只改变的一个变量；
- `H3状态：未运行 / 已运行`、`盲审状态：未审 / 已审`。

没有真实 H3 视频和独立盲审时，必须写“仅设计假设，尚未验证”。不得把文字生成、自评或模型想象当成视频验证。

## Codex 边界

默认只读 GitHub 并输出任务卡/提示词。只有在真实执行链、文件权限和费用授权均存在时才运行本地生图或 H3；不得虚报运行、上传、Canvas 归档或验收。若需要修改仓库文件，先读取最新版本，使用独立分支/PR，不直接推 `main`，并回读验证实际提交。
