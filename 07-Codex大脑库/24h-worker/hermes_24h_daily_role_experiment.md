# Hermes × Codex｜《黎黎隆》角色主角实验 24h 每日督促协议 v1.0

## 目的

Hermes 是每日监督与交接层，Codex 是执行层。两者共同推进“每个角色卡都是主角”的十元魅力实验：

- 每天轮换角色；
- 每个角色做单人 / 场景 / 互动三组实验；
- 每轮产出 8 条 H3 镜头词；
- 累积十元生克补如何转成镜头、微故事与角色魅力的证据；
- 不把文字设计、自评或漂亮画面冒充真实视频验证。

## 24 小时循环

### 00:00–06:00｜状态守夜

- 检查上一日 8 条镜头是否有实际产出、是否重复、是否标注素材路径；
- 检查 Codex/H3/图片链路失败、超时和待领取项；
- 检查是否有重复角色、重复对象、重复关系、重复动作；
- 只记录阻塞，不为了“有进展”重写旧结论。

### 06:00–12:00｜角色与素材准备

- 从 GitHub 读取最新角色卡、角色图、场景图；
- 选定当天唯一主角，优先最近未覆盖角色；
- 核对角色十元、场景十元和已确认造型；
- 缺图或缺设定就标记，不虚构；
- 为 Codex 准备当天三类实验的输入清单。

### 12:00–18:00｜执行与检查

- 督促 Codex 完成单人 / 场景 / 互动三组实验；
- 每组先发散 3 个候选，再选 1 个进入 3 镜头微故事；
- 汇总 8 条 H3 提示词；
- 如本地执行链真实可用，检查图像/视频、prompt、run_id、时间、文件路径；无证据不得标“已生成”。

### 18:00–24:00｜回收与日报

- 检查 8 条镜头字段是否完整；
- 将可复用的十元→关系→动作→镜头规则写入实验记录；
- 区分“设计假设”“实际生成”“盲审结论”；
- 生成 `role_mv_daily_YYYY-MM-DD.md`；
- 给出次日唯一变量：只改变角色、对象、关系、动作或镜头语言中的一个；
- 若全天没有真实新证据，写“本日无实证进展”，不得用重复发散充数。

## 每日验收标准

当天只有同时满足以下条件才可标记 `DAY_DONE`：

1. 有且仅有一位主角；
2. 三类实验均有记录；
3. 8 条镜头均有真实角色图/场景图路径，或明确标记缺失；
4. 每条都有十元关系方向、改变变量和起点→终点；
5. 至少一条微故事能在 3 镜头内成立；
6. H3 提示词可直接复制；
7. 实际视频与盲审状态分开记录；
8. 日报写明阻塞、失败原因和次日唯一变量。

未满足时写 `DAY_BLOCKED`，并列出最小阻塞，不得伪造完成。

## Hermes 督促规则

- Hermes 只监督、提醒、汇总和暴露阻塞，不代替 Codex 编造图片或视频结果。
- 每次督促必须指向一个具体缺口：角色图、场景图、十元证据、H3 提示词、实际视频、盲审或归档。
- 连续两次无新证据时，暂停重复发散，改做查重、素材核验或失败分析。
- 不新建重复的每小时任务，不恢复已停用的 I04 场景核验，不连接 Teams，不自动上传私有图片，不自动 push `main`。
- 不修改十元核心理论；有争议只进入“候选解释 / 待确认”，不冻结。
- 每日汇报格式：`日期｜主角｜三组实验｜8条镜头｜实际视频数｜盲审数｜新增经验｜阻塞｜次日唯一变量｜DAY_DONE/DAY_BLOCKED`。
