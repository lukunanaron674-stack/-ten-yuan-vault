# 十元关系长期阻塞降级门禁 v1.0

> 用户采用B方案：严格生克补长期不能成立，但较弱机制能够稳定复现时，降级为“条件关系 / 概率关系 / 入口关系”，不再无限期冒充严格生克补，也不直接删除历史证据。

## 1. 总原则

```text
严格关系没有通过
≠ 关系完全不存在
≠ 可以永远保留在严格关系推进池
```

审计必须分开三个判断：

1. 严格`生 / 克 / 补`机制是否成立；
2. 是否存在稳定但更弱的作用形式；
3. 该弱作用应归为条件、概率、入口，还是普通共现/显影/加权/状态影响。

## 2. 三种降级类型

### 2.1 条件关系 `conditional_relation`

源端点只有在明确前置条件、阶段或结构缺口成立时，才改变目标端点；离开条件后关系不稳定或不成立。

必须写明：

- 必要前置条件；
- 适用阶段；
- 被改变变量；
- 条件拿掉后的结果；
- 不适用范围。

### 2.2 概率关系 `probability_relation`

源端点只提高或降低目标出现、持续或被调用的概率，不能单独生成、克制或补足目标核心变量。

必须写明：

- 概率方向；
- 不能证明的严格机制；
- 中介变量与第三因素；
- 至少两类独立模板中的复现；
- 不得使用“通常如此”代替证据。

### 2.3 入口关系 `entry_relation`

源端点只建立目标关系、状态或结构的入口、许可、启动机会或候选位置；目标的稳定形成仍依赖后续共同时间、承载、制度、修复或其他关系。

必须写明：

- 入口前目标为何尚未成立；
- 源端点具体打开什么入口；
- 后续由什么机制完成稳定结构；
- 只到入口而未完成目标的反例；
- 入口撤回与稳定目标形成后的不同后果。

## 3. 状态机

```text
ready / research-active
→ 连续三轮无新增独立证据
→ blocked_waiting_evidence
→ 退出普通每小时轮转
→ 等待一次跨领域复验或高质量新证据
→ 严格关系通过：恢复严格研究或锁定
→ 严格关系失败、弱机制稳定：downgraded-conditional
→ 严格与弱机制均失败：保留为否定记录，另行进入移出审查
```

`blocked_waiting_evidence`只是停止空跑，不等于自动降级，也不等于自动删除。

## 4. 进入跨领域复验的条件

长期阻塞关系只有满足以下任一条件，才允许重新进入审计：

- 链条问题单提交命中该卡明确证据缺口的P0/P1/P2新证据；
- 出现与原主要材料不同领域、制度或人物模板的控制案例；
- 用户提供能够解决核心定义分歧的判断；
- 现行信息卡、准度卡、关系卡、关系表或词典发生实质变化；
- 已识别出一个可检验的弱机制，需要判断是否应降级收口。

普通相似案例、同一作品的换场景复述、情绪更强的同类桥段，不构成跨领域复验。

## 5. 降级门槛

关系只有同时满足以下条件，才可由严格关系降级为B类弱关系：

1. 源、目标端点本身稳定，不是端点误判；
2. 严格`生 / 克 / 补`的核心变量变化在关键拿掉、反向或第三因素冻结中失败；
3. 至少两类独立领域、制度环境或人物模板中，出现同一种更弱机制；
4. 弱机制能够被可观察条件描述，并有明确反例；
5. 弱机制不能被单纯共现、剧情先后、视觉相似、主题公式或情绪强度完全解释；
6. 审计明确说明为什么它不是严格关系，又为什么不是零关系；
7. 关系卡理论版本必须递增，并完成关系索引与必要正本同步。

只因连续三轮无新增、最终分低于95或暂时找不到案例，不得直接降级。

## 6. 降级后的卡片字段

实际降级时，原关系卡保留原路径和历史，frontmatter至少写入：

```yaml
relation_status: downgraded-conditional
strict_relation_eligible: false
weak_relation_type: conditional_relation | probability_relation | entry_relation
downgraded_from: 生 | 克 | 补
downgrade_run_id: null
downgrade_commit: SELF
downgrade_reason: null
cross_domain_templates: []
```

正文必须新增：

```text
## 严格关系为何失败
## 保留下来的弱机制
## 弱机制成立条件
## 弱机制失败条件
## 与共现/显影/加权/状态影响的区别
## 重新升级为严格关系所需证据
```

## 7. 对索引与正本的影响

降级完成后：

- 原单卡保留，不删除历史；
- 生/克/补索引状态改为“条件关系”“概率关系”或“入口关系”；
- 该关系退出严格未锁定推进池，不再按普通`next_priority_relation`循环；
- 十元生补克表不得继续把它计作严格生克补；
- 关系词典与专项正本记录弱关系类型、条件和边界；
- 动态链可以引用弱关系，但必须显式标注类型，禁止仍画成严格`生 / 克 / 补`箭头；
- 所有旧案例与失败证据保留，作为降级依据和未来升级审计材料。

## 8. 对当前关系的处理

本协议生效时，不自动修改任何现有关系卡。

- 已处于`blocked_waiting_evidence`的关系：等待跨领域复验；
- `z 生 nz`：当前已有“关系入口”候选，但尚未完成跨领域复验，不立即降级；
- 其他关系若只能稳定证明进入概率、显影、加权、状态压制或条件作用，也必须按本协议单独审计后再降级。

## 9. 审计运行要求

每轮遇到长期阻塞关系时，汇报必须增加：

```text
是否为跨领域复验：是 / 否
严格机制结果：通过 / 失败 / 未完成
弱机制候选：none / conditional / probability / entry
弱机制跨领域复现：0 / 1 / 2+
本轮处理：继续阻塞 / 恢复严格研究 / 降级B类 / 进入移出审查
```

若决定降级，必须真实更新单卡、索引、必要关系表/词典/专项、中枢和账本，并完成原子提交与全链回读；不得只在账本写“已降级”。

## 10. 与A、C方案的关系

- 不采用A作为无限期默认：没有明确新证据路线的关系不能永久留在严格推进池。
- B是当前正式收口规则：严格关系失败但弱机制稳定时，降级保留。
- C不是本协议的自动结果：只有后续证明连弱机制也无法跨领域复现，才进入“移出严格表并保留否定档案”的单独审查。

## 11. 一句话

```text
严格关系证明不了，就验证它究竟是条件、概率、入口，还是根本没有关系；能稳定保留的弱机制要降级命名，不能继续冒充严格生克补。
```
