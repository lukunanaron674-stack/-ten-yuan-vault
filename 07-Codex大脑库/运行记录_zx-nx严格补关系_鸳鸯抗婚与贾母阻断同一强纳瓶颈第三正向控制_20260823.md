## 1｜事实资产

- 鸳鸯明确占据“不嫁贾赦”的方向，并公开把拒绝压入现实，当前 `zx` 端成立。
- 贾赦仍具有现实推进强纳的能力，个人拒绝不足以稳定阻断。
- 贾母拥有真实上位保护/留用/阻断权限，鸳鸯实际进入该接口，当前 `nx` 端成立。
- 第四十七回贾赦最终“无法，又且含愧”，转而另买嫣红，说明原强纳鸳鸯路径确实被现实阻断。

## 2｜nx → zx

去掉贾母或等价保护/否决接口：

```text
鸳鸯拒绝方向仍成立
→ 但贾赦仍可通过家内身份、兄嫂、邢夫人继续推进
→ 个人拒绝缺稳定现实阻断力
```

因此：

```text
贾母 nx 保护/否决接口
→ 补鸳鸯 zx 的现实阻断路径缺口
```

成立。

## 3｜zx → nx

按 current canonical：

```text
zx 补 nx
= 把外部关系/权限通道转成实际行动、公开决定和结果推进
= 补 nx 单独运行时“有路径却缺落地权能”的缺口
```

保留贾母的一般家内保护/留用权，但拿掉鸳鸯自己的明确、公开拒绝：

```text
保护/否决路径仍存在
→ 但缺将该路径具体兑换成“鸳鸯不嫁贾赦”这一同对象层结果的主体方向输入
```

原文内部反事实亦支持：邢夫人的思路就是“老太太虽不依，搁不住鸳鸯自己愿意”。若鸳鸯本人愿意，贾母的一般留用偏好并不自动等价生成“替鸳鸯拒婚”的同一结果。

因此鸳鸯 `zx` 把贾母已有保护路径触发、具体化并兑现为公开现实阻断，符合 current canonical 的“有路径却缺落地权能”。

## 4｜第三因素冻结

“贾母依赖鸳鸯、舍不得她”可以解释贾母为什么愿意动用保护接口，但不能替代：

- 鸳鸯自己的拒绝方向；
- 贾母真实否决能力；
- 两端对同一强纳瓶颈的双向补缺。

冻结时不得把“贾赦仍能现实推进强纳”这一命名瓶颈直接删除。

## 5｜对象分层继续保留

鸳鸯长期婚姻方向可以非 nx，同时局部家内保护/阻断权限仍为 nx；对象层不能互相覆盖。

本轮只恢复严格补子结论，不修改人物稳定本体。
