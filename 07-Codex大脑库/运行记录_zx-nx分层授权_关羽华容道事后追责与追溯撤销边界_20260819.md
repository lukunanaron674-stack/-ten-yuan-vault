# 运行记录｜关羽华容道：事后追责 与 追溯撤销边界

## 结论先行

本轮不重复创建“关羽华容道”人物正式案例，而是复用已有 99/98 `evidence-locked` 案例，专门反打当前待审议问题的下一刀：

> **上级在事后能够处罚主体，不等于上级能够追溯撤销主体已经造成的局部现实结果。**
>
> 因此，“事后追责权”不能直接倒推为“该局部决定当时必须经事前批准”，也不能单独把局部行为从 `x / 非nx` 打回 `nx`。

本轮仍不锁关羽稳定人物本体，不锁严格 `zx↔nx` 补关系。

## 1｜剧情事实

### 1.1 事前外部军令真实存在

诸葛亮命关羽守华容道，并要求不得容情；关羽立下军令状。

### 1.2 关羽在真正结果窗口实际否决

曹操到华容道后，关羽明知军令，最终仍实际放行。曹操因此脱离华容道，继续逃走。

### 1.3 事后追责真实存在

关羽回营后主动请死。诸葛亮指出其念旧恩故意放行，并依据军令状命武士推出斩首。

下一回刘备以桃园结义、生死之盟请求“权记过，容将功赎罪”，诸葛亮随后赦免关羽。

所以事后组织确实拥有：

```text
追责
→ 拟处罚
→ 最终记过/赦免
```

### 1.4 但曹操逃脱这一既成结果没有被追回

无论诸葛亮是否处罚关羽，都不能把“曹操已经被放走”追溯改回“曹操已在华容道被擒/被杀”。

因此必须拆开：

```text
对象A：关羽本人是否受军法处分
→ 组织事后可处理

对象B：曹操是否已经从华容道逃脱
→ 既成局部结果没有被追溯撤销
```

## 2｜nx 判断

已有正式案例已锁：在“曹操放不放”这一最终执行层，关羽实际使用否决，故 `nx_in_final_execution_decision_layer: rejected`。

本轮新增限制：

> **不能因为诸葛亮事后能处罚关羽，就反推关羽当时的现场结果必须经诸葛亮再次批准。**

军法追责说明组织能够处理“违令者”，不等于组织能够实时或追溯取消“已经发生的放行结果”。

因此：

```text
事后可处罚主体
≠
事前必须批准局部行为
≠
事后可撤销既成局部结果
```

## 3｜zx 判断

关羽放曹操仍不形成 `zx`。

原因不变：一次强烈违令和巨大后果，没有使关羽获得新的长期军事裁决范围；他回营后反而继续受军法约束。

所以：

`zx_in_narrow_stage: rejected_as_primary`

## 4｜关键压力

压力包括：

- 军师明确命令；
- 军令状；
- 违令可能处死；
- 曹操旧恩与义气动机。

这些压力可以解释关羽选择成本，但不能代替权限结构判断。

## 5｜最近邻排除

### nx vs x

本轮不把关羽“放曹操”锁成正式 `x` 权限，因为小说没有证明“违背诸葛亮战略、决定敌方最高目标去留”本来就是关羽稳定授权范围。

本轮只讨论：**事后追责不能反推事前批准。**

### nx vs nz

旧恩、义气解释关羽为什么放曹操，但不回答组织是否能追溯撤销既成结果。

### nx vs xz

军令状和死刑风险属于压力，不等于最终方向归属。

### zx

强违令、强后果不等于扩权。

## 6｜拿掉测试

### 拿掉诸葛亮事后处罚

曹操已经逃脱这一事实仍成立；因此局部结果是否成立，并不依赖事后处罚。

### 拿掉刘备求情

即使关羽最终真的被军法处死，曹操逃脱仍然无法追溯改写。

所以：

> **“上级能追责到很重”也不等于“上级能撤销已经生效的前一层结果”。**

### 拿掉曹操的历史重要性

只要是“主体先让结果成立，随后组织只能处罚主体而无法恢复原结果”，本边界仍成立。

## 7｜反向测试

真正的“事后追溯撤销”应满足：

```text
主体先让决定生效
→ 更高节点事后行使稳定撤销权
→ 原决定被法律/组织/制度上判为失效
→ 对象被恢复到原状态或强制回滚
```

例如：临时任命被上级撤销、处分被撤回并恢复职位/资源、交易/许可被追溯取消且现实接口恢复。

只有这种材料，才能真正检验：

> “先行动后报告”是否足以形成完整局部 `x`，还是只形成可被上级追溯覆盖的临时处分层。

华容道本例不满足这一反向结构，因此只能作为**追责 ≠ 撤销**的控制，不能替代真正的“追溯撤销”样本。

## 8｜第三因素冻结

冻结：

- 关羽忠义评价；
- 曹操历史命运；
- 诸葛亮是否故意安排关羽还恩；
- 刘备是否偏袒；
- 关羽武力；
- 军令状是否严格执行。

只看：

```text
局部结果是否先成立？
事后动作针对“主体责任”还是针对“结果本身”？
更高节点能否让既成结果失效/回滚？
```

## 9｜对 pending-review 的增量

当前“nx：事前批准 与 事后回报边界”下一步不能把所有事后上级动作统称“追溯撤销”。应先分三类：

```text
A｜事后报告/备案
→ 不自动打掉局部 x

B｜事后追责/处罚主体
→ 仍不等于撤销既成结果

C｜事后追溯撤销结果本身
→ 才可能说明该局部处分只是临时层，需重新检查更高最终权限
```

本轮正式增加 B 类控制。
