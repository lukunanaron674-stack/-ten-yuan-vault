# 杨志押送生辰纲｜名义提调授权被现实覆盖，稳定 x 不足

## 1｜本轮问题

只测试一个窄对象层：

> 梁中书已经把押送任务交给杨志，并允许他自行设计运输方式；这是否足以证明“何时走、何时停”已经稳定进入杨志现实处分 `x`？

结论：**不够。** 名义授权和实际执行能力都存在，但黄泥冈“是否停歇”这一同一对象层发生现实覆盖，说明稳定 `x` 不能只靠纸面授权锁定。

## 2｜剧情事实

《水浒传》第16回中：

1. 梁中书把生辰纲押送任务交给杨志，并接受杨志提出的低调装扮、精简人手等运输方案；
2. 杨志随后真实组织队伍、催行、约束军健，说明他不是纯名义负责人；
3. 到黄泥冈，杨志判断此处危险，坚持不能停歇；
4. 老都管明确要求众人歇息，并以自身在相府的关系位置压回杨志；
5. 众军健实际停下，杨志的“不停”决定没有稳定生效；
6. 后续买酒节点中，老都管再次介入，杨志最终让步。

因此当前最有信息量的事实不是“杨志被任命了”，而是：

```text
名义授权存在
+
主体确有部分现场管理动作
但
同一对象层关键决定可被原关系节点现实覆盖
→ 稳定 x 不足
```

## 3｜x 判断

current x canonical 要求：

> 对象真实进入主体可占有、调用、调配、处分、否决或排除的边界，而且不能只是职位、授权文本或一次接触。

本例在“运输方案设计、日常催行”上有局部 `x` 候选，但在本轮被测的“黄泥冈是否停歇”对象层：

- 杨志明确说“不停”；
- 老都管要求“停”；
- 现实结果偏向老都管；
- 杨志不能稳定让自己的决定直接生效。

所以本轮锁：

```yaml
real_x_stable_for_tested_stop_rest_decision: false
local_x_in_other_subtasks: possible_not_counted
```

这不是说“杨志整趟押运完全没有 x”，而是严格对象分层：**局部管理存在，不等于整个押运任务所有决定都已稳定内化。**

## 4｜zn 判断

本轮不锁 `zn`。

谨慎、职业经验、害怕失职、坚持赶路，都不能单独通过 `zn` 的内部不可让渡原则门。当前桥段缺少一项在拿掉官职、奖惩、任务责任和现实风险后，仍保有跨情境未来指导资格的明确内部原则。

因此：

```yaml
zn_current: not_locked
stable_zn_essence_locked: false
```

## 5｜关键本体变量

本轮火轴被测变量不是“杨志是什么职位”，而是：

> **押运中的某项具体决定，是否真正进入‘归杨志掌握、可直接处分并让现实结果响应’的边界。**

可观察分水岭：

```text
别人说“归你管”
≠
同类决定稳定由你生效
```

尤其要检查：

- 原节点是否仍可事前覆盖；
- 主体决定被反对后是否必须让渡/重配；
- 同类权限是否需要再次经过关系权重确认。

## 6｜拿掉测试

### 拿掉梁中书名义授权

只保留黄泥冈冲突事实：

> 杨志“不停”的决定被老都管现实压回。

稳定 `x` 仍不足。

说明纸面授权不是本轮分类支柱。

### 拿掉现实覆盖

若老都管反对后仍无法阻止杨志继续赶路，众军必须服从“不停”，则被测对象层 `x` 明显上升。

说明真正支柱是**决定能否在现实冲突中直接生效**。

## 7｜反向测试

要把名义授权升级为现实稳定 `x`，应看到：

```text
主体取得授权
+
同类决定无需逐次重新申请
+
外部节点反对也不能在生效前稳定覆盖
+
现实节点持续围绕主体决定运行
```

原著的黄泥冈停歇节点没有达到这一纯度。

## 8｜最近邻排除

- `x vs z`：提辖身份、梁中书信任、相府关系都只是位置/认可线索，不能替现实处分权；
- `x vs nx`：本例可以出现外部关系权重压回主体决定，但本轮只为火轴 `x` 取证，不从木轴关系结论反推火轴定义；
- `x vs xn`：杨志自行设计运输方案、组织路线可以有 `xn` 邻近，但“怎么组织”不回答“谁能最终决定是否停”；
- `x vs zx`：拥有某项实际权限是 `x`；是否继续扩大到更高边界才查 `zx`。
