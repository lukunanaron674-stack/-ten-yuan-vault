# 待审议问题｜zx↔nx 分层授权灰区

## 触发原因

连续材料压力测试中，已经跨三个独立作品复现同一类边界：

> **主体的“上位任务／战略方向”可以由外部给定，因此在该对象层呈现 `nx` 关系位置；与此同时，任务内部的局部对象、资源、人员和调用边界又可以真实交给主体，形成 `x`。这种分层不能因为主体有局部实权就抹掉上位 `nx`，也不能因为上位方向外置就把主体所有局部权限都写成 `nx`。**

目前支持案例：

1. 《三国演义》关羽受印守荆州；
2. 《水浒传》呼延灼征梁山；
3. 《西游记》孙悟空任弼马温。

三例都满足：

```text
上位任务 / 战略方向由外部给定
+
局部职务或战役权限真实可独立调用
+
未见主体把最高方向或决定边界继续公开推到原授权之外
```

因此触发待审议阈值，但不直接改理论正本。

2026-08-18 补入《红楼梦》薛宝钗反向控制：王夫人虽明确请宝钗协助照看园中，但同时规定若相关人“不听”，宝钗必须回报王夫人。该例证明“受托、被授权、进入管理位置”本身不足以证明局部 `x` 已形成；必须检查冲突发生时，主体能否不回原授权者而独立让处分生效。

---

## 需要审议的核心问题

### 问题 A｜木轴是否应显式要求“对象层分层”

当前 L1 已经把木轴定义为“最终方向与作用权来源”，但案例显示同一人物同一阶段可以出现：

```text
最高方向来源：外部 → nx
局部调用边界：自身可独立处分 → x
```

待审议：是否需要在准度层明确写出“最高方向层、局部权限层、运行方法层必须分开，不可互相覆盖”。

### 问题 B｜受权获得真实局部权限何时仍只是 x，何时升为 zx

三个正向样本提示：

```text
别人把一块权限正式交给我
→ 我在边界内正常调用
```

优先可解释为局部 `x`，并不自动等于 `zx`。

只有进一步出现：

```text
我把决定边界公开推到原授权之外
→ 他者或秩序围绕新增决定接口重新反应
→ 我的决定范围继续上升
```

才有充分理由锁 `zx`。

该边界与现有“已有权限有效 ≠ 权限扩大”的待审议问题相邻，但本问题强调的是**授权层级分割**，不是单纯静态 `x vs zx`。

### 问题 B2｜“被授权”何时连局部 x 都不能锁

《红楼梦》宝钗案例补出反向边界：

```text
上级给我照看/提醒/协助职责
→ 我可以发现问题并提出意见
→ 但冲突发生后，对方若不听
→ 我仍必须回到原授权者
→ 新方案/处分不能由我独立生效
```

此时不能因为“进入管理位置”就写成局部 `x`，更不能跳到 `zx`。

当前最窄候选纪律：

> **局部 `x` 的高质量证据，不是“有任务、有头衔、有协助权”，而是主体在该对象层拥有真实可独立调用的决定/处分接口。若发生不服从或冲突后仍必须回到原授权者，优先保留 `nx` 权限关系，并把局部 `x` 降级或排除。**

### 问题 C｜nx 与 xn 不应跨对象层互相覆盖

呼延灼案例尤其明显：

```text
征剿梁山这个最高目标：外部给定 → nx
拿到任务后如何分兵、布阵、调资源：主体组织 → xn
```

因此“会组织运行”不能自动取消更上层的 nx；反过来，最高任务外置也不能把主体自己设计的运行方式写成 nx。

## 三正例 + 一反向控制的最小差异

### 关羽

```text
刘备集团给：守荆州
诸葛亮给：北拒曹操，东和孙权
关羽掌握：荆州本地文武和守备的局部调用
```

结论：上位战略 nx + 局部 x。

### 呼延灼

```text
高俅/朝廷给：征剿梁山
呼延灼掌握：先锋、三军、装备、阵型与局部战役调度
```

结论：上位战略 nx + 局部 x + xn。

### 孙悟空弼马温

```text
玉帝给：去御马监任弼马温、管理天马
孙悟空掌握：御马监内部官员、事务核查与日常养马管理
```

结论：上位职责 nx + 局部 x；本段不锁 zx。

### 薛宝钗照看大观园｜反向控制

```text
王夫人给：协助照看园中、发现问题可以说
宝钗拥有：观察、提醒、报告的协助功能
冲突测试：相关人若“不听”，必须回王夫人
最终强制处分：仍在王夫人
```

结论：上位授权存在，但局部独立 `x` 未形成；保留 `nx` 权限关系，排除“受托即 zx”。

这组差异把授权连续谱从三档扩成四档：

```text
纯代理：目标、方法、关键批准都在外 → nx 深
名义/协助授权：有任务、有观察或提醒权，但冲突后仍回上级 → nx + 伪x/伪zx
真实局部授权：最高方向外置，但局部接口可独立调用 → nx + x
真实局部授权后继续公开越界扩张 → 再检查 zx
```

## 拿掉测试

### 拿掉具体作品和职位名称

统一改写为：

```text
上级给我一个不可由我重设的总体任务
→ 同时把任务内部一块对象和人员的实际调用权交给我
→ 我可独立处理局部事务
→ 但不能自行改写最高任务
```

前三例结构仍同型。

### 拿掉局部独立权

如果任何关键操作都必须逐项回到上级批准，则局部 `x` 应下降，更接近纯代理 `nx`。宝钗案例就是该反向控制的高纯实例。

### 拿掉最高方向外置

如果主体连“要不要做、做什么总体任务”都能自行决定，则上位 `nx` 下降，应重新检查 `x/xn/zx`。

### 拿掉宝钗案例中的王夫人最终否决接口

若宝钗在相关人不听时可以直接处分且立即生效，无需再回王夫人，则该例会从“名义/协助授权”向“真实局部 x”移动。

## 反向测试

### 反向 1｜纯代理

```text
上级给目标
+ 上级给方法
+ 上级保留每一步批准权
+ 主体只执行
```

更接近 nx 覆盖较深的代理结构。

### 反向 2｜名义/协助授权

```text
上级给任务或管理角色
+ 主体可观察、提醒、建议
+ 一遇真实冲突仍须回上级
```

局部 `x` 不应高锁，优先保留 `nx` 权限关系。

### 反向 3｜局部 x

```text
上级给最高目标
+ 主体对局部对象有真实独立调用权
```

即关羽、呼延灼、弼马温三例的灰区结构。

### 反向 4｜zx 上升

```text
主体取得局部权限后
→ 继续公开突破授权边界
→ 让更大秩序围绕新增权能重排
```

此时才应提高 zx。

## 当前建议纪律（仅待审议，不是正本）

暂建议研究时采用以下分层问法：

```text
1. 谁决定最高方向？
2. 谁掌握局部对象/资源的真实调用权？
3. 发生冲突或不服从时，谁能让决定独立生效？
4. 谁设计运行流程与节点？
5. 主体有没有把决定边界继续公开推大？
```

对应候选：

```text
最高方向外置 → nx
冲突后仍须回上级 → nx 保留，局部 x 降级
局部调用权可独立生效 → x
主动组织运行 → xn
公开扩大决定边界 → zx
```

五问必须按对象层分别取证，不得因为其中一项成立就覆盖另外几项。
