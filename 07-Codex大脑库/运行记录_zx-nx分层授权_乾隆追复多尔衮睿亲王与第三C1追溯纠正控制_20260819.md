# 运行记录｜乾隆追复多尔衮睿亲王与第三 C1 追溯纠正控制

## 0｜本轮目的

当前待审议已经区分：

```text
A｜事后报告/备案
B｜事后追责主体
C1｜真正追溯撤销/纠正旧决定本身
C2｜重新授权/重新接纳/新任命
```

仓库已有两个高纯 C1：宋孝宗追复岳飞原官、明宪宗为于谦昭雪复官。本轮寻找第三个独立高质量历史控制，并优先要求：

```text
旧处分已经真实生效
+ 同一制度连续体内后来最终权限重新审查旧案
+ 明确否定旧罪/旧案依据
+ 恢复的正是旧封爵、旧官方身份或旧记录
+ 不是新功、新任命、新申请造成的新状态
```

## 1｜史料事实

### 1.1 旧处分真实生效

多尔衮死后，顺治八年因属人首告等材料，被诸王大臣以谋逆定罪，发生除封、追削王爵并黜宗室等正式后果。

因此旧状态不是未执行处分，也不是口头评价，而是已经进入清朝宗室、封爵与官方记录体系的既成决定。

### 1.2 乾隆四十三年重新审查旧案

乾隆在追复谕旨中直接重新检视旧案，明确指出多尔衮身后之案由宵小构成，旧定罪属于“诬以谋逆”，并明确提出应为其“昭雪”。

随后决定：

```text
复还睿亲王封号
+ 追谥曰忠
+ 补入玉牒
+ 补继袭封
+ 修其茔墓
+ 太常寺春秋致祭
+ 配享太庙
```

这不是只追加一个纪念性荣誉，而是把旧“谋逆 → 除封 → 宗室/世爵状态改变”的官方对象层重新改写。

### 1.3 与 C2 的决定性差别

多尔衮早已死亡，不存在：

```text
旧处分生效
→ 本人后来重新立功
→ 因新功再授睿亲王
= C2
```

乾隆谕旨处理的是旧案本身：

```text
旧谋逆定罪/除封真实生效
→ 后来重新检查旧案证据与成立逻辑
→ 明确认定旧案为诬构、应昭雪
→ 恢复原封号并补回玉牒/世袭体系
= C1
```

## 2｜zx 判断

### 结论

`zx_new_expansion_in_revocation_stage: rejected_as_primary`

乾隆作出追复决定影响极大，但现行 zx 必须看到主体相对原权限边界继续扩大自己的决定范围。

本案更接近皇帝直接调用既有最高宗室封爵、旧案纠正与官方记录处分接口。没有证据显示乾隆因本案取得此前不存在的新决定层。

所以：

> 决定规模巨大 ≠ zx 扩权。

更符合：

`x_existing_final_revocation_authority_neighbor: evidence-locked`

## 3｜nx 判断

### 结论

`nx_in_revocation_decision_layer: rejected_as_primary`

在“是否撤销多尔衮旧谋逆/除封官方状态并恢复原封爵”这一窄对象层，最终决定接口就在乾隆皇权侧。

谕旨并非乾隆向另一个更高现实权限主体申请后才生效，因此不符合 nx“权限在别人手里、主体沿外部权限通道推进”的结构。

臣工整理史料、宗人府/军机大臣执行补录与袭封，只属于信息、程序与执行层，不能反推最终决定权外置。

## 4｜关键压力

关键历史压力包括：

- 多尔衮死后权力格局变化；
- 顺治初年旧案形成与宗室政治；
- 乾隆对开国功臣、宗室旧案的系统性重新评价。

这些只能解释为什么旧案被重新检视，不能直接判 zx/nx。

真正有判别力的是：

```text
旧处分已实际生效
+ 后来最终权限明确否定旧案成立基础
+ 恢复的是原封号/玉牒/世袭官方状态
+ 被处分者已死亡，不可能以新功获得新任命
```

## 5｜拿掉测试

### 5.1 拿掉“忠”“功臣”等价值评价

只保留：

```text
旧谋逆定罪与除封已生效
→ 后来最终权限认定旧案系诬构
→ 复还原封号并补回玉牒/世袭状态
```

C1 仍成立。

### 5.2 拿掉配享、修墓、春秋致祭

只保留：

```text
诬以谋逆 → 昭雪 → 复还睿亲王封号 → 补入玉牒 → 补继袭封
```

仍足以锁定 C1。说明祭祀礼遇不是分类支柱。

### 5.3 拿掉乾隆三十八年先行修墓

乾隆三十八年的修墓与祭扫属于前置缓和措施；真正四十三年的谕旨进一步直接处理旧定罪、封爵与宗室记录。

所以即使拿掉三十八年的前置动作，四十三年的 C1 仍独立成立。

## 6｜反向测试

### 6.1 反向成 C2

如果结构是：

```text
旧除封有效
→ 后人另立新功
→ 因后人新功重新获得一个新爵
```

则是新状态，不是多尔衮旧处分的 C1。

### 6.2 反向成“追加纪念但不撤旧案”

如果乾隆只修墓、祭祀、评价功劳，却保留“谋逆定罪 + 除封 + 宗室记录”不变，则 C1 显著下降。

### 6.3 反向成 nx

若乾隆只能建议昭雪，必须经过另一个真实最终节点批准后才能恢复封号与玉牒，则本对象层 nx 上升。史料不支持此结构。

## 7｜最近邻排除

### 7.1 x

本轮最强最近邻是 `x`：既有最高宗室封爵、旧案纠正与官方记录接口已经属于皇权可直接调用范围。

### 7.2 xn

军机大臣、宗人府、国史馆后续议奏、补录、立传、承袭安排属于程序执行，不回答谁拥有最终纠正接口。

### 7.3 zx

乾隆公开颁谕并改变旧官方状态，动作非常强，但没有证据显示他的皇权边界因本案继续外扩，因此不重复收 zx。

### 7.4 nx

存在臣下机构执行，不代表最终方向来自臣下。必须区分信息/执行节点与最终决定接口。

## 8｜第三因素冻结

以下因素全部冻结，不参与木轴主判：

- 多尔衮历史功过；
- 顺治朝宗室政治评价；
- 乾隆对开国宗室的总体政策；
- 多尔衮是否真的有政治野心的现代史学争议；
- 祭祀、陵寝的象征意义；
- 乾隆个人政治评价。

只检查：

> 旧处分是否真实生效？后来处理的是旧决定本身还是新状态？谁掌握最终纠正接口？该接口是否需要外部再批准？

## 9｜与岳飞、于谦 C1 的最小差异

### 岳飞

```text
旧冤狱处分生效
→ 宋孝宗追复元官
→ 旧官爵/官方记录对象层回滚
= C1
```

### 于谦

```text
旧谋逆处分生效
→ 旧案“事白”并认定受枉
→ 明宪宗复官赐祭
= C1
```

### 多尔衮

```text
旧谋逆定罪 + 除封/黜宗室状态生效
→ 乾隆明确认定旧案系诬构、应昭雪
→ 复还原封号 + 补入玉牒 + 补继袭封
= C1
```

三例共同排除：

> “后来恢复”必然只是 C2。

更窄纪律为：

> 若旧处分已真实生效，后来最终权限直接否定旧案成立基础，并恢复旧官爵/封号/官方记录对象层，而不是基于新功、新申请建立新状态，则可锁真正 C1。
