# 待审议问题｜nx：事前批准 与 事后回报边界

## 触发原因

跨三部独立作品连续出现同一边界：

> **主体在被测试的局部对象层可以先让决定/行动结果独立生效，之后仍需要向更高节点回覆、奏报、复命、备案或移交。此时“之后要报告”并不能自动证明“之前必须获得批准”。**

该问题属于现有“zx-nx分层授权灰区”的更窄子问题，但已达到三作品阈值，因此单独形成待审议问题；仍不得直接修改理论正本。

## 三个独立作品

### 1. 《红楼梦》王熙凤｜宁国府处分

```text
凤姐作出处分
→ 处罚直接执行
→ 结果已经生效
→ 执行者再回覆
```

关键：回覆发生在决定生效之后。

### 2. 《水浒传》鲁智深｜擒方腊

```text
鲁智深发现方腊
→ 当场制服并绑缚
→ 捕获结果已经成立
→ 后来移交宋江
```

关键：宋江接手的是下一层押解/处置，不是鲁智深现场捕获的事前批准者。

### 3. 《三国演义》陆逊｜夷陵统军

孙权明授陆逊“先斩后奏”，并划定“阃以内孤主之，阃以外将军制之”。陆逊可直接发布前线军令、约束宿将、部署战役；后续奏报孙权发生在前线决定已经独立运行之后。

关键：文本直接把“后奏”与“先处分”分开。

## 当前最窄候选纪律

> **判断 `nx` 权限关系时，必须区分“事前批准门”和“事后报告义务”。只有当报告/请示是决定生效的前置条件，且外部节点可以真实拒绝、修改或不放行，才构成强 `nx` 权限证据。若主体可以先让局部决定独立生效，之后才回覆、奏报、备案、复命或移交，则这些后续动作本身不能把该局部 `x` 打回 `nx`。**

## 反向控制 A｜事后追责 ≠ 追溯撤销

《三国演义》关羽华容道提供第一类负控制：

```text
关羽实际放曹操
→ 曹操已经脱离华容道
→ 关羽回营请死
→ 诸葛亮依据军令状拟按军法处置
→ 刘备求情后关羽被记过/赦免
```

组织确实拥有**事后追责主体**的能力，但没有把“曹操已经逃脱”的既成结果追溯改回“曹操在华容道被擒/被杀”。

因此：

```text
事后可处罚主体
≠
事前必须批准局部行为
≠
事后可撤销既成局部结果
```

## 反向控制 B｜重新接纳 ≠ 追溯撤销

《西游记》孙悟空被逐后回归提供第二类负控制。

第二十七回唐僧逐走孙悟空以后，原处分已经真实生效：孙悟空实际离队并回到花果山，取经队伍在没有他的状态下继续运行。

第三十一回发生新的危机：唐僧被黄袍怪所困，八戒重新赴花果山求援，孙悟空回援并救回唐僧；唐僧随后重新称其“贤徒”，四众继续西行。

因此后段更适合写成：

```text
旧处分真实生效
→ 中间状态真实存在
→ 新危机 / 新请求 / 新行动出现
→ 后来重新接纳
```

而不是：

```text
旧处分真实生效
→ 上级事后宣布旧处分自始无效
→ 原状态被追溯恢复
```

所以：

> **关系、职位或许可后来重新建立，只能证明“现在又有效”；除非文本明确证明旧决定本身被追溯判失效并发生回滚，否则不能把重新接纳/重新授权冒充 C 类追溯撤销。**

## 事后动作现行分型

当前至少需要区分四类：

```text
A｜事后报告 / 备案
→ 不自动打掉局部 x

B｜事后追责 / 处罚主体
→ 仍不等于撤销既成结果

C1｜真正追溯撤销结果本身
→ 旧决定被撤销/判失效
→ 对象/资源/职位/许可实际回滚
→ 才可能说明该局部处分只是临时层，需重新检查更高最终权限

C2｜重新授权 / 重新接纳 / 新任命
→ 旧决定曾真实有效
→ 后来条件变化后建立新状态
→ 不能冒充 C1
```

## 对象层限制

本纪律不能跨对象层扩大。

例如陆逊：

```text
最高战略“破蜀”方向 → 孙权给定 → 上位nx
阃外前线军令/处分 → 陆逊可先独立生效 → 局部x
国家最高战略/阃内权力 → 仍不属于陆逊
```

关羽华容道：

```text
对象A：关羽是否受军法处分 → 组织事后可处理
对象B：曹操是否已从华容道逃脱 → 既成结果未被追溯撤销
```

孙悟空被逐后回归：

```text
对象A：第二十七回逐出是否真实生效 → 是
对象B：第三十一回是否重新形成师徒/同行关系 → 是
对象C：第二十七回处分是否因此被追溯判无效 → 否
```

不能把后段新状态倒推成前段旧状态从未成立。

## zx 限制

“先做后报”同样不是 `zx` 的充分条件。

若这块局部权限本来就已通过职位/授权进入主体边界，当前只是正常调用，应优先解释为 `x`；只有主体进一步公开突破原授权边界，并让更大秩序承认新增决定接口时，才重新检查 `zx`。

同时，“违令后被追责”或“后来恢复关系”也不自动产生 `zx`：若主体并未获得新增长期决定范围，仍不能锁 `zx`。

## 拿掉测试

### 拿掉事后报告

若局部决定本来即可独立生效，拿掉报告义务后 `x` 仍成立，说明报告不是权限来源。

### 把报告前移

如果改成：

```text
主体提出决定
→ 必须先报告
→ 外部节点可拒绝/修改
→ 批准后才执行
```

则 `nx` 权限关系显著上升，局部 `x` 降级。

### 拿掉独立生效能力

如果主体只能观察、建议、控制现场但不能让结果正式成立，之后还必须经更高节点确认，不能用“曾先行动”冒充完整局部 `x`。

### 把事后追责替换成真正撤销

真正 C1 反例必须更强：

```text
主体先让决定生效
→ 更高节点事后行使稳定撤销权
→ 原决定被判失效
→ 对象/资源/职位/许可实际回滚或恢复
```

### 把“恢复”替换成无新条件的旧决定回滚

如果旧处分已经生效，后来并非重新申请/新危机/新授权，而是合法上级明确撤销旧处分本身并恢复原状态，才向 C1 靠近。

## 最近邻排除

- `x`：当前局部决定能否先独立生效。
- `nx`：该决定是否必须先经过外部批准接口。
- `xn`：主体怎样组织执行流程。
- `zx`：主体是否把决定边界继续向原授权之外公开扩张。
- **追责权**：处理“谁违反了规则”。
- **撤销权**：处理“已经生效的决定本身是否还能继续有效”。
- **重新授权/接纳权**：处理“在旧状态结束后是否建立一个新的有效状态”。

三者不得混写。

## 第三因素冻结

不得用“有领导、要汇报、职级高低、行动强弱、结果成败、人物忠诚、事后被处罚、后来关系恢复”直接判定。
