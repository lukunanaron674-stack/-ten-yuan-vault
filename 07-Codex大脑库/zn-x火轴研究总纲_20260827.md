## 2｜固定验证协议

木轴只迁移方法，不迁移语义。火轴统一检查：

```text
对象层
当前窗口
最近邻
拿掉
反向
第三因素冻结
名义 ≠ 现实
局部 ≠ 整体
历史曾成立 ≠ 当前仍激活
拒绝一端 ≠ 对端自动成立
```

权限与生命周期继续分开：

```text
current x ≠ permanent ownership
local x ≠ global x
future revocability ≠ prior current x never existed
x lifecycle ≠ zn lifecycle
```

pressure-display 继续分开：

```text
expression window blocked ≠ zn erased
later stable principle ≠ same principle already existed before pressure
similar language ≠ same principle restored
```

strict 对抗审计追加：

```text
verified positive 不是永久标签
99/95 也必须接受第三因素、主体归因和循环定义攻击
若最低项跌破95 → 从 verified 统计撤回，降为 deferred former positive
```

## 5｜当前强化纪律

1. 放弃/失去 `x` ≠ 自动 `zn`。
2. pure `zn` 不需要先有 `x`；责任/保护对象 ≠ 掌握对象。
3. `x` 可以独立成立，不要求同步存在 `zn`。
4. 高责任/高代价 ≠ `zn`；先拿掉外部驱动。
5. `zn` 可限制已成立 `x` 的使用而不消灭 `x`。
6. 限制 `x` 前先查限制来源；外部命令/否决/惩罚/收益/策略不足锁 `zn`。
7. `zn+x` 共现必须两端分别过门；co-occurrence ≠ strict。
8. 两个强端点跨阶段/跨对象层不能拼成共现；同一人物不是对象层胶水。
9. 最终结果与 `zn` 同向 ≠ 主体拥有使结果生效的 `x`；第三方 veto 必须归第三方。
10. strict 前置门包括同窗、同对象、端点独立、因果归属与第三方等价替代冻结。
11. 现实执行接口 ≠ `zn` 不可替代现实落点。
12. strict `x→zn` 禁止事后缩窄/循环定义：先独立命名原则，再拿掉 `x`。
13. 共享治理/组织制度若能解释同一结果，不能把共享 `x` 私有化到单一人物名下。
14. 领导位置 + 公共分配结果 ≠ 领导者个人 `zn` 自动成立。
15. 跨情境都表现为“治理得更好” ≠ 同一窄原则；需验证 same conflict-order criterion。
16. 名义身份、称号、牌印、交权意向 ≠ 现实 `x`。
17. local `x` ≠ global `x`；future revocability ≠ prior current `x` never existed。
18. 当前 `x` 关闭 ≠ `zn` 未来调用资格删除；`x` 持续 on ≠ `zn` 永久持续。
19. different new `x` formed ≠ old `zn` 必然继续；历史曾成立 `zn` ≠ 永久人物本体。
20. 被承认时间 ≠ `zn` 成立时间；承认既非必要也非充分。
21. 真实第三因素足以解释同一结果时，不能重复拿结果证明 `x`。
22. pressure-display 必须 same principle + same boundary + same conflict-order criterion 复位；禁止 temporal backfill 和相似口号假复位。
23. **evidence-locked 可被对抗审计撤回。事实 99 不等于分类永久95；最低独立性项跌破95时必须降为 deferred，且 positive 统计回滚。**
