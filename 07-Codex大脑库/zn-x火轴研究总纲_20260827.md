# zn ↔ x 火轴研究总纲｜2026-08-27

> 本文件是 L4 研究总览，不是 L2 正本。所有定义以 current canonical 为准；本文件只负责状态地图、案例矩阵、方法沉淀、待审议索引与高价值缺口。

## 1｜current canonical 骨架

L1 v1.6 固定：

```text
火 = 阳火 zn ↔ 阴火 x
主题领域 = 本体
广义变量 = 对象独立成立资格与归属方式：保留自身成立 ↔ 纳入掌握、调用与处分边界
```

`zn`：主体内部一项不可轻易让渡的意义或原则，必须能在无奖励/认可时进入判断，在冲突中排序选择，并保留未来调用资格。

`x`：对象、资源、地盘、权限或关系真实进入“归我 / 我方掌握”的边界，主体拥有实际占有、使用、调配、调用、处分、否决或排除能力。

`zn ↔ x` 补卡 current canonical：

- `zn → x`：补掌握用途、守护与放弃标准、否决原则；
- `x → zn`：补意义的现实落点、可保护对象范围与明确我方边界；
- 两端必须先独立成立；拿掉任一端后，另一端仍成立但必须重新出现可命名方向/落点缺口。

## 2｜火轴固定验证协议

木轴只迁移方法，不迁移语义。火轴案例统一检查：

1. **对象层**：原则对象与掌握对象必须明确；局部成立不得倒灌人物整体。
2. **当前窗口**：区分稳定本体、当前状态、行为显影、关系位置、外部压力。
3. **最近邻**：`zn vs z/xn/n/zx/x/nz`；`x vs zx/xn/nx/x并z/nz`。
4. **拿掉**：去掉认可、奖励、职位、资源、称号、外观后，端点是否仍成立。
5. **反向**：原则让渡 / 掌握失去后，是否出现可观察改变。
6. **第三因素冻结**：道德评价、阵营、题材、胜负、称号不能替代端点。
7. **名义 ≠ 现实**：身份、职位、牌印、授权意向不自动证明现实 `x`。
8. **输入 ≠ 成立**：外部定义、承认、要求出现，不自动构成 `zn` 或 `x`。
9. **局部 ≠ 整体**：一项 `zn` / `x` 不自动定义整个人物。
10. **拒绝一端 ≠ 对端成立**：放弃资源不自动证明 `zn`；拒绝关系不自动证明现实 `x`。
11. **成熟度与权力分离**：L4 99/99 仍不能覆盖 L2；跨作品必须同 criterion_version。
12. **正反分账**：positive、negative guard、lifecycle、pressure display、strict 分别统计。

## 5｜当前已强化出的火轴纪律

1. **反奖励选择是 `zn` 高价值压力测试，不是定义本身。**
2. **放弃 `x` ≠ `x` 从未成立；放弃 `x` 也 ≠ `zn` 自动成立。**
3. **现实用途 / 家庭需求 ≠ `zn`。**
4. **pure `zn` 不需要先有可掌握 `x` 对象。**
5. **保护 / 责任 / 不抛下 / 公共责任 ≠ 被负责对象进入 `x`。**
6. **`zn` 可以限制已成立 `x` 的使用而不消灭 `x`。最短：有权不用 ≠ 没有权。**
7. **限制 `x` 前先查限制来源。** 内部原则才进入 `zn` 候选；外部命令、现实否决、惩罚恐惧、收益计算、临时策略不足。
8. **关系处分 `x` 必须用现实生效证明。** 名义“师父/首领/长辈/伴侣”不够。
9. **历史外部来源 ≠ 当前永久外置。** 完成真实交付并取得直接处分权后，应重新检查 `x`。
10. **`zn+x` 共现必须先让两端分别过门；共现 ≠ strict。**
11. **现实 `x` + 强烈坚持/受辱 ≠ `zn+x`；真实 `zn` + 爵位/职位/称号/印信 ≠ `zn+x`。**
12. **现实执行接口 ≠ `zn` 不可替代现实落点。**
13. **原则保护 / 对待 / 评价谁 ≠ 谁必须进入主体 `x` 掌握边界。**
14. **名义身份 / 高称号 / 外部承认 ≠ 现实 `x`。**
15. **外部交权意向 ≠ 权已经归主体；名义授权 + 部分管理动作 ≠ 稳定全局 `x`。**
16. **局部现实 `x` 成立 ≠ 整个组织/任务层全部 `x` 成立。**
17. **当前 `x` 关闭 ≠ `zn` 未来调用资格被删除。**
18. **old `x` lost + different new `x` formed ≠ `zn` must be replaced。**
19. **被承认的时间 ≠ `zn` 真正成立的时间。** 外部承认既非必要条件也非充分条件。
20. **被承认 / 赦免 / 受诏 ≠ 自动形成现实 `x`。**

## 7｜当前高价值缺口

P1｜**第一份真正 strict `zn↔x` 正例。** 必须通过 `x→zn` 不可替代现实落点门；当前 strict 为 `0 positive / 4 guards / 3 works`，不为凑数降门槛。

P2｜**lifecycle 第一份反向护栏。** 优先找 `x` 稳定存在但旧 `zn` 明确退出/被替换；其次找 `x` 关闭后同类压力再次出现而旧 `zn` 明确不再回来。

P3｜**pure-zn 第一份伪正例护栏。** 人物看似承担责任/坚持原则，但主要由命令、惩罚、舆论、身份收益或即时策略驱动；拿掉外因后不保留未来指导资格。

P4｜**被承认 vs 真正成立第二独立正向/反向作品。** 不复制宋江、吕布同型皮肤。

P5｜**第二部“`zn` 真 + 假 `x`”伪共现。** 优先代理授权、临时持有、可撤权限。

P6｜**第三因素替代一端的伪共现。** 表面两端同在，但第三因素足以解释其中一端功能。

P7｜**第二部“名义授权 + 原节点现实覆盖”反向护栏。** 复验杨志不是押运特例。

P8｜**第二部“已成立 `x` 受外部命令/否决限制，但 `zn` 不成立”护栏。** 复验贾政限制来源门。

P9｜**第二种 pure-`x`。** 优先地盘、权限、稳定关系掌握，避免继续复制赠与银钱。

P10｜**pressure display 首份高纯控制。** 必须同一对象层、同一端点硬判据、压力前/中/后完整链。
