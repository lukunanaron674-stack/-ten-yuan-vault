## 1｜current canonical 骨架

```text
火 = 阳火 zn ↔ 阴火 x
主题领域 = 本体
广义变量 = 对象独立成立资格与归属方式：保留自身成立 ↔ 纳入掌握、调用与处分边界
```

- `zn`：内部不可轻易让渡的意义/原则；必须能在无奖励/认可时进入判断，在冲突中排序并保留未来调用资格。
- `x`：对象、资源、地盘、权限或关系真实进入“归我/我方掌握”边界，具有实际占有、调用、处分、否决或排除能力。
- `zn→x`：补掌握用途、守护/放弃标准与否决原则。
- `x→zn`：补现实落点、可保护对象范围与明确我方边界。
- strict 必须先两端独立成立，再过同窗、同对象、第三方冻结与双向不可替代缺口。

## 2｜固定验证协议

木轴只迁移方法，不迁移语义。火轴统一检查：

```text
对象层
当前窗口
最近邻
拿掉
反向
第三因素冻结
名义 ≠ 现实
局部 ≠ 整体
历史曾成立 ≠ 当前仍激活
拒绝一端 ≠ 对端自动成立
```

权限与生命周期继续分开：

```text
current x ≠ permanent ownership
local x ≠ global x
future revocability ≠ prior current x never existed
x lifecycle ≠ zn lifecycle
```

pressure-display 继续分开：

```text
expression window blocked ≠ zn erased
later stable principle ≠ same principle already existed before pressure
similar language ≠ same principle restored
```

### 3.5｜strict zn↔x
`1 positive / 1 work + 4 negative guards / 3 works + 2 precondition guards / pending-review`。

#### 首份正向｜诸葛亮卤城换班｜99/95

## 5｜当前强化纪律

1. 放弃/失去 `x` ≠ 自动 `zn`。
2. pure `zn` 不需要先有 `x`；责任/保护对象 ≠ 掌握对象。
3. `x` 可以独立成立，不要求同步存在 `zn`。
4. 高责任/高代价 ≠ `zn`；先拿掉外部驱动。
5. `zn` 可限制已成立 `x` 的使用而不消灭 `x`。
6. 限制 `x` 前先查限制来源；外部命令/否决/惩罚/收益/策略不足锁 `zn`。
7. `zn+x` 共现必须两端分别过门；co-occurrence ≠ strict。
8. 两个强端点跨阶段/跨对象层不能拼成共现；同一人物不是对象层胶水。
9. 最终结果与 `zn` 同向 ≠ 主体拥有使结果生效的 `x`；第三方 veto 必须归第三方。
10. strict 前置门包括同窗、同对象、端点独立、因果归属与第三方等价替代冻结。
11. 现实执行接口 ≠ `zn` 不可替代现实落点。
12. 首份 strict 正向提示“对象构成型 x”可能通过反向门，但不得降低后续门槛。
13. 名义身份、称号、牌印、交权意向 ≠ 现实 `x`。
14. 名义授权 + 部分管理 ≠ 稳定全局 `x`。
15. local `x` ≠ global `x`。
16. future revocability ≠ prior current `x` never existed。
17. 当前 `x` 关闭 ≠ `zn` 未来调用资格删除。
18. `x` 持续 on ≠ `zn` 永久持续。
19. different new `x` formed ≠ old `zn` 必然继续。
20. 历史曾成立 `zn` ≠ 永久人物本体。
21. 被承认时间 ≠ `zn` 成立时间；承认既非必要也非充分。
22. 真实第三因素足以解释同一结果时，不能重复拿结果证明 `x`。
23. expression window blocked ≠ `zn` erased。
24. pressure-display 必须 same principle + same boundary + same conflict-order criterion 复位。
25. 后来稳定原则 ≠ 压力前已存在同一原则；禁止 temporal backfill。
26. 相似口号/主题词 ≠ old `zn` 复位；真实排序换芯优先 lifecycle replacement。
