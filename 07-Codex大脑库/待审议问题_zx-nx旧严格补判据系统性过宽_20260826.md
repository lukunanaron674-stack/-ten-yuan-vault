# 待审议｜旧严格补判据是否系统性过宽｜正本冲突暂停

## 0｜状态纠正

本文件原先提出一个更严的新门：

> 拿掉 `zx` 后，必须直接损伤 `nx` 自身的资源、许可、保护、专业能力等“核心功能”，否则只能算 `nx→zx` 单向补。

2026-08-26 重新读取仓库正本后发现：这个门**比当前 `zx补nx_补卡` 正本额外增加了条件，并与正本明文定义发生冲突**。

正本当前写的是：

```text
nx 补 zx：补入外部权限接口、救兵、关系通道与非正面解决方案。

zx 补 nx：把借到的资源、关系与通道重新转成实际行动、公开决定和结果推进，改变 nx 单独运行时“有路径却缺落地权能”的缺口。
```

红线只要求：

```text
拿掉任一端
→ 另一端仍成立但出现可命名缺口
→ 补回后缺口得到改善
```

正本**没有要求**：

```text
拿掉 zx
→ nx 自己的资源处分能力 / 许可能力 / 专业能力本体必须受损
```

因此本文件原先的“nx 自身核心功能损伤门”目前只能算候选新方法，不能在未修改正本的情况下反向生效。

## 1｜层级纪律

仓库层级必须保持：

```text
canonical-current 正本
>
pending-review / 方法卡 / 运行记录
```

所以：

- pending-review 可以提出“是否应该把严格补收得更窄”；
- 但在 `zx补nx_补卡` 未正式修改之前；
- 不得用这个更窄候选门撤销与正本文字直接相容的严格补案例；
- 更不得把“新门下统计为0”写成当前正本事实。

## 2｜曹操陈留借卫弘家资复核

《三国演义》第五回提供了直接同型材料：

```text
曹操 zx：反董、公开起兵、募兵发檄方向由自身生成并公开推进

卫弘 nx：外部家资接口，曹操必须请求，卫弘保留真实同意/拒绝权
```

拿掉 `nx`：

```text
曹操仍想起兵
→ “资少恐不成事”
→ 启动资本、衣甲旗幡、募兵规模出现缺口
```

拿掉 `zx`：

```text
卫弘仍有资源/通道
→ 但缺把这条外部资源通道兑换成公开起兵、军政行动与现实结果推进的落地权能
```

后一条正是当前补卡“`nx` 有路径却缺落地权能，`zx` 把借来的资源/通道转成实际行动与结果推进”的明文情形。

因此按**当前正本**，曹操—卫弘恢复为严格 `zx↔nx` 正例。详见：

`运行记录_zx-nx严格补规则冲突_曹操陈留借卫弘家资按正本补卡复核恢复严格补_20260826.md`
