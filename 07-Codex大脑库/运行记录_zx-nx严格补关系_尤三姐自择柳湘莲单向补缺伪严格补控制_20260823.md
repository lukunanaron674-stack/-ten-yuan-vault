# 运行记录｜尤三姐自择柳湘莲：单向补缺不构成严格 zx↔nx

## 1｜本轮目的

压力测试“zx 与 nx 都真实成立，而且共同指向同一个大结果，是否就足够构成严格补关系”。

本轮沿用仓库已经 99/97 evidence-locked 的《红楼梦》尤三姐第66回正式案例，不重复制造人物结论，只提取其中此前尚未单独索引的失败机制：**只有 nx→补 zx 缺口成立，反方向 zx→补 nx 缺口不成立。**

## 2｜剧情事实

尤三姐自己明确择定柳湘莲，并拒绝家人替换对象。家人后续只能围绕她指定的柳湘莲推进，因此“嫁给谁”的当前婚姻方向由尤三姐本人占据。

但个人选择不能单方面形成婚约。贾琏承担实际说合通道；柳湘莲本人拥有真实同意/否决权，并交出鸳鸯剑作为定礼。尤三姐收下定礼以后，婚约才进入双方确认状态。

## 3｜zx 证据

锁定：`zx_endpoint: evidence-locked`。

- 婚姻对象由尤三姐自己决定；
- 她公开锁定对象并拒绝家人改写；
- 家庭后续行动围绕她指定的人展开；
- 当前婚姻方向位置由“可被安排”推进为“必须围绕她自己的选择处理”。

这里只锁当前状态/行为功能，不锁稳定人物本体。

## 4｜nx 证据

锁定：`nx_endpoint: evidence-locked`。

- 柳湘莲是否接受婚约不由尤三姐单方面处分；
- 贾琏承担真实说合、承诺和定礼传递通道；
- 尤三姐实际沿外部媒介与对方同意接口，把自己的方向推进成现实婚约。

这里的 nx 不是“没主见”，而是强主体在双边关系实现层必须经过外部真实同意接口。

## 5｜严格补测试

### 5.1 拿掉 nx

拿掉贾琏媒介与柳湘莲同意：

- 尤三姐“只嫁柳湘莲”的 zx 方向仍然成立；
- 但个人选择不能自动变成双方婚约。

因此：

`nx_repairs_zx_gap: supported`

nx 的确直接补了 zx 在“把个人方向变成双边现实关系”上的同意/媒介缺口。

### 5.2 拿掉 zx 高显影端点

不能把尤三姐最低限度的婚姻意愿整个删掉，否则等于删除研究对象。只拿掉“公开、自主锁定对象并使家庭围绕其选择行动”这一 zx 高显影端点，保留最低限度“愿意接受柳湘莲婚约”。

此时：

- 贾琏仍可说合；
- 柳湘莲仍可同意；
- 鸳鸯剑仍可作为定礼；
- 双边许可/媒介结构仍足以让婚约形成。

因此：

`zx_repairs_nx_gap: rejected`

不存在“nx 已经拿到关系/许可接口，但没有 zx 就无法让接口落地”的对称缺口。

## 6｜关键压力

本轮关键不是“封建婚姻”或“尤三姐痴情”，而是：

1. 主体自己的婚姻方向真实存在；
2. 双边关系的另一方拥有不可替代的真实同意权；
3. 两端共同指向“形成婚约”这一大结果；
4. 但补缺关系只在一个方向成立。

因此：**同目标、同事件、甚至同现实结果，并不自动等于严格双向补。**

## 7｜最近邻排除

### zx vs x

尤三姐当然有个人婚姻边界，但本段重点是她的自定方向实际进入家庭安排并迫使家人围绕指定对象行动，所以当前 zx 高显影高于纯静态 x。

### nx vs xn

尤三姐本人没有搭建复杂媒介流程、排程和节点系统。贾琏的说合过程不能倒算成尤三姐 xn。

### nx vs nz

情感与专一解释为什么选择柳湘莲，但不能替代柳湘莲本人真实同意权这一权限事实。

### strict complement vs 普通双边关系

双边关系天然需要两方意愿，不代表双方端点自动互补。严格补仍必须逐向检查“拿掉一端后，另一端是否留下由该端直接补回的不可替代缺口”。

## 8｜反向测试

### 真严格补版本

必须进一步出现：

```text
nx 的同意/媒介接口已经到位
↓
但若没有尤三姐 zx 的公开落地权能
↓
该接口仍无法形成婚约结果
```

原段证据不足。

### 纯 nx 版本

```text
家人替尤三姐选择对象
→ 尤三姐不占对象方向
→ 只按外部说合和同意结果接受
```

则 zx 明显下降。

## 9｜第三因素冻结

冻结：尤三姐后来自刎、柳湘莲后来出家、人物道德评价、痴情/刚烈性格、婚姻制度主题、贾府整体悲剧。

只问：

1. zx 是否独立成立？是。
2. nx 是否独立成立？是。
3. nx 是否补 zx 的现实缺口？是。
4. zx 是否反向补 nx 的现实缺口？否。

分类保持 97%。

## 10｜结论

本轮锁定：

> **尤三姐自择柳湘莲 = zx 与 nx 并存，但属于单向补缺，不是严格 zx↔nx 双向补关系。**

新增边界意义：

> **严格补至少需要双向缺口都真实成立。两端都真、共同指向同一个大结果，甚至 nx 明确补了 zx，也仍不足以自动锁严格补。**

本轮不修改 L1、zx/nx 信息卡、准度卡或 zx补nx_补卡；仅将这一“单向补缺失败机制”作为正式运行记录挂入严格补关系研究链。
