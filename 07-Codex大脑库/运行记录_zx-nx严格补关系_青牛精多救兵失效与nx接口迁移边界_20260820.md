# 运行记录｜青牛精多轮救兵失效与 `nx` 接口迁移边界

## 0｜结论先行

本轮测试一个比“外部节点退出”更窄的问题：

> 当前瓶颈明确存在，`nx` 外部节点也真实进入行动链；如果该节点随后失效、失败或退出，能不能说一个严格 `zx↔nx` 补关系刚刚完成闭环？

结论：**不能。**

金兜山青牛精段中，孙悟空为救唐僧连续接入多个外部神仙权限／能力接口：李天王父子、火德星君、水德星君、如来与十八罗汉。它们都是真实的 `nx` 关系功能：关键能力属于他者，悟空必须请求并沿既有天庭／佛门网络取得。

但这些接口先后都没有修复当前核心瓶颈：青牛精的金刚琢继续套走兵器、火具与金丹砂，水攻也无法解决。于是悟空在**同一个未解决瓶颈**下不断迁移外部接口，最终根据如来提示找到太上老君；老君作为金刚琢与青牛的真正处分节点，才使问题结束。

因此必须区分：

```text
nx接口进入行动链
≠
nx已经成功补掉zx当前缺口
```

以及：

```text
失败接口退出 / 被证明无效
≠
严格补关系完成闭环
```

更准确的结构是：

```text
同一现实瓶颈持续存在
→ nx接口A尝试，失败
→ 迁移nx接口B，失败
→ 迁移nx接口C，失败
→ ...
→ 找到真正能处分瓶颈来源的nx接口
→ 当前缺口才得到有效修复
```

本例因此锁为：**`nx` 接口迁移正例 + “失败接口退出＝严格补闭环”反例**。

## 1｜剧情事实链

### 阶段A｜当前瓶颈明确成立

青牛精以金刚琢套走孙悟空金箍棒，并扣住唐僧、八戒、沙僧。

当前瓶颈不是笼统的“妖怪很强”，而是：

> 孙悟空已有明确救师方向与直接行动能力，但常规兵器、神兵与多种外部攻击手段都会被金刚琢吸收或压制，无法形成稳定收伏。

因此：

```yaml
active_bottleneck: 金刚琢导致常规武力与多种外援手段无法稳定生效
bottleneck_status: evidence-locked
```

### 阶段B｜李天王／哪吒接口真实进入，但失败

孙悟空上天查勘后，玉帝派李天王、哪吒等下界助战。

这是高纯 `nx` 关系功能：

- 天兵神将不是孙悟空稳定直属资源；
- 需要经过天庭既有权限网络取得；
- 对应能力真实进入战场。

但哪吒等神兵同样被金刚琢套走。

所以：

```text
nx接口成立
+
现实缺口没有被修复
```

不得把“请到救兵”自动写成严格补成功。

### 阶段C｜火德星君接口真实进入，仍失败

李天王等提出水火可能不被圈子套走。孙悟空于是再上天，请火德星君率火部众神助阵。

火德星君真实接受请求并带火部进入战场，但火龙、火马等火具又被金刚琢套走。

因此：

```yaml
nx_endpoint: 火德星君
relation_function: evidence-locked
same_gap_repair: rejected
```

接口是真的，补缺失败也是真的。

### 阶段D｜水德星君／黄河水伯接口真实进入，仍失败

孙悟空随后转请水德星君，并取得黄河水伯的一盂黄河水作为外部能力接口。

这里仍是 `nx`：水势不属于孙悟空自身稳定调用范围，需要进入水部既有神权网络取得。

但水攻并未解决青牛精；核心瓶颈继续存在。

因此：

```text
接口迁移了
瓶颈没有迁移
```

### 阶段E｜如来／十八罗汉金丹砂接口真实进入，仍失败

孙悟空又赴灵山求如来。如来派十八罗汉以金丹砂助力，明确给出一个外部解决方案。

罗汉真正下砂后，青牛精仍以金刚琢把金丹砂全部套走。

所以这又是一次：

```text
高纯nx关系功能
→ 真实进入行动窗口
→ 没有修复当前缺口
```

随后降龙、伏虎转达如来预留的信息：若金丹砂也失效，就应去兜率宫寻找太上老君。

### 阶段F｜最终迁移到太上老君，缺口才关闭

悟空到兜率宫发现青牛失踪、金刚琢被盗。太上老君明确指出金刚琢的性质，并带芭蕉扇下界。

老君到场后收回金刚琢、使青牛现本相并牵回兜率宫。

此时才发生：

```text
金刚琢处分来源被找到
+
真正权限持有人进入
+
阻断对象被直接收回
→ 当前瓶颈关闭
```

## 2｜`zx` 判断

本轮**不重新锁孙悟空稳定 `zx` 本体**，也不把每一次叫阵、追打都重复收成新的 `zx`。

可保留的只是：

- 救师方向由孙悟空自己持续占据；
- 多轮外援失败后，他没有把最终目标交给某个救兵决定；
- 他持续重新寻找能够突破当前瓶颈的外部接口。

但“持续主动”“多次行动”“很能打”本身不满足现行 `zx` 准度卡的新增扩权硬门。

因此：

```yaml
zx_stable_essence_relocked: false
zx_new_expansion_in_each_rescue_attempt: rejected_as_primary
```

本轮核心不是新增一个 `zx` 锚，而是检查 `nx` 补端什么时候真正有效。

---

## 3｜`nx` 判断

本轮多个 `nx` 关系功能均可独立成立。

共同结构是：

```text
关键能力 / 权限不属于孙悟空
→ 进入既有天庭、火部、水部、佛门网络
→ 请求具体能力持有人出手
→ 外部能力真实进入现场
```

因此：

```yaml
nx_relation_function_attempts: evidence-locked
```

但必须加入第二层判断：

> **`nx` 成立，只证明“主体正在使用外部通道”；不证明该通道已经有效补掉当前 `zx` 缺口。**

这是本轮最重要的分类增量。

---

## 4｜关键压力

压力变量从头到尾基本冻结：

```text
唐僧等仍被扣
+
金刚琢仍控制战场关键物件
+
孙悟空原有直接手段无法稳定收伏青牛精
```

李天王、火德、水德、罗汉的先后进入，没有改变这个核心瓶颈。

因此，本轮不是“每换一个救兵就换一个问题”，而是**同一问题下的接口迁移**。

这正好使样本比安道全案例更纯：安道全退出时缺少一个正在运行的即时医疗瓶颈；本例则有明确持续瓶颈，但早期 `nx` 接口虽然真实参与，却没有补成功。

## 5｜拿掉测试

### 拿掉李天王／哪吒

孙悟空救师方向仍在，金刚琢瓶颈也仍在；后续仍可转请火德、水德、如来。

因此李天王接口不是当前瓶颈不可替代的成功补端。

### 拿掉火德星君

同理：核心瓶颈不变，孙悟空可继续迁移到水德等节点。

### 拿掉水德星君

核心瓶颈仍在，后续可继续迁移。

### 拿掉十八罗汉金丹砂

仍不能说明悟空已经没有其他外部通道；如来的信息最终仍把问题指向老君。

### 拿掉太上老君

这里结果发生质变：

- 金刚琢真正主人与处分来源消失；
- 青牛真正归属节点消失；
- 现有多个外援已被文本证明不能稳定解决；
- 当前同槽瓶颈留下清晰、可命名缺口。

所以：

> 早期外援是 `nx` 尝试接口；老君才是本段真正完成当前缺口修复的有效外部端点。

## 6｜反向测试

若李天王第一次下界就能直接收伏青牛、救出唐僧，并使金刚琢失去阻断作用，那么：

```text
李天王nx接口
→ 当前缺口实际修复
```

才有资格继续检查其与孙悟空当前 `zx` 是否构成严格补关系及其闭环时间。

若火德星君烧毁金刚琢并直接结束问题，同理。

实际文本并非如此。

因此：

> **接口参与 ≠ 缺口修复；接口退出 ≠ 补关系闭环。**

---

## 7｜最近邻排除

### vs `xn`

孙悟空按“神兵失败→火→水→佛门→老君”不断调整解决路线，具有明显策略与节点迁移，因此 `xn` 邻近存在。

但：

- `xn` 回答“下一步去找谁、怎么换方案”；
- `nx` 回答“为什么必须接入不属于自己的外部能力／权限节点”。

不能用主动换方案把 `nx` 擦掉。

### vs `x`

李天王、火德、水德、罗汉、老君的能力均不属于孙悟空稳定处分边界，所以不是 `x`。

### vs `zx`

主动叫阵、战斗、奔走不能替代新增扩权证据。

### vs 严格补关系闭环

闭环讨论的前提应是：

```text
严格补关系已经成立或至少当前nx端已实际修复zx缺口
```

若某个 `nx` 节点只是尝试、但没有修复缺口，那么它后来失败、退出或被替换，严格说是：

> **失败接口终止 / nx端点迁移**

而不是：

> **一个已经成立的严格补关系完成闭环。**

## 9｜与最近三轮时间窗口材料的最小差异

### 孙策借兵

```text
nx资源真实补掉当前兵力缺口
→ 资源内化为稳定x
→ 旧nx闭环结束
```

### 红孩儿

```text
nx观音接口真实补掉当前收伏缺口
→ 红孩儿任务完成、瓶颈消失
→ 旧nx闭环结束
```

### 安道全

```text
节点退出
→ 退出当刻没有证实正在被它补的当前同槽瓶颈
→ 不能倒推活跃严格补关系
```

### 青牛精（本轮）

```text
当前瓶颈明确持续
→ 多个nx接口真实进入
→ 但早期接口均未修复缺口
→ 接口失效后迁移到下一节点
→ 不能把“失败节点退出”写成严格补关系闭环
```

所以时间窗口问题现在至少需要先问两道前置门：

```text
A. 退出前是否存在当前同槽瓶颈？
B. 该nx接口是否已经真实修复 / 持续补住该缺口？
```

A、B 任一不满足，都不能只凭“节点离开”锁严格补闭环。

## 11｜下一轮最值得跑

继续找真正的“第三种闭环”正例，但筛选条件进一步收紧：

```text
T1：当前同槽瓶颈明确存在；
T2：nx接口已经真实、有效地补住该瓶颈；
T3：任务尚未完成，瓶颈本身也没有消失；
T4：该nx接口因死亡、调离、权限撤销、关系断裂或环境失效而退出；
T5：主体必须改接新的外部接口或改走新的现实路径。
```

只有这样，才有资格测试：

> **“有效 nx 端点被强制失效”是否构成严格补关系第三种闭环机制。**

当前不要把任何“救兵失败后换下一个”混进这类正例。
