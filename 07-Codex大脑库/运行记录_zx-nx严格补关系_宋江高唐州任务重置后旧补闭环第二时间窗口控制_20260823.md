# 运行记录｜宋江高唐州任务重置后旧严格补闭环第二时间窗口控制

## 0｜结论先行

高唐州初始窗口继续保持仓库既有 99/98 严格 `zx ↔ nx` 正例：宋江已有救柴进、破高唐的公开军事推进，但高廉妖法形成可命名的当前瓶颈；公孙胜的专属法术能力与罗真人的真实放行／授法接口直接解除该瓶颈，宋江随后重新传令推进，同一战役目标得到兑现。

但这条严格补不能继续永久挂在宋江后续军事 `zx` 上。

第五十四回结束时，高廉已被杀，高唐州已被攻入，柴进被救出，梁山撤离高唐州并返回山寨。原瓶颈“高廉妖法阻断当前攻城救援”因此不再处于 active 状态。

紧接着呼延灼连环马成为新瓶颈时，公孙胜这个人物关系仍在梁山体系中，但文本转而寻找汤隆、徐宁和钩镰枪作为新的直接解决接口。由此可锁：

> **严格补关系的时间闭环不要求旧 nx 资源一定内化成 x；只要当前任务／对象状态已经完成并重置，原现实瓶颈消失，旧 nx 即使关系仍存在，也不能继续自动补后续 zx。**

## 1｜剧情事实、触发、对象、动作与结果

### 阶段 A｜初始严格补窗口仍成立

宋江率梁山军攻高唐州救柴进。高廉妖法使梁山现有普通军事推进无法稳定穿透，宋江一度坚守等待公孙胜到来。

罗真人最初不愿放公孙胜下山，后经戴宗、李逵等反复请求才放行，并另授可破高廉的正法。公孙胜回到军中以后，宋江重新传令拔寨推进；公孙胜破高廉妖法，高廉最终被杀。

这一阶段继续保持：

```yaml
strict_zx_nx_complement_in_initial_window: true
initial_same_real_bottleneck_direct_coupling: true
```

### 阶段 B｜原任务完成，原瓶颈被消灭

高廉死后，宋江收军进入高唐州，安民、开牢、寻找柴进；李逵最终从井中救出柴进。梁山随后带柴进、家眷与相关财物离开高唐州，得胜返回梁山。

这使原被测试瓶颈：

```text
高廉妖法
→ 阻断“当前破高唐／救柴进”
```

不再存在。

这里不是简单“时间过去了”，而是：

```text
目标对象已经完成
+ 原阻断者高廉已经死亡
+ 当前高唐州攻救任务结束
= 原瓶颈状态重置
```

### 阶段 C｜关系仍在，但新的瓶颈换了

高唐州之后，高俅派呼延灼征剿梁山。连环马击败梁山军，形成新的当前军事瓶颈。

此时公孙胜仍在梁山体系中，文本明确出现晁盖、吴用、公孙胜下山慰问宋江；但破连环马的直接方案并没有继续调用“公孙胜破高廉妖法”旧接口，而是由汤隆提出钩镰枪，并进一步需要徐宁这一专属枪法节点。

因此：

```text
旧关系存在
≠ 旧瓶颈仍存在
≠ 旧严格补仍处于当前有效窗口
```

## 2｜zx 判断

### 初始窗口

宋江的 `zx` 端继续锁在：

```text
自己占据救柴进／破高唐方向
→ 公开率军推进
→ nx 条件进入后重新发令进攻
→ 现实作用推进到高唐州城内
```

并非因为“宋江是首领”就自动 zx；既有军令权是 `x` 最近邻，当前 `zx` 只锁公开作用继续跨过新的现实阻断。

### 后续窗口

宋江以后仍可出现新的军事 `zx`，但必须围绕新的当前瓶颈重新判。

不能因为：

```text
公孙胜曾经救过高唐州
```

就把以后所有宋江军事推进永久记成：

```text
公孙胜 nx → 宋江 zx
```

## 3｜nx 判断

### 初始窗口

`nx` 高纯成立在外部专属解决接口：

- 普通军力无法稳定穿透高廉妖法；
- 公孙胜的专属法术不在宋江稳定处分范围；
- 公孙胜离山又受罗真人真实许可约束；
- 罗真人可拒绝，而且曾实际拒绝；
- 放行并授法后，接口直接作用于当前高廉妖法瓶颈。

### 后续窗口

本轮不主张“公孙胜关系消失”，也不需要把公孙胜整体内化为宋江的 `x`。

真正变化是：

> **原 nx 接口不再对应一个仍然生效的同一现实瓶颈。**

所以机器可读应锁：

```yaml
old_nx_relation_still_exists_as_relation: true
old_nx_relation_still_complements_current_zx: false
```

---

## 4｜关键压力

初始压力：高廉妖法让宋江当前公开军事推进无法稳定兑现救柴进、破高唐。

闭环结束的关键不是章节间隔，而是四件事：

1. 高廉被杀；
2. 高唐州被攻入；
3. 柴进被救出；
4. 梁山撤离并进入新的呼延灼／连环马任务。

因此旧严格补失效的机制是：

```text
active_task_bottleneck
→ solved
→ task/object state reset
→ later bottleneck is different
```

而不是孙策型的：

```text
nx external resource
→ internalized x
```

## 5｜拿掉测试

### 5.1 初始窗口拿掉 nx

拿掉公孙胜／罗真人及等价专属破解接口：

- 宋江的救援方向和公开军事推进仍成立；
- 但高廉妖法继续卡住当前高唐攻救。

因此初始严格补仍成立。

### 5.2 后续窗口拿掉“公孙胜曾经帮过高唐州”的历史事实

只保留：

- 高廉已死；
- 高唐州任务已结束；
- 柴进已救出；
- 呼延灼连环马成为新问题；

宋江当前面对连环马的现实瓶颈不会因此发生变化。

旧 nx 历史不再是当前不可替代缺口。

### 5.3 补回旧关系

补回“公孙胜仍在梁山、此前曾经直接破解高廉妖法”只能增加历史连续性，不能重新制造：

> “当前仍有高廉妖法卡住救柴进”

这一已结束瓶颈。

所以：

> **关系连续 ≠ 瓶颈连续。**

## 6｜反向测试

如果高廉妖法没有被彻底处理，或者同一“破高唐／救柴进”任务在后续再次被同类妖法卡住，而且宋江仍必须再次经过公孙胜／罗真人的同一外部接口才能推进，那么严格补时间窗口应继续，不应机械切断。

反过来，如果只是公孙胜这个人物仍与宋江同处梁山，但当前瓶颈已经换成连环马、攻大名府或另一种完全不同限制变量，则旧严格补应结束。

---

## 7｜最近邻排除

### vs 普通时间间隔

不是“过了一回书 = 自动结束”。本例闭环来自任务完成与瓶颈消失。

### vs 关系破裂

也不是“关系没了 = 结束”。公孙胜关系可以继续存在，旧补仍可结束。

### vs x 内化

孙策控制证明外部资源内化成 `x` 可以结束旧补；本例不需要资源内化，单纯任务／瓶颈状态重置已经足够。

### vs xn

公孙胜如何施法、梁山如何部署新战役属于运行组织问题；本轮只测试旧 nx 是否仍是后续 zx 当前不可替代门。

### vs 普通历史因果

公孙胜曾经帮助宋江是历史因果事实；严格补要求的是当前仍有双向缺口与同一现实瓶颈，而不是“以前帮过”。

## 8｜第三因素冻结

冻结：

- 宋江与公孙胜私人关系好坏；
- 公孙胜是否长期留梁山；
- 高廉妖法是否符合现实世界；
- 宋江主帅身份；
- 梁山最终胜负；
- 汤隆、徐宁人物评价；
- 后续战役数量。

只检查：

```text
原瓶颈现在还在吗？
原任务现在还在吗？
旧 nx 仍是当前必经门吗？
新的 zx 若出现，缺口是否还是旧 nx 直接补的那个缺口？
```

结论不变。

案例级候选纪律：

> **严格补关系应有闭环结束条件。除“外部 nx 资源内化为主体稳定 x”外，若当前任务已经完成、原现实瓶颈被消灭或对象状态重置，则旧 nx 即使作为人物关系继续存在，也不应永久挂在后续 zx 上。判断时间窗口应看“当前瓶颈是否仍 active、旧 nx 是否仍是当前不可替代门”，而不是看人物是否还认识、还同队或曾经直接帮过。**

本轮不修改 L1、zx/nx 信息卡、准度卡或 `zx补nx_补卡`。
