## 1｜木轴当前骨架

```text
zx：主体占据最终方向与作用权来源，并把自身权能公开压入现实。

nx：主体不占最终方向；关键权限、资源或解决接口仍在外部；主体真实沿既有关系、权限、流程或通道续接。
```

禁止直接用强弱、身份、职业、胜负、听话、求人一次、主动性、有无明确目标判十元。

## 2｜最近邻地图

### 2.1 zx vs x

```text
x：冲突前已拥有该对象域稳定调用/处分权，现在把它用出来。
zx：决定范围、影响位置或凌驾程度推进到原本不属于主体的对象域/层级。
```

稳定纪律：**权力有效 ≠ 权力扩大。**

### 2.2 nx vs x

```text
nx：关键许可/资源/保护/专业接口仍外置，主体不能稳定自行调用。
x：权限/资源已经稳定进入主体直接调用边界。
```

“有人参与 / 部下执行 / 使用组织资源”不是 nx 充分证据。

### 2.3 nx vs xn｜pending-review × 3 works + 2 类反向护栏

```text
nx：沿别人已有方向、权限、接口推进。
xn：主体自己搭人员、资源、节点、流程、排程与运行骨架。
```

三部独立作品正向控制：
- 《三国演义》貂蝉连环计｜99/97：王允给上位政治任务 = nx；现场哭诉、误导、自刎威胁等执行策略由貂蝉自行组织 = xn；
- 《红楼梦》王熙凤协理宁国府｜99/98：贾珍/王夫人给协理授权入口 = nx；宁府分班、点卯、巡查、责任节点由凤姐自搭 = xn；
- 《水浒传》呼延灼征梁山｜99/98：朝廷/高俅给征剿任务 = nx；先锋、兵马、阵型、连环马运行结构由呼延灼组织 = xn。

反向护栏：
- 伪 xn：《西游记》孙悟空红孩儿按观音“许败不许胜”预设诱敌｜99/98：执行很忙、动作复杂 ≠ 自己搭运行骨架；
- 伪 nx：《三国演义》关羽土山约三事｜99/97：名义进入曹方体系、接受职位/供给 ≠ 承接曹方最终方向；关羽保留最终归向、条件否决与退出权。

纪律：
> **谁决定“要做什么”与谁决定“具体怎么运行”必须分层。听命不能吞掉执行自主；执行有自主也不能倒抹上位任务来源。动作复杂度不是 xn 充分证据，名义入体系也不是 nx 充分证据。**

## 3｜已形成的研究主干

### 3.1 对象分层｜pending-review

高层最终方向非 nx，不覆盖局部保护/许可/资源 nx；局部 nx 也不得倒灌成长期终点 nx。

正向：关羽、林冲、鸳鸯。反向：探春、马谡、宋江。

### 3.2 nx 激活与退出窗口｜pending-review

nx 按当前执行窗口判断，不是历史关系永久标签。已锁退出机制：方案失效、环境不可持续、许可节点撤回/反转、主体当前最高行动目标改变并停止续接。

任务层同人相邻 `nx off→on` 已形成独立 pending-review，**3 controls / 3 works**：
- 《西游记》孙悟空：齐天大圣空衔时当前任务层 nx=off；权管蟠桃园并真实承接后 nx=on｜99/98；
- 《红楼梦》周瑞家的：回王夫人话结束欲退出时宫花任务 nx=off；薛姨妈临时交花并承接后 nx=on｜99/98；
- 《水浒传》秦明：青州兵马总管身份长期存在，但清风山军务未接入前任务层 nx=off；慕容知府明确交任务并承接后 nx=on｜99/98。

稳定纪律：
> **关系/身份存在 ≠ 当前 nx 在线；任务发出 ≠ 任务已经接入。必须看外部方向、权限或任务是否真实进入本轮行动链，并被主体承接。**

下一步转向反例：任务已发出，但主体拒绝承接、改写最高方向或转走另一通道时，检查 nx 为什么仍不激活。

### 3.3 具体节点可替代 vs 接口层不可绕过｜pending-review

换具体人不等于摆脱 nx。真正削弱 nx 的是存在稳定、可重复、不经等价外部接口、仍实现同一结果的内部路线。

主动内部绕行前置门：

```text
P1 当前开放可用
+ 主体主动不走
+ P2 不依赖等价外部接口
+ 同一结果完成
```

关羽五关、甘地自取盐为正向；武松、玄奘、孙悟空二调芭蕉扇、凯撒为反筛选护栏。

### 3.4 外部对象 / 处分域在场 ≠ nx｜pending-review

孙悟空生死簿、李逵劫法场、董卓废立形成三作品控制：对象/处分域在外只证明外部性；主体若不沿接口，而是直接压掉原接口当前否决/处分能力并改写同一结果，优先检查 zx。

护栏：探春抄检只压回局部越界，不等于整体搜检接口失效。

### 3.5 主动目标 + 外部通道 ≠ zx+nx｜pending-review

王熙凤铁槛寺、刘备三顾茅庐、林冲投梁山跨三作品支持：**“我自己想干 + 我很主动 + 我真实走外部接口”不能自动推出 zx+nx。** zx 必须另证公开显权与决定范围新增。

### 3.6 名义权限 vs 现实否决权｜P4 pending-review

两门：

```text
A 实效门：外部节点真的能卡住同一结果吗？
B 激活门：该接口本轮真的进入主体行动链了吗？
```

最强因果拨动：`拒绝 → 同一结果停住 → 放行 → 同一结果恢复`。

证据分档：A 因果拨动；B 有效拒绝；C 只改条件/时间/方式；D 名义反对但结果照常。

### 3.7 秘密改结果 ≠ 公开扩权 zx｜pending-review × 四大名著

四部独立作品：孙悟空偷桃酒丹、周瑜蒋干盗书、王熙凤毒设相思局、宋江私放晁盖。

```text
隐匿 / 欺骗 / 诱导 / 绕权 / 时序组织
→ 具体结果成功改变
→ 但现实没有围绕主体新增公开决定接口运行
≠ zx
```

宋江补出“系统内部秘密反向型”：主体可拥有正式职位/信息入口 `x`，再利用 `x + xn` 秘密破坏系统结果；只要没有公开扩张处分边界，仍不得升级 zx。

### 3.8 压力显影 ≠ 人物换芯｜evidence-locked：1 positive + 2 negative guards

正向：《西游记》孙悟空五行山受压 → nx 救援通道高显影 → 解压后 zx 按自身硬判据复位｜99/97。

护栏：
- 刘备借截袁术离许都：高层自定方向 + 子任务 nx + xn 工具化，**对象层不一致**；
- 曹操华容道：同层 nx 抬高成立，但解压后只恢复既有 `x`，**恢复 x ≠ zx 复位**。

正向结构：

```text
稳定端已有可靠锚
→ 强外压封住该端现实入口
→ 另一端在同一对象层高显影
→ 压力解除
→ 原端以自身硬判据重新出现
```

当前正向仍只有 1 部，不升级 pending-review。

## 4｜严格 zx↔nx 补｜canonical 纠偏后的当前状态

### 4.1 当前必须服从的正本口径

当前 `zx补nx_补卡` 是 `canonical-current-card v0.1`，明文定义：

```text
nx 补 zx
= 补入间接路径、外部权限接口、救兵、关系通道与非正面解决方案

zx 补 nx
= 把借到的资源、关系与通道转成实际行动、公开决定和结果推进
= 改善 nx 单独运行时“有路径却缺落地权能”的缺口
```

正本红线：两端先独立成立；领导服从、强弱搭配、求人一次、普通协作或资源相加不足；拿掉任一端，另一端必须仍成立但出现可命名缺口，补回后缺口可重复改善。

2026-08-26 曾建立更严候选门：拿掉 zx 后，必须损伤 nx 自身资源/许可/保护/专业能力本体。该门与现正本“有路径却缺落地权能”发生层级冲突，现状态：

```yaml

```

因此此前基于该更严门形成的“严格补正例=0”“八例单向补”均不得继续作为当前仓库事实。


> **主体后续必须能稳定直接调用/处分，且原外部节点不再保留能在同一结果生效前真实撤回、覆盖、否决或要求逐次批准的权力。**

共同候选纪律：

> **严格补是当前现实瓶颈上的关系，不应因历史来源而永久追挂。初始 strict 成立后，若当前命名瓶颈真实消失，或外部 nx 条件稳定内化为主体 x，使旧接口不再是同一结果的现实必经门，则旧 strict 当前窗口应关闭；后续新任务重新判断 zx、nx 与补关系。**

该纪律已跨 3 部独立作品，因此形成 `pending-review`，但**不得直接修改 L1、信息卡、准度卡或补卡**。

后续优先补反例护栏，不再机械增加第四个普通 closure：

1. B 型“资源表面内化但原节点仍保留现实否决”已经有杨志第一份护栏，下一步优先跨到《三国演义》《红楼梦》或《西游记》复验；
2. 任务表面完成，但同一命名瓶颈很快复发，旧接口仍是必经门；
3. 具体旧节点退出，但立即被等价外部接口替代，检查是否只是“节点退出”而非“nx 接口层退出”。

更基础的 nx 动态纪律继续有效：

```text
nx 真实激活
→ 任务完成 / 瓶颈消失 / 接口退出 / 资源内化
→ 旧 nx 不得永久追挂后续阶段
```

### 4.6 第三因素方法

冻结有效性护栏已跨三作品：曹操陈留、宋江高唐州、鸳鸯抗婚。稳定纪律：**冻结不能直接删掉被测端点或当前命名瓶颈。**

“第三因素制造表面双向缺口”仍只有刘备联孙抗曹 1 部高纯控制，继续补样本。

反筛选：第三因素若只解释“为什么接口打开 / 为什么节点愿意合作”，而不能替代 `nx` 的外部条件功能或 `zx` 的现实落地权能，就不足以打破严格补。

红孩儿再补一层：**外部解决节点若明确需要主体充当现实接入/诱敌/执行端，不能把外部能力存在本身误写成“无需 zx 落地”。反之，如果外部节点完全可自行完成同一结果，则 zx→nx 缺口必须重新检查。**

```text
A. 资源/权限看似内化，但原外部节点仍保留现实撤回 / 最终许可权
   → 杨志已完成第一份；优先换独立作品复验
```

## 7｜可迁移到火/土/金/水的方法

可直接复用：
1. 对象层拆分；
2. 最近邻排除；
3. 拿掉 / 反向测试；
4. 当前执行窗口；
5. 现实否决因果拨动；
6. P1 当前可用性检查；
7. 第三因素冻结；
8. 对子第0门：两端先独立成立；
9. **研究层不得越级覆盖正本；候选新门先审议、再改正本、最后才回扫历史案例；**
10. 新方法出现后回扫旧高置信正例，但回扫必须使用当前有效层级的判据；
11. 结果变化与权能位置变化分离；
12. 阶段切分禁止倒灌；
13. 压力显影与稳定本体分离；
14. 压力显影先过对象层一致性；
15. 解压复位按原端硬判据验收；
16. 上位目标来源与局部运行权分层；
17. **路径缺口与落地权能缺口分开检查**；
18. **交换/激活条件与端点功能分层**；
19. **接口载体与补资格分离**；
20. **外部解决路径与主体接入端分层**：若外部能力必须由主体诱敌、接入、执行才能兑换成同一结果，可形成“有路径却缺落地权能”；若外部节点可自行完成同一结果，则反向缺口必须重验；
21. **初始补关系与后续窗口闭环分开统计**：端点成立、补成立、nx退出/内化是三个不同状态，不得一步推导；
22. **时间窗口闭环按机制分型**：至少区分“任务/瓶颈解决后接口退出型”与“外部资源内化为 x 型”；不能因为都表现为旧 nx 退出，就把不同闭环机制混成同一种证据；
23. **同型 temporal closure 跨作品复验时，冻结作品表面差异，只保留：初始 strict 是否成立、当前命名瓶颈是否消失、旧接口是否仍为同一结果必经门；**
24. **历史来源与当前权限状态分离**：资源曾由外部给出，不足以永久追挂 nx；反过来，资源已经“在手”也不足以自动判 x。必须检查原节点是否仍保留撤回权、逐次批准权或最终处分权；
25. **x 内化必须经过现实否决门**：纸面授权、名义负责、对象持有只证明候选；原节点若还能在结果生效前稳定覆盖主体决定，则 x 尚未稳定成立，旧 nx 不应关闭；
26. **执行动作复杂度 ≠ 运行骨架自主**：判断关键节点、终点、胜负/裁定方向究竟由谁预设，而不是数主体做了多少动作；
27. **名义入体系 ≠ 真实承接最终方向**：受封、入职、投降、受供给只证明外部关系存在；必须另查主体是否保留最终否决、重设与退出位置；
28. **关系/身份长期存在 ≠ 当前接口激活**：检查本轮是否有明确外部方向、任务、许可或解决过程真实进入行动链并被主体承接；
29. **任务发出 ≠ 任务已接入**：任务已存在但主体拒绝承接、改写最高方向或转入另一通道时，仍需重判 nx；
30. **最低主体参与/同意 ≠ zx 高显影**：双边关系或共同结果需要最低主体参与，不等于主体端点提供了严格补意义上的不可替代落地权能；
31. **跨作品统计必须使用同一判据版本**：经历 canonical 冲突的旧案例，逐案重验后才能恢复 cross-work 数；
32. **外部条件存在 ≠ 外部条件已经自行落地**：条件、资源、许可存在，与其是否已转换成同一现实结果必须分开。

跨轴提示：
- 火 `zn↔x`：归属条件与实际处分落地分开；合作动机不能替代归属端点；长期名义归属不等于当前归属功能激活；
- 土 `n↔x并z`：通道存在与对象真实跨界/承载落地分开；空间入口存在不等于当前对象已接入该入口；
- 金 `xn↔z`：流程路径存在与最终裁定落地分开；尤其要区分外部给目标与主体自行搭运行骨架；
- 水 `xz↔nz`：回返条件存在与现实回返路径真正恢复分开；历史回返路径存在不等于当前窗口已经打开。

时间窗口迁移：
- 火：外部归属/许可接口在任务完成或权限内化后是否仍是当前归属结果必经门；名义归属转交不足，还要查旧节点现实否决是否退出；
- 土：边界/通道完成当前跨界后，旧入口是否仍控制后续同一对象；
- 金：一次流程裁定完成后，旧最高裁定节点是否继续支配下一轮新任务；
- 水：一次回返/去向问题解决后，旧回返接口是否仍是新危机当前必经路径。

## 8｜仓库治理纪律

- 正本高于本总纲；
- evidence-locked 不自动升级正本；
- 同一结论优先归并总纲/待审议，不重复造同义文件；
- 新方法推翻旧子结论时，先检查方法层级是否允许覆盖旧正本口径；
- 若发现 canonical conflict，立即暂停降级统计并恢复“按正本待重验”；
- control 数与 cross-work 数分开统计，同一作品多案例不能冒充独立作品数；
- 初始 strict、时间窗口闭环、nx 内化/退出必须分开统计；
- 跨作品统计必须使用同一判据版本，经历正本冲突的历史案例须逐案重验后再恢复计数；
- 没有真实新增/修正不提交。
