# 运行记录｜孙策质玺借兵：旧“严格补”按新规则复核为单向补缺

## 0｜结论先行

第十五回孙策“以传国玉玺作质 → 袁术借兵三千、马五百 → 孙策渡江取江东”的事实链不变；`zx` 与 `nx` 两端也仍可分别成立。

但按 2026-08-23 以后已经建立的严格补门槛重新做**双向拿掉 + 第三因素冻结**后，旧记录中的：

```yaml
strict_zx_nx_complement_in_initial_window: true
```

不再成立。

更可靠的分类是：

```yaml
zx: true
nx: true
nx_to_zx_gap_filling: true
zx_to_nx_gap_filling: false
strict_zx_nx_complement: false
one_way_complement: nx_to_zx
```

即：**袁术的外部兵马接口真实补掉孙策 zx 的启动军力缺口；但孙策的 zx 高显影并不反向补袁术“兵马处分接口”自身的不可替代核心缺口。**

孙策能让袁术愿意放兵的直接交易诱因，是另一独立变量——传国玉玺。该变量不能冒充“孙策 zx 对袁术 nx 的反向补缺”。

本轮只修正案例分类，不修改 L1、zx/nx 信息卡、准度卡或 `zx补nx_补卡`。

---

## 1｜剧情事实

### 1.1 触发

孙策不愿继续久困袁术之下，想渡江取江东、救母舅并图取大业，但直属可用兵力不足。

吕范明确指出：

```text
只怕袁术不肯借兵
```

孙策提出以父亲留下的传国玉玺作质。吕范随即指出袁术早就想得到此物，以玺作质便很可能发兵。

### 1.2 对象

本轮只分三个对象层：

```text
A｜孙策自己的江东扩张方向
B｜袁术掌握的三千兵、五百马调用权
C｜孙策持有、袁术高度欲求的传国玉玺
```

严禁把 B 与 C 混成一个对象，也不得把 C 的交换价值倒灌成孙策 zx 的“反向补缺”。

### 1.3 明确动作

孙策：

- 主动提出借兵；
- 主动拿传国玉玺作质；
- 获得兵马后立即领兵渡江；
- 后续持续招将、扩军、取地。

袁术：

- 听到有玉玺后取而视之；
- 明确表现出高兴；
- 决定借兵三千、马五百；
- 同时给予军职。

### 1.4 结果

孙策取得兵马并迅速把该外部条件投入江东扩张。后续江东军力逐渐进入孙策稳定统辖边界；到第十七回，袁术反而向孙策借兵而被拒。

## 2｜zx 判断

### 2.1 当前状态

`zx` 仍成立。

关键不是“孙策很勇猛”，而是：

```text
江东扩张方向由孙策自己占据
→ 获得条件后由其自身军政行动公开推进
→ 外部地盘、将领与秩序围绕其力量重新响应
→ 决定范围持续扩大
```

这满足 zx 准度卡：主体权能公开进入现实、他者/环境响应、决定范围扩大。

### 2.2 最近邻排除

- 不是单纯 `x`：孙策不是只使用已经稳定属于自己的江东统治权，而是在建立并扩大新的现实范围。
- 不是单纯 `xn`：招将、分兵、路线组织可有 xn，但本轮主变量是方向与权能公开扩张。
- 不是因为“胜利”才判 zx：即使局部战斗失败，只要其权能持续迫使秩序围绕其扩张方向调整，zx 仍可存在。

稳定人物本体本轮不锁，只记录第十五回当前状态。

---

## 3｜nx 判断

### 3.1 外部权限真实存在

`nx` 在兵马资源层成立：

```text
三千兵、五百马仍在袁术手中
→ 孙策不能自行调走
→ 必须提出请求并给出质押
→ 袁术有真实批准/拒绝能力
→ 袁术批准后资源才转移
= nx 关系功能
```

### 3.2 nx vs xn

孙策设计“以玺作质”的交易方法可以有 `xn` 邻近，因为他主动组织了取得资源的方案。

但：

```text
方案怎么设计
= xn邻近

兵马最终能不能拿走
= 袁术外部处分接口
= nx
```

所以不能因为孙策自己想出质押方案，就把 nx 消掉。

### 3.3 nx vs x

在借出以前，兵马并不属于孙策稳定直接调用范围，所以不是孙策的 `x`。

后续兵力逐渐内化为孙策可直接统辖资源，才进入旧记录已经锁定的 `nx → x` 时间转态；这一部分本轮保留。

## 4｜关键压力

孙策当前现实瓶颈是：

```text
江东扩张方向已存在
+
直属启动军力不足
```

袁术的兵马接口直接补的是这个瓶颈。

因此：

```text
nx → zx
```

方向的补缺非常清楚。

真正需要重审的是反向：

```text
zx → nx ?
```

## 5｜拿掉测试

### 5.1 拿掉 nx

拿掉袁术兵马，且不给孙策等价外部兵马：

```text
孙策江东方向仍成立
→ 但启动军力留下直接缺口
```

所以：

```yaml
nx_to_zx_gap_filling: true
```

### 5.2 拿掉 zx

现在反过来拿掉“孙策公开扩张江东的 zx 高显影”，只保留：

- 袁术仍掌握兵马；
- 袁术仍有把兵马借出/不借的处分接口；
- 孙策仍持有可交换的传国玉玺；
- 存在最低限度借兵交易需求。

袁术的兵马处分接口并不会因为缺少孙策 zx 高显影就失去核心功能。

更重要的是，袁术本轮愿意放出兵马的直接诱因在文本中另有明确来源：

```text
袁术长期欲得传国玉玺
→ 孙策提出以玉玺作质
→ 袁术见玺大喜
→ 随即批准借兵
```

因此：

```yaml
zx_to_nx_gap_filling: false
```

旧“严格补”在反向拿掉门失败。

## 6｜第三因素冻结

### 6.1 第三因素

候选第三因素：

```text
传国玉玺的独立交换价值 / 袁术对玉玺的强烈欲求
```

它不是孙策 zx 的同义词，也不是孙策江东扩张本身。

### 6.2 有效冻结

冻结“袁术因为玉玺而特别愿意借兵”这一交换诱因，但保留：

- 孙策 zx 江东方向；
- 孙策启动军力不足这一现实瓶颈；
- 袁术 nx 兵马处分接口；
- 袁术理论上仍可决定借或不借。

冻结后，孙策仍需要外部军力；袁术的兵马处分权也仍然存在。但所谓“袁术反向需要孙策”的表面理由显著消失。

因此，任何把“袁术愿意借兵”解释成“袁术 nx 端反过来需要孙策 zx 才完整”的说法，都被玉玺这一独立交换变量削弱。

### 6.3 无效冻结

不能冻结：

```text
孙策根本不想取江东
```

因为这会删除 zx 端。

也不能冻结：

```text
孙策本来就有足够直属兵力
```

因为这会直接删除本轮 nx 所补的启动军力瓶颈。

这遵守现有第三因素冻结有效性护栏：端点和目标瓶颈必须留在桌面上。

## 7｜反向测试

若要把本例重新锁成严格补，至少必须证明：

```text
拿掉孙策 zx 高显影
→ 袁术兵马处分接口自身留下一个不可替代现实缺口
→ 而这个缺口只能由孙策 zx 直接补回
```

现有文本没有给出这种证据。

如果唯一可见的“袁术为什么愿意借兵”是：

```text
想得到玉玺
```

那么反向缺口属于交换资源层，而不是 zx 对 nx 的补缺。

---

## 8｜严格补判定

按当前待审议最低门：

1. zx 独立成立：通过；
2. nx 独立成立：通过；
3. nx 与 zx 接在同一当前启动军力瓶颈：正向通过；
4. 拿掉 nx，zx 有缺口：通过；
5. 拿掉 zx，nx 有不可替代缺口：**不通过**；
6. 同一有效时间窗口：初始窗口通过；
7. 第三因素不能制造伪反向需求：玉玺交换变量进一步削弱反向补。

因此：

```yaml
strict_zx_nx_complement: false
one_way_complement: nx_to_zx
```
