# 运行记录｜宋江高唐州｜严格补时间窗口 canonical 复验

## 1｜本轮问题

本轮不重复证明宋江高唐州初始 `zx↔nx` 严格补。该子结论已经按 current canonical 以事实99 / 分类99 锁定。

本轮只检查：

```text
初始 strict 成立
→ 高廉妖法这一当前瓶颈被破解
→ 高廉被杀、城破、柴进救援继续完成
→ 公孙胜 / 罗真人这一旧 nx 解决接口
   是否仍应继续作为“同一个高唐州结果”的当前必经门？
```

## 2｜剧情事实

- 初始窗口里，高廉妖法真实阻断梁山普通军力，宋江必须寻找公孙胜这一专属破解能力。
- 公孙胜本人又不能擅自下山，必须经过罗真人放行与授法；因此初始 nx 接口真实成立。
- 罗真人放行并授法后，公孙胜回到高唐州。宋江、吴用、公孙胜共同商议破高廉，宋江随后传令各寨起军，公开军事推进恢复。
- 公孙胜斗法破解高廉，战役继续推进，高廉最终被杀。
- 高廉死亡后，宋江收军入高唐州，先令不得伤害百姓、出榜安民，随后转入寻找并救出柴进的后续任务。
- 到这一节点，“普通军力无法穿透高廉妖法”这个专属现实瓶颈已经消失；完成高唐州救援不再需要再次经过“请公孙胜→罗真人是否放行/授法”这一旧入口。

## 3｜初始 zx / nx 端点只作前提，不重复涨样本

### zx 前提

宋江持续占据“破高唐、救柴进”的公开方向，并在外部解决条件接入后重新传令、组织公开军力，把条件兑现为现实推进。

### nx 前提

公孙胜专属破解能力与罗真人许可/授法在初始窗口不属于宋江稳定直接调用边界，且第一次拒绝确实卡住原请援链。

因此初始 strict 维持既有锁定，不在本轮重复计数。

## 4｜时间窗口闭环

本轮锁定的不是“公孙胜以后永远不再与宋江发生 nx”，而是更窄的当前任务结论：

```text
高廉妖法瓶颈存在
→ 公孙胜 / 罗真人接口为当前必经 nx

高廉妖法被破解 + 高廉死亡
→ 同一专属瓶颈消失
→ 旧请援/许可接口不再是完成同一高唐州救援结果的必经门
→ 初始 strict 关系的当前窗口关闭
```

后续若出现新的法术、许可或专业瓶颈，必须重新判断新的 nx；不得把本次历史来源永久追挂到人物后续全部阶段。

## 5｜拿掉测试

### 拿掉“旧 nx 仍然活跃”假设

在高廉已死、妖法瓶颈已消失后，删除“宋江仍必须再次找罗真人放行公孙胜才能完成高唐州救援”的假设：

```text
宋江仍能收军入城
→ 安民
→ 搜索牢狱
→ 继续救柴进
```

同一任务不会重新退回“高廉妖法尚未解决”的状态。

因此旧 nx 接口不再是当前必经门。

### 拿掉初始 nx

反过来回到瓶颈尚未解决的早期窗口，若删除公孙胜 / 罗真人等价专属破解接口，高廉妖法仍会卡住宋江的公开推进。

这说明：

```text
初始 nx 真实成立
≠
任务完成后 nx 永久在线
```

## 6｜反向测试

若原著结构是：

```text
高廉虽然暂时败退
→ 妖法瓶颈仍未真正解除
→ 宋江每推进一步仍必须重新获得公孙胜/罗真人许可
→ 不经该旧接口就无法完成同一救柴进结果
```

则不能判时间窗口关闭。

本案不是这种结构：高廉被杀后，战役进入收城、安民、搜救柴进阶段，旧“破解高廉妖法”接口已完成其当前功能。

## 7｜最近邻排除

### 不是 nx→x 资源内化

本轮不主张罗真人的许可权或公孙胜的专属能力已经稳定成为宋江自己的 `x`。

闭环机制优先写成：

```text
当前命名瓶颈被消除
+ 旧外部接口不再是同一结果的必经门
```

而不是“外部能力被宋江彻底拥有”。

### 不是 xn

宋江收城、安民、搜救柴进当然有组织流程，但本轮变量是旧专业/许可接口是否仍为当前必经门，不是后续流程由谁排程。

### 不是人物换芯

宋江并没有因为不再需要本次公孙胜/罗真人接口就“从 nx 变回 zx”。人物稳定本体不锁；这里只判断一个具体关系功能在一个具体任务窗口中的激活与退出。

## 8｜第三因素冻结

可以冻结：宋江英雄评价、高廉善恶、柴进关系亲疏、妖法奇观、后续梁山总体命运。

不可删除：

```text
初始 strict 是否真实成立
高廉妖法是否是当前命名瓶颈
该瓶颈是否真正消失
同一高唐州救援结果是否还必须经过旧接口
```

删除这些变量等于换题，不是第三因素控制。

## 10｜本轮价值

本例与《西游记》红孩儿形成第二部独立作品的 strict 时间窗口控制：

```text
红孩儿：专属收伏瓶颈解决 → 观音旧 nx 接口退出同一任务窗口
高唐州：专属妖法瓶颈解决 → 公孙胜/罗真人旧 nx 接口退出同一任务窗口
```

共同支持一个更窄的方法候选：

> **严格补只能在当前命名瓶颈与当前执行窗口内判断；初始 strict 成立，不允许把一次外部解决接口永久追挂到后续已经更换任务对象的阶段。**

当前只有 2 部独立作品完成 canonical 时间窗口复验，因此本轮只记 `evidence-locked` 控制，不新建或升级理论正本。
