# 知识蓝图节点编辑器设想 2026-05-21

## 核心目标

做一个类似 Maya / Houdini 节点编辑器的知识蓝图：

- 大框连接大框。
- 点开大框后进入小框视角。
- 小框里仍然可以有大框连接大框。
- 每个框可以对应一个 Obsidian `.md` 文件。
- 新建框、编辑框、连线变化，都能写入 Obsidian 文件或事件日志。
- Codex 下次接手时，可以通过事件日志知道哪些知识被改动。

## 推荐架构

第一阶段不要直接做完整大软件，先用 Obsidian 文件系统做底座：


## 三层系统

### 1. Obsidian Canvas 底座

Obsidian Canvas 可以先承担：

- 大框布局
- 连线
- 文件卡片
- 子 canvas 链接
- 与 Obsidian vault 共存

这适合做 v0.1，不需要额外软件。

### 2. Ten Yuan Brain Map 编辑器

自制一个本地网页编辑器，优先考虑 React Flow / xyflow。

原因：

- 更接近 Maya/Houdini 节点编辑器。
- 支持节点、端口、连线、subflow。
- 适合做“点大框进入小框视角”。
- 可控性强，方便接入十元关系类型。

节点类型示例：

```text
十元节点：zn / x / n / xn / nx ...
主题节点：时间 / 本体 / 空间 / 因果 / 命运
母型节点：回收 / 崩坏 / 扭曲 / 桥接 / 污染桥
素材节点：F12归档片段 / 作品案例 / 反例
任务节点：待验证 / 待删减 / 待深拆
```

连线类型示例：

```text
生 / 克 / 补 / 压 / 激活 / 承载 / 改写 / 反噬 / 桥接 / 污染桥 / 归档来源
```

### 3. watcher 事件日志

复用“龙虾式文件改动监听”的思路：

```text
你在框里编辑
→ 对应 .md / .canvas / graph.json 改动
→ watcher 监听到文件变化
→ 写入 events.jsonl
→ Codex 下次接手先读 events.jsonl
→ 知道你改了哪个框、哪条线、哪个知识区
```

注意边界：

- 文件改动可以触发本地 watcher。
- 文件改动不会天然唤醒当前 Codex 聊天框。
- 若要自动唤醒，需要额外接 Codex automation / heartbeat / local bridge。

```text
   07-Codex大脑库/_brain-map/graph.json

3. 根据最近 changed files 读取对应节点 md。

4. 输出：
   - 最近改动
   - 当前脑图结构
   - 需要吸收的内容
   - 建议下一步
```
