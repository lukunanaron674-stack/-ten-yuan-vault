# zn ↔ x 边界压力测试｜《The Book of Eli》Eli：唯一实体载体 ≠ 唯一现实锚点

## 0｜本轮结论

本轮原本作为 P0 strict-v2 天然对象型候选进入：Eli 长期持有并保护一册明确、稳定、自然可识别的实体 Bible，同时长期坚持把其内容带到西方安全地点保存。

压力测试后不允许升为 strict verified positive。真正新增的是一条 strict-v2 前置护栏：

> **物理载体在作品中即使被称为“最后一册 / 唯一一册”，也不能自动推出该载体是原则的唯一 current reality anchor。若同一内容在同窗内已经存在可现实调用的功能等价锚点，则“唯一物理载体”不等于“唯一现实落点”。**

《The Book of Eli》的关键反证非常强：Carnegie 夺走实体 Braille Bible 后，Eli 仍继续到达 Alcatraz，并从记忆完整口述 Bible，新的实体副本随后被印刷出来。因此，若把 Eli 的 `zn` 偷偷定义为“必须守住这一本实体书”，就会把**文本内容层**与**物理载体层**混成一个对象层。

本轮因此只计 `strict-precondition guard`，不计 strict-v2 negative，也不计 x-scope ordinary guard。

## 3｜zn 独立端点

先不用被测实体书 possession `x` 命名 Eli 的 current 原则：

> **Biblical text 应被带到能长期保存并重新进入人类知识系统的安全地点；即使途中持续承担死亡风险、拒绝权力交换，并在实体书被夺走后仍继续完成保存任务，这一方向仍保留最终指导资格。**

支持：

- 三十年持续向西，不是一时情绪；
- Carnegie 提供现实替代路径/权力交换时不改向；
- 被追杀与重伤后仍继续；
- 最关键：实体 copy 被夺走后，任务没有随 possession loss 一起消失，而是转由记忆口述完成。

因此：

```yaml
zn_endpoint: true
zn_fact_confidence: 99
zn_classification_confidence: 99
```

这里锁的是“保存/传递 Biblical text 的原则与未来调用资格”，不是“永远不得把某一本实体书交给别人”。Eli 为救 Solara 现实交出实体书，反而证明该原则存在高层排序：保护/传递文本的长期使命并不等于对具体物理载体的绝对不放弃。

## 5｜关键压力：carrier layer 与 content layer

这个案例最容易诱发错误推理：

```text
作品说：最后一册实体 Bible
→ 看起来物理载体不可替代
→ 于是直接把 x→zn 判通过
```

但 current strict-v2 禁止把“绝对唯一现实载体”当强门，而且要求 same current window / same object layer / competing anchors freeze。

本案实际结构是：

```text
physical carrier copy
≠
Biblical text/content anchor
```

在 Carnegie 夺走实体 copy 的同一生命阶段，Eli 已经完整记忆该文本；而且这个 memory anchor 不是理论假设，它随后被现实调用：Eli 在 Alcatraz 口述文本并生成新实体副本。

所以：

> **carrier uniqueness ≠ anchor uniqueness。**

即使接受“那一册实体书是最后一册”的作品内设定，也只能说明 **physical-copy carrier 极稀缺**；不能说明保存/传递 Biblical text 的 current reality anchor 只有该 copy。

## 6｜same-object-layer 前置门为什么失败

如果把 `zn` 写成：

> “这一本实体书本身永远不能放弃。”

会被剧情直接反驳：Eli 为救 Solara 主动交出实体书，之后仍继续完成使命。

如果把 `zn` 正确写成：

> “Biblical text 应被保存/传递到安全地点。”

那么被测 `x` 却只是：

> “对这一册 physical copy 的 possession/use/custody。”

两者已经出现：

```text
zn object layer = preserved/callable Biblical content
x object layer = one physical carrier copy
```

把两者强行写成“同一对象”只能通过事后 composite bundling：

```text
physical copy
+ memorized content
+ mission
+ last-copy status
→ 一个大 x bundle
```

这违反 current strict gate。

因此 strict-v2 在方向门之前就被 `same object layer` 前置条件卡住。

## 7｜拿掉 / 反向

### 拿掉实体 copy x

剧情已经替我们做了现实 removal test：Carnegie 夺走实体 Bible 后，Eli 对该 copy 的 possession/custody `x` 退出。

但：

- Biblical text 仍可被 Eli 当前调用；
- 西行保存原则仍继续；
- Alcatraz 最终获得完整文本；
- 新物理副本由记忆内容重新生成。

因此不能写：

```text
remove physical-copy x
→ zn loses current callable/reality anchor
```

正确是：

```text
remove physical-copy x
→ one carrier anchor lost
but memorized-content callable anchor survives
→ tested x→zn gap not established
```

### 反向

若 Eli 从未完整记忆 Bible，且实体书一旦离开其 possession 后，当前阶段没有任何可调用文本接口、无其他同窗现实载体/功能等价 anchor，那么才值得重新测试 physical-copy `x→zn`。

本作品恰恰给出相反事实，所以不能为 strict 破零。

## 8｜第三因素冻结

本轮冻结：

- Eli 的宗教身份标签；
- “last Bible” 的象征意义；
- 神迹/被保护设定；
- Eli 的战斗能力；
- Carnegie 的政治野心；
- Solara 后续继承；
- 结局是否成功；
- 作品对 faith 的主题表达。

保留后仍有足够事实支持：

```text
stable physical-copy x = true
stable preservation/transmission zn = true
physical copy is lost
memorized full content remains callable
same mission continues
new physical copies can be regenerated from memory
```

所以核心不是象征，而是**现实功能等价 anchor 存活**。

## 9｜最近邻

### vs Matt King / The Descendants

Matt King 卡在 `zn→x`：拿掉 preservation zn 后，fiduciary / beneficiary / financial standards 仍给 x 提供独立 purpose/ranking anchor。

Eli 不同：本轮首先卡的是 `same object layer / x→zn reality-anchor attribution`。不是 x 自己还有另一套使用规范，而是原则真正指向的**内容**拥有另一条 current callable anchor。

### vs Antigone

Antigone 是 `zn=true` 但 stable x 本身未过门；Eli 则 physical-copy possession/use/custody x 很稳定。失败点不在 x 强度，而在**载体 x 与原则对象层不一致**。

### vs Sun Ce / imperial seal x-scope control

孙策案例已经说明“能处分象征物 ≠ 能处分其代表权能”，但那是 x-scope permission/represented-authority 分层。

Eli 新增的是 strict-specific 问题：**即使物理载体 x 与 zn 共现，载体所承载的信息内容若存在 current functional equivalent，仍不能把载体 uniqueness 当成原则 reality-anchor uniqueness。** 因此不重复计 x-scope ordinary guard。


锁定边界句：

> **strict-v2 的“relevant current reality anchor”不能按物理载体稀缺度判断。一个 carrier 即使在物理上唯一，只要被测 zn 真正指向的功能/内容在同窗还有可现实调用的等价 anchor，`x→zn` 就不能靠 carrier uniqueness 过门；若为强行过门而把 carrier、content、memory 与 mission 合并，则属于 composite-x bundling / object-layer collapse。**
