# 运行记录｜孙悟空·红孩儿｜严格补时间窗口 canonical 复验

## 1｜本轮问题

本轮不重复验证“红孩儿阶段是否为严格 `zx↔nx` 补”。该初始 strict 已于 2026-08-26 按 current `zx补nx_补卡 v0.1` 完成 99/99 canonical 重验。

本轮只验证：

> 初始严格补成立以后，红孩儿任务完成、当前瓶颈消失时，旧观音 `nx` 接口是否退出当前执行窗口；后续新危机是否必须重新判断新的 `nx` 接口，而不能把旧观音关系永久追挂。

## 2｜剧情事实链

第四十二回中，观音明确给悟空诱敌方案，要求其“许败不许胜”；悟空真实承接该外部方案，叫阵、交战、故意败退，把红孩儿引入观音收伏场。

第四十三回开头，红孩儿被观音彻底收伏并带回落伽山。观音随后明确让悟空“快早去洞中，救你师父去来”；悟空与观音叩别，返回洞中救出唐僧。至此：

```text
红孩儿 / 三昧真火造成的当前专属瓶颈
→ 已解除

观音高位收伏接口
→ 已完成本轮功能
→ 不再是“救出唐僧、通过火云洞”这一已结束任务的当前必经门
```

随后叙事立即进入黑水河新危机。该新危机调用的是新的现实接口与新的解决链，而不是把“红孩儿阶段观音 nx”继续当作永久当前关系。

## 3｜初始 zx / nx 端点只作前置条件

### zx 前置

孙悟空持续占据救师、破局方向，并以自身公开行动完成叫阵、破门、交战、诱敌和现实接入。

### nx 前置

红孩儿专属收伏能力与高位处分接口在观音侧；悟空真实进入并沿该外部关系/权限通道推进。

两端已经在独立 canonical 复核中锁定，本轮不重复涨 strict positive 计数。

## 4｜时间窗口闭环测试

### 4.1 触发条件

闭环触发不是“观音离开”这个表面动作，而是：

```text
当前命名瓶颈被解决
+ 当前任务结果完成
+ 旧 nx 接口不再是同一结果的必经门
```

红孩儿被收伏、唐僧获救后，三项同时满足。

### 4.2 拿掉测试

在任务完成后的新窗口里，拿掉“观音仍持续作为当前必经解决接口”这一假设：

- 唐僧已经从火云洞获救；
- 红孩儿已经不再构成当前阻断；
- 原任务结果不会因此重新变成未完成；
- 后续黑水河危机需要重新寻找当时有效的解决接口。

因此旧 `nx` 不再是当前关系功能。

### 4.3 反向测试

若红孩儿并未真正被收伏，或唐僧仍被困，或悟空下一步仍必须继续经观音许可/能力才能完成同一个“救师脱离火云洞”结果，则旧 `nx` 窗口不能判关闭。

原著不是这种结构。

### 4.4 最近邻排除

- **不是人物 nx 本体消失**：本轮只讨论“红孩儿解决接口”这一关系功能窗口，不讨论孙悟空长期人物本体。
- **不是 nx→x 内化**：观音的净瓶、天罡刀和高位处分能力没有稳定转入悟空自己的调用边界；所以闭环机制不是资源内化，而是“任务瓶颈消失 + 旧接口退出”。
- **不是 xn**：后续遇新危机是否重新组织流程是另一问题，不能把“重新找解决路径”本身自动判 nx 或 xn。
- **不是 zx 证明 nx 永久存在**：悟空后续继续公开行动，不得倒推旧观音 nx 仍持续激活。

## 5｜第三因素冻结

可冻结：

- 红孩儿善恶评价；
- 观音慈悲主题；
- 孙悟空主角身份；
- 红孩儿后来成为善财童子的长期意义。

必须保留：

```text
初始 strict 已成立
+ 当前瓶颈是否真的被解决
+ 同一任务是否真的完成
+ 旧外部接口是否仍是同一结果的必经门
```

如果把“任务已经完成”删掉，就等于换题，不能拿来反证时间窗口闭环。
