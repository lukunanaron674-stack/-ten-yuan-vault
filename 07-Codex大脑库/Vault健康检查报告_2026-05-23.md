## 已经做得很好的地方

1. **总入口存在且克制。**  
   `00-中枢索引/总入口.md` 没有堆正文，只负责跳转，这是大型 vault 的正确做法。

2. **理论、案例、工作流三层已经分开。**  
   十元系统、五大主题、银矿库、Codex 大脑库各有职责，不是单纯按来源乱堆。

3. **有二审意识。**  
   `待二审`、`降权`、`不确定` 这些机制很关键，说明这个库不是“AI 输出全收”，而是有质量闸门。

4. **最近活跃方向很集中。**  
   2026-05-23 最近修改集中在 `05-银矿库/角色库/详细卡` 和 `角色库/简索`，这说明当前实际生产重点是“角色案例库”，不是散点漂移。

5. **Codex 大脑库定位准确。**  
   `给你看的大脑报告.md` 已经把 Codex 的吸收方式说清楚：规则库、素材库、F12 验证、降权/删除。

## 主要风险

### 1. 编号冲突

当前同时存在：

- `05-对话归档`
- `05-银矿库`

这会让未来导航、排序、自动脚本都产生歧义。建议后续改成：

- `05-银矿库`
- `09-对话归档`

先不急着物理移动，先在入口页里标清楚“05-对话归档为历史遗留区”。

### 2. 字段不统一

很多核心材料有 YAML，但模板并不完全一致。银矿、角色、F12、动画、工具报告应该各自有稳定字段，否则 Dataview 看板很难发挥。

建议最少统一这几个字段：

```yaml
type:
status:
updated:
theme:
review_status:
source:
priority:
```

### 3. 归档包和正式库边界偏软

`06-旧库迁入`、`12_归档包`、`silver-mine` 与正式 `05-银矿库` 存在重名和历史副本。现在不要急着删，先建立“只读归档”规则：

- 旧库内容：只读，不直接二次编辑。
- 正式内容：进入 `05-银矿库` 或 `01/02` 后才算当前版本。
- 归档包：保留来源证据，不作为日常入口。

### 4. 自动索引还没吃满

装了 Dataview，但目前更像“手工索引为主”。这个库到了该上看板的时候了，尤其是：

- 角色库看板
- 待二审看板
- F12 回流看板
- Codex 待吸收看板
- 降权/待删看板

### 5. F12 输出有编码/命名污染迹象

最近 F12 归档中出现过文件名乱码，例如 `F12褰掓` 这种痕迹。说明某些自动化链路仍有编码问题。建议把 F12 输出统一写入 UTF-8，并在回流前做文件名清洗。

## 推荐目录规则

### 当前不建议大搬家

这个库已经比较复杂，大规模移动会破坏双链和工作流。现在建议采用“入口治理 + 字段治理 + 新增规则优先”的方式。

### 建议心智分层

| 层级 | 目录 | 作用 |
|---|---|---|
| 中枢层 | `00-中枢索引` | 只负责导航、状态、路线 |
| 理论层 | `01-十元系统`、`02-五大主题` | 存放当前有效理论 |
| 项目层 | `03-雾中渡口`、`08-动画方向` | 面向作品和生产 |

| AI 脑层 | `07-Codex大脑库` | Codex 可吸收规则、报告、回流 |
