# 待审议｜zn-x 生命周期中 x 窗口变化与 zn 未来调用资格分离边界

## 1｜候选命题

当前 3 部独立作品、同一 criterion 下的 L4 `evidence-locked` 正向控制共同支持：

> **`x` 的当前运行窗口、现实失去、恢复或载体替换，与 `zn` 的未来调用资格不是同一个变量。某一具体 `x` off / lost / replaced，不足以自动删除此前已经独立过门的 `zn`；同样，`x` 恢复或新 `x` 形成，也不能自动证明 `zn` 是新产生的。**

新增第一份反向护栏进一步补齐：

> **`x` 持续 on，也不能替已经成立的 `zn` 保鲜；只要后续同类冲突里旧原则明确不再完成最终排序，并且没有复位，就必须允许判定旧 `zn` 已退出 / 崩解。**

更短：

```text
x lifecycle
≠
zn lifecycle
```

本文件仅为 L4 `pending-review`，不得覆盖 L2 current canonical。

## 2｜正向控制

### 2.1 《三国演义》严颜｜现实 x 丢失，zn 在同一高压窗口继续

- 旧 `x`：巴郡城防与军政处分。
- 变化：城失、被擒，原 `x` 现实断开。
- `zn`：不可因敌军武力与死亡威胁而被迫屈膝归降；关系若改变，必须重新经过主体自己的价值判断。
- 结果：`x` 已失后，`zn` 仍直接进入生死冲突排序；张飞撤掉威逼、改以义礼后，严颜才自愿归附。
- 置信：事实 99 / 分类 97。

机制：

```text
x lost
→ zn immediately persists under pressure
```

### 2.2 《西游记》唐僧｜关系 x 窗口关闭再恢复，同一 zn 后续再次调用

- `x`：唐僧对当前同行孙悟空的师徒处分 / 约束权限。
- 第27回：`zn + x` 同时运行，唐僧逐走孙悟空。
- 逐走后：当前直接师徒处分 `x` 窗口关闭。
- 第31回：孙悟空重新归队，关系 `x` 窗口恢复。
- 第56-57回：同一“不轻伤人命” `zn` 再次进入同类处分排序。
- 置信：事实 99 / 分类 96。

机制：

```text
x window on
→ off
→ on again
while same zn retains future-call qualification
```

### 2.3 《水浒传》宋江｜旧 x 失去，后来不同新 x 形成，同一 zn 跨载体持续

- 旧 `x`：郓城县押司值日、公文处理与县衙事务中的现实职事权限。
- 变化：杀阎婆惜后逃亡 / 刺配，旧公务 `x` 现实断开。
- `zn`：即使现实上被逼出原秩序，也不愿把永久草寇化视为最终政治 / 法理归属；愿承担官府处分，并保留日后合法回返 / 归顺的未来资格。
- 第36回：旧 `x` 已失时，宋江仍拒绝被梁山强行截取入伙，坚持不杀防送公人、不擅开枷、先赴江州接受处分。
- 后期：完全不同的梁山军事 / 组织 `x` 形成后，同一 `zn` 继续限制新权力的用途与最终方向，持续追求归顺。
- 置信：事实 99 / 分类 98。

机制：

```text
old x on
→ old x lost
→ zn persists without old x
→ different new x forms
→ same zn guides new x
```

## 3｜第一份反向护栏

### 3.1 《悲惨世界》沙威｜现实执法 x 仍 on，但旧法律绝对原则 zn 在同类冲突中退出

- 旧 `zn`：法律与正式司法秩序拥有最终裁定资格；依法应捕者不应因私人恩惠、同情或例外关系而放弃执行。
- 旧原则此前已独立成立：沙威曾因自己错误控告马德兰而主动要求被免职/惩罚，说明法律/职责标准对自己也生效，而不是只在有奖励时使用。
- 关键新事实：冉阿让在街垒有机会杀死沙威，却放他自由。
- 后续同类冲突：下水道出口以后，沙威重新现实控制冉阿让，当前逮捕 / 扣留 / 移交 `x` 仍然 on；他并非“无权执行”。
- 结果：沙威最终放走冉阿让，并明确陷入“自己的释放行为违反警察条例、司法秩序与法典”的原则崩解；旧标准没有复位，随后自杀。
- 置信：事实 99 / 分类 97。

机制：

```text
old zn established
+
current x still on
→ same-type conflict reappears
→ old zn no longer completes final ordering
→ no later restoration
→ old zn lifecycle exits / collapses
```

本护栏证明：

> **`x` 持续存在 ≠ `zn` 必然持续。**

它与前三份正向控制共同把 lifecycle 审计从单向变成双向。

## 4｜正反两面共同支持什么

三份正向不是剧情换皮：

```text
严颜：x 直接丢失，zn 同窗口持续
唐僧：x 窗口关闭 / 恢复，zn 未来调用资格保留
宋江：旧 x 丢失 / 新 x 替换，zn 跨载体持续并重新定向新 x
```

第一份反向则是：

```text
沙威：x 仍在现实运行
→ 旧 zn 在同类冲突中崩解并不再复位
```

共同支持：

1. **当前 `x` off / lost ≠ `zn` 自动退出。**
2. **`x` 恢复 / 新 `x` 形成 ≠ `zn` 自动重新生成。**
3. **`zn` 的未来调用资格可以跨具体 `x` 载体持续。**
4. **`x` 持续 on ≠ `zn` 自动持续。**
5. **端点生命周期必须分别记录，不能从其中一端的变化或稳定倒灌另一端。**
6. **生命周期控制不等于稳定人物本体锁定。** 只锁被测原则与被测掌握对象层。

## 5｜与 current canonical 的关系

本候选不改写 L2：

- `zn` current canonical 已要求跨阶段保留未来调用资格，并允许当前高调用、暂停、遮蔽与真实退出分开判断；
- `x` current canonical 本来就要求具体对象处于现实占有、调用、处分或排除边界；
- 本轮只是把二者的**生命周期不同步**用 3 份正向跨作品控制 + 1 份反向护栏做 L4 压力测试。

因此本 pending-review 的用途是补充审计协议，而不是创造新的端点定义。

## 6｜必须继续找的反例 / 护栏

停止继续堆第四个普通正例，优先找以下反向材料：

### A｜第二部独立作品：x 稳定存在，但 zn 真实退出 / 被替换

首份沙威控制已经证明此机制可成立。下一步必须换作品、换皮肤：

```text
同一 x 持续 on
+
此前 zn 已独立成立
→ 后续同类冲突中原 zn 明确不再进入排序
→ 新原则 / 相反原则稳定接管，或旧原则明确无法复位
```

### B｜x 关闭以后，旧 zn 后续确实不再回来

如果同类压力再次出现，而主体明确使用了相反标准，并跨阶段稳定，则应判 `zn` 已退出 / 被改写，不能因为历史上曾经成立就永久追挂。

### C｜伪 zn 生命周期

表面看原则跨阶段重复，但每次都能由同一个外部命令、身份收益、惩罚或认可刺激完整解释；拿掉外因后无未来调用资格，则不得计 `zn` lifecycle。

### D｜压力显影分账

“外压使 zn 暂时无法表达、解压后再显影”属于 pressure-display；“端点是否退出 / 保留未来调用资格”属于 lifecycle。两者可同案共存，但必须分开计数。

## 7｜拿掉与反向协议

以后判断 `zn` 是否因 `x` 变化而退出，至少问：

```text
1. 被测 x 是否真的 off / lost / replaced，还是仍然 on？
2. 原 zn 在 x 变化或稳定之后还有没有同类冲突可检验？
3. 后续同类冲突中，它是否再次进入最终排序？
4. 若没有再次出现，是文本无机会，还是出现了相反硬证据？
5. 新 x 出现时，是旧 zn 继续定向它，还是已经换成新原则？
6. 若 x 一直存在，主体是否仍有现实能力按旧 zn 行动，却明确不再这样排序？
```

没有同类后续测试机会时，不得把“没再出现”直接写成 `zn` 已消失。

同样，如果主体只是暂时无法表达旧原则，而后续同类冲突又恢复，则优先判 pressure-display / 当前调用遮蔽，不得误写成 lifecycle 退出。
