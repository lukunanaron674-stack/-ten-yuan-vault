# 待审议｜zn-x 生命周期中 x 窗口变化与 zn 未来调用资格分离边界

## 1｜候选命题

3 部独立作品、同一 criterion 下的正向控制支持：

> **`x` 的当前运行窗口、现实失去、恢复或载体替换，与 `zn` 的未来调用资格不是同一个变量。某一具体 `x` off / lost / replaced，不足以自动删除此前已经独立过门的 `zn`；同样，`x` 恢复或新 `x` 形成，也不能自动证明 `zn` 是新产生的。**

两份独立作品反向护栏进一步补齐：

> **`x` 持续 on 不能替旧 `zn` 保鲜；不同新 `x` 稳定形成也不能证明旧 `zn` 必然跨载体持续。只要后续同类冲突中旧原则不再完成最终排序，并出现稳定新排序或明确不复位，就必须允许旧 `zn` 退出 / 崩解 / 被替换。**

最短：

```text
x lifecycle
≠
zn lifecycle
```

本文件仅为 L4 `pending-review`，不得覆盖 L2 current canonical。

## 2｜正向控制

### 2.1 《三国演义》严颜｜x 丢失，zn 同窗口持续

- 旧 `x`：巴郡城防与军政处分。
- 城失、被擒后原 `x` 现实断开。
- `zn`：不可因武力与死亡威胁而被迫屈膝归降；关系改变必须重新经过主体价值判断。
- `x` 已失后该原则仍进入生死冲突排序；张飞撤掉威逼、改以义礼后才自愿归附。
- 事实 99 / 分类 97。

机制：`x lost → zn immediately persists under pressure`。

### 2.2 《西游记》唐僧｜关系 x off→on，zn 保留未来调用资格

- 第27回：不轻伤人命 `zn` 与师徒处分 `x` 同时运行，逐走孙悟空。
- 逐走后当前直接关系 `x` 窗口关闭。
- 第31回关系恢复；第56–57回同一 `zn` 再次进入同类处分排序。
- 事实 99 / 分类 96。

机制：`x on → off → on while same zn retains future-call qualification`。

### 2.3 《水浒传》宋江｜旧 x lost，新 x 形成，同一 zn 跨载体持续

- 旧 `x`：郓城押司现实职事；杀惜逃亡/刺配后断开。
- 旧 `x` 已失时，宋江仍不愿把永久草寇化视为最终政治/法理归属，坚持接受官府处分并保留合法回返资格。
- 后来完全不同的梁山军事/组织 `x` 形成，同一 `zn` 继续限制新权力的用途与最终方向。
- 事实 99 / 分类 98。

机制：`old x lost → zn persists → different new x forms → same zn guides new x`。

## 3｜反向护栏

### 3.1 《悲惨世界》沙威｜x 仍 on，旧 zn 崩解

- 旧 `zn`：法律与正式司法秩序拥有最终裁定资格。
- 旧原则此前已独立成立，并曾对沙威自己生效。
- 冉阿让宽恕后，下水道出口沙威仍现实控制冉阿让，逮捕/扣留/移交 `x` 并未消失。
- 但后续同类冲突里旧原则不再完成最终排序：沙威放走冉阿让，陷入原则崩解，旧标准没有复位。
- 事实 99 / 分类 97。

机制：

```text
old zn established
+ current x still on
→ same-type conflict
→ old zn no longer completes final ordering
→ no restoration
```

锁：**`x` 持续存在 ≠ `zn` 必然持续。**

### 3.2 《教父》(1972) 迈克尔·柯里昂｜不同新 x 形成，旧 zn 被新排序替换

- 旧 `zn`：可以属于家庭，但不把家族犯罪权力与暴力秩序作为自身最终生活/行动归属；与犯罪业务保持现实距离。
- 该原则在参军、保持业务距离、向 Kay 明确区分“家族”与“我”等前置行为中独立成立。
- Vito 遇刺后，Michael 从外围保护转为主动提出并执行对 Sollozzo / McCluskey 的双杀。
- 后来新的 Corleone 家族组织、人事、交易与暴力处分 `x` 稳定形成，现实节点按其决定运行。
- 影片末段旧“保持距离”原则没有复位，新“家族安全/权力与主动控制”排序稳定接管。
- 事实 99 / 分类 97。

机制：

```text
old zn established
→ high pressure transition
→ different new x forms and stabilizes
→ new ordering takes over
→ old zn does not restore
```

锁：**different new `x` formed ≠ old `zn` 必然跨载体持续。**

## 4｜正反两面共同支持什么

```text
严颜：x 直接丢失，zn 同窗口持续
唐僧：x 窗口关闭/恢复，zn 未来调用资格保留
宋江：旧 x 丢失/新 x 替换，zn 跨载体持续

沙威：x 持续 on，旧 zn 仍可崩解
Michael：different new x 形成，旧 zn 可被新排序替换
```

共同纪律：

1. 当前 `x` off / lost ≠ `zn` 自动退出。
2. `x` 恢复 / 新 `x` 形成 ≠ `zn` 自动重新生成。
3. `zn` 可以跨具体 `x` 载体持续，但不是必然。
4. `x` 持续 on ≠ `zn` 自动持续。
5. 新 `x` 稳定形成 ≠ 旧 `zn` 必然继续指导新 `x`。
6. 历史上曾成立的 `zn` ≠ 永久人物本体；后续同类冲突必须允许检验退出、崩解、替换与不复位。
7. lifecycle 只锁被测原则/对象层，不锁整个人物永久本体。

## 5｜与 current canonical 的关系

本候选不改写 L2：

- `zn` current canonical 已要求跨阶段未来调用资格，并允许高调用、暂停、遮蔽与真实退出分开判断；
- `x` current canonical 要求具体对象处于现实占有、调用、处分或排除边界；
- 本 pending-review 只是用 `3 positive works + 2 negative-guard works` 压硬**两端生命周期不能互相倒灌**的审计协议。

## 6｜下一阶段高价值反例

停止继续堆普通 lifecycle 正例，也停止复制现有两种反向皮肤。优先：

### A｜x off 后旧 zn 明确不复位

```text
old zn established
→ x closes/lost
→ later same-type pressure reappears
→ subject uses a stable opposite/new standard
→ old zn does not return
```

这能补齐“x 关闭后原则是否仍可真实退出”的第三种机制。

### B｜伪 lifecycle

表面原则跨阶段重复，但每次都能由同一个外部命令、身份收益、惩罚或认可刺激完整解释；拿掉外因后没有未来调用资格，则不得计 `zn lifecycle`。

### C｜pressure-display 分账

“外压使旧 `zn` 暂时无法表达、解压后恢复”属于 pressure display；“旧 `zn` 是否退出/保留未来调用资格”属于 lifecycle。两者可同案共存，但必须分别计数。

## 7｜拿掉与反向协议

以后至少问：

```text
1. 被测 x 到底 on / off / lost / replaced 哪一种？
2. 原 zn 后续有没有同类冲突可检验？
3. 后续同类冲突里，它是否再次进入最终排序？
4. 若没有再次出现，是文本无机会，还是已有相反硬证据？
5. 新 x 出现时，是旧 zn 定向它，还是新原则接管？
6. 若 x 一直存在，主体是否仍有能力按旧 zn 行动却明确不再这样排序？
7. 是否只是 pressure-display 暂时遮蔽，后续其实复位？
```

没有同类测试机会时，不得把“没再出现”写成 `zn` 已消失。
