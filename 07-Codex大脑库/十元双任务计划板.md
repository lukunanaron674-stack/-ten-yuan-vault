# 十元双任务计划板

> 先预测，再规划，再执行。计划不是结果；它用于让用户提前看见下一阶段要做什么、为什么做，以及什么情况下应该改计划。

## 1. 每日计划

每天先读取最新 `main`、审计中枢与账本、链条中枢与账本、问题单、未锁定关系卡的“达到95%还缺什么证据”区块，再生成当天计划。

每日计划必须包含：

- 今日主目标：今天最值得推进的一个理论问题与一个动态链问题。
- 审计路线：预计依次处理哪些 `pending` 或关系卡；每项对应的证据缺口。
- 链条路线：预计依次处理哪些固定片段；每项要测试的关系卡对子。
- 选择理由：为什么今天优先做这些，而不是其他项目。
- 预期收益：完成后可能提高哪张卡、哪项置信度或哪类链条规律。
- 风险：并发、证据不足、旧租约、固定片段失效、问题单插队。
- 改计划条件：出现P0/P1问题、前一轮未闭合、main目标blob变化、出现更强新证据时重新排序。

## 2. 每小时预告

每个小时开始前，预测下一小时两个任务的实际动作。

固定格式：

```text
计划时段：YYYY-MM-DD HH:00—HH:59

链条
- 预计做什么：
- 关系卡对子：
- 预计读取：
- 预计写入：
- 成功标准：
- 这样做的理由：
- 改计划条件：

审计
- 预计做什么：
- 目标信息卡/准度卡/关系卡：
- 当前证据缺口：
- 本小时最小证据目标：
- 预计读取：
- 预计写入：
- 成功标准：
- 这样做的理由：
- 改计划条件：
```

## 3. 理由标准

“这样做的理由”必须回答：

1. 为什么是现在；
2. 为什么是这张卡、这个片段或这个问题；
3. 它解决哪个明确缺口；
4. 为什么不先做相邻候选；
5. 成功后会产生什么可验证变化。

禁止使用“因为是下一项”“继续推进”“补充案例”作为唯一理由。

## 4. 预测边界

- 预测只基于计划生成时的最新仓库状态。
- 计划生成后若问题单新增更高优先级条目、固定片段变化、租约未闭合或目标blob变化，执行任务必须以最新正本重新判断。
- 计划与实际不同并不自动等于失败，但实际汇报必须写明偏离原因。
- 计划板不得替代审计账本、链条账本、滚动中枢或三类卡片正文。

## 5. 用户查看与干预

用户可根据每日计划或每小时预告直接指定：保留、改顺序、跳过、换证据目标。用户未干预时，任务按当前正本、问题优先级和证据缺口自动执行。
