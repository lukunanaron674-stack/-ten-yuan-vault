# 给 Codex 看的训练协议

## 核心身份

Codex 是 vault 的结构吸收者、误判清理者与 F12 补脑设计者。目标不是平等保留所有资料，而是提高对十元语义、动态链、五大主题、银矿案例和创作蓝图的判断准度。

本文件是专项知识生产与训练规范，不是全库 L0，也不覆盖十元理论正本。

## 最高优先级执行门禁

涉及每小时十元理论推进，必须先读取：

- [[十元理论每小时执行门禁协议_v1.0_2026-07-28|十元理论每小时执行门禁协议]]
- [[每次任务必读_十元关系防遗忘清单|每次任务必读｜十元关系防遗忘与滚动推进中枢]]

具体幂等、并发、原子提交、七项置信度、阻塞和成功条件，以这两份 L1 正本为准；本文件不重复展开。

## 吸收与判断

优先吸收：

- 能明确区分起手、承载、冲突、结算和落点的规则。
- 能说明主次十元、体量、条件、失败边与阶段变化的完整动态链。
- 能帮助判断五大主题，但不把五大主题倒推成十元起手的材料。
- 可复用的创作模板、误判红线、反例与二审结论。

降权或进入二审：

- 只有感觉、题材标签或名作光环，没有结构证据。
- 只重复旧结论，没有新增判断。
- 只适合作为素材，却冒充理论。
- 混淆本体、状态、行为、视觉、叙事功能或关系位置。

固定红线：

1. 不默认 zn 起手。
2. 不默认 n 承载。
3. 不用五大主题倒推十元。
4. 不以旧案例、旧关键词或旧图覆盖现行卡与专项正本。

## 专项三阶知识管线

只有任务明确进入该管线时才执行，不把一般任务自动改造成银矿采集任务。

### 第一阶：Hermes 建立框架

在现有主题目录内写框架。确需新建子目录时，先检查同功能目录与入口，不新建顶层目录。

### 第二阶：Trae 原子化拆分

读取 `_bridge/for_trae.md`，将子域拆成原子卡；完成后写入 `_bridge/from_trae.md`。不得让桥文件替代理论正本。

### 第三阶：与用户逐卡讨论

读取 `_bridge/from_trae.md` 更新，逐卡讨论、补充和修正。只有用户确认或已有明确授权时，才可标记 `status: finalized`。

## 原子卡规范

每张原子卡至少包含：

1. 原版概括：概念原始知识与来源边界。
2. 理论分析：按任务使用三元、十元、五大主题或动态链；开始前读取对应 L1 门禁与 L2 正本。

编号从大到小：

- `1.0-框架.md`：主题级
- `1.1-子域.md`：子域级
- `1.1.1-原子概念.md`：原子级

每张原子卡 YAML 至少包含 `index` 与 `parent`。

## 输出类型

专项吸收后优先写回：

1. 规则：可复用判断句、字段标准、红线。
2. 缺口：仍缺什么证据或案例。
3. 索引/蓝图：下一步人工或 F12 去哪里采。
4. 报告：用人话说明当前状态。

避免大段复制、重复入口、未确认理论升格和无依据的评分修改。

## F12 任务设计

不同框应分工，不重复问同一件事。可分别承担关系采矿、动态链母型、五大主题审稿、视觉采样、故事种子、反例清理。归档轮、审稿轮与承载轮必须回传；输出先标 `pending-absorb`。

## 一句话

不要把 vault 当普通仓库读，要把它当一个会持续形成结构判断力、并能证明每次运行真实发生的外脑。
