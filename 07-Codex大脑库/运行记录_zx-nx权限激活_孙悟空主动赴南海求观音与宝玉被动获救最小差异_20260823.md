# 运行记录｜孙悟空主动赴南海求观音：主体接入外部解决通道的 nx 正向控制

## 0｜本轮问题

上一轮《红楼梦》宝玉挨打已经锁定：王夫人、贾母的保护接口真实存在且真实改变结果，但宝玉本人没有请求、等待、承接或沿该通道推进，因此不能只凭“被别人救了”反推主体 nx 行为功能。

本轮专找最小差异：

> **同样是外部高位保护/解决接口介入，如果主体本人明确发现自身路径失效，主动进入既有关系网络，说明问题、请求帮助，并继续沿外部给出的解决路线推进，nx 是否成立？**

结论：成立，99/98。

## 1｜剧情事实

红孩儿摄走唐僧后，孙悟空持续自行救师。正面对抗被三昧真火压制，四海龙王施雨也不能解决。到第四十二回，孙悟空明确离开当前战场，主动飞赴南海落伽山。

他到达以后先向诸天说明“要见菩萨”，获准入内后向观音陈述：唐僧被红孩儿摄去，自己与八戒交战失败，龙王施雨仍不能胜火，当前救师路径无法闭环。

观音回应后，孙悟空没有绕开这个接口另起一套最高解决方向，而是接受观音进入当前救师链，随后继续承担诱敌、配合和回洞救师等执行动作。

因此本轮对象层非常明确：

```text
孙悟空自己的最高方向：
救唐僧 / 突破红孩儿阻断
= zx方向端仍在

当前现实瓶颈：
三昧火与红孩儿专属能力使自身路径失败

主体动作：
主动赴南海
→ 明确请求见观音
→ 说明当前失败与缺口
→ 接受观音这一既有高位解决接口进入
→ 按该解决路线继续行动
= nx行为功能真实激活
```

## 2｜zx 判断

本轮不重新制造“孙悟空稳定人物本体 = zx”的结论，只锁当前方向端：

- 救师方向不是观音替他生成；
- 第一次、第二次失败后，最高目标仍由孙悟空维持；
- 进入观音接口以后，他没有把“是否救师、是否继续取经”的最终方向交出。

因此：

`zx_current_direction_stage: evidence-locked`

但本轮重点不是严格补关系，而是 nx 是否被主体真实激活。

## 3｜nx 判断

现行 nx v2.5 要求：方向、权限或解决通道已经存在，主体在当前对象层真实请求、借用、承接或沿其继续。

本例满足得非常干净：

1. 观音这一既有关系/高位解决通道客观存在；
2. 孙悟空主动离开战场去南海；
3. 明确提出“要见菩萨”；
4. 进入以后主动陈述当前失败与救师缺口；
5. 没有把观音只当信息源，而是实际接受其解决能力进入；
6. 后续继续沿该解决路线承担诱敌与救师动作。

所以：

```yaml
subject_requests_external_help: true
subject_enters_existing_relation_channel: true
subject_reports_problem_to_external_authority: true
subject_accepts_external_solution_route: true
nx_behavior_function: evidence-locked
nx_relation_position: evidence-locked
```

这里的 nx 不是“孙悟空没主见”，而是强主体在具体瓶颈上真实进入外部权限/能力通道。

## 4｜与宝玉挨打的最小差异

### 宝玉挨打

```text
外部保护接口存在
→ 王夫人 / 贾母自行介入
→ 结果改变

但：
宝玉本人没有请求
没有等待
没有承接
没有沿关系通道推进

= 外部救援有效
≠ 主体 nx 行为激活
```

### 孙悟空红孩儿

```text
自身路径失败
→ 主体主动识别外部解决接口
→ 主动进入
→ 明确说明缺口
→ 请求 / 接受外部解决路线
→ 沿该路线继续

= nx 行为功能成立
```

因此本轮真正新增的最小差异是：

> **“别人主动救我”与“我把当前问题真实接到别人拥有的解决通道上”不是同一结构。**

## 5｜最近邻排除

### nx vs 外部状态改变

只有外部节点替主体改状态，不足以锁主体 nx；本例多出的是主体自己的“进入/请求/承接/续接”链。

### nx vs xn

孙悟空当然会判断、赶路、说明情况，但“观音这一高位解决接口”不是他自己搭建的计划网络。请求接口的动作多，不等于主体自己设计了新的持续运行骨架。

本窄请求阶段：

`xn_in_request_stage: rejected_as_primary`

### nx vs x

观音的法力、法宝与最终收伏接口不属于孙悟空原有稳定调用边界，因此不是孙悟空自己的 x。

### nx vs zx

孙悟空保留最高救师方向，不会抹掉具体问题层 nx。自己的方向可以很强，同时某个关键解决接口仍在别人那里。

## 6｜拿掉测试

### 拿掉孙悟空主动接入动作

如果改成：

```text
观音自行得知红孩儿之事
→ 主动赶到现场
→ 直接替孙悟空解决
```

那么就会向宝玉挨打型靠近：只能先证明外部保护接口有效，不能仅凭结果自动锁孙悟空当前 nx 行为。

### 拿掉观音外部接口

孙悟空的救师方向仍存在，但已知三昧火和红孩儿当前专属能力让原路径无法闭环，现实解决缺口重新出现。

这证明外部解决接口是真缺口，不是装饰性社交。

### 拿掉“请求”这个表面词，但保留承接/续接

即使原文没有明确说“请帮我”，只要仍存在：

```text
主动到南海
→ 说明问题
→ 接受观音解决路线
→ 继续沿其推进
```

nx 仍应成立。

因此不能把 nx 机械缩成“必须说出求人话术”。

## 7｜反向测试

### 非主体 nx 激活

```text
主体未请求、未等待、未承接
→ 外部节点自行介入并改变结果
= 宝玉挨打型
```

### 主体 nx 激活

```text
主体发现自身路径无法闭环
→ 主动进入已有关系/权限网络
→ 请求、说明、借用或承接
→ 当前行为真实沿该通道继续
= 本例
```

### 仍非 xn

若孙悟空不是去找已有观音接口，而是自己建立一套新的人员、资源、时序和解决体系，才应重新查 xn。

## 8｜第三因素冻结

冻结：

- 孙悟空稳定人物本体标签；
- 主角光环与战力；
- 观音地位；
- 师徒感情强度；
- 红孩儿善恶评价；
- 最终是否成为善财童子；
- 后续取经成功。

只保留：

1. 外部解决接口是否真实存在；
2. 主体此前路径是否出现现实缺口；
3. 主体本人是否主动/明确把当前问题接入外部接口；
4. 主体后续是否沿该接口继续推进。

结论仍稳定为 99/98。

## 9｜结论

本轮最窄可靠纪律：

> **外部权限/保护接口存在且改变结果，不足以锁主体 nx；但主体若明确把当前问题接入已有关系、权限或解决通道，并实际沿其继续，则 nx 行为功能成立。**

进一步：

> **主动请求是高强 nx 激活证据，但不是唯一形式；真正变量是“主体是否把当前行为接到外部通道上续接”。**

因此本例与宝玉形成当前最清楚的正反最小差异：

```text
宝玉：被救，但主体未接入 → 非主体nx激活
孙悟空：主动接入并续接 → nx激活
```

本轮不修改 L1、zx/nx 信息卡、准度卡或补卡；也不重测此前已锁定的红孩儿严格补与时间窗口结论。
