# 动态链 v2.0｜输入输出正本

> 版本名称固定为：**动态链**。版本号：**v2.0**。

## 1. 版本定位

`动态链 v2.0`是**卡片回流优先版**：

```text
十元信息卡、十元准度卡、十元关系卡
→ 指导作品动态链分析
→ 作品产生正例、反例、边界与机制证据
→ 回写三类十元卡
→ 其次保存作品动态链案例
```

作品不是最终仓库，作品是三类卡持续生长的实验材料。

## 2. 输入合同

### 第一核心输入｜十元信息卡

必须读取本轮所有候选端点的现行信息卡，用来回答：

- 这个端点究竟是什么；
- 核心变量是什么；
- 对象层、主体和阶段是什么；
- 稳定本体、当前状态、行为功能和关系位置怎样分开；
- 该十元有哪些已知正例、反例、显影方式和误判边界。

保存入口：

```text
01-十元系统/十元体系密度卡总览.md
01-十元系统/【各十元信息量卡】.md
```

### 第二核心输入｜十元准度卡

必须读取本轮所有候选端点对应的现行准度卡，用来回答：

- 为什么必须判成该十元；
- 最近邻是什么；
- 必要条件是否满足；
- 拿掉后是否仍成立；
- 反向是否恢复；
- 是否存在第三因素；
- 当前是纯例、污染例还是未判定例。

保存入口：

```text
01-十元系统/03-十元准度卡/
```

### 第三核心输入｜十元关系卡

必须读取本轮候选关系对应的生卡、克卡或补卡，以及已有具体关系专项，用来回答：

- 两个已成立端点之间是否真的发生生、克或补；
- 被改变的是目标的哪一个核心变量；
- 是直接关系边、间接路径还是条件；
- 失败边违反了哪一条门槛；
- 该具体关系对子已有多少证据与什么边界。

保存入口：

```text
01-十元系统/04-十元生克补卡/
01-十元系统/关系专项/
01-十元系统/十元生补克表.md
```

### 第四输入｜作品证据

- 一部作品中的一个预先固定C级单场或片段；
- 上一精确案例路径；
- 该片段中的可观察行为、材料、程序、确认主体和阶段变化；
- 与旧案例的可比点和竞争解释。

### 第五输入｜运行状态

- 当前main SHA；
- 产品版本、执行协议；
- 滚动中枢；
- 唯一账本；
- slot、attempt、租约、pending案例和目标blob。

## 3. 输出合同

## 第一核心输出｜三类卡增量包

每轮必须生成`card_delta_manifest`，逐项记录相关卡片：

```text
card_path
card_type：information / accuracy / relation / relation-specific
input_version
output_version
operation：UPDATE / APPEND_EVIDENCE / NO_CHANGE
new_evidence
boundary_change
reason
source_case_path
confidence
```

### A. 信息卡输出

作品出现实质新材料时，原位补充相关信息卡中的一项或多项：

- 新对象层或新主体层；
- 新稳定本体/状态/功能区分；
- 新显影方式；
- 新正例或反例；
- 新误判边界；
- 新体量表现；
- 原定义需要收窄或补充的条件。

### B. 准度卡输出

原位补充相关准度卡中的一项或多项：

- 最近邻差异；
- 必要条件；
- 拿掉测试；
- 反向测试；
- 第三因素；
- 纯例、污染例或失败例；
- 新的视觉/行为误判来源。

### C. 关系卡输出

- 生、克、补的通用门槛只有发生实质边界变化时才修改通用关系卡；
- 具体关系对子的新证据，优先写入`关系专项/`对应关系卡；
- 尚无专项卡但证据达到建立门槛时，新建候选关系专项；
- 未达到门槛时，只在作品案例中登记候选，不修改十元生补克表。

关系卡增量可以是：

- 新直接边正例；
- 新正式失败边；
- 新最近邻；
- 新必要条件；
- 新阶段边界；
- 新跨对象层复现；
- 对旧关系的收窄、分账或降级证据。

### 核心进度状态

```text
CARD_DELTA_COMMITTED
CARD_EVIDENCE_APPENDED
CASE_ONLY_NO_CARD_DELTA
```

- 至少一张核心卡或具体关系专项获得实质增量，才可称为`CARD_DELTA_COMMITTED`。
- 定义不变但新增一条经核验的正例、反例或失败边证据，可称为`CARD_EVIDENCE_APPENDED`。
- 三类卡均无任何新增时，必须标记`CASE_ONLY_NO_CARD_DELTA`，不得把案例数量增长冒充十元理论推进，也不得为了交差硬改卡。

## 第二输出｜作品动态链案例

保存一个明确C级片段的完整分析：

- 对象分层、主体和阶段；
- 端点卡路由；
- 唯一核心被改变变量；
- 主生、主克、主补；
- 具体直接边；
- 间接路径与条件节点；
- 动态类型；
- 正例和至少一个正式失败候选；
- 最近邻、拿掉、反向、第三因素；
- 确认分账和错误来源；
- 七项置信度；
- 卡片回流摘要；
- 搭配效果和母型累计。

保存位置：

```text
08-生克补动态链研究/影片案例/
08-生克补动态链研究/现实案例/
```

## 第三输出｜状态与索引

- 更新动态链滚动中枢；
- 更新动态链总索引；
- 更新唯一运行账本；
- 保存精确完成案例路径；
- 保存三类卡修改路径和版本变化；
- 保存下一固定作品、片段、目标卡缺口和研究问题。

## 4. 单轮完整输入输出

```text
输入：
信息卡 + 准度卡 + 关系卡
+ 当前卡片缺口
+ 固定C级作品片段
+ 上一精确案例
+ 中枢/账本/执行状态

处理：
端点确认
→ 准度排邻
→ 生克补直接边判断
→ 动态链组合
→ 提取卡片新证据
→ 判断哪些卡应更新

第一输出：
信息卡增量
+ 准度卡增量
+ 关系卡/关系专项增量
+ card_delta_manifest

第二输出：
作品动态链案例

第三输出：
中枢 + 索引 + 账本 + 下一卡片缺口
```

## 5. 每轮最低交付标准

每次运行至少必须明确回答：

1. 本轮读取了哪些信息卡、准度卡和关系卡；
2. 每张卡得到什么新证据；
3. 哪些卡实际更新，哪些卡因无实质新增保持不变；
4. 作品的哪一条直接边或失败边支持了该增量；
5. 作品案例保存在哪里；
6. 下一轮优先解决哪张卡的哪个缺口。

## 6. 与十元关系审计的边界

动态链可以更新：

- 信息卡中的作品证据、边界和显影；
- 准度卡中的最近邻与测试证据；
- 通用生克补卡的非锁定边界；
- 具体关系专项的案例证据与候选机制。

动态链不得单独完成：

- 未达到95%就锁定新关系；
- 擅自改十元核心本体定义；
- 擅自改十元生补克表中的锁定关系；
- 用一部作品推翻跨案例正本。

需要改变锁定关系时，把证据送入“十元关系审计”主线完成正式锁定。

## 7. 版本一句话

> `动态链 v1.0`是“读卡分析作品”；`动态链 v2.0`是“读卡分析作品，再让作品反过来长进卡里”。
