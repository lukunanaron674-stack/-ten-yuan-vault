# 动态链 v2.1｜链条与审计分工正本

## 1. 身份

本任务简称**链条**。链条负责作品动态链分析、直接边与失败边验证、动态母型积累和证据生产。

十元理论任务简称**审计**。审计负责十元信息卡、十元准度卡、十元关系卡、关系专项与十元生补克表的研究、修改、升级和锁定。

## 2. 链条输入

链条必须读取现行信息卡、准度卡和关系卡作为判定工具，但这些卡片属于审计维护的理论正本。

链条的主要研究输入是：固定C级作品片段、上一精确案例、当前矿区、现行卡路由、动态链方法、模板、中枢、索引和运行账本。

## 3. 链条第一输出

链条第一输出始终是作品动态链案例：对象层、主体、阶段、端点、唯一核心变量、直接生克补边、条件、失败边、拿掉、反向、竞争解释、七项置信度、动态类型、搭配效果和母型累计。

## 4. 链条第二输出｜审计提案

链条发现理论卡可能存在问题时，不得直接改卡；必须写入`08-生克补动态链研究/交接给审计/动态链给审计的提案队列.md`。

每条提案至少包含：

```text
proposal_id
status: WAIT_AUDIT
source_case_path
target_card_path或target_area
proposal_type: information / accuracy / relation / relation-specific / relation-table
observed_evidence
suggested_change
counterevidence
seven_confidence
reason_for_audit
```

链条可以提出：新增正例、反例、失败边、最近邻、必要条件、阶段边界、机制收窄、跨作品复现或定义冲突。

## 5. 权限边界

链条不得直接：

- 修改十元信息卡；
- 修改十元准度卡；
- 修改十元关系卡或关系专项；
- 修改十元生补克表；
- 提升理论版本或记忆版本；
- 锁定、降级或推翻关系。

即使证据达到95%，链条也只提交高优先级提案，由审计复核后写入理论正本。

## 6. 审计职责

审计每轮优先读取`WAIT_AUDIT`提案，结合跨案例证据独立复核。审计可接受、部分接受、拒绝、要求补证或合并提案，并负责实际修改三类卡及关系正本。

## 7. 闭环

```text
审计发布理论正本
→ 链条读取理论并分析作品
→ 链条保存动态链案例
→ 链条提交WAIT_AUDIT提案
→ 审计复核并决定是否改卡
→ 链条下一轮读取新正本
```

## 8. 矿区轮换

链条选片与断点应保持矿区平衡，优先补足低覆盖矿区，尤其`nx`与`nz`。矿区轮换影响作品选择，不改变审计对端点和关系的最终裁定权。

## 9. 一句话

> 链条负责把作品变成可靠动态链和证据；审计负责把可靠证据变成十元理论。
