# 动态链 v2.2｜链条与审计分工正本

> 文件名作为稳定入口保留；正文与frontmatter版本为现行版本。

## 1. 身份与职责

本任务简称**链条**。链条负责作品动态链分析、直接边与失败边验证、动态母型积累、关系组合与顺序效果研究，以及向审计提供可复核证据。

十元理论任务简称**审计**。审计负责十元信息卡、十元准度卡、单条关系卡、关系专项与十元生补克表的研究、修改、升级和锁定。

## 2. 链条输入

链条读取现行信息卡、准度卡和关系卡作为判定工具，但这些卡片属于审计维护的理论正本。

链条主要输入：固定C级作品片段、上一精确案例、当前矿区、现行卡路由、动态链方法、模板、中枢、索引和运行账本。

## 3. 链条第一输出

链条第一输出始终是作品动态链案例，包括：对象层、主体、阶段、端点、唯一核心变量、直接生克补边、条件、正式失败边、拿掉、反向、竞争解释、七项置信度、动态类型、搭配效果、链段顺序效果和母型累计。

## 4. 链条第二输出｜给审计的问题

链条发现理论卡可能存在问题时，不得直接改卡；只可写入唯一交接入口：

`08-生克补动态链研究/链条给审计的问题单.md`

问题至少记录：issue_id、pending状态、优先级、来源案例、目标卡路径、原始事实、对象层、阶段、受影响变量、拿掉/反向/最近邻/第三因素、链条推断、审计问题与置信度。

链条可以提交：端点不适配、最近邻缺口、拿掉/反向失败、关系机制缺口、新反例、新失败边、跨作品复现或版本断链。

没有实质问题时，在案例与账本记录`audit_issue: none`，不得为了交差制造问题。

## 5. 权限边界

链条不得直接：

- 修改十元信息卡；
- 修改十元准度卡；
- 修改单条关系卡或关系专项；
- 修改十元生补克表、关系词典；
- 提升理论版本或记忆版本；
- 锁定、降级或推翻关系。

即使证据达到95%，链条也只提交P0/P1问题，由审计独立复核。

## 6. 审计职责

审计每轮先读取问题单，优先处理最高优先级、最早提交的`pending`条目；无待处理问题时才推进常规关系断点。审计可接受、部分接受、拒绝、延期补证或合并，并负责实际修改三类卡与关系正本及回写处理结果。

## 7. 闭环

```text
审计发布理论正本
→ 链条只读理论并分析作品
→ 链条保存动态链案例
→ 有问题则追加pending问题单
→ 审计独立复核并决定是否改卡
→ 链条下一轮读取新正本
```

## 8. 矿区轮换

链条的后续选片与断点安排应保持矿区平衡，优先补足低覆盖矿区，尤其`nx`与`nz`。矿区轮换只影响动态链采样，不改变审计对端点和单条关系的最终裁定权。

## 9. 执行前职责自检

任何写入前必须先生成本轮目标文件清单，并执行以下硬门：

```text
目标路径包含 01-十元系统/
→ 当前身份是否为审计？
→ 否：立即停止，返回 ROLE_WRITE_VIOLATION

目标路径包含动态链案例、中枢、索引、账本、执行协议或问题单
→ 当前身份是否为链条或治理任务？
→ 否：立即停止，返回 ROLE_WRITE_VIOLATION
```

链条的允许写入集合仅为：固定案例、动态链滚动中枢、动态链总索引、动态链唯一账本，以及必要时对唯一问题单的追加。任何其他路径都必须在提交前从tree中移除；不能移除则整轮停止。

## 10. 原子提交硬门

同一事务修改两个或以上文件时，只允许：

```text
create_blob
→ create_tree(base_tree=当前main tree)
→ create_commit(parent=写前重读的当前main)
→ update_ref(force=false)
```

禁止连续调用单文件更新接口来模拟原子事务。写前必须重读最新main和全部目标blob；任一目标发生变化，返回`CONCURRENT_RESTART_REQUIRED`并从最新main重新开始。

## 11. 成功一致性门

链条只有在回读后同时满足以下条件，才可汇报`VERIFIED_SUCCESS`：

- 唯一账本中的slot与本轮slot一致；
- attempt与本轮attempt一致；
- 唯一账本状态为`VERIFIED_SUCCESS`；
- 滚动中枢状态为`READY`或协议规定的封账后稳定态；
- active_lease为`null`，pending_case为空；
- 案例路径、案例SHA、累计变化、下一固定clip_key在案例、中枢、索引和账本之间一致；
- 可选问题单只发生追加，历史条目未删除或改写；
- 本轮提交不包含任何理论卡路径。

只验证账本而未验证中枢、索引、lease和下一断点时，不得汇报成功。

## 12. 一句话

> 链条负责把作品变成可靠动态链和问题证据；审计负责把可靠证据变成十元理论；执行器必须先过职责、原子性和全链一致性三道硬门。
