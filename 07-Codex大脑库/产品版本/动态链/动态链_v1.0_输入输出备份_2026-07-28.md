# 动态链 v1.0｜输入输出备份

> 这是上一版的冻结快照，只用于回看和必要回滚，不再作为现行每小时任务正本。

## 1. 版本定位

`动态链 v1.0`是**作品案例优先版**：三类十元卡主要作为读取工具，核心交付物是影片C级片段动态链案例，以及中枢、索引和账本的推进。

## 2. 输入

### A. 十元理论输入

- 本轮源端点、目标端点的现行十元信息卡；
- 本轮源端点、目标端点的现行十元准度卡；
- 生卡、克卡或补卡；
- 十元生补克表、关系专项索引与现行关系机制；
- 十元关系防遗忘清单；
- 动态链方法修正与影片分析模板。

### B. 作品输入

- 一部影片中的一个固定C级单场或片段；
- 上一影片案例；
- 当前`next_priority_film`、`next_priority_clip_key`、`next_priority_question`。

### C. 执行输入

- 当前main SHA；
- 滚动中枢；
- 唯一运行账本；
- slot、attempt、租约、目标文件blob与并发状态。

## 3. 输出

### 第一输出：作品动态链案例

- 对象层、主体、阶段；
- 十元端点；
- 核心被改变变量；
- 主生、主克、主补；
- 直接关系边、间接路径、条件节点与失败边；
- 动态类型；
- 拿掉、反向、最近邻和第三因素；
- 七项置信度；
- 搭配效果与母型候选。

### 第二输出：运行与累计

- 新建或更新影片案例；
- 更新动态链总索引；
- 更新滚动中枢与下一固定片段；
- 更新唯一运行账本；
- 通过门槛时增加案例或母型支持数。

### v1.0没有强制输出

- 不强制把作品发现回写进十元信息卡；
- 不强制把最近邻和失败边回写进十元准度卡；
- 不强制把关系机制证据回写进十元关系卡或关系专项。

三类卡在该版本中主要是**输入**，不是每轮的第一交付物。

## 4. 典型执行流

```text
读取三类卡
→ 分析固定影片片段
→ 形成影片动态链案例
→ 更新中枢、索引和账本
→ 必要时累计母型
```

## 5. 退出原因

该版本可以持续增加影片案例，但作品所得的新正例、反例、误判边界和关系机制不一定回流三类十元卡，容易形成：

```text
卡片提供理论
→ 作品消耗理论
→ 案例库增长
→ 卡片本身增长不足
```

因此从`动态链 v2.0`起，三类十元卡成为第一输入和第一输出，作品案例退到第二产出。
