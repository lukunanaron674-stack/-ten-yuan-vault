# 13｜对象状态机与ID命名规范

> 原库能列出“有哪些对象”，却没有统一说明对象怎样从秘密变成证据、从合同变成废纸、从房间变成归属。对象若永远只以名词存在，剧情就只是名词在会议室里开会。

## 一、规范ID命名空间

原表中的短编码保留用于阅读，但跨文件引用必须加命名空间。

| 类型 | 规范前缀 | 示例 | 对应文件 |
|---|---|---|---|
| 题材母型 | `T-` | `T-A01` 契约婚姻 | 01 |
| 主体对象 | `S-` | `S-09` 财阀继承人 | 02 |
| 关系对象 | `R-` | `R-01` 契约婚姻关系 | 03 |
| 资源对象 | `O-` | `O-10` 股份 | 04 |
| 秘密对象 | `M-` | `M-13` 真实任务 | 04 |
| 场域对象 | `F-` | `F-01` 财阀家族 | 04 |
| 叙事行为 | `B-` | `B-A01` 主动搭话 | 05 |
| 行为链 | `C-` | `C-01` 假关系变真关系 | 06 |
| 情绪回报 | `P-` | `P-09` 被明确选择 | 07 |
| 单话钩子 | `H-` | `H-16` 弱者获得拒绝权 | 07 |
| 言语行为 | `VB-S` | `VB-S08` 告白 | 12 |
| 微动作 | `VB-M` | `VB-M12` 站到同一侧 | 12 |
| 风险条目 | `RISK-` | `RISK-03` 经济控制 | 14 |
| 篇幅模型 | `LEN-` | `LEN-S24` 24话季 | 15 |

### 冲突修正

原库中题材 `A01` 与行为 `A01` 会发生编码冲突。自v1.1起：

```text
题材 A01 → T-A01
行为 A01 → B-A01
```

短码只能在所属文件内部使用，跨文件链接、Dataview查询和自动生成必须使用规范ID。

## 二、对象五层模型

| 层级 | 定义 | 典型对象 |
|---|---|---|
| 主体对象 | 能主动行动、回应与拒绝的角色 | 继承人、回归者、记者 |
| 关系对象 | 把多个主体持续绑定的结构 | 契约、师徒、共犯、亲缘 |
| 资源对象 | 可被转移、分配、消耗或放弃的东西 | 钱、股份、技能、名额 |
| 秘密对象 | 由知情差和公开权产生力量的信息 | 血统、任务、旧案真凶 |
| 场域/规则对象 | 决定准入、惩罚与行为代价的环境 | 公司、皇宫、公会、平台算法 |

“阻碍对象”不是第六种对象类型，而是任一对象在当前目标中的功能角色。

## 三、通用对象状态机

```text
潜伏 latent
→ 被发现 discovered
→ 被命名 defined
→ 被主张 claimed
→ 被争议 contested
→ 被控制 controlled
→ 被转移 transferred / 被共享 shared
→ 被公开 exposed
→ 被损毁 destroyed / 被放弃 renounced
→ 留下后效 legacy
```

不是每个对象都要经过全部状态，但每条主线至少要发生三次可识别状态变化。

## 四、不同对象的状态规则

### 1. 资源对象

```text
未知归属 → 确认所有者 → 争夺 → 临时占有 → 转移/共享 → 消耗/冻结/放弃
```

必填字段：

```yaml
quantity_or_scope:
current_holder:
access_condition:
transfer_method:
depletion_rule:
```

### 2. 秘密对象

```text
只有一人知情 → 有人怀疑 → 获得证据 → 小范围共享 → 被要挟 → 公开 → 产生后效
```

必填字段：

```yaml
truth_holder:
knowers:
suspecters:
proof_object:
disclosure_owner:
exposure_cost:
```

### 3. 关系对象

```text
无许可 → 临时许可 → 条件性绑定 → 越界 → 反制 → 重订规则 → 自由状态下重新选择
```

必填字段：

```yaml
entry_condition:
shared_object:
power_asymmetry:
exit_cost:
boundary_rule:
renegotiation_event:
```

### 4. 场域对象

```text
场外 → 获得准入 → 被监控 → 获得席位 → 违反规则 → 受罚/夺权 → 改规则或离场
```

必填字段：

```yaml
entry_requirement:
authority_source:
visible_rules:
hidden_rules:
punishment:
exit_cost:
```

### 5. 主体对象

主体不是可被占有的财物。主体状态记录的是行动资格：

```text
被定义 → 获得发言权 → 获得拒绝权 → 获得配置资源权 → 承担后果 → 自主选择身份
```

禁止使用“男主拥有女主”“女主被赢得”作为对象状态。应记录谁获得了关系许可、公开权或决定权。


## 六、最小状态变化标准

一条有效剧情单元必须满足至少一项：

```text
资源持有者改变
知情者名单改变
关系许可改变
场域准入改变
主体拒绝权改变
公共评价改变
对象被放弃或损毁
```

若一场戏结束后上述全部不变，它可能仍有氛围价值，但不能冒充主要剧情推进。

## 七、机器可读字段规范

```yaml
canonical_id: T-A01
schema_version: hanman-1.1
status: draft / reviewed / validated / deprecated
object_refs:
  - R-01
  - O-10
behavior_refs:
  - B-C01
source_evidence:
  - work:
    episode:
    scene:
confidence: 0.0-1.0
last_reviewed: YYYY-MM-DD
```

## 八、迁移规则

1. 不强制改写旧表中的显示码，避免产生一整片毫无信息量的机械diff。
2. 新条目必须直接使用规范ID。
3. 旧条目首次被引用或采矿验证时，补充`canonical_id`。
4. 自动查询只读取规范ID，不使用裸`A01`、`C01`等短码。
5. 废弃条目保留ID并设置`status: deprecated`，禁止回收编号。
