# 问题卡模板｜Problem State v1

先检索现有 Q-ID 和问题卡，再决定更新、合并或新增。复制模板不代表已批准建立新问题。

```yaml
---
q_id: Q-DOMAIN-000
scope: global
domain:
status: OPEN
volume: 1
blocker: 1
priority_score: 1
linear_issue:
parent_goal:
problem_statement:
problem_depth: D1
known: []
unknown: []
tried: []
rejected: []
current_hypotheses: []
evidence: []
source_refs: []
current_version: 1.0
next_decision:
done_condition:
required_agent: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

## 字段约束

- `scope`: `global` 或具体项目名；项目卡留在项目目录。
- `problem_depth`: D1/D2/D3；不得与 Agent 能力等级 L1–L10 混淆。
- `known` 只记有来源事实；`unknown` 记缺口；`tried` 记已发生动作；`rejected` 记有理由的否决；无证据解释保留在 `current_hypotheses`。
- `evidence` / `source_refs` 必须可回到 Linear、真实文件、版本或可观察结果。
- `volume` 为问题范围 1–10；`blocker` 为对直接父目标的阻塞度 1–5；`priority_score = volume × blocker`。不得把体量写成难度。
- `current_version` 仅在有效结论、范围或状态变化时递增。
- DONE 只由证据满足 `done_condition` 后设置；候选与建议不能代替用户确认。

## Linear 执行回执

回执至少包括 `run_id`、读取来源、`changed_files`、`created_files`、验证、commit/远端证据、阻塞项和下一步。不得把 commit SHA 写成语义版本。
