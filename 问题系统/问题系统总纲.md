# 全局问题系统总纲

## 目标与边界

本系统承接跨聊天、跨项目的真实问题，保留可追溯来源、当前状态、父目标、执行回执和下一步。它与学术研究知识图谱 `AI问题解决Canvas/` 分开，也与《黎黎隆》项目问题树分开；项目卡只在确有关系时被链接，不复制正文或复用同一个 Q-ID。

唯一入口：[[问题系统.canvas]]。问题正文写入独立 Markdown；Canvas 用可点击文件节点显示目标、问题、状态与关系。

## 信息进入与审核

```text
Chat / 文件 / Linear
→ L1 提取事实、来源、冲突、不确定项
→ L2 分类与路由
→ L3 去重并判断新问题/既有问题/伪问题
→ L4 形成 Problem State v1
→ 更新或建立 Q Markdown 与 Canvas
→ Linear 调度执行
→ Codex 按 write_scope 修改并回写证据
→ Chat 审核语义结论与验收
```

L1–L4 是交接层；D1/D2/D3 表示问题树深度。二者不可混用。

## 人在环外运行模式

目标模式是**人在环外**：在明确授权、规则冻结、输入和写入范围完整时，系统自动完成信息搬运、去重、状态整理、问题登记、路由、执行、验证和回写，不逐步等待用户确认。Q-ID 入树也可按已授权规则自动处理；AI 不能把无证据假设升成正式问题。

人只处理异常或作者主权事项：新 Canon / 角色身份核心变化；candidate XN 升级为 XN_LOCK；规则冲突无法自动消解；低置信度或 AMBIGUOUS 达阈值；不可逆操作或覆盖冻结主参考；连续失败达到重试上限。此边界复用 674-282 中由 74 确认的升级规则。每条工作流必须声明适用的权限配置；不可逆发布仍须有对应授权。

超出权限配置、缺少来源/验收依据或无法判定时，停止该项并记录 `WAIT_USER` / `BLOCKED`；其余任务不因无异常而暂停。人工确认、用户偏好和 Canon 结论必须保留可追溯来源；工具成功和 AI 推断不能冒充它们。

## Q 卡规则

- 分配 ID 前搜索现有 Q；重复项更新原卡并保留原 ID。
- 正式卡按模板记录已知、未知、已尝试、已否决、假设、证据、版本、下一判断和 DONE 条件。
- 假设没有证据时留在 `current_hypotheses`，不升格成正式问题或 Canvas 节点。
- `volume` 衡量问题自身范围；`blocker` 衡量对父目标的阻塞程度；优先级分数为两者乘积。
- Canvas 只画证据支持的关系，边必须标明关系语义；Markdown 保存完整研究。
- 执行状态与语义结论分开记录。Linear 状态、文件 commit 和远端发布分别验证。
