# 云端主端—本地素材生图审图—结果同步说明

> 目标：GitHub 云端主端维护任务与主要决策；本地素材/生图代理从云端领任务，在本地生成、审核和整理图片。图片本体留在本机，素材代理只把本地审核结果回传云端。

## 职责与数据流

1. **云端主端（GitHub `main`）**维护当前任务、提示词、任务状态和主要决策，是本地查询任务时的默认来源。
2. **本地素材代理**先查云端任务，再查本地素材索引；素材缺失时交给本地生图代理，不凭旧的本地任务状态开工。
3. **本地生图与审图**只处理当前任务明确缺少的图片；本地素材代理负责审核、整理路径、维护本地索引和按需更新 Canvas。
4. **回传云端**只包含 `task_id / task_version / asset_id / 本地审核状态 / 结论摘要` 等验证文字，不包含图片、图片引用、哈希或本机绝对路径。
5. **4090 执行端**不是云端主端。本地图片不自动同步给 4090；只有 4090 收到独立的云端运行任务时，才按既有权限发送该任务所需的图片。

```text
GitHub main（任务 / 当前状态 / 主要决策）
        ↓ 本地开工前查询
本地素材代理 → 本地生图代理（缺图时）→ 本地审图、归档、更新 Canvas
        ↓ 只回传验证结果文字
GitHub 候选区 / 任务状态

独立路径：云端运行任务 → 4090 执行端 → 仅发送该任务所需图片
```

本地图片、图片 Canvas 引用和素材库始终留在本机。云端主端只收到本地审核结论，不会收到用于查看图片的附件。

## 任务读取与结果回传规则

- 每批开始前读取 `origin/main` 的最新任务与状态；一批执行中不自动切换任务版本。
- 若本地任务版本落后于云端版本，标记 `STALE_RESULT` 并重新核对，不把旧任务结果冒充为当前结果。
- 本地生成结果先登记为候选；本地保留图片、路径、SHA-256、生成来源与完整审核记录。
- 云端候选区只接收素材代理的验证结论、任务版本和必要说明，不直接覆盖云端 `main` 的正式状态。
- 不配置本地图片传输。4090 仅按独立云端运行任务发送其所需图片，不同步本地素材库。
- 素材代理文字回传器：[[../20_Agent系统/07_本地执行/回传本地审图结果]]。它只发布本地审核结果文字；首次真实结果发送前仍需有对应的本地审图结果 JSON。
