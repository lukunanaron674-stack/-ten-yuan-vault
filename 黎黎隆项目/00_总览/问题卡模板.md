# 问题卡模板｜Problem State v1

新问题先经 L1–L4 编译与审核，再决定新建或合并到既有 Q。L1–L4 是 Agent 交接层；`problem_depth` 的 D1/D2/D3 是问题树深度，两者不可混用。复制本模板时，先检查现有 Canvas、Q-ID 和来源，不能因模板而另建重复问题。

```yaml
---
q_id: "Q-DOMAIN-000"
scope: "lililong"
domain: ""
level: 1 # 兼容旧卡；问题树深度以 problem_depth 的 D1/D2/D3 为准
problem_depth: "D1"
parent: "G0 或现有父 Q-ID"
goal: "现有目标 ID"
parent_goal: "现有直接父目标或父问题"
volume: 1
impact_weight: 1
priority_score: 1
status: "OPEN"
linear_issue: ""
problem_statement: ""
known: []
unknown: []
tried: []
rejected: []
current_hypotheses: []
evidence: []
source_refs: []
current_version: "1.0"
next_decision: ""
done_condition: ""
required_agent: []
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
---
```

## 字段约束

- `q_id`：新问题才分配新 ID；重复问题更新原卡。已存在 Q-ID 不改名。
- `parent` / `goal`：只引用现存父 Q 或目标；D2/D3 子问题必须有真实父项，不可为了图上整齐虚构父子关系。
- `parent_goal`：写明此问题直接服务/阻塞的冻结目标 ID（G0–G9 或既有分目标）；D2/D3 的直接父问题另由 `parent` 写现存 Q-ID。不得把 G 目标编号与 D 深度混淆。
- `known`、`unknown`、`tried`、`rejected`、`current_hypotheses`：分别写事实、缺口、尝试、否决及尚待验证假设；不要混为一段摘要。
- `evidence` 与 `source_refs`：结论需能回到真实路径、Linear、版本或可观察结果。候选来源要标明候选状态。
- `current_version`：有效结论变化时递增；只改格式不递增。
- `next_decision`：写下一位执行者可采取的单一步骤。
- `done_condition`：写可观察、可判定的关闭条件；条件未被证据满足时不标 DONE。
- `required_agent`：列出现有专业代理；不在此创建新代理或扩展其权限。
- 正式 Q 才进入 Canvas；纯假设、重复项、范围外项留在现有审计段落，不分配新 Q-ID。
