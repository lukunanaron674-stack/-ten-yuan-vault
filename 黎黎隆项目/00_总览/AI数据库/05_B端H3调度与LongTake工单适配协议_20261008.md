本协议把现有 AUTO_DISPATCH、AGENT_IO、PROJECT_STATE、AG-07、AG-08、PRODUCTION_LOOP、RENDER_TASK、REVIEW、CONTINUITY 规则接入当前 Linear 正本。不修改 Canvas，不新建 Linear issue。

不为每阶段新建 Linear issue。

## 4｜PROJECT_STATE 对账门

PROJECT_STATE.json 继续作为机器执行状态源，但不是永远正确的现实事实。

当前仓库快照仍是 state_version=21，且 blocker/next_action 来自 2026-10-01。因此从 R3 起：

RECONCILE_BEFORE_RESUME = TRUE

286 想继续旧 production_loop，必须先核对：
- 282 当前角色 semantic/version
- 293 当前 asset/path/SHA/review state
- 289 当前真实视频 outputs
- Linear 当前 blocker/receipt
- 76 当前 goal
- 旧 job 是否 superseded/canceled/stale

输出 PROJECT_STATE_RECONCILE：
base_state_version / snapshot_status(CURRENT|STALE|PARTIAL) / stale_fields / confirmed_fields / superseded_jobs / current_blockers / proposed_next_action / evidence_refs。

只有相关字段已确认后，director 才能合并并 state_version+1。禁止因为旧 blocker 仍写在 JSON 中就自动重复执行旧任务。

## 5｜幂等与最小上下文

- same state_hash + same inputs → NO_OP
- 同一 blocker 未变化 → 不重复诊断/建任务
- 旧 base_state_version → STALE_RESULT
- 每 tick 默认最多 3 个 distilled brief + 2 个 raw source
- 跨 Agent 优先消费结构化 packet/result

## 6｜H3 两层硬门

Gate A：含角色任务必须 CHARACTER_H3_READY_PACKET.production_gate.status=READY_FOR_H3。

Gate B：进入 executor 前必须生成 H3_AGENT_PLAN_PACKET，并检查 source_type / intended_role / aspect_ratio / resize_mode / role_fit / controls_locked / variables_changed / planned_runs / stop_conditions。

只有 status=APPROVED_FOR_RENDER 且所有 input_preflight=PASS 才生成 RENDER_TASK。

禁止：
- HEADSHOT 越权承担 BODY/FULL_BODY
- 非等比 stretch
- 为了先跑让 H3 猜身体/服装
- ref 职责不匹配仍排队

## 7｜Render 状态

严格区分：
TASK_WRITTEN / QUEUED / RENDERING / SUCCESS / REVIEWED / LOCKED。

RENDERING 必须有 executor_receipt/runtime evidence；SUCCESS 必须有真实 output + SHA。GitHub commit、Linear comment、prompt 文本完成都不能冒充渲染成功。

TASK_ERROR → 286/AG-07 修任务，executor retry 最大2。
ENV_ERROR → BLOCKED。
执行级 retry 与视觉 retry 分开计数。

## 8｜10–11秒与 LongTake

当前最小稳定单元继续使用 10–11s / 16:9 / 可观察动作链。

LongTake 当前定义为：
多个 10–11s segment + 同 lineage_id + 上一段 closing_state + 下一段 opening_state + 角色/场景/方向/光照/动作端点连续。

正式生产默认 LongTake sequence；独立能力测试可 single segment。局部失败优先只重跑失败 segment。

## 9｜连续性

每个通过 segment 保存：
lineage_id / segment_id / previous_segment_id / opening_state / closing_state / character state / scene state / camera state / props / temporal state / continuity_check。

RETRY / REPLAN / BLOCKED 不推进 next segment。

## 10｜TECHNICAL_PASS 与 CANONICAL_PASS

AG-08 机器审核 PASS = TECHNICAL_PASS。
可用于测试轨继续、参数实验、failure family 学习；不能替代作者最终锁定。

674-173 USER PASS = CANONICAL_PASS。
用于正式版本锁定候选、正式 LongTake previous PASS、可信 closing_state、最终剪辑候选。

因此技术实验可人在环外继续，但不夺取 USER 作者权力。

## 11｜674-289

289 是唯一视频事实/版本仓，记录：
video_id=H3V-NNNN / source_task_id / shot_id / sequence_id / source_character_packet / source asset IDs+SHA / prompt_version / workflow/profile / seed / MP4 path+SHA / first-mid-end frames / machine review / USER review / failure_family / supersedes / created_at。

每个真实输出都获新的 H3V-NNNN；rerun/variation 不覆盖旧 video_id。
