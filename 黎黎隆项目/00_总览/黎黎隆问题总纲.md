## Problem State v1｜交给 L5/L6 前的当前状态

正式问题沿用原 Q-ID 和 `parent` / `goal`，并在同一张卡上维护冻结状态字段：`q_id`、`parent_goal`、`problem_statement`、`problem_depth`、`domain`、`status`、`known`、`unknown`、`tried`、`rejected`、`current_hypotheses`、`evidence`、`source_refs`、`current_version`、`next_decision`、`done_condition`、`required_agent`。

- 问题树深度统一写 D1 / D2 / D3；旧 `level` 保留兼容，不能与 Agent 能力层 L1–L4 混称。
- 事实、来源、未知、尝试、否决、假设分栏；候选不升格为 canonical，文件存在不等于审核通过。
- 子问题的 `parent` 必须指向现存父 Q-ID；`parent_goal` 记录其父目标。重复问题回写原 Q，不另开平行卡。
- 有效结论变化时递增 `current_version`；没有证据满足 `done_condition` 时不得改成 DONE。
- 当前三类真实样例：[[Q-CHAR-001.1_头部身份锚是否稳定继承]]、[[Q-ASSET-001_旧角色设定和新设定谁优先]]、[[Q-WORLD-001_候选世界观版本如何安全进入实验]]。后两类新卡分别保留原来源工单 674-53 / 674-52，不替换其他问题 ID。

## 头像问题系统 v1｜正式冻结规则（674-91）

### 1｜节点层级

- `G0` 为总目标，`G1/Gx` 为分目标；正式问题树使用 `Q`、`Q.x`、`Q.x.x`，最多三级（D1/D2/D3）。
- `level` 是问题树深度的兼容字段，不得与 Agent 能力层 L1–L4 混用。子问题的 `parent` 必须指向现存父节点。
- 已可直接设计实验时停止拆分；不为树形完整度补空节点。

### 2｜正式 Q 准入

只有同时满足以下条件才建立正式 Q：

- 有具体头像资产、记录或用户反馈证据；
- 对父目标或父问题有直接影响，因果链清楚且不把相关性冒充因果；
- 有可观察、可判定的 DONE 条件。

“可能”“感觉”“更好看”、类别清单以及把解决方案改写成问题，都不能单独成为正式 Q。

### 3｜结果分流

- **DONE**：真实问题满足预先写明的 DONE 条件，证据和关闭依据已回写原 Markdown；Canvas 同步状态。
- **OPEN / BLOCKED**：问题有证据成立，但缺少输入、样本、权限、人工确认或其他必要条件。必须记录 `blocked_reason` 和 `unblock_condition`；不得为提高完成率提前关闭。若当前只证明验证缺口，要写成证据缺口，不得宣称视觉失败。
- **REJECTED / UNVERIFIED_HYPOTHESIS**：无证据假设、纯审美偏好、伪因果、同义重复、已由其他 Q 覆盖、把方案写成问题。只留 Markdown 审计记录，不分配正式 Q-ID，不进 Canvas；如重复，写明 `duplicate_of`。

### 4｜volume 与 impact_weight

- `volume` 1–10：问题自身波及范围。
- `impact_weight` 1–10：问题对直接父节点的影响强度。
- 二者不得混用，不代表工时或百分比，兄弟节点不要求加总为 10。

### 5｜Canvas 固定字段

头像分支正式 Q 节点使用 text node，只显示：Q-ID、问题名、level、volume、impact_weight、parent、status、Markdown 内链。保留原 Canvas、节点 ID、位置和父子关系；不为伪问题创建节点。详细证据与研究内容留在 Markdown。

### 6｜Markdown 固定字段

- Frontmatter：`q_id`、`level`、`parent`、`goal`、`volume`、`impact_weight`、`status`、`linear_issue`。
- 正文至少包括：问题一句话、为何影响父问题、当前证据、因果链、DONE 条件、当前结论、下一步；如适用，再记录 `blocked_reason` / `unblock_condition` 或“否决假设 / 伪因果 / duplicate”。
- DONE 卡必须留关闭依据；状态和来源变化回写原 Q 卡，不以 Linear 取代问题本体。

### 7｜拆分停止

达到三级、已能直接设计实验、继续拆分不会改变解决动作、子问题只是父问题换说法、或证据不足以区分原因时停止。后两类转为待验证假设，不继续造节点。

### 8｜人工审核边界

角色是否为同一人、审美身份是否成立、正面/半侧是否保持同人、是否接受视觉差异，必须由用户最终确认。Agent 可整理证据和提出判定方法，不替用户做审美身份判断。图像存在或规则初检通过不等于人工通过。

### 9｜v1 验证案例

- **DONE**：[[Q-CHAR-001.1_头部身份锚是否稳定继承]]——S10/H06 特定错配经修正并由用户确认。
- **OPEN / BLOCKED**：[[Q-CHAR-001.4_H04正面半侧身份继承是否有充分证据]]——存在 H04 原头像、四宫格和报告，但缺少正面/半侧锚点对照结论；这证明验证缺口，不证明 H04 已错配。
- **REJECTED**：[[Q-CHAR-001.3_可发散范围是否进入任务输入]]——“可发散范围普遍导致头像漂移”缺少输入/失败图配对与因果证据，不分配正式 Q、不进 Canvas。

### 10｜v1 代理边界

仅处理头像身份问题证据、因果树、原 Canvas/Markdown、验证步骤和结果；不自行生成或替换图片，不把候选提升为正式资产，不扩到全身、场景、剧情、分镜、H3 或其他生产流程。
