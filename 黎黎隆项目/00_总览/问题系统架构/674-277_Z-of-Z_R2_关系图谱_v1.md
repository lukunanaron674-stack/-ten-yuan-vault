# 1｜7 个 Z1 的父关系判定

## Z1-A｜目标 / 问题结构治理
体量：72/100
与 Z0：REQUIRED_COMPONENT
必要性：HIGH

原因：
- 没有目标/问题层级，后续 XN、NX、PATH、权力都失去挂载对象。
- 是整个问题系统的“骨架”。

父Z贡献性质：
- 必要组成
- 不直接执行现实任务，但决定“问题是什么 / 属于哪个 Z / 是否继续拆”

## Z1-B｜XN规则获取与校准
体量：74/100
与 Z0：REQUIRED_COMPONENT
必要性：HIGH

原因：
- 问题系统最终不是只记录问题，而是要得到可复用规则。
- XN必须有来源、覆盖度、可靠度、有效性、校准和版本状态。

## Z1-C｜NX / 偏好补充
体量：63/100
与 Z0：REQUIRED_COMPONENT
必要性：HIGH，但作用方式与 B 不同

原因：
- 74大量判断不能一开始完全XN化。
- 没有 NX 保留区，系统会把模糊偏好错误形式化，产生假规则。

关系：
- SUPPORTS Z1-B
- 与 Z1-B 是“补充 / 结晶”关系，不是下级隶属。

## Z1-D｜Agent主权与责任治理
体量：70/100
与 Z0：REQUIRED_COMPONENT
必要性：HIGH

原因：
- 系统必须区分谁判断、谁执行、谁审核、谁冻结、谁上报。
- 否则“有能力”会被误当成“有权力”。

关系：
- DEPENDS_ON Z1-A：先知道当前 Z / Problem，才能分权。
- SUPPORTS Z1-E：权力明确后 PATH 才能安全执行。

## Z1-E｜PATH现实执行与跨端落实
体量：78/100
与 Z0：REQUIRED_COMPONENT
必要性：CRITICAL

原因：
- 没有 PATH，问题系统只停在“知道怎么做”。
- 这是把规则转成现实 Z 的桥。

关系：
- DEPENDS_ON Z1-B：先有规则/目标要求，才知道需要什么执行桥。
- DEPENDS_ON Z1-D：先有执行权限，才允许现实动作。
- DEPENDS_ON Z1-F：需要状态和证据回传。

## Z1-F｜状态 / 证据 / 版本 / 回传治理
体量：73/100
与 Z0：REQUIRED_COMPONENT
必要性：CRITICAL

原因：
- 无状态就无法知道当前走到哪。
- 无证据就无法校准。
- 无版本就无法复现。
- 无回传就无法形成闭环。

关系：
- SUPPORTS Z1-B：提供验证证据。
- SUPPORTS Z1-C：提供偏好素材证据。
- SUPPORTS Z1-E：提供输入输出和回传。
- SUPPORTS Z1-G：提供恢复点和历史状态。

## Z1-G｜长期运行 / 恢复 / 调度
体量：65/100
与 Z0：REQUIRED_COMPONENT（但可后置）
必要性：MEDIUM-HIGH

原因：
- 对“单次问题解决”不是第一前置。
- 对“持续运行的问题系统”是必要组成。
- 它决定系统能不能长期自动跑，而不是每次靠74手动续命。

关系：
- DEPENDS_ON Z1-A / D / E / F
- SUPPORTS 整个 Z0 的持续性

# 3｜冲突关系

当前确认至少有三组结构性张力。

## 冲突 C1｜Z1-D 主权治理 ↔ Z1-E 执行效率
- 越严格的人类批准，越安全，但效率下降。
- 越高AI自主，效率上升，但需要更高校准与可逆性。

结论：
这不是“选一个”，而是需要动态授权。
状态：CONFLICTS_WITH / TENSION

## 冲突 C2｜Z1-B XN约束 ↔ Z1-C NX开放性
- XN越多，系统越稳定，但可能过早压缩NX。
- NX保留越多，系统越灵活，但机器可执行性降低。

结论：
需要“候选XN”中间态，不允许NX直接强制转正式XN。
状态：CONFLICTS_WITH / BALANCED_BY_CANDIDATE_STATE

## 冲突 C3｜Z1-A 层级治理 ↔ Z1-G 长期自动扩展
- 自动发现/扩展能力越强，越容易产生过多子Z/问题。
- 层级治理越严格，越可能限制探索。

结论：
用拆分STOP条件 + spawn门槛平衡。
状态：CONFLICTS_WITH / GOVERNED_EXPANSION

# 4｜阻塞关系

当前不把任何 Z1 永久标为 BLOCKS 另一个 Z1。

BLOCKS 只在“当前状态”动态出现。

例如：
- Z1-F 状态不可读 → BLOCKS Z1-E 当前执行
- Z1-D 权限未授权 → BLOCKS Z1-E 当前动作
- Z1-B 关键XN缺失 → BLOCKS 某个 Z2/Z3，而不必阻塞整个 Z0
- Z1-A 父目标不清楚 → BLOCKS 对应分支继续拆解

规则：
> **BLOCKS 是状态关系，不是永久结构关系。**

# 5｜必要性分级

- Z1-E PATH现实执行
- Z1-F 状态/证据/版本/回传

## HIGH
缺失会让系统失去治理能力：
- Z1-A 目标/问题结构
- Z1-B XN规则获取与校准
- Z1-C NX/偏好补充

## MEDIUM-HIGH
单次可暂时没有，但长期系统必须有：
- Z1-G 长期运行/恢复/调度
