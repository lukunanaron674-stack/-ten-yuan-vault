# Q-CHAR-001｜头像跨来源使用时如何保持面部身份一致

## 问题一句话
不同头像来源或版本进入同一角色资产链时，如何避免面部身份错配并验证一致？

## 父目标与因果关系
父目标：G2-AV｜角色头像身份稳定且可验证。头像是角色面部识别的直接依据；来源引用错配会把另一个角色的五官带入本角色头像资产，阻断该目标。Canvas 关系：本节点影响 G2-AV。

## 体量与影响分量
- volume：6/10（问题波及不同来源/版本的角色头像使用。）
- impact_weight：9/10（对直接父目标头像身份稳定的影响强度；不是工作量或百分比。）

## 当前证据
1. **已确认的身份错配案例**：S10 暂用登记明确记录其四宫格暂代自 H06，且 H06 ≠ S10、面部特征不一致；登记同时说明这只是暂代，不解决身份一致性。见 [[黎黎隆项目/03_角色/角色库/06_assets/S10/00_S10四宫格暂用登记_STAGING|S10 暂用登记]]。这是一个有来源记录的头像问题，不推论为全库普遍故障。
2. **版本冲突控制案例**：CH-013 正本记载用户当前头像原稿为依据，旧 H3 角色描述降为历史；现行处理已清楚。见 [[黎黎隆项目/03_角色/角色库/01_角色卡/CH-013_岑烬|CH-013 正式角色卡]]。与既有 [[Q-ASSET-001_旧角色设定和新设定谁优先]] 重叠，不另建重复 Q。
3. **反例/边界证据**：H04/H06/H09 四宫格报告记载同人视觉初检通过；这反驳“脸锚普遍失效”的笼统说法，但不等于正面/半侧面专项测试或用户终审。见 [[黎黎隆项目/03_角色/角色库/青桶头像四宫格候选_20260929/青桶四宫格执行报告_20260929|青桶四宫格执行报告]]。

## DONE 条件
对所有被标为当前头像来源的资产，来源角色 ID 与目标角色 ID 一致；临时代位明确标为非身份一致资产；专属头像/四宫格通过面部锚点比对并由用户确认。满足条件时将对应 Q 设为 DONE，并记录验收证据；目前整体问题保持 OPEN。

## 下一步 / 当前子问题
当前正式子问题：[[Q-CHAR-001.1_头部身份锚是否稳定继承]]（DONE，S10/H06 错配已处理）与 [[Q-CHAR-001.4_H04正面半侧身份继承是否有充分证据]]（DONE，用户最终确认 TL/TR/BL/BR 四格均通过，见 674-97/98/110）。

## 三轮验证记录（674-85）

### 第1轮｜结构检查
- Canvas 使用 G0 → G2 → G2-AV → Q-CHAR-001 的层级；Q 卡和 Canvas 节点字段分工清楚，头像问题节点链接到本 Markdown。
- volume 表示自身规模，impact_weight 表示对直接父节点影响；两者分开。
- 发现 MVP-02 中“身体比例锚 / 比例样张”和全身景别内容越出本工单头像边界；这些旧拆分不再作为正式 Q，也不保留在头像树。

### 第2轮｜真实案例结构验证
- S10/H06 面部不一致：登记卡明确身份、来源与差异，能形成直接可执行的头像核验；保留为 Q-CHAR-001.1。
- CH-013 用户当前头像与旧实验描述：正本已写明来源优先级和旧版状态，且与 Q-ASSET-001 重叠；作为已处理控制案例，不复制为头像 Q。
- H04/H06/H09：执行报告记录四宫格同人视觉初检通过，但证据不覆盖正面/半侧面专项，不能据此建立“跨角度脸型漂移”问题。

### 否决假设 / 伪因果
- “头部身份锚普遍不能继承”：**未证实**。现有规范有头像脸锚要求；没有通用失败样本。保留在 [[Q-CHAR-001.1_头部身份锚是否稳定继承]] 的具体 S10 案例内，不推广成通用失败。
- “可发散范围普遍导致头像漂移”：**未证实**。目前没有附带任务输入和失败头像的配对证据，旧卡已降为假设记录，未建 Canvas Q 节点。
- 比例/体型相关旧拆分：**本工单范围之外**，不纳入头像代理树。
- CH-013 版本冲突不重复登记，归原 Q-ASSET-001 跟踪。
- 脸型、五官比例、年龄感、风格统一、线条块面、正面/半侧面差异：目前没有找到足以确认失败的具体头像样本；类别清单不自动转为 Q。

## MVP-03 第二验证（674-90）｜BLOCKED 与伪问题分流

- **accepted_problem / created_or_reused_Q**：新建正式子问题 [[Q-CHAR-001.4_H04正面半侧身份继承是否有充分证据]]，状态 OPEN / BLOCKED，volume 2/10，impact_weight 4/10。H04 原头像、四宫格候选和执行报告证明具体验证缺口；报告记录整版初检/候选选择，但没有逐格正面/半侧身份锚对照。它说明验证覆盖不足，不证明 H04 面部已失败。
- **blocked_reason**：缺少可追溯的原头像与正面/半侧画格对照结论；整版视觉选择不能替代该专项核验。
- **unblock_condition**：对原头像与对应格形成并排身份锚核对记录，并由用户确认同一角色；发现差异时记录具体格位及特征。
- **rejected_candidate**：[[Q-CHAR-001.3_可发散范围是否进入任务输入]] 所记录的“可发散范围普遍导致头像漂移”。
- **reject_reason**：没有生成输入与失败输出的配对样本，也没有可重复因果证据；该说法只是无证据假设，保留为 UNVERIFIED_HYPOTHESIS，不建 Canvas 节点。
- **duplicate_of**：none（按无证据假设否决，不是重复 Q）。
- 决策边界：一项留下，因为具体 H04 资产与报告证明存在可定位的身份验证缺口；一项不进树，因为它目前只有原因猜测，没有对应的失败头像证据。

### 第3轮｜头像问题代理规则 v1（本轮冻结）
- **Canvas 字段**：Q-ID、问题名、层级、volume、impact_weight、直接父级、状态；Canvas 只放管理字段及到卡片的链接。
- **Markdown 字段**：Q-ID/问题名/层级/父级与目标、volume、impact_weight、状态、因果关系、当前证据、可判定 DONE 条件、下一步/子问题、Linear ID。
- **拆分停止**：最多 L3；子问题必须由父问题直接导致并有证据。已能直接设计实验时停拆；无证据区分原因时保留待验证假设；同义重复、方案句或其他范围一律不建 Q。
- **问题关闭**：先写 DONE 条件；只有证据满足条件才设 DONE。涉及审美/身份判断时须有人类确认，生成存在不等于通过。
- **伪问题处理**：在原问题卡“否决假设 / 伪因果”记录证据与否决理由；无证据时标假设，不分配正式 Q-ID/Canvas 节点；范围外问题只标出范围，不展开。
- **头像 Problem Agent 最小职责**：检查头像问题证据、确认父子因果、维护原 Canvas/Markdown、提出可判定验证步骤并记录结果；不得据类别清单造问题，不自行生成/替换图，不把候选升为正本，不扩至全身、场景、剧情、分镜、H3或其他流程。
