# H3 动画四技能执行链 v1.0

> 目的：把已学习的四项视频提示词方法做成 B 端四道连续工作工序，而不是让四个步骤分别写互相矛盾的 prompt。现阶段这是 **B端可执行文本编写技能**，不是已安装在4090上的独立软件或四个具备后台执行权限的AI agent。
> 范围：每小时一名角色、一张13图池场景、单人连续叙事、两段各15秒；每段同一最终prompt请求两次独立生成。所有规则为 B端文本侧要求；是否真渲染/是否支持seed由Work核实。

## 输入契约

必须先读取实际 main 分支的 `assets/character_pool_index.json`、`assets/scene_pool_13_index.json`、所选角色身份卡、`rules/video_tenyuan_prompt_schema_v1.2.md`，再构造：
`character_id`、`source_image(s)`与视图作用、`scene_id`及`source_path/github_blob_sha`、人物单实例限制、`changed_variable`、动态链首尾状态。
没有图时角色和场景原图由 Work 查找绑定；B端不停止写文本，但不能标记已验证。

## Skill 02：I2V 运动编译器（先写动作）

- 对照角色原图与场景语义，给出唯一主体和 **1 个主动作链**：开始姿态/触发事件/具体肢体运动/与现有场景或道具接触/可观察结果。
- 动作必须可以看见，例如“机械爪足抓住已有地面边缘，长尾向相反方向连续摆动，使身体侧转”，不写“变得机灵”。
- 动作限制须依 `reference_view_type`：仅全身身份图时降低动作幅度；半身动态参考用于脸和上半身，全身只锁身形。
- 不能从语义描述臆造场景里有门、绳、吊环、另一人。未实际看到场景结构，就改写为可见的地形/光影/方向变化，不假称已经核实细节。
- 输出 `motion_plan`（首帧→核心动作→结果）和 `motion_visibility_check`。

## Skill 03：四要素场面编排器

- 把上一步可见动作写进 subject/environment/action/style-and-atmosphere 四个段；身份主参考优先于场景中的人形元素。
- 明确机位、镜头移动和必要的切镜，不强迫视频包含大量镜头；每段至多一个主镜头运动，确有叙事必要才切镜。
- 画风来自角色原稿与项目色卡；环境仅影响照明/氛围，不改角色身份与色彩。每镜头的叙事责任写明：让观众看见哪一个变量变化。
- 输出 `composition_plan`、`shot_grammar` 与跨段空间连续性说明。

## Skill 04：清晰度与矛盾扫描器

- 从单句“谁在何处，通过什么动作使什么状态变化”校准可读性。写不出单句就减少事件数量。
- 只保留可执行内容，删去重复身份叙述、无画面证据的抽象情绪词、互相冲突的指令：例如“固定镜头同时急速环绕”“无声但爆发音乐”“不出现第二人却安排另一个角色接物”。
- 音频保留 `ambient_soundscape`（环境/动作声）与 `emotional_sound_cue`（非歌词情绪性声响/简短音乐质地）；应标注动作触发点，不用音乐卡点剪辑、MV 段落或暗示第二人物声音。
- 输出 `concise_prompt`、`audio_design`、`contradiction_report`；发现硬冲突必须改写，再进入下阶段。

## Skill 05：负面约束与工作台双抽检查器

- 负面约束只列真正相关故障：same-character duplicate、second person、split-screen/quadrant output、face/costume drift、extra limbs、invented props、scene mismatch、text/watermark；不得把正常自然阴影/声响一概消灭。
- 每一段最终**完全相同的提示词**由 Work 独立抽样两次 `run_A` / `run_B`，角色图、场景图、参数保持一致；只允许随机种子不同。若接口不支持显式 seed，`seed=null` 并分别记录真实生成task_id，绝不捏造两个整数 seed。
- 一轮两段，各两抽：最多4条视频尝试，不是4个不同描述词。B段续接A段选择后的末帧时，Work须记录A段选用哪个run及B段续接条件，不能拿未选用的A段假装连续。
- Work 验证图像身份后才真正出片；Work验收：人数=1、角色同一性、动作和环境关系、音频氛围、连续性，记失败原因，必要时调整**下轮**单一变量；B端无实际回写时这些维度均为 `unverified_by_b_end`。
- 输出 `negative_constraints`、`sampling_plan`、`WORK_VALIDATION.md` 的双抽表与 `results/version_history/<task_id>_DIFF.md` 的方法版本差异。

## 简明执行顺序

原图/场景索引与身份锁 → 02动作编译 → 03四要素/镜头 → 04明确动作与音频/冲突扫描 → 05负面约束/双抽/Work验证交接 → 提交GitHub。

四道工序只加工 **同一份任务**；不得自行触发云端H3或把“计划两抽”写成“已经抽了两遍”。
