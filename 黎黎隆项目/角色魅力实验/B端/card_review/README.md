# B 端卡片首帧审核网页 v1.0

**状态：已提交静态网页；尚未核实 GitHub Pages 正式发布。** 打开本目录 `index.html` 即可在浏览器审核。若浏览器不直接执行 GitHub 的 HTML 预览，请下载该文件后在本机打开；或由 Codex 将本目录部署到已配置的静态站点。不要在没有验证的情况下声称已有可访问的线上 Pages URL。

## 当前文件

- `index.html`：卡号/首帧卡片列表，支持搜索、按是否有首帧筛选、展开查看 run_A/run_B 的首中尾真实帧、审核判定与文字备注、导出审核 JSON。
- `cards.json`：只读卡片数据目录；两条**历史任务** R35/R37 的真实首帧由仓库 `results/frames/<task_id>/run_A_key_head.jpg` 引用；ZX 新实验 CH 卡仍待正式分配、待生成首帧。禁止把旧任务临时展示 ID 当成 CH 永久卡号。
- 网页通过仓库 raw 地址读取 `cards.json`；读取失败使用页面内置的已核实历史样例。图片加载失败应显示异常，不自动替换成其他角色图。

## 下一轮接入卡系统的强制步骤

1. Codex 查重后，创建唯一权威 `CARD_INDEX.json`、正式卡号及卡片版本；不要直接假定 CH-000001 已注册。B1/B2/B3/4090/B4 各阶段携带同一 `card_id`、`round_id`、`task_id`。
2. 每个运行真正生成视频后，云端从**该运行的真实视频**提取 `run_A_key_head.jpg`（或已约定的十元变化节点抽帧），将图传入可由网页读取的地址；在 cards.json 为相应卡记录帧文件路径、run、原始视频 task/output ID、帧号、时间点、宽高、SHA-256。视频本体不用上传至 GitHub。
3. 首帧必须对应**实际这一张卡、这一轮和这一抽样**，不允许拿角色参考图、另一轮图片、H3 四宫格或占位图冒充。
4. `cover.path` 指向已验证存在的真实首帧；未生成前为 null，页面显式写“待回传”。帧级时间分镜的变化节点证据应另存在该卡的动态实验记录中，不能把“有首帧”当成“动态链已验证”。
5. 审核者在网页点“通过 / 需要修改 / 证据不足”并填写意见，再使用“导出审核 JSON”；本页面纯静态，不持有 GitHub 写权限、不直接写回 GitHub。由已授权的 Codex/4090 读取导出 JSON 并写回相应卡，附 commit/SHA。
6. 首帧卡片封面只是用于识别与快速阅读；十元动作时间先后需由变化节点帧及实际视频验证，**首帧不代替动态链审核**。
7. 保持动画 16:9 横屏；角色参考素材可为 9:16。对历史 R35/R37 不事后更改实际尺寸或旧结论。
8. 更新 cards.json 时保留旧版本变更记录、旧轮次和历史任务引用；字段 `card_id`、`card_version`、`rule_version`、`round_id` 各自独立。唯一分配由索引器完成，静态网页不分配卡号。

## 发布状态

GitHub 上的 HTML 文件链接只展示源文件，不保证直接呈现网页；本版本提供可本机打开的静态 HTML 和后续部署材料。需要真正公网网址时，可由仓库管理员按组织的权限与私密要求为该目录部署 GitHub Pages 或其他静态服务，并先实测网址后发布给审核者。注意该仓库为 public，不应将内部保密素材或访问 token 写进此页面。
