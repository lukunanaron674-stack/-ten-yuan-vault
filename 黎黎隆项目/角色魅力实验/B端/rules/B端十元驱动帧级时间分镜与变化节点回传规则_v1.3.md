# B端十元驱动帧级时间分镜与变化节点回传规则 v1.3

> 本文为 B 端新轮次的时间分镜及反馈增补规范。与 v1.0/v1.2 的固定 0–2、2–4 秒分段、固定首中尾抽帧、全程必须固定景别冲突时，本文件优先；不自动改写已执行历史轮次。保留单角色、单场景、10–11 秒、同词双抽、输入身份/风格稳定、audio 三字段。视频输出 16:9 横构图；9:16 仅可作为角色参考图尺寸要求，绝不能以 9:16 否决实际 16:9 视频。

## 1. 核心顺序

B2 先确定十元角色基线、主次、当前体量、关系操作（生/克/补/共存，注明作用方向和对象）、事件的起点→触发→变化→结果以及每环可反证的可见动作；再决定这一环需要多少时间、景别、视线方向、机位/镜头运动/光影如何服务于事件；B3 把时间线编译为实际 H3 工作流帧率上的整数帧区间，并生成最终纯视觉/动作/镜头/声音提示词；4090 按实际视频帧率和实际输出总帧数，在指定十元变化节点前后抓取关键帧；B4 比较预定与实际变化，并将反馈回写 B2。不得先按 2 秒均分视频后填十元词。

十元是**镜头决策依据**，不是每变一次就强制切镜。景别、机位、构图、光影、镜头速度和焦点可受动态关系驱动，但必须优先确保角色身份、场景和动作连续。每个节点明确 `camera_change: none | reframe | motivated_cut | movement`、前后景别、决定依据和风险；复杂变焦、多次跳切不能因套理论而强加给生成模型。

## 2. 帧级时间线与精度

4090 回写实际 `fps_num/fps_den`、`total_frames`、`duration_seconds`、`width/height`、`workflow_id`；无法确认 fps 时不允许伪称固定 24/30 fps。按实际帧率把相邻十元状态的边界定为整数 `start_frame`（含）/`end_frame_exclusive`（不含）；相邻段首尾无空档、无重叠，第一段从 0 开始，最后一段到 `total_frames` 结束。时间使用实际 rational fps 换算：`time_seconds = frame_index * fps_den / fps_num`。B2 可先写相对时间或目标时间，B3 在确认工作流后编译整数帧；所有节点以帧号为准，秒数只是显示值。不同实际帧率/时长的 run_A/run_B 分别换算，不能借用另一段的固定帧号。

每环至少填写：`node_id`、`state_before`、`relation`（主/次、方向、对象、体量变化，及 hypothesis/known 状态）、`state_after`、`observable_event`、`precondition`、`start_frame`、`transition_frame`、`end_frame_exclusive`、`shot_scale_before/after`、`camera_change`、`camera_reason`、`lighting_or_focus_change`、`evidence_sampling`。没有可区分画面证据的关系不得硬贴 PASS 标签。

## 3. 变化节点的回传，不是固定六张

4090 照常生成完整视频；**不要求上传完整视频**。4090 依据任务中的 `evidence_sampling` 从其本地视频抽帧。每个关键十元变化节点优先抓变化前状态（`transition_frame-1`）、首次发生变化（`transition_frame`）、变化后清楚可辨的稳定或峰值帧（`peak_or_settled_frame`）。相邻节点若同帧可去重；首尾锚点可保留，但不得以首中尾三帧代替节点证据。关键事件数决定回传帧数，双抽不是固定总数六张。每帧回写 run、node_id、requested_frame、actual_frame、timestamp、stage(pre/onset/peak/post)、素材路径或可读取地址、SHA-256、宽高；实际节点相对预定有偏移时，另记 `observed_transition_frame` 和 `offset_frames`，没有判读能力则记 unknown，不得把计划帧号冒充实测发生帧号。

抽帧只能证明离散时点出现了什么，不能单独证明两帧之间没有变形或精确先后。需要判定严格动作顺序、镜头运动连续性时，B4 标 `NEEDS_TEMPORAL_REVIEW`；可让4090对关键区间追加逐帧/密集抽帧的客观记录，或在可访问视频时再审，不因缺失视频就声称已完成时序验证。

## 4. 示例：10 秒 / 24 fps（纯示例，不是 H3 实际 fps）

总 240 帧，范围 f0…f239，时间线必须连续。这是“鼠耳少女听见声响并做出选择”的示例假设，十元关系是否成立仍待证据检验：

| 帧区间（含首不含尾） | 时间 | 内部十元/事件 | 镜头决策及理由 | 预设变化节点 |
|---|---|---|---|---|
| [0,36) | 0.00–1.50s | N8：稳定站定，保留原有包与安全距离 | 中景固定，先建立完整人物与空间 | f0 初态 |
| [36,72) | 1.50–3.00s | 外部轻响；稳定状态开始受到刺激 | 保持机位，画外声音建立方向，不强行切镜 | f36 刺激起点 |
| [72,108) | 3.00–4.50s | Z4 启动：鼠耳先转向 | 同镜头允许注意力/构图强调耳部；需保留面部、包和空间锚点 | f72 耳部变化起点 |
| [108,156) | 4.50–6.50s | NZ7 补 N（待验）：眼/头跟随但脚仍稳定 | 可选择轻微取景强化眼耳关系；模型不稳时仍固定中景 | f108 眼头变化起点 |
| [156,204) | 6.50–8.50s | Z5 主动小选择（待验）：按稳身侧既有包 | 回到人物与手部同框中景，须看见因果而非只看脸 | f156 主动动作起点 |
| [204,240) | 8.50–10.00s | N 回稳：动作停住但注意方向已改变 | 维持空间/角色连续，保留结果对照 | f204 终态开始；f239 终帧 |

示例节点 f72 的证据帧可选 f71（前）、f72（起）、f95（可辨变化后），并按实际事件调整。f108 等每个节点独立列取样计划；上述帧号仅示意，不可直接挪用到其它帧率或时长。镜头变化须能帮助区分“关系导致动作”与“剪辑制造动作错觉”。

## 5. B2 → B3 → 4090 → B4 契约

B2 提交 `dynamic_chain_nodes[]`（十元主次、双方、关系方向、变化前后体量、可观察事件、因果预期和反例）；`shot_intent_per_node[]`（景别、构图/光线/焦点/镜头运动的理由）；`target_duration`；`validation_question`。B3 输出 `frame_timeline[]`、`requested_sampling_frames[]`、`final_h3_prompt` 及 prompt hash，确保最终 H3 prompt 只写可执行的动作/场景/镜头/光影/音频描述，不泄漏十元内部标号；画幅 16:9。4090 必须绑定真实角色与场景素材、记录 SHA、实际 fps/帧数、run_A/B seed/task/output、抽帧证据和异常，不需上传视频。B4 为每个节点填：`planned_frame`、`observed_frame_or_unknown`、`visible_before`、`visible_after`、`shot_match`、`event_match`、`relation_verdict: SUPPORTED | CONTRADICTED | AMBIGUOUS | NEEDS_TEMPORAL_REVIEW`、`failure_family: binding | prompt | timing | camera | render | hypothesis | unknown`。B4 只能将已观察事实和本轮可检验操作假设判为支持/冲突，不得据单轮结果证明或推翻普遍十元规律。

若失败原因是时间点错位、镜头遮住动作或输入/执行漂移，先修 B3/4090；只有排除这些后，才将相关局部假设退回 B2 重做对照实验。固定实际视频输出的 16:9 横屏要求，绝不再把正常横屏误判为失败。

## 6. 生效与未完成事项

本规范作为**新一轮研究/执行规则**写入仓库。它不是运行中的云端程序修改，旧 v1.2 文件和已排队任务不会自动改变；Work/4090 与 B1/B2/B3/B4 调度端需要显式加载本文件、升级反馈 JSON 字段并做实际端到端验收，才能宣称云端已按节点抽帧。
