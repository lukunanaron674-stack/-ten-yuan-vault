## 每小时输出：先感受，后十元和动作

新轮次**首先读取本页顶部总规**，并沿用 `rules/video_tenyuan_prompt_schema_v1.3.md`、`skills/H3动画四技能执行链_v1.0.md`、`rules/B端_版本号与轮次差异记录_v1.2.md` 和 `assets/character_refs/B端_Work验证交接与单角色叙事规范_v1.1.md` 中不冲突的技术约束。

1. `viewer_impression_hypothesis`：用日常人际语言写初见感受、可能触发变化的可见时刻、最终感受、反例和替代解读；区分角色内部感受与观众对角色的感受。不得用十元术语代替观众表达。
2. `ten_yuan_explanation`：十元主/次、体量、阶段方向及生克补假设，解释可能的感受变化，必须保留证据和证伪条件，不预设观众必然按同一方式解读。
3. `tasks/inbox/<task_id>.json`：真实素材 ID/路径及状态、参考图 Picture 映射、感受假设、动态链、可观察动作、变化节点、镜头语法、音频设计与交接状态。
4. `prompts/generated/<task_id>_H3.md`：把感受目标转成**可观察行为**的单人连续事件，标明镜头起始→变化→结束；抽象十元词仅留在内部结构字段。使用当前10–11秒、16:9、同词双抽规则。
5. `tasks/inbox/<task_id>_WORK_VALIDATION.md`：供 Work 校验真实原图、角色身份、场景几何、Picture 映射、动作连续性和成片回传的验证纸。
6. `results/version_history/<task_id>_DIFF.md` 和 `INDEX.md` 记录真实相邻轮次变化。实际生成后分层写技术审核与感受盲审：`expected_impression` / `observed_feedback` / `technical_validation` / `interpretation`；没有真实输出或观众反馈时保留 pending，不造结果。

新轮次完成以本轮规定的真实文件成功提交 GitHub `main` 为准；提交失败如实记录，不写虚构 commit。网页 B端提交任务文本与索引，云端负责拿图执行；不要求网页端每小时重复搬图。

## 单角色叙事：不做 MV

每条任务只选一个角色 ID 为唯一出镜人物；不同小时可以更换主角，但**同一条视频只出现所选这一名角色的一个实体**。禁止其他演员、同屏分身/克隆/画中画、镜面或水面多出第二个完整人物；角色卡的不同视图都属于同一人物，不可生成多人。可以切镜、转身、出画再入画，但跨镜头身份及动作必须连续。

保持起点→阻碍→角色行动→关系改变→结果这一可观察叙事骨架，但每轮先写「观众最初怎么看此人→哪个动作可能让看法变化→看完如何看此人」。场景和物件承担外部关系，不引入第二人物。不恢复澈 MV 风格基准、音乐卡点蒙太奇或角色轮播；声音只服务场景事件、氛围和情绪。
