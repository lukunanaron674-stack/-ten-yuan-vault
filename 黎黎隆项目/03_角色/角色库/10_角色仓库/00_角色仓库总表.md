# 角色仓库总表

> 本页是角色代理的仓库入口与字段目录。Canvas 负责结构，GitHub/Obsidian 中每个角色的 Markdown 是文字正本，674-154 维护图像 Asset Index/Review Manifest，Linear 负责任务和回传。
> 角色图片以 canonical asset/path/SHA 引用，不在本目录重复复制。候选视觉 ID（H/N/S/NPC）不等于正式角色主 ID（LLL-CHAR-###）。

## 角色记录字段

每个角色记录要能回到本仓库对应 Markdown，并逐项核对：

| 字段 | 含义 | 空值规则 |
|---|---|---|
| visual_id / character_id | 候选视觉编号或正式角色 ID | 未认领正式身份时保留 visual_id，不虚构 character_id |
| canonical_name / aliases | 正式名与别名 | 未确认名称标 STAGING |
| ten_yuan_primary | 主十元 | 未有证据时 UNKNOWN |
| ten_yuan_secondary | 次十元 | 可留空；不得为凑主次强加第二元 |
| ten_yuan_evidence | 文字/行为/事件依据与置信度 | 头像剪影不能证明十元 |
| region | 关联区域 ID/名称 | 未确认时 UNKNOWN |
| organization | 关联组织 ID/名称 | 未确认时 UNKNOWN |
| home_scene | 关联场景 ID/名称 | 未确认时 UNKNOWN |
| role_card_path | 对应角色文字正本路径 | 指向已有正本，不重复造身份 |
| asset_ids / source_issue | 头像、四宫格、参考图的资产索引与来源 | 以 674-154 为准 |
| status | L1/L2/L3 与角色卡状态 | 用 UNKNOWN / STAGING / PASS 等明确表达 |

## 当前目录

- `base/`：现有 H/N/S/NPC 候选记录，逐编号 Markdown；各记录回链头像源与候选文字设定。
- `图库/图库索引.md`：头像/角色图 canonical 路径与 SHA 登记；图片资产继续以 674-154 的 Asset Index 为准。
- `../01_角色卡/`：既有 CH-001–CH-014 正式角色卡正本。当前角色仓库索引通过 `role_card_path` 引用，不移动、不复制，避免打断现有 Canvas/Wikilinks。
- `../候选角色/`：候选文字设定 STAGING 来源；通过 `role_card_path` 或相关字段对应到编号，不把候选文字冒充 Canon。

## 审核/归属规则

- 每个 L3 PASS 角色至少对应一个 home_region / home_scene；组织若尚未确认就标 UNKNOWN，并保留证据。
- 主/次十元必须有来源与证据；允许单十元。头像只能提供视觉观察，不能单独推断职业、组织、区域或十元。
- 角色、区域、组织、场景分别登记；需要写它们之间发生的作用关系时，再引用 674-266 的 A↔B Pair 结构。
- 现有记录未填的字段是待核缺口，不自动代表“没有设定”。
- 角色 Markdown 与素材资产用稳定 ID 对应；图片源不复制，引用 asset_id/path/SHA，避免形成第二资产身份。
