# 青色世界观增量｜关系责任链

> 日期：2026-10-02
> region：青色
> status：KEEP-CANDIDATE
> 核心：Z × X并Z
> 主关系：X并Z → 生Z（沿用 CTX 已冻结关系，不反推 Canon）

## 机制

青色文明发现：当功能本来就由多个对象、环境、时序与维护行为共同生成时，事故也往往不属于某一个“坏掉的东西”。因此事故治理从寻找单一责任物，转向重建事故发生前后的完整关系配置，并把可重复的失配链标准化为责任与预防规则。

一句话：**功能属于关系，故障也可能属于关系；责任必须沿关系链定位，而不能随便抓一个最后接触事故的人。**

## 十元映射证据

- X并Z：事故由对象组合、接入顺序、环境变化、维护间隔等共同关系产生，单独检查任一对象都可能显示正常。
- Z：文明把事故关系重建为可记录、可复验、可比较的时序链，进一步形成维护义务、接入警告、事故等级与责任分配规则。
- 动态仍是 `异常关系/失配 → 关系重建 → 复验 → 责任节点/维护义务 → 新规程`，符合既有 `X并Z → 生Z`。

## 具象映射

一座公共冷藏库由菌膜、矿粉、软体生命呼吸液、湿度和定期翻面共同维持。某批药材腐坏后，菌膜、矿粉和软体生命分别检测都正常；最终发现是运输队提前半日更换矿粉，恰好与维护员延迟一次翻面、当日湿度上升共同形成失配窗口。

青色调查不会简单处罚“最后碰过冷库的人”，而会重建：

`对象版本 → 接入时间 → 环境变化 → 维护动作 → 功能衰减 → 事故`

由此出现关系事故图、时序封存牌、维护签、接入版本记录和失配复验场。

## 文明后果

1. **法律**：从单体所有权责任扩展到关系义务；拥有一个对象不等于独自承担由整个关系网络产生的事故。
2. **职业**：出现关系事故复验师、时序取证员、维护义务审计员。
3. **城市**：重要公共功能必须保留接入/退出与维护历史，否则事故后无法重建关系链。
4. **产业**：厂商不能只证明“我的零件没坏”，还必须声明它在什么关系窗口内才安全。
5. **剧情**：所有参与者都没有单独犯错，却共同组成了致命失配；冲突从“谁是坏人”变成“谁本应知道这段关系会这样组合”。

## 去重审核

- 与「功能配方库」区别：配方库回答功能怎样出现；本机制回答功能失败后怎样定位关系责任。
- 与「关系工程学」区别：关系工程设计关系；本机制处理现实运行中多方关系共同失效后的追责与规则更新。
- 与「关系迁移账」区别：迁移账审计节点离开会造成什么后果；本机制审计事故已经发生时责任如何沿关系链分配。
- 与「规程生态债」区别：生态债处理旧标准长期使用形成的历史依赖；本机制处理一次或一类具体关系事故的因果重建与责任制度。

## 候选审核

- KEEP｜关系责任链：新增层级明确，可直接生成法律、职业、城市设施与事故剧情。
- MERGE｜关系事故黑匣：只是关系责任链的取证器具，不独立建机制。
- MERGE｜多方维护签：只是责任链中的记录制度，不独立建机制。
- LOW｜关系责任保险：属于产业衍生，暂不足以成为母机制。
- REJECT｜所有参与对象平均担责：抹掉时序、知识义务与实际贡献差异，把关系治理退化成机械均摊。
