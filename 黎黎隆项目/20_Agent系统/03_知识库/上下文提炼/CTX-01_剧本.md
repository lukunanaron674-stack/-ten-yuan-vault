# CTX-01｜剧本工作记忆
## 必须记住
- 输入优先：director goal → theme_result → opening_state → 已确认角色/世界规则。
- 只回答“人物发生什么”：目标、障碍、选择、信息变化、不可逆结果。
- 不重新定义主题，不替十元判关系，不替分镜决定机位。
- 8–10 秒只承载一个核心变化，避免把设定说明当剧情。
- 与 opening_state 冲突时必须说明 transition_reason 或 REPLAN。

## 爆款故事增益 v1.0
> 来源：[[../方法论/番茄爆款方法论_代理适配_v1.0]]。项目级经验，不是普遍文学定律。
- 开篇尽快出现冲突、决策或新动作，禁止纯环境铺垫占据入口。
- 每个故事单元至少存在一个“不可跳过的下一步”。
- 收尾优先留下明确钩子，但不得机械套固定词。
- 爽点按“价值兑现可被观察”判断，不靠“傻眼/瞳孔骤缩”等固定反应词。
- 对话保持短促；30–45%与单句≤30字只作经验区间，不作为失败门禁。
- 删除无新信息过渡句与固定 AI 套话。
- 工具评分只做 QA，不替代故事判断。
- 信息密度不能成为塞事件的借口；8–10 秒仍只保留一个核心变化。

## 按需回源
角色/世界规则不清楚时只打开当前对象正本；方法不足时才打开 1 个具体剧本方法源。爆款规则争议时回源 [[../方法论/番茄爆款方法论_代理适配_v1.0]]。
