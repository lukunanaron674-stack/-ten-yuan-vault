# STORY_TENYUAN_CROSS_VERTICAL_PROTOCOL｜十元 × 剧本横纵动态链联合流程

## 目的
把“十元结构”用于发现故事动力，而不是把剧情硬套成十元公式。

适用：
- 一句话故事发散
- 角色主题曲 / 电影 / 案例启发后的故事转译
- 黎黎隆及其他角色的短剧情实验

不适用：
- 未经听音/逐段分析就断言某首音乐本体拥有某条十元动态链。
- 用十元标签替代人物目标、因果、选择与后果。

---

## 核心区分

### 1. 横向构图
同一阶段内，同时存在的力量与关系：
- 角色内部构成：如 ZX主 + Z中 + 小XN
- 角色 ↔ 对手 / 伙伴 / 世界
- 生 / 克 / 补的直接作用
- 多个十元可同时存在，不等于必须按顺序互相变成

### 2. 纵向动态链
沿时间推进，状态真实发生改变：
- T1 起始状态
- T2 作用 / 受克 / 获得条件
- T3 选择 / 改道 / 升级 / 失控
- T4 不可逆后果
- T5 回收后的新状态

横向关系必须能够改变纵向发展；纵向变化也应重新排列横向关系。

### 3. 构成 ≠ 转换
“ZX主 + Z中 + 小XN”是角色内部构成，不得机械写成：
ZX → Z → XN。

只有人物行为、能力、关系或决定权真的发生变化时，才登记为纵向变化。

## 静态文字横纵构图｜默认呈现规范（2026-10-28 USER校正）

**用户给定的优先示范**：多泳道等宽纯文本结构，使用 `────────────────` 标记分区、列标题表示角色／工单／资源与职责，`──→` 表示流向，`↑/↓/└──→` 表示跨泳道反馈与依赖。用户示范的“静态视觉线／审核反馈／H3视频线／连续镜头反馈／有限测试线／世界观输入／正式层级阻塞”是结构范式，不是要求每次输出这些业务名称。

**本章定义“如何画”，上文横纵机制定义“画什么”。** 即使叙事分析正确，若以长篇散文、独立人物小传、单纯时间表、卡片标题+正文、堆叠表格代替等宽横纵网络，判 `FORMAT_FAIL`，必须重排。

### 强制输出规则

1. **静态主图优先**：先给一整张在代码块内可复制的等宽纯文字主图，不得先用数千字解释故事。用真实分层名称（例如「历史因果／第一集发现／第二集调查／第三集兑现／后果反馈／待验证」），不是把横轴和纵轴拆成两篇。
2. **同层横向**：每条横向线同时写清参与者／物件／环境／权力与限制／动作及指向、谁改变了谁的什么变量；列标题固定、文本短句、箭头有清楚方向，长句下沉到主图后的局部说明。
3. **纵向连通**：同一个事件的结果作为下一层的可见输入，使用 `│`、`↓`、`└──→` 和回流箭头连接；跨年代人物与现时人物必须通过信件、证据、决定等实际桥接物件连通。
4. **反馈单独成线**：像 USER 示例的“审核反馈”一样，列出回收、反证、失败返工、误解修正、跨集作用；不能只有单向时间顺序。要标明反馈回到哪一段和它改变的对象。
5. **分清关系性质**：箭头须能判读为“事件因果／信息转移／十元生克补候选／正式依赖”，必要时用 `【事实】`、`【USER】`、`【H 假设】`、`【待核】` 分别标明。十元补位位置锁定不等于镜头中已启动。
6. **视觉可读**：优先 3–6 个有效列；尽量让一行在常见编辑器内不必横向滚动；中文等宽显示可能受字体影响，用清楚的分区和换行保持结构，即使对齐略有偏差也不能牺牲箭头语义。
7. **无意义节点省略**：只显示实际参与事件或有明确约束的对象；不因为理论中有十元就强行安排一列。未核事实标待核，不补虚构。
8. **输出层次**：①一张静态主图；②最多一张局部关系放大图（仅在需要时）；③3–5句解释最大因果瓶颈、验证条件。被用户明确要求详细研究时再补材料论证表。

### 合格示意｜跨代音乐信（演示性原创候选，非已定稿）

```text

保存旧谱 ─────────────→ 发现异常旋律 ───────→ 辨认祖母笔迹
                          │                       │
                          └──────────┬────────────┘
                                     ↓

共同选择线  ──────────────────────────────────────────────────
```

**验收（FORMAT_PASS）**：能一眼沿横箭头看清同层任务/人物关系，沿纵线看清上一段如何导致下一段，沿反馈线追踪谁回写谁；删除某箭头后能解释哪项因果证明丢失。否则 `FORMAT_FAIL`，禁止把普通纵向列表称为“横纵文字构图”。

**和 Obsidian Canvas 排版 Skill 的边界**：此协议是逻辑结构＋纯文字静态视觉；`07-Codex大脑库/skills/obsidian-canvas-layout/SKILL.md` 是 JSON Canvas 节点坐标/颜色/连线的几何编辑协议。前者不能代替后者；用户仅要文字图时不创建 Canvas。

## 联合工作顺序

### STEP 0｜输入
可来自：
- 角色正本
- 世界观正本
- theme_result
- 一首歌曲 / 一个电影案例 / 一个叙事机制

若来源是音乐或外部案例：
- 先提炼“叙事机制候选”，例如：双轨竞争、受克后改道、多点联动、循环失控、关系转移、自主选择。
- 未经正式验证，不把候选机制写成“该音乐已验证十元动态链”。

### STEP 1｜十元 Agent：先搭横纵结构
输出：
1. 角色内部构成
2. 横向关系图
3. 纵向动态链候选
4. 生 / 克 / 补直接作用
5. 哪些是 VERIFIED，哪些是 HYPOTHESIS
6. 一条“禁止机械化”提醒

要求：
- 先说明谁改变了谁、改变了什么。
- 删除任何“只贴标签但不改变后续”的关系。
- 不替剧本写完整事件。

### STEP 2｜剧本 Agent：把结构变成人物事件
基于 STEP 1，先发散 6–10 条一句话故事。

每条必须包含：
- 主角主动想要什么
- 第一行动由角色性格产生
- 阻碍具体改变行动路径
- 至少一次选择或变招
- 一个可见后果
- 结尾状态与开头不同

禁止：
- “世界出事，所以主角被迫行动”作为唯一发动机
- 为了凑十元而让人物突然变性格
- 用抽象词代替事件，如“获得成长”“理解自由”“完成蜕变”

### STEP 3｜十元 Agent：反审故事
逐条检查：
1. 横向关系是否真的进入因果？
2. 生 / 克 / 补是否产生不同后果？
3. 删除某关系后，故事是否完全不变？
   - 若不变：该关系只是装饰，不登记为有效动态链。
4. 角色主十元是否被剧情抹掉？
5. 是否出现“自己制造自己的克制”等更有价值结构？
6. 是否存在动态链断裂、假回收、伪关系？

输出只做结构审查，不重写完整故事。

### STEP 4｜剧本 Agent：二次改写
根据反审结果：
- 修掉装饰关系
- 强化人物主动性
- 让代价由角色此前选择产生
- 保留意外与不完全可控性
- 不把所有故事收束成同一模板

从中保留 3 个“机制不同”的骨架，例如：
- 世界关系 × 人物关系双层回收
- 角色内部构成冲突
- 双向竞争 / 循环失控转关系变化

### STEP 5｜联合验证
最终每个骨架都要回答：

**横向**
- 同一时刻有哪些力量？
- 谁生 / 克 / 补谁？
- 直接改变是什么？

**纵向**
- T1 到 T5 每一步什么状态改变？
- 哪一步是不可逆变化？
- 结尾怎样回收到开头矛盾？

**角色**
- 主角仍然像这个角色吗？
- 主十元是否仍主导？
- 次十元是否通过行为而非标签显现？

## 六种可复用叙事构图候选

这些只是“叙事机制模板”，不是音乐本体的已验证十元结论。

1. **双轨竞争型**
   - 横向：主角 ↔ 对手；Z 作为变招方式
   - 纵向：挑衅 → 回应 → 变招 → 升级 → 关系重排

2. **受克后改道型**
   - 横向：XN 克 ZX；Z 提供另一条路径
   - 纵向：争取 → 受阻 → 失败 → 改道 → 以新方法争取

3. **多点联动型**
   - 横向：ZX / Z / N / NZ 等多方同时作用
   - 纵向：一个动作 → 连锁反应 → 意外 → 借势 → 新关系

4. **循环失控型**
   - 横向：ZX 与阻力相互升级
   - 纵向：争取 → 受克 → 加码 → 再受克 → 失控 → 后果

5. **关系转移型**
   - 横向：个人目标与 N / 伙伴关系共同变化
   - 纵向：为自己争取 → 关系建立 → 行动伤害关系 → 修复 → 共同目标

6. **世界规则 × 自主选择型**
   - 横向：NZ / X并Z / XN 与角色 ZX+Z 形成多层关系
   - 纵向：自由状态 → 被定义 / 工具化 → 发现另一种可能 → 重新争取决定权

- 已有 ≥ 6 条一句话故事
- 至少 3 种不同机制
- 已完成一次十元反审
- 已保留 3 个机制不同的骨架
- 每个骨架都有横向关系 + T1–T5 纵向变化
- 没有把未验证的音乐映射伪装成正式十元结论

## 通用三级编译｜十元架构 × 图形横纵 × 分幕卡视听（2026-11-02）

> 用户当前要的不是一张剧情提纲，而是**作品分析和原创创作共享的可逆编译协议**。本节为 **L5应用方法**，不重定义L2十元/生克补。执行总控：[Linear 674-324](https://linear.app/674/issue/674-324)；十元关系以674-105及现行L2单条关系门禁为准；审核证据归674-106。

### 0｜完整输入与两条运行方向

- **分析/学习**：原片或可信剧情事实 → 逐个可核的具体事件 → 卡级视听观察 → 同层横向 × 阶段纵向 → 图形拓扑/十元概念候选 → 可迁移事件零件。未见原片时，不虚构景别、剪辑、配乐或时间码；视听未知填「待看片」。
- **创作**：主题问题＋目标感受（十元感受谱可为预测） → 选图形构成并比较竞争骨架 → 指定十元焦点与真实缺口/约束 → 构造事件横纵网 → 按幕/卡逐级展开 → 视听参数 → 删除/反向测试 → 镜头/H3执行包。
- **五维可选**：时间、本体、空间、因果、命运负责主题议题；不等于五组反向感受五轴。不得从「时间=xn+z」倒推所有时间片段都已启动xn补z。
- **层级区分**：T=图形拓扑，不等于生克补；R=十元关系作用，必须有源/目标/变量/条件/反例；E=具体事件；Axx-Cxx=幕卡；V=视听安排。一个事件能采用多种图形候选，需比较哪种有因果必要性。

### L1｜整片/整集的十元架构（Macro）

固定输出：
1. **主题问题**：一句可被剧情行动检验的矛盾；只选相关五维，不强行全部映射。
2. **人物/制度/物件角色**：对象、时间点、主/次十元感受候选及诱发行为证据。人物性格标签、作者意图、观众感受预测、真人感受四者分开。
3. **结构母型**：在已登记的图形库里选1个主拓扑、至少1个竞争拓扑；说明谁是桥、端点、汇聚点与决策点。比如：单向桥接、双向桥接、双轨并行、三角闭合、三方汇聚、分叉、回路、双向补位拓扑等是*形状候选*，不是新增十元。
4. **十元边**：逐条给 source、target、relation_type（生/克/补/仅拓扑/对立）、direction、object_layer、precondition、changed_variable、observable_consequence、evidence、status。不能因为两人互相帮助就判定严格双补；z/zn相关旧机制遇端点冻结必须标WAIT_REAUDIT。
5. **对照**：拿掉桥/物件/关系后，具体事件链是否断裂？至少一个竞争解释、一个可证伪条件。
6. **终点**：起始关系配置→中段主导权/缺口变化→结局残余/不可逆条件。不是“第一幕→第二幕→第三幕”空序列。

### L2｜图形骨架融入文字横纵构图＋十元符号概念映射（Meso）

**始终先输出一张等宽纯文字主图**，服从\`07-Codex大脑库/skills/story-horizontal-vertical-text/SKILL.md\`。一行是**同一时间窗发生的角色与物件/制度作用**，竖向是上一行动的*结果*作为下一行动的*前提*，底部有回流目标及待核区。图形模板Txx可画在图题上，不能替代事件动作。

示范（原创结构示范，不是电影事实/现行剧情确认）：

\`\`\`text
【L2｜T-桥接＋双轨汇聚；十元关系待判】
第一幕·错失 ──────────────────────────────────────────
 A人物（想获得）       中介物件/规则          B人物（能选择）
 求助 ──────────────→ 门票被扣留 ─────────────→ 不知请求已存在
       └────────────→ 信息缺口=1；会面机会减少
                               │
                               ↓ 票据留存→成为下一幕唯一实物证据
第二幕·变招 ──────────────────────────────────────────
 A人物（主动核对）       票据被发现             B人物（主动决定）
 自证 ──────────────→ 找到背面签名 ───────────→ 改为共同赴约
       └────────────→ 信息缺口归零，进入决定关口
                               │
                               ↓ 选择产生不可逆代价
第三幕·回收 ──────────────────────────────────────────
 A承担代价 ──────────→ B公开说明缘由 ────────→ 旧规则受质疑
【回流】B的说明 ──→ 第一幕「无人知道请求」得到纠正而非时间倒流
【反证】去掉票据仍能直接见面？若能，本图的桥接功能尚未成立
\`\`\`

**必须另列的概念映射（四层，不用隐喻代替作用）：**
\`\`\`text
十元符号/焦点（例如XN，假设）
→ 目标感受或主题矛盾（例如被时间流程压迫，仍可表达自主决定）
→ 触发机制（期限、流程主导权、被动/主动组织的差异）
→ 可观看事件（提交→被驳回→改办法→公开决定）
→ 视听呈现（固定中轴/表格声/门框遮挡→镜头主导权改变）
\`\`\`
“期限”不是XN本体；可以是XN感受的诱发条件。只有关系端点成立且源端改变目标变量，才可进一步登记真正的生克补。

### L3｜分幕×分卡的单焦点十元/关系视听卡（Micro）

**编号法**：\`A01-C01\`（第一幕第一卡）、\`A02-C03\`（第二幕第三卡）。外部电影若非严格三幕制，可据实际结构使用A01..An；编号不等于剧情时间码。每卡只明确**一个主要评估焦点**：
- **SINGLE_TENYUAN**：表现一种十元感受的可观察诱因，不编造生克补作用。
- **SINGLE_RELATION**：只检验一条源→目标关系；补位可记录两个方向但**本卡只检验一个有证据的改变变量**，另一方向另卡测试。

卡片文本模板：

\`\`\`yaml
act_card: A01-C01
stage: 第一幕｜引入/变故
topology_ref: Txx/未核编号
focus_mode: SINGLE_TENYUAN | SINGLE_RELATION
focus: XN（预测） | XN克ZX（经L2门禁核对）
relation_status: H | CURRENT_CANON | WAIT_REAUDIT | NOT_RELATION
theme_question: 这个人想得到什么、牺牲什么？
participants: A、B、物件/规则（各自能做什么）
horizontal: A动作 --经物件/制度--> B/规则的可见反应
vertical_in: 前一卡留下的可观测前提
trigger: 本卡启动事件
action: 人物主动做的实际动作
changed_variable: 改变的唯一主要变量
visible_consequence: 改变后镜头能拍到什么
vertical_out: 传给下一卡的新前提
residue: 尚未偿还的代价/未解除的缺口
counterfactual: 删除本卡或逆转该变量，下一卡会怎样？
shot_scale: 远/中/近或具体镜头切换
composition: 主次体量、空间重心、遮挡、轴线
camera: 机位/运镜（目的与变量对应）
lighting_color: 色温、对比、面积及变化
editing: 节奏、转场、停顿、动作衔接

### R1-A｜12种拓扑母型（原图已有，原位复用，不复制）
- **T01** 单向：最小一条关系通道。A的行为必须改变B的某个状态；同框不算发生作用。
- **T02** 双向：A改变B，B也以独立行为改变A。双向作用不等于天然互补；需分两条事件证据。
- **T03** 串联：第一步的输出成为第二步的条件，强调逐级传递；B只是经过站时不升级为“架桥”。
- **T04** 分叉：同一个行动分出两种后果；检查B、C是否真的分别变化，而非重复叙述A的行动。
- **T05** 汇聚：两个来源汇向共同结果C。检验各自输入及共同造成的变化，可构成合力或抵消。
- **T06** 并联／双通道：同一双人之间有两条独立机制。双人双补可填两条严格补位；必须分别给出事件与变量。
- **T07** 架桥：M提供不可替代的中介／桥变量，使A与C由不连通变可连通。拿掉M后连线须断。
- **T08** 三角：三处关系真实相互牵制或回流。图上画三角形却没有第三方作用，不成立。
- **T09** 菱形／分合：起点分成至少两条不同路径，在D合流；两条路径要提供不同条件而非重复。
- **T10** 星形／中心辐射：多个对象与中心H发生关系。检查中心移除后哪些支路失效，辨别权力中心与中介平台。
- **T11** 回环／反馈：阶段末回到同一对象，但A₁应带有可观察的残差或新状态；原样重播只是重复。
- **T12** 交叉／镜像：两组角色/力量交叉作用于两端，适合错位、互换、双线反衬；检验四条边的必要性。
