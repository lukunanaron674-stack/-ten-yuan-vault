# 黎黎隆角色文字发散｜每小时任务

## 任务目标

每小时执行一轮“角色主角实验卡 v1.0”：从 GitHub checkout 的现有角色卡、角色图、场景图和十元资料中选择一位主角，先回答“谁改变了谁的什么”，再生成 8 条 H3 镜头词。01–03 合成为一个约 10 秒微故事提交本地 H3；04–08 作为改变单一变量的对照描述词留档。所有角色包括未完成设计者都具有主角资格；未确认部分只标记待定，不擅自补成正式设定。

## 已锁定的上游约束

- 核心句：**奇幻生物感的大形 + 后加的科技模块 + 少量灾变改写痕迹 + 强剪影 + 动画友好复杂度。**
- 黎黎隆身份锚：红发、高表情、小上身、大尾体；巨尾是第二身体，承担平衡、运动、身份与情绪。
- 机械规则：先读 2–4 个大体块，再读中型嵌合关节，最后才读接口；禁止串珠机械、均匀重复和零件数量堆积。
- 颜色规则：低饱和大面；红绑定人物主观性，青绑定系统/接口，黑紫只表示灾变缺口；每轮最多一主色、一结构辅色、一焦点色。
- 世界规则：NZ 是软、旧、活、手工；Z 是冷、模块、接口、包覆；X并Z 是缺口、错位、侵入、黑紫改写。
- 参照上游：[[黎黎隆_角色总览_素材汇总_v0.1]]、[[角色风格_R1-R3/00_STYLE_CANVAS/Character_Style_Grammar_v0.1]]、[[黎黎隆_世界观总纲_v2.0]]。

## 每小时固定流程

1. 读取 GitHub checkout 当前角色卡、实际存在的角色图/场景图、角色总索引和十元动态链正本；记录 `HEAD` 与 `origin/main`，不自动 fetch/pull。
2. 选择一位角色作为主角；读取已确认身份、造型和十元状态，未完成部分写入 `pending`。
3. 写三种候选故事，先填 `source → target / mechanism / changed_variable / before → after`，再选择一个以可观察行为成立的方案。
4. 生成 8 条 H3 镜头词。01–03 合成 9–15 秒微故事；04–08 分别改变场景、关系、动作或拍法。
5. 先通过 Hermes → `h3_4090d_channel.py` 做 4090D 状态检查；状态通过后执行 `check --spec`，再执行 `submit --spec`。ComfyUI 离线、预检失败或生产心跳异常时不入队，保留词并把阻塞证据写给 Hermes。
6. 保存实验卡、8 个单条镜头文件、H3 前后状态、MP4 probe 和人工验收待办；不写回正式角色 Canvas，不修改十元理论正本。

## 8 小时首轮变量表

| 小时 | 只改变量 | 验收问题 |
|---|---|---|
| H01 | 黎黎隆主剪影 | 缩小后是否仍是一具“小上身 + 大尾体”？ |
| H02 | 巨尾承力状态 | 自由、挂接、锁止、卸载是否一眼可分？ |
| H03 | 脸与尾巴的表情分工 | 不靠台词能否读出情绪方向？ |
| H04 | 服装与尾根接口 | 衣服是否服务尾部活动，而非盖住机制？ |
| H05 | NZ / Z 材料边界 | 软体、壳体、绑带、接口是否有清楚交界？ |
| H06 | P00 功能色比例 | 青、红、黑紫是否各自有功能而非装饰？ |
| H07 | 三个动作姿态 | 走、锚定、卸锚是否保持同一主轮廓？ |
| H08 | 公共维护关系 | 角色身体是否改变场景和他人的行动？ |

## 安全边界

- 只使用远端 4090D 的现有 `pool_run.py` 生产者；Hermes/本任务不得直接 POST `/prompt`，不得启停或杀 ComfyUI，不清空已有队列。
- H3 完成条件必须同时有 history/runner 完成、实际 MP4 和 probe；MP4 存在仍标记 `已生成_待人工验收`，不等于十元镜头验证成功。
- 不覆盖 `02_角色` 下的原始 Canvas、用户原稿或已存在候选图。
- 每轮保存“镜头生产词”和“十元设计经验”两类成果；人工确认前不得升级为正式设定或锁定关系。
- 远端 H3 提交必须留存动作编号、`check`/`submit` 日志、task_id、实际 MP4、远端与本地 probe、SHA256 和人工验收状态；任何一项缺失都只能标候选/阻塞。
- 停止任务：注销 Windows 任务 `LLL-Character-Text-Hourly`，或在本文件 frontmatter 将 `status` 改为 `paused` 后再停用任务。
