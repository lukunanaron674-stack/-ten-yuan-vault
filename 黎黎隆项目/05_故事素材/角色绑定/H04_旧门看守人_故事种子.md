# H04｜旧门看守人｜一句话故事种子

> 角色文字设计：[[../../03_角色/角色库/候选角色/H04_旧门看守人]]  
> 当前开发原则：保留 3 个 ACTIVE，其他 HOLD；未被选中不等于淘汰。

## 当前 ACTIVE

### H04-STORY-002｜《两个都回来了》
- bucket: CHARACTER_CANDIDATE
- theme: 本体 / 命运
- status: ACTIVE
- one_line: 一个失踪者以两个只拥有一半记忆的身体同时返回，系统要求注销其中一个，旧门看守人却把两个人都登记为本人，第二天旧门因此分裂出两个合法出口。
- core_value: 身份关系分叉后，两个后继是否都可以合法成立。
- tenyuan_test: 强测 ZN ↔ NZ 双核候选。

### H04-STORY-004｜《门认得你的旧名字》
- bucket: CHARACTER_CANDIDATE
- theme: 本体 / 命运
- status: ACTIVE
- one_line: 一个改名逃离过去的人被旧门拒绝通过，因为门只承认她离开时的名字；看守人没有逼她变回过去，而是尝试为“现在的她”重新建立一条回返关系。
- core_value: 角色主动采取行动，而不是只负责解释世界规则。
- tenyuan_test: ZN 保留“现在的她”的成立资格，NZ 重建新的回返路径。

### H04-STORY-006｜《门不认得看守人》
- bucket: CHARACTER_CANDIDATE
- theme: 本体
- status: ACTIVE
- one_line: 守了几十年旧门的看守人突然被门拒绝进入，而刚来的学徒却被承认为看守人，他不得不确认自己究竟是在守这扇门，还是早已靠这扇门证明自己是谁。
- core_value: 世界第一次反过来审判负责审判他人的人，最适合验证角色本体。
- tenyuan_test: 重点验证 ZN 主 / NZ 主 / 双核三种候选。

### H04-STORY-005｜《遗物回来了》
- bucket: CHARACTER_CANDIDATE

- status: HOLD

### H04-STORY-007｜《回来得太完整》
- bucket: CHARACTER_CANDIDATE
- theme: 本体
- status: HOLD
- one_line: 一个失踪十年的人带着完全一致的身体、记忆、声音、习惯和伤疤回来，所有人都认为这是奇迹，只有看守人拒绝放行，因为“去那种地方十年，一点没变才最不正常”。

### H04-STORY-008｜《最后一把钥匙》
- bucket: CHARACTER_CANDIDATE
- theme: 本体 / 因果
- status: HOLD
- one_line: 看守人死前必须把旧门交给下一任，门却始终拒绝承认继任者，直到新人第一次违背他的命令，独自放一个陌生人回家，门才真正承认了新的看守人。
- risk: 容易滑成“传承考验”寓言，因此暂不占开发位。

## 统一发动机

```text
探索者进入未知
↓
未知改变探索者
↓
回来的人与出发的人出现连续性争议
↓
制度给出一个答案
↓
H04发现具体的人与制度答案不一致
↓
他必须决定：
“还是不是他？”
“还能不能回来？”
```
