# 论文方向3专项｜第1课：Node / Edge / Relation Type

> 学习目标：不用学术英语，也能看懂一张“创作意图关系图”最基本的三样东西。
>
> 状态目标：KNOWN → RECOGNIZE → APPLY

---

# 1｜Node｜节点

## 一句大白话

> **把脑子里一个可以单独讨论的意思，单独拿出来做成一张卡。**

Node 不是“十元”。

它可以是：

- Goal｜我要什么
- Constraint｜什么不能改
- Choice｜我决定选什么
- Property｜画面/角色/叙事的一个属性
- Reference｜参考
- Stage｜当前阶段

## 黎黎隆例子

可以做成 Node 的东西：

### Node A
“黎黎隆必须保持长机械龙尾的总体比例与节奏”

这是一个 Constraint Node。

### Node B
“动作要更夸张、更快、更有好胜感”

这是一个 Goal Node。

### Node C
“角色脸型和身份不能漂移”

这也是 Constraint Node。

这些都是三张独立卡。

## 和十元的关系

十元不是 Node 类型。

错误：
Goal = ZX

更正确：
Goal = 动作要表现好胜与主动抢先
然后再额外挂：
ten_yuan_semantic = ZX candidate

所以：

> **Node 负责“这是什么创作问题”；十元负责“它可能是什么关系/性质”。**

论文相关性：**P0 核心**

---

# 2｜Edge｜边

## 一句大白话

> **两张卡之间拉一条线，告诉 AI：它们不是互不相关。**

例如：

~~~
Node A：机械龙尾比例必须保持
      ↓
Node B：动作要更夸张
~~~

光画这条线，只说明：

> “这两个要求之间有关系。”

但还没说：
- 是支持？
- 是冲突？
- 是谁影响谁？
- 为什么？

所以 Edge 只是“连起来”。

## 社会为什么需要 Edge

如果只有一堆 Node：

- 长尾要保留
- 动作要夸张
- 身份要稳定
- 镜头要快
- 画风不能碎

AI 只看到五条独立要求。

一旦有 Edge：

> AI 才能知道“改 A 会不会影响 B”。

论文相关性：**P0 核心**

---

# 3｜Relation Type｜关系类型

## 一句大白话

> **这条线到底在干什么。**

这是你和十元最有关系的地方。

社会上常见：

- support｜支持
- conflict｜冲突
- inhibit｜压制
- compensate｜补偿
- preserve｜保持
- depend_on｜依赖
- replace｜替代

所以：

~~~
A —— B
~~~

信息很少。

而：

~~~
A --conflicts_with--> B
~~~

信息就多了。

---

# 4｜拿黎黎隆真正画一条

### Node A
“机械龙尾总体比例必须保持”

### Node B
“动作要更夸张、更有速度感”

可能出现两种完全不同的 Relation Type：

## 情况 1｜supports

如果长尾本身能形成更大的动作弧线：

~~~
长机械龙尾
-- supports -->
夸张速度感
~~~

意思：
> 长尾帮助动作更有冲击力。

## 情况 2｜conflicts_with

如果动作夸张到尾巴比例、模块结构全变了：

~~~
夸张动作
-- conflicts_with -->
尾巴结构保持
~~~

意思：
> 为了动作更爽，反而破坏了冻结设计。

所以关键不是：
> “尾巴是什么十元？”

而是：

> **在这一轮创作里，A 和 B 之间到底发生了什么关系。**

---

# 5｜这里才接十元

社会先有：

~~~
Node A
Node B
Relation Type
~~~

十元再尝试进一步编码：

~~~
A --生--> B
A --克--> B
A --补--> B
~~~

但十元必须先回答：

> 生和 support 有什么区别？
> 克和 inhibit/conflict 有什么区别？
> 补和 compensate 有什么区别？

如果只是换名字：
> 没有论文新增性。

如果十元能稳定多表达：
- 改变了什么目标变量；
- 作用量 E 多大；
- 关系后来怎样转型；
- 能预测下一轮真实选择；

才可能有增量。

所以：

> **先学 Relation Type，才能判断十元到底有没有多做东西。**

论文相关性：**P0 核心**

# 6｜这三个词的最小记忆图

~~~
Node
= 一张意思卡

Node A        Node B
   \          /
    \        /
      Edge
= 两张卡连起来

A --[Relation Type]--> B
= 这条线到底在干嘛
~~~

# 8｜应用测试

下面不是十元题，先只用社会结构。

场景：

> 你要求一个 AI 把黎黎隆的跑步动作画得更有冲击力。
> AI 把动作做得很好，但为了速度感，把机械长尾缩短了很多。
> 你说“不行，动作可以改，但长尾总体比例和节奏不能动”。

请自己拆：

1. 有哪两个主要 Node？
2. 两个 Node 之间是什么 Relation Type？
3. 哪个是 Goal，哪个是 Constraint？
4. 这里为什么还不需要先判断 ZX/XN/其他十元？

# 10｜重要纠错：社会 Relation Type ≠ 十元生克补

这一课讲 Relation Type，是为了先理解“社会上的图为什么要给边分类”。

但进入十元时必须换层：

```
对象A → 判十元A
对象B → 判十元B
↓
十元A + 十元B + 当前阶段
↓
机制 / 目标变量 / 方向 / 证据
↓
才允许判：生 / 克 / 补 / NONE / AMBIGUOUS
```

所以不要记成：

> 生 = support，克 = conflict，补 = compensate。

正确理解是：

> **support / conflict / compensate 是社会关系词的例子；生克补是建立在十元端点上的关系判断。**

后面论文比较时，也比较“十元端点 + 关系启动 + 动态链”整体，不单独比较三个关系词。
