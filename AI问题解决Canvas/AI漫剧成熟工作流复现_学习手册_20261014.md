## 一句话读懂
**我们已会用 H3 让单镜动起来；现在要学别人怎样把很多镜头组织成有事件、有统一人物、有声音、能剪辑的“漫剧”。**

### 上排——漫剧真实生产流
| 流程 | 大白话 | 可检验的交付 |
|---|---|---|
| 剧本 Script | 故事先发生什么，后发生什么 | 镜头表、有因果 |
| 角色锚点 Character Anchor | 每个人的身份证 | 身份/衣服/比例固定 |
| 分镜契约 Shot Contract | 这一镜如何拍 | 动作、机位、景别、时长、对白明确 |
| 参考图绑定 Reference Binding | 图片真正进模型，而非只保存在硬盘 | refs SHA + 节点绑定回执 |
| H3生成 Render | 让这个镜头真的动 | 真MP4、fps、frame_count、seed |
| 质检 QA | 技术有没有坏，故事有没有不通 | 技术检查 + USER观看审美 |
| 剪辑交付 Edit | 镜头接起来，声画同步 | 三镜成片与完整溯源 |

### 三个例子：原剧第2镜如何拆
原始镜头里的**林川**看着水位红线，**苏芮**在对讲机前，台词表示电力只够两分钟。

1. **事件信息**：危险是城市洪水→设备和电力不稳→时间越来越少。
2. **资产**：林川的深蓝工装与短发、苏芮的黄雨衣与白色安全盔必须跨镜不乱变。
3. **拍摄**：控制室、警报红光、双人中景、监控屏幕等均应属于镜头说明，不能当成模型必然生成成功。
4. **导演问题**：这一镜应让观众意识到“时间不足”，而不是只看见一个人物在说话。

### 你要能答出的三个小问题
**Q1：为什么“一条鼠标H3视频通过”还不能叫“漫剧生产线通过”？**
因为鼠标单镜尚不要求人物多次出现、前后剧情因果、说话者一致、剪辑声音字幕。

**Q2：为什么不一开始就用《黎黎隆》测试？**
先复现别人现成的10镜演示才知道错误出在外部方法、机器适配还是我们原有资产。原剧成功之后再做《黎黎隆》适配。

**Q3：为什么不能混淆Ref2VA和I2V？**
工作流和模型权重不同；I2V成功只能证明单图视频通路有效，并不证明多个角色参考图一致性已经建立。

### 必须标注“原版”和“改编版”
- 源示例 `SOURCE_DEMO_ORIGINAL`：2人、10镜、120s、9:16。
- 本机首镜 `ADAPTED_16_9 / DURATION_ADAPTED`：剧情内容来源同一公共Demo，画幅/时长有改变。
- 后续《黎黎隆》专属版 `INTERNAL_ADAPTATION`：应新建资产和导演版本，不能冒充原作者方法原封不动输出。

### 每次复现回执看这五项
**输入依据**（repo+commit+剧本/参考SHA）→ **执行日志**（Comfy任务/节点/参数）→ **媒体实物**（MP4/首中尾）→ **机器质检**（身份/连贯/时序）→ **USER裁决**（PASS/FAIL/重跑原因）。
