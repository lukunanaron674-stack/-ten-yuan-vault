# 0｜R1 结论

抽查 2023–2026 年 15 个代表系统 / 框架后，现有“创作意图结构化”方法可以暂时收敛成 **6 个功能家族**：

1. **Prompt Refinement / Traceability**
2. **Multimodal / Contextual Elicitation**
3. **Attribute / Dimension / Taxonomy**
4. **Atomic Intent Units / Tags**
5. **Semantic / Concept / Reasoning Graph**
6. **Evolving / Cross-stage Intent Continuity**

重要结论：

> 社会上已经不只是“把 Prompt 写得更好”。

研究已经从：
**文字提示词**
→ **变量化**
→ **标签化**
→ **图结构**
→ **推理结构**
→ **动态演化**
→ **跨阶段保持**

因此十元后续绝不能把弱 baseline 定成“普通 Prompt”。

---

# 1｜家族 A：Prompt Refinement / Traceability

## A1｜Promptify（2023）
Text-to-Image Generation through Interactive Prompt Exploration with LLMs

结构：
- 初始 Prompt
- 生成结果
- 用户偏好
- LLM 建议修改
- 迭代 Prompt

解决：
**不知道怎么把意图写成 Prompt。**

结构化程度：
低～中。

---

## A2｜PromptCharm（CHI 2024）

结构：
- multimodal prompting
- prompt refinement
- attention / image feedback
- 局部修改

解决：
**生成结果和 Prompt 对应关系不清，修改难。**

结构化重点：
Prompt 与结果之间的映射。

---

## A3｜GenTune（2025）

环境设计师可以：
- 选择图片里的元素；
- 回溯它对应的 prompt labels；
- 修改 label；
- 精细调整同时保持整体一致。

结构化重点：
**Image element ↔ Prompt label traceability**

这已经开始从“句子”转成“可追踪标签”。

---

# 2｜家族 B：Multimodal / Contextual Intent Elicitation

## B1｜DesignPrompt（DIS 2024）

把：
- image
- color
- text
- moodboard

组合成 multimodal prompt。

目标：
**设计师不必把视觉意图全部翻译成文字。**

---

## B2｜ContextCam（CHI 2024）

输入不只是 Prompt，而是：
- location
- facial expression
- music
- screen content
- weather

系统先做 framing，再 focusing。

结构化重点：
**意图 = 用户指令 + 情境数据**

这类方法试图补：
> 用户自己没有明确说出来的意图。

---

## B3｜ACAI（2025）

把广告创作意图拆成 panel：
- Branding
- Audience & Goals
- Inspiration Board

结构化重点：
**用界面模块代替空白 Prompt 框。**

---

# 3｜家族 C：Attribute / Dimension / Taxonomy

## C1｜Fashion Attribute-based Interaction（2026）

六类主要变量：
- item type
- silhouette
- material
- pattern
- color
- style

再由规则自动转 Prompt。

核心：
> **Creative intent = 一组可单独操纵的设计变量**

优势：
- 清晰；
- 可编辑；
- 可控变量实验；
- 适合 HOLD 其他变量。

弱点：
- 关系、理由、冲突较弱。

---

## C2｜Luminate（CHI 2024）

LLM 先生成：
- design dimensions
- values

再让用户沿不同维度探索设计空间。

核心：
> 不要一开始就收敛到一个答案，先把“可能空间”结构化。

---

## C3｜DesignWeaver（CHI 2025）

从：
- design brief
- generated images

抽出 design dimensions，
变成 selectable palette。

核心：
**Dimension Scaffold**

帮助新人获得本来不会写出来的设计词汇。

---

## C4｜Design Keywords + AHP（2026）

过程：
- keyword elicitation
- KJ clustering
- AHP weighting
- structured prompt
- comparative evaluation

多了一步：

> **变量不只是有/没有，还可以有权重。**

这和以后十元的“体量 / 强度”比较值得对照。

---

# 4｜家族 D：Atomic Intent Units / Intent Tags

## D1｜IntentTagger（CHI 2025）

把用户意图拆成：

> **small atomic conceptual units**

也就是 Intent Tags。

特点：
- granular；
- graphical；
- adaptive；
- non-linear；
- micro-prompting。

用户可以逐渐：
- 添加；
- 修改；
- 细化；
- 组合自己的意图。

这是“节点粒度”很重要的一条路线。

---

# 5｜家族 E：Semantic / Concept / Reasoning Graph

这是目前和你的 IRG / 十元最近的一组。

## E1｜ToMigo（DIS 2026）

### Design Concept Graph

Node 主要包括：
- Purpose
- Concepts
- Content
- Stylistic Features

例如：
- mood
- function
- art style
- narrative
- motif
- composition
- color
- typography
- texture

Edge：
> 一个设计选择如何支持另一个设计选择。

例如：
`bright color → supports playful mood`

特点：
- edge 有方向；
- edge 有解释；
- graph 可编辑；
- 用户修改 node / edge 后可以重新生成；
- 支持 intent evolution。

**这是十元当前最重要 baseline。**

---

## E2｜DesignerlyLoop（DIS 2026）

结构化：
- problem framing
- constraints
- strategies
- evaluation criteria
- reasoning

采用两层 diagram：
- Design Intent Canvas
- LLM Reasoning Canvas

核心：
> Intent 和 reasoning 都要变成持续可编辑对象，而不是埋在聊天记录中。

---

## E3｜Semantic UI Generation（CHI 2026）

先从 UI prompting guideline 中抽：
- design semantics；
- hierarchy；
- interdependency。

然后：
- 显式指定语义；
- 可视化语义关系；
- 回看这些语义如何出现在生成 UI 里。

核心：
> **Semantic Representation 作为 Human Intent 与 AI Output 的中间层。**

---

# 6｜家族 F：Evolving / Cross-stage Intent Continuity

## F1｜Creative Dialogue（C&C 2025）

提出两个 loop：

### Creative Intention Loop
人 ↔ 主 AI
讨论和澄清 intent。

### Creative Execution Loop
主 AI → 其他生成工具
执行 image / video 等。

生成结果：
→ 回到人
→ 改变 intent
→ 下一轮。

核心：

> **Intent 不是静态输入，而是创作过程里的 evolving state。**

---

## F2｜Sketching vs AI Prompt Based Design Intent Evolution（CHI 2026）

61 位产品设计本科生。

研究直接跟踪：
> design intent 在 sketch 与 AI prompting 中怎样变化。

一个重要信号：
AI 组有时会从“设计问题本身”转向“怎么操作这个 AI 工具”。

说明：
**意图的演化路径本身可以被观察和研究。**

---

## F3｜GID-HGCC（2026）

四阶段：
1. requirements confirmation
2. concept generation
3. concept evaluation
4. 3D modeling

强调：
- 每阶段的人 / AI 权限；
- structured prompt；
- candidate concept；
- evaluation outputs；
- modeling issue list。

这些 artifact 负责：
> **跨阶段 carrying constraints**

研究的问题就是：
- semantic decay；
- constraint drift；
- requirements 丢失。

核心：

> **Intent / Constraint 要成为跨阶段可追踪 artifact。**

# 8｜现有研究实际已经覆盖了什么

把 15 个系统合起来看，社会已经在结构化：

## Node / Unit
- attribute
- keyword
- dimension
- tag
- purpose
- content
- style
- constraint
- strategy
- criterion

## Edge / Relation
- support
- explanation
- dependency
- interdependency
- mapping
- traceability

## Weight / Priority
- AHP weight
- dimension selection
- emphasis

## Rationale
- reasoning edge
- design reasoning
- reflective chat
- evaluation criteria

## Time
- iterative refinement
- evolving intent
- feedback loop
- revisable canvas

## Stage
- requirements
- concept
- evaluation
- production / modeling

## Evidence / Trace
- prompt label trace
- generated result
- evaluation output
- cross-stage artifact

所以：

> **Node、Edge、Weight、Reasoning、Time、Stage、Trace 都已经有人做。**

十元后面不能靠“我也有这些字段”证明新意。

# 9｜R1 对十元的第一条硬边界

现在最重要的不是问：

> 十元有没有 Relation？

而是：

> **十元的 Relation 到底和 ToMigo 的 supportive influence edge、普通 dependency edge 有什么操作级区别？**

同理：

主次：
> 和普通 Priority / Weight 有什么区别？

动态链：
> 和 evolving intent / feedback loop 有什么区别？

生克补：
> 是已有 relation type 的重新命名，还是能表达普通 graph 很难表达的关系变化？

这三个问题必须留给 R3 / R4。

# 10｜R1 暂时收敛出的 6 类

```
A Prompt refinement / traceability
↓
B Multimodal / context elicitation
↓
C Attribute / dimension / taxonomy
↓
D Atomic intent units / tags
↓
E Semantic / concept / reasoning graph

```

它们不是严格时间顺序，
而是“结构化程度 / 功能”上的谱系。
