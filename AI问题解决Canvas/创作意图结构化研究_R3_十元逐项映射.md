# 创作意图结构化研究｜R3 十元逐项映射 v1

> 目标：把当前十元正本逐项映射到 R2 的 Generic Intent Graph。
>
> 判定标签只允许：
>
> 1. **ISOMORPHIC｜已有字段同构**
> 2. **SPECIALIZATION｜已有字段细化**
> 3. **NEW OPERATOR CANDIDATE｜可能新增操作符**
> 4. **OUT OF SCOPE｜不该塞进创作意图 Schema**
>
> 本轮是结构映射，不证明十元优于社会已有方法。

---

# 0｜R3 最重要的总修正

R1/R2 的初步直觉里容易出现：

```
主次 ≈ Priority
体量 ≈ Weight
动态链 ≈ Timeline
```

读取当前 canonical 后，这三个映射都必须修正。

当前十元正本已经明确区分：

```
C｜证据置信度
T｜体量：十元在指定对象结构中的占位规模
M｜显影强度：已存在十元在当前阶段表现得多明显
E｜关系作用量：源端点实际改变目标变量多少
```

因此：

> **T / M / E / C 必须四分。**

不能再用一个“强度 1–10”字段同时承担：
- 结构占位；
- 当前显影；
- 关系效果；
- 证据可靠性。

这是 R3 对意图 Schema 的第一条硬修正。

# 1｜十元端点 X / Z / N / ZN / NZ / XN / NX / ZX / XZ / X并Z

## 判定
**SPECIALIZATION｜已有字段细化**

## 它不是什么

十元端点不是：
- Goal；
- Choice；
- Constraint；
- Property；
- Reference；
- Stage。

也不应该把：
`Goal = ZX`
这种写法当成完整意图结构。

## 它更像什么

在当前正本里，十元用于判断：

> 一个对象 / 关系 / 状态在指定窗口里“是什么性质 / 处于什么结构位置”。

因此放到 Intent Graph 中更合理的位置是：

```
Node
- object_id
- node_type = Goal | Choice | Constraint | Property | ...
- semantic_class = ten_yuan_candidate
```

例：

```
Node A:
type = Goal
content = “主动夺回选择权”
ten_yuan_semantic = zx

Node B:
type = Constraint
content = “制度流程限制行动路径”
ten_yuan_semantic = xn
```

十元端点是：
> **Semantic Class / Structural Position Annotation**

不是 Node 本身。

## 为什么不是 NEW
社会已有：
- ontology label；
- semantic class；
- category；
- role annotation；
- state label。

十元的价值如果存在，在于这套十个语义类别本身是否具有稳定区分力，而不是“给节点贴语义标签”这一行为。

---

# 2｜生 / 克 / 补

## 判定
**SPECIALIZATION｜已有字段细化**

这是 R3 最谨慎但最重要的判断。

## 当前 canonical 的严格语义

### 生
源端点：
> 提供目标端点成立、展开、积累、延续或进入下一阶段的条件。

### 克
源端点：
> 压缩、限制、阻断、改写或破坏目标端点继续成立的条件。

### 补
源端点：
> 补足目标端点独立运行时缺失的条件，使其成立、稳定或完成。

而且正式关系必须有：

```
source
target
mechanism
target_variable
direction
observable_change
third_factor_exclusion
reverse_explanation_test
```

## 映射

它们不是普通无类型 Edge。

更接近：

```
typed_causal_effect_relation
```

例如：

```
A --生--> B
effect:
  target_variable = path_set
  operation = expand/establish

A --克--> B
effect:
  target_variable = decision_right
  operation = compress/rewrite

A --补--> B
effect:
  target_variable = missing_condition
  operation = restore/complete
```

## 为什么当前仍判 SPECIALIZATION 而不是 NEW

社会已有关系语法里已经有：
- supports；
- enables；
- inhibits；
- conflicts；
- constrains；
- compensates；
- depends_on。

因此：
> “一种带方向的作用关系”并不是新操作。

十元真正可能新增的地方只能是：

> **生/克/补三类关系在同一套规则下，是否比普通 support/conflict/compensate 更稳定地描述创作意图之间的作用。**

这留给 R4/R5。

# 3｜关系目标变量

## 判定
**SPECIALIZATION｜已有字段细化**

十元当前要求不能只写：
`A 克 B`

必须写：
> A 通过什么机制，改变 B 的什么变量？

允许目标变量包括：
- 能力；
- 边界；
- 路径；
- 资源；
- 关系位置；
- 显影强度；
- 状态；
- 持续条件。

这相当于把 Edge 从：

```
A --conflicts--> B
```

升级为：

```
A --relation--> B
affected_field = path_set
before = ...
after = ...
```

这个做法很有操作价值，
但本质仍属于：
**typed edge + affected variable**

不是全新数据结构。

---

# 4｜主 / 次

## 判定
**SPECIALIZATION｜已有字段细化**

这是本轮最需要纠正的点。

## 主 / 次真正表达什么

十元组合正本明确：

```
对子 P =
主十元
+ 次十元
+ 对象层
+ 体量配比
+ 激活方式
+ 整体功能
```

而且：

```
zx主 + nx次
≠
nx主 + zx次
```

所以十元“主 / 次”表达的是：

> **同一对象 / 同一阶段的结构主导权**

更接近：
- compositional dominance；
- hierarchy；
- structural role。

## 它不等于什么

**主 / 次 ≠ conflict priority**

即：

> ZX 是主十元

不自动意味着：

> 当 ZX 意图和另一个创作要求冲突时，必须优先保 ZX。

创作决策里的：
- must preserve；
- may sacrifice；
- LOCK；
- FLEX；
- 用户价值优先级

仍然需要独立字段：

```
decision_priority
```

## R3 修正

以后 Intent Graph 必须同时允许：

```
semantic_dominance:
  primary_ten_yuan
  secondary_ten_yuan

decision_priority:
  must_keep
  preferred
  flexible
  sacrificial
```

两套不能合并。

---

# 5｜T｜体量

## 判定
**SPECIALIZATION｜已有字段细化**

正本：

> T = 十元在指定对象结构中的占位规模。

例如：

```
zx8 + nx2
≠
zx4 + nx7
```

它表达的是：
**composition occupancy / structural share**

不是：

- confidence；
- visual salience；
- relation strength；
- user preference；
- decision priority。

## Intent Graph 映射

```
semantic_composition:
  zx:
    T: 8
  nx:
    T: 2
```

它更像：
> 一个 Node / Object 内部语义构成的占位比例。

## 重要边界

T 不能直接用于：

> “这个创作要求有多重要？”

因为那是 decision priority。

---

# 6｜M｜显影强度

## 判定
**ISOMORPHIC｜已有字段同构**

正本：

> M = 已存在十元在当前阶段表现得多明显。

这非常接近通用 Schema 里的：

- salience；
- visibility；
- activation level；
- state expression strength。

例如：

```
semantic = zx
T = 8
M(stage_1) = 3
M(stage_2) = 9
```

说明：

> 这个对象本来 ZX 占位很高，但第一阶段还没有明显表现；第二阶段强烈显影。

这与现有状态属性完全同构。

因此 M 不应作为十元创新点。

---

# 7｜E｜关系作用量

## 判定
**SPECIALIZATION｜已有字段细化**

正本：

> E = 源端点实际改变目标变量多少。

这是当前十元里最接近：

```
relation_effect_strength
```

的字段。

示意：

```
A --克(E=7)--> B.path_set
```

含义：
不是 A 自己“很强”，
而是：

> A 对 B 的某个目标变量实际造成了多大变化。

## 与 T / M 完全不同

```
T = 我占多少
M = 我现在显得多明显
E = 我实际改变对方多少
```

这个三分法值得保留。

## 是否新

社会已有：
- edge weight；
- causal effect size；
- influence strength；
- transition magnitude。

所以目前仍属于 SPECIALIZATION。

---

# 8｜C｜证据置信度

## 判定
**ISOMORPHIC｜已有字段同构**

正本已经明确：

> C = 这个判断有多可靠？

这就是：
- confidence；
- evidence strength；
- uncertainty。

社会高度成熟。

不能拿 C 作为方法创新。

但必须保留，因为它防止：

```
低置信
→ 被写成低体量

高显影
→ 被写成高置信
```

---

# 9｜动态链

## 判定
**NEW OPERATOR CANDIDATE｜可能新增操作符**

注意：
不是说“时间链”是新东西。

时间线、state machine、evolving intent、workflow trace 都已有。

动态链值得进入 NEW OPERATOR CANDIDATE 的唯一原因是：

> **它尝试把“关系本身如何跨阶段继续 / 反转 / 退隐 / 转位”作为第一等对象。**

当前正本要求每阶段重新审核：

```
阶段1：端点与关系
阶段2：目标变量发生变化
阶段3：新端点是否形成
阶段4：关系是否继续、反转、退隐或转位
```

并且：

> 前一阶段关系不能自动继承下一阶段。

这比普通：

```
State0 → State1 → State2
```

更强调：

```
Relation0
→ relation transformation
→ Relation1
```

## 对应通用 Schema

动态链更像：

> **Temporal Typed-Relation State Machine**

结构：

```
Stage0:
A --克--> B.path

Stage1:
A --补--> B.resource

Stage2:
B --克--> A.decision_right
```

## 为什么只是 Candidate

现有：
- temporal graph；
- dynamic Bayesian networks；
- state transition systems；
- evolving intent models

都可能覆盖类似能力。

R4 必须查：
> “关系类型转型作为可编辑创作意图操作符”是否真的已有成熟同类。

因此目前只能：
**NEW OPERATOR CANDIDATE**

不能写“原创”。

---

# 10｜起点 → 变化 → 终点

## 判定
**ISOMORPHIC｜已有字段同构**

这是标准：
- state transition；
- process trace；
- before/after；
- event transition。

本身没有新增性。

真正可能新增的是：
> 起点和终点之间，Relation Type 怎样变。

所以它只是动态链的载体，不是创新点。

---

# 11｜激活方式 simultaneous / alternating / conditional / layered

## 判定
**SPECIALIZATION｜已有字段细化**

组合研究已经有：

```
activation_mode:
simultaneous
alternating
conditional
layered
```

它对应：
- temporal activation；
- conditional activation；
- compositional scheduling。

社会已有类似概念。

但它对创作意图很有用，可以继续保留作为 relation scheduling。

# 12｜对象层 object_layer

## 判定
**ISOMORPHIC｜已有字段同构**

当前十元严格区分：
- character；
- relationship；
- institution；
- scene；
- stage；
- whole_work。

这是标准 ontology / scope / level 字段。

重要，但不是新。

# 13｜五轴

## 判定
**OUT OF SCOPE｜不该塞进当前 Creative Intent Schema**

这是本轮一个非常重要的“删”。

当前正本：

> 五轴 = 传统五行在十元体系中的结构化表达。

五轴研究：
- 十元相反端；
- 木火土金水结构；
- 跨轴生克；
- 核心变量；
- 领域转译。

它是：

> **十元语义空间的高阶结构层**

不是创作者意图数据结构必须字段。

如果把五轴硬塞进 Intent Graph：
- 会扩大论文；
- 会增加解释层；
- 会让关系语法研究失焦。

所以：

> **五轴可以作为十元内部 ontology / background model，但不进入论文方向 3 的核心 Schema。**

除非 R4/R5 出现：
> 没有五轴就无法完成某个必要意图操作。

否则保持 OUT OF SCOPE。

---

# 14｜五维

## 判定
**OUT OF SCOPE｜不该塞进当前 Creative Intent Schema**

当前正本分工非常明确：

```
五维：
这个故事究竟研究什么主题问题。

十元：
问题内部有哪些力量、它们是什么性质。

动态链：
这些力量如何连续作用、反作用、收敛、回写。
```

五维是：
- 时间；
- 本体；
- 空间；
- 因果；
- 命运。

这是：

> **Narrative / Theme Layer**

不是创作意图关系语法本身。

因此方向 3 当前不要把五维带进来。

如果用户的 Goal 是：
> “我要研究命运主题”

那“命运”可以作为普通 Goal 内容。

但不需要把整套五维系统塞进 Intent Graph。

研究范围骤降。

# 19｜R3 最大的三个发现

## 发现 1
**十元端点不是 Intent Node 类型。**

它是：
> Node / Object 的语义标注层。

---

## 发现 2
**主次绝对不能直接等于创作优先级。**

结构主导权与：
> “发生冲突时必须保谁”

是两套东西。

---

## 发现 3
**动态链是目前唯一值得进 NEW OPERATOR CANDIDATE 的部分。**

不是因为它“有时间”，
而是因为它可能把：

> **Relation Type 的跨阶段转型**

做成第一等可操作对象。

这就是 R4 最值得狠狠干的地方。
