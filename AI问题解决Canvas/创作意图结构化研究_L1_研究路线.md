# 创作意图结构化研究｜L1 研究路线 v1

> 状态：OPEN / 独立研究线
>
> 目标：回答两个问题：
> 1. **别人到底如何把创作意图结构化？**
> 2. **十元 / 生克补 / 动态链到底补在现有方法的哪一层，是否有额外价值？**
>
> 本线不直接冻结论文题目；先把方法谱系与差异研究清楚。

---

# 0｜当前总判断

外部研究已经说明：

**“把创作意图结构化”本身不是新东西。**

现在至少已经存在五种常见路线：

1. Attribute / Taxonomy
2. Concept Graph
3. Intent / Reasoning Canvas
4. Evolving Intent Loop
5. Cross-stage Constraint Artifact

所以十元如果要进入论文，不能说：

> “我第一次把创作意图结构化。”

真正需要验证的是：

> **十元是否提供了现有结构中缺少或较弱的“关系语义、主次、强度与动态变化”表达能力。**

---

# 1｜别人如何结构化：五类

## A｜Attribute / Taxonomy｜属性 / 分类变量

代表：
2026 Fashion & Textiles：
**From prompting to attribute-based interaction**

核心结构：

```
Design Intent
↓
Item type
Silhouette
Color
Material
Pattern
Style
↓
规则化组合
↓
Prompt
↓
Generation
```

特点：
- 把模糊意图拆成离散变量；
- 每个变量可单独修改；
- 可 HOLD 其他变量不动；
- 强调 controllability / interpretability。

强项：
**“有什么属性”表达得清楚。**

弱项：
- 属性之间“为什么互相冲突”表达弱；
- 主次关系弱；
- 随创作过程变化的动态关系弱。

---

## B｜Concept Graph｜概念图

代表：
**ToMigo: Design Concept Graph**

核心结构：

```
Node
= purpose / content / style / design choice

Edge
= 节点之间可解释的联系
```

来源：
reference image + text
↓
AI 推断 concept graph
↓
用户查看 / 修改
↓
重新对齐设计

强项：
- 不只是一排属性；
- 有 node + edge；
- 能直接编辑；
- 能看到 AI 如何理解自己的意图。

这是当前与你 IRG **最近的社会基线**。

关键：
> “用图表示创作意图”已经不是十元独有价值。

---

## C｜Intent / Reasoning Canvas｜意图与推理画布

代表：
**DesignerlyLoop**

常见节点：
- problem framing；
- constraints；
- strategies；
- evaluation criteria；
- reasoning steps。

核心思想：

> 创作意图不是放在聊天历史里，而应该成为一个**可外显、可编辑、可持续保留的对象**。

强项：
- 支持非线性思考；
- 支持不断修改；
- 支持创作者看到 AI 的推理结构；
- 增强 agency。

弱项：
- 节点之间的作用关系未必有统一关系语法；
- “A 压制 B / A 补偿 B / 谁必须优先”不一定显式。

---

## D｜Evolving Intent Loop｜演化意图循环

代表：
**Creative Dialogue / evolving intent**

核心：

```
Creative Intention Loop
人 ↔ AI：讨论、澄清意图

        ↓

Creative Execution Loop
AI → 图像 / 视频 / 其他生成模型

        ↓

Output
        ↓
反馈回创作者
        ↓
Intent 更新
```

最大贡献：

> **Intent 不是一次输入，而是会变。**

这和你的：
`State0 → State1 → State2`
非常接近。

强项：
- 抓住时间维度；
- 抓住创作过程的反馈循环。

弱项：
- 变化“为什么发生”与关系类型未必细化。

---

## E｜Cross-stage Constraint Artifact｜跨阶段约束载体

代表：
多阶段 Human–GenAI 设计流程。

核心：

```
Requirements
↓
Concept
↓
Evaluation
↓
Model / Production
```

每一阶段都必须把约束继续传下去。

它解决：

- semantic decay；
- constraint drift；
- 多阶段丢意图。

关键思想：

> **创作意图必须成为一个跨阶段持续存在的 artifact，而不是只写在第一条 Prompt。**

这和你的 F 长流程可靠生产直接相连。

# 2｜五类现有结构，可以压成五层

```
L1｜WHAT
我有哪些变量 / 属性？
Attribute / Taxonomy

L2｜WHAT CONNECTS
这些概念之间有什么连接？
Concept Graph

L3｜WHY / HOW THINKING
我为什么这样想、怎样组织思考？
Reasoning / Intent Canvas

L4｜HOW IT CHANGES
意图怎样随着创作变化？
Evolving Intent Loop

L5｜HOW IT SURVIVES
意图怎样跨阶段不丢？
Cross-stage Constraint Artifact
```

现有研究已经覆盖得相当完整。

# 3｜十元到底和它们是什么关系

## 十元不能承担全部结构

十元不应该代替：
- Goal；
- Object；
- Constraint；
- Attribute；
- Reference；
- Stage；
- Evidence。

这些仍然应该由普通结构字段承担。

例如：

```
Goal = 监狱压迫感
Constraint = 方志敏身份不可改变
Property = 冷硬空间 / 铁窗光
Choice = 保留人物温度
```

这些不是十元。

---

## 十元可能真正承担的是 Relation Grammar

例如：

```
Goal A
  ↓
【克】
Goal B

Constraint C
  ↓
【补】
Goal A
```

也就是说：

> **十元不是“节点本身”，更可能是节点之间的关系语法。**

---

# 4｜目前最值得保留的十元映射

## 1. 生 / 克 / 补
对应：
**Typed Relation**

不是简单：
`A — B`

而是：
- A 增强 B；
- A 压制 B；
- A 补偿 B；
- A 改道 B。

这是与普通 concept graph 最直接的比较点。

---

## 2. 主 / 次
对应：
**Priority / Hierarchy**

当两个正确意图冲突：

> 到底谁必须保留？

现有 graph 有连接，但不一定把“冲突时谁让位”作为第一等字段。

---

## 3. 体量 / 强度
对应：
**Relation Strength / Intent Weight**

例如：
- ZX 8；
- NZ 3。

论文里暂时不要宣称数字天然客观。

应理解为：
> 一个可检验的强度标注方案。

---

## 4. 动态链
对应：
**Temporal Relation Transition**

不是：
`A 和 B 什么关系`

而是：

```
State0
A 克 B

↓ 创作事件

State1
B 被削弱 / C 补 A

↓ 决策

State2
A → C
```

这能和 Evolving Intent Loop 直接对照。

---

## 5. 起点 → 变化 → 终点
对应：
**Intent State Transition**

这是十元当前最适合进入机器表示的一部分。

---

# 5｜现在最关键的差异假设

现有外部方法已经很强。

所以不能比较：

> “普通 Prompt vs 十元”

因为这会挑一个太弱的 baseline。

真正公平的比较应该是：

### B0｜Natural Language
普通自然语言创作说明。

### B1｜Attribute / Taxonomy
结构化变量表。

### B2｜Concept Graph
普通 node + interpretable edge。

### B3｜Intent Graph
Goal / Constraint / Choice
+ Priority / Rationale / Dynamic Trace
但不用十元。

### B4｜Ten-Yuan Relation Graph
在 B3 上额外增加：
- 生 / 克 / 补；
- 主 / 次；
- 强度；
- 动态链。

真正的问题：

> **B4 相比 B3 到底有没有新增预测 / 控制价值？**

只有这里成立，
才能说十元对“创作意图结构化”有额外贡献。

# 6｜5 轮研究路线

## R1｜现有方法谱系
回答：

> 别人到底有哪些结构化方法？

任务：
- 找 10–20 个代表系统；
- 抽统一字段；
- 建：
  `Node / Edge / Constraint / Priority / Rationale / Time / Stage / Evidence`
  比较表。

输出：
**社会已有结构总谱。**

DONE 条件：
新论文基本能落入已有类别，不再不断冒出新类别。

---

## R2｜字段级拆解
不看论文名字，直接拆 schema。

例如：

| 方法 | Node | Edge | Priority | Rationale | Time | Constraint | Editable |
|---|---|---|---|---|---|---|---|
| Taxonomy | 属性 | 组合规则 | 弱 | 无 | 弱 | 强 | 是 |
| ToMigo | purpose/content/style | explanation edge | 中 | 有 | 中 | 中 | 是 |
| DesignerlyLoop | framing/constraint/strategy | reasoning link | 中 | 强 | 强 | 强 | 是 |

目标：

> 看清“社会已经解决到字段哪一层”。

---

## R3｜十元映射
把十元逐项放进社会 schema：

- 十元端点是什么？
- 生克补属于 edge 还是 state transition？
- 主次属于 priority 还是 hierarchy？
- 体量属于 weight 还是 confidence？
- 动态链属于 temporal graph 还是 process trace？

输出：

> **哪些是同构，哪些是真新增，哪些根本不该塞进去。**

这一轮特别重要：
**禁止硬映射。**

---

## R4｜差异 / GAP 审计
逐条问：

- 社会已有完全一样的吗？
- 只是换名字吗？
- 十元更细还是只是更复杂？
- 能产生什么原有 graph 做不到的操作？

最终只保留 1–3 个可能增量。

当前候选：
1. typed relational semantics；
2. priority under conflict；
3. temporal relation transformation。

但这只是初始假设，不冻结。

---

## R5｜验证设计
最终不能用“解释得通”。

做 B0–B4 对照：

```
B0 Natural Language
B1 Attribute Structure
B2 Concept Graph
B3 Generic Intent Graph
B4 Ten-Yuan Relation Graph
```

任务可以选：
- 预测下一轮 ACCEPT / REWORK / REJECT；
- 预测哪个意图会被保留；
- 多轮编辑中保持创作关系；
- 发生冲突时选对优先级；
- 跨阶段恢复意图。

如果 B4 ≈ B3：

> 十元没有证明增量。

如果 B4 稳定优于 B3：

> 才可以说十元的关系语法提供额外价值。

---

# 7｜当前暂时判断

外部方法已经覆盖：

- 属性结构化；
- 概念图；
- reasoning canvas；
- evolving intent；
- cross-stage constraint。

所以十元最可能的位置不是：

> **Creative Intent Structure**

而是它里面更小的一层：

> **Creative Intent Relation Grammar**

即：

```
普通创作意图结构
+
十元关系语法
=
关系类型 + 主次 + 强度 + 动态变化
```

这个定位比“十元能理解创作意图”更窄，
但也更容易真正验证。
