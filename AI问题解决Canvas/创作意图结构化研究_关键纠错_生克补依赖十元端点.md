# 创作意图结构化研究｜关键纠错：生克补不得脱离十元端点单独评价 v1.0

> 权限：本文件覆盖 R3–R5 中任何把“生 / 克 / 补”当作脱离十元端点的独立 Relation Type 进行比较的表述。
>
> 原因：十元正本已经明确，关系启动必须以前置端点判断为条件。

# 1｜正确层级

错误拆法：

```
Node A
Node B
↓
直接判断 Relation Type = 生 / 克 / 补
↓
再和 support / conflict / compensate 比
```

正确拆法：

```
对象 A
↓
冻结对象层 / 阶段
↓
判断 A 的十元端点（单十元或主/次十元）

对象 B
↓
冻结对象层 / 阶段
↓
判断 B 的十元端点（单十元或主/次十元）

A十元端点 + B十元端点
↓
检查该十元组合是否允许/候选某类生克补关系
↓
再检查真实作用机制
↓
目标变量是否被改变
↓
方向是否唯一
↓
第三因素 / 反向解释排除
↓
关系才能正式启动：
生 / 克 / 补 / NONE / AMBIGUOUS
```

所以：

> **生 / 克 / 补不是脱离十元的三种通用关系词。**
>
> 它们是建立在已判定十元端点之上的关系判断。

# 2｜十元关系的最小结构

一条十元关系至少是：

```
对象A
+ A十元端点
+ 对象B
+ B十元端点
+ 当前阶段
+ 作用机制
+ 被改变的目标变量
+ 方向
+ 生/克/补判定
+ E关系作用量
+ 变化前后证据
+ 第三因素排除
```

因此不能只拿：

```
生 vs support
克 vs inhibit
补 vs compensate
```

做一一词汇对照。

这种对照最多只能帮助理解表面作用语义，
不能评价“十元关系系统”本身。

# 3｜社会方法应该和什么比较

公平比较单位必须从“一个关系词”升级成“整个关系判定结构”。

## Generic Dynamic Intent Graph

```
对象 / Goal / Constraint
+ semantic labels
+ generic relation
+ mechanism
+ affected variable
+ priority
+ rationale
+ state / transition
+ evidence
```

## Ten-Yuan Dynamic Relation System

```
对象层冻结
+ 十元端点判定
+ 主/次 + T/M/C
+ 十元端点组合
+ 生/克/补关系启动条件
+ mechanism
+ target_variable
+ E关系作用量
+ 动态链阶段审核
+ NONE / AMBIGUOUS
+ 第三因素 / 反向解释测试
```

真正比较的是：

> **“十元端点 + 关系启动规则 + 动态链”这个整体，是否比 Generic Dynamic Intent Graph 多提供稳定预测 / 控制价值。**

不是：
> “生这个词是否比 support 更新。”

# 4｜对 R3 的修正

R3 中“生/克/补 = Typed Effect Relation”的说法必须改成：

> **Ten-Yuan-conditioned Relation**
>
> 即：由十元端点条件化的关系判定。

十元端点不只是旁边附带的 semantic annotation；
它们是生克补关系能否成立的**前置条件之一**。

因此 B4 不能被拆成：

```
Generic Graph
+ 三个新 relation labels
```

而应是：

```
Generic Graph
+ Ten-Yuan Endpoint Layer
+ Ten-Yuan Relation Activation Rules
+ Dynamic Chain
```

# 5｜对 R4 的修正

R4 原先单独审：
“生/克/补是否只是 support/inhibit/compensate 换名”

这个审计只能保留为：
**词义表面相似性检查**

不能作为十元关系系统的新增性结论。

R4 真正需要审的是：

1. 十元端点是否提供 Generic Intent Graph 没有的稳定结构分类；
2. 端点组合是否限制了关系候选空间；
3. 生/克/补的关系启动规则是否减少误判；
4. target_variable + mechanism + E 是否带来额外操作能力；
5. 动态链是否在端点变化后强制重新审核关系，从而提高预测/控制。

# 6｜对 R5 的修正

B4 仍然可以和 B3 对照，
但 B4 的实验处理必须是完整整体：

```
B4 =
B3
+ 十元端点判定
+ 主/次/T/M/C
+ 端点组合约束
+ 生克补启动规则
+ target_variable / mechanism / E
+ 动态链重新审核
```

禁止：

- 只给 B3 加“生/克/补”三个词就称 B4；
- 不判十元端点直接判生克补；
- 已知关系结果后反推端点；
- 用生克补单独和 generic relation label 做性能结论。

# 7｜新的核心研究问题

修正后，方向 3 更准确的问题是：

> **把创作对象先映射到十元结构端点，再依据端点与作用证据建立生克补及动态链，是否比通用动态意图图更能保持和预测创作者的关系性意图？**

这里真正被验证的是：

> **十元结构 + 生克补 + 动态链的整套关系表示**

而不是三种关系孤立地被验证。

# 8｜状态

CORRECTION_FROZEN

后续教学和实验统一遵守：

> **先十元端点，后生克补；先对象层和阶段，后关系启动；关系不得脱离端点单独成立。**
