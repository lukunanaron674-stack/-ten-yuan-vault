# 候选 11｜十元创作意图结构能否预测真实创作选择

## 当前一句话

> **如果先把创作意图写成“主次 + 生克补 + 强度 + 动态链”，是否比只看画质或普通文字要求，更能预测创作者最终会 ACCEPT / REWORK / REJECT？**

来源：
- 674-119｜创作意图关系化表示：十元 × 动态链
- 674-122｜真实评价：ACCEPT / REWORK / REJECT
- 674-278｜USER→SOCIETY 社会价值分中心

状态：**CANDIDATE / NOT FROZEN**

---

## 这题到底在研究什么

普通评价往往问：

> 这张图好不好？

但真实创作里，创作者最终做的是：

- **ACCEPT**｜接受，继续生产；
- **REWORK**｜方向保留，修改后继续；
- **REJECT**｜这次结果/方向不再继续。

而 REJECT 不等于“画得差”。

一个结果可能：
- 技术质量高；
- 画面漂亮；
- 没有明显错误；

但仍然因为：
- 创作关系错了；
- 主次错了；
- 情绪方向错了；
- 本来应保留的关系被抹掉；
- 叙事目标被替换；

而被否决。

因此问题变成：

> **能不能把“创作者脑子里为什么要/不要”的关系结构显式化，并用它预测真实决策？**

---

## 十元在这题里的位置

十元不是先验正确答案，而是**候选的创作意图关系表示法**。

可记录：

- 主十元 / 次十元；
- 生 / 克 / 补；
- 强度；
- 起点 → 变化 → 终点；
- 动态链；
- 哪些关系必须保留；
- 哪些关系允许转向。

它不是为了“解释完作品后显得很合理”，而是要进入**事前规则 / 后续预测**。

---

## 《方志敏》为什么适合当第一案例

《方志敏》已有真实创作过程，不是为了论文临时造案例。

项目中已经发生过：
- 监狱压迫；
- 日常暖意；
- 战友情；
- 《清贫》插叙；
- 人物关系主次；
- 某些镜头“漂亮但不对”的否决；
- 叙事情绪与关系结构的反复调整。

因此可以把既有创作选择整理成：

```
事前/早期创作意图
→ 十元 / 动态链表示
→ 候选镜头/方案
→ 隐藏最终真实选择
→ 预测 ACCEPT / REWORK / REJECT
→ 揭盲
```

---

## 最小实验

### 组 A｜只看画面质量
判断：
- 好不好看；
- 技术有没有错误；
- 完成度够不够。

### 组 B｜普通自然语言创作要求
例如：
- “监狱压迫，但保留人物温度”。

### 组 C｜十元 / 动态链结构
例如：
- 主 / 次；
- 生克补；
- 强度；
- 起点→变化→终点；
- 必须保留关系。

然后统一预测：

```
ACCEPT / REWORK / REJECT
```

最后和真实创作决策揭盲比较。

---

## 如果什么结果出现，这题才真正有价值

### 支持
如果 C 组在未见最终答案前：
- 更准确预测真实选择；
- 尤其更能识别“画面很好但创作意图不对”的 REJECT；
- 并且不是靠泄露答案；

那么可以说：

> **结构化创作意图表示，对真实创作选择具有增量预测价值。**

### 不支持
如果 C 与普通文字没有明显差异，或者只能事后解释：

> 十元在这个任务上没有证明额外价值。

这也算有效研究结果。

---

## 最大风险

### 1｜事后合理化
先知道用户选了什么，再用十元解释。

→ 禁止当验证证据。

### 2｜自产自测
同一个人制定规则、挑案例、打分、解释结果。

→ 必须做隐藏答案、固定规则、最好有独立评价者。

### 3｜样本太少
只拿 3–5 个漂亮案例。

→ 只能当案例分析，不能说有预测能力。

- 和 122 的真实评价自然接上；
- 研究问题小于“证明十元理论正确”，更适合本科阶段；

# 候选 12｜F 长流程可靠生产：面向独立创作者与小型创作团队的可控 AI 创作生产协议

## 当前一句话

> **能否构建一套面向独立创作者与小型创作团队的长流程 AI 创作生产协议，使创作者意图在多轮 Agent / AIGC 生产中持续保持，同时让自动化权限、结果验收、资产状态与失败恢复都处于可控、可追踪状态？**

来源：
- 674-123｜F-LONGRUN 长流程 Agent 可靠生产与恢复
- 674-278｜USER→SOCIETY 社会价值验证

状态：**CANDIDATE / NOT FROZEN**

## 这题到底研究什么

不是研究“AI 能不能 24 小时自动跑”。

真正的问题是：

> **当 AI 进入长流程、跨工具、多阶段创作后，怎样让它持续推进，却不把创作者的意图、控制权、资产状态和判断依据弄丢？**

核心对象：

```
Intent / Constraint
→ Agency / Escalation
→ Evaluation
→ Recovery / Production
```

对应四层：

1. **Intent / Constraint｜意图与约束**
   - 创作者到底想保留什么；
   - 哪些内容 LOCK；
   - 哪些允许 FLEX；
   - 多轮生产中如何避免意图漂移。

2. **Agency / Escalation｜AI 权限与人工接管**
   - 哪些任务可以 AUTO；
   - 哪些需要 CHECKPOINT；
   - 哪些必须 USER_REVIEW；
   - 哪些情况必须 STOP。

3. **Evaluation｜结果与过程验收**
   - 是否真的完成；
   - 是否保持创作意图；
   - 是否违反约束；
   - 中间轨迹是否可靠。

4. **Recovery / Production｜状态与恢复**
   - 状态是否丢失；
   - 失败是否可续；
   - 资产是否可追踪；
   - path / SHA / seed / manifest / receipt 是否完整；
   - 中断后能否恢复到正确节点继续生产。

## 面向谁

- 独立 AI 创作者；
- 2–20 人的小型动画 / 视觉团队；
- 没有大型基础设施的个人工作室；
- AI 动画 / AIGC 视觉生产团队；
- 技术美术 / AI Pipeline 岗位。

## 和社会已有方法的边界

不能把以下内容说成原创：
- Agent；
- HITL；
- workflow / orchestration；
- checkpoint / rollback / retry；
- provenance；
- benchmark / TEVV。

本候选真正可能新增的是：

> **把这些通用方法整合并操作化到长期视觉创作场景中，使“创作者意图保持 + AI 权限控制 + 真实评价 + 失败恢复”形成一条统一生产链。**

## 最小论文切口

本科论文不需要证明整个系统。

可以压成：

> **长流程 AI 创作中，结构化的意图约束、人工升级门与状态恢复机制，是否能降低多轮生产中的意图漂移与返工？**

### 对照 A｜普通流程
- 聊天；
- 文件夹；
- 人工记忆上下文；
- 需要时再返工。

### 对照 B｜可控长流程协议
- Intent / Constraint；
- AUTO / CHECKPOINT / USER_REVIEW / STOP；
- Outcome / Intent / Trajectory Evaluation；
- state / evidence / recovery / manifest。

### 可以测
- 创作意图丢失次数；
- 错误资产调用次数；
- 人工解释/重复说明次数；
- 返工次数；
- 中断恢复时间；
- 用户审核次数；
- 最终任务完成率。
