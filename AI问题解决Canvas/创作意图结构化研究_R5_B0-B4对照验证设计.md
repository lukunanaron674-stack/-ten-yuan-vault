# 创作意图结构化研究｜R5 对照验证设计 v1

> 目标：设计一个能真正保住或杀死“十元关系层”的实验。
>
> 核心原则：
> **先预测，再揭盲。**
>
> 禁止：
> 已知创作者最后怎么选 → 再用十元解释 → 宣称有效。

---

# 0｜唯一研究问题

> **在已经存在一个强 Generic Dynamic Intent Graph（B3）的前提下，加入十元关系编码（B4）是否仍能稳定提升对真实创作决策的预测与约束保持？**

如果不能：
> 十元在该论文方向没有额外增量。

如果能：
> 才保留“十元关系层具有增量预测价值”的候选主张。

---

# 1｜五组对照

## B0｜Natural Language
输入：
- 当轮创作说明；
- prompt / notes；
- 当前图像/版本；
- 不做结构化。

目标：
代表普通 AI 协作。

---

## B1｜Attribute Structure
输入：
- Goal
- Style
- Color
- Character
- Scene
- Constraints
- 可变/不可变属性

目标：
代表属性化 / taxonomy 方法。

---

## B2｜Static Concept Graph
输入：
- Goal / Choice / Constraint / Property
- supports / conflicts_with / depends_on / preserves / replaces
- 静态 node-edge 图

不提供：
- relation history
- transition
- 十元

目标：
代表当前较强 Concept Graph。

---

## B3｜Generic Dynamic Intent Graph
在 B2 上增加：
- decision_priority
- LOCK / FLEX
- rationale
- state
- transition
- relation history
- evidence
- affected variable

关系词使用通用语汇：
- support
- inhibit
- conflict
- compensate
- preserve
- replace
- depend_on

目标：
**最强非十元 baseline。**

---

## B4｜Ten-Yuan Dynamic Relation Layer
B3 全部保留，再增加：

### Node semantic annotation
- ten_yuan_semantic
- primary / secondary
- T structural occupancy
- M stage salience
- C confidence

### Typed relation
- 生 / 克 / 补
- mechanism
- target_variable
- E effect magnitude

### Dynamic relation
- continue
- strengthen
- weaken
- reverse
- fade
- shift
- new endpoint

目标：
测试十元关系层是否在强 B3 上仍有增量。

---

# 2｜实验单位：一个“真实创作决策窗口”

每个 case 必须来自真实创作过程，不是为了实验临时编的题。

一个 case 定义：

```
t0｜当前创作目标/约束
+
当前可见版本/候选图
+
此前有限历史
──────────────
隐藏 t1
──────────────
t1｜创作者真实下一步：
ACCEPT
REWORK
REJECT
```

同时记录：

- 哪些约束被保留；
- 哪些约束被牺牲；
- 修改对象；
- 修改方向；
- 真实理由；
- 是否产生新的意图；
- relation 是否发生变化。

# 3｜样本设计

## Phase A｜内部开发集
来源：
- 《方志敏》
- 黎黎隆
- 现有 PASS / FAIL / REWORK
- 角色 / 场景 / 分镜 / H3 审核历史

数量：
**30–50 case**

用途：
- 调 Schema；
- 校准字段；
- 发现 failure family；
- 确认 B0–B4 都能正常运行。

禁止：
> 用 Phase A 得分当社会有效性结论。

---

## Phase B｜内部留出集
从同一创作者历史中抽出：
**10–20 case**

要求：
- R5 schema 冻结后再揭盲；
- 不允许根据结果回改编码规则再重测同一批。

用途：
- 检查是否只是过拟合开发集。

---

## Phase C｜外部创作者
至少：
**1 位独立创作者 + 对方自己的真实项目**

目标：
**10–20 case**

要求：
- 不是让对方评价你的作品；
- 使用对方自己的目标、参考、版本、修改和真实选择；
- 在不知道最终决策时完成 B0–B4 预测。

这是从 USER_VALIDATED_INTERNAL 向 EXTERNAL 的最低门。

# 4｜预测任务

每个 B 组都必须输出完全相同的任务。

## Task 1｜Decision Prediction
预测：
- ACCEPT
- REWORK
- REJECT

主指标：
**Macro-F1**
因为三类可能不均衡。

辅指标：
- Accuracy
- per-class F1
- confusion matrix

---

## Task 2｜Preserve Prediction
预测：
> 下一轮哪些约束会被保留？

指标：
- Precision
- Recall
- F1

---

## Task 3｜Sacrifice Prediction
预测：
> 冲突时哪些约束会被牺牲 / 放宽？

指标：
- Precision
- Recall
- F1

---

## Task 4｜Modification Target
预测：
> 真正被改的是哪一个对象 / 属性 / 关系？

指标：
- top-1 accuracy
- top-2 hit rate

---

## Task 5｜Relation Transition
仅 B3/B4 重点比较：

预测：
- continue
- strengthen
- weaken
- reverse
- fade
- shift

指标：
- Macro-F1

---

# 5｜真正检验十元的主比较

不是：

```
B4 vs B0
```

而是：

```
B4 vs B3
```

因为 B3 已经有：
- typed relation
- priority
- rationale
- dynamic history
- affected variable

所以只有 B4 仍然提升，才说明十元编码有额外价值。

---

# 6｜最低成功门槛

不预先宣称某个百分点必然代表科学显著。

但为了避免“涨 1 个点也算赢”，先冻结工作门：

## Internal Holdout
至少满足：

1. B4 在主指标 Macro-F1 上 > B3；
2. 提升不是只来自一个类别；
3. Preserve / Sacrifice 至少一个任务同步改善；
4. Failure family 不出现明显代价扩大。

## External Creator
至少满足：

1. B4 不低于 B3；
2. 至少一个主任务有稳定正增量；
3. 不需要重新解释/重写十元规则才能适应第二创作者。

若只在自己项目有效：
> 仍停在 USER_VALIDATED_INTERNAL。

---

# 7｜杀死十元的明确 STOP 条件

出现任一情况，就停止把十元作为论文新增性：

### STOP-1
B4 ≈ B3，差异微弱且不稳定。

### STOP-2
B4 只在开发集提升，留出集消失。

### STOP-3
B4 只能通过事后知道结果再调整编码。

### STOP-4
十元编码导致更高解释复杂度，但预测没有改善。

### STOP-5
跨创作者后需要重新定义十元关系才能成立。

### STOP-6
提升主要来自 B3 已有字段，而不是十元增量。

结论写法：

> **十元关系编码未显示超越通用动态意图图的稳定增量。**

这仍然是有效论文结果。

---

# 8｜保住十元的最低条件

只有同时出现：

1. B4 > B3；
2. 留出集仍成立；
3. 至少一位外部创作者仍成立；
4. relation transition / preserve / sacrifice 中至少一个任务明显受益；
5. 编码规则在测试前冻结；

才允许写：

> **十元关系编码在动态创作意图建模中显示出初步增量预测价值。**

仍不能写：
- 普适有效；
- 已证明更优；
- 能理解创作者内心；
- 十元是新的通用图理论。

---

# 9｜编码盲法

每个 case 按以下顺序：

```
1. 截断在 t0
2. 隐藏 t1
3. 生成 B0–B4 输入
4. 冻结五组预测
5. 记录 prediction timestamp / version
6. 揭晓 t1
7. 对比真实结果
8. 记录 failure family
```

严禁：
- 看到 t1 后回填 rationale；
- 看到 t1 后改十元端点；
- 因为预测错就重编码同一个 case；
- 把后验解释计入预测分。

---

# 10｜防自产自证

至少采用以下三项：

## A｜时间遮蔽
预测时只能看到 t0 之前信息。

## B｜编码与评分分离
最好：
- 一人/一轮负责结构化；
- 另一轮脚本负责自动统计；
- 真实 label 来自历史记录。

## C｜强 Baseline
必须保留 B3。

## D｜外部 case
最终至少一位第二创作者。

---

# 11｜Failure Family

每次错不只记错/对。

至少分类：

- FF01｜技术质量误导
- FF02｜约束遗漏
- FF03｜创作意图漂移
- FF04｜审美否决不可预测
- FF05｜关系类型误判
- FF06｜主次 / decision_priority 混淆
- FF07｜T/M/E/C 混淆
- FF08｜transition 误判
- FF09｜后验解释污染
- FF10｜外部创作者迁移失败

真正有价值的是：

> B4 到底减少哪一种 failure？

---

# 12｜最小本科版本

如果学校论文只有约 5000 字，不需要把 Phase A/B/C 全部做完。

最小可交版本：

## 数据
30 个历史真实 case。

## 对照
只保留：
- B0 Natural Language
- B3 Generic Dynamic Intent Graph
- B4 Ten-Yuan Dynamic Relation Layer

## 任务
只测：
1. ACCEPT / REWORK / REJECT
2. Preserve / Sacrifice

## 结论
只回答：

> **结构化动态意图关系是否比普通自然语言更能预测真实创作决策？十元关系编码是否在通用动态关系图上进一步提供增量？**

这样已经足够形成一篇完整本科论文。

---

# 13｜如果结果分三种

## 结果 A｜B3 > B0，B4 ≈ B3
最可能、也很有价值：

> 动态结构化意图有效，但十元没有额外增量。

论文仍成立。

---

## 结果 B｜B3 ≈ B0，B4 ≈ B3
说明：
> 结构化方法对这批任务没有预测价值。

也成立：
> 复杂结构可能只是管理负担。

---

## 结果 C｜B3 > B0，B4 > B3
最强结果：

> 动态关系结构有效，且十元编码提供额外增量。

这时才值得继续做更大样本和跨创作者验证。
