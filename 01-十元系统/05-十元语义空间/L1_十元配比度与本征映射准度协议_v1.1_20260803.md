# L1｜十元配比度与本征映射准度协议 v1.1

## 0｜双指标总则

正式实例分析必须同时回答两类问题：

```text
十元配比度：这个对象由哪些十元共同构成，各占多少？
本征映射准度：这个对象单独看，有多像某个十元本身？
```

两者必须分字段保存。前者是构成比例，后者是原型相似度。

## 1｜十元配比度

机器字段：

```yaml
ten_yuan_composition_ratio:
  x: 0
  z: 0
  n: 0
  zn: 0
  nz: 0
  xn: 0
  nx: 0
  zx: 0
  xz: 0
  x并z: 0
normalization: sum_100
```

规则：

- 十项总和必须等于100；
- 表示当前尺度下各十元对该实例的相对构成份额；
- 主十元是配比最高者，副十元是第二高者；
- 配比高不等于一定更接近该十元原型，只表示在该对象内部占比更高。

示例：

```text
外翻帘幕刘海：zx 77%／n 23%
```

这回答的是“它由什么构成”。

## 2｜单十元本征映射准度

机器字段：

```yaml
ten_yuan_archetype_accuracy:
  target: zx
  score: 0-100
  domain: 发型
  scale: 刘海结构
  model:
  evidence_confidence:
  audit_status: provisional | evidence-tested | canonical
```

规则：

- 每个目标十元独立评分0–100；
- 不要求十个准度相加等于100；
- 回答“它有多像该十元本体／原型”；
- 只能在相同领域、相同分析尺度、相同评分规程内排序；
- 同分共享名次，后续名次采用竞赛排名法，例如1、1、3；
- 准度必须由本体判据、可观察证据、反证和最近邻差异支持。

示例：

```text
外翻帘幕刘海：zx本征映射准度 84/100
十元内排名：zx 第2/6
```

这回答的是“它像不像zx本身”。

## 3｜三个数字不得混写

| 字段 | 回答的问题 | 是否要求总和100 |
|---|---|---:|
| 十元配比度 | 对象内部由各十元构成多少 | 是 |
| 本征映射准度 | 对象对单个十元原型有多像 | 否 |
| 证据置信度 | 当前证据是否足够可信 | 否 |

此外，体量回答结构大小，纯度回答主结构受混入程度，也不得冒充上述字段。

## 4｜十元内排序

每个十元必须可生成独立排行榜：

```yaml
ten_yuan_ranking:
  target: zx
  domain: 发型
  scale: 刘海结构
  ranking_method: competition_rank
  entries:
    - item:
      archetype_accuracy:
      rank:
      evidence_status:
```

排序只使用本征映射准度，不使用配比度、体量或证据置信度替代。

## 5｜类型继承映射度

`is-a狭义`的五行轴继承仍单独保存：

```yaml
axis_inheritance_degree: 100
ten_yuan_inheritance_degree:
  同行阳端: 100
  同行阴端: 100
```

这里的两个100表示完整继承五行两端，不是实例配比，也不是本征准度排名。

## 6｜刘海98种的当前迁移状态

### 6.1 配比度保留

当前保留既有双项迁移模型：

```text
主十元配比度＝旧纯度
副十元配比度＝100－旧纯度
其余八项＝0
model＝provisional-two-pole-normalized
```

### 6.2 本征准度种子

第一版本征准度以旧纯度作为种子：

```text
主十元本征映射准度＝旧纯度
model＝legacy-purity-seed
visual_archetype_audit＝pending
```

因此当前配比主值与本征准度可能暂时数值相同，但语义不同、字段不同、排序用途不同。逐项视觉复审后，两者允许并且通常应当分离。

## 8｜失败条件

- 将配比度和本征映射准度写成同一字段；
- 用本征准度凑配比总和；
- 用配比度直接替代十元内排名；
- 不限定领域和尺度就跨库排名；
- 没有本体判据和可观察证据却标记为canonical；
- 排行榜不是由本征映射准度生成；
- 把类型继承度、实例配比度和本征准度混为一谈。
