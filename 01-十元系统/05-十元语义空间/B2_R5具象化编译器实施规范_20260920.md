# R5 B2｜抽象→具象编译器候选 v0.1（2026-09-20）

**性质：可执行结构检查器 + LLM生成提示协议；不是已经训练好的语义模型，不是独立评分器，也没有产生新的封闭盲测样本。**

## 输入与正本

- R4/L1维持原有正本，不修改五轴映射与十元端点。关系只读取同目录 B1_R5关系输入审计_20260920.json 的30条有向记录；该文件是非正本审计叠加层，不能解除旧机制冻结。
- 输入见 B2_R5示例输入_20260920.json；六字段预测及事件DSL见 B2_R5示例预测_20260920.json。
- 任何五轴轴级“金克木”都**不能**自动转换为任意端点间的克。必须传精确 relation_id，例如 克_xn_zx。
- endpoint_redefinition_freeze、research_active：strict 模式阻断；research 模式仅作候选且不得计入正式关系成绩。legacy_mechanism_documented：仅表明旧文档已有机制表述，真实案例仍须逐项语义取证。

## 两段工作流

第一段（模型生成）：
1. 录入 INPUT：题目ID、精确关系ID、世界规则、前情、目标、人物、初始状态、端点证据、观察者已知事实。预测时**不放入GOLD及真实后续**。
2. 运行 prepare，复制生成的提示给 GPT、Qwen 或本地模型；只要JSON预测，不允许模型自己写出后续答案、评分或修改关系。
3. 生成六字段：carrier、target、actions、mediators、state_change、visual_frame；增加 variable_binding、variables、causal_chain、observer_state 约束。
4. actions逐项写 actor/verb/object/tool/preconditions/effects/observable_fact_ids；因果链按有向边记录，可分支而非强迫纯线性；单帧指定 moment_id/viewpoint_actor/visible_fact_ids。

第二段（程序校验）：
1. 校验关系ID、状态门禁、必要字段、角色引用、状态前后差、关键状态是否被动作效果生成、依赖图是否有环、动作前置条件有无先行依据、图像瞬间是否引用未来或不属于该观察者的已知事实。
2. 校验通过只代表**结构候选有效**。人物意图、五轴语义是否成立、变量命中、隐藏事实、真实视觉可见性与场景因果仍须独立评审及对照样本。
3. 进入B3后，预测文件落盘和哈希冻结，才允许独立释放 GOLD。只在全新封闭集统计六字段分、因果边F1、变量F1、抽象残留；当前 SEALED BLIND 仍为0/100。

## 命令

在仓库根目录运行，需要 Node.js 20+，只用Node内置模块：

~~~bash
node tools/r5_compiler_cli_v0_1.mjs prepare --case 01-十元系统/05-十元语义空间/B2_R5示例输入_20260920.json --mode strict --out /tmp/r5_prompt.txt
node tools/r5_compiler_cli_v0_1.mjs validate-prediction --case 01-十元系统/05-十元语义空间/B2_R5示例输入_20260920.json --pred 01-十元系统/05-十元语义空间/B2_R5示例预测_20260920.json --mode strict
node --test tests/r5_compiler_v0_1.test.mjs
~~~

Windows 无 /tmp 时，把输出路径改为当前目录下的 r5_prompt.txt。

## 已知边界与B3验收

- 仅靠字符串状态和图依赖不能证明每个动作在真实世界可实施。特别是同一变量在平行分支上的竞态、观察者“已知”与真正“可见”的区别，均须场景语义与分镜审核。
- 当前的 observable_fact_ids 由生成器自报，结构校验只能阻止未定义、未来与明确禁止访问的引用，不能防止模型虚构新事实；B3需用独立GOLD和视觉对照验证。
- B1对 Z/ZN 采取保守全局冻结，不应从旧机制卡出现“locked”就自动解冻。
- 先用20例独立Pilot验证可复现性、双评分者一致性、不同题材与五轴关系覆盖，再开正式100例。Pilot被用于调规则后不能重复用于正式测试。
