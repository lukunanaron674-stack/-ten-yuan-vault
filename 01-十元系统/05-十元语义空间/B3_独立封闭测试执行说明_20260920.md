## 一、权限边界：须由真正不同的执行身份保证

独立作者/评分者将真实 GOLD 放入预测者无法访问的外部私有存储，不能放在本仓库、同一可读取的目录、同一账号的另一 GitHub 分支、或预测模型可以调用的相同连接器里。两个聊天框不是权限边界。本仓库只放工具、20个任务规格和合成烟雾测试，不上传真实 GOLD。

预测者只能访问新写的 INPUT、固定 B1关系规则和 B2编译器，并向不可随意覆盖的 exchange 提交预测。评分者先封存 GOLD，后读取已经锁定的预测。两名评分者分别给分，双方不得查看对方未提交的评分，也不应是题目作者或预测者。

程序使用的作者ID、评分者ID、时间戳和哈希是可审计字段，不是防伪身份凭证；普通文件独占创建只能防止意外覆盖，不能阻止有相同系统权限的进程删除文件。正式部署须由不同账号、进程权限、访问日志和可信归档建立外部隔离。公开案例可能有模型训练记忆污染，新写题材与独立作者能降低风险，但不等于绝对证明模型从未见过答案。

## 二、如何独立准备20例 Pilot

分配表：B3_Pilot20分层计划_20260920.json。它从 B1 的15条未被全局冻结、已有机制文件的十元有向记录中安排20个题槽，并将各题分配到不同原创场景类别。B1关系仍属项目内部条件，不表示经过外部关系正确性测试。

每题由独立作者在预测之前同时完成 INPUT 和 GOLD：

INPUT 沿用 B2_R5示例输入_20260920.json 的字段：case_id、relation_id、scene、goal、actors、focus、world_rules、initial_state、known_facts、endpoint_evidence。对预测者只放 INPUT，不放参考后续或评分意见。

GOLD 仅存独立评分者的私有环境，至少包含以下字段：case_id、source_type 为 original_independently_authored、author_id、authorship_attested true、gold_preexisting true、predictor_has_no_gold_access true、reference_continuation、world_constraints 数组、core_variables 数组、causal_edges 数组、valid_alternatives 数组、forbidden_shortcuts 数组。

独立作者要在预测前明确真实后续、关键事件依赖和世界约束；不能看见预测后再修改正确答案。除作者原定结局的匹配度外，评分者也须承认不违背世界条件、能够实现同一指定关系的有效替代机制。不得把“不同于参考作者选择的道具”直接判为具象化失败。

## 三、执行命令（在仓库根目录，Node.js 20+）

独立评分者提前封存 GOLD，第三个参数是预测者完全没有读取权限的路径：

    node tools/r5_b3_evaluator.mjs seal /independent/INPUT.json /independent/GOLD.json /private-r5-vault

预测者只拿到 INPUT，在新独立会话中用 B2 编译器输出六字段、现实变量、动作链、状态差与最小单帧后冻结：

    node tools/r5_b3_predictor.mjs freeze ./INPUT.json ./PRED.json /exchange PREDICTOR_ID

评分者读取私人 GOLD 和 exchange 中已锁定的预测，分别先完成两张独立评分卡，之后聚合：

    node tools/r5_b3_evaluator.mjs score R5-PILOT-001 /private-r5-vault /exchange /private/rater1.json /private/rater2.json

评分卡字段：case_id、rater_id、independent true、six_fields（carrier/target/actions/mediators/state_change/visual_frame，均0到2分）、causal（correct/predicted/gold三个非负整数）、variables（同上）、abstract（residual_clauses/total_clauses）、visual.result（PASS/FAIL/AMBIGUOUS）、notes。

同一字段两名评分者相差大于1分，或视觉结果不一致，程序自动标记 adjudication_required；第三方裁决前，不得宣布该题取得最终分数。因果边和变量采用 F1；六字段按两名评分者均分记录，抽象残留率使用明确定义的关键动作子句比例。

## 四、自动检查的范围及已知局限

- B2负责精确关系ID、冻结门禁、结构字段、动作前置状态、因果循环、最终状态、画面未来事实/观察者明显不可见信息引用。它无法证明角色意图、真正的现实可行性或五轴语义正确性。
- B3负责封存时间先于预测、INPUT与GOLD一致的输入哈希、预测和GOLD的原文标准化哈希、锁定文件独占写入、评分身份字段与范围、评分分歧和数值汇总。程序仍不能判断作者声明是否真实，也不能从六字段文本自动发现所有观察者泄漏。
- 视觉验证须在事件文本通过独立审核后，另做 POS / NEAR / REVERSE 图像对照，并允许 PASS / FAIL / AMBIGUOUS；本轮没有生成或审查真实图片。
- tests/r5_b3_sealing_v0_1.test.mjs 中的 MOCK GOLD 与 MOCK RATER 刻意写在本地临时目录，属于可公开的流程烟雾测试，不是独立出题、也不贡献任何盲测样本。

## 五、严格验收门槛

先由独立作者完成20例原创Pilot的真实出题和事前GOLD封存，再验证无交叉访问、预测冻结、双评分、争议复核与题材分层。Pilot若被用于修改编译器或评分规则，不得与随后正式100例共用。正式C-pool须重新独立创作并封存，按关系/题材汇报六字段平均、因果边F1、变量F1、抽象残留率、视觉审核结果、评分者一致性及所有失败族。只有正式C-pool达到此前规定的100例及效果门槛，才考虑R5-v1.0冻结。
