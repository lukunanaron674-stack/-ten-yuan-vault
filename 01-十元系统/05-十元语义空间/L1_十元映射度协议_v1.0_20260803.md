# L1｜十元映射度协议 v1.0

## 0｜为什么必须保存映射度

只保存“主十元／副十元”只能说明排序，不能说明两者差多少，也不能说明其他十元是否仍有弱显影。

因此正式记录必须同时回答：

```text
映射到哪个十元？
映射强度是多少？
这个数字属于类型继承，还是具体实例显影？
证据可靠度是多少？
```

## 1｜两种映射度

### 1.1 类型继承映射度

用于 `is-a狭义` 类型关系。

```text
狭义子项 --is-a狭义[domain=领域]→ 五行广义父项
```

正式狭义类型继承完整五行轴，因此：

```yaml
axis_inheritance_degree: 100
pole_inheritance_degree:
  阳端: 100
  阴端: 100
```

这里的两个100表示“两端都被完整继承”，不是实例中阳阴各占50%，也不是要求具体案例两端同时出现。

示例：

```yaml
relation_type: is_a_narrow
child: 因果
parent: 木
domain: 叙事
axis_inheritance_degree: 100
ten_yuan_inheritance_degree:
  zx: 100
  nx: 100
```

### 1.2 实例十元映射度

用于具体人物、动作、发型、场景、音乐段落、情节或作品阶段。

```yaml
ten_yuan_mapping_degree:
  x: 0
  z: 0
  n: 0
  zn: 0
  nz: 0
  xn: 0
  nx: 0
  zx: 0
  xz: 0
  x并z: 0
normalization: sum_100
```

十个数总和必须为100。它表示当前分析尺度下，各十元对该实例结构的相对解释份额。

## 2｜映射度与其他数字的区别

| 字段 | 回答的问题 | 是否归一到100 |
|---|---|---:|
| 十元映射度 | 这个实例由各十元解释多少 | 是 |
| 体量 | 该结构在画面、行为或叙事中有多大 | 否，通常1–10 |
| 纯度 | 主十元是否少受邻近十元混入 | 否，可用百分比 |
| 证据置信度 | 当前资料是否足以支持判断 | 否，可用0–100 |
| 类型继承度 | 狭义子项是否完整继承父五行轴 | 正本类型固定100 |

禁止用“纯度”替代十元映射度，也禁止用映射度冒充证据置信度。

## 3｜主副十元

主副关系由映射度排序产生：

```text
主十元＝映射度最高者
副十元＝映射度第二高者
```

若最高两项差值小于10，应标记：

```yaml
dominance_status: dual-core
```

若最高项至少高出第二项20，可标记：

```yaml
dominance_status: clear-primary
```

主副只是摘要，完整十维向量才是正本数据。

## 4｜刘海98种的v1迁移规则

刘海旧研究已有“主十元、副十元、纯度”，但没有完整十维分配。为避免凭空编造八个弱十元，v1先保存主副双项归一映射：

```text
主十元映射度＝旧纯度
副十元映射度＝100－旧纯度
其余八项＝0
```

必须同时标记：

```yaml
mapping_model: provisional_two-pole_normalized
mapping_source: migrated_from_legacy_purity
full_ten_dimensional_audit: pending
```

这只是迁移模型，不等于已经完成十维终审。后续逐项重审时，可将弱映射分配给其他十元，但总和仍须为100。

## 5｜证据门

任何实例映射度必须至少记录：

```yaml
mapping_evidence:
  observable_features: []
  counterevidence: []
  nearest_confusions: []
  source_scope:
  confidence: 0-100
```

没有可观察证据时，只能写 `unscored`，不得为了表格完整随手填数字。

## 7｜失败条件

- 十维实例映射度总和不等于100；
- 类型继承度与实例显影度混写；
- 只写主副十元而不保存映射度；
- 将纯度、体量或置信度直接当成同一个数字；
- 没有证据却写高精度百分比；
- `is-a狭义`关系未保存两端十元继承度。
