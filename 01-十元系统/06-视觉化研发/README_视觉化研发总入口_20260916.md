# 视觉化研发｜总入口

> 本入口用于把 2026-09-15 至 2026-09-16 已推进的视觉化研究收束成桌面端可继续执行的工作台。它不重写十元／五轴正本，只记录视觉转译、生成实验、审核协议与下一步。

## 0｜当前总目标

```text
十元／五轴抽象定义
↓
Visual DSL / 可画结构
↓
单图生成实验
↓
图像审核器判定
↓
失败归因
↓
修正结构变量
↓
再生成并入库
```

核心原则：

1. 不再把“颜色、职业、表情、武器、题材符号”当成十元视觉化本体。
2. 先验证空间结构、关系结构、方向、边界、重心、路径、端点、开合、可逆性，再看风格和题材。
3. 五轴 V1.0 已封版，视觉化阶段不回头重做五轴理论；只有真实 failure 才定点重开。
4. 生成实验默认“单张图”，不要把十个实验塞进十宫格。
5. 一轮可做 10 次，但每次一张，便于逐张审核和回归。

---

## 1｜当前视觉化研发主线

### A. 图像审核器 R1.5｜极高优先级

**定位：**
判断生成图是否真正体现目标十元／关系结构，而不是靠题材、颜色、表情或符号投机命中。

**已确定的真实样本协议：**

```text
同角色
同场景
同画风
每次 3 张单图
只改结构
```

对照组示例：

```text
XZ 正样本
Z 对照
非 XZ 负样本
```

已明确禁止作为捷径：

- 黑红配色
- 黑手／怪物
- 武器
- 恐怖或夸张表情
- UI / 标签 / 文字说明
- 单纯靠“危险感”“高冷感”“王者感”替代结构证据

**审核核心：**

```yaml
structure_visible: 目标结构是否可直接从画面关系读出
shortcut_dependency: 是否必须依赖题材捷径才能判中
contrast_valid: 与相邻十元对照是否仍可区分
composition_evidence: 构图、边界、方向、路径、重心是否提供证据
relation_evidence: 若为生克补，关系是否真的发生而非共存
confidence: 0-1
failure_family: 若失败，归因到哪一类
```

**当前续跑点：**
- XZ 对照实验已形成方法论。
- 下一批重点转向 NX 等其他十元，复制同一严格协议。
- 图像审核器本身优先于继续无限扩“十元外观词库”。

---

### B. 动态链视觉化｜高优先级

**固定职责：**
只负责把动态链中的：

```text
主符号
次符号
方向
端点
条件
阶段变化
```

转译为可画面化、可生成、可审核的视觉结构。

**不要做：**
- 不重复证明动态链理论本身。
- 不把任务重新变成人物设定、世界观设定或一般十元定义。

**视觉验证重点：**

```yaml
start_state: 起始视觉状态
transition_trigger: 触发变化的视觉事件
direction: 结构变化方向
blocked_path: 被封闭的路径
opened_path: 新生成的路径
endpoint: 最终停在哪个结构端点
phase_change: 前中后阶段何处发生质变
```

**当前策略：**
动态链理论已有较充分结构基础，后续价值主要在“关系真的能不能被画出来”，而不是继续堆抽象卡。

---

### C. 十元角色／风格视觉化｜高优先级

#### X Style Grammar｜已冻结

冻结核心：

```text
独立形体单元
+ 清晰边界
+ 单元自足
+ 彼此不融合
+ 留有间隔
```

X 不等于：
- 几何
- 机能
- 冷酷
- 黑白
- 尖角
- 科技题材

后续若测试 X，只验证冻结语法是否能跨题材成立，不再随意修改定义。

#### ZN｜当前跨对象测试

不要只用“少女”测试 ZN。

跨对象组：

```text
建筑
机器
植物群
城市
房间
组织
```

目标：验证 ZN 的核心视觉规则是否能跨对象成立，避免把“自然、柔和、少女气质”误当 ZN 本体。

---

### D. 十元生克视觉化｜高优先级

当前要研究的是“关系如何出现在画面里”，不是把五轴生克理论再讲一遍。

关系层优先保留：

```text
生
克
补
```

不要无依据扩成五种关系。

最低证据：

```yaml
source: 哪个结构在作用
target: 作用到哪个结构
before: 作用前目标的状态
action: 画面中真实发生的结构变化
after: 作用后目标的合法状态空间如何变化
relation_type: 生 / 克 / 补
evidence_in_frame: 哪些可见关系支持这个判定
```

**关键防错：**
- 两个十元同时出现 ≠ 发生关系。
- 题材冲突 ≠ 克。
- 情绪互补 ≠ 补。
- A 在旁边帮助 B ≠ 生。

---

### E. 五轴视觉化｜高优先级，理论冻结后转应用

上游：`README_五轴V1.0总入口_20260916.md`

五轴当前不再追求“猜中关系”，而是锻炼：

> **把抽象结构名词转译成具体可见画面的能力。**

重点不是传统象征词，而是：

```text
关系的生克
→ 结构变量变化
→ 具象动作 / 空间 / 物件 / 路径 / 边界 / 站位
→ 可审核画面
```

五轴理论只有在视觉实验出现真实 failure family 时才重开。

---

### F. Visual DSL｜连接层

目标：让不同模型不必每次重新阅读长篇自然语言定义，而能读取稳定的中间结构。

视觉任务至少包含：

```yaml
subject: 主体
object: 对象
primary_ten_yuan: 主十元
secondary_ten_yuan: 次十元
relation: none / 生 / 克 / 补
relation_direction: A->B
changed_variable: 真正改变的变量
composition:
  center: 视觉中心
  boundary: 边界
  direction: 方向
  spacing: 间隔
  enclosure: 包裹/开放
  path: 路径
  endpoint: 端点
controlled_variables: 本轮冻结不变项
forbidden_shortcuts: 禁用题材捷径
audit_target: 本轮要让审核器判断什么
```

## 2｜统一实验格式

每张图对应一张实验卡：

```yaml
sample_id: VIS-YYYYMMDD-XXX
round: R1/R2/...
target: x/z/n/zn/nz/xn/nx/zx/xz/x并z 或 五轴关系
relation: none / 生 / 克 / 补
object_type: character/building/machine/city/room/organization/...
controlled:
  character: true/false
  scene: true/false
  style: true/false
changed_structure:
  - ...
forbidden_shortcuts:
  - color-coding
  - weapon
  - facial-expression
  - UI-text
prompt: ...
audit:
  target_hit: true/false
  structural_evidence: ...
  shortcut_dependency: low/medium/high
  nearest_confusion: ...
  failure_family: ...
verdict: PASS / FAIL / AMBIGUOUS
next_action: ...
```

---

## 3｜命名规则

建议统一：

```text
VIS-[模块]-[十元或关系]-R[轮次]-[序号]
```

例如：

```text
VIS-AUDIT-XZ-R1-01
VIS-AUDIT-NX-R1-01
VIS-STYLE-X-R6-03
VIS-ZN-CROSSOBJ-R1-ARCH-01
VIS-REL-SHENG-R1-01
VIS-CHAIN-XZ-NX-R1-01
```

图片、提示词、审核卡使用相同 sample_id，避免桌面端再次发生“图和结论分家”这种人类传统艺能。

## 4｜当前优先级

```text
P0  图像审核器 R1.5
P1  五轴/十元关系视觉化
P1  动态链视觉化
P1  十元角色/风格视觉化
P1  ZN 跨对象测试
P2  Visual DSL 标准化
P3  扩张题材词库 / 外观词库
```

说明：
- P0/P1 解决“结构能不能真的被画出来、看出来、审核出来”。
- P3 只有在前面稳定后才有价值，否则只是高效率制造漂亮但没结构的图。

```text
当前轮次
```
