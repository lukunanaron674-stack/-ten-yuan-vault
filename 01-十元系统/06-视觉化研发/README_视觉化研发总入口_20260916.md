# 视觉化研发｜总入口

> 本入口用于把 2026-09-15 至 2026-09-16 已推进的视觉化研究收束成桌面端可继续执行的工作台。它不重写十元／五轴正本，只记录视觉转译、生成实验、审核协议与下一步。

## 0｜当前总目标

```text
十元／五轴抽象定义
↓
Visual DSL / 可画结构
↓
单图生成实验
↓
图像审核器判定
↓
失败归因
↓
修正结构变量
↓
再生成并入库
```

核心原则：

1. 不再把“颜色、职业、表情、武器、题材符号”当成十元视觉化本体。
2. 先验证空间结构、关系结构、方向、边界、重心、路径、端点、开合、可逆性，再看风格和题材。
3. 五轴 V1.0 已封版，视觉化阶段不回头重做五轴理论；只有真实 failure 才定点重开。
4. 生成实验默认“单张图”，不要把十个实验塞进十宫格。
5. 当前 Style Grammar 阶段不再大量随机找图；找图只承担反例、混淆边界和跨风格外部复核，生图承担关键因果验证。

## 1｜当前视觉化研发主线

### A. 图像审核器 R1.5｜极高优先级

**定位：**
判断生成图是否真正体现目标十元／关系结构，而不是靠题材、颜色、表情或符号投机命中。

**已确定的真实样本协议：**

```text
同角色
同场景
同画风
只改一个结构变量
```

已明确禁止作为捷径：

- 黑红配色
- 黑手／怪物
- 武器
- 恐怖或夸张表情
- UI / 标签 / 文字说明
- 单纯靠“危险感”“高冷感”“王者感”替代结构证据

**审核核心：**

```yaml
structure_visible: 目标结构是否可直接从画面关系读出
shortcut_dependency: 是否必须依赖题材捷径才能判中
contrast_valid: 与相邻十元对照是否仍可区分
composition_evidence: 构图、边界、方向、路径、重心是否提供证据
relation_evidence: 若为生克补，关系是否真的发生而非共存
confidence: 0-1
failure_family: 若失败，归因到哪一类
```

**当前续跑点：**
- 把十元 Style Grammar 的结构字段直接接入审核器。
- 优先检测 ZX / NX / NZ 等高捷径污染对象。
- 图像审核器优先于继续扩“十元外观词库”。

---

### B. 动态链视觉化｜高优先级

**固定职责：**
只负责把动态链中的：

```text
主符号
次符号
方向
端点
条件
阶段变化
```

转译为可画面化、可生成、可审核的视觉结构。

**不要做：**
- 不重复证明动态链理论本身。
- 不把任务重新变成人物设定、世界观设定或一般十元定义。

**视觉验证重点：**

```yaml
start_state: 起始视觉状态
transition_trigger: 触发变化的视觉事件
direction: 结构变化方向
blocked_path: 被封闭的路径
opened_path: 新生成的路径
endpoint: 最终停在哪个结构端点
phase_change: 前中后阶段何处发生质变
```

**当前策略：**
动态链理论已有较充分结构基础，后续价值主要在“关系真的能不能被画出来”，而不是继续堆抽象卡。

---

### C. 十元角色设计 Style Grammar｜高优先级｜已进入视觉因果验证

详细总整理：

`十元角色设计StyleGrammar_研究总整理_20260916.md`

#### 已正式冻结

**X**

```text
独立形体单元
+ 清晰边界
+ 单元自足
+ 彼此不融合
+ 留有间隔
```

**Z**

```text
建立方向
→ 明确转向节点
→ 至少两个后续不同结构层级继承新方向
```

X、Z 除出现明确反证外，不再追加理论轮次。

#### 当前八元候选

```text
N       双向互为条件
ZN      关系规则改写 α→β→β
NZ      终端嵌合
XN      异质单元规则槽位化
NX      缺席组织位
ZX      非对称组织锚点
XZ      低余量临界耦合
X并Z    上位包络双重读取
```

其中：
- XN / XZ：强冻结候选，仍需 A/B 图证。
- N / ZN / X并Z：冻结候选，仍需关键因果验证。
- NZ / NX / ZX：深研后已改写，优先验证。

#### 当前方法

```text
20% 定向找图复核
80% 控变量验证 / 审核
```

找图只用于：
1. 反例 / 假阳性；
2. 具体混淆边界；
3. A/B 通过后的跨风格外部泛化。

不再因为文字逻辑完整而自动推进冻结。

#### 当前 A/B 验证队列

```text
ZX → NX → NZ → ZN → N → X并Z → XZ → XN
```

该顺序只按视觉捷径污染风险排序，不代表理论价值排名。

若按原聊天研究顺序继续，则 N 当前仍应停在 A/B 因果验证口，不自动跳到 ZN。

### D. 十元生克视觉化｜高优先级

当前要研究的是“关系如何出现在画面里”，不是把五轴生克理论再讲一遍。

关系层优先保留：

```text
生
克
补
```

不要无依据扩成五种关系。

最低证据：

```yaml
source: 哪个结构在作用
target: 作用到哪个结构
before: 作用前目标的状态
action: 画面中真实发生的结构变化
after: 作用后目标的合法状态空间如何变化
relation_type: 生 / 克 / 补
evidence_in_frame: 哪些可见关系支持这个判定
```

**关键防错：**
- 两个十元同时出现 ≠ 发生关系。
- 题材冲突 ≠ 克。
- 情绪互补 ≠ 补。
- A 在旁边帮助 B ≠ 生。

---

### E. 五轴视觉化｜高优先级，理论冻结后转应用

上游：`README_五轴V1.0总入口_20260916.md`

五轴当前不再追求“猜中关系”，而是锻炼：

> **把抽象结构名词转译成具体可见画面的能力。**

重点不是传统象征词，而是：

```text
关系的生克
→ 结构变量变化
→ 具象动作 / 空间 / 物件 / 路径 / 边界 / 站位
→ 可审核画面
```

五轴理论只有在视觉实验出现真实 failure family 时才重开。

### F. Visual DSL｜连接层

目标：让不同模型不必每次重新阅读长篇自然语言定义，而能读取稳定的中间结构。

视觉任务至少包含：

```yaml
subject: 主体
object: 对象
primary_ten_yuan: 主十元
secondary_ten_yuan: 次十元
relation: none / 生 / 克 / 补
relation_direction: A->B
changed_variable: 真正改变的变量
composition:
  center: 视觉中心
  boundary: 边界
  direction: 方向
  spacing: 间隔
  enclosure: 包裹/开放
  path: 路径
  endpoint: 端点
controlled_variables: 本轮冻结不变项
forbidden_shortcuts: 禁用题材捷径
audit_target: 本轮要让审核器判断什么
```

Style Grammar 审核增补字段：

```yaml
unit_independence:
relation_reciprocity:
relation_state_before:
relation_state_after:
transition_node:
terminal_interface:
terminal_clearance:
shared_rule_strength:
slot_deviation:
absent_organizer:
negative_space_dependency:
asymmetric_anchor:
constraint_propagation:
minimum_clearance:
critical_interface_count:
outer_envelope:
internal_unit_autonomy:
dual_readability:
shortcut_flags:
deletion_sensitivity:
cross_position_stability:
cross_style_stability:
```

## 2｜统一实验格式

每张图对应一张实验卡：

```yaml
sample_id: VIS-YYYYMMDD-XXX
round: R1/R2/...
target: x/z/n/zn/nz/xn/nx/zx/xz/x并z 或 五轴关系
relation: none / 生 / 克 / 补
object_type: character/building/machine/city/room/organization/...
controlled:
  character: true/false
  scene: true/false
  style: true/false
changed_structure:
  - ...
forbidden_shortcuts:
  - color-coding
  - weapon
  - facial-expression
  - UI-text
prompt: ...
audit:
  target_hit: true/false
  structural_evidence: ...
  shortcut_dependency: low/medium/high
  nearest_confusion: ...
  failure_family: ...
verdict: PASS / FAIL / AMBIGUOUS
next_action: ...
```

A/B Style Grammar 实验额外锁死：

```yaml
same_character: true
same_pose: true
same_camera: true
same_shape_count: true
same_color: true
same_material: true
same_detail_density: true
same_style: true
```

## 3｜命名规则

建议统一：

```text
VIS-[模块]-[十元或关系]-R[轮次]-[序号]
```

例如：

```text
VIS-AUDIT-XZ-R1-01
VIS-AUDIT-NX-R1-01
VIS-STYLE-N-R5-A
VIS-STYLE-N-R5-B
VIS-STYLE-ZX-R5-A
VIS-STYLE-ZX-R5-B
VIS-REL-SHENG-R1-01
VIS-CHAIN-XZ-NX-R1-01
```

图片、提示词、审核卡使用相同 sample_id，避免桌面端再次发生“图和结论分家”。
