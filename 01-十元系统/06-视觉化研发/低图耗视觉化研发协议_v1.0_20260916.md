# 低图耗视觉化研发协议 v1.0

## 0｜目的

当正式生图额度有限时，不允许视觉化研发被额度卡死。

默认研发链从“多生图探索”改为：

```text
100 个视觉想法
↓
L0 结构推演 / Visual DSL
↓ 筛到约 30
L1 草图代理 / 本地低成本粗图
↓ 筛到约 10
L2 结构样本验证
↓ 筛到约 3
L3 正式高价值生图
↓
冻结 / failure 回流
```

正式高成本生图原则上只负责最后约 3% 的关键验证，不承担大规模发散。

---

## 1｜四层研发模型

| 层级 | 名称 | 任务 | 成本策略 |
|---|---|---|---|
| L0 | 结构推演 | 十元结构、方向、边界、路径、端点、关系变量 | 0 正式生图 |
| L1 | 草图代理 | 火柴人、块面、构图草图、低清本地粗图 | 极低成本 |
| L2 | 结构样本 | 同角色同场景同画风，只改变结构变量 | 少量生成 |
| L3 | 正式视觉 | 高质量角色、材质、风格、最终展示 | 高成本，严格限额 |

任何研究假设若 L0/L1 就无法说清结构，不得直接进入 L3。

---

## 2｜正式生图的默认用途

正式生图只承担“裁判局”，不承担“海量探索局”。

每个待验证规则优先固定为三样本：

```text
A 正样本：目标结构成立
B 最近邻对照：只改变一个关键结构变量
C 负样本：移除目标结构，测试审核器误判
```

默认一组 = 3 张。

只有以下情况允许扩到 6 张：

- 三样本结果仍 AMBIGUOUS。
- 最近邻混淆无法定位。
- 不同对象层出现系统性差异。
- 审核器与人工判断持续冲突。

禁止因为“还想看看更多风格”无条件把 3 张扩成 10～50 张。

---

## 3｜L0：Visual DSL 先筛

正式生图前，至少填：

```yaml
hypothesis_id: VIS-HYP-XXX
target: 目标十元/关系/动态链
changed_variable: 本轮真正改变的变量
visible_structure:
  boundary: ...
  direction: ...
  path: ...
  endpoint: ...
  center: ...
  enclosure: ...
nearest_confusion: 最可能混淆的十元
controlled_variables:
  - character
  - scene
  - style
forbidden_shortcuts:
  - color-coding
  - weapon
  - facial-expression
  - UI-text
expected_positive_evidence: ...
expected_negative_evidence: ...
```

若无法给出 `expected_positive_evidence` 与 `expected_negative_evidence`，先继续结构推演，不生图。

---

## 4｜L1：草图代理

可以用：

- 火柴人
- 黑白块面
- 简单透视框
- 箭头与路径草图
- 本地 512/768 低步数粗图
- 固定 seed 的低成本变体

L1 不要求好看，只验证：

```text
包围 / 开放
靠近 / 分离
侵入 / 排斥
路径关闭 / 打开
端点唯一 / 多解
重心偏移
边界清晰 / 融合
可逆 / 不可逆
```

若粗糙结构已经无法区分最近邻十元，禁止进入正式高质量生图。

---

## 5｜本地与云端的职责分配

### 本地 GPU

负责数量：

```text
低分辨率
低步数
固定 seed
固定角色
固定场景
只换结构变量
```

用途：结构缩略图与低成本淘汰。

### 云端 GPU

负责批量：

- ZN 跨对象
- 十元风格跨题材
- 动态链阶段图
- 生 / 克 / 补对照
- 图像审核器训练 / 回归样本

批量生成后优先自动审核，人工只查看：

```text
AMBIGUOUS
强正例
危险误判
最近邻混淆
```

### ChatGPT / 高价值正式生成

负责关键三样本、疑难对照、最终展示，不负责几十张无筛选发散。

---

## 6｜自动审核后的人工采样

若一次本地/云端批量 30 张：

```text
PASS
AMBIGUOUS
FAIL
```

人工优先只看：

```text
最强正例 ×2
最危险误判 ×2
最近邻混淆 ×2
```

其他样本保留 manifest 与审核记录即可。

目标是让人工注意力用于发现 failure family，而不是逐张充当图片分类器。

---

## 7｜各模块额度策略

### 图像审核器

额度等级：高。

理由：图像本身就是实验数据。

默认：每轮 3～6 张正式关键样本。

### 动态链视觉化

额度等级：中。

流程：

```text
结构草图
→ 三阶段 storyboard
→ 正式验证
```

不要对每个链条假设直接生成精图。

### ZN 跨对象

额度等级：低～中。

先完成六类对象的 DSL，再每类优先：

```text
1 正样本
1 最近邻对照
```

若区分失败才增加负样本。

### 十元风格

额度等级：低～中。

冻结前：结构语法 → 跨题材低成本测试。
冻结后：仅周期性回归。

### 五轴视觉化

额度等级：低。

五轴 V1.0 已冻结。优先做：

```text
抽象结构词
→ Visual DSL
→ 草图
```

只有 DSL 出现真实分歧才进入正式图像验证。

## 8｜新版主循环

```text
十元 / 五轴定义
↓
Visual DSL
↓
结构草图
↓
本地低成本批量
↓
自动审核
↓
选关键三样本
↓
正式生图
↓
人工审核
↓
PASS → 冻结 / 回归
FAIL → 回到 DSL
```

---

## 9｜进入正式生图的闸门

只有同时满足以下条件，才进入 L3：

```yaml
dsl_complete: true
changed_variable_isolated: true
nearest_confusion_named: true
forbidden_shortcuts_defined: true
positive_evidence_defined: true
negative_evidence_defined: true
cheap_test_passed: true
```

否则：

```text
BLOCK_L3
→ 继续 L0 / L1
```

---

## 10｜停止条件

某条视觉规则满足：

- 跨至少 3 种题材 / 对象仍成立。
- 最近邻十元可区分。
- 去掉颜色、表情、武器、UI 后仍成立。
- 审核器能指出结构证据。
- failure 可归入明确错误族。

即可暂时冻结，不再继续消耗正式生图额度。

---

## 11｜默认策略

从本协议生效起：

```text
默认低图耗模式 = ON
```

除非任务本身就是：

- 最终角色设计探索
- 最终风格探索
- 关键审核器样本
- 用户明确要求大量图像视觉发散

否则都先走 L0 → L1 → L2，再进入 L3。
