# zx 补 nx｜总词典旧暗线口径撤回与正式机制同步补丁

## 一、补丁范围

本补丁不新建理论定义，只同步已经通过 97% 门槛的 parent 正本：

`01-十元系统/关系专项/zx补nx_直接显权与关系借力互补正式机制_20260721.md`

本补丁只覆盖关系词典中 `zx ↔ nx` 的旧“内容待二审”“暗线分析、追踪、计算、结算”口径。关系词典其他关系不在覆盖范围内。

## 二、正式结论

`zx` 与 `nx` 是两种互补的现实推进路径：

- `zx`：主体以自己的公开权能直接决定方向、压过阻力并推进现实；
- `nx`：主体承认目标位于他者、关系、身份、权限或既有通道中，暂不占据该处最终决定位置，沿现成关系与权限网络获得许可、信息、工具、救兵或入口。

正式双向机制：

```text
nx 补 zx：
直接权能无法越过他者权限、对象归属或专属接口
→ 主体进入既有关系与权限网络借力
→ 获得自身不能直接制造的入口、许可、工具或协助
→ zx 重新获得可推进条件

zx 补 nx：
借力路径只能提供入口、条件或他者权限
→ 若主体始终停在求人、等待和转交位置，现实无法由其完成收束
→ 主体在获得条件后重新公开承担决定与行动
→ nx 不退化为永久依附，事情进入直接完成阶段
```

一句话：

> `nx` 解决“我进不去”，`zx` 解决“进去以后谁来做成”。

补位不表示互相生成，也不表示固定的领导与服从。

## 三、关系对象分层

| 层级 | zx | nx | 本关系判定 |
|---|---|---|---|
| 稳定本体 | 长期依靠公开显权、扩权和凌驾成立 | 长期不占方向决定位置，沿外部方向推进 | 不由一次出手或一次求助反推 |
| 当前状态 | 此阶段公开接管、压过阻力 | 此阶段进入他者权限或关系通道 | 正式机制最常发生层 |
| 行为功能 | 宣告、命令、直接推进、承担最终决定 | 求助、请示、借力、沿权限接口进入 | 行为必须回到端点变量 |
| 光影 | 中心、高位、众人转向 | 侧位、门槛、引路人与通行证 | 只作显影 |
| 场景 | 战场、公开冲突、现场接管 | 官署、师门、组织、关系网络 | 场景不替代端点 |
| 时间关系 | 可先直接行动，也可在借力后重新出现 | 常在直接路径遇到边界时补入 | 不固定为单向生成 |
| 关系位置 | 自己的权能中心 | 他者的权限、身份与关系接口 | 必须说明接口归谁 |
| 显影 | 直接决定范围、现实推进强度 | 可获得的入口、许可、工具与救兵 | 双方各补一个缺口 |
| 动态链 | 把条件兑换成现实推进 | 让直接行动穿过自身权能边界 | 不机械生成成功 |

## 四、端点、变量、阶段、体量与显影

### 4.1 `nx 补 zx`

已有 `zx`：主体能够直接出手或公开决定，但目标属于他者权限、专属知识、对象归属或关系网络，继续加大自身力量也不能打开正确接口。

`nx` 补入后改变：

- 外部权限可达性；
- 专属工具、信息和救兵的获得率；
- 主体能否进入不属于自己的决定范围；
- 直接推进是否获得有效入口。

### 4.2 `zx 补 nx`

已有 `nx`：主体已通过关系、身份或权限网络获得入口与条件，但他者不会替主体完成全部现实承担。

`zx` 补入后改变：

- 最终决定是否回到主体；
- 条件能否被兑换为现实行动；
- 借力是否形成闭环；
- 主体是否承担结果与公开推进位置。

### 4.3 成立阶段

```text
主体先以 zx 直接推进
→ 遇到不属于自己的权限或对象归属边界
→ 转入 nx 借关系与权限接口
→ 获得条件后重新进入 zx
→ 现实推进闭环
```

也可以从 `nx` 已先取得入口开始观察，但不能把两端写成互相自动生成。

### 4.4 体量

- 低体量：一次请求许可或借用专属工具，使单次行动得以继续；
- 中体量：跨部门、跨身份或跨组织借力后，由原主体重新承担现场决定；
- 高体量：主体长期在多个他者权限网络间取得条件，同时保持最终现实承担位置。

### 4.5 显影条件

- 存在真实的他者权限、对象归属或专属接口；
- 直接力量无法替代该接口；
- 借力后主体重新承担决定和行动；
- 排除固定预案、资源归属变化、普通建议与全程代办。

## 五、机制候选及理论后果

### 候选 A：权限缺口补偿

```text
目标位于他者专属权限内
→ 自己再强也无法直接调用
→ nx 进入关系与权限接口
→ 获得许可、专属工具或对象归还
→ zx 恢复推进条件
```

理论后果：`nx` 不是弱小、暗算或结算，而是承认现实里存在“不是我的权限”。

### 候选 B：条件到行动的闭环

```text
关系网络提供条件
→ 条件本身不替主体承担最终行动
→ zx 重新公开接管并推进
→ 借力不再停留于求人和等待
```

理论后果：`zx` 不消灭 `nx`，而是为借来的入口承担最后兑现。

A 解决入口缺口，B 解决兑现缺口，二者组成同一双向补位机制。

## 六、正例

### 6.1 《西游记》孙悟空与红孩儿阶段

- `zx`：孙悟空直接交战、救唐僧并试图压过现场；
- 权限边界：三昧真火、红孩儿的归属与收伏资格不是继续挥棒即可解决；
- `nx`：孙悟空进入观音菩萨的关系与权限网络，请其出面并借法器、身份和收伏资格；
- `nx 补 zx`：获得自身不能制造的专属处理接口；
- `zx 补 nx`：借力后仍由孙悟空继续承担取经队伍保护与现实推进。

拿掉观音接口，增加战斗强度仍不能稳定解决；拿掉孙悟空的后续承担，求助也不会自动完成取经任务。

### 6.2 《西游记》孙悟空与青牛精阶段

- `zx`：孙悟空多次直接交战并公开调动天兵天将；
- 权限边界：金刚琢属于太上老君，普通兵器和增援均被收走；
- `nx`：孙悟空沿天庭、神仙与法宝归属关系查找，最终请太上老君收回坐骑与法宝；
- `nx 补 zx`：关系网络提供对象归属信息与唯一有效回收权限；
- `zx 补 nx`：查明归属后，孙悟空继续保护师父并恢复队伍路线。

查资料本身不是 `nx`；真正的 `nx` 是承认法宝和对象属于他者权限，并进入对应接口。

### 6.3 跨部门救援结构例

现场负责人拥有直接救援指挥权，但危险区域属于另一机构管辖，并需要专属设备与通行许可。

```text
负责人直接组织现场
→ 遇到他者权限边界
→ 通过既有联络关系请求许可与设备
→ 获得入口后重新承担现场决定与行动
```

## 七、反例

1. 强者命令下属执行：属于权能压位，不足以证明补位。
2. 主体按预案联系固定部门：若只是流程自动运行，优先检查 `xn`。
3. 朋友提供普通建议：没有新增权限、入口、工具或信息，只是交流。
4. 主体被别人全程替代完成：只有依赖或方向转移，没有 `zx` 闭环。
5. 领导借关系取得长期资源归属：核心变量是资源归属时优先检查 `x`。
6. 幕后算计、追踪、记录和结算：现行优先检查 `xn`，不是 `nx`。
7. 多人合作但没有明确他者权限边界：只能证明合作。
8. 主体求人后仍不承担任何决定与结果：不能证明 `zx 补 nx`。

## 八、最近邻排除

### 与 `xn`

`xn` 主动组织计划、记录、流程和资源，使结构持续运行；`nx` 进入已经属于他者的关系、身份或权限通道，暂不占据该处最终决定位置。

### 与 `x`

`x` 是对象、资源、权限或关系归我掌握；`nx` 是承认接口归他者，沿其关系和权限进入。借到工具不等于工具归我长期掌握。

### 与领导和服从

`zx ↔ nx` 不等于强者命令弱者。补位要求直接推进缺入口，关系借力缺最终兑现。

### 与普通合作

合作只说明多人同时行动；补位必须说明单靠一端缺什么，以及另一端具体改变了什么变量。

## 九、拿掉测试

1. 拿掉他者权限、关系入口和专属工具后，`zx` 是否无法进入目标范围？
2. 拿掉主体自己的公开决定与行动后，借来的条件是否无法形成现实闭环？
3. 拿掉主动组织流程后，权限接口是否仍独立有效，从而排除 `xn`？
4. 拿掉资源长期归属后，借力是否仍成立，从而排除 `x`？
5. 若继续增加直接力量即可同样解决，则案例不需要 `nx`。
6. 若他者替主体完成全部目标，则主体没有重新进入 `zx`。

## 十、反向测试

本关系是双向补位，不设置单向生成方向：

```text
zx 遇到权限边界
→ nx 补入入口
→ zx 重新兑现
```

也可以从 `nx` 已取得入口开始观察：

```text
nx 已取得条件
→ zx 补入最终决定与行动
→ 现实闭环
```

`nx` 不自动制造主体权能，`zx` 也不自动制造关系和权限网络。

## 十一、动态链后果

```text
我能直接做成一部分
→ 现实中存在不属于我的权限
→ 我进入他者关系与通道取得条件
→ 再由我承担决定、行动与结果
```

改变的是现实推进方式：从单一力量，转为“直接承担＋承认权限边界＋借力后重新兑现”的闭环。

本关系不机械生成成功、领导服从、永久依赖或稳定人物本体变化。
