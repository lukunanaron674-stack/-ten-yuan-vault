# 十元符号卡片引擎

## 0. 模块定位

十元符号卡片引擎是一个通用能力模块，用来把新名词、工具概念、理论概念、F12 模块、游戏机制、角色场景等，转化为可理解、可评分、可定位、可触摸、可入库、可复用的能力卡。

它不是单纯起比喻名，而是完整执行：

```text
名词雷达
+ 大小向量
+ 十元定位
+ 物象概念
+ 动态链解释
= 十元符号卡片
```

## 1. 适用范围

可用于：

- [[F12总控载体蓝图]] 的功能模块解释。
- [[v0.5-GitHub归档回流器]] 等自动化概念解释。
- [[雾中渡口总蓝图]] 的游戏机制卡片化。
- 角色、场景、物件、系统、工具、工作流的语义展开。
- Codex 工单、Obsidian 模板、ChatGPT 分析回复。
- 银矿哥评分前的概念拆解。

## 2. 名词雷达

每当出现新词、英文词、工具词、抽象词，先判断用户可能是否了解，再决定解释深度。

| 等级 | 判断 | 处理方式 |
|---|---|---|
| 0 | 用户已熟悉 | 不解释，只使用 |
| 1 | 可能听过但不稳 | 简短解释 |
| 2 | 新工具名 / 英文名词 | 必须解释 |
| 3 | 会影响操作的关键名词 | 解释 + 比喻 + 操作位置 |
| 4 | 会影响系统设计的核心名词 | 解释 + 十元 + 动态链 + 例子 |

### 判断标准

```text
是否是新名词？
是否是英文工具词？
是否会影响操作？
是否会影响系统结构？
是否会影响后续归档？
```

例如：

- commit：等级 3，要解释为“给当前文件状态拍版本照片”。
- checkpoint：等级 4，要解释为“断点锚”，并说明如何续跑。
- repository：等级 3，要解释为 GitHub 仓库，不只是普通文件夹。
- GitHub 归档回流器：等级 4，是系统结构模块。

## 3. 大小向量

每张卡必须给出大小向量，也就是这个概念的作用大小、风险和迁移能力。

| 向量 | 分数 | 说明 |
|---|---:|---|
| 重要性 | /10 | 是否是核心概念 |
| 使用频率 | /10 | 以后是否经常用 |
| 风险度 | /10 | 弄错会不会出大问题 |
| 依赖度 | /10 | 其他模块是否依赖它 |
| 解释成本 | /10 | 理解它需要多少说明 |
| 迁移性 | /10 | 能否迁移到其他项目 |

### 尺标解释

```text
1-3：低，只是辅助小概念。
4-6：中，常用但不决定系统骨架。
7-8：高，影响主要流程。
9-10：核心，错了会导致系统失真或断链。
```

## 4. 十元定位

每个概念都要定位：

```text
主十元：
副十元：
五维：
体量：
顺序感谱：
```

### 使用原则

- 主十元判断本体：它是什么。
- 副十元判断辅助结构：它靠什么成立。
- 五维判断高阶主题：它解决什么本质问题。
- 体量判断存在感强度，不等于力量。
- 顺序感谱判断第一反应和动态顺序，不等于善恶。

## 5. 十元物象概念


### 目标

不是为了可爱，而是为了让抽象结构变得可抓、可记、可复用。

例如：

```text
checkpoint = 锚点
commit = 封蜡
payload = 投递纸条
workorder = 航海令
```

## 6. 动态链条解释

每张卡都要说明它如何运动。

```text
起手：

触发：
反馈：
回流：
结算：
```

并写出十元链：

```text
zx 触发
→ n 承载
→ xn 规则化
→ x并z 可视化
→ zn 归档成意义
```

动态链用来判断：

- 它是不是跑通。
- 它卡在哪里。
- 它是否断链。
- 它是否误判本体。

## 8. 示例一：v0.5-GitHub归档回流器

### 名词雷达

原词：GitHub Archive Returner / GitHub 归档回流器  
中文名：归档回流器  
类型：自动化结构模块  
用户熟悉度：2-3  
是否需要解释：需要  
一句话解释：把 F12 / ChatGPT 的归档内容写成 Markdown，送回 GitHub / Obsidian。

### 大小向量

| 向量 | 分数 | 说明 |
|---|---:|---|
| 重要性 | 9 | 解决长跑记忆丢失 |
| 使用频率 | 8 | 每个归档轮都会用 |
| 风险度 | 7 | 路径错会导致材料丢失或串仓 |
| 依赖度 | 8 | F12、GitHub、Obsidian、中枢框都依赖 |
| 解释成本 | 5 | 概念不难，但链条较长 |
| 迁移性 | 9 | 可迁移到视觉库、银矿库、游戏库 |

### 十元定位

主十元：xn  
副十元：n  
五维：空间 x并z+n / 因果 zx+nx  
体量：8  
顺序感谱：先收束，再回流，再稳定

### 物象概念

小比喻名：铁轨仓  
物象：带标签的矿车沿轨道进入远程仓库  
触感：金属、编号牌、轨道震动  
动作：装货、封箱、上轨、入仓  
画面：一车归档文件被推进 GitHub 仓库  
声音：咔哒，轨道锁上  
不能误解为：中枢脑、审稿官、自动判断器

### 动态链条

起手：F12 归档轮产生结果  
承载：Markdown 模板接住内容  
触发：写入 GitHub  
反馈：Obsidian 拉取后出现新节点  
回流：中枢框下次可从 GitHub 读取  
结算：聊天短期记忆变成外部长期记忆  

十元链：

```text
zx 触发归档
→ n Markdown承载
→ xn 路径和版本规则化
→ x并z Obsidian可视化
→ zn 中枢吸收成稳定意义
```

## 9. 示例二：v0.3-工单断点

### 名词雷达

原词：Work Order / Checkpoint  
中文名：工单断点  
类型：自动化续跑模块  
用户熟悉度：2  
是否需要解释：需要  
一句话解释：记录任务跑到哪，断了之后从断点继续。

### 大小向量

| 向量 | 分数 | 说明 |
|---|---:|---|
| 重要性 | 10 | 108 轮长跑的生命线 |
| 使用频率 | 9 | 每个长任务都要用 |
| 风险度 | 8 | 误判 running 会重复发送或漏发 |
| 依赖度 | 9 | v0.4 看门狗、v0.5 回流都依赖它 |
| 解释成本 | 6 | 任务卡、工单、checkpoint 需要分开解释 |
| 迁移性 | 9 | 可迁移到任何长链工作流 |

### 十元定位

主十元：xn  
副十元：n / nx  
五维：因果 zx+nx / 时间 xn+z  
体量：9  
顺序感谱：先记录，再判断，再续接

### 物象概念

小比喻名：航海令 / 船票 / 锚点  
物象：航海令管理路线，船票记录单个乘客，锚点固定断点  
触感：纸张、印章、湿绳、铁锚  
动作：登记、发船、停靠、续航  
画面：雾中渡口的任务船队按编号继续航行  
声音：印章盖下，锚链落水  
不能误解为：自动理解内容、自动审稿、自动归档正文

### 动态链条

起手：任务开始  
承载：任务卡记录单个任务  
触发：工单决定当前任务  
反馈：checkpoint 保存状态  
回流：中断后读取 checkpoint  
结算：从上一次断点继续，不从头重跑  

十元链：

```text
n 任务卡承载
→ xn 工单排序
→ zx 发送执行
→ nx checkpoint判断
→ n 状态保存
→ xn 续跑规则恢复
```

## 10. 使用红线

- 不要只起比喻名，不做十元定位。
- 不要只讲技术定义，不做物象概念。
- 不要把体量写成力量。
- 不要把五维写成十元起手。
- 不要用视觉外显反推本体。
- 不要跳过大小向量，否则无法判断重要性。
- 不要跳过动态链，否则无法判断它怎么跑。
