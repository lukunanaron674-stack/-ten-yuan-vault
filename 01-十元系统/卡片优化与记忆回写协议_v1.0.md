# 十元卡片优化与记忆回写协议 v1.0

> 账本证明任务运行；卡片保存理论真正学会的内容。卡片优化是每轮研究的核心目的。

## 1. 信息保存位置

- `07-Codex大脑库/十元理论每小时运行记录.md`：只存slot、attempt、状态、SHA、修改卡路径、评分和下一关系。
- `07-Codex大脑库/每次任务必读_十元关系防遗忘清单.md`：只存断点、尝试次数、证据缺口和下一证据目标。
- 十元信息卡：保存十元本体、对象层、核心变量、血肉表现和本体边界。
- 十元准度卡：保存必要条件、最近邻、拿掉、反向、误判与评分封顶。
- `04-十元生克补卡/生/`、`克/`、`补/`：保存25张单条或单组关系卡的机制、案例、测试、评分和证据缺口。
- 动态链案例：保存单片段事实；发现卡片问题时写入链条问题单，由审计独立复核后回填对应卡片。

## 2. 每轮回写顺序

```text
本轮单条关系卡
→ 本体变化时更新源/目标信息卡
→ 判定边界变化时更新源/目标准度卡
→ 达到95%时同步核心表、词典和专项正本
→ 更新滚动中枢
→ 最后更新运行账本
```

无新证据时，不扩写信息卡与准度卡；只在单条关系卡增加紧凑复核记录和下一证据目标。关系卡的案例检索必须由该卡的95%证据缺口块驱动，不得盲目追加相似案例。

## 3. 双版本制

每张核心卡维护：

```yaml
version: 理论内容版本
memory_record_version: 运行记忆版本
last_memory_run_id: 最近一次写卡运行ID
last_memory_commit: SELF
```

- `version`只在本体、必要条件、机制、红线、案例分类或结论实质变化时递增。
- `memory_record_version`只在卡片新增有效运行记忆时递增，禁止无内容空涨。
- `last_memory_commit: SELF`表示当前提交就是该次记忆提交；实际SHA由Git历史和账本记录。
- 结构迁移、链接修复和证据缺口格式标准化不自动增加理论版本或记忆版本。

## 4. 记忆记录最小格式

```text
### MR-x.y｜run_id｜日期
- 本轮类型：轻量 / 完整 / 动态链回填
- 新增独立证据：是 / 否
- 结论变化：
- 新增案例或边界：
- 七项最弱值：
- 下一证据目标：
- commit_ref：SELF
```

## 5. 三类卡边界

- 信息卡只回答“它是什么”。
- 准度卡只回答“为什么必须判成它，怎样排除误判”。
- 单条关系卡只回答“两个已成立端点之间怎样生、克或补”。

每一条生、每一条克、每一组补必须独立成卡。三张旧总卡只作为类型说明与索引，不再承载每小时理论正文。

## 6. 95%证据缺口协议

### 6.1 适用范围

所有`relation_status: research-active`的单条生卡、单条克卡与单组补卡必须维护`evidence_gap_schema_version: v1.0`，并包含固定区块`## 达到95%还缺什么证据`。

### 6.2 固定字段

```text
- 当前最弱项：直接引用七项置信度中的最低项或并列最低项。
- 已有证据：只写已经通过控制、可以复用的部分。
- 尚缺控制证据：写成可观察、可反驳、可失败的条件。
- 优先采矿：分别写电影/叙事、史料/现实、对照/反例的目标形态。
- 锁定条件：写明独立模板数量、必须通过的控制和七项门槛。
- 否定或降级条件：写明失败后应退回的最近邻、状态关系或非关系解释。
```

### 6.3 写入纪律

1. 不得只写“需要更多案例”“继续寻找证据”或罗列作品名。
2. 每项缺口必须能被一次具体人物阶段、制度对照、拿掉、反向或第三因素冻结检验。
3. 每轮开始时先从该区块选择一个最小证据目标，再决定检索材料和案例。
4. 新案例若没有命中区块中的某项缺口，不计作有效新增独立证据。
5. 轻量轮无新增时只复核该区块，不改写、不涨版本。
6. 完整审计、新反例、链条问题单、第三因素隔离或跨案例复现改变缺口时，必须同步更新该区块。
7. 卡片达到锁定后，将该区块转换为`95%保真与降级条件`；保留锁定所依赖的控制和解锁触发器。

### 6.4 与七项置信度的关系

- `当前最弱项`决定下一轮优先采矿方向。
- `尚缺控制证据`必须逐项对应`independent_evidence`、`rival_exclusion`、`reversibility`或`replication`等低分原因。
- `锁定条件`未满足时，即使案例数量增加，也不得把七项全部抬到95。
- `否定或降级条件`一旦命中，必须降低对应评分并检查关系是否退回共现、显影、加权、授权、状态压制、策略调整或最近邻。

## 7. 完成判定

一轮研究必须记录对应单条关系卡、必要的信息卡或准度卡、卡片双版本、中枢断点、账本中的卡路径和提交SHA，并完成回读验证。对未锁定关系，汇报还必须写明本轮命中的证据缺口编号、是否填补、未填补原因与下一最小证据目标。
