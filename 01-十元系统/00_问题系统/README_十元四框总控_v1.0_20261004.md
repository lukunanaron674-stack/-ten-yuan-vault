## 2｜四框职责

### Lina00｜总控与索引
负责来源、版本、依赖、去重、状态、最终验收。

负责十元感受核、人类感受定义、五轴感受控制旋钮、五维边界。
Linear：674-104。

### Lina02｜关系与动态链
负责生/克/补的感受关系、对子、Observed Feeling Relation、动态感受链/动态图、长故事、游戏、音乐动态链。

`endpoint → position → mechanism lifecycle → observed relation → chain causality → chain quality`

**位置合法 ≠ 机制可调用 ≠ 案例真实发生 ≠ 动态链成立 ≠ 高质量动态链。**

### Lina03｜证据、可视化与应用

Linear：674-106。

生成或工程成功不自动构成理论证据。

## 3｜跨框权力顺序

```text
Lina01 人的感受定义 / 五轴诱发机制
↓
Lina03 跨媒介诱发证据 / AI预测
↓
Lina03 目标感受生成

并行高级线：Lina01 → Lina02 生克补 / 动态链 → Lina03 高级生成

Lina00 全程负责 HUMAN_GATE / 证据等级 / 版本治理
```

下游发现稳定 failure 时，只能回写十元问题系统，再由对应上游框处理；不得直接反向覆盖 canonical。

## 4｜统一状态模型

跨框资产至少同时保存：

- `theory_status`
- `mechanism_lifecycle`
- `evidence_level`
- `execution_status`

禁止用一个 `status` 同时表达“理论是否冻结、关系是否可调用、证据有多强、任务是否完成”。

### 常见状态不可混同

- `FROZEN_REGRESSION_ONLY`：理论已冻结，只在真实 failure 时重开。
- `ENDPOINT_REDEFINITION_FREEZE`：旧关系机制因端点变化冻结，当前不可调用。
- `ENGINEERING_PASS`：工程链跑通，不等于理论成立。
- `ARCHIVE_ONLY / LEGACY_NEEDS_CURRENT_GATE`：旧案例只供追溯，不是现行真值。

## 7｜总控读取顺序

以后 Chat / Agent / Codex 进入十元研究时：

1. 先读本文件确认职责与状态语义；
2. 再读十元问题总纲 / Canvas 确认当前感受版 Q；
3. 感受定义 / 五轴诱发机制进 Lina01；
4. 生克补 / 动态感受链进 Lina02；
5. 跨媒介诱发、AI感受预测、H3与目标感受生成进 Lina03；
6. 所有真实感受证据必须经过 HUMAN_GATE；
7. 结果回到 Lina00 做证据等级、版本、状态和索引验收。
