# 十元信息卡正本总览 v1.3

> 信息卡回答“它具体改变什么变量”；L1 五行正本回答“它是哪一阴阳五行位”；准度卡回答“为什么必须判成它”；关系卡回答“两个已成立端点之间发生了什么”。

## 1｜固定读取与回写顺序

```text
先读L1：确认十元的直接阴阳五行身份与相反轴
→ 分对象层
→ 读源/目标信息卡
→ 读源/目标准度卡
→ 读本轮单条关系卡
→ 查核心表与专项正本
→ 先回写单条关系卡
→ 本体变化时回写信息卡
→ 判定边界变化时回写准度卡
→ 最后写中枢与运行账本
```

卡片优化与版本规则：[[卡片优化与记忆回写协议_v1.0]]。

## 2｜最高五行本体口径

当前唯一正本：[[05-十元语义空间/L1_十元即阴阳五行相反轴正本_v1.2|L1 十元即阴阳五行相反轴正本 v1.2]]。

```text
五行就是十元。
十元就是木、火、土、金、水各分阴阳后的十个直接位置。
同行阴阳首先是相反两极。
```

| 五行轴 | 阳极十元 | 阴极十元 |
|---|---|---|
| 木 | `zx`＝阳木 | `nx`＝阴木 |
| 火 | `zn`＝阳火 | `x`＝阴火 |
| 土 | `n`＝阳土 | `x并z`＝阴土 |
| 金 | `xn`＝阳金 | `z`＝阴金 |
| 水 | `xz`＝阳水 | `nz`＝阴水 |

固定纪律：

1. 不得再写“五行在上、十元在下”或把二者当成两套系统；
2. 单个十元本身已经具有完整的阴阳五行身份；
3. `阳↔阴`表示同行相反轴，不等于已锁定的生、克、补、互补或转化；
4. 旧 `⨝` 交补构成口径停止作为核心正本；
5. 五行身份不能替代信息卡的具体变量定义，也不能由情志、颜色、职业、情绪或作品气质直接倒推十元。

## 6｜卡片记忆与版本

- 理论内容变化：递增卡片`version`。
- 有效运行记忆变化：递增`memory_record_version`。
- 最近运行写`last_memory_run_id`。
- 提交引用写`last_memory_commit: SELF`，实际SHA由Git历史与账本记录。
- 无新证据时不扩写信息卡和准度卡，只在对应单条关系卡保存紧凑复核记忆。

## 8｜版本纪律

1. `redirect-only`、`legacy-evidence-only`不得覆盖`canonical-current`。
2. 信息卡不得自行锁定生克补；关系卡不得改写十元本体。
3. 五行阴阳相反轴不等于单条十元生克补关系。
4. 五行相生相克是母结构，不能自动展开为全部十元细边。
5. 账本不得成为理论记忆唯一位置；可复用结论必须回填卡片。
6. 动态链只写关系启动后哪一层感觉走向改变，不把关系当机械生成器。

## 9｜最短召回

```text
L1：它是哪一阴阳五行位，与同行哪一端相反。
信息卡：它具体是什么、改变什么变量。
准度卡：为什么必须判成它。
单条生卡：A怎样使B出现或上升。
单条克卡：A怎样使B的核心变量下降。
单组补卡：A与B各自存在时，怎样分别补足对方缺口。
账本：证明哪一轮真实更新了哪张卡。
```
