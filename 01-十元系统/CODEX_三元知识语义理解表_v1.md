 # CODEX_三元知识语义理解表 v2（原路径正文革新）

## 0. 文件用途

本文件给 Codex / Obsidian 整理员使用。

它的任务不是发明理论，不是重新评分，不是重新分析作品，而是帮助 Codex 在整理文档时理解：

1. 三元基础语义
2. 十元基础语义
3. 体量、顺序感谱、五大主题的分层关系
4. 银矿字段含义
5. 哪些判断禁止自动脑补
6. 如何整理五大主题银矿仓

Codex 的身份是：

> 本地档案整理员 / Obsidian 文件工人 / Markdown 仓库搬运工

阿白 / 银矿哥负责理论判断与二审。  
Codex 负责文件整理、字段提取、索引生成、缺失标记。

## 1. 总原则：先分层，再整理

| 层级 | 回答的问题 | 整理用途 | 绝对禁止 |
|---|---|---|---|
| 三元 | 已判十元内部更关注物、认可还是整体关系 | 解释十元内部比例与质地 | 不得用三元派生、缩小或反推十元 |
| 十元 | 本体是什么 | 给作品、角色、关系、空间做结构标签 | 不要用视觉或结局倒推十元 |
| 体量 | 有多强 | 标注存在感强度 | 不等于力量、战斗力、大小 |
| 顺序感谱 | 第一反应先发生什么 | 判断起手与动态顺序 | 不等于善恶，不等于重要性 |
| 五大主题 | 上升到什么结构 | 给银矿按主题入仓 | 不等于十元起手 |
| 动态链 | 关系如何运动 | 生成骨型、模板、二审任务 | 不要硬套 zn 起手 |
| 功能位 | 点火 / 承载 / 冲突 / 结算 | 辅助整理链条结构 | 功能位不能替代十元本体判断 |

核心句：

> 十元独立定点位，三元解释内部质地，体量定强度，顺序定第一反应，五大主题定高阶结构。

## 2. 三元基础语义表

| 三元 | 最小语义 | 常见表现 | 在整理中的作用 | 不要误判成 |
|---|---|---|---|---|
| x（醒） | 具体物象、物质关系、归属、价值、局部因果 | 切分、判断、所有权、价格、功能、控制与保存 | 解释清楚精准以及人物层的自私狭隘 | 不要把危险、黑暗或欲望直接当作三元x |
| z | 精神个体需要认可主体看见、回应并确认自己 | 认可、证明、展示、荣耀、舞台、精神位置成立 | 解释对认可主体的需要 | 舞台追光必须回到认可结构 |
| n（耐） | 精神、整体与多方关系 | 理解、包容、协调、人际、群体、历史与整体关系 | 解释宏观关系理解及具体物质逻辑较散 | 不把区域大写成n更高级，不把n写成天然服从整体 |

## 3. 三元快速判断句

| 现象 | 优先考虑 |
|---|---|
| 注意力持续落在具体物象、归属、价值和局部因果 | x |
| 人物把自己与眼前对象切得很清，区域外的人和关系被弱化 | x |
| 人物需要某个认可主体看见、回应并确认自己 | z |
| 舞台、荣耀或证明行为能回到明确认可对象 | z |
| 人物持续理解、包容或协调多方精神与关系 | n |
| 注意力落在群体、社会、历史和整体关系，而非单件物象 | n |

注意：

> 三元只解释十元内部比例与质地，不作为前置底座，不派生十元，也不直接决定入库。

| x | 欲望 / 占有 / 深层驱动 / 失控强度 | 创伤、贪婪、占有、吞没、欲望、压迫、恐惧 | 标记本体欲望、反噬、崩坏源 |

## 5. 体量理解表

体量表示：

> 在不在场、强不强、占不占空间。

体量不表示：

- 战斗力
- 物理大小
- 能力强弱
- 谁更重要
- 谁更善恶

| 体量 | 整理理解 | 常见表现 |
|---|---|---|
| 1-2 | 几乎不可察 | 背景、微弱、只作铺垫 |
| 3-4 | 可感知但不压场 | 辅助节点、局部出现 |
| 5 | 标准存在值 | 能支撑一段剧情 |
| 6-7 | 明显存在 | 开始影响他人或场域 |
| 8-9 | 场域级存在 | 角色或结构本身成为事件 |
| 10 | 极限存在 | 本体即空间，叙事围绕其运行 |

Codex 注意：

> 如果原文没有体量，不要自动补体量。写“不确定”。

## 6. 顺序感谱理解表

顺序感谱回答：

> 第一反应先发生什么？

它不回答：

- 谁更强
- 谁更重要
- 谁善恶
- 谁是最终主题
- 谁一定是本体

| 顺序 | 基础理解 | 常见对应 |
|---|---|---|
| 123 | 先安顿，再行动，再推进 | n / N |
| 慢123 | 缓慢抵达，延迟结束 | nz |
| 132 | 先中心显现，再带动行动 | zn / ZN |
| 213 | 先反馈，再评估，再定价 | xn / x并z；不得再因“评估、定价”自动补nx |
| 231 | 先忍耐，再爆发，再结算 | z / xz |
| 312 | 先动手，再思考，再改写 | zx |
| 321 | 被拖入深处，欲望或压迫先吞没 | x |

Codex 注意：

> 顺序感谱可以辅助整理，但不能用它反推十元本体。

## 7. 五大主题归类表

五大主题是十元互补组上升后的高阶结构。

| 五大主题 | 公式 | 核心问题 | 入仓判断 | 典型动态结果 |
|---|---|---|---|---|
| 时间 | xn+z | 规则、期限、节拍如何压出爆点？ | 作品核心围绕时间规则、记忆顺序、倒计时、等待、错过展开 | 记忆封存、擦除后回吸、倒叙剥皮、光点压成一生 |
| 本体 | zn+x | 角色真正靠什么活着？精神与欲望如何撕裂？ | 作品核心围绕身份、主体资格、身体、人格、自我认知展开 | 作品吞生、表象反噬本体、身体脱壳、主体殖民 |
| 空间 | x并z+n | 什么容器承载了关系、阶级、制度或观看？ | 作品核心围绕家、建筑、舞台、机构、城市、封闭场域展开 | 包装空间破壳、语言围栏、阶级容器爆裂、空间庇护腐烂 |
| 因果 | zx+nx | 公式暂保留；旧“nx=暗线结算”解释作废 | 旧因果仓必须重新区分xn的判断结算、zx的执行与nx的被动延续 | 内容显影待二审，不再用旧账暗流反推nx |
| 命运 | xz+nz | 为什么相遇、漂流、停靠、分离？ | 作品核心围绕失位、漂流、临时归属、归家失败、停靠资格展开 | 非法亲缘、停靠错认、双重归属重判、无法归家 |

Codex 注意：

> 五大主题用于入仓，不用于倒推起手。

## 8. 银矿等级规则

| 分数 | 等级 | 入库状态 |
|---:|---|---|
| 95-100 | 金矿 | 正式银矿，优先二审 / 可升核心锚点 |
| 90-94 | 高银矿 | 正式银矿，二审后可升锚点 |
| 85-89 | 银矿 | 正式银矿，但要保留污染风险 |
| 85以下 | 铜矿 / 废矿 | 不进入正式银矿仓 |

硬规则：

> 85分以下不得进入正式银矿库。

## 9. 银矿字段解释表

| 字段 | 含义 | Codex 怎么填 | 缺失时 |
|---|---|---|---|
| work | 作品名 | 使用原文档里的作品名 | 不要猜 |
| score | 分数 | 直接复制已有分数 | 不确定 |
| level | 等级 | 95+金矿，90-94高银矿，85-89银矿，85以下铜矿 | 按分数换算 |
| theme | 五大主题 | 时间 / 本体 / 空间 / 因果 / 命运 | 不确定 |
| start | 起手 | 第一推动力对应十元 | 不确定，不要用五维回填 |
| relation | 十元关系 | 谁作用谁，推进 / 污染 / 反咬 / 克制 / 互补 / 桥接 | 不确定 |
| dynamic_result | 动态链结果 | 链条跑完后的骨型名 | 不确定 |
| zn_status | zn状态 | 起手 / 被压出 / 被激活 / 被包装 / 被改写 / 被回收 / 失去落点 / 非主线 | 不确定 |
| review_status | 审稿状态 | 待二审 / 已二审 / 降铜 / 核心锚点 | 默认待二审 |
| priority | 优先级 | S / A / B / C | 不确定 |
| source_round | 来源轮次 | R1 / R2 / R24 等 | 不确定 |

## 14. 绝对禁止项

1. 不要默认 zn 起手。
2. 不要默认 n 是承载位。
3. 不要把五大主题当十元起手。
4. 不要用结局倒推起手。
5. 不要用视觉风格反推本体。
6. 不要把体量理解成战斗力。
7. 不要把名作光环当入库理由。
8. 不要把“感觉很像”当十元关系证据。
9. 不要把 85 分以下放入正式银矿仓。
10. 不要修改已有评分，除非文件中已有二审结论。
11. 不要把功能位当成十元本体。
12. 不要把动态链结果写成 zn 专属。
13. 不要把作品题材当主题本质。
14. 不要把主题情绪当链条证据。

## 15. Codex 最终执行口令

你是 Codex，本地 Obsidian 文档整理员。

你的任务是：

1. 读取银矿文档。
2. 识别作品字段。
3. 补齐 YAML frontmatter。
4. 按五大主题移动文件。
5. 生成索引与待二审列表。
6. 记录字段缺失与冲突。
7. 不确定时写“不确定”。

你不能：

1. 新增作品。
2. 重评作品。
3. 脑补缺失字段。
4. 修改理论规则。
5. 把五维主题倒推成起手。
6. 把名作光环当入库理由。

遇到不确定：

> 写“不确定”，并放入“待人工二审”。

核心分工：

## 16. 最终封存句

这份表不是理论大全，而是 Codex 的语义入馆证。

它只负责让 Codex 明白：

1. 什么该搬到时间仓。
2. 什么该搬到本体仓。
3. 什么该搬到空间仓。
4. 什么该搬到因果仓。
5. 什么该搬到命运仓。
6. 什么字段缺牙。
7. 什么东西不能乱补。

最终目标：

> 把聊天残骸整理成可查询、可二审、可复用的五大主题银矿仓。
