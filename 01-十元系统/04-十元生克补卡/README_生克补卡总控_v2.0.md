# 十元生克补卡总控 v2.0

> 信息卡确认端点是什么；准度卡确认为什么必须判成该端点；每条生、每条克、每组补分别进入独立关系卡。总控只导航，不承载完整关系正文。

## 1. 三个独立目录

- 生：[[生/README_十元生卡索引_v1.0]]，10张单条生卡。
- 克：[[克/README_十元克卡索引_v1.0]]，10张单条克卡。
- 补：[[补/README_十元补卡索引_v1.0]]，5张单组补卡；每卡内部拆两个补向。

## 2. 每轮写入目标

```text
本轮关系对应单卡（必写或明确无新记忆）
→ 源/目标信息卡（本体变化时写）
→ 源/目标准度卡（判定边界变化时写）
→ 核心表、词典、专项正本（达到95%并改变正式机制时写）
→ 滚动中枢
→ 唯一运行账本
```

## 3. 关系类型最小差异

- 生：目标此前不足或不存在；源使目标自身核心变量出现或持续上升。
- 克：目标关系前真实存在；源使其核心能力、资格、边界或调用下降。
- 补：两端独立存在；一端补入后改变另一端的真实结构缺口，拿掉后原端仍在但缺口重现。

## 4. 卡片双版本

每张单卡维护理论`version`和`memory_record_version`。理论结论没变时不涨理论版本；运行新增有效复核记忆时才涨记忆版本。提交自引用使用`last_memory_commit: SELF`，实际SHA写入Git历史与运行账本。

## 5. 七项置信度

分别记录源端点、目标端点、机制、独立证据、竞争解释排除、拿掉/反向可逆性、跨案例复现，最终取最弱项。七项均不低于95%才允许锁定。

## 6. 未锁定关系卡的95%证据缺口块

所有`relation_status: research-active`的单条关系卡必须包含：

```text
## 达到95%还缺什么证据
- 当前最弱项
- 已有证据
- 尚缺控制证据
- 优先采矿：电影/叙事、史料/现实、对照/反例
- 锁定条件
- 否定或降级条件
```

规则：

1. 该区块不是愿望清单，必须从七项最低分、最近邻、拿掉、反向和第三因素推出。
2. “尚缺控制证据”必须写成可观察、可失败的条件，禁止只写“需要更多案例”。
3. “优先采矿”必须说明找哪类人物阶段、制度环境和反例，不得只列作品名。
4. “锁定条件”必须说明需要多少种独立模板、通过哪些控制、七项达到什么门槛。
5. “否定或降级条件”必须明确该关系何时退回共现、显影、加权、状态压制、策略调整、授权或最近邻。
6. 轻量轮无新增证据时不得空改本区块；完整审计、新反例、链条问题单复核或第三因素隔离改变缺口时才更新。
7. 每轮检索、采矿和案例选择必须优先服务本区块，不得继续盲目增加相似案例。

已锁定关系卡不强制写“还缺”，后续复核时可使用同构的`95%保真与降级条件`区块，记录哪些控制一旦失败就必须降级或解锁。
