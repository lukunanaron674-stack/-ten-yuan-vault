# x 准度卡 v0.1

> **x = 对象、资源、地盘、权限或关系进入“归我 / 我方掌握”的边界，主体拥有实际占有、使用、调配、调用、处分或排除能力。**

## 必要条件

1. 被掌握对象明确；
2. 掌握主体明确；
3. 实际权限类型明确：占有、使用、调配、调用、处分、否决或排除；
4. 这种权限不是纯名义、视觉或一次接触；
5. 拿掉掌握关系后，案例核心明显变化。

## 对象分层

- 人物本体：长期依靠掌握对象与范围成立。
- 状态：当前阶段取得或失去某项控制。
- 行为：占有、收拢、划界、调配、保护范围。
- 关系：谁能决定对象的使用、退出、调用和归属。
- 场景：地盘、金库、办公室、账户只是载体。
- 视觉：黑暗、收藏、幕后、压迫只作辅助。

## 最近邻

```text
x vs zx：x是有权与掌握；zx是显权、扩权和公开凌驾。
x vs xn：x回答什么归我调配；xn回答怎样组织它持续运行。
x vs nx：x拥有权限；nx承认权限在别人手里并沿通道借用。
x vs x并z：x是内部掌握边界；x并z是该边界的公共识别与调用壳。
x vs nz：x可以独占与替代决定；nz要求自由离开、回返和修复。
```

## 非充分条件

贪婪、黑暗、吞噬、收藏、反派、老板、资本家、幕后、控制欲、拥有贵重物品，均不能单判`x`。

## 拿掉测试

拿掉头衔、外观、威慑和公开显权，只保留实际权限。若主体仍能调配、处分、调用或排除，`x`成立。若权限来自别人且随时可撤，检查`nx/x并z`。

## 反向测试

- 公开威风但没有实际处分权：偏`zx`或视觉。
- 掌握流程但不能决定对象归属：偏`xn`。
- 能让系统停摆但不能正向处分：关键人瓶颈，不足以判完整`x`。
- 只有密码、职位或代理授权：必须检查授权来源与撤权后是否仍成立。
- 关系对象可自由退出，主体主动缩窄掌握：`x`下降。

## 六项评分

`object_layer / endpoint_fit / neighbor_exclusion / evidence_independence / removal_reverse / cross_context`分别评分，最终取最小值。

## 召回版

```text
什么归谁？
谁能使用、调配、处分、否决或排除？
没有实际掌握权，不能判纯x。
```
