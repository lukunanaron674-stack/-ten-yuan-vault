# 十元准度卡总控 v0.5

> 信息卡回答“它是什么”；准度卡回答“为什么这个对象必须判成它”；单条关系卡回答“两个已成立端点之间怎样发生生、克或补”。准度结论不能只留在运行账本。

## 1. 固定流程

```text
明确判断对象与阶段
→ 分稳定本体 / 状态 / 行为 / 场景 / 光影 / 时间关系 / 关系位置 / 显影 / 动态链
→ 读取现行信息卡
→ 列出至少两个最近邻
→ 做必要条件、拿掉与反向测试
→ 输出六项端点置信度
→ 端点稳定后进入对应单条关系卡
```

三元与十元并行核验，不写成父子派生。

## 3. 六项端点置信度

1. `object_layer`；
2. `endpoint_fit`；
3. `neighbor_exclusion`；
4. `evidence_independence`；
5. `removal_reverse`；
6. `cross_context`。

最终取六项最小值。关系卡的七项评分是另一层：它把源端点与目标端点分开，再增加关系机制、竞争解释与关系复现，不得混用。

```text
95–100：对象层明确、必要条件完整、两组独立证据、最近邻排除、拿掉反向通过、跨情境复现。
90–94：主判稳定，但仍缺一个关键控制。
80–89：强候选，仍混有第三因素、状态层或相邻类型。
60–79：主要是共现、行为、视觉或场景相似。
0–59：端点或方向不稳定。
```

强制封顶：层级混淆≤79；只有视觉/题材≤59；最近邻仍解释主要变化≤79；单事实换词≤69；拿掉或反向失败≤79；单阶段却判本体≤79。

## 4. 三个门槛

- 80%：强候选，不自动生成关系链。
- 90%：当前对象层稳定工作判定。
- 95%：正式端点进入关系锁定或正本修正。

工程执行95%与理论判定95%不得混用。

## 5. 卡片记忆回写

当一轮研究改变必要条件、最近邻、拿掉/反向结果、误判来源或评分封顶时，必须直接更新对应准度卡：

- 实质理论变化递增卡片`version`；
- 新增有效运行记忆递增`memory_record_version`；
- 写入`last_memory_run_id`与`last_memory_commit: SELF`；
- 账本只记录路径、版本和实际提交SHA。

无准度变化时不得为了完成任务空涨版本。完整规则见[[../卡片优化与记忆回写协议_v1.0]]。

## 7. 禁止事项

- 不得用角色名、职业、服装、光色或题材替代十元。
- 不得把一次行为升级为稳定人物本体。
- 不得把关系机制写成十元本体定义。
- `z克nx`仍未锁定；旧“z持续决定和占位，把nx让没”不得调用。
- `xz`临界行动是高显影，不是必要条件。
- `nz`等待与余温只是子型。
- `x并z`内外不一只是子型。
