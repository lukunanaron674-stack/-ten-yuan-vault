# 自主推进与提问阈值协议 v0.1

## 1. 总原则

> **只要有至少 95% 的把握，用户会同意该结论或处理方式，就直接完成，不重复请示。**

> **只要存在超过 5% 的概率，用户会给出另一种答案，而且该差异会改变理论主骨、关系方向、文件结构或创作结果，就先提问。**

这不是要求所有判断达到数学意义上的精确概率，而是要求助手明确区分：

```text
可由已有口径稳定推出
vs
存在真实分叉，需要用户裁决
```

## 2. 可以自主完成的事项

满足下列条件时直接执行：

- 只是整理用户已经明确表达的口径。
- 修正与最新口径直接冲突的旧文档。
- 将同一规则同步到准度卡、总控、纠正档案和迁移入口。
- 补齐格式、索引、版本号、交叉链接和错误代码。
- 将确定的概念拆成本体、状态、行为、环境、结果等对象层级。
- 根据已锁定定义制作判定模板、反例、边界检查和盲测格式。
- 将明显过时材料降级到历史池或待二审池，但不擅自删除历史。
- 在不改变理论结论的前提下，优化措辞、顺序和可执行性。

## 3. 必须向用户提问的事项

出现以下任一情况时提问：

- 两个以上解释都与现有材料相容，且会改变核心定义。
- 会改变生、克、补的标准方向。
- 会把一个材料从一个十元正式迁移到另一个十元。
- 会决定一个复合结构究竟是主副、桥接、污染还是时间变化。
- 会改变人物本体，而不仅是状态、行为、视觉或环境。
- 用户曾经给过互相冲突的口径，无法通过日期与明确纠正判断最新版本。
- 一个命题虽合理，但用户已经明确说“很难说”“需要讨论”“先不要锁死”。

## 4. 不应提问的伪问题

以下问题不得反复打断用户：

- 文件叫什么名字更整齐。
- 标题、标签、目录和版本号如何统一。
- 已明确口径是否要同步到相关旧卡。
- 是否要把已确认错误标成 deprecated。
- 明显可以从上下文恢复的主语、对象或术语。
- 只影响表述、不影响理论结构的细节。

## 5. 推断标签

自主完成但尚未由用户逐字确认的内容，必须按影响程度标记：

| 标签 | 含义 | 处理 |
|:---:|:-----|:-----|
| LOCKED | 用户明确说过 | 可作为正式主骨 |
| DERIVED | 由锁定口径高置信推出 | 可执行，可在后续案例中复核 |
| CANDIDATE | 存在真实分叉 | 不锁定，等待用户裁决 |
| LEGACY | 历史旧口径 | 保留但不得作为当前依据 |

## 6. 置信度与理论准度的区别

- **95% 阈值**：决定助手要不要继续追问用户。
- **80% 准度闸门**：决定一个案例能不能进入生克补与动态链。

二者不能混用。

## 7. 最短执行规则

```text
已有口径能稳定推出 → 直接做
存在真实结构分叉 → 问
只是格式与同步问题 → 不问
用户说“待讨论” → 不锁死
```
