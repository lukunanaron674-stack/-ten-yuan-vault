# 十元准度卡总控 v0.1

> 血肉卡回答“它能长成什么”；准度卡回答“为什么必须判成它”；关系卡回答“判定以后怎样生、克、补”。

## 1. 开发顺序

```text
三元定义
→ 三元判定
→ 三元到十元的构成关系
→ 十元准度判定
→ 血肉扩展
→ 生克补判定
→ 动态链与故事
```

**禁止倒序：**不能因为一条故事链好看，就反推人物本体或十元类型。

## 2. 五种对象必须分开

每次判定前先标记对象：

1. **本体**：人物长期稳定的发动结构。
2. **状态**：当前阶段或当下情绪。
3. **行为**：这一次采取了什么方式。
4. **环境 / 场域**：外界正在形成什么压力结构。
5. **结果**：事件最后落成什么形态。

不同层级出现不同十元，不等于人物本体不断换标签。

## 3. 判定闸门

在以下项目没有完成前，不进入生克补：

```text
[ ] 判断对象已明确
[ ] 三元主次已有证据
[ ] 十元必要条件成立
[ ] 相邻十元已排除
[ ] 本体 / 状态 / 行为 / 环境没有混淆
[ ] 置信度达到 80%
```

低于 80% 时只输出候选，不生成关系链。

## 7. 当前硬规则

- `xz` 不能只靠暗色、破损、怪物造型判断。
- `nx` 不能再只靠暗算、看牌、结算、聪明判断。
- 流行词可以作为召回入口，但不能代替必要条件。
- 图像适合建立外显原型；关系型十元必须补连续行为脚本。
- 三元构成尚未正式锁定的部分，必须标注“待三元表校验”，不得自行补理论。

## 8. 验收指标

```text
三元判断准确率 ≥ 90%
对象层级判断准确率 ≥ 90%
十元相邻类型准确率 ≥ 80%
主副与体量判断准确率 ≥ 75%
```

达到门槛后，再将准度卡接入生克补和动态链自动化。
