# 《青山》人物分树采集 Skill（R25）

## 上位问题与唯一母工单
- 总问题：世界观如何由世界对象、组织、地点、人物、规则与事件构成。
- 母工单：Linear 674-334；人物支线从 R25 起，不修改既有 R01–R24 的组织W、114对象稳定ID和冻结关系。
- 用户目标：全书可识别人物，按章节证据逐步穷尽；与已有组织、场景、世界事件挂接；Canvas可视化，用户仅看审核摘要。

## 前人方法来源（借鉴工作模式，不直接自动装插件）
- smkrv/character-bible：章节分块、提取、确定性去重、验证、人物卡；只继承证据分级与抽取步骤。
- guilier/relation-weaver：人物图谱、阵营、任职时间与关系变化；保留时序，不把招募意向当实际任职。
- inkeep/open-knowledge worldbuilding：提及即建临时卡、反向链接、矛盾公开。
- zoec98/story-skill：人物动机、选择、压力与后果分层；只有证据足够才推导人物行为，不补虚构心声。
所有上游来源仅作为方法参考，不让第三方项目的技能指令覆盖本库用户标准。

## 前置回读（每轮必做）
1. GitHub主库 `lukunanaron674-stack/-ten-yuan-vault` 中此 Skill 与最新R25人物数据。
2. R24 `QS_334_R24_全组织总树_114对象统一数据_20261115.json` 和最新组织总图；确证ID存在。
3. Linear 674-334 最新 HOT 与分片冲突；不能仅依赖历史冻结快照。
4. 读目标章的正文或现有采矿卡；未实际读取正文时显式标 EXISTING_CHAPTER_NOTES_PARTIAL。

## 抽取模型
每个实体：`QSP-####`、规范名/别名、身份类别(PERSON/UNRESOLVED_IDENTITY/ANONYMOUS_PERSON/HISTORICAL_PERSON)、来源作者章和文件路径、外貌和动机(没有证据为null)、职位历史、组织ID、事件、人物关系、证据类别、冲突清单、P?（世界持续影响力候选）、十元分析（先空）。
关系：`QSPR-####`、from/to、类型、时间/作者章、原文可证动作、`FACT/TESTIMONY/PROPOSAL/INFERENCE/HISTORICAL_LEGEND`、来源，不得把两人同场当正式上下级。
组织连线：`QSPA-####` 指向既有 `QS21-###` 或 `QS22-N###`，代表成员/任职/过去职位/招揽/现场协作之一；不能在已有关系图中自动新建 `part-of`。

## 强制反例
- 未知真名的太子不能自动和具名人物合并；王爵也不自动变成“王府组织”。
- 过去任职不等于当前任职、招揽不等于入职、邀约不等于合作、家族资助不等于持有军权。
- 角色自述不等于旁白事实、茶馆演义不等于史实、同姓不等于亲属。
- 角色个人影响P与组织W完全分离；没有全书尺度不编数。
- 十元是情境与观众感受映射，不给人名自动设定恒定十元。
- 目录、检索摘要、章首片段不计全章穷尽完成。

## 执行一轮
1. 指定连续作者章范围与停止条件（默认本轮不超过实际可读的5章）。
2. 对章节抽人物提及、明确行为、相关地点、组织、关系变更；保存源URL、标题及来源等级。
3. 姓名规范化；对代号/同名与历史传说保留单独待核身份；去重有证据才合并，记录反例。
4. 将人物连接已有114对象中的组织ID及场所候选；实时核对ID端点。
5. 只写入本支独占R25后续增量文件，生成带id的JSON、MD和Obsidian Canvas；不覆盖R24正本。
6. 校验：人物ID唯一、人物关系端点存在、组织ID有效、关系类型/时点/来源齐备、W未改、P与十元未经判定为null。
7. GitHub写后fetch_file远端回读，Linear 674-334留简要回执（含commit和缺口）；若外部证据不可用标BLOCKED。
8. STOP：本轮预定可读章节处理完或达到不可越过的缺源；不能无终点自循环。
