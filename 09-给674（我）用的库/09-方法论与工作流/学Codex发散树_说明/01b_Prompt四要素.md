# 📝 Prompt 四要素

> 写齐四样，Codex 少瞎猜、少乱跑、少返工。

## 为什么

Codex 只能看到你给的信息。信息越含糊，它越靠"猜"，猜错就返工、乱改、跑偏。

四个要素把「要什么、在哪、什么不能碰、怎样算完」一次说清，等于给它一张**验收清单**，做完还能自查。

## 四要素

| 要素 | 一句话 | 缺了会怎样 |
|---|---|---|
| 🎯 **Goal（目标）** | 要达成什么 | 它不知道该干什么 |
| 📂 **Context（上下文）** | 涉及哪些文件 / 报错 / 设定 | 它自己乱找或瞎猜 |
| 🚧 **Constraints（约束）** | 不能碰什么、按什么标准 | 它可能改坏别处 |
| ✅ **Done when（完成标准）** | 怎样算完成 | 它说"好了"，但你没法验收 |

## 每个要素怎么写

1. **🎯 Goal**：动词 + 对象 + 结果
   - ❌ "帮我弄一下脚本" → ✅ "给 `scripts/clean.ps1` 加一个 `-DryRun` 预览开关"
2. **📂 Context**：@ 引用文件 + 关键背景
   - 直接 **@文件** 引用最省事，比贴大段文字准
   - 相关报错原文、约束文档一起给
3. **🚧 Constraints**：范围 + 标准 + 禁止项
   - "别动别的模块""保持现有参数默认值""用中文输出""16:9 横构图"
4. **✅ Done when**：可验证的完成条件
   - "测试通过""能跑起来""跑 `-DryRun` 只打印、不动盘""这个 bug 不再复现"

## 例子（前后对比）

### ❌ 模糊版

> 帮我改一下清理脚本

### ✅ 四要素版

> 🎯 给 `scripts/clean.ps1` 加一个"只预览不删除"的开关
> 📂 参照 @clean.ps1 现有参数
> 🚧 不改变默认行为；新增 `-DryRun` 参数
> ✅ 跑 `-DryRun` 时只打印要删的文件、不动盘；普通模式行为不变

## 直接套的模板

```
🎯 Goal：改什么 / 做出什么
📂 Context：@文件 或 关键背景
🚧 Constraints：不能碰什么、按什么标准
✅ Done when：怎样算完成（可验证）
```

## 什么时候写全 vs 简写

- 一句话能说清的小活：不必硬凑四要素，写完让它"做完自己验证"即可
- 复杂 / 高价值 / 怕它乱改的任务：写齐更稳，尤其 **Context 和 Constraints**
- 和发散树 / 子代理配合：把四要素写进任务描述，子代理才知道边界和验收标准

## 你要记得

✅ Goal 用"动词 + 对象 + 结果"写具体
✅ 文件用 @ 引用，别贴大段内容
✅ Constraints 先写"不能碰什么"，再写"按什么标准"
✅ Done when 要**可验证**，否则没法验收
❌ 别只说"帮我看看 / 帮我弄一下"，它只能猜

## 配合推理档位

- 简单任务：Low 更快
- 复杂调试 / 多步：Medium / High 更细（本机已设 medium）
