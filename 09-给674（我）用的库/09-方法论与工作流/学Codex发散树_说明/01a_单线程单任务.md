# 🧵 单线程单任务

> 一个 chat 只干一件事。

## 为什么

Codex 每次回复都会把**整个对话历史 + 系统上下文**打包发给模型。历史越长 → 处理越慢 → 越"卡"。

你实测：一个跑了一整天的 chat，上下文堆到 **20 万 token**，一次回复首字要 20~26 秒，还出现过 gpt-5.6-luna **502 上下文超窗**。

官方 Best Practices 把它列为头号反面教材：

> "Using one chat for an entire project instead of one chat per coherent outcome. This leads to bloated context and worse results over time."

## 怎么做

### 长对话处理
- **`/compact`**：对话变长时，把早期上下文压成摘要（Codex 也会自动压缩）
- **`/fork`**：开新线程但保留原对话记录（工作真正分叉时用）

### 拆线程的原则
- 一个 **coherent 结果** = 一个线程（"修完这个 bug""生成这套分镜"各一个）
- 还在同一件事里 → 留在同一个 chat（保留推理脉络）
- 真正分支了 → 才 `/fork`
- 项目级杂活 → 拆给子代理，别塞主线程

## 你要记得

✅ 新任务就新开线程
✅ 感觉线程又长又乱 → 先 `/compact` 再继续
❌ 别把一整个项目塞进一个 chat 连轴转一整天
