# 学 Codex｜发散树（根节点）

> 从一个线程干一件事开始，把 Codex 用顺。

## 这张图在讲什么

把"怎么把 Codex 用好"拆成四个区块，按优先级排：

- 🥇 **第一优先级｜治卡 + 每天用** —— 直接解决你"Codex 加载卡"的三大根因
- 🥈 **第二优先级｜提升质量** —— 让产出更可靠、少返工
- 🥉 **第三优先级｜进阶** —— 进阶工作流（skill / 子代理 / 定时）
- ⚠️ **安全与文件卫生** —— 权限风险 + 本地文件维护

## 为什么"单线程单任务"排第一

你今天卡顿的根因，官方 Best Practices 直接命中：

> "Using one chat for an entire project instead of one chat per coherent outcome. This leads to bloated context and worse results over time."

一个 chat 从早上跑到晚上、上下文堆到 20 万 token，每次回复前模型都要处理整个历史 → 首字要 20~30 秒 → 体感就是"卡"。

## 本机背景（实测）

- `C:\Users\19308\.codex` 是 **Junction → `E:\C_Migration\19308\.codex`**，真实文件在 E 盘
- 会话记录在 `C:\Users\19308\.codex\sessions\<日期>\rollout-*.jsonl`，只会越长越大
- 当前模型走 opencodex 代理（`127.0.0.1:10100` → DeepSeek）
