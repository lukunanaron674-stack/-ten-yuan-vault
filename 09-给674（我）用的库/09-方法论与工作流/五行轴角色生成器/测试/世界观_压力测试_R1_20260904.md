# 五行轴角色生成器｜世界观压力测试 R1

> 本文件只测试应用映射层，不修改 L1/L2 canonical、信息卡、准度卡或正式关系卡。

## 1｜测试目标

当前应用层只有 `zx × 世界观` 与 `z × 世界观` 两格，因此本轮选择 **世界观模块横向压力测试**。重点检查：

1. 三种模式是否真的具有不同算法语义；
2. zx / z 的最近邻是否偷渡；
3. 题材翻译是否只换皮、不换 changed_variable；
4. 具象名词是否被误当成十元定义；
5. 当前映射数量是否导致模板重复；
6. seed、模块锁定、人生顺序等能力是否已经有真实实现。

## 2｜重要实现事实

仓库当前只有应用映射 Markdown，没有发现可执行生成器代码、seed 状态机、模块锁定状态机或自动压力测试脚本。因此：

- 可以进行 **静态结构化样本审计**；
- 不可以伪造 runtime 通过；
- `mode_failure_rate / seed_reproducibility / lock_integrity / life_order_error_rate` 中依赖真实代码的项必须标记 `NOT_IMPLEMENTED`；
- 多符号模式虽然有规范，但当前没有 zx↔z 的组合规则、职责分配算法或可执行 composer，故多符号 20 个样本均只能形成 `BLOCKED_NOT_IMPLEMENTED` 测试样本，不能伪造为有效生成。

## 4｜八项指标

| metric | result | 解释 |
|---|---:|---|
| semantic_drift_rate | `0/40 = 0% (STATIC_AUDIT_ONLY)` | 只统计 S/G 40 条人工结构化审计样本；不代表 runtime 已通过 |
| neighbor_leak_rate | `0/40 = 0% (STATIC_AUDIT_ONLY)` | 所有有效静态样本保留 zx/z 的 nearest-neighbor 排除；不代表程序能自动守门 |

## 5｜5 个代表失败样本｜永久回归集 R1

### FAIL-R1-01｜题材换皮冒充新结构

```text
zx → 公开挑战 → 决定席转移 → 挑战席 → 中古奇幻
zx → 公开挑战 → 决定席转移 → 权限挑战节点 → 科幻
```

失败点：只有名词与题材改变，relation_shape 相同。若系统把两条计成两个新“结构”，重复率统计失真。

**回归门**：去除 genre/concrete 后必须归一到同一 structure_id。

### FAIL-R1-02｜多符号职责来源缺失

```text
zx 主：公开挑战取得决定席
z 副：确认挑战结果
```

失败点：当前没有规则说明 z 为什么是副符号、谁负责 changed_variable、确认是否只是普通流程结果。

**回归门**：无明确 `primary_variable / secondary_variable / composition_relation / source_evidence` 时禁止生成。

### FAIL-R1-03｜z 被自动登记系统偷换

```text
z → 身份确认 → 自动数据库登记 → 身份成立
```

失败点：拿掉明确认可主体后仍成立，应该转查 xn/x并z，不应继续 z。

**回归门**：z 样本必须存在 named recognition/adjudication subject；否则 neighbor leak。

### FAIL-R1-04｜zx 被静态王位偷换

```text
zx → 王冠 → 皇帝 → 最大领地
```

失败点：没有公开介入、他者被迫响应或决定范围的实际变化，只是身份/静态掌握。

**回归门**：zx 样本必须有 observable response + decision-scope transition；缺一即拒绝。

### FAIL-R1-05｜无向量模式偷偷恢复强度

```text
zx 80% → z 20% → 强zx世界
```

失败点：把审美强度伪装成理论尺度，违反无向量模式。

**回归门**：graph mode 禁止 percentage / strength_score / weighted_symbol 字段。

## 6｜本轮实际修复

本轮无法修复不存在的 generator runtime，因此没有伪造代码修改。实际落地修复为：

1. 建立第一份 **60 样本压力测试基线**；
2. 明确把 runtime 未实现项写成 `NOT_IMPLEMENTED`；
3. 建立 `FAIL-R1-01`—`FAIL-R1-05` 五个永久回归样本；
4. 建立结构归一化要求：题材/具象变化不能自动算新结构；
5. 建立多符号组合硬门：没有 `primary_variable / secondary_variable / composition_relation / source_evidence` 时直接阻断；
6. 建立 zx、z 最近邻最低 guard；
7. 建立 graph mode 禁止权重字段的回归门。

## 8｜下一轮最高风险

### P0｜先实现“结构 ID / 去重归一化”

当前 `duplicate_structure_rate = 75%`。若继续扩题材和具象名词而没有结构归一化，库会迅速产生大量“看起来不同、实际上同构”的垃圾变体。

建议下一实现最小结构：

```text
structure_id = hash(symbol + module + changed_variable + relation_shape + module_grammar)
```

`genre_translation` 与 `concrete_candidate` 不进入 structure_id，只作为变体层。

### P1｜实现三模式真正不同的 composer

- single：同 symbol 内跨 sub_semantic 取模块；
- multi：必须显式 primary/secondary variable 与 composition relation；
- graph：仅节点/关系，不允许权重。

### P2｜再实现 seed 与 lock

在结构归一化与 composer 未完成前，先做 seed/锁定只会稳定复现错误算法。
