# z × 世界观｜应用映射 v0.1

> 本文件只属于生成器应用层。任何建筑、职业、颜色、奖项、舞台、王座、印章、榜单都不是 z 定义。

## 0｜本轮判定：存在 current 口径同步债

当前三份高相关材料不能无缝合并：

1. `L1_十元即阴阳五行相反轴正本_v1.6`：金轴 `xn↔z` 的广义变量是“运行权与裁定重心配置”，z 端写作“收束到单一最高裁定点”。
2. `【z信息量卡v2.2】` 与 `z_准度卡_v0.1`：z 核心仍是明确认可主体对主体的存在、能力、作品、选择或发现进行看见、回应、确认；没有认可主体与认可内容不能锁纯 z。
3. `角色行为案例库/z.md` 虽含 `evidence-locked` 记录，但文件首义仍是“单点最高化、认可不是必要条件”，并且同行映射仍出现旧的火轴表述，和 current L1 v1.6 的金轴 `xn↔z` 不一致。

因此本轮纪律：

```text
只使用 current L1 与 z 信息卡/准度卡的安全交集生成候选；
旧 evidence-locked 只作为“存在历史冲突”的证据，不作为本轮 evidence-supported 升格依据；
全部正向候选暂记 pending-review；
不得由 L5 应用层裁决 z 的最终本体。
```

## 1｜本轮安全交集

```text
明确对象
→ 进入一个对其具有重要性的确认/裁定位置
→ 明确主体看见、回应、归因或确认
→ 对象在该位置上的成立状态发生变化
```

应用层暂把 relation_shape 写成：

```text
many observations / claims / candidates
→ one designated recognition-or-adjudication position
→ explicit confirmation on a named object
→ recognized status becomes active / denied / revoked
```

这不是宣称“单一最高裁定点 = z 定义”，而是只取 current 两套材料都不会直接否定的结构交集。

## 7｜明确拒绝的 3 类表面联想

### R1｜“王座 / 皇冠 / 皇帝 = z”

- `status`: rejected
- 原因：身份与视觉中心不等于认可关系，也不自动证明单一裁定位置如何对明确对象完成确认。
- 最小反例：世袭皇帝从出生即拥有王冠，但从未参与任何确认关系或裁定变化。

### R2｜“舞台 / 聚光灯 / 奖杯 = z”

- `status`: rejected
- 原因：current z 准度卡明确规定舞台、聚光、成功、获奖、被很多人看见均非充分条件。
- 最小反例：自动播放的虚拟偶像永久站在聚光灯下，没有重要认可主体，也没有确认内容。

### R3｜“唯一目标 / 执念 / 只走一条路 = z”

- `status`: rejected-for-current-generator
- 原因：行为库旧 evidence-locked 仍有此口径，但 current z 信息卡/准度卡明确要求认可主体；同时 current L1 v1.6 将 z 放在金轴裁定重心端。应用层无权选择旧行为库覆盖 current 卡。
- 最小反例：某人终生独自攀登同一座山，完全不需要任何见证、确认、评价或采用位置。

## 8｜三种生成模式在本格的约束

### 单符号 z 世界观

允许多个不同 z 子语义，但每个核心制度必须回答：

```text
谁确认？
确认什么？
该位置为什么重要？
确认改变哪一个被承认状态？
```

若回答不了，禁止仅靠舞台、排名、中心建筑补视觉。

### 多符号

z 只能承担明确的“确认/裁认模块”；例如：

```text
xn：组织长期考试流程
z：最终确认具体资格
```

不能写成“70% xn + 30% z”。

### 无向量尺标

只记录：

```text
候选对象 → 确认主体 → 确认内容 → 采用范围 → 状态变化
```

不生成“z强度 8.7”一类伪精确值。
