# n × 世界观｜应用映射 v0.1

> 本文件只把 current `n` 的理论变量翻译成世界观生成语法。家、医院、旅馆、避难所、母亲、温暖、善良、容器、房屋都只是载体，不能反向定义 `n`。

## 0｜canonical 锚点

土轴广义变量：对象跨越内外边界的方向；`n` 是外→内纳入承载，`x并z` 是内→外映射外化。

current `n`：对象真实进入主体或结构内部，被允许留下，并由该主体或结构跨阶段接收、处理、保护和承担持续负荷。稳定 n 必须同时排除一次帮助、被迫忍受、拘禁、单纯房屋意象与职业标签。

本轮只抽取：真实准入、可持续内部位置、持续负荷处理、外压下抗崩、非强制扣留、重复返回后仍能被接住。任何候选若只有“看起来像容器/家庭/医院”，一律不能进入 n。

## 1｜N-W-001 可持续准入的内部席位

```yaml
id: N-W-001
symbol: n
module: 世界观
sub_semantic: 真实准入与持续内部位置
changed_variable: 外部对象进入后是否获得可跨阶段保留的内部席位而非一次停留
relation_shape: 外部对象提出进入 -> 结构真实接纳 -> 内部席位成立 -> 后续阶段仍可停留并被处理
module_grammar: 设计一种进入后会产生真实成员位置、且该位置要求结构继续承担后续负荷的内部准入机制
concrete_candidate: [会为新成员腾出长期席位的漂流城, 接纳后自动分配生活与照护资源的旅团核心区, 允许患者长期进入康复周期的浮空诊所]
genre_context: [中古奇幻, 太空殖民, 都市幻想, 灾后共同体]
genre_translation:
  中古奇幻: [接纳后成为城内正式负荷单位的旅人席位]
  太空殖民: [接纳后占用真实舱位与生命维持配额的成员位]
positive_reason: 核心不是“有入口”，而是进入后得到真实内部位置并让结构承担持续成本
nearest_neighbor: x并z / nz
why_not_neighbor: x并z 只负责外部如何识别和进入接口；nz 负责离开后的可信回返。本候选冻结的是进入之后内部位置是否真实成立并持续被承载
removal_test: 去掉城门、病床、家庭称谓与暖色，只要对象进入后仍拥有持续席位且其负荷继续被内部处理，n 仍成立
reverse_test: 若只允许短暂停留、进入后立刻转交，或必须持续服从才能不被驱逐，则 n 明显下降
counterexample: 任何人都能买票进站，但车站不承担其长期位置与负荷
source_evidence: n 信息卡 v2.0；n 准度卡 v0.1；Black Jack SBR-BLACKJACK-HAZAMA-001/002
confidence: 98
status: candidate
```

## 2｜N-W-002 负荷随成员进入而被结构接管

```yaml
id: N-W-002
symbol: n
module: 世界观
sub_semantic: 现实负荷接管与持续处理
changed_variable: 成员进入后其时间空间照护风险或资源负荷是否由内部结构真实接手并跨阶段处理
relation_shape: 对象进入 -> 负荷显现 -> 内部持续分配资源和处理 -> 负荷变化时继续响应而非立即外包
module_grammar: 让成员资格自动绑定可验证的持续负荷责任，世界必须显示谁在反复支付时间资源和风险成本
concrete_candidate: [会跟随成员伤病变化重新分配资源的地下城邦, 把每个新居民的氧气食物医疗计入共同账的星舰, 对入院者负责到康复阶段的魔法疗养院]
genre_context: [废土, 科幻舰队, 医疗幻想, 城邦]
genre_translation:
  废土: [新成员的水药品守夜与风险共同进入据点负荷表]
  科幻舰队: [成员生命维持与维修资源进入舰内长期预算]
positive_reason: current n 的硬门不只是允许留下，而是持续处理真实负荷；这条把负荷承担直接写成世界机制
nearest_neighbor: xn / zn
why_not_neighbor: xn 会把处理经验组织为流程；zn 决定什么原则不可抛下。本候选只要求内部真实承担具体对象负荷，不要求流程创新或价值排序
removal_test: 去掉制度名词，只检查对象的现实负荷是否仍由内部结构跨阶段承担；若是，结构保留
reverse_test: 若结构只登记成员身份，却把照护风险与资源全部推回个人或外部，则 n 下降
counterexample: 一个拥有完整会员名册但从不为成员承担任何生活风险或资源成本的协会
source_evidence: n 信息卡 v2.0 持续负荷；Black Jack SBR-BLACKJACK-HAZAMA-003/005
confidence: 98
status: candidate
```

## 3｜N-W-003 外压下仍保持接收与抗崩

```yaml
id: N-W-003
symbol: n
module: 世界观
sub_semantic: 外部压力下的承载连续性
changed_variable: 资源紧张攻击灾害或政治压力出现后结构是否仍保留已纳入对象的内部位置与最低处理能力
relation_shape: 对象已进入 -> 外部压力上升 -> 内部资源受压 -> 结构仍继续保护和处理 -> 承载能力下降但不立即把对象推出
module_grammar: 设计会在压力测试中暴露承载极限、但默认先压缩自身余量而不是先驱逐内部对象的世界结构
concrete_candidate: [封锁期间仍维持内部居民配给的城塞, 能源不足时优先保留住民生命维持的飞船, 灾潮中仍继续接收既有病患的移动医院]
genre_context: [围城奇幻, 灾难科幻, 战争, 末世]
genre_translation:
  围城奇幻: [城墙被围后仍为既有居民维持食物与庇护席位]
  灾难科幻: [系统降载时先减少非必要功能而非弹射住民]
positive_reason: n 信息卡与准度卡均要求外部压力下仍有一定接收与抗崩能力，这里直接把压力作为验证器
nearest_neighbor: x / zx
why_not_neighbor: x 可能通过占有与排除维持内部；zx 可能通过强势否决外压。本候选不要求控制或夺权，只检验已接入对象是否继续被承载且不是被强制扣留
removal_test: 去掉城墙、战争与英雄叙事，只保留资源收缩时是否仍处理已进入对象的负荷；若仍成立则 n 核心保留
reverse_test: 若危机一来就把弱者推出、取消内部位置，或把所有成员强制封锁为资源，则 n 不成立或需转查 x/zx
counterexample: 以“保护”为名禁止任何人退出的封闭堡垒
source_evidence: n 信息卡 v2.0 抗崩门；n 准度卡外压条件
confidence: 96
status: candidate
```

## 4｜N-W-004 重复返回后的再次承载

```yaml
id: N-W-004
symbol: n
module: 世界观
sub_semantic: 重复进入后的持续接住
changed_variable: 同一对象多次带着新负荷返回时内部位置是否仍能再次接收并处理
relation_shape: 首次进入并被承载 -> 对象离开或负荷暂退 -> 再次带负荷进入 -> 原内部处理位置重新承担 -> 多轮仍可持续
module_grammar: 让世界中的承载结构接受同一对象的重复负荷，而不是只提供一次性救援券
concrete_candidate: [伤员可反复返回治疗的边境诊所, 航海者每次受损都能重新入坞修复的母港, 学徒失败后仍可回到内部继续训练的工坊]
genre_context: [冒险, 海洋奇幻, 医疗, 学院]
genre_translation:
  海洋奇幻: [同一船员多次带伤归港后仍获得维修医疗与休整位置]
  学院: [成员失败退出实习后仍可重新进入训练与照护周期]
positive_reason: 反复返回本身可能是 nz 条件，但本候选冻结的是回来之后内部结构是否再次承担真实负荷
nearest_neighbor: nz / xn
why_not_neighbor: nz 保存的是对象特异回返路径；xn 组织重复流程。本候选的核心变量是每次进入后仍被真实接住，而非是否能回来或流程是否标准化
removal_test: 去掉港口和归队意象，只看同一对象重复进入后内部是否继续付出资源处理负荷；若是则 n 保留
reverse_test: 若只保留回返资格但回来后无人处理负荷，则转向 nz；若只是自动化流程无对象承载，则转查 xn
counterexample: 会员拥有无限次入场权，但每次进入后的风险和损失全部自理
source_evidence: Black Jack SBR-BLACKJACK-HAZAMA-004；n 信息卡“反复返回、结构抗崩能力”
```

## 5｜N-W-005 内部差异对象被分别处理而非同质化

```yaml
sub_semantic: 内部异质负荷的持续协调
changed_variable: 多种不同对象进入同一内部后是否都获得真实位置并由结构分别处理其不同负荷
relation_shape: 多类对象进入 -> 各自负荷不同 -> 内部不要求先变成同一种对象 -> 分别协调资源和保护 -> 多对象共同持续存在
module_grammar: 设计一种能让异质成员同时留下、并对差异负荷做持续内部协调而不是靠驱逐或同质化减负的世界结构

positive_reason: n 的内部位置与负荷处理允许对象差异真实存在；若必须先被同化才可留下，承载会滑向控制或身份壳
nearest_neighbor: x / x并z
why_not_neighbor: x 强调归我掌握和排除；x并z 强调外部公共识别。这里不要求统一身份和归属，只要求进入内部后差异负荷仍被真实处理
removal_test: 去掉种族职业与视觉差异，只要多个不同负荷对象仍能同时获得位置并被持续协调，n 结构仍在
```

# 6｜明确拒绝的误映射

### REJECT-N-W-001｜“温暖的家就是 n”
- status: rejected
- 原因：家庭、暖色、房屋与照顾台词都是非充分条件。必须看谁进入、是否有真实持续位置、谁承担跨阶段负荷。

### REJECT-N-W-002｜“关得越牢越能承载，所以封闭监狱是高 n”
- status: rejected
- 原因：无法退出、强制扣留直接违反 current n 必要条件；优先检查 `x/xn/zx` 控制结构。

### REJECT-N-W-003｜“有开放入口和漂亮前台就是 n”
- status: rejected
- 原因：外界知道怎样进入、怎样识别和调用，是同轴 `x并z` 的公共壳变量；进入后若没有内部位置与持续负荷处理，不能判 n。

# 7｜最近邻与同轴对端排除

- `n ↔ x并z` 同属土轴：`n` 是外→内真实纳入承载；`x并z` 是内→外形成稳定公共壳。入口可读不等于内部能接住，内部能接住也不自动拥有漂亮前台。
- `n vs nz`：`nz` 保存自由离开后的可信回返；`n` 检查回来或进入之后是否真的被接住并承担负荷。
- `n vs xn`：`xn` 把处理经验组织成持续流程；`n` 只要求具体对象负荷被持续处理，不要求流程创新。
- `n vs x`：`x` 可以通过掌握、处分和排除把对象留在内部；`n` 必须不是强制扣留。
- `n vs nx`：`nx` 沿既有通道和外部方向推进；`n` 是内部承载端。
- `n vs zn`：`zn` 回答何种原则具有未来调用与排序资格；`n` 回答谁真正被留下并承担其负荷。

# 8｜structure_id 检查

五个候选的 `changed_variable + relation_shape + module_grammar` 均不同，形成 5 个新的结构身份；`concrete_candidate / genre_context / genre_translation` 不参与 structure_id。三条 rejected 只保留在源 Markdown，不进入机器运行池。

# 9｜本轮结论

`n × 世界观` 可进入应用层 candidate 机器投影。正确生成重点不是“温暖空间”，而是：谁从外部真正进入、是否获得持续内部位置、哪种现实负荷被谁跨阶段承担，以及压力和重复负荷出现后结构是否仍能接住。
