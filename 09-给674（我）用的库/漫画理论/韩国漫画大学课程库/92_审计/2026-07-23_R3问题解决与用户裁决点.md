# R3问题解决与用户裁决点

> 本文件保留R3阶段的问题记录。用户已经完成裁决，当前执行口径见[[../01_课程总纲/ABC三模式与C动态运行协议]]。

## 1. 原问题

R3曾把“关系生成层”暂定为课程知识进入十元的外部接口，并提出两种身份：

- A：先让现实知识、关系和剧情跑完，再用十元分析调整；
- B：在对象与关系设计阶段，让十元参与候选判断。

后续讨论发现，两者不是互斥关系，还存在更符合动态链的C模式。

## 2. 用户裁决后的正式结论

### A｜分析模式

```text
已有作品／已有场景
→ 专业课程拆解
→ 十元后置分析与调整
```

适用于课程学习、韩漫拆解和作品复盘。

### B｜设计模式

```text
对象与状态
→ 关系条件
→ 对象当前意义
→ 十元候选端点
→ 行为、回应和代价验证
```

适用于人物、场景和剧情起案。对象不能直接匹配十元。

### C｜动态运行模式（默认）

```text
对象状态
→ 关系位置
→ 当前十元端点／已锁定关系
→ 行为与回应
→ 代价与变量变化
→ 新对象状态和新关系
→ 下一轮
```

适用于场景、单话、序列、长篇和连载。C最接近十元动态链的实际工作方式。

## 3. 关系生成层的最终身份

关系生成层既不是第十一元，也不只属于外部工具。

正式口径：

> 它是专业课程与十元之间的运行接口。在A模式中它是分析接口，在B模式中它是设计接口，在C模式中它成为持续运行机制。

因此无需强行选择“完全在十元外”或“完全在十元内”。其身份由工作模式决定。

## 4. 重要纠错

R3课程Canvas曾使用简化词表描述十元，存在把zx写成一般外部行动、把z写成一般截断等风险。R4不再允许课程库自行定义十元。

所有关系调用：

- [[../../../../../01-十元系统/十元生补克表]] v2.21；
- [[../../../../../07-Codex大脑库/每次任务必读_十元关系防遗忘清单]] v3.5。

防遗忘：`zx 克 n`，`zx 被 xn 克`。
