## 2. ABC模式怎样使用课程作业

### A｜分析

把已完成作品拆成：

```text
课程知识证据
＋对象与状态
＋人物行为与回应
＋表现方法
＋生产限制
→ 十元正本复核
```

A模式的十元记录用于发现问题，不冒充作品原本的创作依据。

### B｜设计

从课程对象库与操作库选择条件：

```text
对象状态
＋关系位置
＋表现限制
→ 十元候选端点
→ 设计行为、回应和代价验证
```

课程里的动词不能直接等于十元。

### C｜动态运行

每项叙事、导演或综合作业至少跑一轮：

```text
对象状态
→ 关系位置
→ 当前十元端点／关系
→ 行为与回应
→ 代价与变量变化
→ 下一轮
```

纯技术作业如人体、色彩、字体和软件练习不强制制造十元剧情，但若用于具体场景，必须说明它显影了哪些既有关系变量，而不是用画面风格反推十元。

## 3. 各课程族在C模式中提供什么证据

| 课程族 | C模式证据 |
|---|---|
| 调查／世界观 | 对象是否真实存在，制度与权限怎样运行 |
| 心理／表演 | 欲望、恐惧、策略与回应是否可观察 |
| 故事／类型 | 行为是否形成选择、代价和下一场必要性 |
| 分镜／Webtoon | 关系变化是否被镜头、画格、滚动与停顿看见 |
| 人体／背景 | 身体重心、距离、出入口和空间权限是否可信 |
| 色彩／字体／声音 | 信息层级、节奏和关系压力是否被准确显影 |
| 平台／营销 | 读者承诺、首话信息和反馈怎样改变修改策略 |
| AI／版权／产业 | 素材来源、权利、交付和生产条件怎样限制对象状态 |
| 毕业项目 | ABC三模式能否在完整作品中闭环 |

## 4. 十元关系证据字段

课程作业只有在涉及具体对象与关系时，才填写：

```yaml
十元源端点:
十元目标端点:
候选生克补:
正本状态: 已锁定 / 待确认
启动机制:
被改变变量:
成立阶段:
体量:
顺序:
第三因素:
拿掉测试:
反向测试:
```

关系判断调用[[../../../../../01-十元系统/十元生补克表]]，不得使用旧课程词表自行重画。

## 5. 课程缺口诊断

一所学校若只有：

- 绘画，没有故事与分镜：容易成为插画训练；
- 故事，没有生产：企划无法交付；
- 软件，没有表演与导演：技术作品缺少叙事；
- 项目，没有史论与批评：容易复制当前平台模板；
- 市场，没有版权与健康：商业能力残缺；
- AI，没有基础和伦理：更快地产生不稳定结果；
- 十元标签，没有课程证据：理论看起来很忙，作品仍然不知道该怎么改。
