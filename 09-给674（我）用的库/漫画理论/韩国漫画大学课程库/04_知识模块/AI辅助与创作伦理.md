# AI辅助与创作伦理｜R6

## 1. 本章总判断

AI不是一个“会画画的对象”，而是一套涉及模型、输入素材、工具权限、作者决定、团队劳动、平台规则、输出资产和责任归属的关系系统。

```text
作者提出目标与边界
→ 将部分对象和操作交给AI工具
→ 模型生成候选输出
→ 人工核验事实、权利、连续性和相似性
→ 作者重构、取舍、署名并承担责任
→ 输出进入客户、学校、平台和读者关系
```

“用了AI”不自动等于任何十元；“作者性还在”也不能只靠嘴。必须检查谁掌握输入、方向、修改、署名、发布和撤回权，谁承担风险与代价。

## 2. AI系统的十元对象图

### 作者

- `zn`：创作理由、价值和最终意义；
- `x`：项目边界、素材、修改、发布和拒绝权；
- `zx`：公开决定使用、舍弃或发布；
- `nx`：借模型和既有工具通道做成；
- `xn`：建立可复核工作流；
- `xz`：合同、隐私、版权、交付和职业风险。

### 模型与工具

模型是操作对象和流程接口：

- 模型版本、参数和功能属于`x并z/xn`候选；
- 输出不拥有作者主体资格；
- 工具提供能力不等于决定作品方向；
- 黑箱、服务停用和规则变化会改变可用路径。

### 输入素材

脚本、照片、草图、客户资产、教材和个人数据都要记录所有权、许可、保密、可撤回性和传播范围。

### 输出资产

输出必须判断：可修改性、连续性、相似性、来源记录、使用许可、署名、交付和后续复用。

### 客户、学校、平台和比赛

它们可能通过规则、准入、申报、评价和处罚形成`xn/x并z/z/x/zx`关系。具体规定必须按使用当天官方文本核验。

## 3. 四个可用环节完全十元化

### 3.1 资料与企划

AI可帮助关键词扩展、研究问题、资料分类和方案比较。

十元任务：

- 保留事实来源`x`和确认节点`z`；
- 将模型回答视为候选信息对象，不视为史实；
- 作者保留研究方向`zn/x`；
- 用`xn`流程完成查证、标注和争议记录；
- 若无法追溯来源，输出不得进入事实层。

### 3.2 故事

AI可提供压力测试、反方意见、场景变体和连续性检查。

十元任务：

- 人物主十元与对象意义必须由作者判断；
- AI生成的行为必须有欲望、触发、回应和代价；
- 类型拼接不等于动态链；
- 作者要明确哪些建议被接受、拒绝和重构；
- 最终方向不能在无记录的情况下外包为`nx`。

### 3.3 视觉前期

AI可用于构图发散、色彩、道具、场景和临时预演。

十元任务：

- 候选图只提供可视对象和界面；
- 不能凭画面气氛判十元；
- 检查现有IP、签名、商标和风格挪用；
- 作者重新决定对象、关系、镜头和体量；
- 记录参考与最终稿之间的实际修改。

### 3.4 制作

AI可辅助背景、颜色、分层、重复资产、修补和放大。

十元任务：

- 工作流`xn`必须可重复、可回滚和可审计；
- 作者或团队保留`x`修改权；
- 输出进入统一`x并z`风格界面；
- 不能把错误、漂移和返工代价转移给隐形劳动者；
- 最终资产必须能持续生产，而不是只在一张图里侥幸长得像成品。

## 4. 七类风险的十元结构

| 风险 | 十元知识判断 |
|---|---|
| 事实 | 信息对象由谁掌握、谁能确认`z`、错误由谁承担 |
| 版权 | 素材与输出`x`权利、署名归因`z`、公开界面`x并z` |
| 合同 | 规则`xn`、申报节点`z`、违约处置`zx`和退出权`x` |
| 隐私 | 谁掌握数据、谁可进入、传播范围和删除权 |
| 风格 | 作品身份壳是否稳定，角色与空间能否持续识别 |
| 劳动 | 谁决定方向、谁沿流程执行、谁署名、谁获得报酬和承担返工 |
| 教育 | 学生是否保留独立能力`x/zn`，还是把训练方向外包`nx` |

## 5. 作者性不是口号

作者性至少需要：

```yaml
创作问题由谁提出:
核心对象与关系由谁决定:
哪些输出被拒绝:
哪些输出被重构:
最终分镜与造型由谁确认:
谁拥有修改和撤回权:
谁署名:
谁承担事实、版权和伦理责任:
```

仅输入一句提示并接受首张结果，通常只证明人物成功点击了按钮。按钮对此也没有特别骄傲。

## 7. 不应上传的内容

保密脚本、未公开客户素材、未经同意的私人照片和采访、可识别个人数据、付费教材全文、无授权角色商标和资产，均涉及对象`x`掌握、成员资格、传播界面和潜在`xz`风险。

“模型可能不会保存”不是权限证明，也不是保密协议的新章节。

## 8. 学校作业中的AI

作业规则必须明确：

- 哪些环节允许AI；
- 哪些能力必须独立完成；
- 是否提交提示、原始输出、草稿和修改；
- 是否允许风格模拟；
- 如何处理版权、隐私和署名；
- 评价成品、过程还是独立能力；
- 违规由谁确认、如何申诉。

### 十元判断

- 学校规则属于`xn/x并z`候选结构；
- 作业认可属于`z`节点；
- 学生保留的独立决定属于`x/zn`；
- 使用工具属于`nx`借通道候选；
- 临时改变规则可能形成`xz`风险和不当`zx`处置。

## 9. 漫画项目最低流程

```text
人工确定前提、角色和核心关系
→ 划定允许AI的对象与操作
→ 保存版本、输入与原始输出
→ 核验事实、权利和相似性
→ 人工重构分镜、造型、空间和文字
→ 统一角色、光线与作品身份壳
→ 检查动态链、关系变量和五维结果
→ 记录资产、署名与责任
→ 按规则申报和发布
```

## 10. 生成图像的十元审查

- 现有IP、签名、水印和商标：对象权利与错误归因；
- 人体、服装、道具、空间连续：对象状态和`x`边界；
- 年龄、身份和情绪漂移：`x并z`身份壳失稳；
- 颗粒、光晕和复杂细节：是否只是气氛冒充机制；
- 分层、修改和重复生产：`xn`工作流是否成立；
- 角色关系：姿势和画面是否与实际行为、回应一致；
- 视觉像某十元但没有现实机制：标为误判。

## 11. 生成故事的十元审查

- 前提是否只有类型拼接，没有端点缺失；
- 人物行为是否来自具体对象和主十元策略；
- 对方是否独立回应；
- 冲突是否只靠误会续命；
- 设定和对象状态是否连续；
- 台词是否同质，言语行为是否为空；
- 代价是否进入下一轮；
- 是否有无来源事实；
- 作者保留了哪些独立判断与拒绝。

## 12. 团队、劳动与署名

AI进入团队时必须记录：

- 谁的岗位和任务被改变；
- 谁训练、清理和修正输出；
- 谁承担返工、健康和交付风险；
- 谁拥有工具账户、模型和资产；
- 谁获得署名和报酬；
- 团队是否仍有拒绝和退出权；
- 效率收益是否只被掌握者`x`获取，代价却转移给`nx/n`承担者。

## 13. 关键关系检查

- `xn克zx`：既有合同、审核和制作流程会限制即时决定；
- `x克z`：掌握发布、署名或传播接口可阻断正确认可；
- `zx克n`：若公开处置直接改变成员资格和团队承载，才可能成立；
- `n生xn`：稳定团队承载可生成持续流程，但需正本证据；
- 工具帮助作者做成，通常先检查`nx`借力，不自动写`zx补nx`；
- 未锁定关系只写候选。

## 14. 五维归纳

- 时间：模型版本、工作流、迭代、审核和交付；
- 本体：作者性、作品边界、身份与责任；
- 空间：平台、工具环境、数据权限和公开界面；
- 因果：输入、生成、人工选择、署名和后果承担；
- 命运：规则变化、服务停用、泄露、争议和职业路径。

## 15. 训练

1. 同场景人工版与AI辅助版，比较作者决定与工具操作；
2. 对生成故事做事实、对象、行为、关系、十元和伦理六层审计；
3. 建立可追踪AI资产表；
4. 将生成背景重绘到统一透视、对象状态和关系空间；
5. 分析一项官方AI规则，拆主体、权限、节点和处置；
6. 为团队写AI使用、署名、报酬和退出协议；
7. 完成公开说明，区分工具参与与作者责任；
8. 对“用了AI＝没有作者性”做反向测试；
9. 对“人工修改＝版权风险消失”做拿掉测试；
10. 设计一个保留作者`zn/x`、利用工具`nx/xn`、同时控制`xz`风险的完整流程。

## 16. 更新规则

AI工具、平台政策、学校要求和法律变化快。本章只保存十元化审计框架；具体规则必须按使用当天的官方文本核验，并记录日期、版本和适用地区。
