# 对象库深层结构

> 对象库不是名词清单。一个对象只有在它能限制、诱发或改变人物行为时，才真正进入故事。

## 1. 对象的最低结构

```text
对象类别
＋当前状态
＋可操作性
＋所有权／控制权
＋稀缺度
＋可见性
＋关系绑定
＋变化成本
＋视觉表现
```

只有“医生、学校、戒指、魔法书”这些名称，不足以支持剧情。必须继续问：谁能使用、谁不能使用、谁控制、谁误解、谁依赖、它一旦变化会伤到谁。

## 2. 八类对象

### 2.1 人物对象

记录人物的身份、身体、能力、资源、秘密、关系位置和当前状态。

人物对象不是静态角色卡，还要保存：

- 当前正在争取什么；
- 当前被谁限制；
- 当前掌握什么信息；
- 当前欠谁什么；
- 当前可以采取哪些行动；
- 哪种行动对他来说代价最低或最高。

### 2.2 身份与角色对象

例如学生、继承人、军官、偶像、犯人、家长、导师、编辑。

身份必须包含：

- 进入条件；
- 权利；
- 义务；
- 禁止行为；
- 失去身份的条件；
- 他人对该身份的期待；
- 身份与本人真实欲望的冲突。

同一个人可以同时拥有多个互相冲突的身份。剧情常从“两个身份不能同时履行”开始。

### 2.3 制度对象

例如学校、公司、军队、平台、家庭、宗教、法律、帮派。

制度对象要记录：

- 谁制定规则；
- 谁执行规则；
- 谁能例外；
- 谁从规则中获益；
- 谁承担隐性成本；
- 违反规则后的正式惩罚与非正式惩罚；
- 制度怎样进入人物日常动作。

### 2.4 空间对象

空间不是背景图，而是行为权限的分配器。

记录：

- 谁能进入；
- 谁能看见谁；
- 谁占据中心或高位；
- 出入口、遮挡、距离、光线和声音；
- 哪些动作在此处合法、危险或羞耻；
- 空间变化会把权力转移给谁。

### 2.5 资源对象

资源包括钱、食物、时间、住房、医疗、工作机会、声誉、注意力、情报、情感劳动。

资源卡必须标记：

- 数量；
- 分配者；
- 获取条件；
- 替代品；
- 消耗速度；
- 被夺走或共享后的关系影响；
- 是否可以转换成其他资源。

### 2.6 工具与道具对象

道具的作用不止是象征。它还可能：

- 扩大能力；
- 限制行动；
- 证明身份；
- 保存秘密；
- 建立债务；
- 触发记忆；
- 转移权力；
- 成为追逐或交换目标。

一个重要道具最好经历至少两次功能变化，例如“工具→证据→关系纪念”。

### 2.7 信息对象

秘密、证据、误解、传闻、身份真相、规则说明都属于信息对象。

记录：

- 内容是什么；
- 谁知道；
- 谁以为自己知道；
- 谁能证明；
- 公开成本；
- 隐瞒成本；
- 传播路径；
- 被不同人物解释后会产生什么行为。

### 2.8 象征与身体对象

身体、服装、伤疤、称呼、徽章、照片、遗物既是物质对象，也可能承担身份和关系定义。

必须区分：

- 角色如何理解它；
- 他人如何理解它；
- 社会如何定义它；
- 它在不同场景中是否改变意义。

## 3. 对象的六种状态

对象至少要有状态变化，常见状态包括：

1. 不可见：尚未出现或被隐藏；
2. 可见但不可得：知道存在，却无法接触；
3. 可得但不可用：已经拥有，却缺条件或权限；
4. 可用但有代价：使用会损伤资源、身份或关系；
5. 被争夺或共享：所有权和控制权发生冲突；
6. 失效、损坏或转义：原功能消失，产生新功能。

## 4. 对象的可操作性

可操作性回答“人物能对它做什么”。

| 对象 | 常见操作 |
|---|---|
| 人物 | 接近、说服、欺骗、保护、攻击、定义、抛弃 |
| 身份 | 获得、伪装、维持、质疑、剥夺、继承、退出 |
| 制度 | 遵守、利用、绕过、改革、摧毁、借权力压人 |
| 空间 | 进入、封锁、占据、逃离、隐藏、监视、重划边界 |
| 资源 | 获取、积累、交换、垄断、共享、浪费、牺牲 |
| 道具 | 使用、藏匿、赠送、夺取、修复、销毁、误认 |
| 信息 | 发现、验证、隐瞒、泄露、伪造、重解释、公开 |

## 5. 对象关系词

对象之间不能只用“相关”连接。优先使用具体关系：

- owns：拥有；
- controls：控制；
- grants_access：授予权限；
- blocks：阻止；
- depends_on：依赖；
- represents：代表；
- hides：隐藏；
- proves：证明；
- threatens：威胁；
- transforms_into：转化；
- costs：消耗；
- binds：绑定关系；
- replaces：替代；
- inherits：继承。

## 7. 从对象生成剧情

```text
对象出现
→ 人物判断其价值
→ 人物尝试获取、使用、隐藏或摧毁
→ 其他人物回应
→ 所有权／信息权／使用权改变
→ 关系和局势变化
```

### 示例：一封信

- 名词层：信；
- 状态层：未拆封、被误寄、只允许某人阅读；
- 权力层：送信人掌握真相，收信人掌握公开权；
- 行为层：藏匿、偷看、伪造、转交、烧毁；
- 代价层：公开会伤害第三人，隐瞒会破坏信任；
- 剧情层：信不是伏笔装饰，而是迫使人物选择的对象。

## 8. 对象库的深度检查

一个对象进入库前，至少回答：

1. 谁需要它；
2. 谁控制它；
3. 谁不能得到它；
4. 它允许哪些行动；
5. 它禁止哪些行动；
6. 它的状态怎样变化；
7. 变化会损伤哪段关系；
8. 它如何被视觉化；
9. 它是否在至少两个场景承担不同功能；
10. 它是否真的影响故事，而不是作者觉得设定很酷。

## 9. 训练

- 为一个职业建立30个对象，不许只写名词，必须补状态和操作；
- 为同一道具设计工具、证据、债务、纪念四种功能；
- 把一个空间分别写成安全地、权力场、秘密场和逃生场；
- 为一条制度规则写受益者、受害者、漏洞和地下替代方案；
- 从对象状态变化出发写5个场景，不先写人物心理。
