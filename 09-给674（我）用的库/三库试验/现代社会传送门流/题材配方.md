# 现代社会传送门流｜题材配方

## 0. 硬边界

- 本页只定义题材由哪些模块组合，不保存人物主十元。
- 题材名不等于十元：现代社会不等于 `x`，传送门不等于 `xz`，管理机构不等于 `xn`。
- “传送门开启”“人物被传送”“城市停运”是事件或状态；只有明确主体做出的动作，才能进入十元人物行动判断。
- 名词对象来自[[名词对象库]]；通用行为槽来自第2库。本试运行只引用槽位 ID，不在本页重建行动库。
- 最终可画内容由“名词对象 ID + 行为槽 ID + 前后变量”合流，见[[可画内容实例]]。

## 1. 组合公式

```text
现代社会传送门流
= A 现代城市世界底座
+ B 传送门异常机制
+ C 生存、失联、权限与资源压力
+ D 城市公共系统 / 传送门管理机构
+ 可选 Bridge 专有覆盖层
```

### A｜现代城市世界底座

- 普通居民、学生、职员、游客、记者、店主、骑手。
- 地铁、医院、学校体育馆、住宅楼、商业街、地下管线。
- 手机、广播、门禁卡、监控、交通图、医疗用品与日常衣物。

### B｜传送门异常机制

- 稳定门、微型不稳定门、空间扭曲、重力异常、电子干扰、污染孢子。
- 传送门可出现、扩张、收缩、失稳、关闭失败或改变坐标。
- “被传送”只描述主体遭遇；后续逃离、求援、组织、控制或调查才是主体动作。

### C｜故事压力

- 人员失联与家庭分离。
- 门区污染、受伤、检疫与医疗容量不足。
- 通行许可、封锁线、权限被撤销。
- 交通中断、供电不足、淡水和药品短缺。
- 谣言、监控证据、稳定性报告与官方警报之间的信息冲突。
- 门关闭倒计时与救援窗口。

## 2. D｜城市公共系统 / 传送门管理机构（本轮先行补全）

### 2.1 指挥与监管

- `OBJ-ORG-001` 城市联合应急指挥部：跨警务、消防、医疗、交通与门区管理的协调机构。
- `OBJ-ORG-002` 传送门管理局：登记门、核发通行许可、维护门区档案。
- `OBJ-ORG-003` 传送门检疫站：处理人员、物件与生物的跨门检疫。
- `OBJ-ORG-007` 市政警报中心：核验并发布城市级警报。

### 2.2 城市公共运行

- `OBJ-ORG-004` 城市交通控制中心：地铁停运、换乘封闭与疏散线路。
- `OBJ-ORG-005` 医院急救网络：分流伤员、共享床位与检疫信息。
- `OBJ-ORG-006` 临时避难所网络：住宿、登记、物资配给与寻人。
- `OBJ-ORG-008` 基础设施抢修队：供电、通信、地下管线与临时照明。

### 2.3 D 模块关键岗位

- `OBJ-ROLE-001` 地铁调度员
- `OBJ-ROLE-002` 急救员
- `OBJ-ROLE-003` 消防救援员
- `OBJ-ROLE-004` 警戒线警员
- `OBJ-ROLE-005` 传送门检疫员
- `OBJ-ROLE-006` 门区现场勘测员
- `OBJ-ROLE-007` 避难所登记员
- `OBJ-ROLE-008` 市政抢修工程师
- `OBJ-ROLE-009` 现场应急总指挥

### 2.4 D 模块必需的管理对象

- 许可与身份：`OBJ-DOC-002`、`OBJ-DOC-003`、`OBJ-PROP-009`。
- 监测与记录：`OBJ-PROP-006`、`OBJ-DOC-005`、`OBJ-DOC-008`。
- 疏散与寻人：`OBJ-DOC-001`、`OBJ-DOC-004`、`OBJ-DOC-007`。
- 医疗与检疫：`OBJ-PROP-003`、`OBJ-PROP-008`、`OBJ-DOC-009`。
- 封锁与恢复：`OBJ-PROP-005`、`OBJ-PROP-007`、`OBJ-EVT-005`、`OBJ-STA-002`。

## 3. Bridge 专有覆盖层

Bridge 在本轮按“跨机构传送门联络计划”的暂定专名处理。它不是现代社会或传送门题材的通用常识，所有 `BRG-*` 节点均为试运行候选，等待用户确认名称与设定。

- 通用机构、医院、地铁、避难所不复制到 Bridge。
- Bridge 只保存专有增量：联络组、端点锚、中继箱、跨界通行证、安全屋与专有失联记录。
- 删除 Bridge 模块后，A—D 仍应形成完整的现代社会传送门题材。

## 4. 第2库行为槽接口

下列 ID 是本轮实例引用接口，不是题材默认十元：

| 行为槽 ID | 通用动作 | 判断提示 |
|---|---|---|
| `ACT-NONE-000` | 主体遭遇事件，尚无主动行为 | 不判人物十元 |
| `ACT-GEN-001` | 沿外部给定路线或命令行动 | 检查 `nx` 行为；方向权必须在外部 |
| `ACT-GEN-002` | 主动清点并重排人员、时间与资源 | 检查 `xn` 行为；须形成持续结构 |
| `ACT-GEN-003` | 核验多份证据并建立调查链 | 检查 `xn` 行为；普通“看见”不算 |
| `ACT-GEN-004` | 向拥有权限者申请许可或支援 | 检查 `nx` 关系功能；一次礼貌请求不自动锁位 |
| `ACT-GEN-005` | 控制对象、资源或访问权限 | 检查 `x` 行为/权限功能；须有实际掌握边界 |
| `ACT-GEN-006` | 公开接管并扩大现场决定权 | 检查 `zx` 状态；须核公开、扩大、凌驾结果 |
| `ACT-GEN-007` | 依据名单与线索主动组织搜索 | 检查 `xn`；若只按别人路线搜则检查 `nx` |
| `ACT-GEN-008` | 隔离污染源并维持检疫流程 | 先判具体动作；职业身份不等于十元 |
| `ACT-GEN-009` | 核验信息后发布公共警报 | 可含 `xn` 组织功能；公开发布不自动等于 `zx/z` |
| `ACT-GEN-010` | 将对象转交下一岗位或机构 | 若方向、对象、去向均外定，检查 `nx` |

## 5. 题材查询要求

本配方调用[[名词对象库]]时，至少要返回：

- 2 类普通人物与 2 类公共岗位。
- 2 个机构与 3 个功能地点。
- 3 个道具/资源与 2 份文件/信息。
- 1 个传送门现象、1 个非人威胁、1 个城市系统事件。
- 1 项访问权限压力、1 项医疗/检疫压力、1 项人员失联压力。

## 6. 禁止推断

```text
禁止：传送门题材 → xz 人物
禁止：公共机构 → xn 人物
禁止：身穿制服 → 某十元
禁止：被门吸入 → 人物主动行动
禁止：全员获救 → 把团队结果借给单个人
禁止：同一场景出现两个点位 → 自动命名生克补
```

## 7. 试运行通过条件

- D 模块能独立回答谁指挥、谁检疫、谁疏散、谁治疗、谁修复、凭什么许可、在哪里登记。
- Bridge 节点全部可被关闭而不破坏通用世界。
- 任一可画实例都能追溯到对象 ID、行为槽 ID 和变量变化。
- 遮住题材名后，仍能看出主体做了什么；不能只剩“城市里有一扇门”。
