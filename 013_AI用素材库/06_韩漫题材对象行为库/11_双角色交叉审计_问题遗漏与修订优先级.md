# 11｜双角色交叉审计：问题、遗漏与修订优先级

> 说明：本审计由同一助手采用两个立场相反的审计角色交叉检查，不冒充两个彼此独立的外部模型。
>
> - **审计员A｜结构派**：关注题材、对象、行为、链条能不能真正生成故事。
> - **审计员B｜反例派**：关注覆盖遗漏、编码、排版、Obsidian兼容、来源与理论边界。

# 一、总体结论

**A：** 这套库已经可以作为 v1.0 骨架使用。它最正确的地方，是把“题材”从平台标签拆成了主体、对象、行为、反制、回报，而不是继续收集“财阀、恶役、猎人”这种孤零零的名词。

**B：** 骨架能站起来，不代表可以宣布“完整”。当前更准确的名称应该是：

> **商业韩漫常见叙事生产库 v1.0 基础骨架**

它还不是经过真实作品语料验证的完整韩漫知识库，也不是能直接供程序稳定调用的结构化数据库。

**A：** 同意。当前最有价值的是方法论，不是覆盖率。

**B：** 综合评分：**72/100，可使用，但必须进入 v1.1 修订。**

| 审计维度 | 分数 | 结论 |
|---|---:|---|
| 核心结构 | 88 | 题材、对象、行为、回报分层成立 |
| 故事生成能力 | 80 | 能生成骨架，但链条缺少分支与编码引用 |
| 题材覆盖率 | 63 | 主流商业类型较多，仍有明显空区 |
| 对象覆盖率 | 72 | 人物、关系、资源、秘密、场域已成形，但分类不一致 |
| 行为覆盖率 | 74 | 宏观行为足够，微观语言行为和同意边界不足 |
| Obsidian可用性 | 70 | 文件级双链可用，条目级双链不足 |
| 自动化可读性 | 48 | 编码冲突、无统一Schema、无交叉索引 |
| 来源可信度 | 35 | 没有真实作品、课程、平台或话数来源 |
| 十元理论边界 | 90 | 明确禁止倒推，接口方向基本正确 |
| 排版一致性 | 68 | 标题层级、宽表、目录预告存在问题 |

# 二、第一轮对话：这个库到底算不算“完整”

**A：** 64个题材、48个主体、48个关系、80个资源秘密场域、120条行为、36条链，体量已经不小。

**B：** 数量不是完整性。主要问题有三个：

1. 没有说明采样范围。
2. 没有真实作品频次统计。
3. 没有建立“已覆盖”和“未覆盖”的边界表。

**A：** 所以“完整”应该改成“当前范围内覆盖常见商业结构”。

**B：** 对。否则以后发现科幻、喜剧、BL、历史、儿童、恐怖等空区时，库的版本声明会自相矛盾。

## 共识结论

- `00_总控索引.md` 的版本边界写得相对克制，但文件与PR描述中使用“完整”会造成过度承诺。
- v1.1应新增：
  - `coverage_scope`
  - `excluded_scope`
  - `evidence_level`
  - `corpus_size`

# 三、第二轮对话：编码系统存在全局撞车

**B：** 这是当前最严重的技术问题。

题材库使用：

```text
A01、B01、C01……
```

行为库也使用：

```text
A01、B01、C01……
```

行为链又使用：

```text
C01、C02……
```

场域对象使用：

```text
F01、F02……
```

行为库的交换行为也使用：

```text
F01、F02……
```

**A：** 人眼看不同文件还能分辨。

**B：** 程序、Dataview、Canvas节点、跨文件引用和搜索不能靠猜。搜索 `C01` 会同时得到题材、行为和行为链。编码如果不能唯一识别对象，就只是装饰。

**A：** 模板里也使用 `T-待编号`、`A-待编号`、`C-待编号`，和现有表格的编码规则不一致。

## 必须修复

建议改为全局命名空间：

```text
THM-A01  题材
ACT-A01  行为
CHN-C01  行为链
SUB-S01  主体对象
REL-R01  关系对象
RES-O01  资源对象
SEC-M01  秘密对象
FLD-F01  场域对象
PAY-P01  情绪回报
HOK-H01  单话钩子
```

## 严重级别

**P0｜最高优先级。**

原因：不修复就无法稳定建立条目级链接、Canvas关系、自动生成器和后续采矿表。

# 四、第三轮对话：对象分类前后不一致

**A：** 总控里提出“对象的四种等级”：人物、关系、资源、规则。

**B：** 但实际文件和模板使用的是五类：

```text
人物对象
关系对象
资源对象
秘密对象
场域对象
```

秘密对象在总控四级模型里没有明确位置；“规则对象”在其他文件又被称为“场域对象”。

**A：** 这会造成两个问题：

1. 新条目不知道秘密应该放资源层还是独立层。
2. 场域与规则被混在一起，无法区分“空间”与“制度”。

## 推荐修订

把对象体系明确为六类：

| 编码 | 对象类型 | 定义 |
|---|---|---|
| SUB | 主体对象 | 能主动发起和回应行为的人或人格化存在 |
| REL | 关系对象 | 持续绑定两个以上主体的结构 |
| RES | 资源对象 | 可以转移、交换、剥夺、消耗的东西 |
| SEC | 秘密对象 | 价值来自知情差、公开权和误解的对象 |
| FLD | 场域对象 | 行为发生、进入、停留和离开的空间 |
| RUL | 规则对象 | 决定许可、惩罚、排名和合法性的制度 |

场域和规则经常绑定，但不应视为同一个对象。

## 严重级别

**P1｜高优先级。**

# 五、第四轮对话：题材覆盖有什么明显遗漏

**A：** 当前八大组已经覆盖恋爱、阶级、回归、战斗、悬疑、疗愈、危险关系、职业现实。

**B：** 但它仍明显偏向“恋爱幻想 + 身份逆袭 + 能力升级”。作为商业韩漫常见库可以理解，作为完整题材库则有以下空区。

## 1. 喜剧类不足

当前没有独立的：

- 误会喜剧
- 身份错位喜剧
- 职场讽刺
- 家庭喜剧
- 荒诞日常
- 黑色喜剧
- 游戏吐槽/系统反套路

行为库也缺少喜剧升级链，例如：

```text
小谎言 → 为圆谎制造第二个行为 → 第三者误读 → 公开场合失控 → 意外真相解决假问题
```

## 2. 科幻类不足

缺少：

- 赛博朋克
- 人工智能与仿生人
- 太空殖民
- 时间旅行的科学型结构
- 记忆备份/人格复制
- 虚拟现实
- 机甲与军事科技
- 生物实验与克隆

当前“异能机构”和“游戏世界”不能替代完整科幻母型。

## 3. 历史、战争与政治题材不足

缺少：

- 朝鲜王朝历史剧
- 殖民时期与独立运动
- 战争生存
- 军队组织
- 政治选举与权力公共性
- 历史人物传记
- 宫廷以外的历史社会生活

当前“宫廷继承”更接近幻想贵族，不等于历史题材。

## 4. 恐怖与超自然不足

都市怪谈只有一个入口，还缺：

- 宗教恐怖
- 身体恐怖
- 家族诅咒
- 民俗巫俗
- 驱魔
- 鬼魂关系
- 梦境污染
- 宇宙恐怖
- 怪物共生

## 5. 浪漫幻想细分仍不够

缺少或未独立标注：

- 育儿/养成型浪漫幻想
- 圣女、神官、神谕
- 北部公爵/边境领主治理
- 魔塔主、魔法师组织
- 人外恋、兽人、龙、吸血鬼
- 替嫁、逃婚、追妻
- 多次回归与失败周目
- 女主经营领地/家族产业

## 6. 性别与关系方向没有标签层

BL、GL、异性恋不一定要成为不同叙事结构，但应增加：

```yaml
relationship_orientation:
romance_target:
gender_power_context:
```

否则无法检查某些结构是否过度默认异性恋、男性高位、女性低位。

## 7. 儿童、少年成长与家庭向不足

缺少：

- 儿童冒险
- 少年友情
- 成长仪式
- 校园社团群像
- 亲子代际冲突的非恋爱主线
- 动物拟人/家庭向奇幻

## 严重级别

**P1｜高优先级。**

不是要求一次塞满所有类型，而是必须先把空区写进覆盖边界。

# 六、第五轮对话：行为库数量够，但行为颗粒度不均

**A：** 120条宏观行为足够生成多数事件。

**B：** 宏观行为多，微观行为少。当前行为更像剧情功能词，不完全是可演出的动作单元。

## 已有优势

- 每个行为包含直接对象、叙事功能和代价。
- 权力、保护、欺骗、调查、修复均有独立行为族。
- 明确区分“情绪状态”和“行为”。

## 主要遗漏

### 1. 语言行为库缺失

应增加：

- 承认
- 否认
- 指控
- 解释
- 辩解
- 许诺
- 威胁
- 请求
- 乞求
- 挑衅
- 打断
- 转述
- 保证
- 宣布
- 沉默拒答
- 改口
- 公开命名关系

这些不是普通台词分类，而是改变承诺、责任、关系许可和公共认知的行动。

### 2. 同意与边界行为不足

危险关系题材很多，但缺少系统化的：

- 请求许可
- 明确同意
- 撤回同意
- 拒绝触碰
- 重新协商边界
- 归还隐私
- 删除未经允许的记录
- 寻求第三方保护

若只有监视、隔离、强制、囚禁，却没有完整边界行为，库容易把“描写控制”滑向“默认浪漫化控制”。

### 3. 亲密行为没有功能化词表

总控正确地说接吻、拥抱不是完整行为，但还缺少“动作外壳 → 功能”的映射：

| 动作外壳 | 可能功能 |
|---|---|
| 拥抱 | 安抚、阻止离开、公开占有、确认安全、告别 |
| 接吻 | 请求关系、转移话题、表演身份、操纵、承诺 |
| 牵手 | 引导、保护、公开关系、强制带离、寻求稳定 |
| 递物 | 照料、交换、赔偿、试探、归还关系物 |

### 4. 喜剧行为不足

- 强行圆谎
- 误认身份
- 同时隐瞒两个对象
- 过度准备却用不上
- 模仿失败
- 社交补救越补越坏
- 一本正经处理荒诞规则

### 5. 职业劳动行为不足

职业题材不能只有“竞标、发布、谈判”。还需要具体劳动：

- 设计草图
- 修改方案
- 现场勘查
- 排练
- 剪辑
- 诊断
- 配药
- 复健
- 做菜
- 修缮
- 编程
- 采访整理
- 法律检索

否则职业只是换皮场景。

## 严重级别

**P1｜高优先级。**

# 七、第六轮对话：行为链看起来完整，但机器无法真正调用

**A：** 36条链已经能直接拿来生成剧情。

**B：** 人可以读懂，程序不能稳定引用。每条链目前主要是自然语言箭头，存在四个问题。

## 问题1：没有引用具体行为编码

例如“假关系变真关系”应写成：

```yaml
steps:
  - action: ACT-C04
    function: 签订契约
  - action: ACT-B02
    function: 测试边界
  - action: ACT-E06
    function: 公开维护
  - action: ACT-I03
    function: 解除契约
```

现在的链和行为库没有真正连接。

## 问题2：没有输入状态与输出状态

每条链至少需要：

```yaml
input_relation:
input_power:
shared_object:
turning_point:
output_relation:
output_power:
```

## 问题3：链条过度线性

韩漫连载需要失败分支和延迟分支：

```text
成功分支
误读分支
拒绝分支
外部介入分支
代价提前兑现分支
```

## 问题4：链条长度与话数没有对应

同一条链可以是：

- 1话微链
- 3—5话小链
- 12话中链
- 30话季链

目前没有尺度字段。

## 严重级别

**P0｜最高优先级。**

这是从“知识文档”升级成“生成系统”的关键修订。

# 八、第七轮对话：排版与Obsidian问题

**B：** 行为总库、模板文件等在H1之后继续使用H1：

```markdown
# 05｜行为总库
# A. 接近与建立连接
# B. 观察、试探与判断
```

这会让Obsidian大纲把文件名和分类标题视为同级根节点。

**A：** 应统一为：

```markdown
# 文件标题
## 一级分区
### 单条母型
#### 示例或说明
```

## 其他排版问题

### 1. 宽表在手机和平板上难读

题材总库的六列表、资源对象库的五列表都很宽。建议：

- 总览表只保留三到四列。
- 详细字段拆入条目卡。
- 或使用折叠Callout。

### 2. 推荐目录写了未创建目录

模板文件展示 `11_作品采矿/` 到 `15_行为链卡/`，但这些目录目前并不存在。作为规划没有错，但需要明确标注：

```text
以下为计划目录，尚未创建
```

### 3. 文件级链接多，条目级链接少

当前 `[[01_题材总库]]` 这类文件导航有效，但表格中的“契约婚姻”“公开维护”“假关系变真关系”并不是独立链接。

因此无法从一个对象直接反查：

- 它在哪些题材出现
- 它调用哪些行为
- 它进入哪些链
- 它产生哪些回报

### 4. YAML字段不统一

不同文件只记录不同的计数字段，没有统一的：

```yaml
id:
version:
status:
created:
updated:
schema_version:
source_level:
entry_count:
```

### 5. 缺少CHANGELOG和版本迁移说明

编码一旦修订，旧引用需要迁移表。

## 严重级别

- 标题层级：**P1**
- 条目级链接：**P0**
- 宽表与目录说明：**P2**
- YAML统一：**P1**

# 九、第八轮对话：来源与真实作品证据不足

**A：** 总控已经说后续扩展应以真实作品采矿为依据。

**B：** 但当前库没有一条条目标记来源。无法区分：

- 韩国平台真实高频结构
- 一般网文结构
- 日漫/中漫共通结构
- 本次推理生成的结构

“韩漫”这个名称需要证据支持。

## v1.1应增加的证据字段

```yaml
source_level: 推理生成 / 单作采矿 / 多作重复 / 平台高频
source_work:
source_chapter:
platform:
audience_segment:
observed_frequency:
last_verified:
```

## 推荐证据等级

| 等级 | 标准 |
|---|---|
| E0 | 纯推理条目，尚无作品证据 |
| E1 | 1部作品中出现 |
| E2 | 3部以上作品重复出现 |
| E3 | 10部以上或平台榜单中稳定出现 |
| E4 | 有课程、论文、行业访谈或平台资料支持 |

## 严重级别

**P1｜高优先级。**

不要求现在就把全库变成论文，但必须诚实区分“推理母型”和“实证母型”。

# 十、第九轮对话：危险关系需要伦理与叙事边界字段

**A：** 库里写监视、隔离、囚禁、强制婚约，是为了分析冲突，不是赞美。

**B：** 意图正确，但数据结构没有把这个区别保存下来。以后调用时，生成器可能只看到“高刺激行为”，看不到“必须承担后果”。

## 建议增加

```yaml
consent_status:
power_abuse:
romanticization_risk:
victim_agency:
required_consequence:
recovery_path:
```

## 三种叙事状态必须区分

| 状态 | 定义 |
|---|---|
| 描写 | 作品展示控制行为存在 |
| 批判 | 行为造成代价并被角色或结构反制 |
| 浪漫化 | 行为被当作爱的证明，受害者主体权被抹除 |

## 严重级别

**P1｜高优先级。**

# 十一、第十轮对话：十元接口是否有问题

**A：** 十元接口目前最值得保留。它明确规定：

- 先让叙事对象和行为成立。
- 不默认 `zn` 起手。
- 不默认 `n` 承载。
- 不从视觉和结局倒推。
- 动态链与行为链分开。

**B：** 原则正确，但示例太少。只有契约婚姻示例，容易让接口再次被恋爱题材垄断。

## 应补五类完整案例

1. 恋爱关系：契约婚姻
2. 战斗成长：猎人回归
3. 悬疑因果：证据翻转
4. 日常疗愈：临时家庭
5. 本体身份：附身/署名夺回

每例必须保留：

```text
三场关键行为
对象状态变化
感觉主次
体量
顺序
生克补依据
反证
```

## 严重级别

**P2｜中优先级。**

# 十二、双方最终确认的问题清单

## P0｜必须先修，否则阻碍扩展

| 编号 | 问题 | 修复动作 |

# 十六、最终判定

**A：** 这套库不是失败品。相反，它已经跨过了最难的一步：不再把题材当作名词堆积，而是开始分析对象与行为。

**B：** 但目前它仍是“高质量的人工阅读文档”，还不是“完整、实证、可自动调用的数据库”。

**A：** 最应该保留的是：

- 题材、对象、行为、回报四层分离
- 每个行为必须有代价与回应
- 弱势对象必须拥有反制或拒绝权
- 十元理论不得倒推叙事事实

**B：** 最应该立刻修的是：

1. 全局ID冲突
2. 缺少交叉索引
3. 对象分类不一致
4. 标题层级与YAML不统一
5. 无真实作品来源等级
6. 题材与行为覆盖空区
