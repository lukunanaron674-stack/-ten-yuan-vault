# 十元组合规律研究｜总索引 v1.0

> 本库研究的不是“某条生克补边是否成立”，而是：多个十元在同一对象、同一阶段中怎样组成一个可重复识别的**对子或组合结构**，以及主次、体量、顺序和缺失项怎样改变整体功能。

## 一、研究对象

本库的最小单位不是松散的 `A+B`，而是完整对子：

```text
对子 P = 主十元 + 次十元 + 对象层 + 体量配比 + 激活方式 + 整体功能
```

一张合格组合卡必须说明：

1. 研究的是人物、关系、制度、场景、镜头、阶段还是整部作品；
2. 谁是主十元，谁是次十元；
3. 两者是同时激活、交替激活，还是一者作为另一者的底层条件；
4. 体量与主导权怎样分配；
5. 该对子产生了什么不可由单一端点充分解释的整体功能。

只写“两个十元经常一起出现”不构成组合规律。人类把两样东西摆在同一张桌上，并不会自动发明一门科学。

## 二、与单条关系审计的边界

组合研究不得反向制造生克补正本：

```text
共现 ≠ 生
协同 ≠ 补
冲突感 ≠ 克
先后出现 ≠ 生成关系
主题公式 ≠ 直接机制
```

若组合卡需要使用严格生、克、补箭头，必须引用已经锁定的单条关系正本；未锁定关系只能写成待检候选或中性过程标签。

本库只读十元信息卡、准度卡和关系正本，不直接修改它们。发现端点或关系冲突时，应提交给审计，而不是在组合卡里偷偷改理论。

## 三、组合层级

### 1. 双元对子

```text
A（主） + B（次）
```

研究主次、配比、互缺、交换主导后的功能变化。

### 2. 三元组合

```text
A（主） + B（次） + C（条件或调节）
```

必须说明第三元是核心组成、桥接项、限制项还是阶段性调节项，不能把所有出现过的十元都塞进公式里举办团建。

### 3. 多元簇

仅在双元与三元解释明显不足、且至少三个独立案例都需要同一结构时启动。多元簇不得作为逃避主次判断的垃圾桶。

## 四、主次与体量记录

每张组合卡至少记录：

```yaml
primary_ten_yuan: zx
secondary_ten_yuan: nx
primary_volume: 7
secondary_volume: 4
activation_mode: simultaneous | alternating | conditional | layered
object_layer: character | relationship | institution | scene | stage | whole_work
```

同一符号组合在不同配比下视为不同候选：

```text
zx8 + nx2  ≠  zx4 + nx7
```

主次交换也必须单独测试：

```text
zx主 + nx次  ≠  nx主 + zx次
```

## 五、组合规律证据门禁

一条组合规律进入稳定池前，至少完成：

1. **端点复核**：每个十元均符合当前信息卡与准度卡；
2. **对象层冻结**：不得把人物本体、关系结构与镜头氛围混成一个组合；
3. **主次测试**：交换主次后，整体功能是否变化；
4. **拿掉测试**：拿掉其中一元，核心功能是否显著下降或变质；
5. **替代测试**：以最近邻十元替换后，是否仍产生相同功能；
6. **第三因素冻结**：排除题材、类型片惯例、共同事件和视觉风格；
7. **反例记录**：至少一例同组合但功能不成立的负例；
8. **跨作品复验**：稳定规律至少三部独立作品；
9. **跨领域复验**：若声称普遍规律，至少覆盖两类对象或领域。

同一系列、同一作者的多个作品默认只算一个来源家族，免得复制粘贴被统计学包装成宇宙真理。

## 六、七项置信度

```yaml
primary_endpoint_accuracy: 0-100
secondary_endpoint_accuracy: 0-100
combination_integrity: 0-100
functional_specificity: 0-100
removal_and_substitution: 0-100
rival_exclusion: 0-100
cross_case_replication: 0-100
final_confidence: 取最低项
```

状态门槛：

| 状态 | 条件 |
|---|---|
| `candidate` | 有清晰对象层、主次与功能假设 |
| `observed` | 至少两部独立作品重复出现 |
| `controlled` | 拿掉、替代、主次交换和第三因素已完成 |
| `stable` | 七项均≥90，且至少三部作品复验 |
| `canonical` | 七项均≥95，跨领域成立，并经审计确认不冲突 |
| `rejected` | 主要由题材共现、单一端点或第三因素解释 |

## 八、首批基线池

以下仅为待建卡对象，不因进入清单而自动成立：

### 五大主题对子

- `xn + z`：时间
- `zn + x`：本体
- `x并z + n`：空间
- `zx + nx`：因果
- `xz + nz`：命运

首轮只做“对子基线定义体检”：确认对象层、主次可能性、体量范围、功能边界与反例，不直接宣称它们是最佳组合。

### 开放候选

- `zn + n`
- `xz + nz`
- `xn + z`
- `zx + nx`
- `zx + nx + xz`
- `xn + z + zn`

开放候选来自既有创作与分析经验，全部保持 `candidate`，不得预设故事效果。

## 十、与其他研究库的分工

- **审计**：确认十元端点和单条生克补关系是否成立；
- **组合规律研究**：确认一个对子内部怎样配合、主次与体量怎样改变功能；
- **趋势规律研究**：确认对子与对子之间怎样发生阶段迁移；
- **动态链研究**：在具体作品的连续片段中记录真实对子变化与箭头。
