# AI 文件权力与每小时任务总览

> 这张表只治理“文件有什么权力、AI 应怎样读取、任务会读写哪里”。它不替代十元理论正本，也不从文件层级推导理论层级。

## 1. 先分清两种权力

| 权力 | 回答的问题 | 最高来源 |
|---|---|---|
| **流程权力** | AI 必须先读什么、允许写什么、什么时候停止 | `AGENTS.md`、任务门禁、滚动中枢 |
| **知识权力** | 十元端点是什么、关系是否成立、哪个结论覆盖哪个旧结论 | 信息卡、准度卡、单条关系卡、核心表、专项正本 |

流程门禁不能替代理论结论；理论正本也不能取消安全规则、读写边界或并发门禁。

## 2. 权力等级

| 等级 | 名称 | 对 AI 的约束 | 典型文件 | 冲突时怎么处理 |
|---|---|---|---|---|
| **L0** | 根规则 | 全库绝对强约束 | `AGENTS.md` | 任何下级文件都不能覆盖 |
| **L1** | 强制门禁与滚动中枢 | 范围内强约束；决定启动、边界、当前断点 | `每次任务必读_*`、`每小时执行门禁协议_*` | 同范围内必须执行；它们不改写理论正本 |
| **L2** | 理论正本 | 对知识判断强约束 | 信息卡、准度卡、生/克/补卡、`十元生补克表`、专项正本索引 | 正本覆盖旧审计、旧摘要和案例印象 |
| **L3** | 路由与治理 | 中强约束；决定去哪里读、文件是什么身份 | `总入口.md`、`Codex大脑总入口.md`、`仓库文件层级与is-a总表.md`、本文件 | 只管导航、身份和覆盖，不得造理论 |
| **L4** | 运行账本与审计证据 | 弱约束；证明发生过什么 | 每小时运行记录、审计文件、问题单、验证记录 | 可提供证据，不能单独升格成正本 |
| **L5** | 案例、项目与素材 | 情境约束 | 银矿、影片案例、创作项目、概念库 | 只在指定对象和阶段内使用 |
| **L6** | 归档、旧稿与降权文件 | 最弱；历史证据 | `归档/`、`版本备份/`、`legacy-*`、`superseded`、`pending-absorb` | 永远不能反向覆盖当前正本 |

### 不是“越新越强”

文件日期、文件长度、提交次数、标题里有“总”“正本”“完成”，都不能自动提高权力。必须同时检查：

```text
scope → type → status → version → parent / supersedes → 当前索引登记
```

## 3. 文件功能词典

| 文件功能 | 真正作用 | 不能做什么 |
|---|---|---|
| `入口` | 指路 | 不直接下理论结论 |
| `正本` | 保存当前有效定义或机制 | 不替代执行门禁 |
| `门禁` | 规定启动条件、证据门槛、写入边界 | 不因流程存在就证明理论成立 |
| `滚动中枢` | 保存当前断点、下一目标、运行状态 | 不冒充最终运行成功 |
| `账本` | 证明某轮真实运行与提交 | 不凭运行次数制造知识增长 |
| `索引` | 登记身份、状态、覆盖关系和读取路线 | 不用缺项反推“关系不存在” |
| `审计` | 检验未锁定关系或保留历史证据 | 审计完成不等于机制锁定 |
| `案例` | 提供对象、阶段和事实证据 | 不反向定义十元端点 |
| `Canvas` | 给人查看结构与读写流 | 图上相连不等于理论生克补 |
| `归档` | 保存历史来源 | 内部旧 `active/current` 字样不恢复权力 |

## 9. 冲突裁决

```text
先看任务对象与 scope
→ 流程问题服从 L0/L1
→ 理论结论服从 L2
→ 文件身份与读取路线服从 L3
→ L4/L5 只提供证据
→ L6 只保存历史
```

同级冲突时依次检查：`canonical-current`、明确 `supersedes/covers`、当前索引登记、版本、最后核验 SHA。仍无法判定就标记 `待二审`，不静默选一份。

## 10. Canvas 使用

- 打开 [[AI文件权力与任务总览.canvas]] 看“强弱约束 + 每小时任务读写流”。
- 红/橙节点是强约束；紫色是理论正本；蓝色是路由治理；绿色是账本/证据；黄色是风险。
- Canvas 只显示关系，不改变任何文件的权力。权力仍由本页登记和各文件 frontmatter/索引共同决定。
