# R1.5 R2 独立整理环境方案

> [!warning] 本轮不执行 R2
> 本文件只规划环境，不分类、不移动、不改名、不修 Canvas、不修改 L0–L2、不推送 main。

## 建议目录结构

在备份验收通过后，以 E: 备份为源建立新目录，例如：

`E:\R1.5_Backups\ten-yuan-vault\R2-workspace-20260921\`

建议分为：

- `source-local-head\`：本地 `1f501786…` 的只读来源副本。
- `source-remote-snapshot\`：经只读 API/镜像取得并登记 SHA 的远端快照，不覆盖本地。
- `working-compare\`：只放清单、hash、权限层和冲突表。
- `candidate-import\`：经人工批准后才复制的候选数据。
- `reports\`：审计和验收报告。

该目录不得被 Obsidian 打开，不得接入自动任务，不得设置为 GitHub Desktop 当前仓库。

## R2 分阶段门槛

1. 先验证 R1.5 备份的文件数、字节数、SHA-256、bundle 和恢复流程。
2. 固定本地/远端 SHA，取得新的只读远端 tree；不依赖过期 `origin/main`。
3. 只在 `working-compare` 生成本地独有、远端独有、内容不同、重复和 Canvas 缺失清单。
4. 按 L0–L6 判定文件权力；L0–L2 正本和冻结角色资产只读。
5. 人工确认后，才把允许处理的文件复制到 `candidate-import`；原 Vault 保持不动。
6. 先在独立工作区做 Canvas 引用模拟检查和回滚演练，再考虑任何发布动作。
7. 发布/推送是单独授权动作；不自动推送 main。

## 进入 R2 的阻塞项

- 未归属的 `git commit 01` 触发源仍未知。
- GitHub Desktop 已关闭，但 Obsidian 仍打开并已观测到 workspace/Canvas 写入；无法证明用户程序未来不会写入。
- 实时 GitHub `main` 与本地缓存/本地 HEAD 不同，需重新冻结。
- Git bundle 已通过完整性验证，但早期工作树快照比当前工作树少 16 个文件、少 4,676,945 bytes；未完成稳定当前快照验收，不能创建正式 R2 工作区。
- 隔离 LLL DryRun 进程后仍出现未归属写入，必须先归属 Obsidian/其他 Codex 或生成器写入。
- 停止单次 LLL 进程后，Hermes/角色文字 DryRun 仍以短生命周期形式继续运行；启动器没有稳定 PID，不能安全终止其 Codex app-server/Hermes 宿主。

## 本轮停止条件

- 未创建 `R2-workspace-20260921`，未复制 R2 整理工作区，未分类、移动、改名或修复任何正式文件。
- 未修改 L0–L2 正本、冻结角色资产或 Canvas 引用；本轮仅写入 R1.5 报告及备份元数据。
- R1.5 结论：阻塞，不具备进入 R2 的条件。

## 禁止事项

- 不在日常 Vault 上做批量重组。
- 不复制凭据、令牌或完整敏感日志到公开仓库。
- 不以重复 hash 代替权力、状态和来源判断。
- 不改变现有 Canvas 引用，不自动补图，不自动锁定候选。
