# R1 重复文件与版本冲突

> [!warning] 重要
> 相同内容不等于相同权力、状态或用途。R1 只登记，不删除、不移动、不合并。

## 1. 扫描基线

- 扫描范围：Vault 实际文件，排除根 `.git` 目录；保留并识别嵌套 `.tmp/minoan/.git`。
- 实际文件：10,860 个。
- 总大小：3,386,212,518 bytes。
- 同大小候选组：1,720 组。
- 精确 SHA-256 重复：417 组，涉及 934 个文件（以本轮完整扫描的 SHA-256 组为登记基线）。
- 文件名、目录名和“当前/备用/锁定/归档”等标签没有参与内容相等判定。

上述重复统计是在后台 `chore: compress vault images over 3 MiB`、merge 和后续远端继续变化之前完成的中间扫描。它们是 R1 的已留证快照，不是 R2 可直接执行的当前处置清单；用户冻结后必须重扫并重新计算 hash。

## 2. 已观察的重复模式

| 模式 | 例子 | 风险 |
|---|---|---|
| 《黎黎隆》MET/图像参考在 R4/R5 目录重复 | 多个 `assets/references/imagewell/refR4_*`、`refR5_*` | 同图可能代表不同轮次、来源或审核状态 |
| 方志敏音频在“当前/备用/锁定”路径重复 | 第三幕音频与备份目录 | 文件相同不代表锁定状态相同 |
| 临时截图与正式素材重复 | `方/07_素材图/临时截图/` 与正式素材路径 | 临时副本可能带有时间线或来源证据 |
| 候选、锁定、归档版本重复 | 图片和视频候选目录 | 不能因 hash 相同而自动升格为交付 |
| 嵌套 Git pack 与其他对象边界不同 | `.tmp/minoan/.git/objects/pack/` | 可能把另一个仓库的历史误带入公开仓库 |

## 3. 版本冲突

### 3.1 Git tree 冲突

本地 `HEAD=6a4d1cbb…` 与 GitHub 实时 `main=6108a324…`：

- 共有路径且内容不同：154 个。
- 典型冲突包括 `.gitignore`、`.obsidian` 配置/插件、`00-中枢索引/总入口.md`、十元行为库索引与 JSONL、动态链 Canvas、F12/影刀日志、黎黎隆角色/场景 Canvas。

### 3.2 语义版本冲突

- “正本/研究稿/候选/锁定/归档/备份”混在同一文件树时，不能只按名称选择最新版。
- 同一角色、场景或音频可能在多个工作轮次出现；需要结合 L3 路由、卡级状态、Canvas 所属项目和人工审核状态。
- 内容 hash 相同但路径不同的文件，仍可能承担来源、时间线、审核和回滚证据。

## 4. R2 建议的人工判定字段

每个重复组至少记录：

1. SHA-256、大小、媒体探针结果（如适用）。
2. 文件原始路径、首次发现路径和当前使用路径。
3. 权力层 L0–L6、知识成熟度、候选/锁定/交付状态。
4. Canvas 引用数、卡级引用数和是否为唯一来源。
5. 来源/版权/公开风险。
6. 允许的回滚路径；如未完成，保持 `待二审`。

## 5. 本轮处置

- 未删除、未移动、未覆盖任何重复文件。
- 未把精确重复组自动合并成“主文件”。
- 未修改正本、冻结角色设定、Canvas 引用或 Git 历史。
