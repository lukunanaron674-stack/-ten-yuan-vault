# L1-L6 文件权力 × 知识成熟度双轴协议 v2.0

> 本协议解决一个长期混淆：**文件权力等级**与**知识结论成熟度**不是同一件事。
>
> L0-L6 回答“这个文件有多大治理/知识权力”；成熟度轴回答“这个结论经过了多少证据与审议”。两轴必须同时记录，禁止互相替代。

## 1｜双轴总则

### A 轴：文件权力

继续沿用现行等级：

```text
L0 根规则
→ L1 强制门禁 / 滚动中枢
→ L2 理论正本
→ L3 路由 / 治理
→ L4 运行账本 / 审计证据 / 问题单 / 验证记录
→ L5 案例 / 项目 / 素材
→ L6 归档 / legacy / superseded / 历史证据
```

该轴只回答：
- 谁能约束谁；
- AI 启动先读什么；
- 哪些文件可直接用于知识判断；
- 哪些文件只能提供证据；
- 哪些文件只保留历史。

### B 轴：知识成熟度

推荐状态链：

```text
raw
→ candidate
→ deferred
→ evidence-locked
→ cross-work-control
→ pending-review
→ canonical-current
→ superseded / legacy-evidence-only
```

解释：
- `raw`：原始事实或未分类材料；
- `candidate`：有解释候选，但事实/分类尚未过锁定门；
- `deferred`：存在真实分歧或缺关键证据，暂缓；
- `evidence-locked`：单案例事实与分类均达到当前任务规定的锁定门；
- `cross-work-control`：同一边界在多个独立作品中按同一判据版本复现；
- `pending-review`：达到仓库规定的跨作品/反例/最邻近审议门，等待正式审议；
- `canonical-current`：已被授权审议流程吸收到 L2 正本；
- `superseded / legacy-evidence-only`：被更高版本覆盖，仅保留历史证据。

**成熟度高不自动提高文件权力。** 99/99 的 `evidence-locked` 运行记录仍可以是 L4；它不能因为“很准”自动覆盖 L2。

**文件权力高也不自动提高结论成熟度。** L3 总览可以登记 `candidate`，但不能因位于中枢而把候选变成正本。

## 2｜必须分开的字段

凡是承载可晋级研究结论的新文件，优先同时记录：

```yaml
authority_level: L4
knowledge_status: evidence-locked
fact_confidence: 99
classification_confidence: 98
criterion_version: <当前判据版本/正本引用>
cross_work_count: 1
positive_control_count: 1
negative_guard_count: 0
may_override_canonical: false
```

旧文件不要求批量补齐；仅在被重新触及时按需补充，避免机械改库。

## 3｜L5 / L4 → L2 的正式晋级路线

```text
L5 原始案例 / 材料
↓ 事实核验、对象层切分、最近邻排除
L4 candidate / deferred / evidence-locked
↓ 同一判据版本跨作品复验
L4 cross-work-control
↓ 达到门槛并形成待审议问题
L4 pending-review
↓ 授权审议独立复核
L2 canonical-current
↓
L3 更新索引、覆盖、路由
↓ 必要时
L1 更新执行门禁 / 自动任务读取纪律
```

### 晋级硬门

1. **同一判据版本门**：跨作品统计必须使用同一 `criterion_version`。若正本或判据发生冲突/纠偏，旧案例必须逐案重验，不能继承旧计数。
2. **对象层门**：局部对象层成立不得倒灌整个任务层、人物本体或长期结构。
3. **最近邻门**：必须独立排除最接近的邻居端点/机制。
4. **拿掉门**：移除候选端点/关系后，缺口必须可命名。
5. **反向门**：反向改写时应出现可观察变化；否则降低结论强度。
6. **第三因素冻结门**：不能把共同敌人、制度、资源稀缺、身份规则等第三因素当成两端关系本身。
7. **正反例分账门**：positive controls 与 negative guards 分开计数；反例护栏不增加“支持规则的独立作品数”。
8. **生命周期分账门**：初始成立、激活、退出、压力显影、资源内化、时间窗口闭环分别统计，不能互相自动继承。
9. **canonical 冲突门**：任何 candidate / deferred / evidence-locked / pending-review 都不得反向覆盖 `canonical-current`。冲突时标记 `deferred-canonical-conflict` 或等价状态，等待审议。
10. **真实写入门**：只有真实新增/修正才提交；提交后必须远端回读并记录真实 SHA。

## 4｜降级与回退路线

### 4.1 新证据否决

```text
pending-review / evidence-locked
→ 发现对象层错误、最近邻误判或判据版本失效
→ deferred / rejected / superseded
→ 必要时移入 L6 历史证据
```

### 4.2 正本纠偏

正本发生纠偏时：

```text
先冻结旧跨作品统计
→ 标记 criterion_version 失效
→ 逐案按 current canonical 重验
→ 通过者恢复计数
→ 未通过者降级为单向 / candidate / superseded
```

禁止“批量恢复”或“批量作废”。每个旧案例必须独立通过新门。

### 4.3 局部成立防倒灌

若只证明某一局部功能已内化、激活或退出：

```text
局部 x 成立
≠ 整个任务层 nx 关闭

某一接口退出
≠ 等价外部接口类全部退出

任务/方向发出
≠ nx 自动激活

拒绝某外部方向
≠ 对立端自动成立
```

这类结论只能晋级到被实际证明的对象层。

## 5｜跨轴通用研究纪律

木轴研究已经验证下列方法可迁移到火/土/金/水，但迁移后仍需各轴自己的案例复验：

- 长期结构存在 与 当前功能激活分开；
- 输入存在 与 主体实际接入分开；
- 名义权限 与 现实否决权分开；
- 局部自主 与 整体结构内化分开；
- 最高权威 / 惩罚强度 ≠ 主体实际接入；
- 动作复杂度 ≠ 运行骨架自主；
- 最低主体参与 / 同意 ≠ 高显影端点；
- 初始关系成立 与 后续时间闭环分开；
- 正例数量 与 反例护栏分开；
- 文件权力 与 知识成熟度分开。

这些方法进入治理层时只形成**验证模板**，不得自动生成火/土/金/水的理论关系。

## 6｜各等级如何使用成熟度轴

| 权力层 | 可承载成熟度 | 允许做什么 | 禁止做什么 |
|---|---|---|---|
| L0 | 不承载具体理论成熟度 | 定根规则、安全、权限 | 不定义端点/关系 |
| L1 | 门禁版本 | 规定证据门、晋级流程、当前断点 | 不凭流程宣布理论成立 |
| L2 | `canonical-current` 为主 | 保存当前有效定义/机制 | 不把未审议候选写成正本 |
| L3 | 任意状态的路由登记 | 登记身份、覆盖、晋级路线 | 不因索引位置提高成熟度 |
| L4 | `candidate` 到 `pending-review` 为主 | 审计、验证、跨作品统计、问题单 | 不直接覆盖 L2 |
| L5 | `raw` / `candidate` / 案例证据 | 提供具体对象与事实 | 不反向定义理论 |
| L6 | `superseded` / `legacy` | 保存历史、失效判据与旧证据 | 不恢复旧权力 |

## 7｜自动任务与 AI 的执行要求

当自动任务或 AI 消化研究资产时：

1. 先判定文件权力轴，再判定知识成熟度轴；
2. 汇报中同时说明“写在哪一层”和“成熟到哪一步”；
3. 不得把“提交过很多次”写成成熟度提升；
4. 不得把“跨作品很多”写成自动正本化；
5. 达到 `pending-review` 后停止自动升格，交给授权审议路线；
6. 若新研究方法只是在某一轴通过，不自动修改其他四轴 L2；
7. 所有 cross-work 数必须标注使用的判据版本；
8. 当研究层与 canonical 冲突时，正本优先，研究层保留冲突说明并停止上推。

## 8｜一句话总纲

> **L0-L6 管“谁有权说话”，成熟度轴管“这句话被证明到哪一步”；证据从 L5/L4 向 L2 晋级必须经过同判据、对象层、最近邻、拿掉/反向、第三因素、跨作品与正式审议，任何研究层结论都不得跳级覆盖 canonical。**
