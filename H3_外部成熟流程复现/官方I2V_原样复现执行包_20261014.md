## 5. P2｜原版示例首跑（一个真实 MP4）
1. 备份当前可工作的 ComfyUI 环境信息；优先在原环境中先判断节点兼容性。必要升级须保留回滚，不盲装未知自定义节点。
2. ComfyUI 载入 `video_minimax_h3_i2v.json`；使用例图 `transparent_rgb_gaming_mouse.png` 替换 LoadImage 所需输入。保存一份**未改其余参数**的 `run00.workflow.json`。
3. 按官方教程放齐对应 `diffusion_models`、`text_encoders`、video/audio VAE、模板要求的 LoRA 文件。模板期望的文件名：`minimax_h3_fl2va_pruned_int8_convrot.safetensors`、`qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`、`minimax_h3_video_vae_int8_convrot.safetensors`、`minimax_h3_audio_vae_fp32.safetensors`、`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`。
4. 不改示例 prompt、seed、step、尺寸、时长，提交**一次**。队列忙则等待；不能并发运行旧的《黎黎隆》任务。
5. 获取真 MP4、工作流 JSON、ComfyUI log、模型文件实际列表和版本、输入和输出 SHA256、ffprobe 实测 fps、帧数、宽高、时长、音轨及实际运行耗时。抽取首/中/尾帧用于人工质量判断。不得把“出现 MP4”直接当图像质量过审。

检测 MP4（若已安装 ffprobe/ffmpeg）：
```powershell
ffprobe -v error -show_entries format=duration:stream=index,codec_type,codec_name,width,height,r_frame_rate,nb_frames -of json "PATH_TO_OUTPUT.mp4"
Get-FileHash "PATH_TO_OUTPUT.mp4" -Algorithm SHA256
# 抽帧时间点须依照 ffprobe 的实际总时长设置
```

## 6. P3｜严格依次升级，不提前变更
**前提**：P2 实测完整，有渲染 receipt，非黑屏/单帧、可播放、有真实画面变化。

- `RUN01`：仅在 P2 原样示例成功后，单独将输出调为 **16:9，1344×768**，官方默认采样方案其余尽可能不变，仍用同一示例图。记录与 P2 唯一改动（若自动耦合的分辨率参数有多项，一并登记）。不通过则定位单一问题。
- `RUN02`：仅 RUN01 PASS 且 RAM/VRAM/运行时确认可行后，再把时长提升到接近用户目标，按 H3 官方 **17k+5 帧 / 24fps** 原生网格：**345f=14.375s**；348f=14.5s 只是数学目标，不是已证原生合法值。若希望最终 14.5 秒，仅可单独后期处理并标 EDITED，绝不冒充原生帧数。
- Turbo 8-step / R2V / ControlNet / 自定义图像只在上面稳定且 USER 明确选择下一阶段后开新阶段，不算本轮 PASS 条件。

## 7. 审计交接与停止条件
每轮只写一份简短 receipt：`stage, source_url, source_blob_sha, input_sha256, model_names_revisions, comfyui_version, GPU/RAM, workflow_sha256, seed, steps, width, height, fps, frame_count, duration, output_sha256, output_path, render_time, video_ok, audio_ok, first_mid_end_refs, error_log, changed_variable, verdict, next`。
- `TECH_PASS`：本机真实执行且元数据/视频/抽帧齐备，肉眼无明显严重失败。审美喜欢与否另由 USER 决定。
- `FAIL`：渲染有输出但内容不合格；最多做有证据的一次单变量修正，不盲目循环。
- `WAIT_RUNTIME` / `WAIT_DOWNLOAD` / `WAIT_GPU`：执行条件不具备；每小时检查新增 receipt 即可，不反复编故事。
- `DONE`：P2+P3（至少 RUN01）拥有真实可复核成功样片以及明确的运行参数；RUN02 可标 CONDITIONAL / BLOCKED 不掩盖。
- `STOP`：连续两个小时同一阻塞且无恢复途径，或两次单变量修正无改善，停止自动派发 GPU；只保留等待条件。**没有 LOCAL_RUN_RECEIPT 就不称已复现**。
