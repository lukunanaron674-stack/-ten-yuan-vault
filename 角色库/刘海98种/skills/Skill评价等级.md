# Skill评价等级 v1.0

Skill等级评价的是**系统关键性、失败代价、复用范围与约束强度**，不是文档写得长不长，也不是作者自我感动程度。人类很爱给文件贴“核心”标签，本制度负责让这个词稍微值点钱。

## S级｜系统根基

### 定义

一旦失败，会污染后续多个阶段或整个资产库；必须采用失败关闭、来源追溯、强审计与版本治理。

### 必须满足

- 是多个下游流程的共同输入；
- 错误会级联污染名称、分类、映射、图像或创作；
- 有明确硬失败条件；
- 输出可追溯到来源、日期和执行记录；
- 必须保留历史版本与纠偏记录；
- 不允许在证据不足时凑数完成；
- 可跨角色库、场景库或图鉴库复用；
- 有量化质量门槛和复核机制。

### 当前S级

- `S级_真实参考图片采集`：所有视觉分类与映射的证据入口；
- `刘海98种角色视觉词库建库`：名称、结构、十元与Canvas的总编排器。

## A级｜核心生产

承担一个稳定领域的主要生产任务。失败影响当前项目或当前资产库，但不会自动污染多个理论层。

要求：字段完整、流程可重复、失败可发现、结果可复核。

示例：统一角色刘海重绘、角色三视图标准化、单一角色库批量建卡。

## B级｜重要辅助

提升效率、格式或可读性。失败会增加返工，但不会改变核心结论。

示例：Canvas自动排版、文件名规范化、图片尺寸检查、批次进度汇总。

## C级｜实验能力

规则尚未稳定，允许探索与失败，不得覆盖正式资产。

要求：独立目录、实验状态、不得自动晋升为权威来源。

## D级｜临时工具

一次性迁移、修补或短期脚本。任务完成后应归档或删除，禁止长期冒充正式Skill。

## 等级与成熟度分离

等级高不代表版本成熟。

例如：

- `S级 + v0.1`：极其重要，但仍在实验，必须限制写入；
- `S级 + v1.0`：重要且规则稳定，可作为正式强约束；
- `B级 + v3.0`：辅助工具非常成熟，但仍不是系统根基。

因此Skill元数据必须同时记录：

```yaml
skill_grade: S|A|B|C|D
version: x.y.z
status: experimental|active|stable|deprecated
failure_mode: fail-closed|fail-open
canonical: true|false
```

## 升降级规则

### 升级

满足以下条件可升级：

- 被至少两个下游流程稳定调用；
- 已有失败案例与防错规则；
- 输出字段稳定；
- 可在新项目复用；
- 通过一次完整审计。

### 降级

出现以下情况必须降级或停用：

- 依赖不可追溯来源；
- 结果主要依靠临时聊天记忆；
- 没有硬失败条件；
- 与其他Skill职责重叠且边界不清；
- 多次造成资产覆盖、重复或伪完成。

## S级变更纪律

S级Skill修改必须：

1. 写明变更原因；
2. 保留旧版本或变更记录；
3. 列出受影响下游；
4. 更新验收清单；
5. 回读确认文件存在；
6. 不得静默削弱硬约束。
