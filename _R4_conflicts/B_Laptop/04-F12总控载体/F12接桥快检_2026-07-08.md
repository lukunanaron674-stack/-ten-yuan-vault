## 一句话结论

接桥不是只看 localhost 活着，而是要同时确认：

1. 本地桥在线。
2. Edge 扩展有心跳。
3. 页面池里至少有一个 `online` 页面。
4. 目标页不是旧 tabId。
5. 任务发送前先确认工蜂能接收命令。

如果 `status` 显示桥在线，但 `multi-status` 全部是 `offline`，说明桥接上了，但没有可操作页面。此时必须打开或刷新 ChatGPT / LazyMan 页面，让页面工蜂重新注册。

## 全部 offline 怎么办

这是 2026-07-08 实测遇到的状态：

- 本地桥在线。
- 扩展版本能读到，例如 `Ten Yuan F12 Controller v1.4.1`。
- 但 `multi-status` 页面池全部 `offline`。

处理：

1. 让用户打开 Edge。
2. 打开或刷新一个 ChatGPT / LazyMan 页面。
3. 等 3-5 秒，让 content worker 注册。
4. 再跑：

```powershell
node C:\Users\19308\.codex\skills\ten-yuan-f12-operator\scripts\f12.js multi-status
```

只要出现 `online` 页面，就可以继续绑定、载入、发送。

## 不要做的事

不要把“桥在线”误判成“F12 可跑”。

不要使用几天前的旧 `tabId` 直接发任务。电脑重启、Edge 重开、页面刷新后，旧 tabId 通常已经失效。

不要在全部 offline 时继续 `multi-load` / `multi-auto`，这只会写一堆失败命令。

不要优先尝试点 Edge 边栏 UI。Codex 的稳定路线是本地桥命令。
