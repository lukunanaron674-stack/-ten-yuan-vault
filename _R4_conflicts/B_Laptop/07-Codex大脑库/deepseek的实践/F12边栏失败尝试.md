# F12 边栏失败尝试

## 目标

通过 F12 侧边栏（十元 F12 总控塔 v1.1）操控 Edge ChatGPT 标签页，让 ChatGPT 分析命运型三部作品的主角三元。

## 尝试路径

### 1. CLI 模式（半成功）

- 通过 `f12.js` CLI 重置 / 加载 / 发送任务
- 任务文件 `tasks_sanyuan.txt` → 单轮，提示词简洁
- 问题：内容脚本频繁断开，ChatGPT 标签页刷新后工蜂失联
- 17 轮大任务跑通了，但单轮小任务反而卡在 `carry_packet_due`

### 2. CDP 远程调试（失败）

- 用 `--remote-debugging-port=9222` 启动 Edge
- 通过 WebSocket 连接 DevTools Protocol
- 尝试 `Runtime.evaluate` 点击侧边栏按钮
- 结果：Node WebSocket 超时，未能建立稳定连接

### 3. 侧边栏直接操作（未达成）

- 侧边栏 UI 有完整的多标签页面池、绑定/注入/自动跑按钮
- 但无法通过外部脚本点击扩展侧边栏的 DOM
- 需要用户手动在 Edge 侧边栏操作

## 根因

| 问题 | 根因 |
|------|------|
| 内容脚本断开 | ChatGPT 页面刷新 → 工蜂注入失效 |
| CDP 超时 | Node 原生 WebSocket 与 Edge DevTools 握手不稳定 |
| 侧边栏不可脚本化 | 扩展侧边栏是独立上下文，外部 CDP 需先 attach 到扩展 target |
| 任务提示词约束过多 | ChatGPT 需要呼吸空间，不应预设输出格式 |
| TASK_DONE 不应在 prompt 中 | 会被内容脚本误判为已完成（来自 v0.5.0 研究报告） |

## 教训

1. **CLI + 桥 + 用户手动刷新 ChatGPT 页** 是目前唯一稳定路径
2. **侧边栏是监控面板，不是脚本入口**——它读桥状态，但不适合被外部脚本点击
3. **提示词越短越好**——给方向，不给模板
4. **单轮任务用 `send`，多轮用 `auto`**，中间态用 `resume` 过 carry_packet
5. **工蜂注入是脆弱环节**——每次页面变动都可能断连

## 未归档补充发现

### 租约锁架构

- F12 使用全局租约锁（`lease-lock.js`，2分钟默认），同一时间只有一个标签能执行
- 这不是 bug，是保护——ChatGPT 有频率限制，并行轰炸会一起被限
- 多标签页面池已支持注册和独立管理，但执行是排队而非并行

### C/D 框混跑问题

- 同一 ChatGPT 标签页混合不同框类型的任务会污染上下文
- 解决方案：拆成两个标签页，各自加载任务，排队执行
- 侧边栏页面池可视化选择标签，但实际操作仍需 CLI 配合

### CarryPacket 机制

- 每 5 轮触发 `carry_packet_due`，自动暂停等待记忆承载包生成
- 17 轮跑通证明：细粒度任务 + 每轮 1-2 部作品 → 不再超时卡死
- `resume` 命令可跳过 carry_packet_due 继续

### 工蜂注入脆弱性

- 内容脚本（工蜂）在 ChatGPT 页面刷新后失效
- 需要手动在侧边栏点「💉 手动注入工蜂」或 CLI `inject`
- 自动检测+自动重注是下一步优化方向

### 提示词设计原则（来自 vault 经验文件）

- TASK_DONE 标记不应出现在用户 prompt 中
- 完成检测应基于 assistant 增量文本 + UI idle + quiet window，而非全页扫描
- 提示词越短越好，给方向不给模板
