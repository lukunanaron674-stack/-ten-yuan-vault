# 制作产业与版权｜R6

## 1. 本章总判断

职业漫画生产是一套把创作意义、对象资产、人员劳动、平台界面、合同权利、时间流程和收益代价持续组织起来的十元系统。

```text
企划与作者方向
→ 分镜、作画、背景、色彩、字效等生产对象
→ 编辑、团队和平台组织流程
→ 校对、审核、交稿和修改形成节点
→ 作品进入发行、宣传、付费和改编界面
→ 权利、署名、收益和风险重新分配
```

“画完”只证明文件存在，不证明项目已经完成。剩下的权利、责任、交付和身体代价依然会准时出现，比某些团队成员还可靠。

## 2. 生产管线的十元结构

| 环节 | 十元知识任务 |
|---|---|
| 企划 | `zn`创作意义、`x`项目边界、目标对象与五维承诺 |
| 分镜 | 端点、行为、回应、体量和顺序可读化 |
| 作画 | 身体、对象和关系机制显影 |
| 背景 | 空间权限、路线、承载与危险条件 |
| 色彩 | 信息、观看中心、身份界面和阶段显影 |
| 字体气泡 | 阅读`xn`、声音界面`x并z`和确认节点`z` |
| 校对 | 事实、连续性、授权和端点一致性检查 |
| 平台规格 | 作品进入既有`x并z/xn`系统 |
| 交稿 | 阶段`z`确认和责任转移 |
| 修改 | 谁提出、谁决定、谁承担成本 |
| 宣发 | 对象可见性、归因和认可入口 |
| 权利收益 | `x`权利、`z`署名、`nx`劳动、`zx`决定与`xz`风险分配 |

## 4. 周更生产管线完全十元化

### 前期储备

- 世界、角色、地点和道具建立对象状态；
- 第一季大纲建立动态链和体量顺序；
- 库存扩大安全时间窗，降低`xz`；
- 背景、3D、笔刷、字体和色板属于可复用`x`资产与`xn`流程；
- 审核、修改和交稿节点必须明确`z`确认者；
- 每个节点标最终决策人和返工承担者。

### 单话流程

```text
节拍与端点目标
→ 文字分镜
→ 缩略分镜
→ 编辑独立回应
→ 精分镜
→ 线稿/背景/色彩/字效
→ 手机端与连续性检查
→ 校对和授权检查
→ 交稿z
→ 修改、结算、归档
→ 代价进入下一话
```

### 文件状态

`00_brief`至`10_archive`不是漂亮文件夹仪式，而是`xn`状态机。每个状态要记录：负责人、进入条件、退出条件、版本、待确认对象和返工来源。

## 5. 团队角色与十元关系

| 职位 | 主要对象 | 决策与承担 |
|---|---|---|
| 原作/编剧 | 前提、人物、世界、脚本 | `zn/x`方向和故事责任 |
| 主笔 | 人物、画风、最终画面 | 视觉`x并z`统一与质量确认 |
| 分镜 | 镜头、滚动、行为与回应 | 体量、顺序和演出路径 |
| 线稿助手 | 线稿、局部人物和道具 | 沿流程`nx`执行并反馈问题 |
| 背景 | 空间、透视、3D和连续性 | 空间对象与生产资产 |
| 上色 | 色板、光源、特效 | 视觉界面和阶段显影 |
| 字效 | 气泡、字体、拟声 | 阅读顺序和声音界面 |
| 编辑 | 项目、反馈、平台、进度 | 组织`xn`、确认`z`和入口协调 |
| 制作管理 | 排期、文件、预算、负荷 | 团队`n`承载与风险管理 |

一人兼多职时，职责仍需分开。否则所有问题最终会被归纳成一种神秘诊断：“最近状态不太好”。

## 6. 团队承载与劳动分配

团队是否形成`n`，要看它是否真实接收工作、提供内部位置、分担资源、保护成员并在外部压力下维持。

检查：

- 谁拥有最终方向`x`；
- 谁通过职位公开决定`zx`；
- 谁沿既有方向`nx`执行；
- 谁承担返工、熬夜和沟通成本；
- 谁能拒绝不合理任务和退出；
- 署名与收益是否正确归因`z`；
- 承载是否生成稳定流程`n生xn`候选；
- 公开处置是否击穿成员资格与承载`zx克n`。

## 7. 质量检查的十元化

### 故事

- 本话对象、目标端点、触发和阻力是否明确；
- 行为和独立回应是否成立；
- 主线、关系线或策略线是否至少变化一项；
- 话尾是否来自代价；
- 新信息是否改变对象意义或下一轮策略。

### 画面

- 人物、服装、道具和身份壳连续；
- 场景、路线、光源和时间连续；
- 动作有意图、接触、结果和反应；
- 手机端仍能看见主对象与变量变化；
- 3D与人物共享空间逻辑；
- 特效不吞掉回应和代价。

### 交付

- 文件名、尺寸、格式和色彩模式符合`x并z/xn`接口；
- 字体、素材、照片、3D和笔刷权利可追溯；
- 分层与最终文件均保留；
- 修改意见对应版本和责任人；
- 交付并不自动转移全部版权。

## 8. 编辑反馈与修改权

反馈分为：

1. 必须修改：事实、可读性、平台规格和合同；
2. 高价值建议：动机、结构、节奏、类型和生产；
3. 口味建议：需与目标和证据连接；
4. 冲突意见：必须明确优先级与最终决策人。

### 修改记录｜R6

```yaml
版本:
提出者及权限:
问题对象:
证据:
希望改变的端点/变量:
修改方案:
影响范围:
资源与时间成本:
谁承担代价:
作者是否有否决权:
是否采纳及理由:
结果与下一轮:
```

若掌握发表、推荐或署名入口的一方通过扣留、改署或隔离使作者无法获得正确确认，应检查`x克z`。

## 9. 平台、读者与发行

需要记录：设备、单话长度、更新、付费、等待免费、缩略图、简介、年龄规范、评论、收藏、留存、结算和本地化。

十元化理解：

- 平台界面`x并z`；
- 审核推荐结算`xn`；
- 签约排名认可`z`；
- 入口、数据和权利掌握`x`；
- 上线下架处置`zx`；
- 读者持续接收`n`和回返`nz`；
- 作者借平台做成`nx`；
- 停更、淘汰和政策变化`xz`。

所有规则附年份和官方来源。

## 10. 出版、品牌与跨媒介

纸书分页、封面书脊、印刷色、增补内容、社交媒体、展会、签售、众筹和周边，都是作品进入新`x并z`界面。

每次转换检查：

- 原对象和动态链是否被重排；
- 谁掌握新版本和宣传素材`x`；
- 署名和作品归因`z`；
- 改编方与作者的最终决定位置；
- 新收益、成本和风险由谁承担；
- 宣传是否泄露关键对象或使用无授权资产。

## 11. 权利清单的十元知识

签约前逐项区分：

- 著作权归属与实际控制`x`；
- 独家/非独家、地区、语言和期限；
- 连载、纸书、海外、影视、动画、游戏、音频和商品化界面`x并z`；
- 宣传使用权；
- 自动续约和终止条件；
- 数据与结算查阅权；
- 署名和认可归因`z`；
- 修改、完整和否决权；
- 争议解决流程`xn`与最终处置`zx`。

合同中的“拥有IP”必须拆成具体权利束，不接受一句话将整个宇宙装进口袋。

## 12. 收益结构与代价

稿费、保底、付费分成、广告、版税、海外、改编、商品、奖金和支持项目必须确认：

```yaml
收入定义:
分母:
扣除项目:
比例:
结算周期:
税务:
最低保证:
审计权:
数据查阅:
退款/坏账:
团队分配:
```

百分比只是`z`式确认数字；真正`x`在于谁定义分母、掌握数据和允许审计。分母若能自由发挥，合同就变成抽象表现主义。

版权对象的十元任务：谁掌握`x`、谁被正确归因`z`、通过什么界面`x并z`传播、流程`xn`如何核验、侵权风险`xz`由谁承担。

## 14. AI辅助的产业接口

- 记录工具、模型、日期、输入权利和人工修改；
- 检查平台、比赛、客户和合同申报；
- 检查商标、角色、签名和相似性；
- 保留重要角色、分镜和最终画面的人工决定`x/zn`；
- 不上传保密对象；
- 明确AI收益与人工清理、返工、署名和报酬；
- 具体规则按使用当天核验。

## 15. 健康、排期与真正的生产承载

记录每工序用时、返工率、可持续工时、休息、生病与设备缓冲、库存和成员负荷。

### 十元判断

- `xn`：流程是否可重复；
- `n`：团队是否真实承载成员和工作；
- `x`：成员是否拥有身体边界与拒绝权；
- `nx`：谁沿他人方向持续执行；
- `zx`：谁公开决定加班、停更和交付；
- `xz`：身体、合同和窗口是否进入临界；
- `nz`：成员是否只因不愿项目结束而放弃退出权。

长期熬夜不是制作体系，是拿未来身体做无息贷款，而且贷款机构从未同意。

## 18. 五维归纳

- 时间：排期、连载、审核、续约和结算；
- 本体：作者性、作品边界、署名和完整权；
- 空间：平台、出版、团队、工作室和发行界面；
- 因果：决策、执行、返工、承担和收益分配；
- 命运：职业窗口、停更、解约、改编、回返和身体临界。

## 19. 训练

1. 为项目写R6企划书；
2. 将单话生产流程画成端点、权限和责任状态机；
3. 为团队每个职位写决定权、执行权、拒绝权、署名和代价；
4. 模拟一组冲突编辑意见并建立最终决策协议；
5. 拆一份虚拟合同的权利束和收益分母；
6. 建立20项外部资产权利表；
7. 为AI辅助项目写申报、署名和风险流程；
8. 设计可持续周更排期，并做成员退出和生病压力测试；
9. 找一个`x克z`署名/发表入口案例和一个近邻误判；
10. 做完整交付包与上线后C模式复盘。
