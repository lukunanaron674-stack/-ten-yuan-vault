# 0｜为什么要加「能力」这一层

现状问题（已对账 20 张 MAIN 卡 + 索引 + Linear 674-116）：

1. **能力不是问题**。现有体系里「能力」只零散出现在 4 个 SUB 中（SUB-05-06 / SUB-08-07 / SUB-16-02 / SUB-18-06），从未成为独立层。
2. **能力没被验证**。能力是「能不能做到」，问题是「为什么做不到」。两者 PASS 门不同：
   - 问题 PASS 门 = 找到办法 / 找到根因
   - 能力 PASS 门 = **稳定做到，且可测、可复现、可证伪**
3. **不区分主能力和次要能力点**，就无法回答「这个 MAIN 真正要建的是哪一种能力」。

结论：能力必须是独立一层，且每个能力必须拆成 **1 个主能力 + N 个次要能力点**。主能力是「不建成就不算解决」的那一个；次要能力点是主能力的支撑项，可独立验证、独立降级。

# 1｜五层模型（正式口径）

```
L0  GOAL      目标        要达到什么状态（不是问题）
L1  MAIN      主问题      阻碍目标的什么（可观察失败）
L2  SUB       子问题      主问题的可观察分量（单变量可测）
L3  CAUSE     因果链      谁必须先成立（不是依赖偶然性）
L4  CAP       能力        要建成的「能不能做到」← 新增
L4a CAP-1     主能力      不建成则 MAIN 不算解决（唯一）
L4b CAP-n     次要能力点  主能力的支撑项（可独立验证/降级）
```

**关键区分：**

| 层 | 回答的问题 | PASS 门 | 失败时的动作 |
|---|---|---|---|
| GOAL | 想达到什么 | 状态描述 | 重定目标 |
| MAIN | 什么在阻碍 | 找到办法 | 下钻子问题 |
| SUB | 分量是什么 | 单变量可测 | 换变量 |
| CAUSE | 谁先成立 | 前置闭合 | 补前置 |
| **CAP** | **能不能稳定做到** | **可测 + 可复现 + 可证伪** | **补能力点** |

**硬规则：**

- CAP 不允许替代 MAIN。能力建成但 MAIN 未解决 → MAIN 仍 PARTIAL。
- CAP 不允许凭空新增。必须挂在某个已存在的 SUB 之下，无宿主则不建。
- 一个 SUB 最多 1 个主能力，可有 0..N 个次要能力点。
- 主能力未 PASS 时，次要能力点全为 BLOCKED（不做无意义的局部优化）。
