# RUN-20261001-0815｜H3 渲染运行经验（4090 实战复盘）

> 来源：4090 端（DESKTOP-FKEUGLS）2026-09-22 ~ 09-27 生产实战复盘。
> 状态：实测验证（每条均有对应事故/实验佐证），供 AG-07 按需回源。
> 提炼版已同步 [[../上下文提炼/CTX-07_H3]]。

## 1. 资源与实例（最致命）

- **单实例铁律**：本机 32GB RAM + 24GB VRAM，单个 H3 实例 staged ≈40.5GB（unet 20 + 文本编码器 15 + video vae 5 + audio vae 0.6），靠换页勉强撑、余量为零。**第二个实例一起加载 → 内存穿底 → 系统 OOM 静默杀掉先跑的那个**，日志末行只有 `Using RAM pressure cache.`，无 traceback。
- 诊断口诀：ComfyUI 无栈死亡 → 先数实例，再顺 ParentProcessId 爬父链定位谁启的；`Could not acquire lock on database ... comfyui.db` = 双实例铁证。
- >21GB 的单模型会挤爆内存直接死机；跑批 preflight 必须校验模型文件大小。

## 2. 启动参数

- `--use-sage-attention` **必带**（默认值，非选项；实测 2.2x 提速，画质差异非崩坏）。
- `--enable-assets`、`--enable-triton-backend` **永久禁**（会崩）。
- GGUF 量化不可用于 H3；sage 只配 BF16 pruned + UNETLoader。
- 启动器唯一权威：`D:\H3\h3_workflow\launch_h3_D.cmd`（刷机不丢，启动前强制把 yaml 写回 D 盘、以 D 输出启动）。

## 3. 模型与路径（刷机自愈）

- 模型只认 `D:\H3\models\`（pruned 三件套）；G 盘 32G 非 pruned 版禁用。
- 刷机/重启后第一件事：确认 `extra_model_paths.yaml` 的 `base_path` 指 `D:/H3/models/`（回退 `../../models/` = G 盘 → clip 读不到 → 全部任务 failed）；确认 `--output-directory` 指 D 盘。
- 30 秒确诊 G 回归：`curl -s :8188/object_info/CLIPLoader` 看不到 `qwen3vl_...nvfp4_awq.safetensors` = base_path 被拖回 G。

## 4. 帧数闸门（核心教训）

- **硬上限 264 帧 = 11s**：`len=360`(15s) 16 条仅 1 成功 15 崩；`len=240`(10s) 66 条 0 失败。崩因 = 时长超内存上限（360f staged≈40.5GB > 32GB RAM）。
- **约束维度只有【时间】**：与参考图张数无关，参考图不做限制（曾误判参考图数量为崩因，用户两次纠正）。
- 闸门已代码化：`pool_lib.append_jsonl` 自动把 `length>264` 夹到 264（写 `length_original` 留痕 + WARN）。
- 历史 360f 卡**必须降到 ≤264f 重提，禁止原样重跑**（会重启崩溃循环）。
- 崩溃先查该卡 frames 是否超限，别怪参考图 / flag / sage。

## 5. 排错纪律

- **任务 failed 先读完整 error body，不要猜模型名**：读 `queue/tasks_status.jsonl` 该任务的 `error._body` → `node_errors.<节点id>.errors[].details` 会明说哪个节点、哪个字段、值 not in 哪个列表。
- **权威源**：模板 workflow JSON ≠ 运行时 prompt；唯一权威 = ComfyUI `/history/<prompt_id>`。
- **出片判完成**：`/history` 终态 + 文件大小落定 + 池终态；「文件出现」不算数（SaveVideo 先建空壳）。
- **失败秒数定性**：~2s = 8188 未就绪（环境）；~800s/1500s = 池超时（环境）；`needs_refs` = 素材真缺。
- 环境失败可 unsee 释放重跑；**崩源卡必须 block 拉黑**（unsee 崩源卡 = 重启崩溃循环）。

## 6. 闸门陷阱（R40 实战）

- R40 闸门 = 代码 gate（`MIN_ROUND=40`）+ hold 文件**双保险**，缺一不可。
- ⚠️ **无 R 号的卡（legacy / 测试 / 新系列）会被 `card_round()` 正则返回 -1**：旧版漏过闸门导致废片量产，已修为「无 R 号一律按 pre-R40 跳过」。
- ⚠️ **反向陷阱**：新开卡系列若编号从 R001 起（如 CH-ZX-001-R001），正则会取到 1 < 40 被**误挡**——新系列需按卡名前缀白名单放行。
- 「撤销一条指令」≠「清空积压」：只动那一个开关，绝不连带清池/删卡。

## 7. 进程与调度纪律

- 本机 tasklist / wmic / Get-CimInstance 会卡死；判活只用 curl / nvidia-smi / 心跳文件。
- `os.kill(pid, 0)` 在 Windows 会真杀进程 → 判活用 ctypes `OpenProcess(0x1000)` + `GetExitCodeProcess==259`。
- `schtasks /End`、`/DISABLE` **杀不掉已在跑的 resident `--loop` python 进程**（心跳继续跳）；孤儿需 ctypes 强杀（Walk PEB 读 cmdline，`ReadProcessMemory` 必须显式设 argtypes，否则 64 位指针截断、cmdline 静默读空匹配不到）。
- 改 pool_run / relay 代码后**必须重启进程**（旧实例内存里仍是旧闸）；改代码换进程走 `_swap_when_idle.py`。
- 看门狗：`/RI 10` 必须配大 `/DU 8760:00`，否则 Repetition 窗口整体失效。
- relay 只入池、绝不 POST /prompt；pool_run --loop 是唯一提交者。

## 8. 角色与素材一致性

- 角色 id / 名称一律以 B端卡为准，不要自己看图起名（LEA-001 = MOUSE-EAR-MUTANT-001 同图的教训）。
- 鼠耳异变少女（MOUSE-EAR-MUTANT-001）设计 = **仅右耳、左耳无耳**（全视角一致，非画漏），严禁补左耳/双耳对称。
- ⚠️ 已知冲突：B端 09-25 批次 MOUSE 卡 prompt 仍写「two ears（双耳）」，与单耳设定冲突——渲染前需人工裁决。
- 参考图两道闸门：任务书声称用角色+场景参考就必须真给齐；角色不在池内 → needs_refs 不跑，绝不只挂场景图硬跑。

## 9. 一句话口诀

- 模型只认 D 盘，刷机不丢；启动前先确认 yaml base_path 指 D。
- sage 必带，assets 永禁；单实例，双实例 = OOM 静默死。

- 只跑 R40+，无 R 号当 pre-R40 跳过；新系列低号需白名单。
