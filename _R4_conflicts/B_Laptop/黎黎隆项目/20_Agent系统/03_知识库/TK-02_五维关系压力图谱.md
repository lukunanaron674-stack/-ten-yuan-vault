# TK-02｜五维关系 / 压力图谱 v1.0

> 第二轮目标：把 canonical 的正式生克方向转成主题 Agent 可执行的“关系启动—压力证据—反例排除”流程。
> 本文件不新增生克方向，不修改 canonical，不引入电影机制卡。

## 0｜正式关系只认 canonical

### 生环
```text
空间 → 时间 → 命运 → 因果 → 本体 → 空间
```

### 克环
```text
空间 → 命运 → 本体 → 时间 → 因果 → 空间
```

主题层正式关系只有：

```text
n = 生
x = 克
```

禁止在主题生克盘中自行增加 `z = 补`。补合属于五大主题生成系统，不属于主题间生克关系。

---

## 1｜关系启动四问

Agent 只有同时回答以下四问，才允许输出 `dimension_relation`：

1. **源主题是什么？**
2. **目标主题是什么？**
3. **源主题具体改变了目标主题的哪个变量？**
4. **这个改变在哪里进入关键转折、重大选择、高潮或结局？**

标准句：

```text
【源主题】通过【具体承载对象 / 机制】
改变【目标主题】的【能力 / 边界 / 路径 / 答案】，
因此在【关键转折 / 高潮 / 结局】形成 n / x。
```

回答不了第 3、4 问，只能写：

```yaml
dimension_relation: none_confirmed
relation_status: co_present_only
```

## 2｜“生”到底怎么验

canonical 定义：

> 源主题为目标主题提供成立、展开、积累或进入下一阶段的条件。

Agent 必须找到至少一种可验证变化：

```text
目标从不能成立 → 能成立
目标从不能展开 → 能展开
目标从局部 → 能持续积累
目标从当前状态 → 被推入下一阶段
目标原本没有行动条件 → 获得行动条件
```

### 生的压力证据
- 源主题一变化，目标主题立即获得新条件；
- 删除源主题后，目标主题的关键阶段无法发生；
- 目标的变化不是“同时发生”，而是依赖源主题提供的条件。

### 生的伪阳性
- 两个主题只是同时存在；
- 同一场景里碰巧出现两个维度；
- 角色一句台词把两个概念连在一起；
- 十元层发生“生”，于是倒推主题层也一定“生”。

---

## 3｜“克”到底怎么验

canonical 定义：

> 源主题压缩、限制、改写或破坏目标主题能够继续成立和展开的条件。

Agent 必须找到至少一种可验证变化：

```text
目标能力下降
目标边界被压缩
目标路径被关闭
目标原有答案被迫改写
目标无法继续展开
目标必须换一种存在方式才能继续
```

### 克的压力证据
- 源主题越强，目标主题可行空间越小；
- 删除源主题后，目标限制明显解除；
- 目标不是“变得更痛苦”，而是其结构能力真的下降或被重写。

### 克的伪阳性
- 单纯失败、受伤、悲剧、争吵；
- 两个主题立场相反；
- 角色讨厌某个空间 / 时间 / 身份；
- 视觉上很压迫；
- 十元层某对象发生克制，于是偷换成主题层克制。

## 4｜五条正式生关系：Agent 压力检查表

> 以下是“检查问题”，不是对所有作品都自动成立的唯一机制。

### 4.1 空间 生 时间
核心检查：

```text
某种位置 / 容纳 / 边界 / 共处结构
是否为持续、积累、阶段推进提供了必要条件？
```

Agent 可查：
- 没有这个空间，某段关系 / 行为是否无法持续足够久？
- 进入 / 留在 / 返回某空间，是否让变化进入新阶段？
- 空间是否保存了重复、积累或等待发生的条件？

成立时写：
```text
空间条件 → 时间展开条件获得
```

禁止偷懒：
“在一个房间里待了很久”不自动等于空间生时间。

### 4.2 时间 生 命运
核心检查：

```text
阶段、持续、积累、期限或不可逆节点
是否让可走路径逐渐打开 / 关闭 / 收束？
```

Agent 可查：
- 时间积累后，选择是否少了？
- 某个阶段到来后，原本不可行的去向是否变得可行？
- 延迟 / 期限是否改变 Returnability 或 Option Count？

成立时写：
```text
时间推进 → 命运路径结构被生成 / 推入下一阶段
```

### 4.3 命运 生 因果
核心检查：

```text
某种路径收束、去向压力或“未来将如何”
是否反过来生成当前的行动理由、解释链或责任链？
```

Agent 可查：
- 因为只剩某条路，人物是否开始采取此前不会采取的行动？
- 对未来去向的判断，是否启动新的 Cause → Action → Consequence？
- 路径收束是否迫使人物重新分配责任或行动优先级？

成立时写：
```text
命运路径条件 → 新因果链获得启动条件
```

### 4.4 因果 生 本体
核心检查：

```text
行动、来源、责任、后果或因果解释
是否成为“它究竟是什么”的新证据？
```

Agent 可查：
- 某个行动 / 后果是否改变自我定义或公共身份？
- 接受 / 拒绝责任是否改变人物如何理解自己？
- 新的来源证据是否迫使身份判断更新？

成立时写：
```text
因果证据 → 本体解释获得新条件
```

### 4.5 本体 生 空间
核心检查：

```text
“它是谁 / 属于谁 / 算什么”
是否决定它能进入、占据、离开或共享哪些空间？
```

Agent 可查：
- 身份改变后，空间许可是否改变？
- 归属确认后，是否获得位置 / 返回权 / 容纳资格？
- 本体边界是否直接生成新的空间边界？

成立时写：
```text
本体定义 → 空间位置 / 权限条件生成
```

## 5｜五条正式克关系：Agent 压力检查表

### 5.1 空间 克 命运
核心检查：

```text
位置、边界、进入 / 返回资格
是否真实压缩或改写人生路径？
```

canonical 已明确最低启动线：
- A：只是休息 / 暂留，不启动；
- B：真实人生分叉因空间条件而改变，正式启动；
- C：空间条件成为高潮 / 结局中心条件，强显影。

必须能指出：
```text
空间条件改变 → P_reachable / Returnability / 去留选择改变
```

### 5.2 命运 克 本体
核心检查：

```text
路径被锁定、未来范围收窄或不可逆结果
是否压缩人物“还能成为谁”的范围？
```

Agent 可查：
- 固定去向是否让某些身份不再可维持？
- 不可逆结果是否让人物只剩单一自我解释？
- 未来路径关闭是否破坏某个本体持续成立的条件？

必须能指出：
```text
命运收束 → 本体可持续范围下降 / 本体答案被迫改写
```

### 5.3 本体 克 时间
核心检查：

```text
身份、核心性质、归属或自我定义
是否阻止变化进入下一阶段？
```

Agent 可查：
- “我就是这种人”是否成为拒绝改变的结构条件？
- 身份义务是否把人物锁在旧阶段？
- 某个本体边界是否让时间积累无法转化为真正更新？

必须能指出：
```text
本体边界 → 时间阶段转换 / 变化能力受限
```

### 5.4 时间 克 因果
核心检查：

```text
时间流逝、延迟、上下文丢失、期限
是否让原因更难追溯、责任更难确认或行动链无法完成？
```

Agent 可查：
- 证据是否随时间消失？
- 行动窗口关闭后，因果链是否无法验证 / 修复？
- 变化速度是否超过 Cause Model 建立速度？
- 长期延迟是否把行动与后果切断？

必须能指出：
```text
时间结构 → Cause Access / Reliability / Repairability下降
```

### 5.5 因果 克 空间
核心检查：

```text
某个行动 / 后果 / 责任链
是否直接改变谁还能在哪里存在、进入、停留或返回？
```

Agent 可查：
- 某行为是否导致驱逐、封锁、隔离或失去位置？
- 某后果是否破坏原有共处条件？
- 新因果证据是否改变空间许可 / 边界？

必须能指出：
```text
因果结果 → Access / Exit / Return / Coexistence受限或重写
```

## 6｜关系强度只做工作量，不改 canonical

主题关系的“强弱”仅供 Agent 决定是否值得写进当前场次，不创造新的关系种类。

### R0｜未启动
```text
只共现；无方向作用。
```

### R1｜局部启动
```text
一次明确转折中，源主题改变目标变量；
影响局部选择，但尚未组织主线。
```

### R2｜持续启动
```text
多阶段重复作用；
持续改变目标的能力 / 边界 / 路径 / 答案。
```

### R3｜结局级启动
```text
关系进入高潮 / 结局；
拿掉该关系，作品最终答案必须改写。
```

注意：
- R0–R3 是 Agent 工作标记，不是 canonical 新等级。
- “强”不等于“主主题”；主次仍按显影协议判断。

---

## 7｜关系判定的删除测试

对任何 `A n B` 或 `A x B`，Agent 必须问：

```text
如果保留 A 和 B，但删除“A 对 B 的方向性作用”，
关键选择 / 转折 / 高潮 / 结局是否仍基本一样？
```

- 若 **一样**：只是共现，不成立关系。
- 若 **必须重写**：关系成立候选。
- 若只有局部变化：R1。
- 若主线持续变化：R2。
- 若结局答案变化：R3。

## 8｜标准 relation 输出

```yaml
dimension_relation:
  source: 空间|时间|命运|因果|本体
  target: 空间|时间|命运|因果|本体
  canonical_type: n|x
  status: confirmed|candidate|co_present_only
  target_variable_changed: ""
  carrier:
    character: ""
    action: ""
    state: ""
    scene_or_space: ""
    temporal_structure: ""
  decisive_change: ""
  evidence_level: R0|R1|R2|R3
  counterfactual_delete_test: ""
  canonical_ref: ""
```

只有 `status: confirmed` 才能写入正式主题 delta。
`candidate` 交 THEME_AUDIT 或后续剧情验证。
`co_present_only` 不输出为生克结论。

## 9｜第二轮门禁

- 必须先通过 TK-01，确认主题本身成立，再判断关系。
- 关系方向只能来自 canonical，不允许按感觉反向。
- 两主题同时出现 ≠ 生克启动。
- 十元层生克 ≠ 主题层生克。
- “更惨 / 更紧张 / 更压迫” ≠ 克；必须改变目标结构能力。
- “帮助了 / 鼓励了 / 提供信息” ≠ 生；必须提供目标主题成立、展开、积累或进入下一阶段的条件。
- 本轮不调用 R30–R46 电影机制；第三轮再蒸馏。
