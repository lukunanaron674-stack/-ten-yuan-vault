# 生克补动态链每小时执行门禁 v1.2

> 本协议只治理执行事务，不修改任何研究结论。v1.2把“案例证据提交”和“累计/断点封账”拆开，避免案例已经落库、账本却还在半空中练杂技。

## 1. 固定断点
滚动中枢必须预先写定：`previous_case_path`、`next_priority_film`、`next_priority_clip_key`、`next_priority_case_path`、`next_priority_question`。运行时不得二选一、改键、改路径或换片段。

## 2. slot、attempt与幂等
```text
slot_id = scheduler_task_id | Asia/Taipei YYYY-MM-DD-HH | next_priority_film | next_priority_clip_key
attempt_id = slot_id | starting_main_sha | retry_sequence
```
幂等只按slot_id。账本已有同slot `VERIFIED_SUCCESS`时执行`IDEMPOTENT_SKIP`，不分析、不写Git、不加计数。

## 3. 状态
`READY / RUNNING_REAL / CASE_COMMITTED_AWAITING_FINALIZE / VERIFIED_SUCCESS / IDEMPOTENT_SKIP / LEASE_HELD_BY_OTHER / CONCURRENT_REBASE_REQUIRED / CONCURRENT_RESTART_REQUIRED / RECOVERY_REQUIRED / BLOCKED_MISSING_SOURCE / BLOCKED_ATOMIC_WRITE_UNAVAILABLE / BLOCKED_WRITE_PERMISSION`。

## 4. 第零提交：租约
任何研究前，先用唯一账本当前blob单文件写入`RUNNING_REAL`与`active_lease`：slot、attempt、owner、开始时间、120分钟到期时间、retry_sequence、starting_main_sha。提交后回读owner/slot/attempt完全一致才取得执行权。有效租约存在时，其他触发器不得改动态链文件。

## 5. 强制必读
取得租约后读取中枢列出的信息卡、准度卡、生克补卡、核心表、专项索引、方法修正、模板、总索引和`previous_case_path`精确案例。涉及z必须读取现行z信息卡。`001-概念的定义.md`及旧`z切分焦点+x现象集合`只作legacy evidence。缺文件时写`BLOCKED_MISSING_SOURCE`并释放租约。

## 6. 第一提交：只提交案例证据
第一提交只创建或更新`next_priority_case_path`，不得修改中枢、总索引或累计。案例frontmatter必须写：`slot_id`、`attempt_id`、`clip_key`、`case_status: evidence-committed-awaiting-finalize`。提交后回读案例，再单文件更新账本为`CASE_COMMITTED_AWAITING_FINALIZE`，记录`pending_case_path`和`case_commit_sha`，租约继续保留。

## 7. 第二提交：原子封账
重新读取最新main、中枢、总索引、账本、案例和lease owner。确认pending案例属于当前slot/attempt后，使用：
```text
create_blob
→ create_tree(base_tree=latest_main，包含中枢+总索引+账本)
→ create_commit(parent=latest_main)
→ update_ref(force=false)
```
同一原子commit中：
- 中枢推进`previous_case_path`、下一固定film/clip_key/case_path/question与累计；
- 总索引登记案例和累计；
- 账本登记同slot `VERIFIED_SUCCESS`、案例提交SHA、七项置信度、累计变化，清空pending/current/lease并恢复`READY`。
账本可写`finalization_commit_ref: SELF`，实际SHA以提交后回读为准。

## 8. 并发
无关main推进而动态链目标和owner未变时，记`CONCURRENT_REBASE_REQUIRED`并在最新base重建。案例、中枢、索引、账本或owner变化时记`CONCURRENT_RESTART_REQUIRED`，不得覆盖。

## 9. 恢复
若案例已提交但未封账，租约过期后必须复用`pending_case_path`和`case_commit_sha`，禁止重建案例或重复计数。维护任务只能复核既有案例并完成原子封账。

## 10. 成功门
只有同slot在唯一账本中为`VERIFIED_SUCCESS`，且原子封账commit及中枢、索引、账本全部回读一致，才能汇报成功。任何失败必须写原因、释放租约；不允许永久`RUNNING_REAL`。
