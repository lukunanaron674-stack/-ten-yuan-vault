## 1. 执行权、slot与租约

```text
slot_hour = Asia/Taipei 的 YYYY-MM-DD-HH
slot_id = scheduler_task_id | slot_hour | next_priority_film | next_priority_clip_key
attempt_id = slot_id | starting_main_sha | retry_sequence
```

1. 幂等只按slot_id；手动、自动、维护补跑命中同slot时只能有一个成功结果。
2. 研究前必须先以账本单文件提交抢占120分钟租约，状态写`RUNNING_REAL`。
3. 租约提交后必须回读owner、slot、attempt完全一致，才允许读取材料并形成研究结论。
4. 同slot或其他slot存在未过期租约时，返回`LEASE_HELD_BY_OTHER`，不得并发写研究文件。
5. 过期租约恢复时`retry_sequence + 1`，先核验是否已有案例、提交或累计，禁止重复写入。
6. 第一研究提交后中枢最多写`AWAITING_LEDGER_VERIFY`；最终成功只由账本封账提交确认。

允许状态：

```text
READY / LEASE_CLAIMING / RUNNING_REAL / AWAITING_LEDGER_VERIFY
VERIFIED_SUCCESS / IDEMPOTENT_SKIP / LEASE_HELD_BY_OTHER
CONCURRENT_REBASE_REQUIRED / CONCURRENT_RESTART_REQUIRED / BLOCKED_*
```

## 2. 端点与关系方法

```text
对象、主体、阶段与对象层明确
→ 信息卡回答端点是什么
→ 准度卡完成必要条件、最近邻、拿掉与反向
→ 生卡/克卡/补卡确认关系类型
→ 十元生补克表与专项索引确认机制状态
→ 只登记直接关系边
→ 间接路径、条件节点、失败边另记
→ 单一核心变量与动态类型
→ 后验比较
```

红线：

- 生：目标此前不存在或不足，源提供核心变量净增量。
- 克：目标关系前真实存在，源使其资格、核心变量或运行能力下降；普通阻碍不算。
- 补：两端独立成立，目标原有真实缺口，补源补入对应变量；允许跨十元位置。
- 勇敢、成长、压迫、规则、爱、自由、真相、希望、怀疑、觉醒、角色名、场景、单个动作、演技、聪明、胜诉不得直接当端点。
- 共现、帮助、先后、通关、离场、攻击、胜利、获释、回家与团聚不得直接判关系。
- 若结构为`A生C→C克B`，只登记两条直接边，不再登记“A间接克B”。
- 链尾总体效果不得倒写成首尾直接关系。
- 每片只设一个核心被改变变量；其他后果作展开指标。
- 每片先标改变、崩坏、维持、循环或替换；动态类型不是新十元关系。
- 体量分别记录影响范围、持续时间、不可逆程度，不做固定权重平均。
- 每片至少记录一个正式失败候选。

## 3. 确认与严格x克z

- 确认按主体、内容、证据状态、采用范围、成立阶段分账；禁止z0—z4。
- 个人判断、机构采用与客观事实分开；`z_right/z_wrong`只是正确性注记。
- 严格`x克z`必须有明确主体主动控制必要确认入口，并限定主体、内容、采用范围和阶段。
- 自然漏登、无人目击、搜查无果、诱导询问、确认偏差、传播和程序惯性不足以成立严格`x克z`。
- 只控制自我呈现，而机构仍有物证、专家反鉴别和审查入口时，优先检查`x生x并z→x并z生z_wrong`，不得写“表演克真相”。
- 错误来源按制造型、转译型、缺证型、惯性型分账。
