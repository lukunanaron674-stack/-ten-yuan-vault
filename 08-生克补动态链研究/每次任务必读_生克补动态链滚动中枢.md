## 1. 三层结构

```text
关系对子：谁生谁、谁克谁、谁补谁。
动态链：多个真实成立的关系对子按阶段连接。
通用母型：同一抽象动态链在多个独立、跨题材案例中稳定复现，且链序和被改变变量同构。
```

影片名、人物名、场景名和剧情梗概只能作为案例证据。M-001A至M-032均为`legacy-case-chain`。

## 2. 具体积累格式

```text
人物/团队与阶段
+ 人物/团队行为
+ 具体源名词及十元位置
+ 关系对子
+ 具体目标名词及十元位置
+ 为什么成立
+ 被改变变量
+ 拿掉测试
+ 反向测试
```

行为负责关系发生与显影；具体名词固定两端。端点先写`z切分焦点+x现象集合+十元位置锚+稳定本体/当前状态+体量/阶段`。

## 3. 生克补口径与红线

- 生：源为目标核心变量提供净增量，目标此前不存在或不足。
- 克：目标核心变量、成立资格或实际运行能力下降，不是普通阻碍。
- 补：恢复目标此前真实缺失的核心变量，不是帮助、陪伴或资源共现。
- 动态链只连接通过人物行为、具体名词、变量、拿掉与反向测试的对子。
- 勇敢、成长、帮助、压迫、规则、爱、自由、真相、希望、角色名、组织名、单个动作、场景与镜头不得直接当端点。
- 资源、设备、权限、数据、模型、样品、器件、技术和专业结果首先检查`x`。
- 身份、资格、岗位、名单、许可证、合约、论文、专利、标准、正式报告、图纸和技术包首先检查`x并z`。
- `x生x并z`只生可识别、可调用、可核验的资源/资格/成果壳，不直接生确认或最终成功。
- `x并z生z`必须证明壳使特定人物、结果、资格或技术获得明确归因确认。
- `z补xn`必须证明确认给既有程序补入参与者、对象、材料标准、期限或节点。
- 科研工程案例必须分开`x并z生z`与`xn补z`：正式壳提供识别归因接口，验证程序提供跨时间证据。
- 专利壳存在不等于科学确认、工程可靠性确认或产业采用确认；三者必须分阶段记录。
- 确认存在不等于研发、采购、许可或制造程序已经改线。
- 不要求每个案例机械凑齐主克、主补、主生；没有A级主克必须明确写无。

## 4. 通用母型状态

### UM-004｜资源/能力/成果正式化—目标/资格确认—程序聚焦

```text
x生x并z → x并z生z → z补xn
```

- 状态：`locked-general-archetype`。
- 当前支持7次：《赎金》《疾速追杀2》《查理和巧克力工厂》《隐藏人物》《点球成金》、青霉素、晶体管现实历史案例。
- 同构变量：真实资源、能力、权限、模型、样品、器件、技术或结果掌握→正式可识别、可调用、可核验的壳→特定主体、资格、结果或技术获得明确确认→既有程序获得对象、标准、参与者和节点。
- 严格边界：壳必须有真实内部内容；确认必须写清主体、对象、内容和重要位置；既有程序必须先有真实缺口；最终成功不能倒补中间链段。
- 科研工程附加红线：论文/专利/标准壳与验证程序分账；专利权利确认不替代技术可行性和产业采用确认。

### C-002

- 链：`z补xn → xn生xz → zx克n → n克xz`。
- 支持1次：《疾速追杀3》。
- 状态：`specific-chain-candidate-1`，仍缺异题材复现。

### 用户惯用母型候选

```text
1生2 → 2生3
背景关系：1克3
中介2使1不再直接落向3，而以3可接收的变量形式进入
末尾增加一条补关系，修复链条真实缺口并稳定整体
```

调用要求：
1. 必须先从固定十元位置表证明`1生2、2生3、1克3`同时成立，不能用任意编号做修辞。
2. 具体案例以人物行为为主体，说明2究竟转换了什么变量。
3. 基础`1克3`并未从位置表消失，只是在该阶段被中介路径改写。
4. 末尾必须写明谁补谁、原缺口是什么、补后哪项变量恢复。
5. 目前只是用户确认的惯用结构，尚未建立案例支持编号或UM编号。
