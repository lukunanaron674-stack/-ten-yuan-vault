```text

```

`001-概念的定义.md`为`legacy-evidence-only`；旧“z切分焦点+x现象集合”不得生成、替代或证明现行端点。缺少任一强制文件、精确上一案例路径或可用账本，不得提交新影片结论。

## 1. 执行状态与幂等

```text
slot_id = scheduler_task_id | YYYY-MM-DD-HH | next_priority_film | clip_key
attempt_id = slot_id | starting_main_sha | retry_sequence
```

- 幂等只按slot_id；同一小时手动与自动触发不得重复。
- 账本已有同slot且`VERIFIED_SUCCESS`时执行`IDEMPOTENT_SKIP`。
- 第一研究提交中的本文件最多写`AWAITING_LEDGER_VERIFY`。
- 唯一账本是最终成功权威；封账前不得增加同一slot累计两次。
- 状态只允许：READY / RUNNING_REAL / AWAITING_LEDGER_VERIFY / VERIFIED_SUCCESS / IDEMPOTENT_SKIP / CONCURRENT_RESTART_REQUIRED / BLOCKED_*。

## 2. 端点与关系方法

```text
对象、主体、阶段与对象层
→ 信息卡回答端点是什么
→ 准度卡完成必要条件、最近邻、拿掉与反向
→ 生卡/克卡/补卡确认关系类型
→ 核心表与专项索引确认机制状态
→ 只登记直接关系边
→ 间接路径、条件节点、失败边另记
→ 单一核心变量与动态类型
→ 后验比较
```

红线：

- 生要求目标从不足走向出现或持续上升；先后、帮助和显影不算。
- 克要求目标关系前真实存在且核心变量下降；普通阻碍不算。
- 补要求两端独立成立，目标有真实缺口，补源补入对应变量。
- 勇敢、成长、压迫、规则、爱、自由、真相、希望、怀疑、觉醒、角色名、场景、单个动作、演技、聪明、胜诉不得直接当端点。
- 若结构为`A生C→C克B`，只登记两条直接边，不登记“A间接克B”。
- 每片只设一个核心变量；体量分别记范围、时间、不可逆程度。
- 每片至少记录一个正式失败候选。

## 3. 确认与严格x克z

- 确认必须按主体、内容、证据状态、采用范围、成立阶段分账；禁止z0—z4。
- 个人判断、机构采用与客观事实必须分开；`z_right/z_wrong`只是正确性注记。
- 严格`x克z`必须有明确主体主动控制必要确认入口，并限定主体、内容、采用范围与阶段。
- 自然漏登、无人目击、搜查无果、诱导询问、确认偏差、传播和程序惯性不足以成立严格`x克z`。
- 只控制自我呈现而仍有独立反鉴别入口时，优先检查中间壳与错误确认，不写“表演克真相”。
