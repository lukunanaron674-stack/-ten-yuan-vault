## 1. 三层结构

```text
关系对子：谁生谁、谁克谁、谁补谁。
动态链：多个真实成立的关系对子按阶段连接。
通用母型：同一抽象动态链在多个独立、跨题材案例中稳定复现，且链序和被改变变量同构。
```

影片名、人物名、场景名和剧情梗概只能作为案例证据。M-001A至M-032均为`legacy-case-chain`。

## 2. 戏剧具体积累格式

```text
人物与阶段
+ 人物行为
+ 具体源名词及十元位置
+ 关系对子
+ 具体目标名词及十元位置
+ 为什么成立
+ 被改变变量
+ 拿掉测试
+ 反向测试
```

人物行为负责让关系发生和显影；具体名词固定两端。不得把勇敢、成长、帮助、压迫、规则、爱、自由、真相、希望、角色名、组织名、单个动作或镜头直接当十元端点。

每个端点必须先写：`z切分焦点 + x现象集合 + 十元位置锚 + 稳定本体/当前状态 + 体量/阶段`。

## 3. 生克补口径

- 生：源为目标核心变量提供净增量，目标此前不存在或不足。
- 克：目标核心变量、成立资格或实际运行能力下降，不是普通阻碍。
- 补：恢复目标此前真实缺失的核心变量，不是帮助、陪伴或资源共现。
- 动态链只连接通过具体名词、人物行为、变量、拿掉与反向测试的对子。

## 4. 通用红线

1. 共现、帮助、阻碍、先后、成功、失败、通关、离场、获救、死亡和视觉相似不等于生克补。
2. 稳定本体、状态、行为、光影、场景、时间、关系位置、显影和动态链不得互相替代。
3. 资源、设备、权限、通道、奖品、名额、赏金首先检查`x`。
4. 身份、资格、奖券、许可证、合约、目标档案与公开准入界面首先检查`x并z`。
5. 确认必须写清确认主体、对象、内容和重要位置；曝光和名声不足。
6. 程序不会自动现实生效，资源不会自动变成结果；确认与执行必须分开。
7. `x生x并z`只生可识别、可调用、可兑现或可核验的资源/资格壳，不直接生目标确认、参与者、获胜或继承。
8. `x并z生z`必须证明公开壳使特定主体获得明确目标或资格确认。
9. `z补xn`必须证明确认给既有程序补入参与者、聚焦对象、筛选标准、期限或阶段节点。
10. 随机中奖、营销曝光、购买量、媒体热度和最终获胜不得吞并资源壳、确认与程序三层。
11. 续作延续同一资源、壳、确认与程序，只记连续性或失败边界，不增加独立支持次数。
12. `zx克n`必须由具体人物公开改变接收、保护或运行边界；普通通知与建筑受损不足。
13. `n克xz`必须有实际接收、补给、隐藏、保护或冲击吸收。
14. 不要求每部影片机械凑齐主克、主补、主生；缺少A级主克时必须明确写无，而不是为了表格整齐制造关系。

## 5. 案例链与候选母型状态

- C-001：`x生x并z → x并z生z → z补xn`，暂称“资源公开化—目标/资格确认—程序聚焦”。
- C-001支持3次：《赎金》（1996）、《疾速追杀2》（2017）、《查理和巧克力工厂》（2005）。
- C-001状态：`candidate-supported-3-cross-genre`，暂不升级UM。
- C-001同构变量：实际资源掌握与处分→公开可识别、可调用、可兑现或可核验的壳→特定主体获得明确目标/资格确认→既有程序获得对象、筛选标准和阶段节点。
- C-001失败版：《疾速追杀3》资源壳、目标确认与程序均已存在，只是继续运行，不得重复累计。
- C-001剩余风险：三例仍共同依赖公开资源或资格接口；需要非奖励、非悬赏、非竞赛的制度准入案例。
- C-002：`z补xn → xn生xz → zx克n → n克xz`，支持1次《疾速追杀3》，状态` specific-chain-candidate-1`，仍缺异题材复现。

母型锁定门槛：多次独立复现、至少跨两个题材、关键对子A级证据、具体名词不同但变量与链序同构、排除题材符号与结果解释、能够指出失败版。
