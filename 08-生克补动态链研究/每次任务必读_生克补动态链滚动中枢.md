# 每次任务必读｜生克补动态链滚动中枢

> 每轮从真实断点继续，结束前原位回写。不得只在聊天里分析电影。

## 0. 强制启动顺序

```text
当前 main SHA
→ 本文件
→ 01-十元系统/001-概念的定义.md
→ 十元关系防遗忘清单
→ 十元生补克表
→ 动态链总索引与模板
→ 上一影片案例与唯一运行账本
→ next_priority_film / next_priority_question
```

缺任一项，本轮无效。

## 1. 三层结构，禁止混用

```text
第一层：关系对子
谁生谁、谁克谁、谁补谁，例如 n生xn、zx克n、xn补z。

第二层：动态链
多个真实成立的关系对子按阶段连接。

第三层：通用母型
同一抽象动态链在多个独立案例、不同题材中稳定复现，具体名词虽不同，但关系顺序和被改变变量同构。
```

影片名、角色名、场景名和剧情梗概只能作为具体案例证据，不能直接充当母型。M-001A至M-032均为历史案例链编号。

## 2. 具体积累必须以人物行为为主体

每轮每条关系必须记录：

```text
人物与阶段
+ 人物行为
+ 具体源名词及十元位置
+ 关系对子
+ 具体目标名词及十元位置
+ 为什么成立
+ 被改变变量
+ 拿掉测试
+ 反向测试
```

人物行为负责让关系发生和显影；具体名词挂在行为两端，固定源端与目标端。只写字母不算具体积累；只写名词不写人物行为与变量也不算戏剧关系研究。

## 3. 十元概念预检

每个端点必须先写：

```text
z切分焦点 + x现象集合 + 十元位置锚
+ 稳定本体/当前状态 + 体量/阶段
```

不得把勇敢、成长、帮助、压迫、规则、爱、自由、真相、希望、命运、预言、角色名、组织名、单个动作或镜头直接作为端点。

## 4. 生克补通用口径

- **生**：源为目标核心变量提供净增量；目标此前不存在或不足。
- **克**：目标核心变量、成立资格或实际运行能力下降；不是普通阻碍。
- **补**：恢复此前真实缺失的核心变量；不是帮助、陪伴、资源存在或时间自然恢复。
- **动态链**：只连接已通过具体名词、人物行为、变量和测试的对子。

## 5. 通用红线

1. 共现、帮助、阻碍、先后、成功、失败、通关、离场、获救、死亡和视觉相似不等于生克补。
2. 稳定本体、当前状态、行为、光影、场景、时间、关系位置、显影和动态链不得互相替代。
3. 设备、资源、通道、身体、武器、路线、证件、样本、赎金和赏金首先是`x`。
4. 身份、职责、职业英雄、人质、成员、谈判者、合约壳、目标档案、圣域壳与除名壳首先是`x并z`。
5. 接收、保护、补给、照护、互保、清点、返航、隐藏与反复返回属于`n`。
6. 授权、训练、检查、调查、谈判、审批、合约发布、接单、目标分发、证据组织、惩罚、整改与除名程序属于`xn`。
7. 确认与执行分开；程序不会自动现实生效，资源不会自动变成结果。
8. `xz生zx`只生成状态层或关系位置层的临时决定接口，不生专业、勇气、正确性或稳定领导本体。
9. `n生xn`必须来自持续真实负荷。
10. `xn补z`必须有跨时间证据、反馈和复核闭环。
11. `n克xz`必须实际接收、保护、补给、处理与维持。
12. 危险、创伤、恐惧和妥协不得倒写为`xz克zn`。
13. 原成员回返不是新成员吸纳；身体回到安全地点不等于全部复归。
14. 英雄壳、公众认可、获奖、媒体曝光不得倒证现场机制。

## 6. 资源公开化、悬赏、合约与撤庇红线

15. 现金、赏金、支付承诺`x`；公开悬赏/暗杀合约`x并z`；目标确认`z`；接单、筛选、路线与攻击组织`xn`；抓捕/杀伤执行`zx`；安全接收`n`，必须分账。
16. `x生x并z`只生可识别、可调用、可兑现的资源壳，不直接生目标确认、抓捕或获救。
17. `x并z生z`必须写清谁通过公开壳识别谁、识别什么；曝光和名声本身不足。
18. `z补xn`必须证明确认改变既有程序的聚焦对象、材料筛选、目标优先级、处罚对象、期限或阶段节点。
19. “有钱后很多人行动”不是完整链；必须分别证明资源、壳、确认和程序四层。
20. 既有行业网络是允许条件，不得反写成赏金生成了整个制度。
21. 合约目标确认后出现追杀，只在能回溯到统一目标、接单与兑现接口时计入链条。
22. 血誓制度约束即时拒绝时，必须排除炸屋、暴力胁迫和私人报复，才能锁`xn克zx`。
23. 大陆酒店/行业规则识别违规、关闭服务、限定时间窗并扩大全球追杀时，优先检查`xn生xz`。
24. 续作延续同一资源、合约壳、目标确认与程序，不得冒充新的独立母型支持次数。
25. 资源壳已经存在、目标已经被确认、程序只是在续作中继续运行时，C-001只登记连续性或失败边界。
26. `z补xn`用于追责链时，必须写清确认的是哪位人物、哪项行为、哪种责任，以及确认具体增加了哪些处罚对象、期限和执行节点。
27. `zx克n`用于撤庇时，必须由具体人物公开改变接收、保护或结构运行边界，并证明保护资格或运行能力真实下降；普通制度通知与建筑受损不足。
28. `n克xz`用于防守或接回时，必须有实际接收、补给、隐藏、保护或冲击吸收；武器、建筑、逃跑和暂时停火不足。
29. 同一片中程序、权能与承载可以连续换挡，但每一段必须分别记录人物行为与目标变量，不能用“系统追杀”吞并全部对子。

## 7. 案例链与母型状态

- M-001A至M-032：`legacy-case-chain`。
- C-001：`x生x并z → x并z生z → z补xn`，暂称“资源公开化—目标确认—程序聚焦”。
- C-001支持2次：《赎金》（1996）、《疾速追杀2》（2017）。
- C-001状态：`candidate-supported-2`，仍未达到UM锁定门槛。
- 《疾速追杀3》（2019）只提供连续性和失败边界，不增加C-001支持次数。
- C-002：`z补xn → xn生xz → zx克n → n克xz`。
- C-002当前支持1次：《疾速追杀3》（2019）。
- C-002状态：`specific-chain-candidate-1`，不是UM母型。
- C-002核心风险：同一影片内追责程序、撤庇权能与地方承载高度耦合，仍缺异题材复现。

母型锁定门槛：

```text
多次独立复现
+ 至少跨两个题材
+ 关键对子A级证据
+ 具体名词不同但被改变变量和链序同构
+ 排除题材符号、身份壳、单次动作和结果解释
+ 能指出失败版
```
