## 4. 最新具体动态图｜《隧道》总体临界与车内残余承载岛

```text
坍塌前隧道运输、通行与结构隔离承载 n隧道
                 ║ 坍塌与封堵（第三因素）
                 ▼ S1：总体核心功能退出
碎石压埋、路线归零、缺水缺氧与最后救援窗口 xz隧道

内部残余承载岛：
车厢与相邻稳定空腔 n局部 ─克→ 碎石直达、暴露、无法停留与持续移动临界 xz
                 │ 生
                 ▼
饮水、进食、电量与活动范围的重复生存维持程序 xn内部

资源支路：
两瓶水、生日蛋糕、手机电量与车内物品 x
                 ─允许/供给→ xn内部（不另判补）

外部程序支路：
存活、粗略位置、资源余量与结构确认 z
                 ─补→ 定位、钻探、通风、清障与调度程序 xn外部

外部接手：
救援通路、担架与医疗接收 n外部 ─克→ 被困、缺水、无稳定位置与无法离场临界 xz
```

关键结论：

- 整条坍塌隧道已经完成`n→xz`，但车厢与相邻稳定空腔仍可形成局部残余`n`。
- 两瓶水、蛋糕、手机和电量是`x`资源，不因维持生命就自动变成`n`。
- 未坍塌空隙必须真实接收、隔离危险并允许跨阶段停留，才能判局部承载岛。
- 局部承载反复承担饮水、休息、观察和等待负荷，可生成`xn`内部生存维持程序；一次躲在车里不够。

## 6. 位置变化边界

### R-MIG-02｜严格位置迁移

```text
对象连续
+ 旧位置现实关系退出或失去主导
+ 新位置变量成为运行中心
+ 新位置启动至少一条合法关系边
= 严格位置迁移
```

### R-MIG-04｜承载崩塌—临界主导

```text
同一空间原本真实接收、通行、运输或保护 n
+ 灾难后旧承载关系退出
+ 危险可达性、路线与时间窗成为运行中心 xz
= n→xz
```

### R-MIG-06｜旧承载崩塌—外部新承载接手

```text
旧对象 n→xz
+ 独立外部对象形成真实 n
+ 新n接收主体并降低xz
= 旧对象迁移与外部对象接手并行
```

### R-MIG-07｜总体崩塌—内部残余承载岛

```text
总体对象 n→xz 已完成
+ 内部局部对象仍真实接收、隔离危险并允许停留 n
+ 局部n不接管总体原有核心功能
= 总体迁移与局部残余承载并行
```

《海神号》提供大型空气泡局部岛；《隧道》提供车厢与狭小稳定空腔局部岛，完成跨域复测。

## 7. 方法更新

1. 每个案例必须先分总体对象、局部对象、资源、程序和外部接手对象。
2. `n`必须提供内部位置、接收、隔离危险、停留或返回；“里面有东西”不够。
3. 水、食物、电话、电量、工具和药品优先判`x`，不能因为有助生存就自动判`n`。
4. `n生xn`必须证明承载反复承担负荷并把一次动作沉淀为持续维持结构。
5. 最终获救、死亡或离场不能倒证中间关系边。
6. 母型仅后验比较，不参与首遍端点命名。
