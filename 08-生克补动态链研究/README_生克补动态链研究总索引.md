## 4. 最新具体动态图

### 《火星救援》Pathfinder通信片段

```text
Pathfinder硬件、坐标与操作掌握 x
              │ 生
              ↓
相机指向、字符表与坐标编码通信壳 x并z
              │ 生
              ↓
NASA对Mark存活、位置、资源与风险的操作性确认 z
       ↑ 补                               │ 补
       │                                  ↓
持续通信与核验程序 xn_A       补给、发射与救援规划程序 xn_B

并行背景：栖息舱与生命维持承载 n ─克→ 生存临界 xz
```

压缩：

```text
主链：x生x并z → x并z生z → z补xn_B
并行证据支路：xn_A补z
并行风险承载：n克xz
汇合节点：z
反馈环：无（xn_A与xn_B为不同程序）
搭桥：无
断裂：无通信壳时，操作性确认与后续程序聚焦断裂
```

关键新增：
- 通信硬件`x`、通信壳`x并z`、操作性确认`z`与两种程序`xn_A/xn_B`必须分账；
- `xn_A补z`提供持续证据，`z补xn_B`提供救援程序对象、参数与期限；
- `n克xz`是并行承载背景，不属于主链第四步；
- 本案首遍未调用母型，完成图后才发现主链与高频链同序。

## 6. UM-004当前边界

```text
x生x并z → x并z生z → z补xn
```

只允许后验使用：
1. 新案例先独立锚定节点和关系；
2. 比较时除字母链外，还要比较链序、支路、汇合、反馈、承载背景与断裂位置；
3. 同字母`xn`若具体程序、阶段或体量不同，必须分为`xn_A/xn_B`；
4. 最终成功不能倒证中间关系；
5. 《火星救援》只增加主链支持，不意味着其完整动态图与科研案例同构。

## 7. 方法修正记录

1. 节点是具体名词+十元位置；行为是启动器；生克补是边。
2. 动态链必须保存真实顺序和图拓扑。
3. 串联、并行、汇合、反馈、搭桥、延伸与断裂必须分账。
4. 同一字母不自动代表同一对象。
5. 搭桥是图结构功能，不是凡有中介皆搭桥。
6. 首遍屏蔽母型；母型仅后验比较。
7. 当前案例库已被同一高频主链占据较多，下一轮优先寻找不同主链。
