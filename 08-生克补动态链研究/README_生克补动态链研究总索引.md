# 生克补动态链研究总索引

## 1. 目录职责

- `每次任务必读_生克补动态链滚动中枢.md`：每轮强制启动与断点回写；
- `影片动态链分析模板.md`：每部影片统一分析格式；
- `影片案例/`：每部影片独立正本或审计稿；
- `生克补动态链每小时运行记录.md`：唯一活动运行账本；
- 本文件：案例状态、母型状态与跨影片比较总索引。

## 2. 案例状态

| 影片 | 文件 | 状态 | 主问题 | 母型 |
|---|---|---|---|---|
| 千与千寻 | `影片案例/千与千寻_生克补动态链初审.md` | pending | 主克、主补、主生是否判准 | M-001 candidate |

状态定义：

- `pending`：尚未按统一模板完成；
- `audit`：已完成一轮，但关键节点仍有竞争解释；
- `canonical-current`：主链、变量与最近邻排除均稳定；
- `frozen`：证据不足，暂停重复审计；
- `rejected`：原分析主要由共现、剧情总结或错误端点构成。

## 3. 搭配母型索引

| 编号 | 母型 | 当前状态 | 已支持影片 | 核心风险 |
|---|---|---|---|---|
| M-001 | 压缩 → 承载 → 回认 → 自生 → 反向夺回 | candidate | 千与千寻（待审） | 把规则通关误写成核心克制 |

母型只有满足以下条件才能锁定：

1. 至少两部不同题材影片出现同构链；
2. 每部至少一个关键节点为 A 级证据；
3. 换掉角色身份、场景和视觉符号后仍成立；
4. 能指出失败版或反例；
5. 能说明母型适合产生的叙事效果与不适用边界。

## 4. 跨影片比较维度

后续每完成一部影片，必须向索引补充：

- 主克出现时间；
- 主补进入时间；
- 主生首次显影时间；
- 关系换挡次数；
- 主角从目标端转为源端的时点；
- 结局是否稳定；
- 观众主要获得的效果：爽、痛、暖、悬、悲、敬、释然；
- 最强最近邻解释；
- 母型贡献与反例贡献。

## 5. 当前研究纪律

- 单部影片不能直接锁定搭配母型；
- 不把角色成长总结当作动态链；
- 不把所有帮助都写成补；
- 不把所有阻碍都写成克；
- 不把先后顺序写成生；
- 不因关系数量多就判断搭配丰富；
- 每部影片最多先锁一条主链，其余作为支链；
- 新案例必须反过来修正中枢和母型，而不是只增加文件数量。
