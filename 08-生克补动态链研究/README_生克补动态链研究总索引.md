# 生克补动态链研究总索引

## 1. 目录职责

- `每次任务必读_生克补动态链滚动中枢.md`：强制启动、红线与真实断点；
- `影片动态链分析模板.md`：人物/团队行为、具体名词对子与动态链统一格式；
- `影片案例/`：影片与明确片段的具体积累；
- `现实案例/`：现实或历史案例的具体积累；
- `生克补动态链每小时运行记录.md`：唯一活动账本；
- 本文件：案例登记、候选链累计和通用母型状态。

## 2. 研究层级

```text
关系对子：谁生谁、谁克谁、谁补谁。
具体积累：人物/团队与阶段 + 行为 + 两端具体名词与十元位置 + 为什么成立 + 被改变变量。
动态链：多个具体关系对子按真实阶段连续启动。
通用母型：同一抽象对子链在多个独立、跨题材案例中稳定复现。
```

行为是案例主体；具体名词挂在行为两端。M-001A至M-032均为`legacy-case-chain`。

```text
点接触器件、放大测量、结构与制备方法掌握x
→生论文、专利、图纸、技术说明与统一名称壳x并z
```

## 6. 通用母型索引

### UM-004｜资源/能力/成果正式化—目标/资格确认—程序聚焦

```text
x生x并z → x并z生z → z补xn
```

状态：`locked-general-archetype`。

当前支持：7次，覆盖犯罪悬赏、儿童奇幻资格、历史航天职场、体育管理、现实医药科研工业和电子工业。

变量同构：

```text
实际资源、能力、权限、模型、样品、器件、技术或结果掌握
→获得正式可识别、可调用、可核验的壳
→壳使特定主体、资格、结果或技术获得明确归因确认
→确认给既有程序补入对象、材料标准、参与者、期限与阶段节点
```

严格成立条件：
1. `x`端必须是真实掌握，不是愿望、名声或结果标签。
2. `x并z`端必须形成可识别、可归因、可调用或可复核的正式壳。
3. `z`必须写清确认主体、对象、内容与重要位置。
4. `z补xn`必须证明既有程序原有真实缺口，确认随后改变对象、标准、参与者或节点。
5. 科研工程领域中，成果壳的识别接口与验证程序提供的证据必须分开。
6. 专利壳只固定权利、识别和许可接口，不自动代表科学确认、工程可靠性确认或产业采用确认。
7. 最终成功、获奖、销量、连胜、获救或产业规模不能倒证中间链段。

## 7. 用户惯用母型候选

### C-003｜中介相生改写直接克制—末尾补位

```text
1生2 → 2生3
背景：1克3
中介2把1的直接作用转换为3可接收的变量
末尾：A补B，修复真实缺口并稳定整体
```

当前状态：`user-confirmed-structure-awaiting-case`。

研究要求：
- 先从正式位置表找出满足三条位置关系的真实十元组合；
- 写人物、阶段、行为和三端具体名词；
- 证明拿掉2后，1对3恢复为直接克制或目标变量下降；
- 证明2不是普通中转场景，而是真正接收1的净增量并生给3新的核心变量；
- 末尾补关系必须写明方向、缺口和恢复变量；
- 未经多案例复现，不升级UM。

## 8. 方法修正记录

1. 关系对子是“谁生谁、谁克谁、谁补谁”。
2. 具体积累以主要人物或团队在具体阶段的行为为主体。
3. 具体名词位于行为两端，固定端点并做十元定位。
4. 多个对子合成动态链，不机械套主克、主补、主生顺序。
5. 稳定多次出现的抽象动态链才是母型。
6. 不为模板完整强行制造主克。
7. 失败版同样是母型证据，必须指出具体在哪一段断裂。
8. 通用母型锁定后，新案例仍须独立审计。
9. 基础克制关系不会因动态中介消失；只能在特定阶段被另一条关系路径改写。
