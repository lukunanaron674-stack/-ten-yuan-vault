# 生克补动态链研究总索引

## 1. 目录职责

- `每次任务必读_生克补动态链滚动中枢.md`：强制启动、红线与真实断点；
- `影片动态链分析模板.md`：具体名词对子与动态链统一格式；
- `影片案例/`：每部影片的具体积累；
- `生克补动态链每小时运行记录.md`：唯一活动账本；
- 本文件：案例链登记、候选链累计和通用母型锁定状态。

每轮必须先读`01-十元系统/001-概念的定义.md`，完成`z切分焦点+x现象集合+十元位置+本体/状态+体量`锚定。

## 2. 研究层级

```text
关系对子：谁生谁、谁克谁、谁补谁。
具体积累：具体名词A + 关系对子 + 具体名词B + 为什么成立 + 被改变变量。
动态链：多个具体关系对子按真实阶段连续启动。
通用母型：同一抽象对子链在多个独立、跨题材案例中稳定复现。
```

M-001A至M-032均改标为`legacy-case-chain`。它们是历史影片案例链编号，不再直接视为通用母型。后续逐条抽取具体名词对子，再建立C候选链；满足多次锁定门槛后才升级为UM通用母型。

```text
zx克n → xn补z → x生x并z → x并z生z → z补xn → xn补z → n克xz
```

## 6. 通用母型索引

当前没有因本轮新增而锁定的UM通用母型。

历史UM-01至UM-03保留为待复核记录，不再仅凭旧剧情概括维持锁定状态。需按新模板重新抽取具体名词对子、核验链序和变量同构后，再决定是否恢复`candidate`或`provisionally-supported`。

母型锁定门槛：

```text
多次独立复现
+ 至少跨两个题材
+ 关键对子A级证据
+ 具体名词不同但被改变变量与链序一致
+ 排除视觉符号、身份专属、单次动作和结果解释
+ 指出失败版
```

## 7. 方法修正记录

1. 关系对子是“谁生谁、谁克谁、谁补谁”。
2. 具体积累必须记录双方具体名词及为什么发生生、克、补。
3. 多个对子合成动态链，不要求机械套“主克→主补→主生”的固定顺序。
4. 稳定多次出现的抽象动态链才是母型。
5. 影片名称、人物名称和剧情步骤只能作为证据标签。
6. 一次出现只能建立具体动态链或C候选链，不能直接建立UM母型。
