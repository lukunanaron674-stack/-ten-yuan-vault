# 《机器人总动员》（2008）｜瓦力记忆重置、伊芙照护与对象回返动态链审计

## 1. 固定片段与对象层

只分析瓦力被修复后硬件与基础程序重新运行，但既有记忆、对象识别和对伊芙的关系回应被重置；伊芙用收藏物、共同动作和持续照护尝试唤回，直至牵手接触后瓦力恢复对象特异识别与回应的连续C级片段。

- 对象层：程序运行、对象识别与关系接口重建层。
- 主体：瓦力、伊芙；修复程序与电气接触为非人格化运行条件。
- 阶段：基础程序恢复但关系接口关闭 → 伊芙持续对象特异照护 → 接触触发记忆连续性恢复 → 瓦力重新识别伊芙并主动回应。
- 唯一核心变量：**瓦力从“能运行但不认识伊芙”到“恢复对象特异识别与关系回应”的变化，究竟由程序恢复直接生成，还是需要现实照护保存对象材料、触发机制解除接口关闭，并由独立识别确认关系回返。**

## 2. 端点分账

- `xn_base_repair`：瓦力硬件、能源与基础程序恢复，具备移动、收集和执行既定程序的能力。
- `nx_relation_interface_closed`：瓦力的行动仍被基础程序接管，对伊芙、收藏物和共同经历没有对象特异回应，关系接口实际关闭。
- `n_specific_care_bearing`：伊芙持续保护、移动、展示旧物并尝试重演共同动作，为同一对象保存现实承载。
- `xn_contact_trigger`：牵手产生的电气接触与内部记忆连续性重新接通，使对象识别通道恢复可运行。
- `z_specific_recognition`：瓦力明确识别伊芙、旧物与共同关系位置，而非一般传感器上线。
- `nz_relation_return`：双方重新出现对象特异回应、主动牵手与可回返的关系停靠；这里只登记片段级回返候选，不升级普遍关系锁定。

## 3. 直接边

```text
牵手接触触发程序 xn_contact_trigger
        ──克──▶
对象识别与关系接口关闭 nx_relation_interface_closed
```

接触触发直接降低的是“基础程序可运行但无法调用既有对象记忆与关系回应”的接口关闭程度。若只完成硬件修复而没有记忆连续性接通，瓦力仍能行动，却不会识别伊芙。

## 4. 条件性补边

```text
伊芙持续对象特异照护 n_specific_care_bearing
        ──补──▶
记忆重置阶段缺少的现实关系承载
```

必要条件：

1. 照护始终指向同一瓦力，不是维修任意设备；
2. 伊芙持续承担风险、时间与情绪成本，而非一次程序操作；
3. 旧物和共同动作只保存可供识别的对象材料，不能替瓦力完成识别；
4. 最终仍需独立的接口恢复与对象特异回应，才能检验`nz`。

另有条件候选：

```text
瓦力恢复后的对象特异识别 z_specific_recognition
        ──补──▶
关系回返 nz_relation_return 所缺的主体确认
```

识别确认把既有照护和共同经历重新接入双方关系解释，但不能把伊芙此前的单方照护追溯改写为当时已经完成的双向关系。

## 5. 正式失败边

### 失败边A

```text
✕ 基础程序修复 xn_base_repair
  ──生──▶ 对象特异关系回返 nz
```

不成立原因：瓦力修复后已经能移动与执行收集程序，却不识别伊芙。基础运行能力与对象特异关系接口必须分账。

### 失败边B

```text
✕ 伊芙持续照护 n
  ──生──▶ 完整关系回返 nz
```

不成立原因：照护保存现实材料和对象连续性，但在瓦力无识别、无自由回应阶段，只能证明伊芙单方承载。

### 失败边C

```text
✕ 收藏物与共同动作 x并z
  ──生──▶ 瓦力对象识别 z
```

不成立原因：这些对象携带共同经历痕迹，但瓦力在接口关闭时仍机械压缩或忽略它们；材料存在不等于主体完成识别。

### 失败边D

```text
✕ 电气触发 xn
  ──生──▶ 完整关系 nz
```

不成立原因：触发只恢复记忆与识别接口。若恢复后瓦力识别错误、拒绝伊芙或只执行旧程序，关系回返仍不成立。

## 6. 拿掉测试

- 拿掉基础修复：瓦力无法运行，后续识别与关系回应没有载体，但这只证明它是前置条件。
- 拿掉伊芙持续照护：接触触发仍可能恢复记忆，说明照护不是程序恢复的直接生成源；但对象连续性、关系材料和回返解释显著变弱。
- 拿掉接触触发：瓦力继续按基础程序行动，旧物与照护不会自动解除接口关闭。
- 拿掉恢复后的对象识别：只剩系统状态变化，不能判断`nz`。
- 拿掉此前共同经历：一次牵手后的响应不足以证明对象特异关系回返。

## 7. 反向测试

- 若瓦力恢复记忆接口后仍不识别伊芙，则`xn克nx`成立而`z补nz`不成立。
- 若伊芙停止照护但瓦力仍由电气接触恢复，则说明`n`不是`xn`的直接生成源。
- 若瓦力只识别收藏物、不主动回应伊芙，则只能确认记忆恢复，不能确认双方关系停靠。
- 若瓦力恢复识别后可以拒绝、离开或重新选择，关系回返才具备双方自由回应资格。

## 8. 最近邻与第三因素

- 最近邻：硬件修复、基础程序上线、记忆恢复、一般对象识别、条件反射、旧物提示、单方照护、浪漫叙事回返。
- 第三因素：维修质量、能源恢复、电气短路、既有记忆存储、收藏物熟悉度、叙事剪辑、伊芙的持续投入与瓦力此前形成的对象特异经验。

## 9. 竞争解释

1. **纯技术恢复解释**：关系回返只是维修完成后的自动重启。反证是基础程序先已运行而对象识别仍关闭；但最终触发仍可能主要是技术机制，因此不能把照护写成直接生成源。
2. **旧物唤醒解释**：收藏物和共同动作直接唤回记忆。片段中旧物多次未改变瓦力的机械反应，只能作为承载材料或条件。
3. **伊芙单方投射解释**：所谓关系回返只是伊芙把旧瓦力投射到修复后的机器。最终瓦力出现对象特异识别与主动回应，削弱该解释，但完整`nz`仍需双方自由回应边界。
4. **浪漫剪辑解释**：牵手与音乐让技术恢复被误看成爱情重新生成。必须把接口恢复、识别确认和关系回返拆成三个阶段。

## 11. 动态类型

- 主类型：对象识别接口重建的改变链。
- 次类型：现实照护维持对象连续性，程序触发解除接口关闭。
- 关系类型：对象特异回返候选，不把技术恢复直接等同完整`nz`生成。

## 12. 搭配效果

`xn`基础修复先恢复行动载体，却保留`nx`关系接口关闭；`n`持续照护保存同一对象的现实材料；第二个`xn`接触触发解除记忆接口阻断；`z`对象识别再补入关系回返所缺的主体确认。组合效果是：**关系材料可被单方保存，接口可被程序恢复，但关系回返必须在主体重新识别并能自由回应后才成立。**

## 13. 链段顺序效果

```text
基础程序恢复 xn
→ 对象识别与关系接口仍关闭 nx
→ 伊芙持续现实照护 n
→ 接触触发解除接口关闭 xn克nx
→ 对象特异识别 z
→ 关系回返 nz候选
```

若把`nz`提前到持续照护阶段，会把单方承担误判为双方关系完成；若删掉`z`识别，只剩技术恢复；若把基础修复直接写成关系回返，会忽略片段最关键的“能运行但不认识”的中间状态。
