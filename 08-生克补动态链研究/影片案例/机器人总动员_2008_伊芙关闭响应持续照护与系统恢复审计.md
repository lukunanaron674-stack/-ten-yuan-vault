# 《机器人总动员》（2008）｜伊芙关闭响应、持续照护与系统恢复动态链审计

## 1. 固定片段与对象层

只分析伊芙因植物封存指令进入关闭响应状态后，瓦力持续陪伴、保护并尝试唤醒，直至伊芙系统重新响应的连续C级片段。

- 对象层：关系运行与接口承载层。
- 主体：瓦力、伊芙；程序系统为非人格化运行条件。
- 阶段：伊芙失去即时响应 → 瓦力持续现实照护 → 系统恢复并重新响应。
- 唯一核心变量：**伊芙不可响应期间，瓦力的持续照护是否只是单方承载，还是足以直接生成完整双方关系；系统恢复是否仅恢复接口能力，还是自动生成对象特异回返。**

## 2. 端点分账

- `nx_interface_closed`：伊芙无法向瓦力输出即时回应、共同决定与关系反馈，关系接口处于外部程序控制下的不可响应状态。
- `n_care_bearing`：瓦力以遮雨、移动、守候、共同经历等现实行动持续承担对象的存在与安全。
- `xn_reactivation`：伊芙内部任务程序、能源与响应系统恢复，使感知、行动和回应通道重新可运行。
- `nz_specific_return`：伊芙恢复后能够识别瓦力并发生对象特异回应；是否达到完整关系停靠仍需后续跨阶段互惠验证。
- `z_recognition`：伊芙对瓦力及其照护痕迹的明确识别与确认。

## 3. 直接边

```text
伊芙系统恢复程序 xn_reactivation
        ──克──▶
伊芙不可响应接口状态 nx_interface_closed
```

程序恢复直接降低的是“无法感知、行动和回应”的接口关闭程度。它恢复运行能力，但不凭自身生成瓦力的对象特异意义，也不证明关系此前已经完整成立。

## 4. 条件性补边

```text
瓦力持续现实照护 n_care_bearing
        ──补──▶
关系运行在不可响应阶段缺少的现实承载
```

必要条件：

1. 照护对象始终是同一伊芙，而非可替代任务物；
2. 瓦力持续承担成本与风险，而非只做一次动作；
3. 伊芙不可响应，因此该阶段只能证明单方承载，不能证明双方互惠；
4. 后续系统恢复后必须出现对象特异识别，才能进一步检验`nz`。

另有条件候选：

```text
伊芙恢复后的对象识别 z_recognition
        ──补──▶
既有照护痕迹进入双方关系解释所缺的确认
```

该确认只能补入意义稳定，不能追溯性地把所有单方照护自动改写为完整双方关系。

## 5. 正式失败边

### 失败边A

```text
✕ 持续照护 n
  ──生──▶ 完整关系停靠 nz
```

不成立原因：伊芙在关闭状态中无法自由回应、退出、修复或共同承担；持续照护证明瓦力的对象特异投入，不足以单独证明双方关系完成。

### 失败边B

```text
✕ 系统恢复 xn
  ──生──▶ 对象特异关系 nz
```

不成立原因：程序恢复只恢复接口能力。若恢复后伊芙不识别瓦力、只继续任务，则关系结果不会自动出现。

### 失败边C

```text
✕ 伊芙重新响应 z
  ──生──▶ 过去全部照护的双方互惠性
```

不成立原因：重新响应可以确认照护对象与意义，却不能让不可响应阶段获得当时并不存在的双向反馈。

## 6. 拿掉测试

- 拿掉`xn`系统恢复：伊芙仍保持关闭，瓦力的照护可继续，但双方即时关系接口不恢复。
- 拿掉瓦力持续照护：伊芙仍可能按程序恢复，说明恢复能力不由照护直接生成；但对象特异关系线索与承载痕迹显著下降。
- 拿掉恢复后的识别：只剩程序上线，无法判定`nz`对象特异回返。
- 拿掉既有共同经历：一次恢复后的注视不足以证明完整关系停靠。

## 7. 反向测试

- 若伊芙恢复后只执行任务、不识别瓦力，则`xn`恢复成立而`nz`不成立。
- 若瓦力停止照护但伊芙仍自动恢复，则说明`n`不是`xn`的直接生成源。
- 若伊芙在关闭前已明确建立互惠关系，则持续照护可维持既有关系承载，但仍不等于重新生成关系。

## 8. 最近邻与第三因素

最近邻：单方执着、物品维护、任务守候、投射、习惯陪伴、程序自动重启、对象识别、关系回返。

第三因素：植物任务指令、能源状态、程序锁定、叙事剪辑、瓦力的既有依恋、伊芙此前共同经历与恢复后的记忆连续性。

## 9. 竞争解释

1. **任务解释**：瓦力照护只是维护任务对象，而非关系承载。反证是其投入明显超出任务效率并持续对象特异化，但仍不能据此直接证明完整`nz`。
2. **程序解释**：伊芙恢复纯由内部程序决定。此解释支持`xn克nx`，同时否定“照护生系统恢复”。
3. **叙事浪漫化解释**：连续蒙太奇让单方照护看似天然等于爱情成立。需用不可响应阶段的互惠缺失加以排除。

## 11. 动态类型

- 主类型：接口关闭后的单方承载维持。
- 次类型：程序恢复解除接口阻断。
- 关系类型：对象特异回返候选，尚不升级为完整`nz`锁定。

## 12. 搭配效果

`nx`关闭制造“关系无法被即时确认”的悬置；`n`持续承载保留对象与共同生活痕迹；`xn`恢复重新开放回应通道；`z`识别把单方痕迹带入双方解释。组合效果不是“照护创造爱情”，而是“照护保存关系可被重新确认的现实材料”。

## 13. 链段顺序效果

```text
接口关闭 nx
→ 单方现实承载 n
→ 程序恢复 xn
→ 对象识别 z
→ 对象特异回返 nz候选
```

若把`xn`恢复提前，照护阶段的不可响应边界消失；若删掉`z`识别，只剩技术恢复；若直接从`n`跳到`nz`，则把单方投入误判为双方关系完成。
