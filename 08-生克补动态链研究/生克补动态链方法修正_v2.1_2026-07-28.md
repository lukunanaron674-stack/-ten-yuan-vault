# 生克补动态链方法修正 v2.1

> 本文件是动态链研究的明确范围修正，不改写十元关系表，不替代单条关系审计。凡旧模板、旧案例说明与本文件冲突，以本文件为准。箭头不是关系许可证，标签也不是机制替身。

## 1. 端点必须先完成三层卡路由

每个源端点和目标端点必须按以下顺序确认：

```text
对象、主体、阶段与对象层明确
→ 读取十元信息卡，回答“它是什么”
→ 读取对应准度卡，完成必要条件、最近邻、拿掉与反向测试
→ 标记端点状态：已成立 / 候选 / 未判定
→ 两端均成立后，读取生卡 / 克卡 / 补卡
→ 最后查十元生补克表与关系专项正本索引，确认机制是否可正式调用
```

必须记录：稳定本体、当前状态、行为功能、场景、光影、时间关系、关系位置、显影、动态链、体量三项、对象、主体、阶段和被改变变量。

`z切分焦点`与`x现象集合`已退役，只能解释旧案例怎样形成，不得生成、替代或证明现行十元端点。`01-十元系统/001-概念的定义.md`只按`legacy-evidence-only`读取。

勇敢、成长、帮助、压迫、规则、爱、自由、真相、希望、角色名、组织名和单个动作不得直接作为十元端点。

## 2. 确认不得使用 z0—z4 单轴等级

个人、群体、机构、公众不是从低到高的真实性等级；机构确认也不天然比个人确认更接近事实。确认必须分开记录：

```text
确认主体：个人 / 关系双方 / 小群体 / 机构 / 公众
确认内容：身份 / 责任 / 存在 / 资格 / 事实状态 / 关系位置
证据状态：初步 / 可执行 / 稳定 / 被反证 / 已撤销
采用范围：私人判断 / 档案采用 / 媒体采用 / 医疗采用 / 法律采用
成立阶段：首次判断 / 调查中 / 审判中 / 后段揭露 / 历史回看
```

禁止把“有人猜对了”写成“机构确认已经恢复”，也禁止把“机构采用”写成“客观事实因此改变”。`z_right / z_wrong`只是具体确认正确性的注记，不是新十元位置。

## 3. 直接关系边与间接图路径必须分开

### 3.1 直接关系边

只有源端直接改变目标端核心变量时，才登记关系对子，并必须通过：

- 两端信息卡与准度卡；
- 关系卡必要条件；
- 机制说明；
- 拿掉测试；
- 反向测试；
- 最近邻排除；
- 第三因素隔离。

### 3.2 间接图路径

若实际结构为：

```text
A 生 C → C 克 B
```

则只登记两条直接关系边，不得再追加“A间接克B”进入关系表或累计次数。

### 3.3 链式效果

三步以上造成的总体下降、维持、替换或临界，只能写为动态链效果，不得把链尾结果倒写成首端对链尾的直接生、克、补。

## 4. `x克z`严格门槛

`x克z`只在以下条件同时满足时登记：

1. 明确主体主动控制目标确认所需的必要入口；
2. 控制对象、确认内容、采用主体和成立阶段可明确限定；
3. 拿掉该入口控制后，目标确认能力不再以同样路径下降；
4. 普通混乱、漏登、搜查无果、诱导询问、确认偏差、自然传播和程序惯性不足以解释主要变化；
5. 克制对象是具体确认资格或机构采用能力，不是“现实本身”。

不满足时，优先检查：

```text
x 生 x并z
x并z 生 z_wrong
z_wrong 补 xn
xn 生 xz
```

其中每条关系仍须分别通过现行关系正本；不得为了保留漂亮母型而扩大主克。

## 5. 错误确认来源分类

| 类型 | 核心机制 | 常见结构 |
|---|---|---|
| 制造型 | 主体主动生成、替换或伪造确认材料 | `x生x并z→x并z生z_wrong` |
| 转译型 | 含混现象被解释框组织为确定责任或身份 | `x并z生z_wrong` |
| 缺证型 | 必要证据不足，错误候选未被排除 | 条件不足，不自动登记`x克z_right` |
| 惯性型 | 已有错误确认持续补入旧程序 | `z_wrong补xn`候选，须检查程序真实缺口 |

同一案例可以同时存在多类，但必须按主体、阶段和变量分账。

## 6. 补关系按“具体缺口对应”判断，不要求同层

撤销错误规则：

```text
补对象必须与被克对象同层
```

正确标准是：目标端原先已存在并有可指认的具体缺口；补源把与该缺口对应的变量真实补入目标。必须写：

```text
目标原缺口：对象 / 阈值 / 程序节点 / 承载接口 / 判断资格 / 返回位置
补源提供：与缺口对应的具体变量
补后变化：目标运行能力如何恢复或增加
拿掉补源：原端仍存在，但缺口重新出现
```

禁止把帮助、陪伴、救援、资源出现、悲剧结束或角色获救直接写成补。

## 7. 每片只设一个核心被改变变量

每个影片或明确片段必须写：

```text
对象：
核心变量：
初始状态：
终态：
展开指标：
```

自由、职业、亲密关系、名誉、安全等可以作为展开指标，不得并列充当多个主变量。无法压缩时，应缩小片段或拆分支路。

## 8. 动态类型先标记

```text
改变链：核心变量发生方向性变化
崩坏链：原稳定结构持续失去运行能力
维持链：多个机制共同维持原状态
循环链：变量经程序返回旧位置或重复生成
替换链：原对象、责任、身份或承载被替代对象占位
```

类型是动态图描述，不是新的十元关系。不得把“维持”“循环”“替换”直接登记为生克补关系。

## 9. 体量使用三项描述，不做固定加权总分

```text
影响范围：局部 / 关系 / 组织 / 社会
持续时间：瞬时 / 单场 / 跨阶段 / 长期
不可逆程度：可撤回 / 高成本恢复 / 基本不可逆
```

禁止机械加权平均。需要给1—10体量时，必须附三项依据；任一关键项不明确时保留区间。

## 10. 关系置信度采用七项最弱值

分别记录：

1. 源端点稳定度；
2. 目标端点稳定度；
3. 机制清晰度；
4. 独立证据强度；
5. 竞争解释排除度；
6. 拿掉 / 反向可逆性；
7. 跨案例复现度。

最终置信度取七项最小值，不使用加权平均。任一关键端点或机制低于门槛，整体不得由其他高分抬升。只有七项全部不低于95%，才允许锁定正式关系机制；动态链调用已锁定关系时，仍须为本片具体端点重新评分。

## 11. 案例粒度采用 C→B→A

```text
C级：单场戏或单一明确片段
B级：由多个C级节点组成的关键段落
A级：完整影片总体动态链
```

默认先完成C级，再汇总B级，最后才允许形成A级。若整片跨越多个主体、确认内容或核心变量，不得直接从剧情梗概跳到A级关系链。

## 12. 失败边进入正式反例区

每个案例必须至少记录一个失败候选：

```text
候选关系：
为什么看似成立：
违反哪条测试：
被哪种最近邻替代：
最终处理：失败边 / 条件边 / 未判定
```

失败边与正例同等进入后验比较，不能只积累支持案例。

## 13. 母型编号治理

### 13.1 新编号域

```text
R-MIG：位置迁移、位置叠加、承载中心转移
R-ID：身份壳、公共身份、多主体身份确认
R-ATTR：责任、身份、存在与资格归因替换
R-N：生活/空间/群体承载与残余承载岛
R-PROC：程序补入、程序惯性与程序生临界
```

### 13.2 旧编号保留为历史别名

```text
R-MIG-17 → legacy alias，后续映射R-ID
R-MIG-18 → legacy alias，后续映射R-ID或R-N
R-MIG-19 → legacy alias，后续映射R-ATTR
R-MIG-20 → legacy alias，后续映射R-ATTR-01
```

新案例不再增加上述旧编号计数；历史支持次数保留，直到完成专门迁移审计。

## 14. R-ATTR-01 暂定名与边界

```text
R-ATTR-01｜确认入口或呈现材料—替代归因壳—错误确认进入程序
```

抽象链：

```text
具体材料或入口掌握 x
→ 生成替代责任 / 身份 / 存在壳 x并z
→ 壳生特定主体错误确认 z_wrong
→ 错误确认补入程序 xn
→ 程序改变单一核心变量
```

严格`x克z_right`不是该母型的必备边；只有通过第4节门槛时，才作为并行窄阶段边登记。《狩猎》《一级恐惧》保留为前半链成立、严格主克失败的反例。

## 15. 每轮模板必填字段

```text
分析粒度：C / B / A
动态类型：改变 / 崩坏 / 维持 / 循环 / 替换
端点卡路由：信息卡 / 准度卡 / 端点状态
对象分层：稳定本体 / 状态 / 行为 / 场景 / 光影 / 时间 / 关系 / 显影 / 动态链
确认主体：
确认内容：
证据状态：
采用范围：
成立阶段：
错误来源：制造 / 转译 / 缺证 / 惯性 / 不适用
关系性质：直接关系边 / 间接图路径 / 条件 / 失败边
核心变量：
体量三项：影响范围 / 持续时间 / 不可逆程度
七项置信度及最弱项：
```

## 16. 与十元关系审计主线的边界

- 本修正只治理动态链案例如何使用既有端点与关系；
- 不新增、不删除、不改写十元生补克表中的关系；
- 单片出现的间接作用不得升级为单条关系正本；
- 若动态链案例暴露关系表冲突，只记录为待单关系审计证据；
- 已锁定关系如需修改，必须另行走明确范围的`canonical-amendment`与95%门槛。

## 17. 生效规则

本文件自2026-07-28起用于所有新轮次。`revision: v2.1.1-card-routing-hotfix`撤销本文件旧版第1节的`z切分焦点+x现象集合`端点算法，并把第10节与模板字段统一为七项置信度。旧案例不批量重写；被重新调用、参与母型升级或成为下一案例最近邻时，必须按现行三层卡路由补齐。
