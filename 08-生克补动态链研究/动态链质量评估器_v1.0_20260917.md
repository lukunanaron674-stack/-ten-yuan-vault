# Dynamic Chain Evaluator v1.0

## 0｜目的

用于回答：

> 一条动态链不仅“说得通”，而且是否真的具有高质量结构生产力？

本评价器只评价链条质量，不修改十元正本，不因为低分而重写五轴。

---

# 1｜总分

```text
节点质量 20
边质量   40
整链质量 40
总分    100
```

建议解释：

```text
90–100  高稳定强链候选
80–89   强链候选，允许进入项目压力测试
70–79   可用但存在明显弱边
60–69   结构成立但生产力不足
<60     不建议作为母链
```

分数只用于研发筛选，不等同于作品审美总分。

---

# 2｜节点质量 20

## N1｜十元与主次证据 0–5

- 主十元是否有独立结构证据
- 次十元是否真的影响当前状态
- 是否只是角色气质 / 题材标签

## N2｜同对象层 0–5

必须满足：

```text
same_object_layer = true
```

不得用“社会制度”节点直接和“一个人的即时情绪”节点做伪迁移，除非 DSL 明确跨层接口。

## N3｜同核心变量 0–5

必须满足：

```text
same_core_variable = true
```

链条可跨阶段改变变量值，但不能每一步偷偷换问题。

## N4｜状态可观察性 0–5

节点必须写成状态，不写成空泛标签：

```text
BAD: ZX阶段
GOOD: 离场方向仍由主体掌握，唯一行动目标保持稳定，但可行路径急剧缩窄
```

---

# 3｜边质量 40

每条核心边都必须回答四件事。

## E1｜Mechanism 0–10

是否能明确说明：

> A 通过什么机制改变 B？

不能只写：

```text
于是
因此
受到影响
矛盾升级
```

这些是语言胶水，不是机制。

## E2｜Variable Delta 0–10

必须明确：

```yaml
changed_variable:
before:
after:
```

没有 Δ 的边，本质上只是相邻事件。

## E3｜Residue 0–10

变化发生后，上一状态留下什么：

```text
痕迹
限制
债务
未解决关系
已关闭路径
新接口
损失
惯性
```

若 A 完全消失而没有解释，链条会有“换场景式跳跃”。

## E4｜Next Affordance 0–10

最关键问题：

> **因为这条边发生了，下一阶段现在能做什么，而之前不能？**

高质量边必须生产新的：

```text
可行动路径
可认知对象
决策权
关系位置
合法状态空间
资源接口
制度条件
风险窗口
```

若下一阶段即使没有该边也完全可以发生，则此边生产力低。

# 4｜整链质量 40

## C1｜因果连续与主导权迁移 0–8

检查每阶段：

```text
谁升主
谁降次
谁进入
谁退出
谁仍作为 residue 存在
```

## C2｜不可替代性 0–8

做 deletion / replacement test：

```text
删掉一条边，链是否明显失去结构？
换成任意戏剧事件，是否还能同样成立？
```

若能随便替换，说明链只是剧情顺序。

## C3｜张力与状态变化密度 0–8

张力不等于暴力或大事件。

看的是：

```text
合法状态空间是否收缩 / 扩张
决定权是否迁移
路径是否改变
关系是否改写
剩余选择是否发生压力
```

## C4｜Residue 回收 0–8

前面留下的结构债务是否被：

```text
回收
转化
升级
反转
保留为开放结尾
```

禁止“忘了”。

## C5｜Endpoint / Closure 0–8

结尾必须能说明：

```text
什么变量停止变化？
什么关系已经锁定？
什么仍开放？
为什么链在这里结束，而不是随便截断？
```

# 5｜横向阶段矩阵

每个 Tn 建议固定记录：

```yaml
stage_id:
primary:
secondary:
intensity:
horizontal_relations:
  - source:
    relation: 生|克|补|none
    target:
current_constraints:
current_affordances:
current_paths:
```

横向负责回答：

> **此刻系统内部到底是什么关系。**

# 6｜纵向迁移矩阵

```yaml
from:
to:

changed_variable:

residue:
next_affordance:
primary_shift:
secondary_shift:
newly_appeared:

path_blocked:
reversibility:
```

纵向负责回答：

> **为什么下一阶段比上一阶段多了一个新的结构可能。**

# 7｜边判定 Guard

以下情况默认不得作为高分边：

```text
时间连续 → 自动判因果
同场出现 → 自动判关系
A更强 → 自动判克
A帮助B → 自动判生
关系变好 → 自动判补
角色成长 → 自动判状态变化
场景变大 → 自动判体量升级
```

必须回到：

```text
mechanism + delta + residue + next_affordance
```

# 8｜Evaluator 的反事实测试

每条高价值边至少做一次：

## Delete

```text
没有这条边，下一阶段是否仍自然成立？
```

## Replace

```text
把触发事件换成普通戏剧事件，是否仍能产生同一 Δ？
```

## Reverse

```text
若方向反过来，关系是否仍被错误判成同一链？
```

## Surface Removal

```text
去掉颜色、角色职业、台词、主题标签后，结构是否仍成立？
```

# 9｜R5 验证协议

R1–R4 完成的是评价器构造，R5 负责验证它有没有自我陶醉。

数据应混合：

```text
经典高质量动态链
弱因果但剧情顺畅链
纯时间连续链
关系标签正确但变量没变链
高戏剧性假链
人为构造的伪 next_affordance 链
```

盲测顺序：

```text
隐藏作品名与原解释
→ 独立结构标注
→ Evaluator 打分
→ 再打开文本 / 影片证据
→ 统计误判
→ 只修稳定 failure family
```

不得因为某个经典作品“很伟大”就自动给高分。

# 10｜R6 项目实战

R5 通过后，进入黎黎隆：

目标不是写几十条链，而是从候选中筛出：

```text
2–3 条 8 分钟母链
```

要求：

```text
世界链
人物链
事件链
```

至少两层之间能共享关键 changed variable 或 residue，避免三条链各演各的。

# 12｜冻结原则

Evaluator v1.0 当前：

```text
R1–R4：FROZEN
R5：PENDING
R6：PENDING
```

只有 R5 出现稳定系统误判，才修 Evaluator；不要因为单个作品不符合预期就改评价器。
