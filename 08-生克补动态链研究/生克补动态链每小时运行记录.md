## 5. 动态图与结论

```text
Carson及同谋对乘客记录、儿童物品、柏林消息、藏匿位置与机组信息入口的掌握 x
        ├─生→ 儿童不存在/母亲失常替代壳 x并z
        │          ├─生→ 机组错误存在性确认 z_wrong_crew
        │          │          └─补→ 停止搜查、约束Kyle与封闭禁区程序 xn_crew
        │          └─生→ 乘客错误人物确认 z_wrong_passengers
        │                     └─补→ 群体回避、拒绝协助与敌意传播程序 xn_passengers
        └─克→ 机组对Julia真实存在与绑架事实的正确确认 z_right

机组约束程序 + 绑架/爆炸程序 xn
        └─生→ Kyle行动归零与Julia救援时间窗临界 xz
                   └─生→ Kyle临时搜索/处置决定接口 zx

Kyle机体结构/搜索路径掌握 x
        ─允许→ 重开搜索与最后处置程序
```

结论：
1. `x并z生z_wrong`与`x克z_right`再次同时成立，但必须分账；错误确认不是克源。
2. Kyle个人正确确认持续，不等于机组正确确认持续；确认主体不同。
3. 普通无人目击、搜查无果、Kyle焦虑和飞机复杂空间均不足以单独成立主克。
4. 机体知识属于专业`x`和允许条件，不自动补程序。
5. R-MIG-20由2增至3，新增存在性确认、机组/乘客分账和移动封闭空间；状态`supported-specific-3-cross-domain-confirmation-type`，不升级母型。
