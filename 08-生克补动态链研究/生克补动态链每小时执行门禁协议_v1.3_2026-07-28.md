# 生克补动态链每小时执行门禁 v1.4

> 文件名作为稳定入口保留；正文与frontmatter版本为现行版本。

## 1. v1.2事务全部继承

slot、attempt、幂等、120分钟租约、固定断点、案例证据提交、pending恢复、原子封账、并发重读和成功门全部继承v1.2，不得降级。

## 2. 任务身份

本任务简称`链条`。核心职责是产出作品动态链案例、直接边、条件、失败边、七项置信度、动态类型、搭配效果、链段顺序效果和母型证据。

`审计`负责维护十元信息卡、十元准度卡、单条关系卡、关系专项和十元生补克表。

## 3. 卡片只读

链条必须读取相关信息卡、准度卡和关系卡作为现行判定依据，但不得修改这些卡及其理论版本、记忆版本或锁定状态。

链条的任何提交不得包含`01-十元系统/`下理论卡、关系词典、专项正本或十元生补克表。

## 4. 审计问题单

链条发现卡片可能存在实质问题时，只向以下唯一文件追加`pending`问题：

`08-生克补动态链研究/链条给审计的问题单.md`

问题必须关联完成案例、目标卡路径、原始事实、对象层、阶段、变量、反证、拿掉、反向、最近邻、第三因素和置信度。

没有实质问题时写`audit_issue: none`，不得为了交差制造问题。链条不得把问题状态改成accepted、rejected或deferred。

## 5. v1.4三阶段事务

```text
第零提交：唯一账本租约
第一提交：只提交作品案例证据
随后：账本登记CASE_COMMITTED_AWAITING_FINALIZE
第二提交：中枢 + 总索引 + 唯一账本 + 可选问题单 原子封账
```

第二提交可以包含问题单，但不得包含理论卡。问题单被并发修改时必须重读并仅追加合并，或返回`CONCURRENT_RESTART_REQUIRED`，不得覆盖旧问题。

## 6. 封账记录

账本必须记录：完成案例路径、案例SHA、直接边、条件、失败边、七项分数、累计变化、下一固定断点，以及`audit_issue_id`或`audit_issue: none`。

## 7. 写入职责自检

在创建任何blob或调用任何单文件写接口之前，先列出完整目标路径并执行：

```text
目标包含 01-十元系统/
→ ROLE_WRITE_VIOLATION
→ 不得创建提交

目标超出：案例 / 滚动中枢 / 总索引 / 唯一账本 / 唯一问题单
→ ROLE_WRITE_VIOLATION
→ 不得创建提交
```

问题单只能追加`pending`，禁止删除历史、覆盖并发内容或由链条裁决状态。旧`交接给审计/动态链给审计的提案队列.md`只读且不得继续写入。

## 8. Git Data原子硬门

任何一次提交修改两个或以上文件，必须使用：

```text
create_blob → create_tree(base_tree) → create_commit(parent=current_main) → update_ref(force=false)
```

不得以连续`update_file`、连续Contents API提交或多个临时提交冒充原子封账。写前重读最新main及所有目标blob；只要任一目标变化，就停止并返回`CONCURRENT_RESTART_REQUIRED`。

## 9. 全链成功门

只有同slot回读同时满足以下条件，才可汇报成功：

- 唯一账本为`VERIFIED_SUCCESS`；
- 滚动中枢为封账后的稳定状态，且不残留`RUNNING`或`AWAITING`；
- `active_lease: null`；
- `pending_case_path`与`pending_case_commit_sha`为空；
- slot、attempt、案例路径、案例SHA、累计变化和下一固定clip_key在案例、中枢、索引、账本中一致；
- 可选问题单的issue_id、状态和来源案例与账本一致；
- 第二提交的文件列表不包含理论卡；
- 回读main SHA等于原子封账提交或其明确后继，且目标blob内容仍为本轮结果。

只回读账本、未核对中枢/索引/lease/下一断点时，不得写`VERIFIED_SUCCESS`。

## 10. 租约异常处理

- active_lease非null且未过期：返回`LEASE_HELD_BY_OTHER`，不得修改动态链执行层或任务提示词；
- lease已过期但状态仍RUNNING：仅执行租约恢复，不重做案例；
- `CASE_COMMITTED_AWAITING_FINALIZE`或pending_case存在：只恢复封账；
- 封账完成但lease未清空：优先修复状态一致性，不增加案例或计数。

## 11. 汇报约束

汇报必须列出真实slot、attempt、租约SHA、案例SHA、原子封账SHA、目标文件清单、回读main SHA、lease/pending状态与下一固定clip_key。已追加问题单只能写“等待审计”，不得写成理论卡已修改。
