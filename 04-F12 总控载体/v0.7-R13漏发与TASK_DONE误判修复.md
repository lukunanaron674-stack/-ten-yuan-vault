# v0.7-R13漏发与TASK_DONE误判修复

## 0. 问题定位

本次银矿创作模板库 v3 预跑出现两个问题：

1. R13 未真正发送。
2. R14 被手动或误触提前进入，导致归档轮缺少 R13 作为依据。
3. F12 等待逻辑把页面上的“停止生成按钮候选”误判为仍在生成，从而卡住自动发送。
4. 检测结果显示输入框、发送按钮、TASK_DONE 都存在，但 stopButtonCount 仍为 1，说明 stopButton 不能作为唯一生成判断。

---

## 1. 事故记录

### 1.1 检测结果

```text
editorCount: 2
sendButtonCount: 1
stopButtonCount: 1
bodyHasTaskDone: true
```

### 1.2 正确解释

```text
输入框存在
发送按钮存在
上一轮已有 TASK_DONE
但停止生成按钮候选误报
```

所以问题不是：

```text
找不到输入框
找不到发送按钮
内容写不进去
```

真正问题是：

```text
等待完成逻辑过度依赖 stopButton，导致脚本误判仍在生成。
```

---

## 2. 直接修复规则

### 2.1 旧错误逻辑

```js
if (isGenerating()) wait;
```

问题：ChatGPT 页面可能残留或误识别停止按钮候选，导致永远等待。

### 2.2 新逻辑

```text
只要满足：
1. 最新助手回复包含【TASK_DONE】
2. 输入框可用
3. 发送按钮可用

就允许进入下一轮。
```

### 2.3 stopButton 降级

```text
stopButton 只能作为辅助参考，不能作为硬阻断条件。
```

---

## 3. R13 补发规则

由于 R13 没发，必须先补发 R13，再跑 R14。

正确顺序：

```text
R13：15 个故事种子转短篇大纲
→ 等待 R13 输出【TASK_DONE】
→ R14：R13-R14 短篇大纲归档轮
→ 生成 Markdown 归档文档
```

禁止：

```text
R13 未完成时直接跑 R14
R14 基于空上下文归档
只输出归档标题但没有 R13 内容
```

---

## 4. 下一版 F12 必须具备

```text
1. 明确 currentRound
2. 每轮发送前检查上一轮是否 TASK_DONE
3. TASK_DONE 优先级高于 stopButton
4. stopButton 只用于未出现 TASK_DONE 时的辅助判断
5. 每轮发送后写 checkpoint
6. R13/R14 顺序不可跳过
7. 归档轮必须生成可保存 Markdown 文档
```
