# 十元动态链

> 动态链记录结构如何在时间中从 A 变到 B。它不新增十元定义，也不因事件连续、同框或叙事顺序自动产生生克补关系。

## 1｜统一一句话格式

每条动态链先写一条自然语言句，再写两个机器可读块：

```text
自然语言一句话：
[actor] 在 [current_window] 内，通过 [mechanism]，使 [changed_variable] 从 [起点状态] 经 [变化] 到 [终点状态]；留下 [residue]，并开启 [next_affordance]。

【十元主→次】
[阶段或窗口]：主 [primary] → 次 [secondary]

【向量起点→变化→终点】
[start_vector] → [delta_vector] → [end_vector]
```

其中：

- `起点`是可观察的阶段状态，不是“某十元开始”；
- `变化`必须指向至少一个明确的 `changed_variable`；
- `终点`是当前窗口的结束状态，不是未经证据支持的最终命运；
- `residue`和`next_affordance`防止链条只剩事件顺序。

## 2｜横向阶段：同一时刻内部结构

横向回答“这一阶段内部是什么关系”，每个阶段至少记录：

```yaml
stage:
  stage_id:
  current_window:
  object_layer:
  primary:
  secondary:
  intensity:
  current_state:
  horizontal_relations:
    - source:
      relation: 生 | 克 | 补 | none
      target:
      mechanism:
  current_constraints: []
  current_affordances: []
  current_paths: []
  decision_right:
  reentry_right:
```

横向的“主→次”是同一阶段的结构排序，不等于时间上的转化箭头；左右排列也不代表生克补方向。

## 3｜纵向迁移：阶段之间的状态变化

纵向回答“为什么下一阶段由上一阶段制造出来”：

```yaml
transition:
  from_stage:
  to_stage:
  trigger:
  mechanism:
  changed_variable:
  delta:
    before:
    after:
  residue:
  next_affordance:
  primary_shift:
    up: []
    down: []
  secondary_shift:
    up: []
    down: []
  newly_appeared: []
  removed: []
  relation_changed: []
  path_opened: []
  path_blocked: []
  reversibility:
  endpoint:
```

当前动态链研究的边最低证据固定为：

```text
mechanism
+ changed_variable Δ
+ residue
+ next_affordance
```

“因为剧情需要”“局势升级”“A影响了B”不是机制，也不能代替变量前后值。

## 4｜横纵混合链规范

推荐用阶段卡包住纵向边：

```text
T1 [主A→次B｜当前状态｜横向约束]
  ──自然语言一句话｜机制｜变量 Δ｜残余｜下一可供性──▶
T2 [主C→次D｜当前状态｜横向约束]
  ──自然语言一句话｜机制｜变量 Δ｜残余｜下一可供性──▶
T3 [主E→次F｜终点状态]
```

同一阶段可以有多条横向关系；阶段之间每条纵向边必须有独立的 `transition_id`。如果一句话同时存在两条独立因果箭头、不同对象层或不同核心变量：

```text
标记 SPLIT_IR
→ 拆成独立链
→ 各自保存 actor / object / current_window / changed_variable
→ 不互相回填证据
```

## 5｜动态链与生克补的调用边界

```text
阶段迁移
≠ 自动生
阶段受限
≠ 自动克
阶段互补
≠ 自动补
```

只有当源、目标两个端点先分别通过十元判定，且机制真实改变目标的成立条件、运行空间或缺口状态，才可在横向关系中写 `生`、`克` 或 `补`。详见 [[十元_生克补关系]]。

动态链可以记录：

- 主次十元升降、进入、退出和残余；
- 路径开放、封闭、收窄、汇流和回返；
- 决定权、归属、承载、接口或可逆性的迁移；
- 生克补关系从候选、成立到失败的阶段边界。

动态链不能记录为已成立的内容：

- 仅仅同场、相邻、镜头相接或时间相继；
- 仅仅出现题材道具、颜色、情绪或视觉效果；
- 没有前后变化的“漂亮箭头”；
- 把楼梯、门、火焰、武器等道具直接写成十元端点。

## 6｜质量评估与封账

沿用当前 `Dynamic Chain Evaluator v1.0`：

```text
节点质量 20
边质量   40
整链质量 40
总分    100
```

边质量至少审查：

1. `Mechanism`：A 通过什么机制改变 B；
2. `Variable Delta`：具体改了什么；
3. `Residue`：上一阶段留下什么；
4. `Next Affordance`：因此下一阶段现在能做什么。

整链还要复核因果连续性、不可替代性、变化密度、残余回收、主导权迁移和端点闭合。质量分是研发筛选分，不是十元端点置信度，也不是作品审美分。

## 7｜动态链输出模板

```text
【作品 / 对象 / 窗口】
【一句话动态】
【阶段 T1】
  【十元主→次】
  【当前状态】
  【横向关系】
【阶段 T1→T2】
  【trigger】
  【mechanism】
  【changed_variable：before→after】
  【residue】
  【next_affordance】
  【主次迁移】
  【路径开放 / 封闭 / 回返】
【阶段 T2】
【终点与仍开放项】
【直接生克补边 / 失败边 / none】
【Evaluator 分数与最弱边】
【不确定项 / SPLIT_IR】
```

## 8｜机器可读规则

```yaml
dynamic_chain_protocol:
  sentence_format: actor_in_window_mechanism_changes_variable_from_start_through_delta_to_end
  stage_format: "【十元主→次】"
  vector_format: "【向量起点→变化→终点】"
  horizontal:
    required: [primary, secondary, intensity, current_state, horizontal_relations, constraints, affordances]
  vertical:
    required: [trigger, mechanism, changed_variable, delta, residue, next_affordance]
  minimum_edge_evidence: [mechanism, changed_variable_delta, residue, next_affordance]
  split_when:
    - independent_causal_arrows
    - different_object_layers
    - different_core_variables
  relation_is_not_inferred_from:
    - co_occurrence
    - sequence_alone
    - theme_word
    - visual_prop
  evaluator:
    node: 20
    edge: 40
    whole_chain: 40
  ten_yuan_definitions_read_only: true
  unknown_is_valid_output: true
```
