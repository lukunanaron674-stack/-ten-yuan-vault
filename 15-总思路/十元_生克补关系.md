# 十元生克补关系

> 本页只整理已经存在的关系与调用门，不凭空补关系。关系表的几何位置、关系卡的机制、具体案例证据和动态链阶段必须分开保存。

## 1｜三类关系的现行最低定义

| 类型 | 现行最低门槛 | 不能替代为 |
|---|---|---|
| 生 | 源端使目标此前不足的核心变量出现或上升 | 同时出现、先后相邻、成长感 |
| 克 | 目标端此前真实存在；源端使其核心资格、能力或边界下降 | 大压小、冲突、暴力或失败 |
| 补 | 两端独立存在；一端补入另一端的真实缺口，但不替代另一端 | 拼图、对称、互相喜欢或同框 |

机器召回句：

```text
生＝源使目标此前不足的核心变量出现或上升。
克＝目标此前真实存在；源使其核心资格、能力或边界下降。
补＝两端独立存在；一端补入另一端的真实缺口，但不替代另一端。
```

五行内的阴阳相反轴是静态本体对照，不属于生克补：

```text
zx ↔ nx
zn ↔ x
n ↔ x并z
xn ↔ z
xz ↔ nz
```

## 2｜现有五组补位

这些语义来自 [[01-十元系统/十元生补克表]]，只作为已有补位关系的整理：

| 几何组 | 补位语义 |
|---|---|
| `zx ↔ nx` | 直接以自身权能做成，与通过既有身份、关系、权限和通道借力做成互补 |
| `zn ↔ x` | `zn` 为掌握边界提供内部意义方向；`x` 为意义核心提供具体对象、资源和现实掌握落点 |
| `n ↔ x并z` | `n` 为公开壳提供真实可承载的内部；`x并z` 为承载结构提供可识别、可进入、可持续指认的公共界面 |
| `xn ↔ z` | `xn` 为认可提供跨时间、可复核、可重复呈现的证据；`z` 为长期组织提供明确认可位置、材料筛选标准与阶段收束节点 |
| `xz ↔ nz` | `xz` 提供关系可能失去、回返窗口关闭的命运压力；`nz` 提供明确回返对象、关系终点与归宿方向 |

补位必须回到具体缺口和可观察变化，不能由“五行主题公式”反推已经发生补位。

## 3｜当前可按现行表调用的机制

以下是现行关系表中“已锁定关系语义”经独立 `z/zn` 端点冻结门过滤后的可调用整理；每次使用仍须回读对应关系卡和案例证据：

| 关系 | 机制摘要 |
|---|---|
| `xn 克 zx` | 已被时间、规则、流程和前置行动组织的现实，限制即时显权扩张 |
| `zx 补 nx` / `nx 补 zx` | 直接显权与关系、身份、权限、通道借力互补 |
| `zx 克 n` | 公开显权改变成员资格、接收边界或结构运行条件，使承载能力下降、断裂或失效 |
| `xn 生 xz` | 规则化运行识别偏离，令安全路径、退路或时间窗逐步收窄，临界风险上升 |
| `x 生 x并z` | 已成立的实际掌握边界形成稳定的公开识别、调用、代表或保护壳 |
| `n 克 xz` | 真实承载、保护、处理与持续维持能力降低危险可到达性和行动紧迫度 |
| `n 补 x并z` / `x并z 补 n` | 真实内部承载与可识别公共界面互补，不能用建筑内外视觉比喻代替 |
| `xz 补 nz` / `nz 补 xz` | 失去／错过压力与特定对象回返、停靠、修复路径互补 |
| `n 生 xn` | 持续承载中的负荷、重复、遗漏或冲突被主动提炼为可运行组织结构 |
| `xz 生 zx` | 危险关闭退路或时间窗，直接使原反应资格失效并产生临时公开决定接口；只落在限定状态或关系位置层 |

这是“可按当前关系表读取”的清单，不等于任何具体作品、角色或画面自动命中。来源总览：[[01-十元系统/十元生补克表]]。

## 4｜endpoint-redefinition-freeze

关系专项索引 v2.0（2026-08-02）规定：含独立 `z` 或 `zn` 端点的旧机制在端点重定义后暂停调用。保留几何位置和历史证据，但不能把旧 `canonical-current`、旧正例或旧置信度当成当前机制：

```text
x并z 生 z
z 生 nz
x 克 z
z 克 nx
xn 补 z / z 补 xn

zx 生 zn
zn 生 n
zn 克 xn
xz 克 zn
zn 补 x / x 补 zn
```

解除冻结前，至少重新验证：

```text
新源端点成立
→ 新目标端点成立
→ 同一对象层与被改变变量
→ 拿掉测试
→ 反向测试
→ 最近邻与第三因素
→ 跨独立作品／领域复现
→ 现行置信度门槛
```

当前只允许写：`research-active`、`deferred`、`none` 或 `待二审`，不能把冻结关系写成已锁定。

## 5｜每次关系调用的最小记录

```yaml
relation_call:
  analysis_object:
  object_layer:
  current_window:
  source_endpoint:
  target_endpoint:
  relation_type: none | 生 | 克 | 补
  mechanism:
  changed_variable:
  before:
  after:
  third_factor:
  removal_test:
  reverse_test:
  nearest_neighbors: []
  evidence: []
  confidence:
  status: canonical | candidate | deferred | none | 待二审
```

如果没有 `mechanism + changed_variable + before/after`，关系只能记为 `none`、候选或待证据，不能靠一句“因此”补上缺失机制。

## 6｜与动态链的边界

动态链可以记录关系如何在阶段中出现、退出、迁移或失败，但不能仅凭动态连续性创造新的生克补关系。每条动态边须至少写：

```text
trigger
→ mechanism
→ changed_variable Δ
→ residue
→ next_affordance
```

关系类型仍须通过本页的端点与关系门；横向同阶段共存和纵向阶段变化不能互相冒充。详见 [[十元_动态链]] 与 [[08-生克补动态链研究/动态链质量评估器_v1.0_20260917]]。
