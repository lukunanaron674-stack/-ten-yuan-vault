# Canvas 管理经验

## 这次实验得到的结论

1. **Canvas 负责创作结构，不负责执行。** 主树应该回答“故事怎么分幕、卡之间怎样发散、每张卡的正式入口在哪里”，不应出现执行索引、运行状态、后台任务或模型队列。
2. **状态和创作内容分开。** 状态放进 `方志敏_项目状态.base`，正式描述词仍只放在 `02_描述词`，不要把正文复制到任务管理文件。
3. **项目下一步单独管理。** `方/项目管理/PROJECT.md`、`TASKS.md`、`STATUS.md` 只记录目标、任务、依赖、阻塞、证据和下一步，不承担生图或生视频。
4. **插件要先验证现成能力。** Meta Bind 适合简单属性表单或按钮，但不等于执行器；没有现成 GitHub 实现的 watcher、自动回写、自动 H3 链路不再自研。
5. **归档优先于删除。** 自研执行系统已移到 `方/06_归档_旧版/2026-08-26_自研执行系统归档/`，撤回前完整副本在 `方/方备份/2026-08-26_自研执行系统撤回前/`。

## 当前职责分工

- 主 Canvas：故事结构与发散关系
- `02_描述词`：正式描述词唯一真源
- `08_探索`：探索和方案实验
- `07_素材图`：图片素材
- `04_声音设计`：声音设计
- `05_画布工作台/方志敏_项目状态.base`：按状态查看镜头
- `项目管理/PROJECT.md、TASKS.md、STATUS.md`：下一步、依赖、阻塞和报告

## 当前规则

- 先整理第一幕 1-1、1-2、1-3，等用户审核后再扩展。
- 不重新引入 Meta Bind → watcher → Codex → H3 自研链路。
- 不把素材存在、候选存在或“待审核”误写成用户确认。

## 卡 Canvas 工作台规则

- 卡 Canvas 指主发散树中现有的彩色卡节点，不另造一套平铺卡 Canvas；每张卡内部按“画面描述词 → 当前画面 → 分镜时间 → 视频 → 音效／配音”查看。
- 卡 MD 只保留正式长描述词和最终结果；修改位置、短解决思路和问题清单留在卡 Canvas。
- 已解决过程回收到对应幕 Canvas；最终画面、最终视频、最终声音证据保留在卡 Canvas。
- 幕 Canvas 另设环境音、氛围音／情绪音工作区，完成后仍可点击查看。
- Base 只管理状态、阻塞、下一步、可执行性和入口链接，不复制描述词正文。
- 每轮描述词最多改3处，并记录修改位置、原文、改后、原因。
