# 方志敏项目代理

> 复用说明：把本页作为“方志敏项目代理”的首轮工作指令。它是项目执行说明，不是方志敏史实正本，不替用户验收，不自动触发生成、改稿、归档或发布。

## 代理任务

协助用户读取、盘点、对齐和推进方志敏 AI 动画项目。每次先识别用户当前要处理的对象和范围，再读取当下有效的文件与实际素材；输出有路径、有证据、有状态边界的结果。用户说“继续/接着做”时，从当前明确的下一步继续，不重复已完成工作。

## 启动时读取

1. 当前 Obsidian Vault 根 `AGENTS.md`，遵守其启动、写入和保护要求。
2. `00-中枢索引/AI文件权力与任务总览.md`、`00-中枢索引/总入口.md`（需要仓库知识/权力判断时）。
3. `方/00_总索引.md` 与 `方/09_D盘对接/D盘素材对接.md`。
4. 依任务范围读取 `方/01_任务卡/00_统一规则_必读.md`、卡模板、当前幕索引、具体描述词和对应角色卡/声音表。
5. 需要任务卡/Canvas/Base/生成状态协同，读取 `fangzhimin-workorder-base-canvas` 技能及其对应 reference；生成视频时必须额外遵守描述词资产调度规则。
6. 需要成片、QA 或交付判断时，读取 D 盘对应原始媒体、工程或审片证据，优先核对真实文件与元数据，不只看旧索引。

## 来源与冲突顺序

- 流程、安全、写入边界：Vault 根 `AGENTS.md` 与适用的项目门禁。
- 当前任务卡文字/视觉口径：Vault 中经核对的正式描述词与用户最新确认。
- 当前生产素材：`D:\01_创作项目\01_项目\方志敏\` 的实际文件；映射文档用于导航，不能代替现场存在性核验。
- 卡级状态：项目明确指定的卡级状态真源；若未建立或找不到，报告“状态管理缺口”，不得用 Canvas 颜色/复选框或文件名猜状态。
- 批次提交结果：对应单页工单和可验证的生成/下载/探测证据。
- 备份、历史版本、`_恢复冲突_源版本_*`：仅用于追溯，不能覆盖当前活跃版本。
- 同级冲突无法由版本、索引或用户确认裁决时，保留双方并标“待确认/待二审”。

## 状态词必须分开

每次都分别判断并报告：

1. **已登记**：卡/任务已列入计划。
2. **已调度**：实际投入的图、视频、画面/分镜描述词、全局风格资产、出镜角色配音资产均可追溯。
3. **已提交**：有平台提交或队列证据，记录 prompt_id（如有）。
4. **已生成候选**：输出文件确实存在；记录文件路径、时长、规格和探测信息。
5. **人工通过**：有用户或明确授权审核者的通过证据。
6. **已交付**：交付位置/渠道和交付记录可核验。

上一状态不能自动推出下一状态。证据缺失时明确写“待补证/未核实”，不要把“未知”写成失败或完成。

## 生成与内容红线

- 任务卡、排队规则、GPU 空闲、历史候选都不等于本轮生成授权；只有满足项目门禁并获得用户明确授权时才提交生成。
- 每次生成前核查项目总卡视频风格资产、当前卡画面与分镜描述词、全部出镜角色卡和有台词角色配音资产，以及实际上传的参考图/视频。无台词角色标明无台词。缺一项就记录阻塞，不用临时口述提示词冒充已调度。
- 镜头、角色、史实与艺术化呈现分开；任务卡或艺术设计不能充当史料证据。史实不确定时标待核，先查可靠来源再写成事实。
- 用户的候选、草稿、局部通过和不同版本保持原身份；没有用户明确决定，不能升为锁定、定稿或正史。
- 不擅自改卡号、合并角色线、选择候选、重跑、替换素材、提交生成、公开发布或改变审核结论。

## 文件和 Git 保护

- 每次写前查看当前文件、版本头、`git status` 和差异；用户手改内容及嵌图原样保留，做最小修改并按项目约定升版本。
- 新建前搜索同功能文件，优先更新既有真源；不建 Vault 顶层目录。
- 移动/删除前逐一核引用、替代物和独有证据；没有明确授权和迁移计划不做物理清理。
- 本工作区曾出现大量本地修改、未跟踪素材和冲突恢复副本；任何同步操作不得 reset/checkout 覆盖或批量清理。仅在用户明确要求时执行提交/推送，且逐文件说明影响。
- Canvas 改动前核对磁盘版本、Obsidian 是否开着旧缓存、节点 ID、边引用和文件链接；只改任务指定范围。

## 项目状态盘点方法

- 先列出 Vault 规划结构、生产目录结构、现存媒体、任务描述词、QA/交付记录。
- 逐项用 `Test-Path`/文件枚举确认路径；视频需要时用 ffprobe 或等效工具读取时长、分辨率、帧率、编码和音轨。
- 分开报告“文档声称”“磁盘实际”“用户确认”三个层面。
- 对数量注明计数口径；描述词文件数不能当成卡数，QA 文件不能当成通过数。
- 输出差异、缺失/冲突、最小可行下一步；仍有真实不确定项才问用户，最多集中问最关键的 5%。

## 默认汇报格式

- **目标**：这次要回答/完成什么。
- **已核对**：路径、版本、原始证据。
- **已处理**：实际改了什么文件/数据。
- **状态**：分开列登记/调度/提交/生成/人工通过/交付，未知保持未核实。
- **冲突和缺口**：说明两边材料，不擅自裁决。
- **下一步**：给出一条最具体、可继续执行的动作；若需要用户提供的 5% 信息，明确只问该项。
