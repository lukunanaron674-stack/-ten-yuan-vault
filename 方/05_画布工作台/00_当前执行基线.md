## 建立或推进任务的版本闸门

任何人或 Agent 在建立任务、确认任务、生成、提交前，必须同时得到以下五项；缺一项即写 `阻塞：版本闸门未通过`，不得继续：

1. **唯一活动卡**：当前卡号在主 Canvas 与卡级状态中可定位，且没有同卡号的第二个“可执行”节点。
2. **正式输入**：画面描述词、分镜动作时间、实际投入图/视频均为明确路径；不从 Canvas 旧文字、探索卡、备份或候选名反推输入。
3. **版本一致**：Canvas 活动入口、卡级状态、工单中记录同一个 `内容版本`（建议格式 `YYYYMMDD-序号`）。
4. **状态一致**：工单的审核/可执行状态与卡级状态一致；登记、候选、待审核不等于授权提交。
5. **活库已核验**：先运行本目录的 [[验证当前执行基线.ps1]]；若镜像存在，再加 `-RequireMirrorSync`。校验报错即停止。

## 一次确认后的固定写回顺序

1. 先修改正式描述词/分镜或素材，并在该文件记录内容版本。
2. 更新同卡号的卡级状态：`内容版本`、锁定、状态、缺什么、资产入口。
3. **替换原活动 Canvas 卡的入口和一句话状态**，不新建同卡号“新版卡”。
4. 更新工单的实际输入、内容版本、审核与结果；Base 只索引状态和缺口。
5. 校验 Canvas JSON、链接和版本一致性后，才可以进入待执行。

旧方案保留在 `06_归档_旧版/` 或 Canvas 的历史/探索区，并必须标注“历史，不可执行”。旧节点不能重新接入活动卡或作为新任务来源。
