# v0.7｜Chrome 插件总控架构｜总控塔与分页工蜂

## 0. 当前失败模式

2026-05-17 用户实现了一个可视化窗口版本，但出现关键架构错误：

```text
所有页面一次性全部都有这个框，且会自动发送。
内容还不完全。
```

诊断：当前实现是 **ABAI Page Controller**，属于“每个页面都有一个控制器”。这不是总控。

真正的 F12 总控必须是：

```text
一个总控塔 + 多个分页工蜂
```

而不是：

```text
每个页面各自长出一个总控面板，并读取同一套任务状态同时执行
```

## 1. 架构第一原则

```text
总控只能有一个。
页面执行器可以有多个，但默认沉睡。
```

也就是：

```text
Side Panel / Popup / Options = 总控塔
content.js = 分页工蜂
background service worker = 调度员
chrome.storage.local = 断点仓
```

## 2. 禁止事项

### 2.1 禁止 content.js 自动开跑

content.js 注入页面后，只能注册能力，不能自动发送。

禁止：

```js
runAuto();
sendTask(tasks[index]);
```

允许：

```js
chrome.runtime.onMessage.addListener((msg) => {
  if (msg.type === 'EXECUTE_TASK') executeTask(msg.task);
});
```

### 2.2 禁止每个页面都显示完整总控面板

content.js 不应在每个页面显示完整总控 UI。

允许两种方式：

```text
方案 A：只有 Side Panel 显示完整总控，页面只显示很小的状态胶囊。
方案 B：只有 activeTabId 对应页面显示 overlay，其他页面不显示或显示 dormant。
```

### 2.3 禁止所有页面共享 running=true 后同时执行

必须加入 activeTabId / sessionLock / lease。

状态至少包含：

```json
{
  "controllerSessionId": "uuid",
  "activeTabId": 123,
  "activeUrl": "https://chatgpt.com/...",
  "running": false,
  "leaseUntil": 0,
  "index": 0,
  "tasks": []
}
```

只有满足条件的 tab 能执行：

```text
tabId === activeTabId
running === true
lease 未过期
收到 background 明确 EXECUTE_TASK 指令
```

## 3. 正确模块分工

| 模块 | 文件 | 职责 | 是否显示 UI | 是否能发送 |
|---|---|---|---|---|
| 总控塔 | sidepanel.html / sidepanel.js | 任务管理、断点、日志、CarryPacket、开始/停止 | 是，大窗口 | 不直接操作 DOM |
| 调度员 | background.js | 管 activeTabId、发消息、锁、路由、存储 | 否 | 通过消息命令 content.js |
| 分页工蜂 | content.js | 找输入框、填文本、点发送、读回复状态 | 可选小胶囊 | 只有被授权时 |
| 状态仓 | chrome.storage.local | tasks/index/running/carryPackets/logs | 否 | 否 |
| 承载器 | carry-packet.js | 每五轮生成 CarryPacket markdown | 在总控 UI 展示 | 否 |
| 适配器 | adapter-chatgpt.js | ChatGPT DOM selector 与健康检测 | 否 | 是，受调度 |

## 5. Manifest 原则

content_scripts 可以注入 ChatGPT 页面，但 content.js 默认不显示完整总控，不自动执行。

推荐：

```json
{
  "manifest_version": 3,
  "name": "Ten Yuan F12 Controller",
  "version": "0.7.0",
  "permissions": ["storage", "tabs", "activeTab", "scripting", "sidePanel"],
  "host_permissions": ["https://chatgpt.com/*", "https://chat.openai.com/*"],
  "background": { "service_worker": "background.js", "type": "module" },
  "side_panel": { "default_path": "sidepanel.html" },
  "content_scripts": [
    {
      "matches": ["https://chatgpt.com/*", "https://chat.openai.com/*"],
      "js": ["content.js"],
      "css": ["overlay.css"],
      "run_at": "document_idle"
    }
  ]
}
```

## 6. 启动流程

正确启动顺序：

```text
1. 用户打开 Side Panel。
2. 用户选择当前 ChatGPT tab 为 activeTab。
3. Side Panel 写入 activeTabId。
4. 用户点 Resume / 自动续跑。
5. background 给 activeTab 发送 EXECUTE_TASK。
6. content.js 收到命令后才填入并发送。
7. content.js 回报 SENT / WAITING / DONE / ERROR。
8. background 推进 index。
9. sidepanel 刷新状态。
```

## 7. content.js 工蜂协议

content.js 只监听命令：

```js
chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  switch (msg.type) {
    case 'PING':
      sendResponse({ ok: true, role: 'worker', capabilities: healthCheck() });
      break;
    case 'EXECUTE_TASK':
      executeTask(msg.task, msg.options).then(sendResponse);
      return true;
    case 'GET_PAGE_STATUS':
      sendResponse(getPageStatus());
      break;
  }
});
```

content.js 不允许自己读 tasks 后循环执行。

## 8. Side Panel 总控功能

Side Panel 必须包含：

```text
1. 当前 active tab 显示
2. 选择当前页为执行页
3. 任务列表编辑与导入
4. 发送当前
5. 自动续跑
6. 停止
7. 上一轮 / 下一轮 / 重置断点
8. CarryPacket 列表
9. R5 / R10 / R15 归档状态
10. 日志
11. selector 健康检测：输入框 / 发送按钮 / 停止按钮 / 最后回复节点
12. 导出断点 JSON
13. 下载 CarryPacket.md
```

## 9. 左上角页面小面板

页面 overlay 不应该是完整总控，只做状态胶囊：

```text
Ten Yuan Worker
状态：Dormant / Armed / Running / Waiting / Error
当前页是否 activeTab
最近错误
```

只有 activeTab 才可以展开为小控制面板。

## 10. 五轮记忆承载联动

v0.7 必须继承 [[v0.6-五轮记忆接力器]]：

```text
每 5 轮插入 CarryPacket 要求。
R5/R10/R15... 必须生成承载包。
Side Panel 显示 CarryPacket 状态。
支持复制 / 下载 Markdown。
下一组任务自动携带上一组承载包摘要。
```

## 11. 当前用户问题的直接修复

### 问题：所有页面都有框

修复：

```text
完整面板从 content.js 移到 sidepanel.html。
content.js 默认只注入 worker，不显示总控。
若保留 overlay，只在 activeTabId 对应页面显示。
```

### 问题：所有页面自动发送

修复：

```text
删除 content.js onload 自动 runAuto。
只能由 Side Panel → background → activeTabId → content.js 的 EXECUTE_TASK 触发。
加入 leaseLock。
```

### 问题：内容不完全

修复：

```text
默认任务生成器必须读取 v0.4-lite、v0.6 的规则。
任务模板必须包含普通轮承载缓存与五轮 CarryPacket 指令。
R5/R10 自动变成归档承载轮。
```

## 12. v0.7 验收标准

1. 打开多个 ChatGPT 页面时，不会每个页面都显示完整总控。
2. 只有 Side Panel 是唯一总控。
3. 只有 activeTab 会执行发送。
4. content.js 加载后默认 dormant，不自动发送。
5. 刷新页面后断点不丢。
6. 暂停后不会继续发送。
7. R5 能生成 CarryPacket Markdown。
8. 找不到发送按钮时进入 manual_pause，不推进断点。
9. selector 健康检测能显示输入框、发送按钮、停止按钮、最后回复节点状态。
10. 支持导出 state JSON 与 CarryPacket Markdown。

## 13. 一句话

v0.7 的核心不是“每页都有控制器”，而是“一个总控塔调度多个沉睡工蜂”。总控在 Side Panel，执行在 activeTab，记忆每五轮打包，归档交给 GitHub / Obsidian。
