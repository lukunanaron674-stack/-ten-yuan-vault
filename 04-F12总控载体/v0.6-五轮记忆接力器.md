# v0.6｜五轮记忆接力器｜Obsidian 归档承载轮

## 0. 定位

v0.6 解决长链 F12 的核心记忆问题：

```text
每 5 轮生成一次可承载轮次的 Obsidian / GitHub 归档文件，
把前 5 轮的数据压缩成“记忆承载包”，
并把这个承载包作为下一组 5 轮的起手上下文。
```

它不是页面发送器；页面发送由 [[v0.4-lite-小狗灯]] 负责。

它不是 GitHub 写入器；写入由 [[v0.5-GitHub归档回流器]]、Codex、本地脚本或 GitHub 连接器负责。

它负责规定：

```text
何时归档
归档什么
如何传给下一轮
如何最后总收束
```

## 1. 核心比喻：击鼓传花

```text
R1-R5 产出第一朵花
R5 把花包成 CarryPacket_001
R6 带着 CarryPacket_001 开跑
R6-R10 产出第二朵花
R10 把 CarryPacket_001 + R6-R10 包成 CarryPacket_002
...
最后一轮拿到所有花，生成总归档
```

这不是普通小结，而是“可传递的轮次记忆”。

## 2. 五轮承载节奏

默认规则：

```text
每 5 轮一次承载轮。
R5 / R10 / R15 / R20 / R25 / R30 ... 必须执行记忆承载。
```

如果任务总轮数不是 5 的倍数，最后一轮也必须执行最终承载。

示例：

```text
10轮任务：R5 小归档，R10 总归档
30轮任务：R5/R10/R15/R20/R25 小归档，R30 总归档
100轮任务：每5轮小归档，R100 总归档
```

## 3. 每 5 轮必须生成的文件

建议文件命名：

```text
99-归档包/<项目名>/<框名>/carry/R001-R005-记忆承载包.md
99-归档包/<项目名>/<框名>/carry/R006-R010-记忆承载包.md
99-归档包/<项目名>/<框名>/carry/R011-R015-记忆承载包.md
...
99-归档包/<项目名>/<框名>/总归档.md
```

例如本体类审稿：

```text
99-归档包/本体类41银矿/frame-归档框/carry/R001-R005-记忆承载包.md
99-归档包/本体类41银矿/frame-归档框/carry/R006-R010-记忆承载包.md
99-归档包/本体类41银矿/frame-归档框/本体类41银矿总归档.md
```

## 5. 五轮归档轮提示词模板

每到 R5/R10/R15...，任务提示词必须追加：

```text
【五轮记忆承载要求】
本轮是 R{N}，必须生成 R{N-4}-R{N} 的记忆承载包。

请输出：
1. 五轮完成表
2. 稳定结论
3. 新增结构 / 新增子型
4. 待验证灰矿
5. 污染风险
6. 下一组必须携带的上下文
7. 下一组起手指令
8. 建议写入的 Obsidian / GitHub 文件路径

这不是普通总结，而是给下一组轮次继承的 CarryPacket。
最后输出：CARRY_PACKET_R{N-4}_R{N}_DONE
```

## 6. 普通轮提示词追加

非 5 倍轮次也要维护下一次归档所需数据。普通轮末尾追加：

```text
【承载数据缓存】
请在断点包里额外输出：
- 本轮可进入五轮承载包的稳定结论：
- 本轮新增但未钉死的灰矿：
- 本轮下次必须继承的信息：
```

这样 R5 才能收集 R1-R5，而不是临时回忆。

## 8. 与 v0.4-lite 的联动

v0.4-lite 的默认任务生成器应支持：

```js
function withCarryInstruction(round, total, basePrompt) {
  const isCarryRound = round % 5 === 0 || round === total;
  if (!isCarryRound) {
    return basePrompt + ordinaryCarryCacheInstruction(round);
  }
  return basePrompt + carryPacketInstruction(round, total);
}
```

状态中应保留：

```json
{
  "carryPackets": [
    {
      "range": "R001-R005",
      "status": "generated",
      "suggestedPath": "99-归档包/.../R001-R005-记忆承载包.md"
    }
  ]
}
```

## 9. 与 v0.5 的联动

v0.6 只规定内容与路径，不负责真实写入。

写入流程仍按 v0.5：

```text
F12 生成 CarryPacket Markdown
↓
复制 / 收集
↓
Codex / 本地脚本 / GitHub 连接器写入仓库
↓
Obsidian Pull 后出现节点
```

## 10. 硬规则

1. 每 5 轮必须有承载包。
2. 承载包不是感想总结，而是下一组轮次的上下文接口。
3. 承载包必须包含“下一组起手指令”。
4. 普通轮也要输出承载数据缓存。
5. 最后一轮必须把所有承载包合成总归档。
6. 未钉死内容进入灰矿，不许混进稳定结论。
7. 文件路径必须明确到 Obsidian / GitHub 推荐位置。
8. 下一组轮次必须显式继承上一组承载包。

## 11. 一句话

v0.6 是击鼓传花器：每五轮把手里的花包成一只记忆灯笼，挂进 Obsidian / GitHub，再交给下一组轮次继续跑，直到最后一轮把所有灯笼串成总星图。
