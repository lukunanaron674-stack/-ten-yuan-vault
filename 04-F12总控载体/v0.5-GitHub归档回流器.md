# v0.5-GitHub归档回流器

## 定位

v0.5 负责把 F12 自动轮次产生的归档内容写入 GitHub，让长任务不再只依赖 ChatGPT 当前对话记忆。

它不是理论审稿器，也不是中枢脑。它只负责：

```text
归档文本 → Markdown 文件 → GitHub 仓库 → Obsidian 可视化
```

## 为什么需要它

ChatGPT 对话框的上下文会变长、会丢细节、会忘前轮。GitHub 不负责理解，但能稳定保存每一轮的归档文件。

```text
短期记忆 = 当前 ChatGPT 对话
长期外部记忆 = GitHub + Obsidian
```

只要归档轮成功写入 GitHub，后续中枢框就能重新读取、检索、整合。

## 核心能力

1. 接收归档轮输出。
2. 生成标准 Markdown 文件。
3. 按项目、框位、轮次放入正确目录。
4. 写入 GitHub。
5. 让 Obsidian 通过双链形成可视图谱。

## 最小半自动流程

```text
F12 跑到归档轮
↓
ChatGPT 生成归档 Markdown
↓
复制归档内容
↓
交给 Codex / 本地脚本 / GitHub 连接器写入仓库
↓
GitHub Desktop Pull
↓
Obsidian 出现新节点
```

## 后续全自动流程

```text
F12 看门狗确认归档轮完成
↓
回复收集器读取最后回复
↓
生成 .md 文件
↓
本地脚本 git add / commit / push
↓
GitHub 保存
↓
Obsidian Pull 后可视化
```

## 边界

v0.5 不负责：

- 判断理论质量。
- 自动决定哪些内容入库。
- 自动替代中枢框。
- 在 F12 页面里暴露 GitHub token。

安全原则：

```text
F12 页面不直接推 GitHub。
本地 Node / Codex / GitHub 连接器负责写入仓库。
```
