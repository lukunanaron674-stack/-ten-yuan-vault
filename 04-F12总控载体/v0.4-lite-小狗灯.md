# v0.4-lite｜小狗灯｜F12 可视化总控面板

## 0. 本轮归档结论

2026-05-17 实测：右下角可视化面板版 F12 总控可用，用户评价“这个可视化框非常好”。以后调度 F12 总控时，应优先复刻此版本，而不是只给裸 Console 片段。

截图特征：

```text
右下角浮动黑色面板
标题：十元 F12 总控 v0.4-lite
状态行：断点 1/10｜运行中｜等待回复完成
主按钮：发送当前 / 自动续跑 / 停止
断点按钮：上一轮 / 下一轮 / 重置断点
任务编辑框：任务列表，用 ---TASK--- 分隔
管理按钮：载入文本 / 默认10轮 / 导出断点
日志区：显示时间戳与运行状态
```

## 1. 模块定位

v0.4-lite 负责把 `v0.1-投针` 与 `v0.5-GitHub归档回流器` 中间缺失的“页面执行层”补上。

它不是理论审稿器，不负责判断内容质量；它只负责：

```text
任务文本 → ChatGPT 输入框 → 发送按钮 → 等待回复完成 → 推进断点 → 下一轮
```

在 F12 总控路线中的位置：

```text
v0.1 投针：投什么
v0.2 货架：从哪里取提示词
v0.3 工单断点：跑到哪里了
v0.4-lite 小狗灯：页面是否能发、是否生成完、断点是否推进
v0.5 GitHub 回流器：归档怎么进 GitHub
```

## 2. 必须保留的功能

### 2.1 可视化面板

必须生成一个固定在页面右下角的浮动面板，而不是只在 Console 里打印。

推荐 DOM：

```text
id = TY_F12_CONTROLLER_V04_LITE
position: fixed;
right: 16px;
bottom: 16px;
z-index: 999999;
width: 420px;
max-height: 78vh;
overflow: auto;
background: rgba(18,18,22,.96);
border-radius: 14px;
```

### 2.2 三个主按钮

```text
发送当前：只发送当前断点任务，不自动等下一轮。
自动续跑：发送当前任务，等待回复完成，推进断点，继续下一轮。
停止：停止自动续跑，但保存当前断点。
```

### 2.3 断点控制

```text
上一轮：index - 1
下一轮：index + 1
重置断点：index = 0
导出断点：下载 ty-f12-state.json
```

断点必须写入 localStorage：

```text
STATE_KEY = TY_F12_CONTROLLER_STATE_V04_LITE
```

状态字段至少包括：

```json
{
  "tasks": [],
  "index": 0,
  "running": false,
  "stopped": false,
  "lastStatus": "",
  "logs": []
}
```

### 2.4 任务分隔

任务列表必须支持用以下分隔符切分：

```text
---TASK---
```

这样一次可载入 10 轮、30 轮、100 轮。

### 2.5 默认 10 轮

默认任务可按当前项目替换。2026-05-17 当前默认任务是：

```text
继续执行【本体类 41 银矿全量审稿】R{n}/10
...
最后必须输出：TASK_DONE_R{n}
```

但这个任务内容不是 v0.4-lite 的核心。核心是面板、投递、等待、断点。

## 3. 页面识别策略

### 3.1 输入框识别

必须按优先级查找：

```js
function findInput() {
  return (
    document.querySelector('#prompt-textarea') ||
    document.querySelector('div[contenteditable="true"][role="textbox"]') ||
    document.querySelector('div[contenteditable="true"]') ||
    document.querySelector('textarea') ||
    document.querySelector('[role="textbox"]')
  );
}
```

### 3.2 发送按钮识别

不能只找旧 selector。必须同时尝试：

```js
[
  '[data-testid="send-button"]',
  '[data-testid="composer-submit-button"]',
  'button[aria-label*="Send"]',
  'button[aria-label*="send"]',
  'button[aria-label*="发送"]',
  'button[type="submit"]'
]
```

如果 selector 找不到，应 fallback 到输入框所在 form 的最后一个可见按钮。

### 3.3 生成中识别

用于等待回复完成：

```js
[
  '[data-testid="stop-button"]',
  'button[aria-label*="Stop"]',
  'button[aria-label*="stop"]',
  'button[aria-label*="停止"]'
]
```

### 3.4 回复完成检测

稳定版逻辑：

```text
1. 取最后一个 assistant 消息文本。
2. 如果文本还在变化，重置 stableSince。
3. 如果没有 stop button，且文本 6 秒不再增长，判定回复完成。
4. 超时则停止并保存断点。
```

不要只看“发送按钮重新出现”，因为 ChatGPT 页面 DOM 会变。

## 5. 复刻时的硬规则

1. 必须是“可视化面板版”，不要只给一次性脚本。
2. 必须有 `发送当前 / 自动续跑 / 停止` 三按钮。
3. 必须有 `上一轮 / 下一轮 / 重置断点`。
4. 必须有任务编辑框，并支持 `---TASK---`。
5. 必须有日志区。
6. 必须用 localStorage 保存断点。
7. 找不到发送按钮时，不许清空输入框；必须保留文本，并提示手动点发送。
8. 自动续跑时每轮必须先等待回复完成，再推进 index。
9. 回复完成检测不能只依赖按钮，必须结合“最后回复文本稳定 6 秒”。
10. 失败时必须保存断点，而不是继续乱发。

## 6. 已知问题与处理

### 问题 A：已填入输入框，但找不到发送按钮

原因：ChatGPT 页面 DOM 或按钮 selector 变化。

处理：

```text
1. 保留输入框内容。
2. 提示用户手动点发送。
3. 不推进断点。
4. 下一版补 selector。
```

### 问题 B：回复完成误判

原因：文本流还在变化，但 stop button 消失或按钮重绘。

处理：

```text
以最后 assistant 文本 6 秒稳定作为主要信号。
stop button 只作为辅助信号。
```

### 问题 C：刷新页面后任务丢失

处理：

```text
localStorage 保存 tasks/index/logs。
支持导出 ty-f12-state.json。
```

## 7. 标准使用流程

```text
1. 打开 ChatGPT 页面。
2. F12 → Console。
3. 粘贴 v0.4-lite 总控 JS。
4. 右下角出现面板。
5. 在任务框里粘贴多轮任务，用 ---TASK--- 分隔。
6. 点“载入文本”。
7. 先点“发送当前”测试。
8. 测试成功后点“自动续跑”。
9. 出错时点“导出断点”。
```
