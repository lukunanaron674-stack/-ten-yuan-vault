# v0.6-归档轮文档生成器

## 0. 定位

本文件用于约束下一波 F12 自动链条：每一批任务必须设置归档轮次，并在归档轮输出可直接保存到 GitHub / Obsidian 的 Markdown 文档。

它不是分析模板，不是创作模板，而是 F12 总控链条的收口规则。

---

## 1. 归档硬规则

```text
【归档硬规则】
每一波 F12 自动链条，必须设置归档轮次。
归档轮不能只在聊天里总结，必须输出可保存的 Markdown 文档。

每个归档轮必须生成：
1. 本轮总文档
2. 入库表
3. 污染 / 回炉表
4. 下一轮任务卡
5. GitHub / Obsidian 可直接保存的文件名

文件名格式：
YYYY-MM-DD_项目名_Rxx-Rxx_归档.md
```

---

## 2. 标准自动链结构

```text
分析轮
→ 审稿轮
→ 优化轮
→ 归档轮
→ 生成 md 文档
→ 再进入下一批
```

归档轮是硬终点，不允许省略。

---

## 3. F12 总控插入句

```text
本轮结束后必须进入归档轮，输出完整 Markdown 文档。
不得只做聊天总结。
文档必须可直接保存到 GitHub / Obsidian。
```

---

## 5. 总控判定

如果某轮没有归档文档，则该批次状态为：

```text
未封箱 / 不可入库 / 需要补档
```

如果某轮生成了可保存 Markdown 文档，则该批次状态为：

```text
已封箱 / 可入库 / 可交给 GitHub 或 Obsidian
```

---

## 6. 封存句

F12 不是只负责跑轮次，F12 必须负责把轮次烧成文档。没有归档轮，就只是聊天烟尘；有归档轮，才是仓库砖块。
