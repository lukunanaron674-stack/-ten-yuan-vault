1. Edge 扩展仍然负责真正操作 ChatGPT 页面。

## 4. 运行边界

Codex 不能直接控制 Edge 侧边栏按钮。

可行路径是：

```text
Codex
-> PowerShell / Node helper
-> localhost 本地桥
-> Edge extension background
-> ChatGPT content worker
-> ChatGPT 页面 DOM
```

也就是说，以后要让 Codex 操控 F12 总控，应优先把动作接成桥命令，而不是让 Codex 直接点 Edge UI。

## 5. GitHub 确认桥的判断

GitHub 确认可以接桥，但应分两层：

### 第一层：安全确认桥

只生成确认材料，不直接推送 GitHub。

适合桥接的动作：

- 生成 GitHub 建议路径
- 生成 Codex 写入工单
- 生成批量写入工单
- 生成 HEAD manifest
- 生成 handoff.md
- 生成 GitHub 更新确认包

这一层不需要 GitHub token，不直接改仓库，安全。

### 第二层：真正写 GitHub

真正写入 GitHub 应由 Codex / GitHub 工具 / 用户确认后的 git 流程完成。

不建议把 GitHub token 放进 Edge 扩展或本地桥。

## 7. 操作原则

1. 如果只是普通 F12 任务，走现有 bridge。
2. 如果是 GitHub 更新确认，先生成 handoff / manifest / 工单。
3. 如果要真正写 GitHub，必须经过用户确认。
4. 不把 token 写进扩展。
5. 不让 Edge 扩展直接做高风险仓库写入。
6. Obsidian vault 已连接 GitHub 时，只要把记忆写进 vault，即可进入用户现有同步链。
