# Z发散器运行记录｜OP-003 ENUMERATE_PATH_SET

> research-only。current canonical、十元信息卡/准度卡/正式关系卡、行为 evidence 正本只读。本 operator 只改变“什么值得被检索”，不直接判十元；mutation 输出必须重建 Semantic IR 并重新经过 current 十元语义解释器。

## 0｜为什么值得保留

前两轮已经解决：

1. `SHIFT_OBJECT_LAYER`：同一事件移动观察层；
2. `HOLD_CHANGED_VARIABLE_REPLACE_CONTEXT`：冻结 changed_variable 后跨 context 调用不同机制知识。

当前最明显的下一个瓶颈是 `path_set`：Semantic IR v0.1 有稳定的 `path_set` 槽，但 schema 本身并不规定 path 成员如何枚举、成员是否同层、是否现实可调用、是否属于同一 actor，也不允许 extractor 靠自然语言关键词自行猜值。

因此本轮不是“想更多办法”，而是把模糊的：

```text
还有哪些路？
```

变成：

```text
在冻结 actor / object / object_layer / current_window / changed_variable 的条件下，
枚举所有当前可合理提出的 path candidates，
再逐项审计它们是否属于同一个 relevant path set。
```

真正的查询坐标变化是：

`path_set = opaque / null / prose-summary`

→

`path_set = finite auditable interface set`。

它会改变后续“值得检索什么”：从泛搜解决方案，转成逐接口查询 routing、handoff、fallback、blocking condition、repair、bypass、delegation、parallel route、emergency route 等现实机制。

### 1.1｜research-local path record

不修改 Semantic IR schema。只在 Z research layer 临时把 `path_set` 展开成 path records：

```yaml
path_record:
  interface_id: string
  route_description: string
  actor_scope: same_actor | delegated_for_actor | system_only | unknown
  object_layer_match: same_layer | cross_layer | unknown
  changed_variable_match: same_variable | different_variable | unknown
  current_callable_status: callable | blocked | nominal_only | already_exhausted | unknown
  blocking_condition: string | null
  target_effect: string | null
  reality_anchor: string | null
  provenance: confirmed_input | source_fact | generated_candidate | unknown
```

这些子字段不是 canonical IR 新字段，也不得写回 L1/L2。最终只允许把通过审计的集合压回 `path_set` 槽，其余作为 mutation trace 保留。

## 2｜核心 guard

### G1｜enumerated interfaces ≠ complete relevant path set

模型列出 3 条路，只证明“枚举了 3 条”，不证明世界里只有 3 条。

### G2｜same target effect ≠ same path set

若 object_layer / actuator layer 不同，只因都能维持更高层结果，不能偷算成同一 path family。

### G3｜nominal route ≠ reality-callable route

制度文本、角色口头说法、理论可行方案如果当前窗口无法实际调用，只能标 `nominal_only` 或 `unknown`。

### G4｜system route ≠ actor-specific route

系统仍有路，不等于目标 actor 自己仍拥有该接口；反过来也一样。

### G5｜chosen path ≠ complete path set

主体只走了一条路，不能由这条路失败倒推出其他未走路径已经关闭。

### G6｜generated candidate ≠ confirmed path

AI 能想到 bypass，不等于该世界/制度/工程实例真的存在 bypass。生成结果只能进入 candidate audit，不能直接填 confirmed path_set。

## 3｜query_template

```text
给定 current Semantic IR：
actor={actor}
object={object}
object_layer={object_layer}
current_window={current_window}
changed_variable={changed_variable}
relation_source={relation_source}
relation_shape={relation_shape}
decision_right={decision_right}
path_set={path_set}
reentry_right={reentry_right}
future_endpoint={future_endpoint}
reality_anchor={reality_anchor}

执行 ENUMERATE_PATH_SET。只 mutation path_set，其余字段冻结。

A. 先写 SET DEFINITION：
   “什么条件满足时，一个 route 才属于本次 relevant path set？”
   必须包含 same actor scope、same object layer、same changed_variable、same current window、same target effect family。

B. 生成候选接口，至少覆盖以下类别中现实上相关者：
   direct route / repair / retry / bypass / delegated route / parallel authority /
   alternate execution node / emergency interface / reentry route / automatic route。
   不要求每类都存在。

C. 对每条 route 输出 research-local path_record，并分别判断：
   actor_scope、object_layer_match、changed_variable_match、current_callable_status、reality_anchor、provenance。

D. 分成四组：
   1) IN_SET_CONFIRMED
   2) IN_SET_CANDIDATE_NEEDS_VALIDATION
   3) OUT_OF_SET_CROSS_LAYER_OR_DIFFERENT_VARIABLE
   4) NOMINAL_OR_UNCALLABLE

E. 输出 completeness_status：
   ENUMERATED_ONLY / PARTIALLY_AUDITED / COMPLETE_RELEVANT_SET_PROVISIONALLY_SUPPORTED。
   默认不得输出 complete；只有 source/reality audit 足够覆盖已知 route families 时才允许 provisional complete。

F. 若枚举过程发现冻结字段其实错误，例如某 route 迫使 object_layer 改变，立即停止并返回：
   IR_CONFLICT_REQUIRES_REEXTRACTION。
   不允许在本 operator 内偷偷修 actor/object_layer/changed_variable/current_window。

G. 将通过审计的 path_set 压回 Semantic IR，未确认项保留 mutation trace，不冒充事实。

H. 把重建后的 IR 交给 current 十元语义解释器重新判断；不得由本 operator 直接输出十元结论。
```

## 5｜failure modes

```yaml
failure_modes:
  - REJECTED_RETRIEVAL_ONLY: 只是“再想十个办法”而没有 set membership audit
  - REJECTED_RESKIN: 同一 route 换名称/职业/题材后重复计数
  - PATH_SYNONYM_DUPLICATION: 同一现实接口被多个自然语言名字重复枚举
  - CROSS_LAYER_SMUGGLING: 高层 target-effect substitute 被塞进低层 actuator path set
  - ACTOR_SCOPE_SMUGGLING: system route 被冒充 actor-specific route
  - NOMINAL_AS_CALLABLE: 纸面存在被误判为当前现实可调用
  - CHOSEN_PATH_COMPLETENESS_FALLACY: 已走路径失败被写成完整集合归零
  - GENERATED_AS_FACT: AI 候选被直接写成 source fact
  - VARIABLE_DRIFT: route 实际改变了 changed_variable
  - WINDOW_DRIFT: 为了让 route 存在擅自扩大 current_window
  - UNKNOWN_FORCED_CLOSED: 缺证据的 path 被强填 blocked/closed
  - FALSE_COMPLETE_SET: 枚举数量有限就宣称 complete
```

## 6｜stop condition

出现任一条件即停止 mutation：

1. set definition 无法在当前 object_layer / changed_variable 下写清；
2. actor 或 current_window 无法冻结；
3. 两条以上候选 route 的 membership 取决于改 object_layer；
4. 现实锚点不足，只能继续幻想新方案；
5. 新生成 3 条以上候选都落入 OUT_OF_SET / nominal / duplicate，说明边际信息增益已耗尽；
6. 已形成稳定的 IN_SET_CONFIRMED + candidate gap 列表，立即送回解释器，不继续无限枚举；
7. 若 completeness 无法证实，停在 `ENUMERATED_ONLY` 或 `PARTIALLY_AUDITED`，不得为了漂亮输出强行 complete。

## 7｜when_not_to_use

- `object_layer` 或 `changed_variable` 仍是 unknown：先补 IR；
- 用户只是想找同类案例：用 nearest-neighbor，而不是本 operator；
- 需要换观察层：用 SHIFT_OBJECT_LAYER；
- 需要跨 domain 调用机制知识：用 HOLD_CHANGED_VARIABLE_REPLACE_CONTEXT；
- 需要测试一个具体条件是否必要：用 REMOVE_CONDITION / freeze-one-variable；
- 只有单一路径且结构上不存在 alternate route 概念时，不强行枚举；
- 任务目标是十元最终分类而不是发散查询时，本 operator 只能作为前置研究工具。

## 8｜跨领域测试

> 以下测试只验证 operator 是否打开新的结构查询空间，不累计为任何 xn/十元案例库，也不更新 behavior evidence。

### T1｜《西游记》孙悟空被逐后的回返接口

输入层固定：

```text
actor = 孙悟空
object = 重返师徒/取经共同关系
object_layer = bilateral-reentry interface layer
current_window = 被逐后至恢复共同西行前
changed_variable = 当前可调用的对象特异回返接口
```

若原输入只写“悟空还能回去”，普通检索会搜更多回归剧情。

ENUMERATE_PATH_SET 改为检索：

- direct request
- mediated route（如通过既有中介）
- recognition/adjudication route 是否只是支持 reentry，而不是独立 reentry path
- 任务成员资格恢复是否属于更高 object_layer，应排除

结构空间变化：从“回不回得去”变成**哪些 route 真正属于同层 reentry set**。

结果：PASS。能产生 IN_SET / cross-layer / supporting-interface 分账。

### T2｜《三国演义》关羽麦城撤离路径

冻结：

```text
actor = 关羽
object = 脱离当前封锁并继续撤离
object_layer = battle-level escape route
changed_variable = current relevant escape paths
```

候选至少区分：

- 已实际选择的小路
- 文本明确提及但未选择的大路
- 求援/守城是否属于不同 changed_variable 或不同阶段

operator 迫使模型承认：

`chosen path exhausted ≠ complete path set exhausted`。

结果：PASS。它不是再找三条“逃生妙计”，而是暴露未测试大路这一 completeness gap。

### T3｜工程：航天器供电路径

冻结低层：

```text
object_layer = same actuator family
changed_variable = surviving same-family generation paths
```

候选：

- 同族多个 generation units
- repair/restart path
- LM alternate power
- CM battery

审计后，若 LM/CM 属于更高层“维持任务电力”target-effect routes，则必须进入 `OUT_OF_SET_CROSS_LAYER_OR_DIFFERENT_VARIABLE`，不能因为“都能供电”就塞回低层 path_set。

结果：PASS。直接防止 same target effect 偷换 same path set。

### T4｜制度：采购审批

冻结：

```text
actor = 某项目负责人
object = 单笔采购获得当前有效批准
object_layer = approval-interface layer
current_window = 当前采购周期
changed_variable = 该 actor 当前可调用的有效审批路径
```

候选机制：

- direct approver
- delegated approver
- emergency procurement route
- threshold-based automatic approval
- parallel compliance/security sign-off

审计要求判断哪些是：

- 替代批准路径；
- 只是前置条件；
- 只对其他 actor 可用；
- 只在紧急状态触发；
- 纸面存在但当前不可调用。

结果：PASS。把“审批很复杂”改写成有限接口与触发条件集合，明显打开制度机制检索空间。

### T5｜现实运营：医院 ICU 床位进入路径

冻结：

```text
actor = 当前患者/治疗团队（主体归属单独标）
object = 进入 ICU 的现实接收路径
object_layer = admission-routing layer
current_window = 当前住院窗口
changed_variable = 当前可调用的 ICU admission routes
```

候选：急诊直接转入、普通病房升级、手术后转入、院际转运、行政例外。

operator 会强制区分：

- 同一患者当前可调用；
- 只对另一类患者开放；
- 只是床位释放条件；
- 院际转运属于进入本院 ICU 还是换了 object；
- “有 ICU 床”这种 system-level capacity 是否等于 actor-specific route。

结果：PASS。能产生 actor_scope 与 callable-status 的结构差异，而非医疗题材换皮。

## 9｜防退化 probes

### Probe-R1｜同义路径重复

```text
直接申请 / 正常申请 / 标准流程申请
```

若三者指向同一现实接口、同一 decision node、同一触发条件，只能算一条。

判定：`REJECTED_RESKIN`。

### Probe-R2｜只要求更多办法

```text
“再想 20 种让关羽逃出去的方法。”
```

这扩大想象集合，没有冻结当前 reality anchor，也没有 set membership audit。

判定：`REJECTED_RETRIEVAL_ONLY`。

### Probe-R3｜题材换皮

```text
大路/小路 → 主线路由/备用路由
```

若只是把古典叙事术语换成工程术语而 topology、membership、callability 都没变化：

判定：`REJECTED_RESKIN`。

### Probe-R4｜幻想 bypass

```text
“也许还有密道 / 隐藏管理员 / 未公开 API。”
```

只能进入 `IN_SET_CANDIDATE_NEEDS_VALIDATION`；没有 reality anchor 时不得计 confirmed。

这不是 reskin，也不是 retrieval-only，而是 `GENERATED_AS_FACT` 防护测试。

### 与 current Semantic IR extractor 的兼容性

current extractor 的硬规则是：只有 caller-confirmed structural observations 才能填槽；没有确认的字段保持 `null`。因此 OP-003 不能把 AI 生成候选直接当作 `confirmed_fields.path_set`。

正确链路：

```text
raw / partial Semantic IR
→ ENUMERATE_PATH_SET candidate expansion
→ reality/source validation
→ only confirmed members may populate/rebuild path_set
→ unconfirmed members stay in mutation trace
→ current semantic interpreter re-check
```

这与 `KEEP_UNKNOWN` 原则一致：没有证据时保持未知，比伪造“完整路径集合”更有价值。

## 12｜下一最高价值 mutation

`REPLACE_DECISION_HOLDER`。

理由：OP-003 已经能把 route 拆出来，但 route 是否现实可用通常取决于**谁拥有最终 decision_right / veto / override / delegated authority**。下一轮最有价值的正交 mutation 是冻结 actor、object、object_layer、changed_variable、path topology，仅替换 decision holder，观察：

- 同一路径在不同 holder 下是否从 callable → blocked；
- delegated authority 是否真的等于 final decision right；
- consultation / execution / co-decision / veto 是否会改变 path membership；
- AI 是否会因“上级/领导/管理员”关键词误把建议权当最终决定权。

它能把 OP-003 的“路径存在性”继续推进到“路径由谁真正打开/关闭”，而不是继续堆 route 数量。
