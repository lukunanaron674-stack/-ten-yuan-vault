# 金轴 xn↔z｜多数投票与多签：规则聚合不等于单中心裁定

> L4 research-only。本文件只测试“多数投票 / quorum / 多签是否天然构成 xn”这一缺口，不修改 L1/L2 canonical、信息卡、准度卡、关系卡或行为 evidence 正本。

## 0｜本轮缺口

上轮 `DELEGATION-INDEPENDENCE-GATE-v0.1` 已验证：可撤回授权仍可属于 `z`，真正的 `xn` 需要现实效力不依赖单一中心持续许可。

但上轮有一句操作化过严：

```text
多个节点各自能独立触发现实状态迁移
```

这会误伤合法的阈值聚合结构，例如 `2-of-3` 多签：单个签名本身不能完成发布，但每个节点都提供不可由单一中心替代的独立裁定贡献，最终状态由预先规则机械聚合，而不是由某个最高中心再次裁定。

本轮新增候选门：

`AGGREGATION-NOT-CENTER-GATE-v0.1`

核心变量：

```text
binding_effect_source_distribution
+
aggregation_rule_overrideability
```

## 1｜current criterion

current canonical：

- `xn`：运行权/判断权分布到顺序、规则、记录、节点与流程；
- `z`：判断权与结构重心收束到单一最高中心或最终裁定点。

本轮操作化修正：

```text
xn 不要求每个节点单独完成最终状态迁移。
```

更准确地写：

```text
多个独立节点产生现实有效的裁定贡献
+ 贡献由预先规则/阈值机械聚合
+ 没有单一中心可以在同层同窗内任意覆盖聚合结果
→ xn candidate

多个节点只产生输入/建议/签名前置材料
+ 结果仍需单一中心自由决定是否采纳
→ z
```

因此：

```text
collective aggregation ≠ single center
```

关键不是“最后是否出现一个结果”，而是“最后结果由谁/什么生成”。

## 2｜strict 同层同窗最小差异对

固定系统：同一动画项目发布许可。固定 actor、object、object_layer、current_window、三名审核者、材料、节点数、顺序、记录、阈值 `2-of-3`。只改变聚合结果是否需要一个最高中心再次自由裁定。

object_layer: current_release_authorization

  reviewer_A: independent_vote
  reviewer_B: independent_vote
  reviewer_C: independent_vote
  chair: no_same_layer_override

  - A_vote

  - C_vote
  - threshold_2_of_3

reality_anchor:
  - 任一审核者的票都真实计入阈值
  - 任意两票同意即自动形成当前轮发布许可
  - 主席/导演不能在当前轮无条件改写 2-of-3 结果

这里的 `xn` 来自“裁定贡献 + 聚合规则”的分布结构，而不是要求任一单票都能独立完成发布。

### T2｜边界：主席只在平票时按预先规则投 tie-breaker

固定三节点改成四节点形成 2:2 可能；主席只有在精确平票时，按预定义 tie-break 条款投一票，不能覆盖非平票多数。

```yaml
actor: same_system
object: same
object_layer: same
current_window: same
changed_variable: scope_of_tie_break_power
relation_source: bounded_rule_defined_tie_break_node
relation_shape: distributed_rule_with_conditional_extra_node
decision_right:
  reviewers: independent_votes
  chair: conditional_vote_only_on_tie
path_set:
  - four_votes
  - majority_rule
  - chair_tie_break_only_if_2_2
reentry_right: normal_round_rules_apply
future_endpoint: rule_defined_aggregate_result
reality_anchor:
  - 主席没有普遍覆盖权
  - 只能在规则预先定义的 2:2 条件下增加一票
  - 3:1、4:0 等结果不能被主席翻转
```

判定：

```text
xn PASS 0.93
z FAIL 0.88
```

原因：tie-breaker 是规则中的一个条件节点，不是同层普遍最终中心。

若把 tie-breaker 改成：

```text
主席可在任何票型下最终否决/翻转
```

则立即向 `z` 坍缩。

## 4｜最小判别式

```text
“最后只有一个结果” ≠ z
“参与者很多” ≠ xn
```

真正的最小式：

```text
xn:
multiple independent binding contributions
+ rule-bound aggregation
+ no universal same-layer override

z:
distributed inputs may exist
+ one center retains free terminal adoption/override
```

对多签进一步压缩：

```text
k-of-n signature
若签名直接计入不可任意覆盖的规则阈值
→ xn candidate

k-of-n signature
若只是给最终负责人凑材料/建议
→ z
```

## 6｜removal test

### 从 T0 移除“主席”这个职位名

结构不变：

```text
三票 + 2-of-3 阈值直接生效
```

仍是 `xn`。

### 从 T0 移除任一单票的“独自终止权”

本来单票就没有独自完成发布的权力；只要票仍真实计入阈值，`xn` 不消失。

这证明：

```text
individual_unilateral_state_change
不是 xn 必要条件。
```

### 从 T1 移除主席自由覆盖权

若 2-of-3 结果因此直接生效，则 `z` 的关键来源消失，结构转向 `xn`。

## 9｜positive / negative controls

### positive control｜xn

`2-of-3` 多签直接触发部署密钥释放；没有任何单一负责人可以在阈值满足后同层随意改写。

```text
→ xn PASS
```

### negative control｜z

委员会 5:0 同意，但 CEO 保留完全自由的最终批准权，且可以不说明理由地拒绝。

```text
→ z PASS
```

### negative control｜假 xn 多签

三个部门签字只是“材料齐全”条件；材料齐全后仍由局长自由决定是否批准。

```text
多签存在
但 final adjudication source = one center
→ z
```

### boundary control｜unanimity

`3-of-3` 一致同意才直接生效，且没人拥有额外覆盖权：

```text
仍可为 xn
```

因为每个节点都拥有不可替代的规则内 binding contribution，最终状态由分布节点共同形成，并不因为“要求全票”就变成单中心。

## 11｜失败类型

- `VOTE_COUNT_AS_XN`：看到多人投票就判 xn。
- `SINGLE_OUTPUT_AS_Z`：看到最终只有一个结果就判 z。
- `EACH_NODE_MUST_BE_UNILATERAL`：错误要求每个 xn 节点都必须单独改变最终状态。
- `ADVISORY_MAJORITY_AS_BINDING`：建议性多数误判真实分布裁定。
- `QUORUM_AS_AUTHORITY`：仅有 quorum 数字但结果仍由中心自由采纳，误判 xn。
- `TIE_BREAKER_AS_AUTOMATIC_Z`：存在平票裁决节点就自动判 z，忽略其是否只是受限规则节点。
- `CHAIR_VETO_HIDDEN_BY_VOTING`：大量投票表象遮蔽主席普遍否决权。
- `UNANIMITY_AS_SINGLE_CENTER`：全票规则误判单中心。

## 12｜本轮裁定与成熟度

本轮形成新机制与 guard，足以提交。

核心结论：

> `xn` 的“分布”可以分布在多个独立裁定贡献与一条不可被单中心任意覆盖的聚合规则上；它不要求每个节点都单独完成最终状态迁移。真正把结构拉向 `z` 的，是一个单一中心在同层同窗内保留对聚合结果的自由终局采纳、否决或改写权。

因此对上轮门做 L4 精化：

```text
旧：多个节点各自能独立触发现实状态迁移

修正：多个节点各自提供独立、现实有效的 binding contribution，
这些贡献可由预先规则聚合形成状态迁移，
且不存在单一中心的普遍同层覆盖权。
```

不需要修改 L1。

研究层成熟度建议：`8.0 -> 8.4 / 10`。

## 13｜下一断点

下一轮只测试：

```text
“单一否决节点”是否必然把 xn 拉回 z？
```

重点区分：

1. 多个并列节点各自拥有局部/对称 veto；
2. 一个节点拥有全局 universal veto；
3. 一个节点只有狭窄对象域 veto；
4. veto 只阻止当前轮，但不能自行生成正向最终许可。

目标是建立 `LOCAL_VETO / UNIVERSAL_VETO / FINAL_ADJUDICATION` 三者的最小差异门，避免把任何 veto 都当成 `z`。
