# 十元语义解释器候选 L4

> 研究用途。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得作为正式 evidence 正本。

## 2026-09-06｜nx 翻译校准：外部来源在场 ≠ nx 已激活

### 1. 本轮翻译债务

模型容易看到“老板、命令、制度、求人、关系、授权、组织”就把句子直接翻译成 nx。当前木轴研究已经明确：关系/身份存在不等于当前 nx 在线；任务发出不等于任务已经接入；外部对象或处分域在场也不等于主体真实沿接口推进。

因此本轮新增的是 **IR 字段解耦约束**：

```text
relation_source = external
不能单独推出 nx。

nx positive 必须至少同时检查：
1. external relation/direction/permission/path 是否在 current_window 内真实激活；
2. actor 是否在 tested object_layer 上不占 final decision source；
3. path_set 是否至少包含一条 actor 实际沿用的 external route；
4. 若 external route 被拿掉，同一推进是否在该层出现现实缺口。
```

### 2. 自然语言 → IR 结构还原规则

按以下顺序还原，禁止先贴十元标签再反填字段：

1. **actor**：谁在行动；多主体时只选当前被判主体。
2. **object / object_layer**：这句话实际推进的对象是什么，发生在哪一层。不得把“公司/军队/家庭”整体层吞掉具体任务层。
3. **current_window**：只截取该外部接口真实进入行动链的窗口；历史关系只做背景。
4. **changed_variable**：本句真正变化的是方向来源、权限入口、执行组织、对象归属、终点、回返权，还是别的变量。
5. **relation_source**：方向/许可/资源/解决接口来自 self / external / shared / unknown。
6. **decision_right**：tested layer 的最终方向决定权在 self / external / shared / unknown。注意：执行自由 ≠ final decision right。
7. **path_set**：列出本窗口真实可用且被主体采用/可调用的路径；仅“知道有人可帮忙”不算 activated path。
8. **reentry_right**：主体能否退出后自行重新接入，或必须再次经外部节点许可。
9. **future_endpoint**：本句是否锁定长期归向；若只是局部任务，保持 null/unknown，禁止倒灌人物终局。
10. **reality_anchor**：哪条现实拨动证明外部接口不是名义装饰，例如“拒绝→结果停住；放行→恢复”。

### 3. Positive decision gate｜nx candidate

```text
G1 object_layer 明确；
G2 current_window 明确；
G3 relation_source ∈ {external, shared-with-external-gate}；
G4 至少一条 external path 在 current_window 内真实 activated；
G5 actor 在 tested layer 不占最终方向源，或同一结果仍受外部许可/资源/接口现实约束；
G6 removal external route → 同层推进出现可命名现实缺口；
G7 若 actor 自己搭执行骨架，只能并存检查 xn，不能因此否掉 nx；
G8 若 actor 直接压掉原外部接口的否决/处分能力并公开改写结果，转查 zx，而非继续强判 nx。
```

G1–G6 未通过，不判 nx positive。G7/G8 是最近邻分流门。

### 4. 标准输入与完整 IR

输入：

> “老板已经决定本周上线新版，小林按老板给的上线目标去找法务审批；法务没批之前他不能发布，获批后他自己安排测试和发布时间。”

```yaml
actor: 小林
object: 新版上线
object_layer: 上线许可与上线任务层
current_window: 老板下达上线目标 -> 法务审批 -> 获批后进入发布准备
changed_variable: external_permission_route_activated
relation_source: external
decision_right: shared_layered
path_set:
  - 老板给定上线目标
  - 法务审批接口
reentry_right: external_permission_required
future_endpoint: null
reality_anchor: 法务未批则不能发布；批准后发布链恢复
```

判定：**nx candidate PASS**。理由不是“有老板/有法务”，而是外部任务方向与许可接口都真实进入 current action chain，且许可节点能现实卡住同层结果。获批后“小林自己安排测试和发布时间”另行检查 xn，不抹掉上位任务/许可层 nx。

### 5. nearest neighbors

#### nx vs xn

```text
nx：谁给方向/许可/外部接口？主体是否沿它推进？
xn：谁搭计划、排程、节点、人员、运行结构？
```

最小差异：同一 actor 可以“上位任务 nx + 局部执行 xn”同时成立。不能因为执行很主动就把 relation_source 从 external 改成 self。

#### nx vs x

```text
nx：关键资源/许可/解决接口仍在外部，主体需经接口取得。
x：资源/对象/权限已经稳定进入主体直接调用边界。
```

最小差异：`reentry_right` 与 `path_set` 很关键。主体若退出后仍可直接自行调用资源，且外部节点没有同层现实否决，优先转查 x；“组织里有人参与”不等于 nx。

#### nx vs zx

```text
nx：沿既有外部方向/权限/关系通道。
zx：主体公开把自身方向压入现实，并扩大/改写决定范围。
```

最小差异：成功利用外部通道不等于 zx；反过来，外部制度在场也不等于 nx。若主体直接取消该接口的现实否决并公开改写同层结果，应转查 zx。

### 6. false-positive guards

1. **关键词护栏**：“求人、领导、制度、审批、关系”只触发字段提取，不触发 nx 标签。
2. **历史关系护栏**：长期隶属/亲属/旧交存在，但本窗口未调用，不算 activated path。
3. **任务发出护栏**：命令已发但主体拒绝承接、改写最高方向或转入另一独立通道，不能因“收到命令”判 nx。
4. **名义权限护栏**：外部节点只有头衔或建议权，无法卡住同层结果，不足以证明 nx。
5. **复杂执行护栏**：主体沿外部目标推进同时自行搭流程，可是 nx+x n 分层并存，不得互相吞掉。
6. **对端缺席护栏**：没有 zx / 没有自主决定，不等于 nx 自动成立；必须仍有 activated external route。

### 7. removal / reverse / same-layer / current-window

**Removal**：拿掉被测 external relation/path。如果 actor 在同 object_layer、同 current_window 内仍能稳定实现同一推进，且不需等价外部接口，则 nx 证据显著下降。

**Reverse**：保留“老板/制度/关系”等关键词，但把 reality_anchor 改为“外部节点反对也无法阻止，同一结果照常发生”。若模型仍判 nx，说明把 relation_source 名词误当成现实路径。

**Same-layer**：高层任务来自外部，不得自动把局部执行层全部判 nx；局部可另判 xn/x/zx。反过来局部自主也不能擦掉上位 external gate。

**Current-window**：历史上曾依赖某人，不得跨阶段永久标 nx；当前窗口必须看到接口重新进入行动链。

### 8. adversarial tests

#### T1｜关键词诱导
输入：“他求人很多，但这些人都没有权限，最后他自己直接完成了审批。”
IR 摘要：relation_source=external-attempted；path_set=external routes ineffective；decision_right=self；reality_anchor=external refusal/non-help does not block result。
结论：**nx FAIL**。关键词“求人”不能替代有效外部路径。

#### T2｜题材/职业/情绪诱导
输入：“她是一个温顺的秘书，整天安静地坐在公司里，但项目方向和发布权限都由她自己最终决定。”
IR 摘要：actor=秘书；object_layer=项目方向/发布；relation_source=self；decision_right=self。
结论：**nx FAIL**。职业、温顺、办公室题材均不得倒推。

#### T3｜对象层错位
输入：“将军奉皇帝之命出征，但具体阵型、兵力分配和行军节奏全由将军自行设计。”
IR：高层 object_layer=征战任务，relation_source=external → 可检查 nx；局部 object_layer=运行结构，changed_variable=execution_structure，decision_right=self → 转查 xn。
结论：**不能把整句一锅判 nx**；必须分层。

#### T4｜时间窗错位
输入：“三年前他靠叔父介绍入职；现在已经独立掌管部门，当前项目无需叔父或任何旧关系介入。”
IR：current_window=当前项目；relation_source=self/current-org；旧叔父关系不在 path_set。
结论：**nx FAIL（当前窗口）**。

#### T5｜同关系词异对象层
输入A：“她请朋友把文件送到法院。”
输入B：“她请朋友替她决定是否撤诉。”
A：relation_source=external assistance；object_layer=物流执行；final_decision=self，是否 nx 需看该递送是否为不可绕外部接口。
B：object_layer=案件方向；若朋友实际拥有并行/上位决定权且她沿其决定推进，nx 证据更强。
结论：同样“请朋友”，对象层不同，不能同标签直译。

#### T6｜对端不存在不等于本端成立
输入：“他没有自己的方案，也没接受任何人的方案，只是停在那里什么都没做。”
IR：relation_source=unknown/null；path_set=[]；decision_right=unknown；reality_anchor=null。
结论：**nx FAIL/UNKNOWN**。没有 zx 或没有主见，不等于已有 external route 被承接。

#### T7｜任务已发但未接入
输入：“领导让她调岗，她明确拒绝，随后辞职并走自己的创业路线。”
IR：relation_source=external-offer；path_set=external task not activated；decision_right=self after refusal；current_window=拒绝后。
结论：**nx FAIL（该任务层）**。命令存在 ≠ 承接。

#### T8｜名义审批伪 gate
输入：“委员会形式上要签字，但过去十次都只能备案，无法阻止负责人发布；这次负责人也照常先发布后补签。”
IR：relation_source=external-formal；decision_right=self-in-effect；reality_anchor=external objection cannot stop same-layer result；path_set=committee not a blocking path。
结论：**nx FAIL 或极弱，不得 positive**。

### 9. 本轮新增翻译规则

新增候选规则 `NX-IR-ACTIVATION-v0.1`：

> **外部来源只负责把 IR 的 relation_source 标成 external；只有当 external route 在 current_window、same object_layer 内真实进入 path_set，并且存在现实约束/缺口证据时，才允许把 nx 从 UNKNOWN 提升为 candidate-positive。**

附属约束：

```text
relation_source ≠ decision_right
relation_source ≠ activated path
historical relation ≠ current path_set
task issued ≠ task accepted
external actor present ≠ external veto effective
absence of opposite pole ≠ target pole positive
```

该规则是解释器层候选，不是 canonical 定义修改。

### 10. 下一轮风险

优先检查 **n vs nx**：自然语言里的“跟随别人 / 被关系牵引 / 顺着某人走”很容易把“关系本身的牵引”与“沿外部权限/任务通道推进”混写。建议下一轮专门让 `relation_shape` 与 `relation_source/path_set` 分账。
