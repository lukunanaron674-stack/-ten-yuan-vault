# 十元语义解释器｜n vs xz：持续承载负荷与未来选项收窄分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖或修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜目标与翻译债务

目标混淆对：`n ↔ xz`。

高风险自然语言：

```text
越拖越重。
越陷越深。
越来越难撑。
再这样下去就没办法了。
事情越来越糟，最后只能这样。
```

这类句子至少可能描述两种完全不同的结构变化：

```text
n：同一对象仍在内部，时间、空间、照护、风险或资源负荷持续被承担，负荷强度可以上升。

xz：同层现实路线、退路、时间窗或可逆空间持续失效，未来选项集合变小并朝前置终点汇流。
```

本轮新增：

```text
LOAD-MAGNITUDE-vs-OPTION-SET-CONTRACTION-v0.1
LOAD-BEARER_AUDIT_REQUIRED
OPTION-SET-SNAPSHOT_AUDIT_REQUIRED
BURDEN-INCREASE-does-not-imply-OPTION-LOSS
OPTION-LOSS-does-not-imply-CARRYING
```

核心不变量：

```text
load magnitude change != option-set cardinality change
burden accumulation != future-space contraction
harder to carry != fewer realistic exits
fewer exits != someone is carrying the object
```

若同一事件同时出现“持续承载”与“现实未来收窄”，强制 `SPLIT_IR`，不得把两种变化写进同一个 `changed_variable`。

## 1｜Canonical guard

current canonical 对本轮具有最高权威：

```text
n：外部对象进入内部，被允许留下，并由主体或结构跨阶段持续接收、处理、保护和承担现实负荷。

xz：未来终点先获得结构地位，过程推进时退路、时间窗、路线和可逆空间持续收窄，现实选择向该终点汇流。
```

本研究只增加自然语言到 IR 的解释器约束，不改定义。

## 2｜自然语言 → IR 结构还原规则

### 2.1 禁止“情况变糟”作为终止解析

禁止：

```text
changed_variable: situation_getting_worse
```

必须继续还原“变的是什么”：

```text
护理小时、占用空间、维护成本、风险处理、协调责任、长期资源消耗增加
→ sustained_load / carrying_load

可用路线、退出方案、剩余时间窗、可逆步骤、现实未来方案减少
→ real_option_set / reversibility_window
```

### 2.2 n 的结构还原

```text
external object enters/exists inside
→ object remains across stages
→ identifiable actor/structure bears recurring real load
→ load is actually handled
```

`path_set` 应写承载路径，如：

```text
daily care
night observation
maintenance
risk handling
resource replenishment
repeated coordination
```

不得把“未来路线集合”塞进 n 的 `path_set`。

### 2.3 xz 的结构还原

```text
same-layer realistic options existed
→ current_window contains comparable snapshots
→ options/time windows/reversible paths become unusable
→ future_endpoint becomes more structurally dominant
```

`path_set` 应表达同层现实替代项或 snapshot，如：

```text
t0: [route_A, route_B, route_C]
t1: [route_B, route_C]
t2: [route_C]
```

不得把“护理步骤越来越多”当作 xz 收窄。

## 3｜标准输入句

> 暴雨后，山区救助站接收了十二名暂时无法下山的老人。第一周每天需要两名护理员和一次送药；第二周三人出现感染，需要增加夜间观察、氧气、消毒和转诊联络，站内每天实际投入的护理时间和物资持续增加。与此同时，山下原本有东、西、南三条撤离路线；东线因塌方失效，随后西线桥面封闭，当前只剩南线仍能通行，而且气象部门预计六小时后南线也可能关闭。

同一段自然语言必须 `SPLIT_IR`。

## 4｜完整 IR-A：n

```yaml
actor: 山区救助站
object: 十二名暂时无法下山的老人及其持续照护需求
object_layer: internal_sustained_care_and_load_layer
current_window: 入站安置 -> 第一周基础照护 -> 第二周感染增加 -> 夜间观察/氧气/消毒/转诊联络持续执行
changed_variable: sustained_internal_carrying_load
relation_source: emergency_admission_and_continuing_care
relation_shape: admitted_objects_remain_inside_while_recurring_load_is_actually_borne
decision_right: care_execution_within_medical_and_emergency_constraints
path_set:
  - daily_basic_care
  - medication_delivery
  - night_observation
  - oxygen_support
  - disinfection
  - referral_coordination
reentry_right: null
future_endpoint: null
reality_anchor: 老人持续留在站内，第二周护理时间、夜间值守、氧气、消毒物资与转诊协调均真实增加，并由救助站跨阶段承担
```

判定：`n PASS`。

这里“越来越难撑”由**承载负荷上升**解释，不得因此自动填 `xz`。

## 5｜完整 IR-B：xz

```yaml
actor: 山区撤离环境与调度结构
object: 老人从救助站安全下山的现实撤离选项集合
object_layer: same_layer_real_evacuation_option_set
current_window: t0=[东线,西线,南线] -> t1=[西线,南线] -> t2=[南线] -> six_hour_closure_risk
changed_variable: real_option_set_and_time_window_contraction
relation_source: staged_route_failure_and_weather_closure
relation_shape: mutually_substitutable_real_routes_progressively_removed_toward_no_safe_exit
decision_right: null
path_set:
  - t0: [东线, 西线, 南线]
  - t1: [西线, 南线]
  - t2: [南线]
reentry_right: 东线与西线在当前灾害窗口内不可直接恢复
future_endpoint: 六小时后可能无安全撤离路线
reality_anchor: 东线因塌方、西线因桥面封闭分别退出可用集合，现实撤离路线从3条降到2条再降到1条，剩余时间窗继续缩短
```

判定：`xz PASS`。

这里“越来越没办法”由**现实选项集合收窄**解释，不得因为压力大而自动填 `n`。

## 6｜Positive decision gate

### n gate

至少满足：

1. `object` 已真实进入或留在主体/结构内部；
2. `current_window` 跨至少两个阶段；
3. `object_layer` 是现实承载/照护/资源/风险层；
4. `path_set` 至少含一个持续或重复的 carrying path；
5. `reality_anchor` 明确谁承担对象继续存在造成的负荷；
6. “很重、很麻烦、很惨”不能补结构。

最短门：

```text
object remains inside
+ recurring real load exists
+ actor/structure actually bears it
→ n candidate
```

### xz gate

至少满足：

1. `object_layer` 是同层现实未来选项、路线、退路、时间窗或可逆空间；
2. `current_window` 能比较至少两个时点；
3. 初始存在两个以上现实可调用选项，或明确存在可逆空间；
4. 至少一个选项/时间窗随后真实失效；
5. `future_endpoint` 获得更强结构地位；
6. `reality_anchor` 能说明哪条路/哪个机会为什么没了，而非只说压力变大。

最短门：

```text
same-layer realistic options existed
+ options/time/reversibility are actually removed
+ future endpoint becomes harder to avoid
→ xz candidate
```

## 7｜Nearest-neighbor 最小差异

### A｜负荷增加，但出口不减少

```text
同一病人护理从每天1小时变成每天5小时，
但转院、回家、换机构三个方案始终全部现实可用。
```

预期：`n ↑ / xz FAIL或不变`。

### B｜出口减少，但没有持续承载

```text
登山者仍在山外自行行动，
三条下山路线因天气变成一条，
没有任何组织把他接入内部并持续照护。
```

预期：`xz ↑ / n FAIL`。

### C｜双层并存

```text
避难所持续照护伤员
+
外部安全通道从3条缩到1条
```

预期：`n + xz` 可同时 PASS，但必须 `SPLIT_IR`。

## 8｜False-positive guards

1. “越来越严重”不得直接映射 n 或 xz；
2. “越拖越重”若只说明成本上升，不得自动判 xz；
3. “没办法了”若没有历史选项与真实失效，不得判 xz；
4. 对象长期存在但无人持续处理其负荷，不足以判 n；
5. 工作量增加不等于未来路线减少；
6. 待办数量减少不等于 xz；
7. 时间过去本身不等于时间窗收窄，必须存在现实机会/可逆性失效；
8. 压力、悲惨、紧张、职业、灾难题材均不得补结构；
9. `n FAIL` 不推出 `xz PASS`，反之亦然；
10. 一个 IR 若同时写 `load ↑ + options ↓`，必须拆分。

## 9｜Adversarial tests

### T1｜关键词诱导

> 事情越来越重，已经快没办法了。

没有对象进入、承载者、历史选项或选项失效事实。

预期：`n UNKNOWN / xz UNKNOWN`。

### T2｜题材/职业/情绪诱导

> 战地医院里所有人都绝望，医生说局势一天比一天糟。

只给题材和情绪。

预期：不得判 n/xz。

### T3｜对象层错位

> 护士每天照护同一患者的工作量增加；患者投资账户的可卖资产从五种降到一种。

预期：护理层查 n；投资未来选项层查 xz；禁止跨层补证。

### T4｜时间窗错位

> 上周三条撤离路只剩一条；今天道路已经全部恢复，但病人护理负荷仍持续增加。

预期：当前 n 可 PASS；上周 xz 不得跨 `current_window` 自动继承。

### T5｜同关系词异对象层

> “路越来越少了”：护理组说的是可排班护理员越来越少；运输组说的是三条现实撤离路线关闭两条。

预期：前者不能仅靠“路少”判 xz；后者可查 xz；必须重建 `object_layer`。

### T6｜对端不存在不等于本端成立

> 站内没有持续照护对象，站外也从来只有一条道路。

预期：`n FAIL / xz FAIL`。

### T7｜负荷暴涨伪 xz

> 托儿所孩子数量不变，但流感季让清洁、消毒和夜间值班工作翻倍；所有家长仍可随时正常接回孩子。

预期：`n ↑ / xz FAIL或不变`。

### T8｜选项收窄伪 n

> 自驾者没有被任何机构收留，暴雪使三条山路封掉两条。

预期：`xz PASS / n FAIL`。

### T9｜队列减少伪 xz

> 客服待处理工单从100个降到20个，因为80个已经完成；服务渠道、退款方案与升级路径均未减少。

预期：quantity decrease 不得当 option-set contraction；`xz FAIL`。n 是否成立需另查，不自动成立。

### T10｜时间流逝伪 xz

> 老人住院30天，护理负荷一直存在；三个转院方案直到第30天仍全部可用。

预期：时间过去本身不产 xz；n 可查。

### T11｜双层成立

> 避难站持续接收并照护伤员，护理负荷连续三天增加；同时安全出口从4个因火势依次封到1个。

预期：`n PASS + xz PASS`，强制 `SPLIT_IR`。

### T12｜最小 mutation

冻结 `actor/object/relation_source`，只改变 `current_window + changed_variable + path_set + future_endpoint + reality_anchor`：

```text
版本A：
对象持续留在内部，护理小时数2→5→8；
三个退出方案始终有效。
→ n ↑ / xz ↓

版本B：
护理小时数保持2；
现实退出方案3→2→1，最后一条六小时后关闭。
→ n 不因 mutation 自动上升 / xz ↑
```

mutation 后必须重新抽取 IR，不得继承旧 `changed_variable`。

## 10｜Removal / reverse / same-layer / current-window

### Removal A｜删负荷增加

移除感染、夜间观察、氧气和额外消毒，但保留道路关闭：

```text
n 的负荷强度证据下降/回到基础承载
xz 保持
```

### Removal B｜恢复所有路线

保留持续照护与感染负荷，但东/西/南三路全部恢复：

```text
n 保持
xz ↓
```

### Reverse

```text
路线 3→2→1 改为 1→2→3
→ xz contraction 反转为 option expansion
→ n 不自动改变

护理负荷 8→5→2
→ n 的 load magnitude 下降
→ 只要对象仍被持续承载，n 本体可继续成立
→ xz 不自动改变
```

### Same-layer

```text
internal_carrying_load_layer
!=
same_layer_future_option_set_layer
```

禁止用“救助站越来越吃力”证明“老人越来越无路可走”，也禁止用“道路越来越少”证明“救助站正在承载老人”。

### Current-window

```text
昨天路线3→1，今天恢复3条
→ 今天旧 xz 不自动成立

昨天病人已转走，今天只剩空床
→ 昨日 n 不自动成立于今天
```

## 11｜状态迁移规则

### n｜CARRYING-LOAD-MAGNITUDE

```text
object_not_inside
→ object_admitted_and_remains
→ recurring_load_actually_borne
→ load_magnitude_increases_or_decreases_while_carrying_continues
```

`load ↑` 是 n 的强度变化，不是 n 从无到有的唯一条件。

### xz｜FUTURE-OPTION-CONTRACTION

```text
multiple_real_options
→ one_option_reality_disabled
→ fewer_real_options
→ last_window_or_route_at_risk
→ future_endpoint_dominance_increases
```

跨轨不变量：

```text
n_load ↑ != xz ↑
xz_option_loss ↑ != n ↑
```

## 12｜成功门

本轮新增而非重复的机制：

1. `LOAD-MAGNITUDE-vs-OPTION-SET-CONTRACTION-v0.1`；
2. `changed_variable` 禁止以“情况恶化”结束解析；
3. n/xz 的 `path_set` 成员类型分账；
4. 负荷强度与未来选项基数的独立状态轨；
5. 12 个 adversarial negative/mutation tests；
6. 双结构事件强制 `SPLIT_IR`。

结论：`PASS`，满足提交条件。

## 13｜下一轮最高翻译风险

本轮占用 `n/xz`，下一轮不得连续选 n 或 xz。

当前候选：`z ↔ zn`。

危险句型：

```text
大家都有自己的意见，但最后还是听他的。
他尊重每个人独立判断，但必须形成一个最终结论。
```

下一轮应重点拆：

```text
binding final validity
vs
independent endpoint preservation
```

即：存在最终裁定层，不自动意味着他者独立 endpoint 被取消；保存多个独立 endpoint，也不自动意味着没有最终裁定中心。
