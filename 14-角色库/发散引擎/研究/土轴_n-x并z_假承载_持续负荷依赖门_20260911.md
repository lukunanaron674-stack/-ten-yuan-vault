# 土轴 n↔x并z｜假承载：持续负荷依赖门 v0.1

> L4 研究层。只补 `n` 的假承载护栏，不修改 L1/L2 canonical、信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮缺口

已有 `INTERNAL-CARRYING-vs-PUBLIC-INTERFACE-v0.1` 已明确：

```text
n = object -> inside -> sustained load on carrier
x并z = third_party -> public shell/interface -> identifiable/callable internal object
```

但 `n` 仍有一个高风险误判：

```text
对象进入内部
≠
对象被内部持续承载
```

登记、短暂停留、名义归属、一次性接待、单次转交都可能制造“已经进入内部”的表象，却没有让 carrier 形成持续现实负荷。

本轮因此新增：

```text
SUSTAINED-LOAD-DEPENDENCY-GATE-v0.1
持续负荷依赖门
```

## 2｜判别门

`n candidate PASS` 除已有“进入内部”条件外，还必须同时满足：

1. **load persistence**：对象在 current_window 内产生重复或跨阶段负荷，而非单次瞬时动作；
2. **carrier dependency**：对象继续保持内部位置，现实上依赖 actor 持续提供至少一种资源、协调、风险承担、照护、维护、空间占用或流程处理；
3. **removal consequence**：若拿掉 actor 的持续处理，对象的内部位置、功能、存续或可继续状态会现实下降，而不只是体验变差；
4. **load localization**：负荷确实落在当前 actor/structure 内部，而不是已经外包给别处；
5. **time continuity**：至少存在 `进入 -> 留存/运行 -> 再次处理` 的跨阶段证据，或同类负荷重复发生。

若只满足“对象进来了”，但不满足以上依赖关系，判为：

```text
FALSE_INTERNAL_CARRYING
```

不得 positive n。

## 3｜完整 IR：最小正例

输入：

> 某校临时接收一名转学生后，不只是完成登记。接下来数周持续为其安排课程、宿舍床位、饭卡、学籍衔接、考试资格和冲突协调；若学校停止这些持续处理，该学生无法继续维持当前在校位置。

```yaml
actor: 学校
object: 转学生
object_layer: 校内持续学习与生活承载层
current_window: 入校登记 -> 数周课程与住宿 -> 考试与冲突协调
changed_variable: sustained_load_carrying
relation_source: internal_carrier
relation_shape: object_enters_and_remains_dependent_on_carrier

decision_right: admission_and_internal_arrangement_under_school_rules
path_set:
  - course_assignment
  - dorm_bed_allocation
  - meal_card_support
  - enrollment_transfer
  - exam_eligibility_handling
  - conflict_coordination
reentry_right: unknown
future_endpoint: stable_enrollment_or_exit
reality_anchor: 学生继续维持当前内部位置依赖学校持续投入课程、住宿、学籍和协调资源
```

判定：`n PASS`，置信度 0.96。

`x并z`：当前句没有证明第三方通过公共壳稳定识别/调用/进入内部对象，故 `x并z UNKNOWN/FAIL`，不得因“学校”这一机构名自动 positive。

## 4｜最小差异对

### A｜假承载

> 某校允许外校学生进入校园，在访客系统登记后停留半天，午后由原学校接走。校方不承担课程、住宿、学籍、考试或持续协调。

```text
inside = true
sustained_load_dependency = false
```

结论：`n FAIL`。

### B｜真承载

> 同一学生转入后连续数周由学校承担课程、住宿、饭卡、学籍、考试和冲突协调；撤掉这些处理后无法继续维持当前校内位置。

```text
inside = true
sustained_load_dependency = true
```

结论：`n PASS`。

**最小差异不是“有没有进入”，而是“对象的继续内部状态是否现实依赖 carrier 的持续负荷处理”。**

## 5｜positive / negative controls

### Positive control 1｜家庭

儿童长期住入亲属家后，亲属持续承担床位、饮食、接送、医疗决定与日常风险。

→ `n PASS`。

### Negative control 1｜一次性接待

亲属只让儿童在家里等两小时，随后由社工带走；无持续资源与风险承接。

→ `n FAIL`。

### Positive control 2｜工程系统

新设备并入工厂后，工厂持续提供电力、散热、保养、排程、监控与故障处置；撤掉这些处理设备即无法继续处于当前生产位置。

→ `n PASS`。

### Negative control 2｜物理摆放

设备被临时放进厂房等待运输，未接电、未纳入排程、未维护、未进入生产系统。

→ `n FAIL`。

## 6｜removal / reverse / freeze-third-factor

### Removal

冻结对象已经“在里面”这一事实，只移除 recurring handling：

```text
对象仍物理存在于内部
+
不再得到持续资源/协调/维护/风险承接
```

若 n 仍被判 PASS，说明解释器把“inside”偷换成“carrying”。应判 FAIL。

### Reverse

从真 n 反向改写：

```text
长期纳入并持续处理
->
保留名义成员/登记状态，但把全部现实负荷外包给其他主体
```

若原 actor 不再承担现实负荷，则原 actor 的 n 应下降或 FAIL。

### Freeze third factor

固定：题材、身份、名称、空间位置、情绪、关系亲密度都不变；只改变 `sustained_load_dependency`。

若判定跟着“家/学校/医院/成员”等词走，而不随依赖关系变化，则为关键词误判。

## 7｜与 x并z 的双向负控

### n 可在 x并z 缺席时独立成立

秘密避难点没有公开名称、门牌、热线，外部第三方无法稳定调用；但内部长期承担床位、食物、安保、医疗与协调。

→ `n PASS`；`x并z FAIL/UNKNOWN`。

### x并z 可在 n 缺席时独立成立

某“服务中心”拥有稳定品牌、门牌、热线和在线入口，第三方能持续识别并发起请求；但所有请求都被立即转发到外部承包商，本地不承接持续人员、资源或运行负荷。

→ `x并z PASS`；本地 actor 的 `n FAIL`。

这再次证明两端不能互相倒推。

## 8｜解释器可执行最小式

```text
n = inside
    AND repeated_or_cross_stage_load
    AND carrier_dependency
    AND removal_of_carrier_processing_changes_real_continuity
```

等价提问：

> “这个对象之所以还能继续处于当前内部位置，是不是因为这个主体正在持续替它承担现实负荷？”

若答案是否定，仅有进入、登记、挂名、暂存或一次服务，优先判：

```text
FALSE_INTERNAL_CARRYING
```

而不是 n。

## 9｜本轮新增 guard

```text
GUARD_EARTH_N_01:
physical_inside_or_nominal_membership_without_sustained_load_dependency
=> n FAIL

GUARD_EARTH_N_02:
one_off_admission_transfer_or_registration
=> n FAIL unless recurring/cross-stage carrying is evidenced

GUARD_EARTH_N_03:
all_real_load_outsourced_to_other_actor
=> current actor n FAIL or sharply downgrade
```

```text
有名称/门牌/账号/宣传壳
≠
第三方真的能通过该壳稳定识别、调用、归因、代表或进入内部对象
```
