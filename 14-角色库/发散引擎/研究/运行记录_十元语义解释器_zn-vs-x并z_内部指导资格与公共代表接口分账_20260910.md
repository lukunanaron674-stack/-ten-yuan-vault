# 十元语义解释器｜zn vs x并z：内部指导资格与公共代表接口分账

> research-only。目标只是在“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”之间减少翻译歧义。禁止从题材、职业、身份、颜色、情绪、道德评价、胜负或悲惨程度倒推十元。

## 1｜本轮翻译债务

高危句型：

- “这个名字代表我们，所以绝对不能改。”
- “这是我们的核心价值，所以必须一直用这个品牌。”
- “这个徽章就是我们的信念。”
- “只要大家还能认出这个名字，我们的原则就还在。”

这些句子容易把两种完全不同的证据粘死：

```text
zn：内部原则/意义是否具有跨阶段 future-guidance、冲突排序与不可轻易让渡资格？
x并z：内部对象是否通过稳定公共壳获得跨场景可识别、可调用、可归因、可代表或可进入接口？
```

本轮新增的解释器约束不是“原则 != 品牌”这种词典区别，而是：

```text
INTERNAL-GUIDANCE-HOLDER_AUDIT_REQUIRED
PUBLIC-INTERFACE-OBJECT_AUDIT_REQUIRED
GUIDANCE-PERSISTENCE-vs-INTERFACE-PERSISTENCE_AUDIT_REQUIRED
PRINCIPLE-CHANGE-vs-SHELL-CHANGE-INDEPENDENCE_AUDIT_REQUIRED
```

核心不变量：

```text
公共壳持续存在
!=
内部原则仍拥有 future-guidance 资格

内部原则稳定存在
!=
已经形成第三方可调用的公共接口

“不能改名”
必须继续拆：
- 因为改名违反内部不可让渡原则？ → zn candidate
- 因为改名会破坏第三方稳定识别/调用？ → x并z candidate
- 两者都有？ → SPLIT_IR
```

## 2｜自然语言 → IR 结构还原规则

禁止先识别“价值观/品牌/徽章”等关键词再贴标签。按顺序还原：

1. `actor`：谁持有原则，或谁/什么承担公共接口关系；多主体时分开。
2. `object`：明确被判的是内部原则命题，还是公共壳/被代表内部对象。
3. `object_layer`：至少区分 `internal_guidance_layer` 与 `public_interface_representation_layer`。
4. `current_window`：原则是否在当前冲突中被调用；公共壳是否在当前窗口仍被第三方稳定使用。
5. `changed_variable`：是冲突排序/future-guidance 资格变化，还是公共可识别/调用/归因接口变化。
6. `relation_source`：原则来源可为 internalized meaning；接口来源可为 stable public shell + mapping。来源名词不能单独触发判定。
7. `relation_shape`：zn 必须表达“原则 → 排序冲突 → 指导当前/未来选择”；x并z 必须表达“第三方 → 壳 → 内部对象/能力/关系”。
8. `decision_right`：zn 填原则在主体内部的冲突指导资格；x并z 不得把“公众认得它”误写成 final adjudication right。
9. `path_set`：zn 只允许放“竞争行动候选及原则排序”；x并z 只允许放“识别/调用/归因/代表/进入路径”。两种成员混装视为 IR 类型污染。
10. `reentry_right`：无对象特异回返事实则 null/unknown；不得为了完整字段强填。
11. `future_endpoint`：zn 可记录原则未来继续调用的资格；x并z 可记录公共接口持续/撤销后的调用状态，但不得把“品牌永续”倒灌成人物终局。
12. `reality_anchor`：zn 要指出无奖励/观看或有现实代价时原则仍改变排序；x并z 要指出第三方实际通过壳识别、调用、归因、代表或进入。

新增字段约束：

```text
GUIDANCE-PROVENANCE != INTERFACE-PROVENANCE
```

同一证据句不能未经拆解同时给两个 gate 当 positive evidence。例如“几十年一直用这个名字”只能先证明 interface persistence；除非另有冲突排序事实，不能作为 zn positive evidence。

## 3｜标准输入

> 独立动画工作室“北辰”十年来一直以同一中文名、星形徽记和官方网站发布作品，发行商、观众和合作方都通过这些入口识别工作室并提交合作请求。创始人林澈同时坚持“不能为了融资把作者最终署名权交给投资方”这一原则。投资方提出：只要让渡作者最终署名权，就继续融资，并建议工作室保留“北辰”品牌不变。林澈在无人公开表扬、资金紧张的情况下仍拒绝让渡署名权，但同意把星形徽记改为圆形；官网和中文名继续承担外部识别与合作入口。

必须 `SPLIT_IR`。

### 3.1 zn IR

```yaml
actor: 林澈
object: “不能为了融资把作者最终署名权交给投资方”这一内部原则
object_layer: internal_guidance_and_conflict_ranking_layer
current_window: 原则已存在 -> 融资压力出现 -> 投资方要求让渡署名权 -> 无公开奖励且资金紧张 -> 林澈拒绝 -> 原则保留未来调用资格
changed_variable: internal_principle_conflict_ranking_and_future_guidance_eligibility
relation_source: actor_internalized_nontransferable_meaning
relation_shape: internal_principle_ranks_author_credit_control_above_current_financing_benefit_and_continues_to_guide_future_choices
decision_right: principle_has_internal_conflict_ranking_and_future_guidance_eligibility_for_actor
path_set:
  - transfer_final_credit_right_for_financing: normatively_rejected
  - retain_author_final_credit_right_despite_financing_loss: principle_preferred
reentry_right: null
future_endpoint: principle_remains_eligible_for_future_financing_or_credit_conflicts
reality_anchor: 无公开表扬且资金紧张时仍拒绝让渡作者最终署名权；徽记是否更换不影响该原则判断
```

判定：`zn PASS candidate`。

### 3.2 x并z IR

```yaml
actor: 北辰工作室的公共身份接口结构
object: “北辰”中文名、官方网站及当前可替换视觉标识作为工作室对外公共壳
object_layer: public_interface_identification_and_representation_layer
current_window: 十年稳定发布 -> 当前合作请求仍通过官网/中文名进入 -> 徽记可替换 -> 公共识别与调用保持
changed_variable: stable_public_identifiability_callability_and_representation
relation_source: long_running_public_name_website_and_mapped_identity_shell
relation_shape: external_third_parties_to_stable_public_shell_to_internal_studio_identity_and_collaboration_entry
 decision_right: null
path_set:
  - audience_identifies_studio_by_chinese_name
  - distributors_attribute_works_to_studio_through_name_and_site
  - partners_submit_collaboration_requests_through_official_site
reentry_right: null
future_endpoint: public_interface_remains_callable_while_name/site mapping stays valid; visual mark may be replaced without necessarily breaking the shell
reality_anchor: 发行商、观众和合作方连续多年通过中文名与官网识别、归因和进入合作；星形徽记改成圆形后该接口仍可保持
```

判定：`x并z PASS candidate`。

注意：上方 YAML 中 `decision_right` 与其他固定字段同级；写后远端核验必须检查缩进，避免示例污染。

## 4｜Positive decision gates

### 4.1 zn

```text
G1 原则命题/意义对象明确；
G2 current_window 内存在真实冲突候选；
G3 原则实际改变候选排序或当前选择；
G4 拿掉奖励、观看、赞美、身份收益后仍进入判断；
G5 原则跨阶段保有未来调用/指导资格；
G6 reality_anchor 指向现实代价、拒绝、修订边界或反事实选择，而不是视觉符号持续存在。
```

G1-G6 不足，不从“核心、信念、永远、不能改”等词判 positive。

### 4.2 x并z

```text
G1 公共壳对象明确；
G2 至少一个第三方通过壳稳定识别内部对象；
G3 接口跨场景/跨时间持续，不是一次展示；
G4 壳真实改变识别、调用、归因、代表、进入或保护方式；
G5 壳与内部对象存在可说明映射；
G6 removal 壳或映射后，第三方公共调用/识别出现现实缺口。
```

G1/G2 不可缺。内部信念再坚定，也不能替代第三方公共调用证据。

## 5｜Nearest-neighbor 最小差异

### 差异一｜原则不变，壳可变

```text
“作者最终署名权不可让渡”始终不变；
品牌从“北辰”改为“辰光”，旧官网做完整重定向，新接口稳定建立。
→ zn 可保持
→ 旧 x并z 壳下降/迁移，新 x并z 另判
```

### 差异二｜壳不变，原则可变

```text
“北辰”名称、官网、法人账号全部保持；
创始人却正式改为“融资优先，可让渡作者署名权”。
→ x并z 可保持
→ 旧 zn 下降/失效
```

### 差异三｜无公共壳的强原则

```text
匿名作者多年坚持不替广告商篡改作品结局，且无稳定艺名、官网或公共入口。
→ zn 可查
→ x并z 不自动成立
```

### 差异四｜无强原则的稳定壳

```text
客服品牌十年保持统一名称、热线和账号，但内部价值规则每季度按市场修改。
→ x并z 可查
→ 不因品牌稳定判 zn
```

## 6｜False-positive guards

1. “核心价值/初心/信念/原则”只触发 zn 字段抽取，不触发 positive。
2. “品牌/徽章/名字/制服/官网”只触发 x并z 字段抽取，不触发 positive。
3. 公共壳保持十年，只证明接口 persistence，不自动证明内部意义不可让渡。
4. 原则坚持十年，只证明指导资格候选，不自动证明第三方能够识别或调用。
5. “不能改名”若原因只是客户认不出来，优先 x并z；若原因是违反内部不可让渡意义，优先 zn；两种原因都在则 SPLIT_IR。
6. 一次拒绝改 logo 不等于 zn；一次说“坚持初心”不等于 x并z。
7. 公众喜欢、奖项认可、声誉高不构成 zn positive gate。
8. 内部成员都赞同某原则，不等于形成第三方公共接口。
9. 壳与内部高度一致仍可 x并z；x并z 不要求伪装。
10. zn FAIL 不推出 x并z PASS；x并z FAIL 不推出 zn PASS。

## 7｜Removal / reverse / same-layer / current-window

### Removal A｜拿掉公共壳

撤销“北辰”名称、官网、统一对外账号，第三方无法稳定识别或提交合作，但林澈仍坚持作者署名原则：

```text
x并z ↓
zn 保持
```

### Removal B｜拿掉原则

保持名称、官网和公共入口，但林澈正式接受“融资优先，可让渡作者署名权”：

```text
zn ↓
x并z 保持
```

### Reverse｜原因反转

保留“绝对不能改名”这句话，分别反转原因：

```text
A. 改名会违反祖辈不可让渡的承诺，即使客户全能认出新名也不改
→ zn evidence ↑；是否 x并z 另查

B. 内部没人觉得旧名重要，只因改名会让客户找不到服务入口
→ x并z evidence ↑；zn 不自动成立
```

### Same-layer

正式锁定：

```text
internal_guidance_and_conflict_ranking_layer
!=
public_interface_identification_and_representation_layer
```

同一个“名字/徽记/作品形式”可以成为两层的共享载体，但共享载体不允许共享判定证据。必须分别还原 changed_variable、relation_shape、path_set、reality_anchor。

### Current-window

- 历史上曾坚持某原则，不得跨阶段永久继承 zn；当前窗口要看其仍有 future-guidance 资格。
- 历史上曾有著名品牌，不得跨阶段永久继承 x并z；当前窗口要看第三方仍能通过有效壳识别/调用。

## 8｜Adversarial tests

### T1｜关键词诱导
输入：“这个名字就是我们的灵魂，永远不能改。”
IR：actor/object/reality_anchor/第三方接口事实均不足。
结论：`zn UNKNOWN；x并z UNKNOWN`。关键词不能补字段。

### T2｜题材/职业/情绪诱导
输入：“落魄老匠人含泪守着祖传招牌，宁死也不摘。”
结论：不凭匠人、祖传、含泪、悲惨或牺牲判；必须分查原则冲突与公共接口事实。

### T3｜对象层错位
输入：“医院坚持‘急症不得因贫困拒诊’，而统一门牌与热线只负责让患者找到急诊入口。”
结论：原则层可查 zn；门牌/热线层可查 x并z；必须双 IR，不得把‘医院形象’一锅判。

### T4｜时间窗错位
输入：“去年品牌仍是统一入口且创始人坚持不接博彩广告；今年品牌已注销，创始人也公开取消该原则。”
结论：当前窗口不能继承去年的 zn/x并z。

### T5｜同关系词异对象层
输入A：“这个名字代表我们的对外服务，客户靠它找到我们。”
输入B：“这个名字代表我们不接受匿名代笔的原则，即使无人知道也不改。”
结论：A 优先 x并z；B 优先查 zn；“代表”一词不得共用 relation_shape。

### T6｜对端不存在不等于本端成立
输入：“团队既没有稳定公共名称，也没有任何长期原则，今天临时叫A，明天按报价决定做什么。”
结论：`zn FAIL/UNKNOWN；x并z FAIL/UNKNOWN`。一端缺席不补另一端。

### T7｜接口 persistence 伪 zn
输入：“银行20年都用同一Logo和热线，但内部政策完全按季度利润改变，没有任何不可让渡原则。”
结论：x并z candidate；zn 不自动成立。

### T8｜原则 persistence 伪 x并z
输入：“匿名志愿者十年坚持不公开受助者身份，但从无固定组织名、账号或第三方调用入口。”
结论：zn candidate；x并z 不自动成立。

### T9｜外部奖励污染
输入：“创始人只在媒体采访时说‘绝不改品牌初心’，私下融资一到就改变原则。”
结论：不得用公共曝光和品牌一致性补 zn；去奖励/观看后 gate 不过。

### T10｜视觉载体更换
输入：“星形徽章换成圆形，但中文名、官网、法人账号、客户调用路径保持。”
结论：x并z 不应因视觉符号更换自动 FAIL；接口映射若保持，可继续成立。zn 独立检查。

### T11｜原则反转、壳稳定
输入：“官网与名称完全不变，但董事会把‘作者署名不可让渡’改成‘可按投资比例交易’并稳定执行。”
结论：旧 zn ↓；x并z 可保持。

### T12｜Mutation 双向独立性
Mutation A：只替换品牌/官网，并建立完整重定向；内部原则与冲突排序不变。
预期：旧壳 x并z 迁移/重审；zn 保持。
Mutation B：品牌接口完全不变，只反转内部原则排序。
预期：x并z 保持；原 zn 必须重新判定并下降。任何“同品牌所以同原则”的推断均 FAIL。

## 9｜状态迁移规则

### zn 轨

```text
口号/偏好
→ 明确原则命题
→ 进入真实冲突排序
→ 去奖励/观看仍指导
→ 跨阶段 future-guidance eligibility
```

### x并z 轨

```text
一次自称/展示
→ 稳定壳对象
→ 第三方重复识别
→ 可调用/归因/代表/进入
→ 跨场景稳定公共接口
```

新增独立性：

```text
zn ↑ != x并z ↑
x并z ↑ != zn ↑
principle persistence != interface persistence
shell replacement != principle replacement
principle reversal != shell invalidation
```

## 10｜成功门判断

本轮不是重复已有机制，新增内容包括：

- `GUIDANCE-PERSISTENCE-vs-INTERFACE-PERSISTENCE_AUDIT_REQUIRED`；
- `GUIDANCE-PROVENANCE != INTERFACE-PROVENANCE` 字段来源约束；
- `path_set` 成员类型分离；
- “不能改名”原因反转测试；
- shell replacement / principle reversal 双向独立 mutation；
- 12 个 adversarial negatives/contrasts。

因此满足 research commit success gate。

## 11｜下一轮翻译风险

本轮使用 `zn / x并z`，下一轮必须避开二者。

建议优先扫描 `n ↔ xz`：自然语言“最后只能我来扛/一直扛到最后”可能把“持续承载现实负荷”与“未来路径持续收窄到唯一承担者/终点”混为一体。提交前仍必须先去重；若已有等价 Semantic IR 分账，不得为轮转均衡强写。
