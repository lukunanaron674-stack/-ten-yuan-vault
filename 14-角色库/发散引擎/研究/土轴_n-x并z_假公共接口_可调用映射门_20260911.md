# 土轴 n↔x并z｜假公共接口：可调用映射门 v0.1

> L4 研究层。只补 `x并z` 的假公共接口护栏，不修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮缺口

已有 `INTERNAL-CARRYING-vs-PUBLIC-INTERFACE-v0.1` 已明确：

```text
n = object -> inside -> sustained load on carrier
x并z = third_party -> public shell/interface -> identifiable/callable internal object
```

上一轮又补出：

```text
对象进入内部 ≠ n
```

本轮处理对称误判：

```text
存在名称 / 门牌 / 账号 / 官网 / logo / 前台 / 宣传壳
≠
第三方真的能通过该壳稳定识别、调用、归因、代表或进入内部对象
```

因此新增：

```text
PUBLIC-INTERFACE-USABILITY-GATE-v0.1
公共接口可用性门
```

## 2｜判别门

`x并z candidate PASS` 除“存在公共壳”外，至少要求以下五项：

1. **stable mapping**：公共壳与内部对象/关系/能力存在稳定对应，不是临时宣传、同名歧义或空壳占位；
2. **third-party readability**：不依赖内部私人关系，至少一类第三方能从该壳识别“它指向谁/什么”；
3. **repeatable routing**：第三方能够重复使用该壳执行 identify / call / attribute / represent / enter 中至少一种现实动作；
4. **routing consequence**：通过该接口与不通过该接口相比，第三方的寻找、调用、归因、代表或进入路径现实上发生变化；
5. **current usability**：接口在 current_window 内真实可用，而不是历史上曾经存在、技术上已失效、无人响应、只保留纪念性外观。

若只有“壳存在”，但第三方不能稳定借它抵达、调用或归因内部对象，则判：

```text
FALSE_PUBLIC_INTERFACE
```

不得 positive `x并z`。

## 3｜完整 IR：最小正例

输入：

> 某社区维修站有固定名称、门牌和公开报修号。居民无需认识内部维修人员，只要按门牌找到站点或拨打该号码，就能持续把该社区设施故障路由到同一维修团队；过去一个月多个居民实际重复使用过该入口。

```yaml
actor: 社区维修站
object: 维修站内部维修能力与服务关系
object_layer: 对外识别与报修路由层
current_window: 固定名称/门牌/报修号持续存在 -> 多名居民一个月内重复报修
changed_variable: callable_interface
relation_source: stable_public_shell
relation_shape: third_party_routes_through_shell_to_internal_object

decision_right: null
path_set:
  - identify_by_fixed_name
  - locate_by_signage
  - call_public_repair_number
  - route_fault_to_same_internal_team
reentry_right: null
future_endpoint: null
reality_anchor: 第三方无需私人认识内部人员，即可重复通过固定壳把现实报修请求送达同一内部维修对象
```

判定：`x并z PASS`，置信度 0.97。

`n`：此句没有证明任何对象被纳入内部并由维修站持续承担其留存负荷，故 `n UNKNOWN/FAIL`；不得因“站点/团队”自动判 n。

## 4｜nearest-neighbor 最小差异对

### A｜假公共接口

> 某维修站门口仍挂旧门牌，官网也仍在线，但电话号码已停机，地址无人值守，线上表单无人读取。居民知道“这个站曾经存在”，却无法通过这些壳把请求送达任何当前维修对象。

```text
public_shell_present = true
stable_mapping_to_current_internal_object = false_or_historical_only
repeatable_routing = false
routing_consequence = false
```

结论：`x并z FAIL`。

### B｜真公共接口

> 保持同样名称、门牌和官网，但电话、表单和现场入口均持续把第三方请求送到同一当前维修团队，并反复产生受理记录。

```text
public_shell_present = true
stable_mapping = true
repeatable_routing = true
routing_consequence = true
```

结论：`x并z PASS`。

**最小差异不是“有没有壳”，而是壳是否真的形成第三方可重复调用的现实映射路径。**

## 5｜positive / negative controls

### Positive control 1｜机构服务接口

一家法律援助中心有固定公开名称、地址、电话与申请页面，陌生申请人可持续通过这些入口进入同一资格审查流程。

→ `x并z PASS`。

### Negative control 1｜宣传空壳

某组织有精美官网和社交账号，但所有联系方式失效，网页只发布宣传内容，第三方无法据此申请、进入、调用或稳定归因内部服务。

→ `x并z FAIL`。

### Positive control 2｜软件系统

内部模型服务通过稳定 API endpoint 和固定 schema 暴露能力，多个外部客户端可重复调用并得到同一类内部能力响应。

→ `x并z PASS`。

### Negative control 2｜静态文档壳

仓库 README 写着“提供 API”，也保留 endpoint 名称，但 endpoint 已下线，客户端无法连接，也没有替代入口。

→ `x并z FAIL`。

### Positive control 3｜建筑公共入口

展馆有稳定入口、开放时段、售票/验票路径，陌生访客可通过它进入同一内部展览对象。

→ `x并z PASS`。

### Negative control 3｜象征性门牌

旧馆保留门牌和建筑外观，但已封闭、不售票、不接待、不提供任何现实进入路径。

→ `x并z FAIL`。

## 6｜removal / reverse / freeze-third-factor

### Removal

固定名称、视觉、品牌、门牌全部不变，只拿掉：

```text
repeatable_routing
current_response
stable_mapping_to_internal_object
```

若解释器仍判 `x并z PASS`，说明它把“公共可见”偷换成了“公共可调用”。应判 FAIL。

### Reverse

从真 `x并z` 反向改写：

```text
稳定公共接口可调用
->
只保留历史名称/页面/门牌，但当前所有现实路由中断
```

若第三方无法再借壳改变识别、调用、归因、代表或进入路径，则 current `x并z` 应下降或 FAIL。

### Freeze third factor

固定：品牌、名称、审美、空间位置、题材、机构身份、内部能力都不变；只改变：

```text
third_party_repeatable_routing
```

若判定跟着“官网/门牌/账号/平台”等名词走，而不随可用路由变化，则为关键词误判。

## 7｜与 n 的 SPLIT_IR 与双向负控

### 情形 A｜n PASS，x并z FAIL

秘密照护点长期接收并持续承担对象的床位、食物、药物、安保和协调，但没有公开名称、电话、地址入口，陌生第三方无法稳定找到或调用。

```text
IR-A: internal carrying -> n PASS
IR-B: public interface -> x并z FAIL/UNKNOWN
```

### 情形 B｜x并z PASS，n FAIL

公开转介平台有稳定品牌、热线和网页，第三方可重复发起请求；平台自身不承接人员、资源或长期服务负荷，而是立即路由给不同外部供应者。

```text
IR-A: internal carrying at platform actor -> n FAIL
IR-B: public routing interface -> x并z PASS
```

同一句若同时包含“内部持续承载”与“公共壳稳定调用”，必须 SPLIT_IR，不允许用一边证据证明另一边。

## 8｜判别层级：public visibility vs public interface

本轮建议解释器明确区分：

```text
LEVEL 0: hidden
第三方不知道对象存在

LEVEL 1: visible
第三方知道名称/图像/存在

LEVEL 2: identifiable
第三方可以稳定知道“这个壳指向哪个内部对象”

LEVEL 3: callable / attributable / enterable
第三方可借壳重复调用、归因、代表或进入
```

对 current `x并z`：

```text
LEVEL 1 alone => FAIL
LEVEL 2 without routing consequence => weak / insufficient
LEVEL 3 with stable mapping + current usability => candidate PASS
```

这里不是修改 L1 ontology，而是 L4 判定纪律。

## 9｜解释器可执行最小式

```text
x并z = stable_public_shell
       AND stable_mapping_to_internal_object
       AND third_party_readability
       AND repeatable_routing_or_attribution
       AND routing_changes_real_access_or_identification
       AND current_usability
```

最短提问：

> “一个不认识内部人的第三方，能不能反复只靠这个公共壳，现实地找到、调用、归因、代表或进入同一个内部对象？”

若答案是否定，优先判：

```text
FALSE_PUBLIC_INTERFACE
```

而不是 `x并z`。

## 10｜本轮新增 guard / failure types

```text
GUARD_EARTH_XZ_01:
public_shell_without_repeatable_routing
=> x并z FAIL

GUARD_EARTH_XZ_02:
historical_or_decorative_interface_without_current_usability
=> current x并z FAIL or sharply downgrade

GUARD_EARTH_XZ_03:
third_party_awareness_without_stable_mapping_or_callable_path
=> x并z FAIL
```

失败类型：

```text
PUBLIC_VISIBILITY_AS_INTERFACE
把“看得见/听说过”误当公共接口

DECORATIVE_SHELL_AS_CALLABLE_INTERFACE
把门牌、logo、网页外观误当可调用路径

HISTORICAL_INTERFACE_AS_CURRENT
历史曾可用，倒推当前仍在线

PRIVATE_CONTACT_AS_PUBLIC_INTERFACE
只有熟人知道私人联系方式，却写成公共壳

UNMAPPED_ROUTER_AS_INTERFACE
入口存在，但无法稳定映射到同一内部对象

ONE_SHOT_EXPOSURE_AS_STABLE_INTERFACE
一次宣传/一次曝光误写成稳定外化接口
```

## 11｜本轮结论

与上一轮合并后，土轴已形成第一组对称反误判门：

```text
假承载护栏：
inside ≠ n
必须有 sustained_load_dependency

假公共接口护栏：
public shell ≠ x并z
必须有 stable_mapping + repeatable_routing + current_usability
```

因此 `n` 与 `x并z` 不再依赖“内部/外部”名词表面，而可以通过现实因果箭头独立审计。

## 12｜下一断点

下一轮优先进入最小生命周期，而不是继续堆正例：

```text
进入
-> n 承载成立
-> x并z 外化接口成立
-> 公共接口撤除
-> n 是否仍可独立保持
```

目标是验证：

```text
x并z OFF
并不自动导致
n OFF
```

并建立同一 actor / object 在不同 object_layer、current_window 下的状态迁移规则。
