# 十元语义解释器｜nx vs z：外部许可依赖与最高裁定中心分账

> research-only。仅服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究。不得修改或覆盖 L1/L2 canonical、十元信息卡、准度卡、正式关系卡、行为 evidence 正本。

## 0｜选题与翻译债务

本轮选择 `nx ↔ z`。

前一轮研究对象为 `nz ↔ zn`，因此没有连续复用同一十元。

仓库已有 `nx` 外部 route activation、`z` 最高裁定中心、`z vs x并z`、`x vs z` 等规则，但仍缺少一个解释器级硬分账：自然语言里的“审批、批准、授权、签字、放行、最终同意”既可能描述**被测主体必须沿外部许可 gate 才能继续**，也可能描述**被测主体自己就是使候选结果最终生效的最高裁定中心**。

如果只看“需要审批/由某人批准”，模型会把“依赖裁定中心的人”与“裁定中心本身”粘成同一标签。

本轮新增：

```text
EXTERNAL-GATE-vs-FINAL-ADJUDICATOR-v0.1
ROLE-IN-DECISION-TOPOLOGY_AUDIT_REQUIRED
GATE-BEARER-vs-ADJUDICATOR-BEARER_AUDIT_REQUIRED

being gated by X != being final adjudicator
approval dependency != adjudication centrality
external veto over actor != actor is z
```

## 1｜自然语言 → IR 结构还原规则

### STEP 1｜先冻结被测 actor

同一句出现“申请人 + 审批人”时，不得做 whole-sentence label。

```text
如果 tested actor = 申请/执行者：
  先问 external gate 是否进入该 actor 的现实推进链。

如果 tested actor = 审批/裁定者：
  先问其是否是 same object_layer 的 binding final adjudicator。
```

### STEP 2｜冻结 object_layer

必须区分：

```text
permission/progression layer
= actor 能不能沿一个外部许可/资源/关系通道继续推进

final-validity/adjudication layer
= 多个候选判断/方案中，谁的决定具有最终生效效力
```

### STEP 3｜changed_variable 分流

```text
external_permission_route_activation
external_gate_dependency
external_direction_dependency
→ 查 nx

adjudication_center_distribution
binding_final_validity_source
→ 查 z
```

### STEP 4｜decision_right 必须带 role

禁止只写 `decision_right: approval`。

至少区分：

```text
external_gate_can_block_tested_actor
actor_final_adjudicator
actor_nonfinal_reviewer
shared_nonfinal_review
self_final_after_nonbinding_advice
```

### STEP 5｜path_set 语义类型不得混用

`nx` 的 path_set 记录 actor 实际沿用的 external route / gate / permission dependency。

`z` 的 path_set 记录裁定前仍具有同层有效性的候选判断/方案，以及 final adjudication node。

```text
permission_route_set != candidate_judgment_set
```

### STEP 6｜reality_anchor 必须证明角色位置

```text
nx anchor:
外部 gate 拒绝/撤走 → tested actor 同层推进出现现实缺口；
外部 gate 放行 → 推进恢复。

z anchor:
final adjudicator 改变判断 → 哪个候选最终有效随之改变；
其他同层判断不能覆盖其 binding result。
```

## 2｜标准输入

> “产品经理林澈已经按董事会要求准备上线新版本，但法务总监不签字就不能发布；法务签字后，林澈可以自己安排测试和发布时间。另在法务审查这一层，三名律师分别给出‘可发布 / 修改后发布 / 不可发布’意见，法务总监拥有最终合规裁定权，可以覆盖三名律师的意见并使一个结论成为本轮唯一有效合规结论。”

必须 SPLIT_IR。

### IR-A｜tested actor = 林澈｜nx

```yaml
actor: 林澈
object: 新版本上线
object_layer: 上线许可与推进层
current_window: 董事会要求上线 -> 林澈准备 -> 等待法务签字 -> 放行后进入发布
changed_variable: external_permission_route_activation
relation_source: external
relation_shape: actor_progression_through_external_blocking_gate
decision_right: external_gate_can_block_tested_actor
path_set:
  - board_given_release_direction
  - legal_signoff_gate
  - actor_progress_after_signoff
reentry_right: external_permission_required_if_gate_reopens
future_endpoint: null
reality_anchor: 法务不签字时林澈不能发布；签字后发布链恢复
```

判定：**nx candidate PASS**。

注意：林澈放行后自行安排测试与发布时间，可另层检查 xn；不能反过来抹掉当前许可层 nx。

### IR-B｜tested actor = 法务总监｜z

```yaml
actor: 法务总监
object: 本轮版本的最终合规结论
object_layer: 多个律师意见的最终有效性裁定层
current_window: 三名律师分别给意见 -> 意见并存 -> 法务总监终审 -> 一个结论 binding 生效
changed_variable: adjudication_center_distribution
relation_source: institutional_final_authority
relation_shape: multiple_valid_judgments_to_single_binding_adjudicator
decision_right: actor_final_adjudicator
path_set:
  - lawyer_A_can_release
  - lawyer_B_release_after_changes
  - lawyer_C_cannot_release
  - legal_director_final_adjudication
reentry_right: rejected_opinion_requires_new_review_round
future_endpoint: one_binding_compliance_conclusion_for_current_round
reality_anchor: 法务总监可以覆盖三名律师意见，其判断决定哪个合规结论在本轮最终有效
```

判定：**z candidate PASS（按 current L1 v1.6）**。

## 3｜Positive decision gates

### nx positive gate

至少要求：

1. tested actor 明确，不能把审批人偷换成 actor；
2. object_layer 是 direction / permission / routing / task progression；
3. relation_source 是 external 或 shared-with-external-gate；
4. external route 已在 current_window 真实 activated；
5. actor 在该层不能绕过 gate 得到同一结果，或 gate 具现实阻断能力；
6. removal external gate 后，同层推进出现可命名现实缺口；
7. actor 后续局部执行很主动，不否定上位 nx。

### z positive gate

按 current L1 v1.6，本轮至少要求：

1. tested actor 是当前被测裁定位置，而不是被审批者；
2. object_layer 是 answer / standard / judgment / final-validity layer；
3. 裁定前存在至少两个同层有效候选判断/方案，或至少存在可被覆盖的同层判断位置；
4. decision_right = actor_final_adjudicator / single binding center；
5. actor 的决定能让一个判断取得最终效力，并使其他判断不能保持同等最终效力；
6. removal final center 后，最终有效性不再按原方式收束；
7. “审批人、领导、专家”身份本身不提供 z。

## 4｜nearest-neighbor 最小差异

### nx vs z

```text
nx：
我必须经过谁的现实 gate，才能继续我的推进？

z：
在多个同层判断/方案仍有效时，谁的判断最后具有 binding 效力？
```

最小突变：

```text
tested actor 从申请人切到审批人
+ object_layer 从 progression 切到 final validity
+ decision_right 从 external_gate_blocks_actor 切到 actor_final_adjudicator
→ 十元候选必须重新解释，禁止继承标签
```

### nx vs xn

```text
nx：方向/许可来自外部，并现实卡住推进。
xn：actor 主动生成怎样跨阶段持续运行的流程、节点、记录和资源结构。
```

“获批后自己安排”可形成上位 nx + 下位 xn。

### z vs x

```text
z：决定哪个判断/方案最终有效。
x：决定对象本身如何被使用、调配、冻结、排除或处分。
```

“批准出售设备”必须拆：出售结果的 final approval 与设备处分边界不是自动同一层。

## 5｜false-positive guards

1. “需要审批” ≠ tested actor z；申请人更可能先查 nx。
2. “我是审批人” ≠ z；若只能备案/建议且不能覆盖同层判断，z FAIL/弱。
3. “对方能否决我” ≠ 我 z；这恰恰可能是我的 nx evidence。
4. “最终签字”字样 ≠ z；签字若只是机械确认、无选择空间，不足。
5. external relation_source ≠ nx；route 必须 current-window activated。
6. 有多个律师/专家 ≠ z；需要 binding final center。
7. 一次审批结果唯一 ≠ z；唯一结果可能来自自动规则、随机或候选天然只有一个。
8. actor 自己设计大量后续流程 ≠ 抹掉上位 nx。
9. z FAIL 不推出 nx；nx FAIL 不推出 z。
10. 题材、职位、权威感、语气、胜负、悲惨程度均不得回填标签。
11. old z recognition wording 不得覆盖 current L1 本轮判定。

## 6｜Removal / reverse / same-layer / current-window

### Removal-A｜移除 external gate

把“法务不签不能发布”改成“法务意见只是建议，林澈仍可直接发布”。

预期：

```text
林澈许可层 nx ↓
法务总监是否 z 需在裁定层独立检查
```

### Removal-B｜移除 final adjudication

保留林澈必须经法务流程，但把“三名律师意见由多数票决定，法务总监只能记录结果”。

预期：

```text
林澈 nx 可保持
法务总监 z ↓
```

### Reverse

- 保留“审批”一词，把 external gate 改成 nonblocking advice：nx 必须下降；
- 保留“最终签字”一词，但签字人只能机械执行自动规则：z 必须下降；
- 保留三个候选意见，但没有任何 binding center：不能因多候选自动 z。

### Same-layer

只有同一 object_layer 才能比较 decision topology。

```text
林澈的上线推进层
!=
法务总监的最终合规裁定层
```

同一句可以双判，但必须 SPLIT_IR。

### Current-window

去年法务拥有阻断权、今年只备案：今年林澈不能沿用旧 nx evidence。

去年总监可覆盖律师意见、今年改为委员会多数决：今年总监不能沿用旧 z。

## 7｜Adversarial tests

### T1｜关键词诱导

输入：“这个项目必须审批，但审批按钮只是自动检查字段完整性，任何人都不能改变结果。”

预期：仅凭“审批”不得判 tested operator z；若 actor 也不依赖一个真实 external decision route，则 nx 也不能硬判。

### T2｜题材/职业/情绪诱导

输入：“威严的军法官冷冷说‘由我批准’，但法规自动产生唯一结论，他没有覆盖、否决或选择权。”

预期：z FAIL/弱；职业和威严不提供 decision topology。

### T3｜对象层错位

输入：“采购员必须等 CFO 放行付款；CFO 另外无权决定供应商最终是否中标，中标由委员会多数决。”

预期：采购员付款推进层可查 nx；CFO 在中标裁定层 z FAIL。

### T4｜时间窗错位

输入：“去年所有上线都要 CEO 批；今年制度改为自动合规，CEO 只收通知。”

预期：当前执行者不能沿用去年 external gate；CEO 当前 z 不得由历史签字权续贴。

### T5｜同关系词异对象层

输入A：“法务批准后我才能发布。”
输入B：“三种合规意见最后由法务决定哪种有效。”

预期：A tested actor=发布者时优先 nx；B tested actor=法务时优先 z。相同“批准/决定”不得整句同标签。

### T6｜对端不存在不等于本端成立

输入：“没有任何人最终拍板，申请人也没有沿任何外部许可路线推进，项目停在那里。”

预期：nx FAIL/UNKNOWN；z FAIL/UNKNOWN。没有 z 不等于 nx，反之亦然。

### T7｜外部 gate 强，但 gate holder 非 z

输入：“部署者必须取得安全系统 token；token 由确定性规则自动发放，管理员不能覆盖规则。”

预期：部署者可有 external-gate nx evidence；管理员 z FAIL。外部阻断点存在不等于存在人类最高裁定中心。

### T8｜z 强，但申请人 nx 弱

输入：“评奖主席可在五个候选中最终指定获奖者，但候选人本身无需沿主席给定路线做任何推进，提交后只是等待结果。”

预期：主席 z PASS candidate；不能仅因为候选人受其裁定就把候选人当前行动层强判 nx。

### T9｜审批人只有建议权

输入：“资深专家给出‘建议通过’，负责人可以完全无视并直接发布，过去十次也如此。”

预期：专家 z FAIL；负责人 nx FAIL/弱，因为 external route 不具 blocking reality anchor。

### T10｜一次 gate + 后续自主流程

输入：“董事会决定必须迁址，经理拿到许可后自己设计供应商、排期、迁移批次和回滚流程。”

预期：高层任务/许可层 nx 可 PASS；局部运行层查 xn；不得因自主执行抹掉 nx。

### T11｜多人 review + 单一 binding center

输入：“四个 reviewer 都能发表意见且各不相同，但只有总编辑的终审能决定哪版真正出版。”

预期：总编辑 z PASS candidate；reviewer plurality 本身不削弱单一 final center。

### T12｜最小 mutation：角色位置翻转

冻结 source event/domain/object family，只切：

```text
actor = applicant
object_layer = permission_progression
relation_source = external
decision_right = external_gate_can_block_tested_actor
path_set = [external approval route]
reality_anchor = refusal blocks actor
→ nx ↑ / z 不从该 actor 自动成立

actor = approver
object_layer = final_validity
relation_source = institutional_final_authority
decision_right = actor_final_adjudicator
path_set = [candidate judgments, final node]
reality_anchor = actor choice changes binding result
→ z ↑ / nx 不从该 actor 自动成立
```

这是本轮核心 mutation probe。

## 8｜状态迁移规则

### ROUTE-DEPENDENCY STATE

```text
external actor merely present
→ external advice consulted
→ external gate activated
→ gate refusal blocks same-layer progress
= nx evidence ↑
```

### ADJUDICATION-CENTRALITY STATE

```text
multiple opinions without binding hierarchy
→ reviewer with recommendation weight
→ final override right created
→ one binding adjudicator controls final validity
= z evidence ↑
```

两轨独立：

```text
nx ↑ != z ↑
z ↑ != nx ↑
```

同一事件常见结构是：

```text
applicant tested actor: nx candidate
approver tested actor: z candidate
```

不是同一 actor 的“双标签捷径”。

## 9｜成功门

本轮不是已有机制重复，新增信息包括：

- `ROLE-IN-DECISION-TOPOLOGY_AUDIT_REQUIRED`；
- gate bearer 与 final adjudicator bearer 分账；
- `decision_right` 新的 role-specific 解释约束；
- permission route set 与 candidate judgment set 不可互填；
- 同一“审批”事件按 tested actor 角色翻转的 mutation probe；
- “外部 gate 很强但 gate holder 非 z”的 adversarial negative；
- 两条独立状态迁移轨。

因此：**PASS / 可提交 research-only candidate**。

## 10｜下一轮最高翻译风险

本轮使用 `nx / z`，下一轮必须避开二者。

当前优先候选：`xn ↔ x并z`。

高风险自然语言：

```text
“统一平台 / 系统 / 门户 / 工作台 / 中台”
```

同一个“平台”可能是：

- `xn`：内部运行节点、handoff、记录、排程与流程被组织成可重复结构；
- `x并z`：第三方通过稳定公共壳识别、调用、进入内部对象。

下一轮应重点审计 `caller_population + interface_direction + path_set_semantic_type + mechanism_operation`，把“内部运行平台”与“对外公共接口”拆开，避免一个 UI 名词同时替两种结构打工。
