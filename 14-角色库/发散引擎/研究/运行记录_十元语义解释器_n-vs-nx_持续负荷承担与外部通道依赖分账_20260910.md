# 十元语义解释器｜n vs nx｜持续负荷承担与外部通道依赖分账

> research-only。只服务 `自然语言 -> Ten-Yuan Semantic IR -> 十元判定 -> Z 发散器`。current canonical 永远高于本记录。本轮不修改任何 canonical、准度卡、正式关系卡或 behavior evidence 正本。

## 0｜本轮选择与去重

上一轮为 `zn vs x并z`，本轮避开 zn/x并z。仓库已存在 `n-vs-xz`、`n-vs-z`、`n-vs-x`、`n-vs-xn`、`n-vs-nz`、`zn-vs-n` 等独立分账；未检出独立 `n-vs-nx` Semantic IR 分账文件。

本轮不重复 canonical 已有的“n 接住对象并承担负荷；nx 沿外部方向与通道推进”，而新增 **load bearer / route holder 的角色分账、依赖方向审计和双端独立 removal rule**。

## 1｜翻译债务

高风险自然语言：

```text
“这几年一直是我在撑着。”
“我一直靠他帮忙才能撑下去。”
“事情都是我在扛，但关键权限还在别人手里。”
“他帮我很多，所以他在承担。”
```

这些句子会把两个完全不同的问题焊在一起：

```text
n 问：谁让对象真实留在内部，并持续支付它存在产生的现实负荷？

nx 问：tested actor 当前行动所依赖的方向、权限或解决通道，是否属于外部既有位置？
```

### 1.1 本轮新增翻译规则

```text
LOAD-BEARER-vs-ROUTE-HOLDER-v0.1

LOAD-BEARER_AUDIT_REQUIRED
ROUTE-HOLDER_AUDIT_REQUIRED
LOAD-ORIGIN_AUDIT_REQUIRED
ACTION-DEPENDENCY_AUDIT_REQUIRED
SUPPORT-TRANSFER-vs-PERMISSION-TRANSFER_AUDIT_REQUIRED
```

核心不变量：

```text
who bears recurring load
!=
who owns the route/permission needed to continue the action

外部有人帮忙
!=
内部负荷已经转移给外部人

主体持续承担对象
!=
主体拥有完成所有事项所需的最终权限

主体需要求人/借权限
!=
主体没有承担持续负荷
```

### 1.2 IR 新约束：load-bearing evidence 与 route-dependency evidence 禁止共用

同一句“靠他撑着”必须拆问：

```text
A. 他是否持续支付食宿、照护、风险、维护、时间、资源或内部协调成本？
B. 还是他只提供某个外部许可、关系、身份或通道，使 tested actor 能继续办事？
```

若只有 B，不能把 helper 写成 n 的 load bearer。

若只有 A，而 tested actor 不依赖 helper 的方向/权限/通道，也不能补 nx。

### 1.3 path_set 类型纪律

```text
n.path_set
= recurring load channels / internal carrying channels
例如：住宿、餐食、护理、值守、风险、维护、持续协调

nx.path_set
= external direction / permission / relation routes
例如：主管批准、医院床位许可、法定签字、关系网络、借用他者权限
```

若 `n.path_set` 塞入“找领导、请人签字、托关系”，或 `nx.path_set` 塞入“每天喂饭、夜间值守、承担房租”，判为 Semantic IR type contamination，必须重抽。

## 2｜标准输入句

> 山区儿童之家连续六个月安置十二名临时失依儿童。负责人林澈和机构每天承担住宿、餐食、夜间值守、药品保管、心理访谈和学校接送，即使捐款下降也没有把儿童推出去。与此同时，机构没有跨区转学和特殊医保备案的最终权限；每次办理都必须请求县民政联络员周宁调用其既有行政权限，周宁拒绝时林澈不能自行完成这些手续。但手续是否获批不改变儿童仍由机构继续食宿和照护这一事实。

必须 `SPLIT_IR`。

## 3｜完整 Semantic IR

### 3.1 n IR

```yaml
actor: 山区儿童之家及其当前承载团队
object: 十二名已进入儿童之家并持续生活的临时失依儿童及其日常生活照护负荷
object_layer: sustained_internal_carrying_and_recurring_load_layer
current_window: 儿童进入 -> 连续六个月留置 -> 日常负荷持续发生 -> 捐款下降 -> 仍持续内部承载
changed_variable: sustained_internal_position_and_recurring_load_burden
relation_source: actual_admission_plus_continuing_internal_care
relation_shape: admitted_children_remain_inside_while_named_recurring_living_care_and_coordination_load_is_continuously_borne
 decision_right: bounded_daily_care_execution_without_final_cross_region_school_or_special_medical_filing_authority
path_set:
  - accommodation
  - daily_meals
  - night_duty
  - medicine_storage
  - psychological_interviews
  - school_transport
reentry_right: null
future_endpoint: current_carrying_ends_when_safe_guardianship_or_formal_transfer_is_completed
reality_anchor: 十二名儿童连续六个月真实住在机构；捐款下降后机构仍每天承担食宿、值守、药品、访谈和接送成本
```

判定：`n PASS candidate`。

> 写后核验要求：`decision_right` 必须与其他固定字段同级；若出现 YAML 缩进污染必须修正后再汇报。

### 3.2 nx IR

```yaml
actor: 林澈
object: 为当前十二名儿童办理跨区转学与特殊医保备案
object_layer: actor_specific_external_permission_and_administrative_route_dependency_layer
current_window: 出现跨区转学/医保需求 -> 林澈无最终行政权限 -> 请求周宁 -> 周宁调用既有权限 -> 手续获批或因拒绝而阻断
changed_variable: current_action_dependency_on_external_administrative_permission_route
relation_source: county_civil_affairs_liaison_holds_existing_cross_region_and_special_filing_authority
relation_shape: tested_actor_without_final_administrative_permission_position_to_external_authority_holder_to_current_required_procedure
 decision_right: linche_has_no_final_cross_region_transfer_or_special_medical_filing_right_and_cannot_override_zhou_ning_denial
path_set:
  - request_county_liaison_support
  - use_existing_cross_region_transfer_authority
  - use_existing_special_medical_filing_authority
reentry_right: denied_case_may_reenter_only_through_the_allowed_external_administrative_route_if_rules_permit
future_endpoint: current_transfer_or_medical_filing_is_completed_or_remains_blocked
reality_anchor: 周宁拒绝时林澈无法自行完成跨区转学或特殊医保备案，但机构仍继续承担儿童日常生活负荷
```

判定：`nx PASS candidate`。

## 4｜Positive decision gates

### 4.1 n gate

至少要求：

```text
N1 明确进入内部的 object / member；
N2 获得跨阶段真实内部位置，而非一次停留；
N3 能命名 recurring load；
N4 能识别实际 load bearer；
N5 reality_anchor 证明负荷被现实持续支付/处理；
N6 对象并非被强制扣留；
N7 removal 内部位置或持续处理后，n 应明显下降。
```

`N1 + N3 + N4 + N5` 不可缺。单纯“我很辛苦”“我一直负责”不够。

### 4.2 nx gate

至少要求：

```text
NX1 tested actor/current action 明确；
NX2 方向、权限或解决通道已存在且属于外部位置；
NX3 actor 不占该层最终决定/许可位置；
NX4 actor 实际沿该外部路线推进，而不是仅知道其存在；
NX5 route holder 能 enable/block/change 当前行动；
NX6 removal 外部 route/permission 后，当前行动现实受阻。
```

“有人帮助过我”不是 NX2/NX5 的替代证据。

## 5｜Nearest-neighbor 最小差异

### NN-1：持续照护 vs 一次行政放行

```text
机构每天照顾儿童六个月
→ n evidence ↑

县联络员只在三次转学手续上签字放行
→ 对林澈是 nx route holder evidence
→ 不自动成为儿童日常负荷的 n load bearer
```

### NN-2：外部权限依赖存在，但承载完全独立

```text
周宁拒绝跨区转学
→ 林澈该手续 nx 依赖暴露

儿童仍在机构吃住、治疗、上学
→ n 可保持
```

### NN-3：负荷转移，但权限依赖不变

若食宿与护理整体转交另一家机构：

```text
原机构 n ↓
```

但林澈仍负责办理旧案特殊医保，且仍需周宁签权：

```text
该手续层 nx 可保持
```

### NN-4：获得直接权限，不等于负荷减少

若林澈获得法定跨区转学与医保备案权：

```text
nx ↓
```

但儿童仍连续住在机构并产生同样食宿照护负荷：

```text
n 保持
```

## 6｜False-positive guards

1. “一直在撑”“一直负责”“扛了很久”只触发 n 字段抽取，不直接 positive。
2. “求人”“托关系”“请领导”“借权限”只触发 nx 字段抽取，不直接 positive。
3. helper 提供一次签字、许可或介绍，不自动成为 load bearer。
4. load bearer 持续承担成本，不自动意味着它依赖外部方向或权限。
5. actor 同时承担很重的内部负荷，仍可能在某个行政/专业权限层高 nx。
6. nx route holder 拒绝事项，不等于 n 中 object 被推出内部；必须看对象是否仍被现实承载。
7. n FAIL 不推出 nx PASS；nx FAIL 不推出 n PASS。
8. 医院、家庭、避难所、社工、母亲、护士等题材/职业不得倒推 n。
9. 谦逊、委屈、求人姿态、悲惨程度不得倒推 nx。
10. “别人帮我分担”必须继续问：分担的是 recurring load，还是只开放 route/permission？

## 7｜Removal / reverse / same-layer / current-window

### 7.1 removal：移除外部权限依赖

给林澈完整法定转学与医保备案权：

```text
nx ↓
n 保持
```

### 7.2 removal：移除持续内部承载

儿童整体安全转入另一家机构，原机构不再食宿照护：

```text
原机构 n ↓
```

若林澈仍需周宁处理历史备案：

```text
对应手续层 nx 可保持
```

### 7.3 reverse：把“外部许可”反转成“内部直接权”

```text
必须请周宁批准
→ 林澈依法直接拥有同层许可权
```

只应重审 `nx` 的 relation_source / relation_shape / decision_right / path_set；不得机械改写 n。

### 7.4 reverse：把“持续内部承载”反转成“立即转交”

```text
儿童进入后长期留置并持续照护
→ 仅短暂停留后立即安全转交
```

应显著降低稳定 n；不得因此自动提高 nx。

### 7.5 same-layer guard

```text
sustained_internal_carrying_and_recurring_load_layer
!=
actor_specific_external_permission_and_administrative_route_dependency_layer
```

同一批儿童可以同时出现在两个 IR 的 object 描述中，但关系角色不同，positive evidence 不得共享。

### 7.6 current-window guard

```text
去年靠周宁办过手续
!=
今年仍 nx

去年长期承载过儿童
!=
今年仍 n
```

必须以当前窗口重新检查：对象是否仍在内部、负荷是否仍持续、外部 permission route 是否仍被激活。

## 8｜Adversarial tests

### T1｜关键词诱导

输入：

> “这些年一直都是我在扛，但我也一直求人帮忙。”

预期：`NEEDS_MORE_STRUCTURE`。必须分别提取 recurring load 与 external route；不得凭“扛/求人”直接判 n/nx。

### T2｜题材/职业/情绪诱导

输入：

> “慈祥的护士含泪照顾孤儿，遇事总低声求人。”

预期：两端不得凭护士、孤儿、慈祥、含泪、低声成立。

### T3｜对象层错位

输入：

> “养老院承担老人全年食宿；院长为扩建许可证去找市政朋友帮忙。”

预期：老人生活层查 n；扩建许可层查 nx；禁止把朋友写成老人生活 load bearer。

### T4｜时间窗错位

输入：

> “去年机构长期收留十名儿童且所有医保都靠县里特批；今年儿童已全部转出，机构也取得直接备案权。”

预期：当前稳定 n 与该许可层 nx 均不得继承去年状态。

### T5｜同关系词异对象层

输入：

> “他帮我撑住了。”第一句指每天替班、付房租、做饭；第二句指只帮忙找局长签一次字。

预期：第一句可进入 n recurring-load audit；第二句进入 nx route audit；同一个“帮/撑”不得共享字段类型。

### T6｜对端不存在不等于本端成立

输入：

> “项目取消后，儿童已安全转走；负责人也不再办理任何外部手续。”

预期：n FAIL/下降；nx FAIL/下降。n 不成立不等于 nx 自动成立，反之亦然。

### T7｜纯 n，不补 nx

输入：

> “家庭依法拥有完整监护和医疗签署权限，连续一年承担孩子全部食宿、治疗与上学安排，不需要借任何外部特殊权限。”

预期：n candidate；本题设下 nx 不自动成立。

### T8｜纯 nx，不补 n

输入：

> “律师为客户办一次证件，没有让客户住进自己机构，也不承担客户生活负荷；他必须请有签发权的主管批准。”

预期：nx candidate；n FAIL/不足。

### T9｜helper 只给许可

输入：

> “县联络员每月批准特殊医保，但从未承担儿童住宿、餐食、照护或值守。”

预期：联络员可作为 nx route holder；不得判其为儿童生活层 n bearer。

### T10｜helper 真正接管负荷

输入：

> “周宁不再只是签字，而是把六名儿童接入自己机构，连续三个月承担住宿、治疗和接送。”

预期：周宁所在机构新增 n candidate；这不是 nx 自动迁移，而是必须新建 n IR。

### T11｜双端并存

输入：

> “林澈所在机构连续半年承担儿童食宿；每次跨区转学仍必须借周宁法定权限。”

预期：`n + nx`，必须 SPLIT_IR。负荷很重不能抵消外部权限依赖；外部权限依赖也不能抹掉现实承载。

### T12｜mutation

A：

```text
机构继续承载儿童 + 仍需周宁签权
→ n ↑ / nx ↑
```

B：只给林澈直接行政权：

```text
n 保持 / nx ↓
```

C：只把儿童生活承载整体安全转出，但手续仍由林澈经周宁完成：

```text
原机构 n ↓ / 对应手续 nx 保持
```

mutation 后必须重新抽取 IR，禁止单标签机械切换。

## 9｜状态迁移规则

### 9.1 n 状态轨

```text
对象仍在外部
→ 一次接收
→ 稳定内部位置
→ recurring load 出现
→ load bearer 持续现实支付/处理
→ 外部压力下仍能承载
= n ↑
```

### 9.2 nx 状态轨

```text
actor 自持当前所需方向/权限
→ 出现外部既有 route 需求
→ actor 不占该层最终位置
→ 实际请求/借用/跟随外部 route
→ route holder 可 enable/block 当前行动
= nx ↑
```

两轨独立：

```text
n ↑ != nx ↑
nx ↑ != n ↑
n 的 load transfer != nx 的 permission transfer
nx 的 permission transfer != n 的 load transfer
```

## 11｜下一轮风险提示

本轮使用 n/nx，下一轮不得连续选择 n 或 nx。

优先扫描尚未有独立分账、且自然语言高混淆的“恢复/修复/重新获得”簇。候选之一是：

```text
x ↔ nz
```

高危句：

> “他重新拿回了自己的位置。”

需要区分：

```text
x：当前对象/权限/位置重新进入主体掌握与处分边界？

nz：原对象特异关系在真实退出后是否保存/恢复可信回返资格？
```

若仓库已有等价独立机制则下一轮继续去重跳过，不为轮转均衡强行提交。
