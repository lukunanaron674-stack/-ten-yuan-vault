# 土轴 n↔x并z｜混合子对象解析必须逐对象记账：对象解析广播风险闭环 v0.1

> L4 research-only。只处理上一轮遗留的“同一壳对部分 child 可解析、部分不可解析”真实 pending；不修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮唯一缺口

问题：同一个 grounded public shell 同时挂载多个内部对象，其中 S1 有稳定 object-specific resolver，S2 没有。如果解释器只维护一个 `shell.resolvable = true`，是否会把 S1 的可解析性错误广播给 S2？

结论：会，因此对象解析性必须逐 tested object 记账。

```text
shell-level resolvability
!=
per-object resolvability
```

本轮没有改变 `x并z` criterion，而是把上一轮对象级映射门落实成解释器执行纪律：

```text
resolution_ledger[object_id]
```

禁止：

```text
one_resolvable_child
=> all_children_resolvable
```

该 pending 本轮闭合。

只改 S2 的对象级 resolver。

### Pair A

```text
S1: portal-A/s1 -> S1
S2: portal-A -> opaque dispatch
```

结果：

```text
x并z(S1) PASS
x并z(S2) insufficient
```

### Pair B

只增加：

```text
portal-A/s2 -> stable S2
```

结果：

```text
x并z(S1) PASS
x并z(S2) PASS
```

最小翻转变量：

```text
resolver(S2): false -> true
```

而不是 `shell.resolvable`。

## 3｜removal

### Removal A｜删除 S1 resolver

```text
S1: PASS -> insufficient
S2: remains insufficient
A-system: remains PASS
```

说明 child 的解析状态彼此独立，不能互相补证。

### Removal B｜删除 parent shell grounding

即使保留写着 `/s1` 的外部标签，但该 route 不再真实接到 S1：

```text
x并z(S1): FAIL
```

因此 per-object resolver 仍不能替代 causal grounding。

## 4｜reverse

```text
S2 opaque
-> add stable object-specific resolver
-> x并z(S2) ON
```

反向：

```text
remove only S2 resolver
-> x并z(S2) OFF/insufficient
-> x并z(S1) unchanged
-> x并z(A-system) unchanged
```

若删除 S1 而 portal-A 仍由 S2/其他服务工作，也不能据此改变 parent-level shell 判定。

锁定：

```text
child-state transition is local to that child ledger
```

## 6｜positive / negative controls

### Positive control A｜工程域

同一 API Gateway：

```text
/service/pay -> payment-service
/service/search -> opaque pool {search-v1, search-v2}
```

判定：

```text
x并z(payment-service) PASS
x并z(search-v1) insufficient
x并z(gateway/system) PASS
```

### Negative control A｜组织域

公司公共邮箱可稳定联系公司；其中法务组有公开专属邮箱，研发组只有内部随机转派：

```text
x并z(company) PASS
x并z(legal-team) PASS
x并z(dev-team) insufficient
```

不得因为 legal-team 可解析，就给 dev-team 回填。

### Positive control B｜制度域

统一政务大厅中，事项 A 有稳定事项编号，事项 B 只有“综合受理”后内部派单：

```text
x并z(item-A) PASS
x并z(item-B) insufficient
```

### Negative control B｜创作流程

工作室公共主页下，创作者甲有稳定署名/项目入口，创作者乙长期混合发布且不署名：

```text
x并z(studio) PASS
x并z(creator-A) PASS
x并z(creator-B) insufficient
```

## 7｜最小判别式

```text
FOR EACH tested_object O under shared grounded shell S:
  evaluate resolver(S, O) independently

IF resolver(S, O) is stable
AND third party can repeatedly identify/call/attribute/represent/enter O
THEN object-level x并z(O) = PASS candidate
ELSE object-level x并z(O) = insufficient
```

禁止：

```text
EXISTS child O1 with resolver=true
=> FOR ALL child O: resolver=true
```

简式：

```text
“同壳”共享的是入口，
不是对象级可解析性。
```

## 8｜失败类型与执行 guard

本轮确认一个此前 pending 中实际存在的实现级失败：

```text
FAILURE_RESOLVABLE_CHILD_BROADCAST:
同一公共壳下，只要一个 child 可解析，就把 object-level x并z 广播给全部 child。
```

它是 `FAILURE_SHARED_SHELL_BACKFILLS_ALL_OBJECTS` 的可执行子型，不另建 canonical family。

执行 guard：

```yaml
earth_resolution_ledger_guard:
  key_by:
    - public_shell
    - tested_object
    - object_layer
    - current_window

  prohibit:
    shell_level_boolean_broadcast_to_children: true
    sibling_resolver_evidence_backfill: true

  allow:
    mixed_child_results_under_same_shell: true
```

## 9｜收敛结论

本轮不是新建第三种土轴机制，而是把现有 `EARTH-OBJECT-RESOLVABLE-SHELL-MAPPING-GATE-v0.1` 的最后一个混合子对象 pending 做成逐对象账本并闭环。

状态迁移：

```text
同一壳对部分子对象可解析、部分不可解析
PENDING
-> CLOSED_BY_PER_OBJECT_LEDGER
```

成熟度：

```text
土轴 9.8 -> 9.9 / 10
AXIS_MATURE_CANDIDATE = true
```

剩余低优先级只保留：

```text
自然语言解析阶段把 tested object 错绑定到 parent system 的真实回归失败
```

若没有解释器实际失败，不再继续概念采矿。
