# 十元语义解释器｜xz vs xn：选项集合收窄与流程状态推进分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖或修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮目标与翻译债务

目标混淆对：`xz ↔ xn`。

本轮不重复“xz 是收窄、xn 是流程”这种已有机制，而处理一个仍未被 IR 硬约束的机器翻译漏洞：自然语言里的“层层、一步步、流程、筛选、淘汰、路径、节点、最后只剩”等词，既可能描述同层现实未来选项集合的减少，也可能只是在描述一个任务沿顺序节点推进。

高风险句型：

```text
流程越走越窄。
层层筛选后只剩一个。
每过一关就少一些。
一路走到最后只剩一个出口。
经过五个节点才能完成。
失败就退回上一步。
```

若解释器把 `path_set` 仅当“句中出现的路径/步骤列表”，就会把流程节点数量、待办数量、候选数量、现实替代路线数量混成同一种 cardinality。

本轮新增候选规则：

```text
OPTION-SET-CONTRACTION-vs-PROCESS-STATE-TOPOLOGY-v0.1
PATH_SET_MEMBER_TYPE_AUDIT_REQUIRED
MUTUAL_SUBSTITUTABILITY_AUDIT_REQUIRED
CARDINALITY-SEMANTICS_AUDIT_REQUIRED
```

核心不变量：

```text
alternative_option_member != process_stage_node
option_set_cardinality_change != workflow_progress
stage_count != real_option_count

一个 IR 的 path_set 不得同时混装：
- 可互相替代的现实未来选项；
- 必须先后经过的流程状态节点。
若同一事件同时含两者，强制 SPLIT_IR。
```

## 1｜Canonical guard

current L1/L2 对本轮具有最高权威：

```text
xz：退路、时间窗、路线和可逆空间持续收窄。
xn：运行权和判断权分布到顺序、规则、记录、节点和流程。
```

本研究只把这两个 canonical 变量落实到 Semantic IR 的 `path_set / object_layer / current_window / changed_variable / relation_shape / reality_anchor`，不新增 canonical 定义。

## 2｜自然语言 → Semantic IR 结构还原规则

遇到“流程越来越窄 / 层层淘汰 / 经过多步 / 最后只剩一个”时，必须先做以下结构还原，禁止先贴十元。

1. `actor/object`：若句子同时描述“A.任务怎样被处理”和“B.任务还能选择哪些现实去向”，必须拆成两个 object。
2. `object_layer`：xz 优先 `same_layer_real_future_option_set / route_or_window_reversibility_layer`；xn 优先 `process_state_topology / operation_coordination_layer`。
3. `current_window`：xz 必须比较至少两个现实选项集合快照，如 `t0:[A,B,C,D] -> t1:[B,C,D] -> t2:[C,D]`；xn 表达任务状态迁移，如 `registered -> checked -> assigned -> confirmed -> receipt`。
4. `changed_variable`：xz 用 `real_option_set_contraction / reentry_or_reversibility_space_contraction`；xn 用 `operational_state_transition_structure / workflow_coordination_topology`；结构不足则 `unknown`。
5. `relation_source/relation_shape`：xz 追现实选项为何关闭、汇流或失去回退；xn 追状态为何按规则、节点、记录、handoff、retry 运行。
6. `decision_right`：xz 不要求单一裁定者；xn 也不要求最终战略方向权。`workflow_design_and_routing != final_direction_choice`。
7. `path_set`：每个元素写入前必须判断，它与其他元素是“可互相替代的同层现实去向”，还是“完成同一任务时先后/条件经过的处理状态”。前者服务 xz audit，后者服务 xn audit。禁止在一个 IR 内混装 `route_A, route_B, review_node, retry_queue`。
8. `reentry_right`：流程失败退回前节点是 workflow reentry，不等于现实未来选项被恢复。
9. `future_endpoint`：`future_endpoint != xz`；只有终点真实约束 current option set 且 option set 随阶段收窄时才参与 xz gate。xn 的完成态也不等于命运收窄。
10. `reality_anchor`：xz 必须回答“哪一个现实可替代选项在何时真正失效”；xn 必须回答“哪个任务真实经过哪些节点，节点规则如何影响下一状态”。

## 3｜标准输入与完整 IR

输入：

> 应急调度中心同时有东、北、南、西四条运输路线。暴雨后东线桥梁断裂，东线退出；第二天北线实施交通管制，北线也退出，当前只剩南线和西线仍可现实通行。路线不是被调度流程“审核掉”的。与此同时，每张运单都必须依次经过登记、风险检查、分派、司机确认和回执；风险检查失败会退回登记补资料，司机拒单会退回分派重新安排。这个五节点流程每天重复运行，即使当天四条路线都开放，流程仍照样存在。

必须 `SPLIT_IR`。

### IR-A｜xz：同层现实路线选项收窄

```yaml
actor: 应急运输调度体系
object: 当前可现实采用的运输路线集合
object_layer: same_layer_real_route_option_set
current_window: t0=[东,北,南,西] -> t1=[北,南,西] -> t2=[南,西]
changed_variable: real_option_set_contraction
relation_source: staged_external_route_closures
relation_shape: mutually_substitutable_route_options_progressively_removed
decision_right: none_single_final_adjudicator
path_set:
  - t0: [东, 北, 南, 西]
  - t1: [北, 南, 西]
  - t2: [南, 西]
reentry_right: 东线与北线在当前暴雨管制窗口内不可直接恢复
future_endpoint: null
reality_anchor: 东线桥断和北线管制分别让两条原本可替代的现实路线失效，路线集合从4降到3再降到2
```

判定：`xz candidate PASS`。

### IR-B｜xn：运单处理流程状态推进

```yaml
actor: 应急调度中心流程设计与运行方
object: 运单从进入系统到形成回执的处理方式
object_layer: internal_process_state_topology
current_window: 登记 -> 风险检查 -> 分派 -> 司机确认 -> 回执；失败按规则回退并重试；每日重复
changed_variable: operational_state_transition_structure
relation_source: actor_generated_and_maintained_workflow
relation_shape: sequential_handoff_with_retry_and_record
decision_right: workflow_design_and_rule_routing
path_set:
  - registration_node
  - risk_check_node
  - dispatch_node
  - driver_confirmation_node
  - receipt_node
reentry_right: risk_failure_returns_to_registration; driver_rejection_returns_to_dispatch
future_endpoint: receipt_completed_or_task_reenters_retry_node
reality_anchor: 运单每天真实经过登记、检查、分派、确认、回执节点，失败任务按固定规则回到指定节点重试
```

判定：`xn candidate PASS`。

这里的五个元素是流程状态，不是五条互相替代的未来路线；任务从登记进入检查，不意味着“登记这个未来选项被关闭”。

## 4｜Positive decision gates

### xz candidate gate

```text
XZ1 object_layer 明确是同层现实未来选项、路线、窗口或可逆空间；
XZ2 path_set 成员是可互相替代的现实去向，而不是必须先后经过的流程节点；
XZ3 current_window 至少存在两个可比较的 option-set snapshot；
XZ4 changed_variable 是 real_option_set / reversibility_space 的变化；
XZ5 至少一个原先现实可调用的 option 在后续阶段真正失效、关闭或不可回退；
XZ6 reality_anchor 能指出“哪条 option 为什么不再可调用”；
XZ7 仅有 deadline、阶段数量、任务完成、一次选择、流程推进均不足；
XZ8 removal 关闭机制后，option-set contraction 应停止或明显减弱。
```

### xn candidate gate

```text
XN1 object_layer 明确是运行方式或 process-state topology；
XN2 path_set 成员是顺序、节点、记录、handoff、queue、retry 等流程元素；
XN3 relation_shape 能说明任务怎样从一个状态进入下一状态；
XN4 至少存在两个不同功能的节点/规则元素；
XN5 current_window 跨阶段，并有真实重复调用、维护或状态持久化；
XN6 changed_variable 是 workflow/operation topology，而非 future-option cardinality；
XN7 reality_anchor 能指出真实任务如何经过节点并被节点规则改变状态；
XN8 removal 关键流程节点后，运行/交接/记录出现可命名缺口，即使未来选项集合完全不变。
```

## 5｜nearest-neighbor 最小差异

### 最小差异 1｜四个步骤 vs 四个选项

```text
登记 -> 审核 -> 分派 -> 完成
```
四个元素必须先后经过，是 process-state nodes；优先审 `xn`。

```text
东路 / 北路 / 南路 / 西路
```
四个元素在同一时刻可以互相替代，是 alternative options；若其现实集合持续减少，优先审 `xz`。

### 最小差异 2｜流程持续，但选项不减少

```text
五节点 SOP 每天重复；所有三种产品方案从头到尾都仍然可提交。
```
预期：`xn PASS / xz FAIL或不升`。

### 最小差异 3｜选项减少，但没有流程

```text
三条山路因两次塌方先后关闭，3 -> 2 -> 1；没有登记、审核、分派、记录或稳定处理节点。
```
预期：`xz PASS / xn FAIL或弱`。

邻居提醒：一次最终裁定把多个候选直接变成一个结果，不得把 `N -> 1` 的数字外观自动当成 staged xz；流程设计权回答“事情怎么跑”，也不等于主体方向权回答“哪条自身方向获得现实优先”。

## 6｜False-positive guards

1. “层层审核” ≠ xz；先判这些层是 process stages 还是 alternative options。
2. “筛选” ≠ xz；筛选任务状态不等于同层未来选项减少。
3. 未处理工单数量下降 ≠ xz；可能只是完成量上升。
4. “流程路径” ≠ 命运/未来可选路径。
5. “最后只剩一个完成态” ≠ xz；每个流程本来就可能只有一个完成态。
6. “五个节点” ≠ xn；若没有真实状态迁移/重复调用，仍不足。
7. 流程能退回上一步不自动证明/否定 xz；要看被恢复的是流程状态还是现实去向。
8. 没有 xn 流程 ≠ xz 成立；没有 xz 收窄 ≠ xn 成立。
9. 从头到尾只有一个现实选项，不能称持续收窄。
10. 一个任务离开 queue 只说明 process state 改变，不证明未来 option 被永久关闭。

## 7｜Removal / reverse / same-layer / current-window

### Removal

- 拿掉流程、保留东线桥断和北线管制：`xn ↓ / xz 保持`。
- 四条路线全部恢复、保留五节点 SOP：`xz ↓ / xn 保持`。

### Reverse

- `[南,西] -> [北,南,西]`：现实 option set 扩张，xz 应下降/重新审计，xn 不因而变化。
- 把“检查 -> 分派”重排为“预分派 -> 检查 -> 确认”，若现实路线集合不变，只影响 xn topology，不给 xz 加分。

### Same-layer

```text
route_option_set_layer != process_state_topology_layer
```

同一个“调度系统”可以承载两层，但 Semantic IR 不得因为 artifact 相同就共用一个 path_set。

### Current-window

- xz 比较必须发生在同一收窄过程内；去年缩到一条、今年四条已恢复，不能把历史收窄永久贴到当前。
- xn 只判当前实际运行流程；去年五级审批、今年改成一次直派，旧节点不能继承。

## 8｜Adversarial tests

### T1｜关键词诱导
“申请层层筛选，最后进入完成状态；但A/B/C三种申请方案从提交到完成始终都可以改选。”
预期：真实流程可查 `xn`；`xz FAIL/弱`。

### T2｜题材/职业/情绪诱导
“冷酷的招生主任说‘每过一关命运就少一条路’，但材料只证明有登记、面试、体检三个流程节点，没有证明任何专业志愿失效。”
预期：职业、冷酷、命运措辞不能产 xz；流程真实运行可查 xn。

### T3｜对象层错位
“医院转诊单经过登记、审核、床位确认；与此同时三家可转诊医院因床位满员先后只剩一家。”
预期：处理单流程层 `xn`；可转诊医院 option-set 层 `xz`；强制 SPLIT_IR。

### T4｜时间窗错位
“上个月三条撤离路缩成一条；本周道路已全部恢复，但旧五步报备流程仍继续使用。”
预期：当前旧 xz 不继承；当前 xn 可保持。

### T5｜同关系词异对象层
A：“这个工单被淘汰出待处理队列，因为已经完成。”
B：“北线被淘汰出撤离路线集合，因为桥已封闭。”
预期：A 是 process-state exit；B 才是 alternative-option removal；禁止同词同判。

### T6｜对端不存在不等于本端成立
“这里只有一条路，从开始到结束都没有第二条，也没有任何登记、审核、交接流程。”
预期：`xn FAIL`；`xz 也 FAIL/UNKNOWN`，因为没有从多到少的现实收窄。

### T7｜流程重试伪 xz
“代码审查失败就退回开发，重新提交后再审；A/B/C三种实现路线始终都可选。”
预期：retry/reentry 强化 xn topology；不因“退回/再走”判 xz。

### T8｜纯现实收窄无流程
“四座桥因洪水按时间先后断了三座，没有任何管理者审核或流程设计。”
预期：若四桥原先互为现实替代路线，则 `xz PASS`；`xn FAIL/弱`。

### T9｜同系统双层并存
“奖学金系统内部有申请、材料核验、复审、发放四节点；同时候选学校资格因政策逐月从5所降到3所再降到1所。”
预期：`xn + xz` 均可成立，但必须两个 IR。

### T10｜未处理数量下降伪 xz
“待处理工单从100个降到20个，因为80个已经完成；客户仍可在A/B/C三种服务方案间自由选择。”
预期：queue size 下降不等于 future-option contraction。

### T11｜流程复杂度伪 xn
“文件上画了十个流程框，但实际所有任务都由一个人直接处理，从未经过这些节点，也没有记录或状态迁移。”
预期：`xn FAIL/UNKNOWN`；画出来的流程图不是 reality anchor。

### T12｜最小 mutation
Base：“系统有五条路径。”

Mutation A：“五条路径 = 五个互相替代的现实出口；两次封闭后 5 -> 3 -> 2。” → `xz ↑`。
Mutation B：“五条路径 = 登记、审核、分派、确认、回执五个必须先后经过的处理节点；每天重复。” → `xn ↑`。

若解释器仅因“系统/路径/五条”相同而保持原十元标签，判定失败。

## 9｜状态迁移规则

### OPTION-SET STATE｜xz

```text
multiple_mutually_substitutable_real_options
→ one_or_more_options_reality-disabled
→ fewer_real_options
→ further_closure_or_irreversible_convergence
= xz evidence ↑
```

反向：`closed_option_reopens -> real_option_set expands -> xz evidence ↓ / re-audit`。

### PROCESS-STATE TOPOLOGY｜xn

```text
ad_hoc_handling
→ explicit_state_nodes
→ rule_routed_handoff_and_record
→ repeated_cycle_with_retry/state_persistence
= xn evidence ↑
```

反向：`nodes_removed_or_bypassed -> handoff/record/retry disappears -> xn evidence ↓`。

独立性：

```text
xz ↑ != xn ↑
xn ↑ != xz ↑
```

同一现实系统同时存在“流程机制”与“同层可选项持续减少”时，两者可共存，但必须 `SPLIT_IR`。

## 10｜成功门审计

本轮新增：

1. `PATH_SET_MEMBER_TYPE_AUDIT_REQUIRED`；
2. `MUTUAL_SUBSTITUTABILITY_AUDIT_REQUIRED`；
3. `CARDINALITY-SEMANTICS_AUDIT_REQUIRED`；
4. 一个 IR 的 `path_set` 禁止混装 `alternative_option_member` 与 `process_stage_node`；
5. “数量减少”必须先确认被计数的是未来替代选项，而非 queue/task/stage 数；
6. 流程 retry 与现实选项 reentry 分离；
7. 同一 artifact 上 xz/xn 共存时按 object_layer 拆 IR；
8. 对 `path_set` 语义类型的最小 mutation 测试。

因此满足提交成功门。

## 12｜下一轮风险候选

本轮使用 `xz / xn`，下一轮不得连续选择二者。

下一候选优先审计：`zx ↔ x`。

高风险句型：

```text
“我掌握了这个资源，所以我把自己的方向推成了现实。”
“我有决定权，但我没有用它改变任何竞争方向。”
```

需要继续拆 `current control/disposition scope` 与 `self-direction power actually exercised in reality`，重点字段为 `object_layer + changed_variable + decision_right + relation_shape + reality_anchor`。
