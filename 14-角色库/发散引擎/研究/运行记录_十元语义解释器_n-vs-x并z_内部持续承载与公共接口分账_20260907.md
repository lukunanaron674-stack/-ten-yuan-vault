# 十元语义解释器｜n vs x并z｜内部持续承载与公共接口分账

> 研究层候选。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮翻译债务

`n` 与 `x并z` 都容易被“接纳、内部、共同体、空间、归属、入口、成员、家、机构、平台”之类名词诱导。

真正的 canonical 差异不是题材，而是结构：

```text
n：
对象已经真实进入主体/结构内部
→ 获得可持续位置
→ 主体/结构跨阶段处理该对象带来的现实负荷
→ 压力下仍保持一定承载

x并z：
内部对象/关系/能力已经存在
→ 形成稳定公共壳/接口
→ 第三方可通过该壳持续识别、调用、归因、代表或进入
```

本轮新增的解释器核心不是再列同义词，而是冻结“因果箭头方向”：

```text
n asks:
object -> inside -> sustained load on carrier

x并z asks:
third_party -> public shell/interface -> identifiable/callable internal object
```

同一个“进入”动词可以出现在两边，但进入者、经过的接口和 changed_variable 完全不同。

## 2｜新翻译规则：INTERNAL-CARRYING-vs-PUBLIC-INTERFACE-v0.1

自然语言先做以下结构还原，禁止从“家、医院、公司、成员、门牌、账号”等名词直接判元：

```text
STEP 1 冻结 actor / object / object_layer / current_window。

STEP 2 识别 changed_variable：
- internal_load_carrying / internal_position_continuity -> 优先查 n
- public_identifiability / callable_interface / attribution_interface / public_entry_interface -> 优先查 x并z
- 不清楚则 unknown，不补猜。

STEP 3 审计 relation_shape 的箭头：
A. object -> internal position -> repeated load handling
B. third party -> stable public shell -> internal object

STEP 4 审计 reality_anchor：
- n 要证明对象留下后，主体/结构真的承担时间、资源、风险、照护、协调或空间负荷；
- x并z 要证明至少一个第三方真的可通过稳定壳持续识别、调用、归因、代表或进入。

STEP 5 若一句话同时含 A 与 B，SPLIT_IR；不得把“有前台所以能接住人”或“真能接住所以已有公共入口”互相倒推。
```

### IR 字段约束

固定字段不扩展；本轮只增加字段解释约束：

```text
actor:
  n = 承担内部负荷的主体/结构
  x并z = 维持公共壳或被公共壳映射的主体/对象，按句子确定

object:
  n = 被接收并持续留在内部的对象
  x并z = 被公共壳稳定映射、识别或调用的内部对象/关系/能力

changed_variable:
  n = internal_position_continuity / sustained_load_carrying
  x并z = public_identifiability / callable_interface / attribution_interface / public_entry_interface

relation_source:
  n = internal_carrier / organization / relation / unknown
  x并z = public_shell / institutional_interface / stable_name_or_role / unknown

relation_shape:
  n = object_enters_and_is_carried_across_stages
  x并z = third_party_routes_through_shell_to_internal_object

path_set:
  n = admission + stay + recurring handling/protection/support paths
  x并z = identify/call/attribute/represent/enter paths through public shell

reentry_right:
  非本对 primary gate；除非句子明确涉及返回，不得用它代替 n 的承载或 x并z 的接口。

future_endpoint:
  非本对 primary gate；默认 null/unknown。

reality_anchor:
  n = 负荷确实被主体内部持续处理
  x并z = 第三方通过壳确实改变识别/调用/归因/进入方式
```

## 3｜标准输入

输入：

> 社区夜间收容点允许登记后的流浪者连续住满十四天，工作人员每天提供床位、餐食、药物登记和冲突协调；这个收容点同时使用一个固定名称、门牌和公开热线，医院与街道人员可以凭该名称和热线持续找到并转介人员进入。

这句话必须 SPLIT_IR。

### IR-A｜内部持续承载层

```yaml
actor: 社区夜间收容点
object: 已登记并连续居住的流浪者
object_layer: 收容点内部居住与持续负荷处理层
current_window: 登记进入 -> 连续居住十四天 -> 每日床位餐食药物登记与冲突协调
changed_variable: sustained_load_carrying
relation_source: internal_carrier
relation_shape: object_enters_and_is_carried_across_stages
decision_right: admission_and_internal_support_within_program_rules
path_set:
  - admission_after_registration
  - bed_allocation
  - daily_meal_support
  - medication_record_handling
  - conflict_coordination
reentry_right: unknown
future_endpoint: end_of_14_day_stay_or_next_program_state
reality_anchor: 对象进入后连续占用床位、餐食、登记和协调资源，工作人员每日处理这些负荷
```

判定：`n candidate PASS`。

### IR-B｜稳定公共接口层

```yaml
actor: 社区夜间收容点
object: 收容点作为可被第三方识别和调用的公共服务对象
object_layer: 对外识别、转介与进入接口层
current_window: 固定名称/门牌/热线持续存在 -> 医院与街道人员反复识别和转介
changed_variable: public_entry_interface
relation_source: stable_public_shell
decision_right: null
relation_shape: third_party_routes_through_shell_to_internal_object
path_set:
  - identify_by_fixed_name
  - locate_by_address_sign
  - call_public_hotline
  - refer_person_through_public_interface
reentry_right: null
future_endpoint: null
reality_anchor: 第三方无需认识内部工作人员，也能通过固定名称、门牌和热线持续找到并调用该服务
```

判定：`x并z candidate PASS`。

两端可以同场景并存，但理由绝不共用。

## 4｜positive decision gate

### n gate

至少要求：

1. actor/object/object_layer/current_window 可识别；
2. 对象真实进入内部并获得可持续位置；
3. current window 跨至少两个阶段或存在重复负荷；
4. path_set 中存在现实的处理/保护/补给/照护/内部协调；
5. reality_anchor 证明主体实际承担由对象留下所产生的负荷；
6. 对象不是纯拘禁、封锁或一次性转交。

没有“持续负荷处理”，只看到空间内部或成员名义，不得 positive。

### x并z gate

至少要求：

1. 壳对象明确；
2. 第三方可通过该壳稳定识别被映射对象；
3. 壳不是一次性视觉、临时称呼或单次宣传；
4. path_set 至少有一个可重复的 identify/call/attribute/represent/enter 接口；
5. 壳与内部对象存在稳定映射；
6. reality_anchor 证明该壳实际改变第三方找到、调用、归因、代表或进入的方式。

只有“内部很好”“有名字”“穿制服”“有门”都不够。

## 5｜nearest-neighbor 最小差异

### n vs x并z

```text
n：内部有没有真实接住，并持续承担对象留下后的负荷？
x并z：外部第三方有没有稳定壳，可以持续知道怎样找到、称呼、调用、归因或进入该对象？
```

最小差异：

- 一个没有门牌、没有公开热线的秘密避难所，也可能内部 n 很强；
- 一个品牌、前台、门牌、账号极稳定的机构，内部可能根本接不住任何真实负荷，只有 x并z 壳。

### n vs nz

`n` 看对象已经进入之后是否被持续承载；`nz` 看自由离开/分离之后是否仍存在对象特异、可信、现实可执行的回返与修复空间。

“住得下”不能自动推出“离开后回得来”。

### x并z vs x

`x并z` 是公共可识别/调用接口；`x` 是对象、资源、权限或关系当前现实受谁掌握和处分。

有门牌不等于拥有房子；拥有房子不等于已有稳定公共入口。

## 6｜false-positive guards

1. 房屋/家庭/医院/避难所题材 ≠ n。
2. 对象物理位于内部 ≠ n；拘禁与封锁不是持续承载。
3. 一次接待/一次救援/一次转交 ≠ stable n。
4. 名称/制服/面具/门牌出现 ≠ x并z。
5. 一次宣传/一次曝光/一次自称 ≠ stable x并z。
6. 内部承载很好 ≠ 自动存在公共可识别接口。
7. 公共接口很漂亮 ≠ 自动存在内部承载能力。
8. 第三方知道对象存在 ≠ 已有可调用/归因/进入接口。
9. 对端 FAIL ≠ 本端 PASS。
10. “进入”是词，不是十元；必须识别是谁进入、进入哪里、经过什么路径、改变什么变量。

## 7｜removal / reverse / same-layer / current-window

### n removal

拿掉 recurring handling/support paths：若对象仍在物理内部，但床位、餐食、风险、协调等负荷不再由 actor 处理，则 stable n 应显著下降。

### x并z removal

拿掉固定名称、登记、门牌、热线、账号等稳定公共接口：若第三方无法再持续识别/调用/归因/进入，则 x并z 应下降；内部是否仍能承载另判。

### reverse

- 保留“温暖的家/接纳所有人”台词，但对象只被关押且不处理负荷：n 必须 FAIL。
- 保留华丽门面与品牌，但第三方无法据此实际找到、调用或进入：x并z 必须 FAIL。
- 让内部承载完全不变，只撤公共接口：n 可继续 PASS，x并z 下降。
- 让公共接口完全不变，只撤内部负荷处理：x并z 可继续 PASS，n 下降。

### same-layer

禁止把“内部居住承载层”和“对外公共入口层”揉成同一个 object_layer。它们可以属于同一机构、同一句话、同一 actor，但 changed_variable 不同。

### current-window

历史上曾经有门牌/品牌，不代表当前 x并z 在线；历史上曾经能承载，不代表当前 n 在线。关闭热线、撤登记、资源枯竭、转为一次性临时安置后均需重新判。

## 8｜Adversarial tests

### Test 1｜关键词诱导

输入：
> “这里是所有人的家，永远接纳你。”实际只允许人在大厅停十分钟，随后立即转交别处，不提供持续位置或负荷处理。

预期：`n FAIL`。关键词“家/接纳”不得覆盖现实结构。

### Test 2｜题材/职业/情绪诱导

输入：
> 一位慈祥护士在医院工作，但病区所有长期照护都由另一团队承担，她只在门口问候一次。

预期：该护士作为 tested actor 的 stable `n FAIL`；职业和温柔情绪不得倒推十元。

### Test 3｜对象层错位

输入：
> 地下避难所内部能长期供养二十人，但没有公开地址、名称或第三方转介接口。

预期：内部承载层 `n candidate PASS`；公共接口层 `x并z FAIL/UNKNOWN`。

### Test 4｜时间窗错位

输入：
> 去年救助站有稳定热线和床位，今年热线已注销且床位系统停摆，只剩旧招牌。

预期：当前 stable `n FAIL/UNKNOWN`，当前 stable `x并z FAIL/weak`；不能沿用历史状态。

### Test 5｜同关系词异对象层

输入 A：
> “可以进入中心居住”，进入后连续三周被供餐、照护和协调。

预期：进入后的负荷层查 `n`。

输入 B：
> “可以进入中心官网”，公众通过固定域名查到服务并提交转介。

预期：公共接口层查 `x并z`。

同一个“进入”词不能共享判定。

### Test 6｜对端不存在不等于本端成立

输入：
> 一间废弃仓库既没人管理，也没有名称、入口规则或公共识别，只偶尔有人躲雨。

预期：`n FAIL/UNKNOWN + x并z FAIL/UNKNOWN`。非 x并z 不推出 n，非 n 不推出 x并z。

### Test 7｜强制容纳伪 n

输入：
> 监狱把犯人长期关在牢房内，唯一结构目标是阻止离开；没有以对象持续福祉/内部处理为承载逻辑的独立证据。

预期：仅凭“长期在内部”不得判 stable n；转查 x/xn/zx 等控制结构。

### Test 8｜漂亮前台伪 n

输入：
> 某救助品牌有统一制服、官网、热线、门牌，但来访者一律登记后当日转出，机构本身不提供持续位置或负荷处理。

预期：`x并z candidate PASS`，stable `n FAIL`。

### Test 9｜秘密承载伪 x并z

输入：
> 私人安全屋连续数月接住受威胁者并处理食宿和风险，但故意不设公开名称、门牌、热线，外部第三方无法稳定识别或调用。

预期：`n candidate PASS`，public-shell `x并z FAIL/UNKNOWN`。

### Test 10｜公共可识别 ≠ 可调用

输入：
> 全城都知道一栋楼叫“旧钟塔”，但名称既不代表组织、服务、权限或稳定进入接口，也不改变任何第三方调用/归因关系。

预期：仅公共知名度不足以自动锁 `x并z`；需要 stable mapping + interface function。

## 10｜本轮真实新增

本轮不是重复“n 是承载、x并z 是壳”的定义，而新增三个解释器层资产：

### A. 因果箭头翻译规则

```text
n:
object -> internal position -> sustained load on carrier

x并z:
third_party -> stable shell/interface -> internal object
```

解释器遇到同一个“进入/接纳/内部”词，必须先还原箭头，不得直接标签化。

### B. changed_variable 分流

```text
internal_position_continuity / sustained_load_carrying
!=
public_identifiability / callable_interface / attribution_interface / public_entry_interface
```

### C. 双向独立 removal

同一机构可以：

```text
remove public interface, keep carrying -> n survives, x并z falls
remove carrying, keep public interface -> x并z survives, n falls
```

这构成高价值最小差异，满足本轮 GitHub 成功门。

## 12｜给解释器/Z发散器的镜像摘要

```text
n vs x并z

先问因果箭头：
1. object -> inside -> recurring load handling ?
   => evaluate n
2. third_party -> stable public shell -> internal object ?
   => evaluate x并z

同一“进入/接纳/内部”词不得直接触发标签。
同一机构可 n+x并z 分层并存。
强制容纳不是 n；漂亮公共壳不是 n；秘密承载不自动有 x并z。
```

## 13｜下一最高翻译风险

优先：**n ↔ nz**。

理由：`n` 与 `nz` 都会出现“回来、接住、家、成员、一直给你留位置”等表述。current canonical 已有一句最近邻定义，但 Semantic IR 仍需要把：

```text
n = object already inside -> sustained carrying
nz = object leaves/separates -> object-specific executable reentry/repair
```

正式压成阶段状态机。最危险的是“反复回来”既可能只是 n 的跨阶段内部承载证据，也可能是真正 nz reentry；下一轮应通过 current_window + reentry_right + path_set lifecycle 区分，而不是继续喂关键词。
