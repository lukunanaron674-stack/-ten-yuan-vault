# 十元语义解释器｜xn vs z 轮转校准

> 研究用途。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定”。不得覆盖 current canonical，不写行为 evidence，不直接修改 Canvas。

## 1. 当前翻译债务

自然语言中的“安排、决定、定计划、设节点、通过、确认、批准、认定”常被模型压成同一类“做决定”。但 current canonical 下，`xn` 与 `z` 测的不是同一个 changed_variable：

- `xn`：主体是否主动组织时间、流程、规则、记录、资源和节点，使行动形成可持续运行结构；
- `z`：某认可/确认主体是否对存在、能力、身份、资格、责任、事实状态或关系位置形成并采用一个确认结论。

因此新增翻译门：**过程结构（process structure）与确认状态（recognition/adoption state）必须先拆成两个 IR slice，再分别判定。**

## 2. 新翻译规则｜PROCESS-vs-CONFIRMATION-v0.1

```text
STEP 1：先锁 object_layer。

若句子回答“事情怎样被持续组织、按什么顺序/规则/节点运行”：
  changed_variable = execution_structure / temporal_structure / workflow_state
  → 检查 xn。

若句子回答“谁把什么内容确认进哪个认可/采用位置”：
  changed_variable = recognition_state / adoption_state / confirmation_state
  → 检查 z。

STEP 2：若同一句同时包含流程与确认节点：
  SPLIT_IR
  - slice A = process layer → xn gate
  - slice B = confirmation/adoption layer → z gate

STEP 3：禁止把以下东西互相冒充：
  plan exists ≠ xn
  one decision node exists ≠ xn
  process exists ≠ z
  institutional procedure ≠ z
  objective fact true ≠ z
  recognition word appears ≠ z
```

### IR 字段约束

`xn` 候选优先读取：

- `changed_variable`
- `object_layer`
- `current_window`
- `relation_shape`
- `decision_right`
- `path_set`
- `reality_anchor`

其中 `relation_shape` 应能还原为 repeated/ordered/staged/recorded/scheduled 等运行结构，而不是只写“有计划”。

`z` 候选优先读取：

- `actor`（被确认者）
- `object`（被确认内容）
- `object_layer`
- `current_window`
- `relation_source`（确认主体来源）
- `relation_shape`（recognize/adopt/deny/withdraw）
- `future_endpoint`（若确认是否进入后续采用位置）
- `reality_anchor`

**新约束：`decision_right` 不能代替 `relation_source`。** 谁有权作流程决定，不等于谁在做 z 的确认；谁确认了某对象，也不等于他组织了整个运行结构。

## 3. Positive decision gates

### xn candidate gate

```text
X1 object_layer 明确落在运行/流程/时间/规则/记录/资源组织层；
X2 actor 对“怎样持续运行”有主动组织作用；
X3 current_window 内不只是一次动作，而是至少形成顺序、节点、规则、重复、记录、资源配置之一；
X4 relation_shape 能表达结构连续性，而非单个 final decision；
X5 removal 该组织结构 → 同层运行能力/连续性/可重复性出现现实缺口；
X6 若只有一次临时决定、一次签字、一次确认，xn 不得 positive。
```

### z candidate gate

```text
Z1 必须能命名确认主体；
Z2 必须能命名被确认内容；
Z3 object_layer 落在存在/能力/身份/资格/责任/事实状态/关系位置的确认层；
Z4 relation_shape = recognize / confirm / adopt / deny / withdraw 等认可关系；
Z5 current_window 内该确认进入明确采用范围或至少现实改变被确认者/下游程序的位置；
Z6 removal 认可关系 → 该确认位置不再同样成立；
Z7 客观事实、规则、程序、证据、权力本身不得直接写成 z。
```

## 4. 标准输入与完整 IR

输入：

> “项目负责人把评审拆成三轮，每轮两天，规定每轮必须记录问题并在下一轮前关闭；第三轮结束后，委员会正式确认方案达到上线资格，于是进入发布流程。”

### IR-A｜流程层

```yaml
actor: 项目负责人
object: 方案评审
object_layer: 评审运行结构
current_window: 三轮评审开始 -> 每轮记录与关闭问题 -> 第三轮结束
changed_variable: execution_structure
relation_source: self
relation_shape: staged_repeated_recorded_workflow
decision_right: self_on_workflow_design
path_set:
  - round_1_review
  - issue_recording
  - closure_before_next_round
  - round_2_review
  - round_3_review
reentry_right: workflow_defined
future_endpoint: 第三轮完成
reality_anchor: 去掉分轮/记录/关闭节点后，原三轮评审的持续运行结构消失
```

判定：**xn candidate PASS**。

### IR-B｜确认层

```yaml
actor: 方案
object: 上线资格
object_layer: 机构资格确认层
current_window: 第三轮结束 -> 委员会确认 -> 发布流程开启
changed_variable: confirmation_state
relation_source: 委员会
relation_shape: institutional_adoption_of_qualification
decision_right: committee_on_qualification
path_set:
  - committee_review_result
  - qualification_confirmation
reentry_right: unknown
future_endpoint: 发布流程可进入
reality_anchor: 委员会确认前不能以“已达上线资格”进入发布流程；确认后可进入
```

判定：**z candidate PASS**。

整句结论：**xn + z 分层并存，禁止 whole-sentence collapse。**

## 5. nearest-neighbor 最小差异

### xn vs z

最小差异 1：

```text
“把三轮评审排成流程” → xn
“第三轮后委员会确认上线资格” → z
```

前者改变 `execution_structure`；后者改变 `confirmation_state`。

最小差异 2：

```text
“负责人决定周五提交”
```

若只是一次最终时间点决定，没有可持续结构，不能自动 xn；若“周五提交”只是被某主体认可/采用的资格或结果，也不能自动 z。必须继续看 object_layer。

### xn vs nx

外部给目标、主体自己排流程：高层可 nx，局部运行层可 xn。外部来源存在不能擦掉 xn。

### z vs zx

被委员会确认“有资格”是 z；主体主动扩张现实决定半径、压入公共现实的是 zx。被认可的结果不能倒推主体权能扩张。

## 6. removal / reverse / same-layer / current-window

### Removal

- 拿掉分轮、记录、节点与时间结构，如果事情仍以同样连续方式运行，xn 证据下降。
- 拿掉委员会确认，如果“上线资格”仍在同一采用范围内成立且下游照常启动，z 证据下降。

### Reverse

- 保留“计划、安排、流程”关键词，但改成“一次临时口头决定，之后没有任何重复/节点/记录”，xn 必须 FAIL/UNKNOWN。
- 保留“确认、批准、认定”关键词，但改成“该主体只有建议权，结果不进入任何采用位置”，z 必须 FAIL/UNKNOWN。

### Same-layer

流程设计层与资格确认层即使在同一事件中发生，也必须拆层。不能因为委员会既制定流程又作最终确认，就把所有动作归成同一十元。

### Current-window

历史上曾制定过流程，不等于当前 xn 在线；历史上曾认可某身份，也不等于当前 z 仍有效。必须看当前窗口该结构或确认是否仍被采用、运行或撤销。

## 7. adversarial tests

### T1｜关键词诱导：计划 ≠ xn

输入：“他计划明天辞职，但没有安排任何步骤、节点、资源或后续流程，当晚又放弃了。”

IR 摘要：changed_variable=intention；relation_shape=single_intention；execution_structure absent。

预期：**xn FAIL**。

### T2｜题材/职业/情绪诱导：官僚机构 ≠ xn / z

输入：“这是一个严肃的政府部门，大家情绪紧张，但今天既没有新流程被组织，也没有任何身份、资格、责任或事实状态被确认。”

预期：**xn FAIL / z FAIL**。题材、职业、气氛不能倒推。

### T3｜对象层错位

输入：“校长制定了整学期的巡课排程；期末教师委员会确认某教师达到晋升资格。”

预期：排程层 **xn PASS**；晋升资格确认层 **z PASS**；禁止整句只判一个。

### T4｜时间窗错位

输入：“去年委员会确认他是项目负责人；今年该任命已经撤销，但他仍沿用自己设计的周报、排期和风险复盘流程。”

预期：当前 z（项目负责人确认）**OFF/撤销**；当前运行层 xn **candidate PASS**。

### T5｜同关系词异对象层：‘决定’

A：“她决定把护理分成早中晚三班，并建立交接记录。”
- changed_variable=execution_structure → **xn candidate**。

B：“委员会决定认定她具备执业资格。”
- changed_variable=confirmation_state → **z candidate**。

同一个“决定”不能直接触发同标签。

### T6｜对端不存在不等于本端成立

输入：“这个项目既没有明确流程，也没有任何主体确认它成功或失败，只是暂停。”

预期：**xn FAIL/UNKNOWN；z FAIL/UNKNOWN**。xn 不存在不推出 z，z 不存在也不推出 xn。

### T7｜一次 final-decision node 伪 xn

输入：“老板在最后一分钟拍板选择供应商，之前没有设计采购流程、比较节点、记录规则或重复机制。”

预期：该句不足以判 xn。`decision_right=self` 不能代替 execution_structure。

### T8｜程序存在伪 z

输入：“系统每天自动跑十次校验并记录日志，但没有任何主体把结果确认成资格、身份、责任或事实结论。”

预期：可检查 xn/自动结构，但 **z FAIL**。程序与日志本身不是认可主体。

### T9｜确认词伪 z

输入：“同事说‘我确认看过文件’，但这句话不改变文件身份、资格、责任、采用范围或任何下游状态。”

预期：**z FAIL/极弱**。动词“确认”不是 z 的充分条件。

### T10｜主动执行不能抹掉 z

输入：“研究团队自己设计完整实验流程；最终期刊编辑正式确认论文接受发表。”

预期：实验/投稿组织层可 xn；接受发表这一确认位置可 z。主动组织不擦掉后续 z。

### T11｜被确认不能倒推 xn

输入：“演员获得评委确认‘最佳新人’，但整个参赛流程、排练计划和资源安排都不是她组织的。”

预期：z candidate；xn 不因获奖、被认可而成立。

### T12｜客观事实 ≠ z

输入：“温度计显示机器已经超过 100°C，但没有任何主体把这一读数采用为故障认定或停机资格。”

预期：事实/证据层另查；**z FAIL/UNKNOWN**。若后来工程师委员会正式采用该读数作故障认定，则另开 z slice。

## 8. 通过/失败统计

本轮 12 个 adversarial tests 均通过预期边界设计：

- keyword lure: 2
- genre/profession/emotion lure: 1
- object-layer mismatch: 1
- shifted-window: 1

## 9. 本轮新增翻译规则

新增候选规则：`PROCESS-vs-CONFIRMATION-v0.1`

核心新约束：

```text
execution_structure ≠ confirmation_state
single decision node ≠ sustained xn
procedure exists ≠ z
objective fact true ≠ z
recognition verb appears ≠ z
decision_right ≠ recognition_source
same actor/event can require SPLIT_IR
```

这不是已有 canonical 的复述，而是把 xn/z 的语义差异落实为 Semantic IR 的 `changed_variable + object_layer + relation_shape` 三字段分流规则，因此满足本轮成功门。

## 10. 下一轮最高翻译风险

优先：**z vs zn**。

原因：自然语言里的“认可我是谁 / 我坚持我是谁 / 身份成立 / 意义成立”极易把 `z` 的外部或内化认可位置，与 `zn` 的对象自身成立资格/不可轻易让渡的内部意义混成同一层。下一轮应优先测试：

- self-recognition 是否仍是 z，还是会误吞 zn；
- external recognition absent 时，zn 是否仍可独立成立；
- 同一身份词在“被承认”与“自身不可让渡”两个 object_layer 上如何拆 IR。
