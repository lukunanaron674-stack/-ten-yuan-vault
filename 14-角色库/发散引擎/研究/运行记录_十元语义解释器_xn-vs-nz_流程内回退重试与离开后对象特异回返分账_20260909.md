# 十元语义解释器｜xn vs nz｜流程内回退重试与离开后对象特异回返分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜为什么本轮值得提交

仓库已经分别锁定：

- `xn`：主体主动组织顺序、时间、规则、记录与节点，使任务形成可持续运行结构；
- `nz`：某段对象特异关系在真实分离后，仍保存可信、可验证的回返、修复或重新接近位置。

但自然语言里“退回、恢复、重新进入、回到原来、再走一次”高度重叠，解释器容易把两种完全不同的 `reentry_right` 混成一个字段：

```text
流程内 retry / rollback / reopen
!=
离开关系后的 object-specific reentry
```

本轮新增的不是“xn 是流程、nz 是回来”这种已有口号，而是 **reentry_right 的语义类型约束**。

新增候选规则：

```text
PROCESS-RETRY-vs-OBJECT-RETURN-v0.1
REENTRY-RIGHT-TYPE_AUDIT_REQUIRED
EXIT-BOUNDARY_AUDIT_REQUIRED
SAME-OBJECT-IDENTITY_AUDIT_REQUIRED
```

核心约束：

```text
workflow retry != nz reentry
process node return != relationship return
case reopen != former participant return
same label "恢复" != same object_layer
```

## 1｜自然语言 → IR 结构还原规则

遇到“退回 / 恢复 / 重开 / 重新进入 / 回来 / 返回原位”时，禁止直接写 `reentry_right: true`。必须先回答以下问题：

1. **actor**：谁在运行流程，谁在离开/返回？二者可能不是同一主体。
2. **object**：被退回的是任务/工单/审批状态，还是一个对象特异关系、成员席位、原项目位置？
3. **object_layer**：这是 `process_state_topology_layer` 还是 `object_specific_relation_reentry_layer`？
4. **current_window**：所谓“回去”是否发生在同一个未结束流程窗口内，还是已经发生真实退出/分离后进入新窗口？
5. **changed_variable**：变化的是流程状态位置，还是原对象关系的可回返资格？
6. **relation_source**：回退由系统规则/流程节点触发，还是由原关系双方、 standing rule、对象特异承诺或修复接口维持？
7. **relation_shape**：应还原为 `node_A -> node_B -> retry_to_node_A`，还是 `relationship -> exit -> preserved/rebuilt return path -> same relationship`？
8. **decision_right**：流程节点是否只是按规则路由，还是每次都由第三方重新决定是否接纳原对象？
9. **path_set**：成员是 process nodes，还是离开后返回同一对象特异位置的现实接口？禁止混装。
10. **reentry_right**：必须写出类型，而不是布尔值；至少区分：
   - `workflow_retry_to_named_node`
   - `workflow_reopen_after_failure`
   - `standing_object_specific_return_right`
   - `relationship_repair_path`
   - `per_instance_discretionary_return`
   - `null/unknown`
11. **future_endpoint**：流程是否只是完成任务，或关系是否保留长期重新接近位置；没有证据保持 null。
12. **reality_anchor**：指出一次现实 retry/reopen，或一次真实离开后成功返回/修复；没有现实拨动不得靠“可以回来”填满 IR。

## 2｜Positive decision gate

### 2.1 xn candidate-positive

满足以下门后才允许判 `xn`：

```text
XN-G1 tested object 是运行结构/任务状态，而非对象特异关系本身；
XN-G2 current_window 内至少有两个明确 process state / node；
XN-G3 path_set 成员为顺序、规则、记录、handoff、queue、retry 等流程元素；
XN-G4 retry/reopen 改变的是任务在流程中的 state position；
XN-G5 流程由主体设计、维护或现实调用，并具有重复运行证据；
XN-G6 removal 某关键 retry/routing rule 后，流程恢复能力出现同层缺口；
XN-G7 即使任务“回到原节点”，只要没有真实退出对象特异关系，不得因此补 nz。
```

### 2.2 nz candidate-positive

满足以下门后才允许判 `nz`：

```text
NZ-G1 存在真实、对象特异的先前关系/成员位置/共同位置；
NZ-G2 发生真实退出、分离、冲突或关系中断，不只是流程状态后退；
NZ-G3 返回目标是同一对象特异关系或其可识别修复位置，不是同类新任务/新节点；
NZ-G4 reentry_right 是可信、现实可执行的回返/修复接口；
NZ-G5 每次完全由陌生第三方自由裁量是否重新接纳时，不得把一次成功写成 stable nz；
NZ-G6 reality_anchor 能证明分离后回返、修复或重新接近至少现实成立一次，或 standing right 具有可执行证据；
NZ-G7 流程表单、核验节点可以作为执行接口，但它们本身不自动生成 xn，也不自动生成 nz。
```

## 3｜标准输入与完整 IR

输入：

> 研究院的项目审批系统规定：申请人在“风险复核”节点未通过时，工单自动退回“材料补充”节点；补齐后会重新进入风险复核，这套回退规则每天重复运行。另一边，研究员陈岚曾主动退出自己的长期课题组；课题组章程规定原成员退出后 60 天内仍保留恢复原项目席位的资格。陈岚离开三周后提交恢复，秘书只核验身份和期限，无权重新决定是否接纳，她最终恢复的是原课题组原席位。

必须 `SPLIT_IR`。

### IR-A｜xn

```yaml
actor: 研究院审批系统设计与运营方
object: 项目申请从风险复核失败后回到材料补充并再次进入复核的运行结构
object_layer: process_state_topology_layer
current_window: 材料补充 -> 风险复核 -> 失败 -> 自动退回材料补充 -> 补齐 -> 再次风险复核；每日重复
changed_variable: workflow_state_transition_and_retry_structure
relation_source: actor_generated_and_maintained_workflow
relation_shape: named_process_node_failure_to_rule_based_retry_to_named_prior_node
 decision_right: workflow_design_and_rule_routing
path_set:
  - material_supplement_node
  - risk_review_node
  - failure_retry_edge_to_material_supplement
  - resubmission_edge_to_risk_review
reentry_right: workflow_retry_to_named_node
future_endpoint: application_passes_review_or_remains_in_retry_cycle
reality_anchor: 风险复核失败的工单会自动回到材料补充，补齐后重新进入复核；该规则每天真实运行
```

判定：**xn PASS；nz 不因“退回/重新进入”自动成立。**

> 注：上面 YAML 中 `decision_right` 必须与其他字段同级；正式解释器实现时应按固定 schema 解析，不允许依赖展示缩进猜测语义。

### IR-B｜nz

```yaml
actor: 陈岚与原课题组之间的对象特异成员关系
object: 陈岚退出后可恢复的原课题组原项目席位
object_layer: object_specific_relation_reentry_layer
current_window: 原成员在组 -> 主动退出 -> 三周分离 -> 60天 standing return window 仍有效 -> 本人提交恢复 -> 核验 -> 恢复原席位
changed_variable: object_specific_reentry_recoverability
relation_source: standing_relation_rule
relation_shape: prior_specific_relationship_to_real_exit_to_preserved_return_path_to_same_relationship
 decision_right: former_member_has_standing_return_right_with_nondiscretionary_verification
path_set:
  - voluntary_exit_from_original_group
  - original_seat_preserved_for_60_days
  - former_member_submits_restore_request
  - secretary_verifies_identity_and_deadline_only
  - original_project_seat_restored
reentry_right: standing_object_specific_return_right_within_60_days
future_endpoint: reentry_window_expires_after_60_days
reality_anchor: 陈岚真实离开三周后无需重新竞聘或求人特批，秘书无权自由否决，本人恢复了原课题组原席位
```

判定：**nz PASS；不得仅因存在表单、秘书、核验步骤就补 xn。**

## 4｜nearest-neighbor 最小差异

### 4.1 xn vs nz｜同一个“重新进入”

```text
申请工单：失败后回到材料节点，再进入复核
→ process state retry
→ xn ↑

原成员：退出三周后恢复原课题组原席位
→ object-specific relationship reentry
→ nz ↑
```

最小变量差异是：

```text
object identity:
case/state
vs
former participant + same specific relationship
```

### 4.2 xn vs xz｜回退节点 vs 现实退路

```text
流程失败后可以退回上一步
→ workflow retry / xn

现实未来路线从3条变1条
→ option-set contraction / xz
```

流程的“退路”不是命运选项集合。

### 4.3 nz vs nx｜standing return vs 外部逐次通道

```text
原成员本人满足条件即可恢复，办事员只能核验
→ nz

每次必须重新求人、找领导自由特批才能回去
→ nx candidate；stable nz 不足
```

## 5｜false-positive guards

1. **关键词护栏**：“退回、重开、恢复、重新进入、回到原来”只触发字段审计，不触发 xn/nz 标签。
2. **流程伪 nz**：工单回到上一步，不等于某段对象特异关系保存回返位置。
3. **关系伪 xn**：某人恢复原成员资格，不等于主体主动搭建了多节点持续运行机制。
4. **表单诱导**：存在申请表、秘书、审批页面，不自动 xn；先看它们是否形成被测运行结构。
5. **一次性回归诱导**：陌生高层临时破例让人回来一次，不自动 stable nz。
6. **同类新对象诱导**：离开 A 项目后进入 B 项目的同名岗位，不是 A 的 nz 回返。
7. **状态未退出护栏**：任务一直留在同一个 workflow，只是状态改变，不得写成“真实分离后回返”。
8. **历史规则护栏**：去年有 retry 或 return right，今年已取消，不得跨 current_window 继承。
9. **对端缺席护栏**：xn FAIL 不推出 nz；nz FAIL 不推出 xn。
10. **情绪护栏**：“我永远欢迎你回来”无现实接口时不产 nz；“系统很严谨”不产 xn。
11. **对象层护栏**：恢复账号登录 ≠ 恢复原成员关系；要看 tested object_layer。
12. **执行接口护栏**：nz 的 standing right 可以经一个简单核验节点执行，这个节点不等于另有 xn candidate-positive。

## 6｜removal / reverse / same-layer / current-window

### Removal A｜删 workflow retry

把“风险失败自动退回材料补充”改成“失败即终止”，而原成员 60 天回返权保持。

预期：

```text
xn retry evidence ↓
nz 保持
```

### Removal B｜删 standing return right

保留完整审批 retry workflow，但把“原成员60天可恢复”改成“退出即永久终止原席位”。

预期：

```text
xn 保持
nz ↓
```

### Reverse A｜流程方向反转

把 `复核失败 -> 材料补充` 改成 `材料补充 -> 复核` 的普通前进边，不会自动产生 nz；只是 xn topology 改变。

### Reverse B｜关系回返反转

把“退出后仍可恢复原席位”改成“退出后只能重新申请其他新课题组”，即使新申请流程有五个节点，也必须得到：

```text
原关系 nz ↓
新申请流程 xn 可另查
```

### Same-layer

严格禁止：

```text
workflow node reentry
=
object-specific relationship reentry
```

即使自然语言都写“回到原来”，也必须拆成：

```text
process_state_topology_layer
!=
object_specific_relation_reentry_layer
```

### Current-window

- 历史流程曾允许 retry，但当前版本已失败即终止：旧 xn retry 不继承。
- 历史成员曾有 return right，但 60 天已过期：当前 nz 必须下降。
- 当前流程仍在跑，不代表原成员回返权仍有效；两个时间窗独立。

## 7｜adversarial tests

### T1｜关键词诱导

输入：“系统允许退回、恢复、重新进入。”除此无节点、对象或现实事实。

预期：`xn/nz UNKNOWN`。关键词只触发 `REENTRY-RIGHT-TYPE_AUDIT_REQUIRED`。

### T2｜题材/职业/情绪诱导

输入：“温柔的老校长总说母校永远欢迎你回来，学校流程也很完善。”但没有说明回返资格、具体节点或现实执行。

预期：两端均不得 positive。温情和“流程完善”都只是人类惯用的烟雾弹。

### T3｜对象层错位

输入：“员工的报销单审核失败后会退回补材料；该员工离职后不能恢复原职位。”

预期：报销流程可查 xn；原职位 nz FAIL。不得把“退回”跨层补给成员关系。

### T4｜时间窗错位

输入：“去年离职员工 30 天内可以恢复职位，今年规则已取消；但今年报销系统仍支持失败退回重提。”

预期：当前 nz FAIL；xn 可 PASS。历史 return right 不继承。

### T5｜同关系词异对象层

输入A：“申请被退回原节点。”
输入B：“成员退出后回到原课题组。”

A 的 `reentry_right=workflow_retry_to_named_node`；B 的 `reentry_right=standing_object_specific_return_right`。同一个“回”字不能共用字段语义。

### T6｜对端不存在不等于本端成立

输入：“流程失败后直接结束，成员退出后也永久失去资格。”

预期：xn retry 与 nz 均 FAIL；一端缺席不推出另一端成立。

### T7｜多节点伪 nz

输入：“离职员工想回来必须重新走简历、面试、背调、审批五个节点，最终进入一个新岗位；旧岗位没有保留。”

预期：新招聘流程 xn candidate；旧岗位 nz FAIL。

### T8｜简单核验伪 xn

输入：“原成员有 60 天恢复原席位的 standing right，只需前台核验身份证，不存在排队、复核或多节点状态流。”

预期：nz PASS；不能因有一个核验动作强填 xn。

### T9｜workflow retry 强但关系已终止

输入：“案件可无限次退回补件再审，但代理合同在客户解约后永久结束，不存在恢复原合同路径。”

预期：案件流程 xn 可强；代理关系 nz FAIL。

### T10｜关系修复强但无流程

输入：“两位合伙人分开半年后仍按原约定各自保留重新加入共同项目的资格；回归只需双方按既有约定确认，没有固定 SOP。”

预期：nz 可 PASS；xn 不自动成立。

### T11｜同一事件双层并存

输入：“研究员退出课题组三周后恢复原席位；恢复后，其待审项目工单从冻结状态按制度重新进入风险复核队列。”

预期：必须 SPLIT_IR：成员关系层 nz + 工单运行层 xn。禁止一条 IR 双贴。

### T12｜最小 mutation

冻结角色、机构和题材，只改以下事实：

A：
```text
任务失败 -> 自动回上一步 -> 重试
成员退出 -> 永久失去原席位
```
预期：`xn ↑ / nz ↓`。

B：
```text
任务失败 -> 直接终止
成员退出 -> 60天内本人可恢复原席位，办事员仅核验
```
预期：`xn retry ↓ / nz ↑`。

mutation 后必须重新抽取完整 IR；不得继承 A 的 `reentry_right` 类型到 B。

## 8｜状态迁移规则

### PROCESS-RETRY-STATE

```text
single_pass_no_retry
→ explicit_failure_state
→ rule_based_return_to_named_node
→ repeated_retry_with_state_persistence

= xn retry evidence ↑
```

### OBJECT-SPECIFIC-RETURN-STATE

```text
specific_relationship_exists
→ real_exit_or_separation
→ return qualification absent
→ standing/rebuilt same-object return path exists
→ return/repair exercised

= nz evidence ↑
```

二者独立：

```text
xn_retry ↑ != nz ↑
nz ↑ != xn_retry ↑
```

只有在同一叙事事件里同时出现两层结构，才允许 `SPLIT_IR` 共存，不允许互相代替。

## 9｜成功门核验

本轮新增而非重复的资产：

1. `reentry_right` 从布尔/泛化描述提升为 **typed semantic field**；
2. 新增 `workflow_retry_to_named_node` vs `standing_object_specific_return_right` 的硬分账；
3. 新增 `EXIT-BOUNDARY_AUDIT_REQUIRED`：未发生真实关系退出，不得从流程回退补 nz；
4. 新增 `SAME-OBJECT-IDENTITY_AUDIT_REQUIRED`：进入同类新岗位/新项目不等于原对象回返；
5. 新增最小 mutation，要求仅改变 reentry type 时得到 `xn retry` 与 `nz` 的相反响应；
6. 新增状态迁移双轨，明确 process retry 与 object-specific return 独立变化。

因此本轮通过成功门，可提交 research-only 记录。

## 10｜下一轮翻译风险

本轮使用 `xn / nz`，下一轮不得继续使用两者。

当前高风险候选建议检查：

```text
z ↔ x并z
```

危险句型：

```text
“这是官方唯一入口，所以它说了算。”
“所有人都从这个中心进入，因此它是最高决定者。”
```

待拆变量：

```text
public addressability / stable external shell
!=
final adjudication center / binding validity
```

重点审计 `actor`、`object_layer`、`decision_right`、`relation_shape`、`caller_population` 的隐含信息是否被错误塞进固定 IR 字段。
