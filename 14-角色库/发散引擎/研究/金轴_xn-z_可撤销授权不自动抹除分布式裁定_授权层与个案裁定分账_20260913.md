# 金轴｜可撤销授权不自动抹除分布式裁定：授权层与个案裁定层分账

## 0｜本轮只解决一个问题

固定多个节点对某一具体个案拥有真实 binding decision right，只改变一个上位中心是否拥有“撤销这些节点授权”的元权力。

问题：

> 多节点裁定权来自单一中心授权，而且授权未来可撤销，这是否意味着当前个案其实一直是 z，而不是 xn？

本轮结论：

```text
revocable delegation != automatically current-case z
appointment_source != binding-effect locus
```

必须至少分开：

```text
authority-allocation layer
current-case adjudication layer
future-case jurisdiction layer
```

如果单中心只能按公开边界对“未来案件”撤销授权，不能改写当前已进入裁定窗口的 binding rights，也不能覆盖本案结论，则当前个案仍可判 xn。

如果单中心可以针对当前个案随时撤销节点权限、收回案件并由自己裁定，则：

```text
jurisdiction_allocation = z-like meta-center
current-case adjudication = contingent / unstable xn
whole_case = SPLIT_IR_BY_RIGHT_LAYER
```

如果单中心在分布式结论已经形成后仍能通过“撤销授权”直接使该结论失效并替换结果，则它已不再只是 delegation revocation，而是：

```text
final_adjudication / aggregate_override
-> z
```

新增 guard：

```text
DELEGATION-SOURCE-NOT-DECISION-LOCUS-GATE-v0.1
PROSPECTIVE-REVOCATION-NOT-CURRENT-OVERRIDE-GATE-v0.1
CASE-SPECIFIC-REVOCATION-SPLIT-IR-GATE-v0.1
REVOCATION-AS-POSTHOC-OVERRIDE-GATE-v0.1
```

## 4｜最小判别式

```text
single center originally grants authority
+ revocation only affects future cases
+ current case rights freeze once opened
+ no posthoc invalidation / override
-> current case may remain xn
```

```text
single center can revoke current-case jurisdiction at will
+ can take case for itself
+ delegated nodes cannot independently restore case authority
-> authority layer z-like
-> current case requires SPLIT_IR_BY_RIGHT_LAYER
```

```text
single center can invalidate already-binding distributed result
+ substitute own result
-> final adjudication locus = center
-> z
```

最短版：

> 谁授予裁定权，不等于谁正在裁定；但谁能随时把“本案裁定权”收回来，已经控制了更高一层的裁定入口。

## 5｜removal test

### removal A｜拿掉当前个案撤权

保留：

```text
P appoints A/B/C
P may remove them from future cases
```

删除：

```text
P may interrupt K
```

结果：

```text
case_K -> xn remains
```

说明“权力来源集中”不是当前个案 z 的充分证据。

### removal B｜保留当前撤权，但拿掉 takeover

P可以因资格失效暂停节点，但必须由预设替补节点接手，P自己不能裁定，也不能指定结果：

```text
z evidence weakens sharply
rule/node xn may remain
```

说明：

```text
revocation power alone
!= substantive adjudication power
```

### removal C｜保留 takeover，但拿掉 posthoc invalidation

P只能在 binding result 形成前公开收回案件；一旦结果形成不可改写：

```text
current window may SPLIT
but post-result finality remains distributed for completed K
```

## 8｜positive / negative controls

### 正控 xn｜工程变更委员会

CTO任命三人变更委员会，也可以下月更换委员；但一旦某次变更进入 review window，该三人对该变更的 binding vote 被规则冻结，CTO不能中途撤权、收案或改结果。

```text
xn(case) PASS
```

### 正控 split｜制度许可审查

部长平时让独立小组裁定许可证，但可在任一未结案件中单方撤销小组对该案权限并亲自接管；被撤销小组无独立恢复路径。

```text
authority layer = z-like
case layer before takeover = xn candidate
whole = SPLIT_IR
```

### 正控 z｜创作验收

制片委员会已经按规则形成 binding 版本结论，但总负责人可以以“撤销本轮委员会授权”为由让结论失效，并直接指定另一版本。

```text
final adjudication = z
```

### 负控｜规则性资格撤销

任何评审一旦出现利益冲突，自动退出当前案件并由下一顺位替补；没有任何单一中心可以指定替补结果或自己收案。

```text
rule-bound replacement != z
```

### 负控｜未来组织调整

负责人宣布下季度取消该委员会，但本季度已经进入窗口的案件仍由原委员会作 binding decision。

```text
future structural centralization
!= current-case z
```

## 9｜失败类型

新增：

```text
FAILURE_DELEGATION_SOURCE_AS_CURRENT_Z
因为裁定权由单中心授予，就把当前分布式裁定误判为z。

FAILURE_FUTURE_REVOCATION_BACKFILLS_CURRENT_CASE
未来可撤权，被倒灌成本案当前裁定权仍在中心。

FAILURE_CURRENT_TAKEBACK_IGNORED
节点表面多人裁定，但中心可以任意收回本案，解释器仍判pure xn。

FAILURE_REVOCATION_AS_POSTHOC_OVERRIDE_HIDDEN
中心用“撤销授权”的名义作废已经binding的多人结果，解释器没有识别为final override。

FAILURE_APPOINTMENT_RIGHT_AS_ADJUDICATION_RIGHT
任命权与个案裁定权混账。
```

## 10｜guards

```text
GUARD_METAL_DELEGATION_01
appointment/grant source is not sufficient evidence for current adjudication locus.

GUARD_METAL_DELEGATION_02
revocation must be scoped by current_window and case identity.

GUARD_METAL_DELEGATION_03
prospective revocation cannot backfill current-case z.

GUARD_METAL_DELEGATION_04
case-specific takeback requires authority-layer / case-layer split.

GUARD_METAL_DELEGATION_05
posthoc revocation that invalidates a binding distributed result is functionally final override.
```

## 11｜与已有金轴研究的关系

本卡不替代：

- 单一否决权 vs 完整最终裁定；
- reopen/reset right vs substantive adjudication；
- candidate-set control；
- evidence-admission / fact-space collapse；
- aggregate override / final adjudication。

它补的是此前未独立记账的一层：

```text
who decides
vs

```

只有第二层能够穿透当前 case window 时，才会对本案金轴结构产生直接影响。
