# 十元语义解释器｜x vs x并z：受控壳资产与被代表对象公共接口分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究。本文件不得修改或覆盖 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜为什么本轮选 x vs x并z

上一轮处理 `zx vs zn`；本轮不复用其中任何十元。

现有 canonical 已给出最近邻总原则：

- `x`：对象进入主体的归属、调用、调配、处分或排除边界；
- `x并z`：内部对象向外映射，形成稳定公共识别、调用、归因、代表、进入或保护接口。

但自然语言存在一个解释器级债务：**同一个账号、官网、品牌、职位、门店、钥匙系统或门户，既可能是“被某人控制的壳资产”，又可能是“代表另一个内部对象的公共壳”**。

危险句型：

- “这个官方账号归我管。”
- “官网在我手里，所有人都通过它找到公司。”
- “品牌是公司的，但账号密码只有运营总监能改。”
- “我控制入口，所以我控制入口后面的组织。”
- “公众能通过这个入口进入，所以公众拥有里面的东西。”

若解释器不拆 `control target` 与 `represented object`，会产生两类错贴：

```text
控制公共壳 artifact
→ 错推为控制壳所代表的内部对象

公共壳可被第三方调用
→ 错推为第三方拥有该对象的 x
```

本轮新增：

```text
CONTROLLED-SHELL-vs-REPRESENTED-OBJECT-v0.1

CONTROL-TARGET_AUDIT_REQUIRED
REPRESENTED-OBJECT_AUDIT_REQUIRED
ARTIFACT-ROLE-SPLIT_REQUIRED
CALLER-RIGHT-vs-INTERFACE-ACCESS_AUDIT_REQUIRED
```

核心纪律：

```text
control(shell_artifact) != control(represented_object)
public_call(shell) != disposition_right(caller, represented_object)
shared artifact != shared object_layer
```

## 2｜自然语言 → IR 的结构还原规则

遇到“官网/账号/品牌/入口归我管，并代表公司”一类句子，必须按以下顺序处理。

### Step A｜识别物理/数字 artifact 与被代表对象

分别回答：

1. **shell artifact 是什么？** 例如账号、域名、官网、品牌页、门店前台、认证身份。
2. **represented object 是什么？** 例如公司、项目、服务、作品、组织身份、内部资源。
3. 两者是否只是同名，还是确实为两个 object_layer？

禁止把“官方账号”直接写成一个模糊 `object: 公司账号/公司本身`。

### Step B｜审计 control target

若句子含“归我管 / 我能改 / 我能封 / 我能转移 / 我能排除别人”，必须明确这些动作到底作用于：

```text
账号密码？
域名 DNS？
发帖权限？
账号所有权？
公司预算？
公司资产？
内部政策？
```

只有作用于 tested object 的实际占有、调用、调配、处分、否决或排除权，才进入 `x` gate。

### Step C｜审计 represented object 与 caller population

若句子含“官方 / 对外 / 所有人通过它找到 / 公众通过它进入”，必须明确：

```text
external caller 是谁？
stable shell 是什么？
shell 映射到哪个 internal object？
第三方通过壳获得的是识别/调用/归因/进入，还是处分权？
```

`x并z` 的公共调用只证明 interface relation，不证明 caller 对内部对象有 `x`。

### Step D｜同一 artifact 双角色时强制 SPLIT_IR

若同一个官网账号同时满足：

- 运营总监能改变账号本身的登录、发布、管理员资格；
- 公众通过账号稳定识别并调用组织；

则必须：

```text
IR-A：tested object = shell artifact itself → 审计 x
IR-B：tested object = represented internal object via shell → 审计 x并z
```

禁止一个 IR 同时写：

```text
object: 官方账号和公司
changed_variable: control_and_public_mapping
```

这属于对象层污染。

## 3｜标准输入

> 市立博物馆把认证官网、官方公众号和捐赠入口交给数字运营主管林澈管理。林澈可以重置账号密码、撤销其他编辑权限、切换官网域名解析，也可以把公众号管理员转给新的运营人员；但他不能出售馆藏、改变捐赠政策、决定展览预算，也不能因为掌握官网就取消博物馆法人资格。与此同时，媒体、游客和第一次接触博物馆的捐赠者都长期通过认证官网和公众号确认“这是该博物馆的正式入口”，查看展览信息并提交捐赠申请。公众只能提交和查询，不能改后台账号、处分馆藏或决定预算。

必须 `SPLIT_IR`。

## 4｜完整 IR-A：x｜受控壳资产本身

```yaml
actor: 林澈
object: 博物馆认证官网域名、官方公众号管理资格与后台账号
object_layer: shell_artifact_control_layer
current_window: 林澈取得后台管理权限 -> 可持续重置密码/撤编辑/切DNS/转管理员 -> 当前权限仍有效
changed_variable: current_disposition_scope_over_shell_artifact
relation_source: institutional_delegated_admin_authority
relation_shape: shell_artifact_inside_actor_operational_control_boundary
decision_right: actor_direct_on_shell_access_admin_assignment_and_domain_routing
path_set:
  - reset_account_password
  - revoke_editor_permission
  - change_domain_dns
  - transfer_public_account_admin_role
reentry_right: revoked_editor_requires_new_authorization
future_endpoint: null
reality_anchor: 林澈可不经普通编辑逐次同意，直接改变账号访问、编辑资格、域名路由和管理员归属；但这些权利不延伸到馆藏、预算、捐赠政策或法人资格
```

判定：

```text
x candidate PASS
```

这里 `x` 的对象是**壳资产与其管理权限**，不是博物馆整体。

## 5｜完整 IR-B：x并z｜被代表对象的公共接口

```yaml
actor: 博物馆认证官网与官方公众号这一稳定公共壳
object: 市立博物馆作为可被公众识别与调用的正式组织/服务对象
object_layer: public_representation_and_addressability_layer
current_window: 认证入口长期存在 -> 媒体/游客/首次捐赠者反复访问 -> 识别/查询/提交持续成立
changed_variable: public_mapping_stability
relation_source: certified_public_shell
relation_shape: external_caller_to_stable_shell_to_represented_museum
 decision_right: interface_only_nonfinal
path_set:
  - media_identifies_official_museum_source
  - visitor_reads_exhibition_information
  - first_time_donor_submits_donation_application
  - public_queries_application_status
reentry_right: null
future_endpoint: null
reality_anchor: 不需要认识内部员工的第三方可以长期通过认证官网和公众号稳定确认博物馆身份、获取正式信息并进入捐赠申请通道
```

判定：

```text
x并z candidate PASS
```

这里 `x并z` 的核心不是“林澈掌握账号”，而是**第三方通过稳定壳映射到博物馆**。

> 注：上面 `decision_right` 前的空格仅为展示缩进，语义字段仍固定为 `decision_right`。

## 6｜Positive decision gate

### 6.1 x positive gate

只有同时满足以下条件，才锁 `x`：

1. `actor` 明确；
2. `object` 是被掌握的具体对象/资源/权限/关系，而不是模糊“背后的整体”；
3. `decision_right` 属于占有、使用、调配、调用、处分、否决或排除的实际权限；
4. 权限作用于 **same tested object_layer**；
5. `path_set` 至少有一条 actor 可直接执行的 control/disposition path；
6. `reality_anchor` 能证明该动作真实改变对象状态；
7. removal 掉该权限后，actor 对该 tested object 的掌握出现现实缺口。

### 6.2 x并z positive gate

只有同时满足以下条件，才锁 `x并z`：

1. `shell artifact` 与 `represented object` 可分别指认；
2. 至少存在一个不依赖私人关系的第三方 caller；
3. 存在 `external caller -> stable shell -> represented object` 的稳定路径；
4. 壳跨时间/场景持续，不是一次令牌或一次曝光；
5. 壳真实改变识别、调用、归因、代表、进入或保护方式；
6. `reality_anchor` 证明第三方实际依赖该壳；
7. caller 是否拥有内部对象处分权必须另审计，不能由 interface access 补出。

## 7｜Nearest-neighbor 最小差异

### 7.1 x vs x并z｜本轮主差异

```text
x：
谁能直接改变“这个对象/壳资产本身”的使用、访问、调配、归属或处分状态？

x并z：
第三方通过“这个壳”稳定找到、识别、调用、归因或进入的是哪个内部对象？
```

最小 mutation：

```text
管理员能改账号密码
但公众从不把它当正式入口
→ shell artifact x 可 PASS；x并z FAIL/弱

管理员无权改账号任何设置
但账号作为独立制度壳长期被公众依赖
→ tested admin x FAIL；represented object 的 x并z 可 PASS
```

### 7.2 x vs xn

```text
x：谁拥有对象/壳的当前控制处分边界？
xn：内部节点、记录、顺序和流程怎样被组织成持续运行结构？
```

管理员能封账号，不等于他设计了内容审核工作流。

### 7.3 x并z vs n

```text
x并z：内部对象如何向外形成可识别/调用接口？
n：外部对象进入内部后，其现实负荷如何被持续承载？
```

公众能提交申请，不证明后台真正有人持续接住申请。

## 8｜False-positive guards

1. “官方账号归我管”只触发 `CONTROL-TARGET_AUDIT`，不能直接判 x。
2. “这是官方入口”只触发 `REPRESENTED-OBJECT_AUDIT`，不能直接判 x并z。
3. 拥有官网密码 ≠ 拥有官网所代表公司的预算、馆藏、政策或法人处分权。
4. 公众能通过官网提交请求 ≠ 公众拥有官网背后内部对象的 x。
5. 编辑内容权 ≠ 账号所有权/管理员处分权；必须看 `decision_right`。
6. 品牌归公司所有 ≠ 品牌一定形成稳定公共接口；若第三方不靠它识别/调用，x并z 不成立。
7. 稳定公共壳存在 ≠ 壳维护者拥有 represented object 的最终决定权。
8. 壳被撤销导致 x并z 下降 ≠ represented object 本身一定失去 x 或被他人获得 x。
9. 一个 artifact 同时满足两层证据时必须 SPLIT_IR，禁止用同一个 `changed_variable` 双贴。
10. `x FAIL` 不推出 `x并z PASS`；`x并z FAIL` 也不推出 `x PASS`。
11. 账号/品牌/官网/门店/制服等题材名词均不得直接产十元。
12. “控制入口”只有在 object 明确为入口 artifact 时才能给该 artifact 加 x；不得越层推出“控制入口后的一切”。

## 9｜Adversarial tests

### T1｜关键词诱导

输入：

> “这个官方账号就是我的，我说了算。”但当事人只能提交文案，密码、管理员、删除与转移均由总部控制。

预期：

```text
当事人 tested x = FAIL/弱
若公众长期通过该账号识别总部，组织层 x并z 可独立 PASS
```

### T2｜题材 / 职业 / 情绪诱导

输入：

> 冷酷的品牌总监穿黑西装，每天强调“所有门面都在我掌心”，实际上官网由外包托管，他无管理员权限；品牌也从未形成稳定公共入口。

预期：

```text
x FAIL/UNKNOWN
x并z FAIL/UNKNOWN
```

职业、服装、气质和“掌心”词面不得倒推。

### T3｜对象层错位

输入：

> IT 主管能冻结官网后台账号，但不能改医院诊疗政策；患者通过官网长期识别医院并预约。

预期：

```text
后台账号层：IT 主管 x candidate PASS
医院诊疗政策层：不得由账号控制补 x
医院公共接口层：x并z candidate PASS
```

### T4｜时间窗错位

输入：

> 去年甲掌握域名与管理员资格；今年权限已全部移交乙，但官网仍保持同一认证入口。

当前窗口预期：

```text
甲 x FAIL
乙 x 可查
组织 x并z 可保持
```

历史 control 不得跨 current window 续贴。

### T5｜同关系词异对象层

输入：

> “管理入口”一处指管理员可重置密码，另一处指公众通过入口提交申请。

预期：

```text
reset/admin relation → shell artifact x
public submit/address relation → represented object x并z
必须 SPLIT_IR
```

### T6｜对端不存在不等于本端成立

输入：

> 旧官网已停用，管理员权限也被撤销，公众现在靠临时电话联系，且电话并非稳定认证入口。

预期：

```text
x FAIL/UNKNOWN
x并z FAIL/UNKNOWN
```

一端不存在不能用来证明另一端成立。

### T7｜稳定公共壳但维护者无 x

输入：

> 法院官网由中央系统自动托管，本地书记员无法改域名、管理员或页面结构，但公众十年都通过该官网确认案件入口。

预期：

```text
本地书记员 x FAIL
法院公共接口 x并z PASS
```

### T8｜壳资产 x 强但没有 x并z

输入：

> 收藏家完全掌握一个私人 NAS 的管理员、删除和转移权，但外界不知道它存在，也没有任何第三方通过它识别收藏家。

预期：

```text
NAS asset x PASS
x并z FAIL
```

### T9｜公众 access 伪装成公众 x

输入：

> 市民可以通过市政门户提交维修申请，但不能改派工队、冻结预算或删除其他人的工单。

预期：

```text
门户对市政服务的 x并z 可查
市民对后台工单/预算的 x FAIL
```

### T10｜编辑权伪装成完整 disposition

输入：

> 实习生可以发公众号文章，但不能改密码、删账号、撤其他编辑或转移管理员。

预期：

```text
只证明 bounded use path
若 tested x 定义为完整账号处分，FAIL/弱
不能因为“能发帖”越权补满 x
```

### T11｜同一 artifact 双 PASS 但对象不同

输入：

> 创始人拥有官网域名、管理员与转移权；官网又是客户长期唯一验证公司身份并进入售后服务的认证入口。

预期：

```text
IR-A website asset control → x PASS
IR-B company public mapping via website → x并z PASS
```

必须两份 IR，禁止 `x+x并z` 塞进一个 object_layer。

### T12｜最小 mutation：冻结 artifact，只切 role topology

冻结：

```text
artifact = 同一个认证账号
current_window = 当前
```

Mutation A：

```text
actor 可重置密码/撤管理员；第三方从不依赖该账号
→ x ↑ / x并z ↓
```

Mutation B：

```text
actor 无任何后台控制；第三方长期通过该账号识别并调用组织
→ tested actor x ↓ / organization x并z ↑
```

这是本轮最关键的解释器测试：**同一名词、同一 artifact 不允许锁死同一十元；决定标签的是关系拓扑和 tested object_layer。**

## 10｜Removal / reverse / same-layer / current-window

### Removal A｜去掉 shell control

把林澈的重置密码、撤编辑、切 DNS、转管理员全部拿掉，但官网与公众号仍由独立制度稳定运行，公众继续使用。

预期：

```text
林澈对 shell artifact 的 x ↓
博物馆公共 x并z 保持
```

### Removal B｜去掉 public mapping

保留林澈全部后台处分权，但把官网改成只供内部测试、不公开、不认证、第三方不依赖。

预期：

```text
shell artifact x 保持
x并z ↓
```

### Reverse｜控制对象反转

若林澈原本控制“官网账号”，后来仅能控制“官网里的个人头像素材”，不得把个人素材控制继续当作账号层 x。

```text
same actor
same context words
but control target changed
→ object_layer 必须重算
```

### Same-layer check

以下两层不得混写：

```text
shell_artifact_control_layer
public_representation_and_addressability_layer
```

即便现实里是同一个网页文件/账号，也必须按关系角色拆分。

### Current-window check

管理员权限、认证状态、公共依赖都必须按当前窗口独立检查：

```text
去年有管理员权 != 今年 x
去年是认证入口 != 今年 x并z
```

历史状态只能作为 transition evidence，不能直接续贴当前标签。

## 11｜新增状态迁移规则

### 11.1 SHELL-CONTROL-STATE

```text
view_only
→ bounded_content_use
→ admin_access_and_exclusion
→ transfer/disposition_of_shell_artifact

= shell artifact x evidence ↑
```

### 11.2 PUBLIC-MAPPING-STATE

```text
private_or_ambiguous_shell
→ publicly_identifiable_shell
→ repeatable_external_call
→ third_party_relies_on_shell_to_reach_represented_object

= represented object x并z evidence ↑
```

两条状态轨独立：

```text
shell-control ↑ != public-mapping ↑
public-mapping ↑ != shell-control ↑
```

新增跨轨约束：

```text
control transfer of shell
without mapping break
→ x holder may change while x并z remains stable

mapping collapse
without loss of shell ownership
→ x may remain while x并z falls
```

## 12｜成功门审计

本轮不是重复 canonical 的“掌握 vs 公共壳”一句话，而是新增以下解释器级资产：

1. `CONTROL-TARGET_AUDIT_REQUIRED`：控制动作必须绑定到具体 tested object；
2. `REPRESENTED-OBJECT_AUDIT_REQUIRED`：公共壳必须明确它实际映射谁；
3. `ARTIFACT-ROLE-SPLIT_REQUIRED`：同一 artifact 可以在两个不同关系里分别成为 x 对象与 x并z 壳，必须拆 IR；
4. `CALLER-RIGHT-vs-INTERFACE-ACCESS_AUDIT_REQUIRED`：第三方能调用接口不得补成其对内部对象的 x；
5. 新 adversarial negative：控制入口不等于控制入口后的整体；公共可进入不等于 caller 获得内部 disposition；
6. 新状态迁移：shell-control holder 可变化而 public mapping 不变，反之亦然。

成功门：**PASS**。
