# Z发散器运行记录｜OP-005 REMOVE_CONDITION

> research-only。current canonical、十元语义解释器、L1/L2、信息卡、准度卡、正式关系卡与行为 evidence 正本均只读。本 operator 只用于查询坐标变换；输出必须重建 Semantic IR 后重新进入 current 十元语义解释器，不得由 mutation 结果直接继承十元标签。

## 0｜为什么值得保留

OP-003 已解决“有哪些现实路径”，OP-004 已解决“谁能打开/阻断路径”。下一步高信息增益不是继续找更多 route，而是问：

> 某个被叙述为关键的现实条件如果拿掉，同一 changed_variable、同一对象层、同一 current-window role 下，哪些 route / decision / reentry / endpoint 结构仍成立？

`REMOVE_CONDITION` 不是删除一句话，也不是把故事改成另一个题材。它做的是**必要性消融（necessity ablation）**：冻结 tested structure，只移除一个有 reality anchor 的条件绑定，观察哪些 IR 字段发生结构变化。若拿掉条件后所有结构完全不变，则该条件只是背景或装饰；若 route 可调用性、decision topology、reentry qualification 或 future endpoint 发生明确变化，则该条件值得进入后续检索与解释。

本 operator 因此改变“什么值得被检索”：从“这件事有什么条件”变成“哪个条件是结构必要条件，哪个只是叙事共现”。

## 2｜query_template

```text
给定 current Semantic IR：
actor={actor}
object={object}
object_layer={object_layer}
current_window={current_window}
changed_variable={changed_variable}
relation_source={relation_source}
relation_shape={relation_shape}
decision_right={decision_right}
path_set={path_set}
reentry_right={reentry_right}
future_endpoint={future_endpoint}
reality_anchor={reality_anchor}

执行 REMOVE_CONDITION：

A. 先从 reality_anchor 中提取至多 3 个“有事实锚点且绑定到 IR 字段”的条件候选。
B. 每轮只选 1 个条件做 ablation；其余条件冻结。
C. 明确 FROZEN TEST：actor/object/object_layer/changed_variable/current-window role 不变。
D. 构造唯一 counterfactual：仅令该条件 absent，不额外添加新人物、新资源、新权限、新路径。
E. 重新计算：relation_source / relation_shape / decision_right / path_set / reentry_right / future_endpoint。
F. 比较 before / after IR delta：
   - no structural delta => CONDITION_DECORATIVE_OR_REDUNDANT
   - one or more same-layer structural deltas => CONDITION_STRUCTURALLY_RELEVANT
   - 必须改变 object_layer/changed_variable/current-window role 才能成立 => IR_CONFLICT_REQUIRES_REEXTRACTION
G. 不判十元。把 counterfactual IR 与 baseline IR 一起交 current 十元语义解释器重新判断。
```

## 4｜核心 guard

### G1｜remove one condition only
一次只移除一个 reality-anchored condition。多条件同时删除会把最小差异破坏成重写世界。

### G2｜condition absence ≠ opposite state
拿掉“允许回返”的条件，不自动得到 xz；拿掉“阻断路径”的条件，也不自动得到 nz。`state absence ≠ opposite-pole presence`。

### G3｜background co-occurrence ≠ necessary condition
情绪、天气、职业、身份、颜色、作品气质、结局若没有绑定到 IR 字段，只是背景，不得作为 ablation target。

### G4｜removal cannot inject compensation
删除条件后禁止顺手补一个新资源、新管理员、新 bypass 来“保持故事合理”。否则无法知道 delta 来自 removal 还是补偿。

### G5｜same-layer delta required
若拿掉条件只有换到更高/更低 object layer 才产生差异，当前 operator 失败，改用 SHIFT_OBJECT_LAYER。

### G6｜path existence ≠ path callability
移除某条件后 route 可能仍名义存在，但从 callable 变为 blocked；必须重新审计现实可调用性。

### G7｜decision-holder existence ≠ authority active
某人仍在场，不等于其 override/veto 在条件移除后仍有效；conditional authority 必须重新算。

### G8｜generated condition ≠ confirmed condition
AI 猜出的隐藏许可、秘密通道、紧急规则不得进入事实层 ablation。

## 5｜failure modes

```yaml
failure_modes:
  - REJECTED_RESKIN: 只把条件换成同义表达或题材皮肤
  - REJECTED_RETRIEVAL_ONLY: 只是继续找更多有类似条件的案例
  - MULTI_REMOVAL_CONFUSION: 一次删除两个以上条件
  - COMPENSATION_INJECTION: 删除 A 后偷偷补 B
  - CONDITION_NOT_IR_BOUND: 被删条件没有绑定任何 IR 字段
  - WINDOW_ROLE_DRIFT: 为了让 counterfactual 成立改变测试窗口角色
  - OBJECT_LAYER_DRIFT: 条件移除后研究对象层偷换
  - VARIABLE_DRIFT: changed_variable 被改写
  - NOMINAL_CALLABILITY_CONFUSION: 名义路径仍在就当作现实可调用
  - CONDITIONAL_AUTHORITY_FLATTENING: 条件性权限被当成常态权限
  - GENERATED_AS_FACT: AI 补出的门槛被当事实
  - LABEL_INHERITANCE: baseline 十元标签直接继承到 counterfactual
```

## 6｜stop condition

满足任一即停止：

1. 找不到至少一个有现实锚点、且明确绑定到 IR 字段的条件；
2. 候选条件只能来自职业/情绪/题材/修辞；
3. 单条件移除迫使 actor/object/object_layer/changed_variable/current-window role 改变；
4. 已得到一个清晰 before→after structural delta；
5. 连续两个条件 removal 都无任何 IR delta，说明当前问题更适合其他 mutation；
6. 剩余候选全部是 generated-only；
7. 完成一次最小差异后立即重建 IR，不继续无限删除世界设定。

## 7｜when_not_to_use

- 还不知道有哪些 route：先用 ENUMERATE_PATH_SET；
- 不知道谁握决策权：先用 REPLACE_DECISION_HOLDER；
- object_layer 不稳定：先用 SHIFT_OBJECT_LAYER；
- 需要跨 domain 验证同一变量：用 HOLD_CHANGED_VARIABLE_REPLACE_CONTEXT；
- 目标是扩大/缩小观察时间窗：用 EXPAND_OR_SHRINK_CURRENT_WINDOW；
- 用户只是想“找更多相似条件”：这是 retrieval，不使用本 operator；
- 只有一句抽象主题词、没有 reality anchor：不得做 counterfactual necessity claim。

## 8｜跨领域测试

> 以下仅验证 operator 是否打开不同结构查询空间，不累计为 xn 或任何十元 evidence。

### T1｜《红楼梦》鸳鸯拒婚｜移除“上位现实 veto 可被调用”条件

冻结：鸳鸯本人、婚配对象层、同一拒婚 current-window role、`changed_variable=该婚配提案是否能现实强制生效`。

baseline 中若存在上位现实 veto/阻断接口，则将其作为一个已确认条件绑定到 `decision_right/path_set`。counterfactual 只移除该 veto 可调用条件，不增加新的保护者或逃跑路径。

新的检索问题：原拒绝路径是否仍能独立阻断？施压者是否获得 final authority？是否仍存在其他 same-layer route？

结果：PASS。观察坐标从“谁支持鸳鸯”变成“这个保护条件到底是不是结构必要条件”。

### T2｜《西游记》悟空回返｜移除“当前关系端接受/回应可发生”条件

冻结孙悟空、bilateral reentry object layer、同一回返测试窗口与 `changed_variable=原关系的现实回返资格是否可调用`。

只移除“另一端当前可接受/回应”的条件，不把死亡、换师父、观音直接裁定等新结构注入测试。

新的检索问题：direct reentry 是否从 callable 变 nominal-only？中介 route 是否能替代 bilateral acceptance，还是属于另一 object layer？

结果：PASS。它迫使模型区分“还有中介”与“原关系本人仍可现实重入”。

### T3｜工程：高风险设计变更｜移除 emergency declaration

冻结同一 change request、同一 engineering-change layer 与 path topology。baseline 中 incident commander 仅在 `emergency_declared=true` 时有 break-glass override。

counterfactual 只令 emergency condition absent。

新的检索问题：ordinary approval route 是否重新成为唯一 callable path？override holder 是否仍有 authority？veto 是否恢复完整阻断力？

结果：PASS。`decision holder exists` 与 `conditional authority active` 被明确拆开。

### T4｜制度：采购审批｜移除额度资格条件

冻结同一采购对象、同一 approval object layer、同一 requested action，测试一个“经理仅在金额≤cap 时可最终批准”的结构。

counterfactual 将“金额满足 cap”条件移除，其他路径与人物不变。

新的检索问题：经理从 final holder 退化为 recommender/executor 吗？是否必须进入上级 approval path？原 route 是名义存在还是现实 blocked？

结果：PASS。打开 threshold routing / delegation cap / escalation 的结构检索，而不是多找几个采购故事。

### T5｜现实软件发布｜移除 maintenance-window 条件

冻结同一 release candidate、production-deploy object layer、same changed_variable 与 holder topology。baseline route 仅在维护窗口可正常执行。

counterfactual 只令 maintenance-window absent，不自动赋予 break-glass 权限。

新的检索问题：normal deploy path 是 delayed、blocked 还是仍 callable？是否只有另一个已存在且已确认的 emergency route 可用？

结果：PASS。强制区分 path membership、current callability 与 future availability。

## 13｜下一最高价值 mutation

`EXPAND_SHRINK_CURRENT_WINDOW`。

理由：OP-005 已能做同一窗口里的必要性消融，但大量错误来自把“曾经成立/后来成立/最终成立”偷塞进当前判定。下一步应冻结 actor/object/object_layer/changed_variable，只系统扩大或缩小 `current_window`，观察 relation_source、decision_right、path_set、reentry_right、future_endpoint 与 reality_anchor 如何随窗口边界变化。它能直接审计 lifecycle、历史污染与结局倒推，同时与单条件 removal 保持正交。
