# 十元语义解释器｜z vs nx｜最终裁定中心与沿外部方向续接分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖或修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或 behavior evidence 正本。
>
> 本轮按 L1 v1.6 + L2 v1.1 读取 current z：`z = 判断权与结构重心收束到单一最高中心或最终裁定点`。`【z信息量卡v2.2】`与`【nx信息量卡v2.5】`中残留的旧“认可主体”口径只作历史材料，不可覆盖 L1/L2。

## 0｜本轮翻译债务

高风险句型：

```text
听他的。
由他定。
按他说的办。
最后还是得看老板。
我只是照上面的意思做。
```

旧粗糙翻译常把它们全部压成“外部决定”，然后 z / nx 任意贴。问题在于至少有两个不同结构位置：

```text
A. 某个主体/标准对同层竞争判断拥有 binding final validity
→ final adjudication center
→ 查 z

B. tested actor 不占最终方向，只沿这个外部已有方向/权限/关系通道续接
→ external route following
→ 查 nx
```

本轮新增候选规则：

```text
FINAL-ADJUDICATOR-vs-FOLLOWER-OF-EXTERNAL-DIRECTION-v0.1
DECISION-HOLDER-vs-TESTED-ACTOR-ROLE_AUDIT_REQUIRED
BINDING-VALIDITY-vs-COMPLIANCE-BEHAVIOR_AUDIT_REQUIRED
AUTHORITY-SOURCE-vs-ACTION-SOURCE_AUDIT_REQUIRED
```

核心约束：

```text
someone decides finally != tested actor is z
actor obeys someone != that someone is nx

final adjudication center
!=
actor who follows the adjudicated direction
```

## 1｜自然语言 → IR 结构还原规则

遇到“听他的 / 由他定 / 按他说的办”时，不得先贴十元。必须按以下顺序还原：

1. `actor`：当前到底测试谁。是老板、员工、委员会，还是整套规则。
2. `object`：被裁定/被推进的具体事项是什么。
3. `object_layer`：是否为同一个决策层，禁止把“战略方向”和“执行排班”混为一层。
4. `current_window`：谁先提出、谁能否决、谁最后让结论生效、谁随后执行。
5. `changed_variable` 必须拆为：
   - `binding_final_validity_location`：查 z；或
   - `external_direction_dependency`：查 nx。
6. `relation_source`：z 写最终裁定权来自哪里；nx 写外部已有方向/权限/关系通道来自哪里。
7. `relation_shape`：
   - z：multiple_candidate_judgments_to_single_binding_center；
   - nx：external_direction_or_route_to_actor_following_execution。
8. `decision_right`：z 必须有 final / override / veto / bind 中至少一种现实权限；nx 的 tested actor 应明确没有 final direction right，或当前行为不占该位置。
9. `path_set`：z 放“候选判断/方案 → 最终采用”；nx 放“外部指示/关系通道 → actor 后续执行路径”。不得共用一组成员。
10. `reentry_right`：通常 null；不要把“重新请示”伪造成 nz 回返权。
11. `future_endpoint`：只写当前结构自然延续的终点，不靠职位猜。
12. `reality_anchor`：必须能指出谁的决定真正让同层争议停止，以及 tested actor 后续是否只是沿该结果推进。

若只能得到：

```yaml
changed_variable: who_listens_to_whom
```

则判 `NEEDS_MORE_STRUCTURE`。

## 2｜标准输入

> 产品部在 A / B 两个上线方案间争执。技术负责人、运营负责人都提出方案，但总经理周宁拥有最终上线裁定权；他选择 A 后，技术负责人林澈没有重新提出替代方向，也无权推翻该决定，而是按 A 的已定目标去协调服务器、排上线检查表并申请既有发布权限。若周宁改判 B，林澈也必须沿 B 执行。

必须 SPLIT_IR。

### 2.1 z IR

```yaml
actor: 周宁
object: A/B两个上线方案中哪个获得最终采用资格
object_layer: same_layer_final_product_launch_adjudication
current_window: A/B竞争 -> 多方提出意见 -> 周宁裁定A -> A成为binding方案
changed_variable: binding_final_validity_location
relation_source: formally_granted_final_launch_authority
relation_shape: multiple_competing_judgments_to_single_binding_adjudication_center
decision_right: actor_has_final_bind_and_override_right_on_launch_choice
path_set:
  - candidate_A
  - candidate_B
  - actor_finally_selects_A
reentry_right: null
future_endpoint: A_remains_binding_until_same_or_higher_authority_reopens_decision
reality_anchor: 技术与运营意见冲突时，周宁选择A后同层争议停止，其他负责人无权以自己的方案覆盖该结论
```

判定：`z PASS`。

### 2.2 nx IR

```yaml
actor: 林澈
object: 已被确定为A方案后的上线推进事项
object_layer: downstream_execution_under_external_direction
current_window: 周宁裁定A -> 林澈接受该方向 -> 沿既有发布权限/服务器通道/检查要求推进 -> 完成上线准备
changed_variable: external_direction_dependency
relation_source: superior_final_decision_plus_existing_release_permission_network
relation_shape: externally_fixed_direction_to_actor_following_existing_route_and_permissions
decision_right: actor_has_no_final_direction_right_on_A_vs_B_but_can_execute_bounded_downstream_tasks
path_set:
  - accept_A_as_external_direction
  - coordinate_server_resources_under_existing_scope
  - follow_release_checklist
  - request_existing_release_permission
reentry_right: null
future_endpoint: execute_whichever_launch_direction_is_binding
reality_anchor: 林澈不能把A改回B；若周宁改判B，他的执行路径随之改为B，说明方向源不在林澈
```

判定：`nx PASS`。

## 3｜Positive decision gate

### z gate

```text
same-layer competing judgments/standards exist
+ tested actor/standard is identifiable
+ final bind/override/veto/adopt right is real
+ its decision actually closes or dominates same-layer dispute
+ reality_anchor proves others must treat it as final in current window
= z candidate PASS
```

仅“职位高”“大家尊敬”“经常被询问”不足。

### nx gate

```text
external direction/permission/route already exists
+ tested actor does not occupy final direction position
+ actor continues action through that external route
+ if external direction changes, actor's path correspondingly changes
+ reality_anchor proves dependence is current, not inferred from personality
= nx candidate PASS
```

仅“听话”“礼貌”“是员工”不足。

## 4｜Nearest-neighbor 最小差异

### 4.1 z vs nx

```text
“谁最后让A/B中的一个成为binding答案？”
→ z

“谁没有决定A/B，只沿已经binding的答案继续办？”
→ nx
```

最小 mutation：

```text
林澈可直接推翻周宁并让B生效
→ 林澈 nx ↓，需要重审其 z/zx 等位置

林澈只能在A确定后安排执行细节
→ A/B层 nx 可成立；执行细节层可能另查 xn
```

### 4.2 z vs xn

```text
最终拍板A/B
→ z

A确定后设计排程、检查节点、回滚规则
→ xn
```

### 4.3 nx vs zx

```text
沿已有发布权限与上级方向推进
→ nx

自己生成方向并以自身权能压进现实
→ zx
```

## 5｜False-positive guards

```text
“老板说了算” != 所有参与者都是 z
“我听老板的” != 老板是 nx
职位最高 != z，除非该层现实具有 binding final right
服从一次 != 稳定 nx 人物本体
执行很积极 != zx
执行里主动排流程 != 自动取消上层 nx；必须分 object_layer
有审批链 != z；最终是否收束到单一裁定点要另证
没有 z != nx 自动成立
没有 nx != z 自动成立
```

特别锁定：

```text
same person can be nx on direction-source layer
and xn on downstream execution-organization layer
```

不得因一个人在执行阶段主动排程，就倒写成他拥有上游最终方向权。

## 6｜Removal / reverse / same-layer / current-window

### removal A：拿掉周宁 final bind right

若 A/B 由三人共同等权投票决定：

```text
周宁 z ↓
林澈是否 nx 重新审计
```

因为外部方向仍可能由集体规则生成，不能从“周宁不再z”推出“林澈不再nx”。

### removal B：给林澈同层 override right

若林澈可自行把A改成B并直接生效：

```text
原 A/B 层 nx ↓
```

但不能仅据此自动判 z，仍要查是否真正成为最高裁定中心。

### reverse

将“周宁裁定A，林澈执行”反成“林澈提出最终B并可覆盖周宁意见”：

- 决策中心发生迁移，重新抽取 z IR；
- 林澈原 nx IR 失效；
- 禁止只修改 label 而继承旧 `decision_right`。

### same-layer

```text
A/B战略最终选择层
!=
A方案内部执行排程层
```

同一个人可以在上层 nx、下层 xn；同一个老板可以在战略层 z、在董事会更高层又是 nx。人物不是十元，关系位置才是被测结构。

### current-window

去年周宁能最终拍板、今年已改成委员会表决：

```text
去年 z 不能继承到今年
```

去年林澈听命、今年已获独立产品线最终权：

```text
去年 nx 不能继承到今年
```

## 7｜Adversarial tests

1. **关键词诱导**：“最后都听他的，他让怎么做就怎么做。”没有说明 tested actor、同层事项和 binding right。→ `NEEDS_MORE_STRUCTURE`。
2. **题材/职业/情绪诱导**：威严皇帝怒斥群臣，众人害怕。若没有该事项最终裁定事实，不凭皇帝身份判 z；侍从沉默也不凭恐惧判 nx。
3. **对象层错位**：院长最终决定医院扩建方案，但护士按医生处方执行护理。扩建层可查院长 z；护理路径层查护士是否 nx，禁止跨对象层。
4. **时间窗错位**：去年老板最终拍板，今年预算委员会拥有最终权。不得沿用老板历史 z；员工今年是否 nx 取决于当前外部方向源。
5. **同关系词异对象层**：“听主任的”在战略层指最终项目方向；在手术室里只是按当前流程口令。必须分别重建 IR。
6. **对端不存在不等于本端成立**：项目无任何最终裁定者而自然停摆，不推出员工 nx；员工离职也不推出老板 z。
7. **咨询伪 z**：所有人都会咨询专家，但董事会可无条件否决专家意见。→ 专家 z FAIL/弱。
8. **积极执行伪 zx**：员工按上级A方案跑得极快并主动协调资源，但无权把A改B。→ 上游方向层 nx 可 PASS；不因积极执行判 zx。
9. **主动排程伪非-nx**：员工无权决定A/B，但在A确定后主动搭五步上线流程。→ A/B层 nx + 执行组织层 xn，SPLIT_IR。
10. **名义老板伪 z**：CEO头衔最高，但合同规定技术安全事项由安全委员会一票否决。→ 技术安全层 CEO z FAIL/弱。
11. **共同表决伪单中心 z**：三人等权2/3票通过A，无人拥有最终覆盖权。→ 单一 z 不得强填；按当前 canonical 需另审分布式裁定结构。
12. **最小 mutation**：仅把 `decision_right` 从“无A/B最终权，随外部binding方向改变”改成“可最终覆盖其他意见并让自己的A/B选择生效”，必须重新抽取 IR，原 nx ↓，z 是否↑独立重审。

## 8｜新增状态迁移规则

```text
FINAL-ADJUDICATION-CENTRALITY:
consulted_only
→ strong_influence
→ formal_veto_or_adopt_right
→ single_binding_final_center
= z evidence ↑
```

独立另一轨：

```text
EXTERNAL-DIRECTION-DEPENDENCY:
self_direction_available
→ external_direction_accepted
→ external_permission/route_required
→ actor_path_changes_when_external_direction_changes
= nx evidence ↑
```

因此：

```text
z ↑ != nx ↑ automatically
nx ↑ != z ↑ automatically
```

只有在同一 current_window 中，一个明确 final center 产生 binding direction，而另一个 tested actor 以该方向为外部输入继续行动时，才可分别得到 `z PASS` 与 `nx PASS`。

## 9｜成功门判定

本轮不是重复“z拍板 / nx听话”的口号，而是新增以下可执行翻译约束：

```text
DECISION-HOLDER-vs-TESTED-ACTOR-ROLE_AUDIT_REQUIRED
BINDING-VALIDITY-vs-COMPLIANCE-BEHAVIOR_AUDIT_REQUIRED
AUTHORITY-SOURCE-vs-ACTION-SOURCE_AUDIT_REQUIRED
```

并新增：

- `binding_final_validity_location` vs `external_direction_dependency` 两类 `changed_variable`；
- 同一句“听他的”必须先确定 tested actor；
- 上游方向层 nx 与下游执行层 xn 可在同一人物并存，但不得共享 object_layer；
- final-center removal 不自动取消 follower nx，因为外部方向可由另一中心或集体规则产生；
- mutation 后必须重新抽取 `decision_right`，不得继承旧 IR。

因此：`PASS / 新增翻译规则 = yes`。
