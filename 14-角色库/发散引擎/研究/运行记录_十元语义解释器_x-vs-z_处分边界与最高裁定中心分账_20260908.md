# 十元语义解释器｜x vs z：处分边界与最高裁定中心分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。`z_准度卡_v0.1` 仍保留旧“认可位置”口径，但 L2 v1.1 已明确覆盖：current `z` 以“运行权与裁定重心收束到单一最高中心/最终裁定点”为准。本轮只按 current canonical 建研究层翻译规则。

## 1｜本轮目标与翻译债务

目标混淆对：`x vs z`。

高风险自然语言包括：“我说了算”“这是我的”“归我管”“最终由我决定”“我有否决权”“我能处理它”“必须以我的意见为准”。这些句子都可能出现 `decision_right`，但权利的语义对象不同：

- `x`：对象、资源、权限、关系或范围进入主体当前掌握/调用/调配/处分/排除边界；
- `z`：对一个答案、标准、判断、终局结果或结构重心的最高裁定资格收束到单一中心。

本轮新增候选规则：`DISPOSITION-RIGHT-vs-ADJUDICATION-RIGHT-v0.1`。

核心硬约束：

```text
DECISION_RIGHT_SEMANTIC_CLASS_AUDIT_REQUIRED
OBJECT_OF_RIGHT_AUDIT_REQUIRED

disposition_right != adjudication_right
can_change_object_state != can_define_final_answer
```

不得因为文本出现“决定/否决/最终/归我”就跳标签。必须先回答：这个权利到底在改变“对象状态”，还是在决定“哪个答案/标准/结果具有最终效力”。

## 2｜自然语言 → Semantic IR 结构还原规则

固定先抽 IR，再判十元：

1. `actor`：锁定当前被测主体。若同一句中“资产管理员”和“评审主席”是不同主体，必须拆 actor。
2. `object`：优先区分两类对象：
   - x 候选：钱、账号、设备、岗位名额、资源、成员资格、访问范围、可处分关系；
   - z 候选：答案、评分、标准、判定、是否通过、最终方案、终局口径。
   题材名词不具标签力，必须看对象实际被怎样操作。
3. `object_layer`：若一句同时存在“处分资源”与“裁定结果”，必须 `SPLIT_IR`。不得把“预算控制权”拿去证明“方案终审权”，也不得反过来。
4. `current_window`：只读当前有效权限。历史所有权、未来接管、将来到期都不能直接回写当前。
5. `changed_variable`：
   - x 候选优先：`current_disposition_scope` / `resource_control_boundary` / `object_state_control`；
   - z 候选优先：`adjudication_center_distribution` / `final_answer_authority` / `standard_binding_force`；
   - 无法确认时保持 `unknown`。
6. `relation_source`：记录权利来自所有权、授权、章程、制度、委任或其他来源；来源本身不能代替当前权利位置。
7. `relation_shape`：
   - x：`actor_to_object_direct_state_control`、`object_inside_actor_disposition_boundary`；
   - z：`multiple_judgments_to_single_final_center`、`candidate_answers_to_binding_adjudicator`。
8. `decision_right`：必须写明语义 class 和 scope：
   - `actor_direct_disposition_on_object` / `actor_can_use_allocate_exclude`；
   - `actor_final_adjudication_on_answer` / `actor_can_override_peer_judgments`。
   若文本只说“有决定权”而无法判 scope，填 `unknown`，不得补猜。
9. `path_set`：
   - x 的 path_set 是对象状态可被主体现实拨动的动作，如使用、转账、冻结、分配、收回、排除；
   - z 的 path_set 是候选判断/答案/标准进入最终裁定的路线，如甲方案、乙方案、评审意见、主席终审。
10. `reentry_right`：只在对象离开处分边界后能否重新进入，或被否决候选能否重新取得裁定资格时有直接证据才填。
11. `future_endpoint`：仅文本明确未来终局时填写。`最终由我决定`不等于未来结果内容已知。
12. `reality_anchor`：
   - x：actor 单独动作即可现实改变被测对象状态；
   - z：actor 的判断可改变哪个答案/结果成为最终有效结果，并可压过同层其他判断。

### 新 IR 约束 A｜DECISION_RIGHT_SEMANTIC_CLASS_AUDIT

```text
如果“决定权”回答：
谁能用、拿、调、冻、给、收回、排除这个对象？
→ disposition/control evidence，优先服务 x gate。

如果“决定权”回答：
哪个答案、标准、判断、方案最后生效？谁能覆盖同层判断？
→ adjudication evidence，优先服务 z gate。
```

### 新 IR 约束 B｜OBJECT_OF_RIGHT_AUDIT

同一个 actor 可以同时拥有 x 与 z，但只有在不同 object/object_layer 有各自证据时成立。例如：

```text
我能冻结项目账户
→ 账户资源处分层：x candidate

我能推翻所有评审意见决定是否立项
→ 立项结果裁定层：z candidate
```

禁止用“主体权力很大”把两层合并。

## 3｜标准输入与完整 IR

输入：

> “博物馆馆长可以直接调配馆藏修复预算、冻结子账户并收回工作室钥匙，不需要委员会逐笔批准；但年度展览主题由五名策展人先各自提出方案，馆长拥有最终终审权，即使四名策展人都支持方案A，他也可以裁定方案B作为唯一执行主题。馆长不能因为否决方案A就把策展人的私人设备收走。”

必须拆两个 IR。

### IR-A｜资源处分层：x candidate

```yaml
actor: 博物馆馆长
object: 馆藏修复预算、子账户与工作室钥匙
object_layer: 馆内资源当前使用与处分层
current_window: 权限有效 -> 馆长直接调配/冻结/收回 -> 当前仍有效
changed_variable: current_disposition_scope
relation_source: institutional_authority
relation_shape: object_inside_actor_disposition_boundary
decision_right: actor_direct_disposition_on_object
path_set:
  - allocate_restoration_budget
  - freeze_subaccount
  - revoke_workspace_key
reentry_right: unknown
future_endpoint: null
reality_anchor: 馆长无需委员会逐笔批准即可单独改变预算、账户与钥匙的现实状态
```

判定：`x candidate PASS`。

### IR-B｜展览主题裁定层：z candidate

```yaml
actor: 博物馆馆长
object: 年度展览主题的最终有效方案
object_layer: 多个策展方案的最终裁定与生效资格层
current_window: 五名策展人提出方案 -> 各意见并存 -> 馆长终审 -> 一个方案获得最终执行效力
changed_variable: adjudication_center_distribution
relation_source: institutional_final_authority
relation_shape: multiple_judgments_to_single_final_center
decision_right: actor_final_adjudication_on_exhibition_theme
path_set:
  - curator_proposal_A
  - curator_proposal_B
  - other_curator_proposals
  - director_final_adjudication
reentry_right: rejected_proposal_requires_new_round
future_endpoint: one_binding_exhibition_theme
reality_anchor: 即使多数策展人支持A，馆长仍可令B成为唯一执行主题；撤掉终审权后，馆长意见不再自动覆盖同层判断
```

判定：`z candidate PASS`。

## 4｜Positive decision gates

### x candidate gate

```text
X1 object 明确且是可被现实使用/调配/处分/排除的对象或范围；
X2 actor 明确；
X3 current_window 内 actor 至少拥有一条直接现实控制路径；
X4 decision_right 的语义 class 属于 disposition/control，而非仅“发表意见”；
X5 actor 单独动作能改变同层对象状态；
X6 权利不是纯名义、一次接触或视觉威慑；
X7 reality_anchor 能指向实际使用、冻结、调配、收回、否决访问等现实改变；
X8 removal 该处分边界后，对象状态控制出现可命名缺口，即使最终标准裁定权完全不变。
```

### z candidate gate

```text
Z1 object_layer 明确指向答案、标准、判断、结果、方案或最终有效性；
Z2 同层存在至少两个可比较的候选判断/路线，或明确存在可被覆盖的同层判断位置；
Z3 decision_right 的语义 class 属于 final adjudication，而非对象处分；
Z4 relation_shape 显示判断权/结构重心收束到单一最高中心；
Z5 该中心能使自己的判断取得最终效力，并覆盖或终结同层其他判断的同等最终效力；
Z6 reality_anchor 证明这种裁定效力当前真实存在，不只是头衔或“大家都听他的”；
Z7 单纯拥有对象、资源或否决访问权不足以判 z；
Z8 removal 最高裁定中心后，多判断重新保持同等终局资格或需要新的裁定机制，即使资源归属完全不变。
```

## 5｜nearest-neighbor 最小差异

### x vs z

```text
x：谁能直接改变“对象本身的现实状态/归属/使用边界”？
z：谁能决定“哪个答案/标准/判断/方案具有最终效力”？
```

IR 压缩：

```text
object_state_control
vs
answer_validity_control
```

### x vs zx

`x` 可以是静态已拥有的掌握/处分边界；`zx` 还要主体自身方向/权能公开进入现实、扩大决定范围并使竞争方向或秩序被迫重新反应。已有馆藏处分权不等于正在扩权。

### z vs xn

`z` 把裁定重心收束到最高中心；`xn` 把运行权和判断权分布到规则、记录、节点、顺序与流程。一个人可最终终审，但前面的流程仍可以高度 xn；不能拿流程复杂度否定 z，也不能拿终审位抹掉 xn。

### x vs nx

`x` 当前拥有直接控制路径；`nx` 的关键动作仍沿外部已有路线/权限/通道推进。权利“最初由外部授予”不能单独推出 nx。

## 6｜false-positive guards

1. “我说了算”护栏：必须问说了算的是资源状态还是答案有效性。
2. “最终决定”护栏：如果所谓最终决定只是“最后谁拿钥匙/谁使用设备”，优先查 x，不自动 z。
3. “否决权”护栏：拒绝别人访问账户可以是 x；推翻同层方案并决定最终有效方案才进入 z gate。
4. 老板、馆长、法官、家长、地主等身份不产生标签。
5. 有财产权/管理权不自动有最高标准裁定权。
6. 有最高裁定权不自动拥有被裁定对象的物理/资源处分权。
7. 多数人服从某人，不等于其判断具有结构性最终效力；需 reality anchor。
8. 单一候选从一开始就不存在竞争判断，不足以只凭“唯一结果”判 z。
9. 对象不可处分不推出 z；无最终裁定中心也不推出 x。
10. 不得从题材、财富、威严、胜负、情绪或悲惨程度倒推。

## 7｜removal / reverse / same-layer / current-window

### Removal A｜撤 x 不撤 z

保留馆长展览主题终审权，但把预算、账户、钥匙全部交给独立财务与设施部门，馆长每次必须申请。

预期：
- `x` 在资源处分层下降；
- `z` 在展览主题裁定层可保持。

### Removal B｜撤 z 不撤 x

保留馆长对预算、账户、钥匙的直接处分权，但展览主题改为五名策展人多数决，馆长只有一票且不能覆盖。

预期：
- `x` 可保持；
- `z` 在主题裁定层下降。

### Reverse

```text
保留“我说了算”四个字，
若 actor 只能调配资源却不能决定方案最终有效性
→ 不得判 z。

保留“最终决定”四个字，
若 actor 只能选最终资源接收者但对资源没有后续使用/处分能力
→ 该句优先建立裁定层 z IR；不能借词面自动补 x。
```

### Same-layer

预算处分层与主题终审层必须分开。只有当同一个 object_layer 同时存在两种不同权利时，才允许并列两个 IR；禁止跨层互证。

### Current-window

历史上拥有资产、未来将接管资产、任期结束后失权，都不能覆盖当前窗口。历史曾是最终裁定者，也不能让当前委员会制继续贴 z。

## 8｜Adversarial tests

### T1｜关键词诱导

输入：“老板说‘公司里我说了算’，但银行账户由受托人管理，产品方向由董事会多数决；他只能决定自己办公室家具摆放。”

预期：不能凭“我说了算”判公司层 x 或 z；办公室家具若存在直接处分证据，只能在家具层查 x。

### T2｜题材/职业/情绪诱导

输入：“威严的最高法院院长今天只是保管会议室钥匙，案件裁判必须由合议庭多数形成，他没有额外终审覆盖权。”

预期：钥匙层可查 x；案件裁判层 z FAIL/UNKNOWN。职业与威严不提供 z。

### T3｜对象层错位

输入：“校长可直接调配礼堂和校车，但招生分数线由独立委员会最终裁定；校长不能改分数线。”

预期：礼堂/校车层 x candidate；招生标准层 tested actor z FAIL。不得拿资源管理权证明招生终审。

### T4｜时间窗错位

输入：“去年创始人既控账户又能终审产品方向；今年账户已交托管，方向改为董事会多数决，只保留荣誉董事长称号。”

预期：当前窗口不得继承旧 x/z。

### T5｜同关系词异对象层

输入：“经理对仓库有‘最终决定权’，意思是最终决定谁能领用设备；对产品方案也有‘最终决定权’，意思是能覆盖全部评审意见。”

预期：前者先查仓库资源处分层 x；后者查方案裁定层 z。同一词面不同语义 class。

### T6｜对端不存在不等于本端成立

输入：“被冻结的遗产账户当前没人能动，继承争议也尚无任何法院或仲裁机构取得最终裁定资格。”

预期：x FAIL/UNKNOWN；z FAIL/UNKNOWN。没人有处分权不意味着存在最高裁定中心，反之亦然。

### T7｜否决访问伪 z

输入：“系统管理员能禁用任何员工账号，但无权判断员工绩效等级，绩效由委员会投票。”

预期：账号层 x candidate；绩效层 z FAIL。‘否决’不能跨对象层。

### T8｜终审权伪 x

输入：“艺术奖主席可以从评委结果中最终选出获奖作品，但作品版权、原件和奖金账户均不归主席处分。”

预期：获奖结果裁定层 z candidate；版权/原件/资金层 x FAIL/UNKNOWN。

### T9｜单一结果伪 z

输入：“数据库约束自动删除重复项，最终只剩一条记录；没有任何主体或规则节点拥有覆盖同层判断的终审资格。”

预期：仅‘最后一个’不足以锁 z，需审计是否存在结构性的最高裁定中心/最终裁定点；若只是机械去重且不构成当前 canonical 所指裁定重心，z FAIL/UNKNOWN。

### T10｜状态迁移：处分权变化而裁定权不变

输入：“财务主管原本每笔付款需董事会批准，后来获得50万元内直接调配权；项目是否值得继续仍始终由董事会最终裁定。”

预期：资金层 `x` 上升；项目价值裁定层 z 不自动变化。

### T11｜状态迁移：裁定权变化而处分权不变

输入：“馆长一直能管理预算和钥匙；后来章程改为由他单独终审年度主题，原五人多数决取消。”

预期：资源层 x 不变；主题裁定层 z 上升。

### T12｜同主体双层并存但不可互推

输入：“游戏主策能直接冻结测试服账号，同时也拥有剧情方案最终终审权，但美术资产版权归公司法务管理。”

预期：测试服账号层 x；剧情方案层 z；美术版权层不能因为同一主体很强就补 x。

## 9｜状态迁移规则

本轮新增两条相互独立的迁移链：

```text
external/per-action control
→ direct disposition scope acquired
= x candidate ↑

x 的变化不自动改变 final adjudication center
```

以及：

```text
peer/coequal judgments
→ single binding adjudicator established
= z candidate ↑

z 的变化不自动改变 object possession/disposition boundary
```

因此解释器必须独立维护：

```text
CONTROL_LOCUS_STATE
ADJUDICATION_LOCUS_STATE
```

不得压成一个笼统的 `power=true`。

## 10｜成功门判断

本轮不是重复已有机制，新增了：

1. `DECISION_RIGHT_SEMANTIC_CLASS_AUDIT_REQUIRED`；
2. `OBJECT_OF_RIGHT_AUDIT_REQUIRED`；
3. `object_state_control vs answer_validity_control` 的 changed-variable 分流；
4. “否决访问 ≠ 否决答案”的 adversarial negative；
5. x/z 两条独立状态迁移；
6. `CONTROL_LOCUS_STATE` 与 `ADJUDICATION_LOCUS_STATE` 双状态约束。

结论：`PASS`，满足提交门。

## 11｜下一轮翻译风险

本轮使用 `x / z`，下一轮不得继续使用这两个十元。

当前优先候选：`zn vs xn`。

高风险自然语言：“我给你一套规则让你自己发展”“我建立制度保障每个人独立决定”“我设计流程让多个角色各自成立”。

需要进一步拆：

```text
zn：保存 other independent endpoint 本身
vs
xn：生成/维护让行动持续运行的 procedure topology
```

关键债务是：**制度或流程保护了独立性，不等于制度本身就是 zn；必须区分被保护的 endpoint 与承载该保护的运行结构。**
