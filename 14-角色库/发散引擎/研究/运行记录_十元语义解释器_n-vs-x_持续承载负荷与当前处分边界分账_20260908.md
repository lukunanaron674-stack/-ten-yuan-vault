# 十元语义解释器｜n vs x：持续承载负荷与当前处分边界分账

> research-only。仅服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远优先；不得反写 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮翻译债务

高风险自然语言：

```text
“它归我管”
“东西放在我这里”
“我一直养着/照顾/保管它”
“这个项目一直由我负责”
```

这些句子常把两种独立结构揉成一个“控制/负责”标签：

- `n`：对象进入内部后，谁现实承担它持续存在所产生的负荷；
- `x`：对象当前进入谁的占有、使用、调配、排除或处分边界。

canonical 已经给出概念差异，但解释器仍缺两个机器可用约束：

1. **custody/stewardship 不等于 disposition**：保管、照护、代养、托管可以承担巨大负荷，却没有转让、冻结、改用途、排除原权利人的处分权；
2. **disposition 不等于 carrying**：有权冻结、调配、出售、收回对象，不代表 tested actor 亲自或通过其结构持续处理对象的日常负荷。

本轮新增：

```text
CARRYING-LOAD-vs-DISPOSITION-BOUNDARY-v0.1
CUSTODY-DISPOSITION-SEPARATION_AUDIT_REQUIRED
LOAD-PATH-vs-CONTROL-PATH_AUDIT_REQUIRED
```

并把差异接到 Semantic IR mutation contract：冻结 `actor/object/object_layer/current_window`，只改变 `decision_right + relation_shape + path_set + reality_anchor`，观察候选符号是否发生预期变化。若为了把 n 改成 x 而偷偷改对象层或时间窗，视为 unauthorized reinterpretation。

## 2｜自然语言 → IR 结构还原规则

### STEP 1｜冻结 object 与 object_layer

先问：当前说的是**同一个对象、同一个层**吗？

例如“狗由寄养员照顾”与“狗的出售权属于主人”可以指同一只狗，但测试变量不同：前者是持续负荷，后者是处分边界。若一句话同时含两者，允许 `SPLIT_IR`，禁止把照护证据拿去填处分权。

### STEP 2｜抽取对象在场状态，但禁止 `presence => n/x`

`object_presence` 不新增字段，只编码在 `current_window + relation_shape + reality_anchor`。

```text
对象长期在我这里
!= n 自动成立
!= x 自动成立
```

长期在场可能来自：寄养、仓储、医院照护、拘留、租赁、借用、代管、扣押。必须继续看负荷与权限。

### STEP 3｜对 path_set 做语义分型

```text
carrying paths:
喂养 / 供床 / 补给 / 清洁 / 风险处理 / 维护 / 日常协调 / 持续保护
→ n evidence

control paths:
出售 / 转让 / 冻结 / 调配用途 / 排除他人 / 收回权限 / 改变归属范围
→ x evidence
```

同一动作若只是执行他人决定，不可自动当作 actor 的 x。例如仓管员按货主指令把货移到 B 区，只证明操作执行，不证明仓管员拥有用途处分权。

### STEP 4｜decision_right 做“权限语义类”审计

```text
care_execution_right / custodial_duty
!=
disposition_right / allocation_right / exclusion_right
```

`n` 不要求 actor 拥有对象最终处分权；`x` 则必须有现实控制/归属边界，至少一项对象状态可由 actor 在其 scope 内直接决定。

### STEP 5｜reality_anchor 归因

`n` reality anchor 必须证明：对象继续留在内部造成的现实时间、空间、资源、照护、风险或协调负荷，确实由 actor/structure 跨阶段承担。

`x` reality anchor 必须证明：actor 的决定能直接改变对象的使用、调配、排除、归属或控制状态，而不是只有照顾义务、保管责任或物理接触。

### STEP 6｜mutation contract 最小反事实

固定：

```text
actor
object
object_layer
current_window
```

Mutation N→X：

```text
mutated_fields:
- decision_right
- relation_shape
- path_set
- reality_anchor
```

若把“持续照护但无处分权”改为“停止照护、改为可直接出售/冻结/调配”，预期：`n ↓ / x ↑`。

Mutation X→N：保持对象与时间窗不变，把直接处分权撤掉，改成持续照护/维护负荷，预期：`x ↓ / n ↑`。

这成为本轮新的翻译稳定性检查，不允许靠换题材、换 actor 或换 object_layer 制造标签变化。

## 3｜标准输入与完整 IR

输入：

> “宠物医院替林女士寄养一只老犬三个月。住院部每天喂食、换药、清洁、夜间观察并处理突发状况，老犬持续占用床位和护理资源；但医院不能出售、转赠、改变所有权，也不能在非紧急情况下自行决定重大治疗，主人随时可以终止寄养接走。另一个独立事项里，林女士虽然不亲自照料，但她可以决定是否出售老犬、授权重大治疗、终止寄养并指定新的照护机构。”

必须 SPLIT_IR。

### IR-A｜n：持续负荷承载

```yaml
actor: 宠物医院住院部
object: 林女士寄养的老犬
object_layer: 老犬在寄养期间的内部照护与持续负荷层
current_window: 入院寄养 -> 三个月持续在院 -> 每日护理与突发处理
changed_variable: sustained_load_carrying
relation_source: custodial_care_arrangement
relation_shape: admitted_then_continuously_carried_without_disposition_ownership
decision_right: care_execution_within_medical_and_owner_constraints
path_set:
  - daily_feeding
  - medication_change
  - cleaning
  - night_observation
  - emergency_handling
reentry_right: null
future_endpoint: owner_terminates_boarding_or_term_ends
reality_anchor: 老犬连续占用床位、护理时间、药物和风险处理资源，住院部跨阶段现实承担这些负荷
```

判定：**n candidate PASS**；对住院部的 `x` 不得仅凭“狗在医院里、医院负责管理”成立。

### IR-B｜x：当前处分边界

```yaml
actor: 林女士
object: 同一只老犬的重大处置与照护去向
object_layer: 老犬当前所有权、重大治疗授权与照护机构选择层
current_window: 寄养有效期间 -> 主人持续保有处分/授权权 -> 可随时终止并改派
changed_variable: current_disposition_scope
relation_source: owner_control_boundary
relation_shape: object_under_owner_disposition_while_care_is_delegated
decision_right: owner_direct_on_sale_major_treatment_and_care_destination
path_set:
  - approve_or_refuse_sale
  - authorize_major_treatment
  - terminate_boarding
  - designate_new_care_provider
reentry_right: null
future_endpoint: null
reality_anchor: 林女士即使不承担每日护理，也能直接改变老犬的出售、重大治疗授权与照护去向
```

判定：**x candidate PASS**；对林女士的 `n` 不能只因“她是主人”或支付费用自动成立，需另证其持续承载负荷。

## 4｜Positive decision gates

### n gate

至少要求：

1. actor/object/object_layer/current_window 明确；
2. 对象真实进入 actor/structure 的内部承载边界；
3. 对象获得跨阶段位置，而非瞬时接触；
4. `path_set` 至少含一个重复或持续现实 carrying path；
5. `reality_anchor` 能指出对象留下产生的时间/空间/资源/照护/风险/协调负荷；
6. actor/structure 实际承担这些负荷；
7. 只有 custody、看守、物理在场、一次救援不足；强制拘留也不能伪装成 n。

### x gate

至少要求：

1. object 与被控制 scope 明确；
2. `changed_variable` 指向 current control/disposition/allocation/exclusion scope；
3. `decision_right` 至少存在一项 actor 可现实直接行使的对象控制权；
4. `path_set` 至少一条能改变对象使用、调配、归属或排除状态的 control path；
5. `reality_anchor` 证明 actor 的决定能现实改变对象状态；
6. 保管义务、照护责任、物理持有、按他人命令操作都不能替代处分边界。

## 5｜nearest-neighbor 最小差异

### n vs x

```text
n：对象留下以后，谁持续承担“它继续存在在这里”造成的现实负荷？
x：对象现在由谁拥有直接使用、调配、排除或处分边界？
```

最小对照：

- 寄养员每天照料但不能卖/转/改用途：`n ↑ / x ↓`；
- 所有者可出售/转移但把日常照护完全外包：`x ↑ / n tested actor 未必成立`。

### n vs nx

```text
n：主体/结构承担对象留下后的负荷。
nx：主体不占最终方向，沿外部既有 route 推进。
```

护士按医嘱执行护理可同时出现“承载结构中的 n evidence”和“护士个体沿医嘱的 nx evidence”，必须按 actor 与 object_layer 分账。

### x vs xn

```text
x：哪些对象/权限当前归我掌握。
xn：我怎样主动组织流程、时间、记录与节点持续运行。
```

仓库主管有货物调配权可查 x；他另行设计盘点、交接和复核流程才查 xn。

## 6｜False-positive guards

1. “我负责它”只触发抽取，不产 n/x。
2. “放在我这里”不等于 n，也不等于 x。
3. 物理持有/保管 ≠ disposition boundary。
4. 每日照护很辛苦 ≠ 对象归 actor 掌握。
5. 所有权/处分权很强 ≠ actor 实际承担日常负荷。
6. 支付费用 ≠ 自动 n；付款是否构成持续承载须看 tested layer 与现实负荷。
7. 看守、拘禁、扣押可有 control evidence，但不能因对象长期在场自动判 n。
8. 仓储服务承担空间与维护负荷，不因此取得货物出售权。
9. 按货主指令移动货物 ≠ 仓管员 x；需检查 decision_right 来源与独立 scope。
10. `n FAIL` 不推出 `x`；`x FAIL` 不推出 `n`。
11. 历史照护/历史所有权不能续贴 current window。
12. 职业、身份、情绪、题材不得补缺结构字段。

## 7｜Removal / reverse / same-layer / current-window

### n removal

保留老犬在医院与主人的所有权关系，只撤掉医院的喂养、换药、清洁、夜间观察与风险处理，改由外部团队全包。

预期：住院部 `n ↓`；林女士 `x` 不受此 removal 自动影响。

### x removal

保持医院三个月全部护理不变，把林女士的出售、重大治疗授权、终止寄养与改派权全部交给独立监护机构。

预期：林女士 `x ↓`；医院 `n` 可保持。

### reverse

- “医院负责保管”但只能按主人逐次指令操作：不能反向补医院 x。
- “主人拥有全部处分权”但完全不承担 tested carrying layer：不能反向补主人 n。

### same-layer

同一对象不等于同一变量。若测试“日常照护负荷层”，所有权证据不可倒灌；若测试“出售/重大治疗授权层”，喂食换药不可倒灌。

### current-window

上个月医院曾承担护理、本月已全部转给外包；或主人上月有处分权、本月法院已移交监护。旧状态不得续贴当前。

## 8｜Adversarial tests

### T1 关键词诱导

> “这只狗一直归我管。”实际说话人只是每天喂食，任何出售、转诊、带离都要主人批准。

预期：可查 n；说话人的 x FAIL/弱。关键词“归我管”不得越过 decision_right。

### T2 题材/职业/情绪诱导

> 冷酷典狱长“掌控所有囚犯”，但 tested object_layer 是囚犯是否被持续照护；监狱故意断食且无医疗维护。

预期：不能因职业/气质/控制词判 n；控制结构另查 x/zx 等。

### T3 对象层错位

> 护士承担病人的每日护理；医院法务决定昂贵设备是否出售。

预期：病人照护层查 n；设备处分层查 x；禁止互补。

### T4 时间窗错位

> 去年管理员既照护动物又有转移动物权限，今年只剩照护职责，转移权已交委员会。

预期：current n 可成立，旧 x 不继承。

### T5 同关系词异对象层

> “负责仓库”：甲负责防潮、巡检、维护；乙负责决定货物出售、调拨与冻结。

预期：同一个“负责”，甲侧查 n-like carrying evidence，乙侧查 x；不得词面共标。

### T6 对端不存在不等于本端成立

> 无人照护的弃置仓库里有一批被法院冻结、当前也无人拥有可执行处分权的货物。

预期：tested actor n/x 均 FAIL/UNKNOWN。n 不存在不推出 x，x 不存在也不推出 n。

### T7 保管伪 x

> 博物馆受托保管私人藏画十年，恒温、安保、修复都由馆方承担，但馆方无权出售、外借或改变所有权。

预期：承载层 n 强；馆方 x 不因长期保管成立。

### T8 所有权伪 n

> 收藏家拥有十匹马并可出售转让，但马匹全部寄养，日常饲料、医疗、场地和风险都由马场承担。

预期：收藏家 x 强；收藏家在 tested daily-carrying layer 的 n 不自动成立。

### T9 执行操作伪 x

> 仓管员每天按货主指令调货，自己不能决定用途、冻结、出售或排除货主取货。

预期：不能仅凭“调货”锁仓管员 x。

### T10 控制伪 n

> 执法部门扣押车辆六个月，有权禁止车主使用，但车辆长期露天损坏、无人维护。

预期：可查 x/control；不得因“在内部六个月”锁 n。

### T11 双层并存

> 动物救助机构既承担全部日常护理，又依法取得无人认领动物的转养决定权。

预期：允许同 actor 对同对象在不同 tested variable 上分别 n PASS、x PASS；必须 SPLIT_IR，不得合成一个模糊“负责”。

### T12 mutation contract 最小突变

Source IR：同一寄养员、同一只狗、同一三个月窗口，只有持续喂养/护理，重大处置权归主人。

Mutation：冻结 `actor/object/object_layer/current_window`，仅把 `decision_right/relation_shape/path_set/reality_anchor` 改为“停止护理；寄养员可独立出售、冻结转移并排除主人取回”。

预期：结构变化必须是 `n ↓ / x ↑`。若系统为了得到 x 改 actor、object 或 current_window，mutation 校验应拒绝该解释漂移。

## 9｜状态迁移

两条状态轨独立：

```text
CARRYING_STATE:
object_present_without_support
→ recurring_load_handled
→ resilient_cross-stage_carrying
= n ↑
```

```text
CONTROL_STATE:
physical_custody_only
→ bounded_use/control_right
→ direct_disposition/exclusion_scope
= x ↑
```

核心不变量：

```text
n ↑ != x ↑
x ↑ != n ↑
physical custody != disposition
ownership/disposition != carrying
```

## 10｜成功门核验

本轮不是重复 canonical，新增的信息增益为：

1. `CUSTODY-DISPOSITION-SEPARATION_AUDIT_REQUIRED`；
2. `LOAD-PATH-vs-CONTROL-PATH_AUDIT_REQUIRED`；
3. 对 `decision_right` 增加 care_execution/custodial duty 与 disposition/control 的语义类型约束；
4. 将新 P0-7 mutation contract 用于最近邻最小反事实：冻结 actor/object/object_layer/current_window，只突变权利与路径证据；
5. 新增“保管伪 x”“所有权伪 n”“执行操作伪 x”“控制伪 n”四组 adversarial negatives；
6. 新增 CARRYING_STATE 与 CONTROL_STATE 独立迁移。

因此：**PASS，可提交 research-only。**

## 11｜下一轮风险候选

本轮占用 `n / x`，下一轮必须避开二者。

当前高风险候选：`nz vs zn`。

危险语言：

```text
“我永远给你留位置 / 我不会取消你的资格 / 你随时可以回来”
```

需要拆：

- `zn`：other independent endpoint 是否在当前同层被真实保存；
- `nz`：对象实际离开后，原对象特异 reentry path 是否仍现实可调用。

重点字段：`current_window + reentry_right + decision_right + path_set`，尤其要防止“保留独立资格”自动被翻成“已经存在离开后回返生命周期”。
