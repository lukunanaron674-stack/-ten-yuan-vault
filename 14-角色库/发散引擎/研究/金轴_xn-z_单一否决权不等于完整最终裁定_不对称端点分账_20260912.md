# 金轴 xn↔z｜单一否决权不等于完整最终裁定：不对称端点分账

> L4 research-only。本文件只测试“一个节点拥有单一 veto，是否足以把整个裁定结构判成 z”。不修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮缺口

上一轮 `AGGREGATION-NOT-CENTER-GATE-v0.1` 已确认：多人投票/多签并不天然是 xn；关键在 binding contribution 是否由不可任意覆盖的规则直接聚合，还是仍需单一中心自由最终裁定。

留下的高价值断点是：

```text
系统已有分布式 binding contributions，
但其中某一个节点拥有 veto。

这个 veto 是否自动把整个系统变成 z？
```

本轮结论：

```text
单一 veto 节点 ≠ 自动 z。
```

必须继续区分：

- bounded local veto：仅对预定义条件/局部对象层生效；
- universal negative veto：可单方面阻止任意正向结果；
- positive authorization：能否单方面形成通过结果；
- full final adjudication：能否在同层同窗内自由决定整个 tested state 的最终结果。

新增候选门：

`VETO-NOT-FULL-ADJUDICATION-GATE-v0.1`

核心变量：

```text
endpoint_control_symmetry
+
override_scope
+
final_adjudication_completeness
```

## 1｜current criterion

current canonical：

- `xn`：运行权/判断权分布到顺序、规则、记录、节点与流程；
- `z`：判断权与结构重心收束到单一最高中心或最终裁定点。

本轮操作化：

```text
拥有“阻止”能力
不等于拥有“完整最终裁定”能力。
```

需要把二元结果拆成两个方向：

```text
positive endpoint control：谁能让结果成立？
negative endpoint control：谁能让结果不成立？
```

如果：

```text
正向成立仍必须由多个独立 binding nodes + rule aggregation 共同形成，
单一 veto 节点只能在预定义条件下阻止，
且不能单独批准、改写其他节点贡献、替换聚合规则，
```

则结构仍可保持 `xn`。

如果：

```text
一个中心可以对任意聚合结果自由否决，
并且还拥有最终采纳/批准/重开/改写权，
```

则向 `z` 收束。

若单一中心只有 universal negative veto、没有 positive authorization，则不能草率标 pure z；应先记：

```text
ASYMMETRIC_ENDPOINT_CONTROL
negative endpoint centralized
positive endpoint distributed
```

属于金轴混合/边界态，需要 rights ledger 分账，而不是把“有一票否决”四个字当分类器。

## 2｜strict 同层同窗最小差异对

固定工程场景：同一生产部署许可。固定 actor、object、object_layer、current_window、三个审核节点、2-of-3 聚合规则、材料、记录、部署版本，只改变安全节点 veto 的范围与是否拥有完整最终裁定。

### T0｜xn：受限安全 veto 只是规则内强 gate

```yaml

changed_variable: veto_scope_and_endpoint_control

relation_shape: distributed_rule_with_nonoverrideable_local_veto_condition
decision_right:
  reviewer_A: binding_vote
  reviewer_B: binding_vote
  security_gate: binding_security_check_and_veto_only_on_defined_failure
  chair: none
  positive_authorization: 2-of-3_plus_security_pass_rule
  negative_authorization: security_gate_can_block_only_if_defined_security_failure
path_set:
  - reviewer_A_vote
  - reviewer_B_vote
  - security_gate_result
  - threshold_rule

reality_anchor:
  - 安全节点只有在预定义安全条件失败时能阻止部署
  - 安全节点不能在安全条件通过时单独批准部署
  - 安全节点不能抹掉 A/B 的 binding contribution
  - 安全节点不能把 2-of-3 改成自己说了算
```

判定：

```text
xn PASS 0.96
z FAIL 0.93
```

这里的 veto 是分布规则中的强节点，不是完整最高裁定点。

### T1｜边界态：单一节点拥有 universal negative veto，但无单独批准权

保持人员、规则、材料、窗口不变，只改变安全负责人：即使所有条件通过、2-of-3 达标，也可不受条件约束地单方面否决；但其不能单独批准一个未达阈值的版本。

```yaml
actor: same_system
object: same
object_layer: same
current_window: same
changed_variable: veto_scope_and_endpoint_control
relation_source: distributed_positive_formation_plus_single_universal_negative_veto
relation_shape: asymmetric_endpoint_control
decision_right:
  reviewers: distributed_binding_contributions
  security_head: universal_negative_veto_only
  positive_authorization: distributed_rule
  negative_authorization: single_center_unilateral
path_set:
  - distributed_votes
  - aggregation_rule
  - universal_negative_veto
reentry_right: security_head_may_block_current_round; new_round_requires_revision_or_reopen
future_endpoint: approval_requires_distributed_rule_and_no_veto; rejection_can_be_single_center
reality_anchor:
  - 负责人可在任意票型下单方面阻止部署
  - 负责人不能让一个未达阈值版本直接通过
  - 正向 endpoint 与负向 endpoint 的控制来源不对称
```

判定：

```text
pure xn: FAIL 0.88
pure z: INSUFFICIENT 0.84
result: METAL_ASYMMETRIC_ENDPOINT_SPLIT
```

原因：负向终止权已经集中，但正向成立权仍真实分布。若解释器必须二选一，会丢失关键权利结构。

在 T1 基础上只新增：安全负责人不仅能否决，还能在未达阈值时批准、忽略任意票、重开并改写本轮结果。

## 4｜最小判别式

```text
有 veto ≠ z
有 final 字样 ≠ z
```

最短判别门：

```text
bounded veto
+ cannot approve alone
+ cannot rewrite other binding contributions
+ cannot replace aggregation rule
→ 仍可为 xn
```

而：

```text
universal veto only
+ positive endpoint remains distributed
→ ASYMMETRIC_ENDPOINT_SPLIT
→ 不直接判 pure z
```

只有当：

```text
one center controls both acceptance/rejection
or can freely override the tested final state as a whole
→ z
```

## 5｜nearest-neighbor

- 同一 2-of-3 聚合
- 同一日志
- 同一时间窗

```text

```

```text

```

说明“否决范围”和“完整最终裁定”是两个不同变量，不能用一个 `veto=true` 布尔值吞掉。

## 6｜removal test

### 从 T0 拿掉安全节点的职位名称

只保留一个匿名规则节点：检测条件失败则阻止。

```text
结构仍为 xn。
```

说明“安全负责人/总监”身份不产生 z。

### 从 T1 拿掉 universal veto

恢复为条件化 veto：

```text
split -> xn
```

### 从 T2 拿掉 positive authorization 与 aggregate override

只剩 universal negative veto：

```text
z -> asymmetric split
```

这证明 pure z 的关键不是“能说不”，而是 tested final state 是否整体收束到该中心。

## 9｜positive / negative controls

### positive control｜xn

三个独立服务都必须通过自动健康检查；任一服务检测失败会阻止部署，但没有哪个服务可以在其他服务失败时单独批准，也没有人能覆盖检查结果。

```text
→ xn PASS
```

### positive control｜z

董事长可以无条件批准或否决任一投资案，并可忽略委员会票型；委员会输出不具有不可覆盖 binding effect。

```text
→ z PASS
```

### negative control｜假 z

合规节点在“法律条件未满足”时必须阻止执行，但条件满足时不能自行批准，且其他节点仍有独立不可替代的 binding contribution。

```text
有 veto
但不是 full final adjudicator
→ 不判 z
```

### negative control｜假 xn

五个部门都有检查流程，但任何结果都可由一个负责人无条件批准、否决、改写。

```text
节点很多
但 tested final state 全部归一个中心
→ z
```

## 11｜失败类型

- `ANY_VETO_AS_Z`：看到一个否决权就直接判 z。
- `VETO_WORD_AS_FINAL_CENTER`：把“一票否决/终止”措辞当成最高中心证据。
- `NEGATIVE_ENDPOINT_AS_WHOLE_STATE`：能阻止结果，被误写成能决定整个结果。
- `BOUND_RULE_GATE_AS_FREE_CENTER`：预定义条件 gate 被误判为自由裁定者。
- `POSITIVE_AUTHORIZATION_IGNORED`：只检查谁能否决，不检查谁能让结果成立。
- `ASYMMETRIC_CONTROL_FORCED_BINARY`：正向分布、负向集中仍强塞 pure xn 或 pure z。
- `MANY_NODES_HIDE_FULL_OVERRIDE`：节点众多掩盖一个中心对全状态的批准/否决/覆盖权。
- `ROLE_NAME_AS_AUTHORITY_SCOPE`：根据“董事长/安全负责人/主任”等职位名倒推权限范围。

## 12｜本轮裁定与成熟度

本轮形成新机制、新边界和新 guard，具备提交价值。

新增关键结论：

> 金轴不能只问“有没有最终否决权”，必须把正向 endpoint 与负向 endpoint 分账。单一、受限、规则内 veto 可以完全属于 xn 结构；单一 universal negative veto 会使负向终点集中，但若正向成立权仍分布，则应先标 `METAL_ASYMMETRIC_ENDPOINT_SPLIT`，不能直接升格 pure z。只有 tested final state 作为整体被一个中心自由批准/否决/覆盖时，才形成强 z。

成熟度建议：

```text
8.4 -> 8.8 / 10
```
