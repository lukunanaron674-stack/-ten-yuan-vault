# 十元语义解释器｜nz vs zn：当前独立资格与离开后对象特异回返分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮目标与翻译债务

目标混淆对：`nz vs zn`。

current canonical 中：

- `zn`：自己成立，同时实际保存他者作为独立对象继续成立；
- `nz`：对象特异的回返、修复与重新连接路径被保存或恢复。

高风险自然语言包括：“我永远给你留位置”“我不会取消你的资格”“你随时可以回来”“你一直有自己的位置”“即使离开也还是你的”“我保留你的席位”。

这些句子共享一个“保留”表面词，但可能指向两个完全不同的变量：

1. **当前资格仍在**：other 现在仍处于 same-layer，并保有独立 decision right / endpoint；
2. **离开后的回返资格仍在**：other 已真实离开当前关系，但原对象特异位置仍可恢复。

现有研究已经分别处理 `zn` 的 independent endpoint preservation 与 `nz` 的 caller history / reentry right，但尚未把“当前仍在场”与“已经离场后仍可返回”压成一个强制时态门。因此本轮新增候选规则：

`CURRENT-ELIGIBILITY-vs-POST-EXIT-RECOVERABILITY-v0.1`

以及强制审计：

```text
RELATION-PHASE_AUDIT_REQUIRED
PRESENT-ENDPOINT-vs-REENTRY-RIGHT_AUDIT_REQUIRED

currently-inside + independent endpoint preserved
!=
actually-exited + same-object reentry preserved
```

核心纪律：**“留位置”不是十元证据，必须先确定对象当前还在不在关系内。**

## 2｜自然语言 → Semantic IR 结构还原规则

固定字段不变，新增字段值约束：

1. `actor`：明确谁维持当前独立资格，或谁/什么结构维持离开后的回返资格；不要把 returning party 与 boundary maintainer 混写。
2. `object`：`zn` 写当前仍成立的 other independent endpoint；`nz` 写离开后可恢复的原对象特异关系/原资格。
3. `object_layer`：强制区分 `current_independent_endpoint_layer` 与 `post_exit_object_specific_reentry_layer`。
4. `current_window`：`zn` 必须覆盖“双方当前仍在关系内/同层并存”；`nz` 必须覆盖“原关系内 -> 真实离开/分离 -> 回返资格仍可执行或实际恢复”。
5. `changed_variable`：`zn` 优先 `independent_endpoint_preservation`；`nz` 优先 `object_specific_reentry_space` / `recoverability_after_exit`。
6. `relation_source`：记录资格边界来自 shared constitution / bilateral rule / standing relationship boundary / unknown；来源名本身不产标签。
7. `relation_shape`：`zn` 优先 `coexisting-independent-endpoints`；`nz` 优先 `inside_then_exit_then_same-relation-reentry`。
8. `decision_right`：`zn` 必须写 other 当前在 same layer 的独立决定资格；`nz` 必须写 former participant 离开后是否拥有可执行 reentry right，不能拿“当前不被干涉”冒充。
9. `path_set`：`zn` 至少含 `self_path + other_current_independent_path`；`nz` 至少含 `exit_path + same_object_reentry_path`。不能拿同一条“保留资格”路径同时充两边证据。
10. `reentry_right`：`zn` 若当前没有离开/回返事实，保持 `null/unknown`；不得因为“以后欢迎回来”而臆造 recoverable。`nz` 必须明确其对象、期限、条件与是否需要逐次第三方重批。
11. `future_endpoint`：若离开后回返窗口会失效可填写；`zn` 的当前独立资格不因未来可能离开而自动拥有 nz endpoint。
12. `reality_anchor`：`zn` 证明 other 现在就能现实拒绝、选择、继续自身路线；`nz` 证明退出后原资格仍能现实恢复，而不是获得一个同类新资格。

### 新 IR 约束 A｜RELATION-PHASE AUDIT

```text
RP1 tested object 当前仍在关系内吗？
RP2 若仍在：优先检查 current independent endpoint，不得凭未来假设补 nz。
RP3 若已离开：当前独立 endpoint 是否已经停止生效？若是，不得继续用旧 zn 状态。
RP4 离开是否真实发生，而非暂时缺席、休假、暂停操作、内部换组？
RP5 回返后恢复的是原对象特异关系，还是同类新关系？
RP6 一句话同时描述当前独立权与离开后回返权时，必须 SPLIT_IR。
```

### 新 IR 约束 B｜PRESENCE RIGHT != REENTRY RIGHT

```text
current independent decision right
!=
post-exit reentry right

not removable while present
!=
recoverable after exit
```

这条约束直接解决“不会取消你资格”被解释器同时判成 zn+nz 的重复贴标问题。

## 3｜标准输入与完整 IR

输入：

> “联合工作室里，林澈和周宁当前各自拥有一条产品线。只要周宁仍是成员，林澈就不能改掉周宁的选题、撤她的预算或取消她的发布资格，周宁也能拒绝林澈的跨线修改。章程另有一条退出规则：成员主动退出后，原产品线资格暂停但保留九十天；九十天内本人可以恢复原产品线，不需要重新竞聘，也不需要另一位负责人逐次批准。周宁本月仍在组，因此她当前的选题权有效；如果下月主动退出，才会进入九十天回返窗口。”

必须拆成两个 IR。

### IR-A｜zn：当前独立资格层

```yaml
actor: 林澈
object: 周宁商业产品线当前独立选题与继续成立资格
object_layer: current_independent_endpoint_layer
current_window: 周宁当前仍是成员 -> 双方产品线并存 -> 周宁当前可拒绝跨线修改
changed_variable: independent_endpoint_preservation
relation_source: shared_constitutional_boundary
relation_shape: coexisting-independent-endpoints
decision_right: self_on_self_route + other_current_final_on_other_route
path_set:
  - self_path: 林澈继续决定自己的产品线
  - other_current_independent_path: 周宁当前决定自己的选题、预算与发布
reentry_right: null
future_endpoint: null
reality_anchor: 周宁当前仍在组并可现实拒绝林澈改题，林澈不能单方取消其同层资格
```

判定：`zn candidate PASS`；`nz` 不得仅凭“未来退出可回来”倒灌到当前 tested window。

### IR-B｜nz：退出后对象特异回返层

```yaml
actor: 联合工作室章程所维持的成员关系
object: 周宁退出后可恢复的原商业产品线资格
object_layer: post_exit_object_specific_reentry_layer
current_window: 当前成员 -> 主动退出 -> 原资格暂停并保留90天 -> 原本人可恢复原产品线
changed_variable: recoverability_after_exit
relation_source: standing_membership_reentry_rule
relation_shape: inside_then_exit_then_same-relation-reentry
decision_right: former_member_direct_reentry_within_90_days
path_set:
  - voluntary_exit
  - suspend_but_retain_original_line_eligibility
  - direct_restore_same_product_line
reentry_right: executable_to_same_object_specific_relation_within_90_days
future_endpoint: reentry_window_expires_after_90_days
reality_anchor: 退出后无需重新竞聘或逐次特批即可恢复原产品线，而不是申请一条新的同类产品线
```

判定：`nz candidate PASS`。

这两个 PASS 可以在同一制度中并存，但只能通过不同 `current_window + object_layer` 的两个 IR 成立。

## 4｜Positive decision gates

### zn candidate gate

```text
ZN1 tested party 当前仍处于 same-layer 关系内；
ZN2 actor/self endpoint 当前可辨认并继续成立；
ZN3 other endpoint 当前可辨认且拥有同层独立 decision_right；
ZN4 path_set 至少包含 self_path + other_current_independent_path；
ZN5 actor 无法把 other 当前资格任意吸收、撤销或改写；
ZN6 other 的当前存活不是 actor 本来无权、完全无关或纯静默造成；
ZN7 reality_anchor 证明 other 当前就能现实选择、拒绝、继续；
ZN8 即便文本提到未来可回来，若当前没有离开 phase，不得用其替代 ZN1-ZN7。
```

### nz candidate gate

```text
NZ1 returning party 可证明曾属于 tested object-specific relation；
NZ2 current_window 含真实 exit/separation；
NZ3 离开后 current eligibility 已暂停/终止，不能把“仍然一直在里面”当作回返；
NZ4 reentry_right 指向原对象特异资格，而非同类新资格；
NZ5 path_set 至少包含 exit_path + same_object_reentry_path；
NZ6 回返资格现实可执行，不是纯口头欢迎或每次重新特批；
NZ7 reality_anchor 证明退出后仍能恢复原关系；
NZ8 current zn 强不推出 nz；必须独立证明 post-exit recoverability。
```

## 5｜nearest-neighbor 最小差异

### nz vs zn

```text
zn：你现在还在这里，而且你当前自己的 endpoint 仍然属于你。
nz：你真的离开这里以后，还能不能回到原来的对象特异位置？
```

最小对照：

- “你当前永远不能被我改题，但一旦退出就永久失去资格” → `zn PASS / nz FAIL`。
- “你在岗期间一切由主管决定，但离职30天内可直接恢复原席位” → 当前 `zn FAIL/弱 / nz PASS`。

### zn vs x

`zn` 保存 other 当前独立资格；`x` 将对象纳入主体掌握/调用/处分边界。允许 other 当前使用一项可随时撤回的资源，不等于 zn。

### nz vs xz

`nz` 查离开后是否保有对象特异回返空间；`xz` 查 same-layer 的退路、时间窗和现实选项是否持续收窄。九十天窗口本身可在不同分析层产生“剩余时间减少”的 xz 研究，但不得因此把 nz 的回返资格改写成 xz；必须按 tested variable 分账。

## 6｜False-positive guards

1. “永远给你留位置”只触发 phase/reentry 抽取，不直接产 nz 或 zn。
2. “我不会取消你的资格”若只是当前在岗保护，不能自动补 nz。
3. “你随时可以回来”若从未证明曾经属于该对象关系，不能补 nz。
4. 当前 other 拥有独立权，不等于退出后仍有同一资格。
5. 退出后能申请同类新岗位，不等于 nz。
6. 每次回来都必须由 actor 重新批准，不得只因最终成功回来锁 stable nz。
7. 休假、临时离席、暂停操作但成员资格始终未中断，不足以构成 nz 所需 exit phase。
8. actor 当前无法改 other 的决定，若只是因为本来不同层无权，不得锁 zn。
9. 历史上有 zn 不得续贴到已退出后的 current window；历史上有 nz 回返条款也不得补当前 independent decision right。
10. `zn FAIL` 不推出 `nz`；`nz FAIL` 也不推出 `zn`。
11. 题材、职业、身份、情绪、颜色、胜负、悲惨程度都不得倒推两端。
12. “保留”是自然语言表面词，必须拆成 current eligibility preservation 与 post-exit recoverability 两种结构值。

## 7｜Removal / reverse / same-layer / current-window

### Removal A｜去掉当前独立资格保护

保留“退出90天内可回原位置”，但在岗期间主管可随时改题、撤预算、取消发布资格。

预期：

```text
zn ↓ / FAIL
nz 保持
```

### Removal B｜去掉退出后回返资格

保留在岗期间双方互不能撤销对方同层资格，但主动退出即永久终止原资格。

预期：

```text
zn 保持
nz ↓ / FAIL
```

### Reverse

- 保留“给你留位置”字样，但把退出后规则改成从零竞聘：`nz` 必须下降。
- 保留“你有自己的位置”字样，但允许 actor 当前单方撤销 other 的题材、预算和发布权：`zn` 必须下降。

### Same-layer

当前项目选题独立权与退出后成员回返权通常不是同一个时态层。即使 object 名称相同，只要 `relation phase` 不同，也不得共用一个 IR 双贴。

### Current-window

```text
while-present window -> 检查 zn
post-exit window -> 检查 nz
```

历史标签禁止跨 phase 继承。

## 8｜Adversarial tests

### ADV-1｜关键词诱导

“这个位置永远给你留着。”没有说明当事人当前是否仍在关系内、是否有独立决定权、是否发生过离开、回来是否可执行。

预期：`zn UNKNOWN/FAIL`；`nz UNKNOWN/FAIL`。

### ADV-2｜题材/职业/情绪诱导

“温柔的老船长说每个船员永远有自己的位置。”实际上船员航行时所有决定由船长单方下达，离船后也必须重新招募。

预期：不得因温柔、船长、忠诚氛围倒推；`zn FAIL/弱`，`nz FAIL`。

### ADV-3｜对象层错位

“研究员当前拥有独立课题选择权；离职后只能恢复旧邮箱账号，不能恢复原课题资格。”

预期：课题层可查 `zn PASS`；邮箱 reentry 不能拿来补课题层 `nz`。

### ADV-4｜时间窗错位

“去年成员退出后30天可恢复原席位；今年规则已取消。她今年仍在岗并保有独立选题权。”

预期：当前 `zn PASS`；旧 `nz` 不得继承到今年。

### ADV-5｜同关系词异对象层

“公司给你保留位置。”A 指当前董事席位不能被创始人单方取消；B 指离职60天内可恢复原员工账号。

预期：A 查 `zn` 当前 endpoint；B 查 `nz` account reentry；不得因同一句“保留位置”合并。

### ADV-6｜对端不存在不等于本端成立

“项目已经解散，所有成员资格终止，也没有回返机制。”

预期：`zn FAIL`；`nz FAIL`。一端不存在不推出另一端。

### ADV-7｜当前独立强、回返弱

“两位合伙人在职时各自拥有不可被对方单方撤销的产品线；任何一人退出即永久失去该产品线。”

预期：`zn PASS / nz FAIL`。

### ADV-8｜回返强、当前独立弱

“部门经理在岗时可随时改助理的任务与账号权限；助理若主动离职，30天内却可直接恢复原职位，无需重新招聘。”

预期：tested assistant current endpoint `zn FAIL/弱`；`nz PASS`。

### ADV-9｜休假伪 nz

“成员休假两周，账号和成员资格始终有效，回来后继续工作。”

预期：没有真实 exit，不能仅凭‘回来’判 nz；若当前独立 endpoint 有证据则另查 zn。

### ADV-10｜新对象伪 nz

“设计师辞职后半年，通过绿色通道加入同公司另一个新项目组。”

预期：回到同公司不等于恢复原对象特异位置；原项目 `nz FAIL`。

### ADV-11｜当前保护名称伪 zn

“制度名叫‘独立席位保护’，但负责人可随时撤题、收预算、冻结发布；离开后90天内倒是可以恢复原席位。”

预期：名称不产 zn；`zn FAIL / nz PASS`。

### ADV-12｜最小 mutation：冻结对象，仅切 relation phase

冻结：`actor / object / relation_source`。

Mutation A：

```text
current_window = currently_inside
other current decision_right = independent
reentry_right = none after exit
```

预期：`zn ↑ / nz ↓`。

Mutation B：

```text
current_window = exited
current decision_right = inactive
reentry_right = executable to same original relation
```

预期：`zn ↓ / nz ↑`。

本测试用于证明：同一 actor、同一 object、同一制度来源，仅改变 relation phase 与 right type，就应发生十元翻转；若解释器仍因“保留资格”词面维持同标签，则翻译失败。

## 9｜新增状态迁移规则

### CURRENT-ENDPOINT STATE｜服务 zn

```text
current relation absent
→ currently present but revocable
→ currently protected independent endpoint
→ independently exercised in same layer
= zn ↑
```

### REENTRY STATE｜服务 nz

```text
currently inside
→ actual exit / relation suspension
→ original position remains recoverable
→ same-object reentry executed
= nz ↑
```

关键不变量：

```text
current independent endpoint != post-exit recoverability
zn ↑ != nz ↑
nz ↑ != zn ↑
```

允许状态迁移：

```text
zn(current while present)
→ exit event
→ current zn endpoint stops being active
→ nz reentry state becomes testable
→ successful same-object reentry
→ zn may become testable again in the new current window
```

这不是“zn 自动转 nz 再自动转 zn”，而是 **relation phase 改变后，解释器切换 tested variable**。

## 10｜成功门判定

本轮不是重复已有机制，新增了：

1. `RELATION-PHASE_AUDIT_REQUIRED`；
2. `PRESENT-ENDPOINT-vs-REENTRY-RIGHT_AUDIT_REQUIRED`；
3. `presence right != reentry right` 的 IR 字段值约束；
4. while-present / post-exit 两个 current_window positive gate；
5. “当前独立强、退出即永久失效”与“当前独立弱、退出后可恢复”两组 nearest-neighbor negatives；
6. relation phase 最小 mutation；
7. `zn -> exit -> nz testable -> reentry -> zn testable again` 的阶段切换规则。

因此本轮满足成功门：`PASS`。

## 12｜下一轮最高翻译风险候选

本轮使用 `nz / zn`，下一轮不得继续使用两者。

当前最高候选：`n vs xn`。

高风险语言：

> “我负责把这件事一直运转下去 / 我每天维护它 / 我建立机制保证它不断。”

需要继续拆：

```text
n:
对象留下产生的现实负荷由谁持续承担？

xn:
主体是否主动生成了跨阶段、可重复调用的运行结构？
```

核心下一步可审计变量：`load_bearer + mechanism_author + path_set_semantic_type + current_window`。
