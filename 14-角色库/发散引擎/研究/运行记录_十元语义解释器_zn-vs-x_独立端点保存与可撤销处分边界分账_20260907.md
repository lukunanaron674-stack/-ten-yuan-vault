# 十元语义解释器｜zn vs x：独立端点保存与可撤销处分边界分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1. 翻译债务

上一轮已把 `zn` 的解释器候选门收紧为：self endpoint 与 other independent endpoint 必须在 same object_layer + current_window 内都真实继续成立，且他者存活不能只是主体没注意、没能力阻止或纯粹不干涉。

当前最高风险是自然语言里的“保护你、给你资源、给你位置、允许你继续、我替你保管”会把两种结构揉成一团：

- `zn`：主体自身成立时，他者仍作为独立对象拥有自己的成立资格/路径；
- `x`：对象、资源、权限或关系进入主体现实掌握/调用/处分边界。

因此新增解释器规则 `INDEPENDENT-ENDPOINT-vs-DISPOSITION-BOUNDARY-v0.1`：

```text
benefit_to_other / protection / permission / resource_grant
只触发 IR 提取，不能直接推出 zn。

若 tested object 仍可由 actor 单方撤回、调配、排除、替换或重新分配，
优先在该 object_layer 检查 x；
只有当 other 的独立成立路径在同层真实保留，且不被吸收到 actor 的单方处分权里，
才允许 zn candidate-positive。
```

## 2. 自然语言 → IR 结构还原规则

禁止从“保护、允许、给、照顾、托付、自由”直接贴标签。按固定 IR 字段还原：

1. `actor`：当前被判主体。
2. `object`：必须锁定到底是“资源/钥匙/预算/岗位/权限”，还是“他者自身选择、身份、创作、发展资格”。
3. `object_layer`：资源处分层与独立资格层必须拆开；同一句可 `SPLIT_IR`。
4. `current_window`：只取授权/保存/撤回现实在线的窗口；历史赠与或旧保护不得永久延续。
5. `changed_variable`：优先写 `disposition_scope`、`independent_endpoint_preservation`、`revocability_state` 或 `unknown`。
6. `relation_source`：self / external / shared / unknown；“我给你的”不自动等于 `self` 对所有更高对象层拥有权利。
7. `relation_shape`：revocable-allocation / non-revocable-independent-boundary / shared-control / tolerated-use / unknown。
8. `decision_right`：明确谁能对 tested object 做最终撤回、改配、排除、替换；另行记录谁对自身端点拥有决定资格。
9. `path_set`：x 层列主体可现实调用/处分的路径；zn 层至少列 `self_path + other_independent_path`。
10. `reentry_right`：被撤回后，他者能否自行恢复，还是必须重新获得 actor 许可。该字段对区分“暂时给你用”与“你自己仍独立成立”尤其关键。
11. `future_endpoint`：文本未锁长期终局时保持 null/unknown。
12. `reality_anchor`：x 看“actor 撤回/改配会现实改变 tested object 状态”；zn 看“actor 自身继续成立时，other 仍保有不被 actor 单方吞并的独立路径”。

### 新 IR 约束：处分权优先审计

```text
当文本出现“给他资源/给他位置/允许他继续”时：
先问 tested object 是否仍处于 actor 的 unilateral disposition boundary。

若 answer = yes：
  不能仅凭 benefit/protection 推 zn；
  该 object_layer 优先查 x / x-scope。

若 answer = no，且 other endpoint 有独立 decision_right + path_set + reality_anchor：
  才进入 zn candidate gate。
```

这不是新增 canonical 字段，只是用现有 `object_layer / decision_right / path_set / reentry_right / reality_anchor` 防止“给予行为”把 x 和 zn 混写。

## 3. 标准输入与完整 IR

输入：

> “馆长坚持展馆只展当代艺术的策展标准；合同同时保证驻场艺术家可以独立决定自己作品的主题、署名和是否发表，馆长不能改稿或代替撤稿。馆长另外把一间工作室的钥匙和每月材料额度交给艺术家使用，但这些资源仍可由馆长按馆务需要随时收回或调给别的项目。”

该句必须拆成两个 object_layer。

### IR-A｜独立资格层

```yaml
actor: 馆长
object: 馆方策展标准与艺术家自身创作/发表资格的并行成立
object_layer: 策展标准与艺术家自身创作决定资格层
current_window: 馆长维持当代艺术策展标准 -> 艺术家在合同边界内继续独立决定主题署名与发表
changed_variable: independent_endpoint_preservation
relation_source: shared_contractual_boundary
relation_shape: parallel-independent-endpoints
decision_right: self_on_curatorial_standard + other_on_own_creation
path_set:
  - self_path: 馆方策展标准继续有效
  - other_independent_path: 艺术家继续独立决定主题、署名、是否发表
reentry_right: artist_retains_direct_decision_on_own_creation
future_endpoint: null
reality_anchor: 馆长不能改稿或代替撤稿；馆方标准继续存在时，艺术家自身创作决定资格仍现实在线
```

判定：`zn candidate PASS`。

### IR-B｜资源处分层

```yaml
actor: 馆长
object: 工作室钥匙与每月材料额度
object_layer: 馆务资源使用与处分层
current_window: 资源交给艺术家使用 -> 馆长仍保留按馆务需要收回/调配能力
changed_variable: disposition_scope
relation_source: institutional_self
relation_shape: revocable-allocation-under-actor-disposition
decision_right: actor_final_on_resource_reallocation
path_set:
  - grant_use_access
  - revoke_key_access
  - reallocate_material_quota
reentry_right: external_permission_required_after_revocation
future_endpoint: null
reality_anchor: 馆长单方收回钥匙或调走材料即可现实改变艺术家的资源使用状态
```

判定：该资源层 `x candidate PASS`；不得因为资源“给艺术家使用”就把它直接翻译成 `zn`。

结论：同一自然语言可形成 `zn + x` 分层并存；两者判定对象不同，禁止把“保护/给予”当作十元标签本身。

## 4. Positive decision gates

### zn candidate gate

```text
ZN1 object_layer/current_window 明确；
ZN2 self endpoint 可辨认并继续成立；
ZN3 other endpoint 可辨认并继续成立；
ZN4 path_set 至少存在 self_path + other_independent_path；
ZN5 other 的独立 decision_right 不是 actor 临时借出的同层可任意撤销许可；
ZN6 actor 对自身 endpoint 的成立不要求把 other endpoint 吞入单一处分边界；
ZN7 reality_anchor 证明 actor 自身成立后，other 仍现实拥有其独立资格/路径；
ZN8 removal 保存边界后，other endpoint 出现现实缺口。
```

### x candidate gate

```text
X1 object/object_layer/current_window 明确；
X2 tested object 自然可识别，不靠 posthoc composite；
X3 actor 对该对象至少有一项现实占有/调用/调配/处分/否决/排除能力；
X4 path_set 中至少一条 actor-specific control path 已在线；
X5 decision_right / reentry_right 能说明对象并非仅偶然经过主体手中；
X6 actor 撤回、调配、排除或拒绝时，同层 object state 会现实改变；
X7 使用 ≠ 归属；受益 ≠ 独立资格；保护行为 ≠ 自动 zn。
```

## 5. nearest-neighbor 最小差异

### zn vs x

```text
zn: other endpoint 在 actor 自身成立时仍保有自己的独立成立资格。
x: tested object 进入 actor 的现实调用/处分边界。
```

最小差异：同一资源“交给别人使用”，若 actor 仍能单方收回/改配，该资源层更像 x；若 tested object 是“对方自身创作/身份/发展资格”，且 actor 没有同层单方吞并权，同时两端都有 reality_anchor，才查 zn。

### x vs nx

`x` 是关键对象/资源已经进入 actor 自身现实调用边界；`nx` 是关键许可/资源/解决接口仍需经外部 route 进入。`reentry_right` 是高价值分流字段：退出后能自行恢复调用，更偏 x；必须再次经外部节点许可，转查 nx。

### zn vs z

`zn` 保存 self + other independent endpoints；`z` 在可比 object_layer 内把竞争中心收束成 single final center。主体“保护某人”若最终仍能单方取消对方同层成立资格，不能仅凭善意描述判 zn。

## 6. false-positive guards

1. **保护词护栏**：“保护、照顾、庇护、给机会”只触发字段抽取，不触发 zn。
2. **资源给予护栏**：给钱、钥匙、岗位、账号、名额，不等于把对方变成独立 endpoint；先审 revocability/disposition。
3. **使用≠归属护栏**：他者当前能使用对象，不等于对象归他，也不等于 actor 的 x 消失。
4. **可撤销≠当前无权护栏**：资源可被上级未来撤回，不等于 actor 当前对其没有 x；必须看 current_window 的现实调用/处分权。
5. **不撤回≠不能撤回护栏**：actor 暂时没收回资源，不等于他者拥有独立资格；要区分未行使权力和不存在权力。
6. **受益对象≠独立对象护栏**：某行为对他者有利，不代表他者在 tested layer 获得 independent decision_right。
7. **对端不存在不等于本端成立**：x FAIL 不推出 zn；zn FAIL 也不推出 x。

## 7. removal / reverse / same-layer / current-window

### Removal

- zn：拿掉保护 other independent endpoint 的边界。如果 other 仍完全一样独立成立，则 actor-specific zn attribution 下降；如果立即失去自身决定资格/路径，保存关系有现实锚。
- x：拿掉 actor 的撤回/调配/排除路径。如果 actor 仍不能现实改变 tested object state，则原 x 证据下降。

### Reverse

- 保留“我保护你/给你资源”字样，却明确 actor 可随时单方收回并已实际重配：不得继续用保护词推 zn。
- 保留“资源可撤回”背景，但 current_window 内 actor 对资源没有任何调用/处分/否决能力：不得仅凭所有权或身份反推 current x。

### Same-layer

同一主体可以在“艺术家自身发表资格层”呈现 zn 候选，同时在“钥匙/材料资源层”呈现 x 候选。禁止跨层合并成“馆长既保护又掌控，所以 zn/x 都成立于整个关系”。

### Current-window

去年资源可随时收回，不代表今年新合同下仍 x；反之，未来可能被董事会撤权，也不代表 actor 当前窗口没有现实 x。zn 同样必须看当前 independent endpoint 是否仍在线。

## 8. adversarial tests

### T1｜关键词诱导
输入：“老板说‘我会保护你的创作自由’，但合同写明他可以随时改稿、撤稿、转让署名，而且当天已强制改稿。”
IR 摘要：object_layer=创作决定资格；decision_right=actor_final；other_independent_path 不存在。
预期：`zn FAIL`；保护词不得覆盖现实处分结构。

### T2｜题材/职业/情绪诱导
输入：“慈爱的院长每天照顾年轻研究员，但所有课题、署名和数据发布都只能由院长单方决定。”
IR 摘要：职业/慈爱情绪不入判定；tested research-right layer 为 actor-centralized disposition。
预期：`zn FAIL`；是否形成 x 另按对象和权限审计。

### T3｜对象层错位
输入：“父亲给成年女儿一套公寓居住，但产权与出售权仍在父亲；女儿的职业选择则完全由本人决定，父亲无权替她辞职或换岗。”
预期：房屋资产层可查父亲 `x`；职业选择资格层可查 `zn` 候选。禁止整段判一个标签。

### T4｜时间窗错位
输入：“去年公司给项目经理完整预算调配权；今年预算已收回总部统一审批，但他仍在旧介绍里被称为‘预算负责人’。”
预期：当前预算层旧 `x` 不得延续；title 不替代 current reality anchor。

### T5｜同关系词异对象层
A：“主管允许设计师使用公司摄影棚，但可随时取消预约。”
B：“主管允许设计师保留个人署名，且合同规定主管无权改署名。”
预期：同样“允许”，A 在摄影棚资源层优先查 x-scope/revocable allocation；B 在署名资格层才可能进入 zn gate。

### T6｜对端不存在不等于本端成立
输入：“他既没有控制这笔基金，也没有保障申请者继续独立使用；基金已被冻结，谁都不能动。”
IR：decision_right=unknown/none-in-window；path_set=[]；reality_anchor=global freeze。
预期：`x FAIL/UNKNOWN`，`zn FAIL/UNKNOWN`。不是 x 不成立就自动 zn。

### T7｜不撤回伪独立
输入：“过去一年馆长从未收回过艺术家的钥匙，但合同允许馆长无需理由随时收回，艺术家被收回后只能重新申请。”
预期：`不撤回 ≠ 独立 endpoint`；资源层仍保留 actor x 候选，不能凭长期善意判 zn。

### T8｜可撤销背景伪 x-negative
输入：“部门主管的设备调配权明年可能被总部撤销，但本季度他仍可直接分配、收回、禁用设备，无需再次审批。”
预期：当前窗口 `x candidate PASS`；未来可撤销不等于当前无权。

### T9｜受益伪 zn
输入：“领主开放粮仓赈灾，村民得到粮食，但领主仍可随时关闭粮仓，村民对粮仓没有独立决定权。”
预期：赈灾的善意/受益不推 zn；粮仓处分层优先查领主 x。

### T10｜保护边界真实独立
输入：“编辑坚持出版社的选题标准，但作者保留是否署名、是否接受改稿、是否撤回自己稿件的最终决定权；编辑不能代替作者作出这三项决定。”
预期：若 same-layer/current-window 与双端 reality_anchor 均成立，可进入 `zn candidate PASS`；不能因为出版社拥有出版资源就跨层抹掉作者自身决定资格。

## 9. 本轮新增翻译规则

新增候选规则：`INDEPENDENT-ENDPOINT-vs-DISPOSITION-BOUNDARY-v0.1`。

核心新增约束：

```text
benefit/protection/grant language
→ extract object_layer + decision_right + revocability through reentry_right + path_set
→ do not label yet

actor unilateral disposition on tested object
→ x gate first

other retains independent decision path on same tested layer
+ self endpoint remains
+ reality_anchor
→ zn gate

resource granted to other
≠ other independent endpoint
non-use of revocation
≠ absence of disposition right
future revocability
≠ current x off
```

该规则只属于解释器 L4/L5 research candidate，不修改 canonical。

## 10. 下一轮风险

优先检查 **x vs xz**：自然语言里的“还掌握着、还能重新拿回、暂时失去、永久失去、被收回但可重入”很容易把 `current possession/control` 与 `reentry_right / future return endpoint` 混写。下一轮应重点校准 `current_window`、`reentry_right` 与 `future_endpoint` 三字段，避免“现在没有 x”被错误翻译成 xz，或“未来可重新取得”被误写成当前 x。
