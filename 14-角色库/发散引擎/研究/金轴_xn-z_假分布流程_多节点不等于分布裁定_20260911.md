# 金轴 xn↔z｜假分布流程：多节点不等于分布裁定

> L4 research-only。只补强金轴判别门，不修改 L1/L2 canonical、信息卡、准度卡、正式关系卡或行为 evidence。

## 0｜本轮缺口

上一轮已建立 `BINDING-EFFECT-LOCUS-v0.1`：最后动作节点不等于最终裁定中心，必须追踪现实约束力真正从哪里产生。

本轮补另一侧误判：

> 流程里出现多个评审、步骤、记录、会议、审批、复核节点，不代表 `xn` 已成立。

如果这些节点只采集信息、搬运材料、形成建议或执行机械步骤，而不能独立改变同层运行/裁定状态，则它们只是表面多节点。若现实有效结果从头到尾仍只由一个中心决定，则该层不应因“流程很多”自动判 `xn`。

新增候选判据：

```text
EFFECTIVE-DISTRIBUTION-GATE-v0.1
```

核心问题：

> 多个节点是否各自拥有可观察、不可省略、对同层状态真实生效的局部判断/运行权？

若没有，只是输入汇聚到单一中心，则优先判“pseudo-distributed flow”，而不是 xn。

---

## 1｜研究层派生字段

在正式 Semantic IR 不变的前提下，增加研究审计字段：

```yaml
node_effect_map:
  node_A: informative_only | advisory | state_changing | binding_local
  node_B: informative_only | advisory | state_changing | binding_local
  node_C: informative_only | advisory | state_changing | binding_local
local_state_transition_right: 节点能否在不等待最高中心的情况下改变当前同层状态
skip_consequence: 跳过该节点是否会导致同层现实运行/裁定结果改变
parallel_substitutability: 其他节点能否无损替代该节点
binding_effect_source: distributed_rule | distributed_nodes | shared_vote | single_final_center | external_constraint
```

研究纪律：

```text
node_count ≠ authority_distribution
workflow_length ≠ xn
records_exist ≠ xn
```

必须证明“有效权力分布”，而不是“动作数量分布”。

## 2｜最小差异对

### A｜假分布流程：节点很多，但都只提供输入

输入：

> “三个评审依次阅读同一方案并填写意见表，秘书汇总记录，最终由主任一人决定方案是否通过。三个评审均无否决权、返工触发权或独立通过权，主任可以完全忽略他们的意见。”

IR：

```yaml
actor: 评审流程整体
object: 方案是否通过
object_layer: 当前轮方案裁定层
current_window: 三评审填意见 -> 秘书汇总 -> 主任决定
changed_variable: adjudication_center_distribution
relation_source: advisory_pipeline_to_single_center
relation_shape: multi_node_information_gathering_single_binding_center
decision_right: single_final_center_at_director
path_set:
  - reviewer_A_advice
  - reviewer_B_advice
  - reviewer_C_advice
  - director_final_decision
reentry_right: depends_on_director_decision
future_endpoint: pass_or_fail
reality_anchor: 评审节点不能独立改变方案资格；主任可忽略全部意见并直接决定
node_effect_map:
  reviewer_A: advisory
  reviewer_B: advisory
  reviewer_C: advisory
  secretary: informative_only
local_state_transition_right: false_for_reviewers
skip_consequence: one_reviewer_missing_does_not_change_binding_logic
parallel_substitutability: high
binding_effect_source: single_final_center
```

判定：

```text
xn FAIL at adjudication layer
z candidate PASS at director node
```

注意：并不是说整套流程不存在时间顺序，而是“当前 object_layer 的裁定重心并未分布”。

---

### B｜真 xn：节点各自能改变同层状态

只改一个核心变量：三个评审节点各自拥有不可被主任跳过的局部现实效力。

输入：

> “三个评审分别检查安全、预算、合规。任一节点发现对应硬性问题，都可直接把方案退回返工；只有三节点全部通过，方案才自动进入下一阶段。主任不能覆盖任何一个退回决定。”

IR：

```yaml
actor: 三节点评审系统
object: 方案能否继续推进
object_layer: 当前轮运行/筛选层
current_window: 安全审查 + 预算审查 + 合规审查 -> 全部通过后自动前进
changed_variable: decision_center_distribution
relation_source: distributed_non_overridable_local_gates
relation_shape: multi_node_binding_local_transitions
decision_right: distributed_across_three_gates
path_set:
  - safety_gate
  - budget_gate
  - compliance_gate
reentry_right: rework_after_any_gate_rejection
future_endpoint: next_stage_only_if_all_gates_pass
reality_anchor: 任一节点均可独立改变方案当前状态；无单一中心可覆盖
node_effect_map:
  safety: binding_local
  budget: binding_local
  compliance: binding_local
local_state_transition_right: true
skip_consequence: skipping_any_gate_changes_validity_of_progression
parallel_substitutability: low
binding_effect_source: distributed_nodes
```

判定：`xn candidate PASS`，置信度 0.97。

### 最小差异

```text
A：节点只产生信息，不能独立改变当前同层状态
→ pseudo-distributed flow
→ xn FAIL

B：节点各自拥有不可被单一中心覆盖的局部状态改变权
→ effective authority genuinely distributed
→ xn PASS
```

真正区分变量：

```text
local_state_transition_right
+ skip_consequence
+ binding_effect_source
```

## 3｜removal test

### 对 A

拿掉任一评审，只要主任仍可在剩余信息基础上直接决定：

```text
裁定结构本身不变
→ xn 不成立
```

拿掉全部评审，如果主任仍然具有同样通过/否决权：

```text
说明 binding-effect locus 原本就没有分布
```

### 对 B

拿掉安全节点后，系统无法合法完成原先“三门全过”的推进逻辑：

```text
同层运行结构出现现实缺口
→ 支持 xn
```

这不是“人数少了”，而是一个真实局部状态门被删除。

---

## 4｜reverse test

保留全部词面：

```text
“多部门”
“多步骤”
“复核”
“记录”
“流程”
```

但所有节点均仅提建议，最高中心可无条件覆盖：

```text
xn 必须 FAIL
```

反过来，删除“流程、记录、多部门”等关键词，只保留：

> “A/B/C 三个独立门均可单独阻止对象进入下一状态，且任何单一节点都不能覆盖其他门。”

则：

```text
xn 仍应 PASS
```

因此流程词不是 xn 的必要条件，也不是充分条件。

## 5｜freeze-third-factor

冻结以下条件：

- 节点数 = 3
- 顺序不变
- 都有记录
- 都产生意见
- 最终输出仍是通过/不通过
- 同一 actor/object/object_layer/current_window

只改变：

```text
各节点是否拥有 local_state_transition_right
以及最高中心是否拥有 unilateral_override
```

若判定稳定从 `xn FAIL / z candidate` 转为 `xn PASS / single-final-center消失`，则支持本门。

## 6｜正反控制

### Positive control｜工程门禁

一个发布流水线包含测试、签名校验、依赖检查三个强制门；任一门失败都直接阻止进入发布状态，且没有单一负责人能跳过。

预期：当前运行层 `xn PASS`。

### Negative control 1｜咨询委员会

多个专家分别给意见，但 CEO 可完全忽略，项目状态只由 CEO 一人改变。

预期：专家节点不构成 xn；CEO 节点查 z。

### Negative control 2｜流水线搬运

文件依次经过登记、扫描、归档、转发四个节点，但这些节点都不改变裁定状态，最后仍由同一裁定者决定。

预期：不能因多步骤判 xn。

### Negative control 3｜重复确认

三个节点都只能确认“已收到”，没有任何一个能拒绝、返工、暂停、改判或改变对象当前资格。

预期：`xn FAIL`。

## 7｜nearest-neighbor

### xn vs z

```text
xn：多个规则/节点分别拥有真实、不可省略的局部运行或判断效力。
z：同层现实有效性最终依赖单一可覆盖竞争判断的最高中心。
```

### xn vs nx

多节点沿既有外部方向执行，不等于 xn。若每个节点只是服从同一个外部方向、不拥有局部状态改变权，应查 nx/执行层，而不是因为“多人接力”判 xn。

### xn vs x并z

多个公开接口不等于多个运行裁定节点。`x并z` 看第三方能否经公共壳调用内部对象；`xn` 看同层运行/判断效力是否真实分布。

## 8｜失败类型

新增候选失败标签：

```text
FALSE_DISTRIBUTED_FLOW_NODE_COUNT
```

触发：模型因为流程节点多、部门多、步骤多就判 xn，但节点无 local_state_transition_right。

```text
INFORMATION_FLOW_AS_AUTHORITY_DISTRIBUTION
```

触发：把意见、数据、记录的分布误写成裁定权/运行权分布。

```text
SERIAL_EXECUTION_AS_XN
```

触发：机械串行执行被误判为 xn；实际同层权力仍集中。

```text
OVERRIDABLE_GATE_FALSE_XN
```

触发：所谓“门”可被一个最高中心无条件跳过，却仍被计为分布裁定节点。

## 9｜本轮最小判别式

```text
xn 不问“有几个节点”，先问：

这些节点中，是否至少存在多个节点能够在不等待单一最高中心的情况下，独立改变同一 object_layer 的当前现实状态？

有，并且这些局部效力不可被一个中心无条件覆盖
→ xn candidate PASS。

没有，节点只是采集信息、记录、建议、搬运或机械执行；真正 binding-effect locus 始终只有一个中心
→ pseudo-distributed flow，xn FAIL，转查 z。
```

压缩：

```text
many nodes ≠ distributed authority
binding local transitions + non-overridability = xn gate
```

## 10｜本轮结论

本轮建立 `EFFECTIVE-DISTRIBUTION-GATE-v0.1`，补上金轴另一侧的反误判门：

```text
上一轮：final action ≠ final center
本轮：many nodes ≠ distributed authority
```

两者合起来，当前金轴解释器研究层可以先追踪 `binding_effect_source`，再判断重心是：

```text
distributed across binding local nodes → xn
single final binding center → z
```

而不再依赖“流程/最终/签字/委员会”等词面。

## 下一断点

下一轮优先推进 `strict xn↔z 同层同窗对照`：在完全相同 actor/object/object_layer/current_window 下，只通过“是否允许单一中心覆盖局部门”这一变量，验证 `xn → z` 的最小结构迁移，并检查是否可形成 `distributed→final-center` 的生命周期判据。
