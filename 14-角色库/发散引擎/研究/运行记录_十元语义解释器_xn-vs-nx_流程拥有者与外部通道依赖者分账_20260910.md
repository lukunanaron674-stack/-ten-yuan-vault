# 十元语义解释器｜xn vs nx｜流程拥有者与外部通道依赖者分账

> research-only。只服务 `自然语言 -> Ten-Yuan Semantic IR -> 十元判定 -> Z 发散器`。current canonical 永远高于本记录。

## 0. 本轮选择与去重

上一轮为 `z vs nz`，本轮避开 z/nz。仓库已有 xn/nx 的 canonical 最近邻说明，但未发现独立 `xn-vs-nx` Semantic IR 分账运行记录。本轮不重复“主动排程=xn / 跟着别人=nx”口号，而新增 **process owner / route-dependent participant 的主体角色分账与 counterfactual ownership audit**。

## 1. 翻译债务

高危句型：

- “这件事必须走他们的流程。”
- “我负责把这个审批流程跑完。”
- “系统要求先登记再复核，所以我是 xn。”
- “他自己排了很多步骤，所以不是 nx。”

这些句子容易把两件事混成一个变量：

```text
流程结构是谁建立、维护、可重排？
!=
当前 tested actor 是否必须沿一个外部既有流程/权限通道行动？
```

同一事件可同时出现：

```text
平台方：xn
申请人：nx
```

也可同一 actor 分层：

```text
上游许可层：nx
下游执行组织层：xn
```

## 2. 新增自然语言 -> IR 规则

### PROCESS-OWNERSHIP-vs-ROUTE-DEPENDENCY-v0.1

新增强制审计：

```text
PROCESS-OWNER_AUDIT_REQUIRED
ROUTE-DEPENDENT-ACTOR_AUDIT_REQUIRED
REDESIGN-RIGHT_AUDIT_REQUIRED
EXTERNAL-GATE-REMOVAL_AUDIT_REQUIRED
```

结构还原顺序：

1. `actor`：先确定当前被判主体。系统/机构与流程参与者不得默认同一 actor。
2. `object`：xn 的对象优先写“运行结构”；nx 的对象优先写“当前需推进事项”。
3. `object_layer`：至少区分 `process_ownership_and_operation_layer` 与 `external_route_dependency_layer`。
4. `current_window`：分别截取流程重复运行窗口与 actor 实际受外部通道约束窗口。
5. `changed_variable`：禁止写泛化 `process` / `procedure` / `responsibility`；继续拆成 `operational_state_structure` 或 `current_external_route_dependency`。
6. `relation_source`：xn 要说明结构由谁生成/维护；nx 要说明方向、许可、关系或通道来自谁。
7. `relation_shape`：xn 记录 node/handoff/retry/record topology；nx 记录 actor -> external route/gate -> action result。
8. `decision_right`：新增 **redesign right** 审计。能执行流程节点不等于能改流程；能在流程内自行排局部步骤也不等于拥有上游通道。
9. `path_set`：xn path_set 只装运行节点/边；nx path_set 只装 actor 当前沿用的外部方向/权限/关系通路。不得混装。
10. `reentry_right`：流程 retry 与 actor 重新取得外部许可分账。
11. `future_endpoint`：局部办事默认 null/unknown；不得由“必须走流程”倒推长期人物归向。
12. `reality_anchor`：xn 要证明结构真实重复运行；nx 要证明外部 gate 的允许/拒绝真实改变 actor 本次推进。

### 新 IR 不变量

```text
can execute process step
!=
can redesign process topology

has local scheduling freedom
!=
owns upstream direction/permission route

process exists
!=
tested actor is xn

actor passes through process
!=
tested actor is nx
```

最后一条很重要：若 actor 本来就拥有直接资格，只是依法使用统一入口，不能只因“走流程”判 nx；必须证明外部方向/权限/解决通道确实不属于 actor 且能现实卡住当前事项。

## 3. 标准输入

> 市科研平台规定，外部课题申请必须依次经过登记、材料校验、伦理复核、预算核验和发布许可；失败任务会按固定规则退回指定节点，平台运营组维护节点、修改规则并持续记录每次状态。研究员林澈要发布自己的实验数据时，本人无最终发布许可，必须进入这套既有流程；伦理委员会若拒绝，他不能绕过该节点发布。但获得许可后，林澈可以自己安排数据清洗、图表制作和具体发布时间。

必须 SPLIT_IR。

## 4. 完整 IR-A｜xn

```yaml
actor: 市科研平台运营组
object: 外部课题与数据发布申请的持续处理结构
object_layer: process_ownership_and_operation_layer
current_window: 登记 -> 材料校验 -> 伦理复核 -> 预算核验 -> 发布许可；失败按规则退回；跨申请重复运行
changed_variable: operational_state_structure_and_process_topology
relation_source: actor_generated_and_maintained_workflow
relation_shape: named_nodes_with_rule_based_handoff_retry_record_and_maintenance
decision_right: actor_can_maintain_and_authorized_roles_can_redesign_process_topology_within_governance_scope
path_set:
  - registration_node
  - material_validation_node
  - ethics_review_node
  - budget_check_node
  - release_permission_node
  - retry_edges_to_named_nodes
  - state_recording
reentry_right: workflow_retry_to_named_node
future_endpoint: request_passes_release_permission_or_remains_in_rule_based_retry_or_terminates
reality_anchor: 平台运营组持续维护节点、状态记录和退回规则，多批申请真实重复经过同一结构
```

判定：`xn PASS`。

## 5. 完整 IR-B｜nx

```yaml
actor: 林澈
object: 当前实验数据获得合法发布资格并完成发布
object_layer: external_route_dependency_layer
current_window: 产生发布需求 -> 进入既有平台流程 -> 伦理节点审查 -> 获得发布许可 -> 自主安排下游制作与发布时间
changed_variable: current_external_permission_route_dependency
relation_source: institutionally_existing_review_and_release_authority
relation_shape: tested_actor_without_final_release_authority_to_external_mandatory_gate_to_current_action
 decision_right: actor_has_no_final_release_permission_right_but_has_local_downstream_execution_freedom
path_set:
  - submit_to_existing_platform
  - pass_material_validation
  - obtain_ethics_clearance
  - obtain_release_permission
reentry_right: denied_request_must_reenter_through_rule_defined_route_if_resubmission_is_allowed
future_endpoint: current_release_completes_after_binding_permission
reality_anchor: 伦理委员会拒绝时林澈不能绕过节点发布；获批后才恢复发布路径
```

判定：`nx PASS` at 上游许可层。

注意：林澈获批后主动安排数据清洗、图表制作、发布时间，可另建 **下游执行组织层 xn IR**；这不删除上游 nx。

## 6. Positive decision gate

### xn gate

```text
G1 actor 与 process object 明确；
G2 object_layer = 运行结构拥有/组织层；
G3 存在至少两个可区分 node/阶段/记录/顺序/资源安排元素；
G4 actor 对这些元素存在主动组织、维护或授权范围内重排能力；
G5 结构跨一次性动作形成重复/持续运行；
G6 reality_anchor 证明现实任务真实经过该结构；
G7 仅仅遵守别人流程，不得通过。
```

### nx gate

```text
G1 tested actor 与 current action object 明确；
G2 external direction / permission / route 至少一项在 current_window 真实激活；
G3 actor 在 tested layer 不拥有对应 final direction / permission / route ownership；
G4 actor 实际沿该既有通道推进；
G5 external gate removal/denial 会造成同层可命名推进缺口；
G6 actor 下游拥有局部排程自由，不足以否掉上游 nx；
G7 仅仅使用自己本来就有直接资格的标准入口，不得自动通过。
```

## 7. Nearest-neighbor 最小差异

### 差异 A｜同一流程，不同 actor

```text
运营组设计、维护、重排审批节点
→ xn

申请人不能改节点，只能沿节点取得许可
→ nx candidate
```

### 差异 B｜同一 actor，不同层

```text
老板定“必须发布A”，我无权改A/B，只能沿法务许可推进
→ 上游方向/许可层 nx

拿到许可后，我自己排测试、清洗、发布时间与回滚节点
→ 下游运行组织层 xn
```

### 差异 C｜标准入口不等于 nx

```text
本人依法拥有直接申报资格
+ 法律规定所有人统一从官网提交
+ 没有额外他者自由许可
→ 流程可属于系统 xn
→ 使用者不因“走流程”自动 nx
```

## 8. False-positive guards

```text
“有流程” != xn
“走流程” != nx
“我负责跑流程” != xn
“审批很多层” != xn
“我自己安排几个步骤” != 上游 nx 消失
“系统不让绕过” != actor 一定 nx，先查 actor 是否本就拥有 direct standing qualification
“流程属于公司” != 公司每个员工都是 xn
“员工很主动” != zx / xn 自动成立
xn FAIL != nx PASS
nx FAIL != xn PASS
```

## 9. Removal / reverse / same-layer / current-window

### Removal A

删除平台运营组的流程维护/改版权，把节点改为外部监管固定不可改，但申请人仍必须走这些节点：

```text
平台运营组 xn ↓ / 重审
林澈 nx 可保持
```

### Removal B

保留整套审批流程，但赋予林澈对该类数据的直接 standing release authority，可自行发布而无需伦理节点许可：

```text
系统层 xn 保持
林澈该许可层 nx ↓
```

### Reverse

把“林澈必须随外部许可走”反转为“林澈可以最终决定是否发布，外部节点只提供建议”：

```text
原许可层 nx ↓
是否转 zx/z/x 另审，不自动补标签
```

把“运营组可维护重排流程”反转为“运营组仅按监管机关给定 SOP 点按钮”：

```text
该运营组 xn ↓
外部给定流程仍可存在
```

### Same-layer

```text
process_ownership_and_operation_layer
!=
external_route_dependency_layer
!=
downstream_local_execution_organization_layer
```

### Current-window

去年拥有流程改版权、今年仅执行旧 SOP，不得继承去年 xn；去年必须求人获批、今年已有 standing authority，也不得继承去年 nx。

## 10. Adversarial tests

1. **关键词诱导**：“这事流程复杂，我负责把流程跑完。”无流程 ownership、无外部 gate 事实 → `NEEDS_MORE_STRUCTURE`。
2. **题材/职业/情绪诱导**：冷酷法官在雨夜处理十级审批，申请人很绝望 → 不凭职业/情绪判 xn/nx。
3. **对象层错位**：医院 IT 组维护预约流程；医生本人靠院长特批借设备 → 预约系统查 xn，设备事项查 nx，禁止混 IR。
4. **时间窗错位**：去年员工无发布权限必须层层审批，今年已获得 standing release authority，但旧平台仍在 → 当前员工 nx 不继承；系统 xn 可保持。
5. **同关系词异对象层**：“走流程”一处指平台内部 retry，一处指员工必须借法务许可 → relation_shape/path_set 分账。
6. **对端不存在不等于本端成立**：既无人主动维护流程，申请人也没有任何外部许可依赖，只是手工一次性办事 → xn/nx 均 FAIL/UNKNOWN。
7. 公司有成熟五步 SOP，但负责人只能机械执行、无维护/重排权；该负责人不因职位判 xn。
8. 申请人必须用统一官网，但其资格由法律直接赋予、系统仅机械校验；不因 mandatory entry 自动 nx。
9. 员工无上游方向权，必须按老板 A 方向推进，但获批后自己搭建复杂执行计划 → 上游 nx + 下游 xn，强制 SPLIT_IR。
10. 平台运营组主动把一次性人工审批改成可重复节点、记录、retry，并持续维护 → xn evidence ↑；参与者是否 nx 另审。
11. 外部委员会删除自由否决权，只保留信息登记；actor 已有直接发布资格 → 原许可层 nx ↓，但流程存在不消失。
12. **最小 mutation**：A“我只能沿别人给定流程跑，但不能改流程”改成 B“目标仍由别人给，但我可设计/维护整套执行流程”；必须重新抽取 IR，预期 B 可出现 `上游 nx + 下游 xn`，不得二选一。

## 11. 状态迁移

### xn

```text
one_time_steps
-> actor_orders_steps
-> named_nodes/records/retry
-> actor_maintains_or_restructures
-> repeated_operational_structure
= xn ↑
```

### nx

```text
self-sufficient_on_tested_layer
-> external_direction_or_permission_needed
-> actor_follows_existing_route
-> gate_owner_can_enable_or_block_current_action
= nx ↑
```

二轨不变量：

```text
xn ↑ != nx ↓
nx ↑ != xn ↓
```

## 12. Gate-registry compatibility note

最新 main 已出现 `semantic_ir_gate_registry_v0.1`，其 production/pending gate 只能引用注册的 Semantic IR 字段，且 null/unknown 不得作为正证据，必须保留 provenance。本记录因此只提出基于固定 12 字段的候选门，不把“职业、情绪、流程、主动”等表面词作为未来 gate predicate。

若未来编译，本轮候选至少应继续要求 `actor/object_layer/current_window/relation_source/relation_shape/decision_right/path_set/reality_anchor` 的结构证据；本记录本身保持 `candidate`，不得直接进入 production registry。

## 13. 成功门结论

本轮不是重复 canonical 的“xn 主动安排 / nx 跟着走”，而新增以下可检验资产：

1. `PROCESS-OWNER_AUDIT_REQUIRED`：流程参与者与流程拥有/维护者强制分主体；
2. `REDESIGN-RIGHT_AUDIT_REQUIRED`：执行节点能力不得冒充流程组织权；
3. `standard mandatory entry != nx`：只有外部 direction/permission/route ownership 对当前 action 形成真实依赖才进入 nx positive；
4. 同一 actor 的 `上游 nx / 下游 xn` 强制 layer split；
5. 两组独立 counterfactual removal，可用于未来回归测试。

结论：PASS，存在新翻译规则、IR 约束、adversarial negatives 与状态迁移约束，允许提交。
