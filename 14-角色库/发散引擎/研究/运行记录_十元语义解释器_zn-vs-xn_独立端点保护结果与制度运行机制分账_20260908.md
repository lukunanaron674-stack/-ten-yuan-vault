# 十元语义解释器｜zn vs xn：独立端点保护结果与制度运行机制分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1. 本轮目标与翻译债务

目标混淆对：`zn vs xn`。

当前高风险自然语言包括：“建立制度保障每个人独立发展”“设计流程让成员自己决定”“设规则保护创作者自主权”“我制定机制避免互相干涉”。表面上同一句话既有“制度/规则/流程”的 `xn` 词形，又有“独立/自主/不干涉”的 `zn` 词形，模型很容易把制度目的、制度形式和制度实际结果压成一个标签。

current canonical 所测变量不同：

- `zn`：actor 自身继续成立，同时 other 作为独立对象的同层决定资格/成立路径被现实保存；
- `xn`：actor 主动组织时间、顺序、规则、记录、节点、分工或资源，使行动形成跨阶段可持续运行结构。

因此本轮新增候选规则：

`PROTECTED-ENDPOINT-vs-ENABLING-MECHANISM-v0.1`

以及强制审计：

```text
MECHANISM-OUTPUT-SEPARATION_AUDIT_REQUIRED
EFFECT_BEARER_AUDIT_REQUIRED

制度/流程“长什么样” -> 只说明 mechanism morphology
制度/流程“现实改变了谁的什么变量” -> 才决定 tested output layer

procedure-shaped mechanism != xn automatically
independence-themed purpose != zn automatically
```

关键新增：解释器必须区分 **mechanism carrier** 与 **effect bearer**。

```text
mechanism carrier = 规则、轮次、记录、否决节点、预算隔离、复核程序等运行装置
effect bearer = 被这些装置实际改变/保存的对象层变量
```

若 tested object 是“制度本身怎样跨阶段运行”，查 `xn`；若 tested object 是“他者独立 endpoint 是否因此现实保存”，查 `zn`。一句自然语言可能需要 `SPLIT_IR`，两端可同时 PASS，但理由不能共用。

## 2. 自然语言 → Semantic IR 结构还原规则

固定先抽 IR，再判十元：

1. `actor`：明确谁建立/维持机制，或谁处在被测独立关系中；一句话角色不同必须拆 IR。
2. `object`：若查 xn，写“运行方式/制度流程”；若查 zn，写“other 的独立决定资格/成立路径”。不得用“这套制度”同时充两边 object。
3. `object_layer`：强制区分 `mechanism_operation_layer` 与 `independent_endpoint_layer`。
4. `current_window`：只取制度真实运行与 endpoint 真实被保存的当前窗口；纸面制度未启用不算当前 xn，历史保护关系也不算当前 zn。
5. `changed_variable`：优先填写 `operational_coordination_structure` 或 `independent_endpoint_preservation`；若只知道“有制度”则 unknown。
6. `relation_source`：xn 追机制是否 actor-generated/shared-generated/external-given；zn 追保护边界来自 shared boundary、actor-maintained boundary 或其他现实约束。
7. `relation_shape`：xn 优先 `ad_hoc_to_repeatable_structure`、`multi_stage_rule_cycle`；zn 优先 `self-plus-other-independent`、`protected_separate_endpoints`。
8. `decision_right`：必须写明“谁对流程设计有权”以及“谁对各自 endpoint 有最终权”。`workflow_design_right` 不能拿来充 `other_on_other_route`。
9. `path_set`：xn 的 path 应是 procedure elements；zn 的 path 至少要能辨认 `self_path + other_independent_path`。两种 path type 禁止混装。
10. `reentry_right`：只有涉及离开后重返才填写；不得因为制度有申诉/复核就自动解释为 nz。
11. `future_endpoint`：仅文本明确锁定终局时填写；“制度长期保护”不能臆造永久终点。
12. `reality_anchor`：xn 要证明机制跨阶段被现实调用；zn 要证明 other 的拒绝/选择/继续成立资格在现实中确实存活。

### 新 IR 约束 A：EFFECT_BEARER_AUDIT

在看到“制度保障 X”时必须分别回答：

```text
EB1 mechanism bearer 是什么？
EB2 mechanism 是否 current-window activated？
EB3 mechanism 直接改变的 tested variable 是流程拓扑，还是独立 endpoint 的存活？
EB4 若拿掉 mechanism，哪个变量先出现可命名缺口？
EB5 若只保留目的口号而删除现实路径，zn/xn 是否还成立？
```

### 新 IR 约束 B：PURPOSE-IMPLEMENTATION NON-INFERENCE

```text
“为了保障独立” -> 不推出 zn
“通过制度实现” -> 不推出 xn
```

目的陈述只进入 `relation_source/reality_anchor` 的待验证区，必须看到现实可执行结构或独立路径后才过 gate。

## 3. 标准输入与完整 IR

输入：

> “联合创作社原来每次发生题材冲突都靠临时争吵解决。负责人后来建立双轨章程：每月先登记各自项目线，预算分别记账，任何一方若要改动另一方的题材，必须经过对方本人同意；每月末还要复核一次两条项目线的预算和发布资格。制度连续运行了八个月。林澈仍决定实验动画线，周宁仍决定商业短片线，任何一方都不能单方撤销另一方的项目资格。”

必须拆两个 IR。

### IR-A｜xn：制度运行机制层

```yaml
actor: 联合创作社负责人
object: 双轨章程的持续运行方式
object_layer: mechanism_operation_layer
current_window: 临时争吵 -> 建立双轨章程 -> 连续八个月按月登记/记账/复核
changed_variable: operational_coordination_structure
relation_source: actor_generated
relation_shape: ad_hoc_conflict_to_repeatable_multi_stage_rule_cycle
decision_right: actor_on_mechanism_design_with_member_constraints
path_set:
  - monthly_project_registration
  - separate_budget_recording
  - consent_gate_for_cross-line_change
  - month_end_budget_and_release_review
reentry_right: null
future_endpoint: null
reality_anchor: 四类制度节点连续八个月被反复调用，冲突处理从临场争吵变成可重复运行结构
```

判定：`xn candidate PASS`。

理由是 actor 主动生成并维持跨阶段运行结构，不是因为制度“很尊重人”。

### IR-B｜zn：独立 endpoint 保存层

```yaml
actor: 林澈
object: 周宁商业短片线的独立决定与继续成立资格
object_layer: independent_endpoint_layer
current_window: 双轨制度运行期间 -> 双方项目线持续并存 -> 交叉改动需本人同意
changed_variable: independent_endpoint_preservation
relation_source: shared_constitutional_boundary
relation_shape: protected_separate_endpoints
decision_right: self_on_self_route + other_on_other_route
path_set:
  - self_path: 林澈继续决定实验动画线
  - other_independent_path: 周宁继续决定商业短片线并可拒绝跨线改动
reentry_right: null
future_endpoint: null
reality_anchor: 林澈不能单方撤销周宁题材、预算与发布资格，周宁的拒绝会现实阻断跨线改动
```

判定：`zn candidate PASS`。

理由是 other endpoint 被现实保存，不是因为存在月度表格或复核节点。

## 4. Positive decision gates

### zn candidate gate

```text
ZN1 object_layer 明确为 independent endpoint / same-layer autonomy；
ZN2 actor 自身 endpoint 可辨认且继续成立；
ZN3 other endpoint 可辨认并有现实 decision_right/path；
ZN4 path_set 至少包含 self_path + other_independent_path；
ZN5 存在现实 boundary，使 actor 不能把 other 的同层资格单方吸收/撤销；
ZN6 other endpoint 的存活不是因为 actor 从来无权、无关系、没注意或纯静默；
ZN7 reality_anchor 证明 other 可现实拒绝、选择、继续或运行；
ZN8 仅有“制度为了保护独立”的目的说明，不足以通过。
```

### xn candidate gate

```text
XN1 object_layer 明确为运行方式/程序拓扑；
XN2 relation_source 证明机制由 actor/shared actor 主动生成或重组，而不是纯外部不可改 SOP；
XN3 path_set 至少含两个不同类型的程序元素（顺序/节点/记录/复核/分工/资源配置）；
XN4 结构有 before -> after 差异，不是一直如此的背景；
XN5 current_window 内至少跨两个阶段/轮次现实调用；
XN6 decision_right 至少覆盖机制设计/重排，而不要求 actor 占每个 endpoint 的最终决定权；
XN7 removal 机制后，运行退回临场/不可重复/缺少同等协调路径；
XN8 仅有“有规则、有章程、有制度”而无实际运行，不足以通过。
```

## 5. nearest-neighbor 最小差异

### zn vs xn

```text
zn：制度运行以后，谁仍作为独立 endpoint 真实成立？
xn：制度本身如何被组织成跨阶段可重复运行结构？
```

最小测试：

- 删除月度登记/复核/记录，但保留简单、直接、现实有效的“双方互不能撤销对方项目资格”边界：`zn` 可保持，`xn` 明显下降。
- 保留复杂月度流程，但把所有最终选题权集中给负责人：`xn` 可保持，`zn` 明显下降。

### zn vs x

`zn` 保存 other 独立 endpoint；`x` 是对象进入 actor 的直接处分/调用边界。若负责人可随时撤掉他者预算，只是“平时允许自主”，优先不是稳定 zn。

### xn vs nx

`xn` 看 actor 是否生成本地运行结构；`nx` 看 actor 是否沿 external 已给定 route 推进。章程来自总部且负责人只能照表执行时，不能因流程复杂就把负责人判 xn。

## 6. false-positive guards

1. **独立词护栏**：“独立、自主、尊重、自己决定”只触发 IR 抽取，不直接产 zn。
2. **制度词护栏**：“制度、规则、章程、流程、机制”只触发 mechanism 抽取，不直接产 xn。
3. **目的护栏**：“为了保护自主”只描述 intended purpose，不证明 actual independent endpoint survived。
4. **纸面护栏**：章程存在但从未运行，不足以判 current xn。
5. **形式护栏**：流程很复杂但所有 endpoint 仍由一个人最终决定，不能用复杂度补 zn。
6. **结果护栏**：双方确实独立，但只靠一个简单不可单方撤销边界即可维持，不强迫补 xn。
7. **对象层护栏**：制度运行机制与成员独立资格必须拆 IR；procedure path 不能充 other_independent_path。
8. **职业/题材护栏**：民主组织、艺术家、合作社、学校、家庭、创作职业都不能倒推 zn/xn。
9. **时间窗护栏**：去年有效的保护制度若本月已废止，不继承旧 zn/xn。
10. **对端缺席护栏**：zn FAIL 不推出 xn；xn FAIL 不推出 zn。
11. **善意护栏**：负责人主观想保护别人但保留随时撤销权，不足以 stable zn。
12. **自动化护栏**：系统自动执行既有保护流程，不等于当前 tested actor 自己生成 xn。

## 7. removal / reverse / same-layer / current-window

### Removal

- `xn removal`：删除月度登记、分账、复核等程序节点，只保留双方不可单方撤销对方资格的简洁边界。若独立 endpoint 仍有效，则 `zn` 可保持而 `xn` 下降。
- `zn removal`：保留全部登记、记录、复核流程，但负责人获得随时改题、撤预算和取消发布资格的最终权。若流程照常运行而 other endpoint 不再独立，则 `xn` 可保持而 `zn` 下降。

### Reverse

- 保留“保护独立”的制度名称，但实际所有决定需负责人终审：`zn` 必须掉。
- 保留“完整章程”字样，但从未执行、无轮次、无记录、无节点现实调用：`xn` 必须掉。

### Same-layer

同一句“制度保障成员独立”至少包含两个候选层：

```text
制度如何运行 -> mechanism_operation_layer -> xn gate
成员是否仍独立成立 -> independent_endpoint_layer -> zn gate
```

禁止拿一个层的证据自动补另一个层。

### Current-window

- 过去八个月运行、本月制度已暂停：历史 xn 不续贴当前。
- 过去双方有独立否决权、本月章程已改为负责人单方终审：历史 zn 不续贴当前。

## 8. adversarial tests

### T1｜关键词诱导
输入：“公司发布《独立创作机制》，首页写‘每个人自主决定’，但所有题材仍须总监终审，机制也从未正式启用。”
- zn：FAIL；目的词与标题不能代替独立 endpoint。
- xn：FAIL；未运行的机制不能形成 current 运行结构。

### T2｜题材/职业/情绪诱导
输入：“一群自由艺术家彼此非常尊重，气氛温柔，但没有共同项目、共同边界或重复运行程序。”
- zn：不能因艺术家/尊重/温柔成立。
- xn：不能因合作题材成立。
- 预期：两端 FAIL/UNKNOWN。

### T3｜对象层错位
输入：“学校建立每周排课、请假、成绩复核流程；学生社团的选题仍由各社团自己决定，教务处不得撤销其题材。”
- 教务流程层：可查 xn。
- 社团选题独立层：可查 zn。
- 禁止把排课流程当作社团独立的直接证据。

### T4｜时间窗错位
输入：“去年双轨章程每月运行且双方互有否决权；今年章程停用，负责人单方决定全部项目。”
- 当前 xn：旧运行不能沿用。
- 当前 zn：旧独立 endpoint 不能沿用。

### T5｜同关系词异对象层
输入：“‘规则保护你自己决定’：规则要求每月四轮复核；同时规定你的项目只有你本人能最终改题。”
- “规则”作为程序拓扑 -> xn gate。
- “规则”作为 independent endpoint 边界 -> zn gate。
- 同一关系词不得共享同一个 IR object。

### T6｜对端不存在不等于本端成立
输入：“旧委员会解散后既没有保护各成员的独立资格，也没有任何新流程，所有事项暂时无人处理。”
- zn：FAIL/UNKNOWN。
- xn：FAIL/UNKNOWN。
- 一端不存在不推出另一端。

### T7｜复杂流程伪 zn
输入：“负责人设计十二步创作审批流程，每月稳定运行，但每一步最终都可被负责人覆盖，成员没有自己的最终项目资格。”
- xn：PASS candidate。
- zn：FAIL。

### T8｜简洁边界强 zn、弱 xn
输入：“两名合伙人只约定一条现实有效规则：任何一方都不能撤销另一方的项目和预算；没有月会、记录、复核或持续程序。”
- zn：若双方独立 endpoint 与现实拒绝权成立，可 PASS。
- xn：不能仅凭一条静态边界强判。

### T9｜纸面制度伪 xn
输入：“章程写了登记、预算隔离、月末复核，但从成立起没有执行过一次，现实仍靠临场争吵处理。”
- xn：FAIL。
- zn：是否成立另看双方 endpoint，不由纸面流程推出。

### T10｜善意伪 zn
输入：“负责人每天说要保护年轻作者独立创作，也给他们排完整周计划，但合同允许负责人随时取消作品和预算。”
- xn：若周计划由负责人生成并持续运行，可查 PASS。
- zn：FAIL/弱；善意目的不能覆盖可单方撤销结构。

### T11｜外部制度伪 actor-xn
输入：“总部下发完整双轨保护 SOP，地方主管不能修改，只负责照表执行；SOP 真实保护两组项目各自否决权。”
- tested local supervisor xn：FAIL/弱，relation_source 为 external-given。
- zn：若两组 endpoint 现实被保存，可在对应关系主体层另查。

### T12｜状态迁移
输入：“前两个月双方仅有口头互不干涉；第三个月开始建立登记、分账、复核并稳定运行；第五个月又把最终改题权集中给负责人。”
- 月1-2：不能仅凭口头互不干涉锁 zn；xn 弱。
- 月3-4：xn 上升；若双方真实拒绝权/独立 endpoint 同时成立，zn 上升。
- 月5：流程不变则 xn 可保持；集中最终改题权使 zn 下降。

## 9. 新状态迁移规则

本轮新增两条独立状态轨：

```text
MECHANISM_STATE:
ad_hoc
-> rule_defined_but_inactive
-> repeatably_executed_structure
= xn candidate 上升
```

```text
ENDPOINT_STATE:
tolerated_but_revocable
-> protected_by_real_boundary
-> independently_exercised
= zn candidate 上升
```

两条状态轨彼此独立：

```text
xn ↑ 不自动推出 zn ↑
zn ↑ 不自动推出 xn ↑
```

并新增跨层因果记录规范：如果某个 xn mechanism 现实促成/维护了 zn endpoint，只允许记录为 `mechanism -> effect` 的跨层因果，不允许把 mechanism 自己直接贴 zn，或把 effect 自己直接贴 xn。

## 10. 本轮成功门

本轮新增并通过以下翻译资产：

1. `PROTECTED-ENDPOINT-vs-ENABLING-MECHANISM-v0.1`；
2. `MECHANISM-OUTPUT-SEPARATION_AUDIT_REQUIRED`；
3. `EFFECT_BEARER_AUDIT_REQUIRED`；
4. `PURPOSE-IMPLEMENTATION NON-INFERENCE`；
5. procedure path 与 independent endpoint path 禁止混装；
6. 两条可独立迁移的 `MECHANISM_STATE / ENDPOINT_STATE`；
7. “复杂保护流程但最终权集中”与“简洁边界但真实独立”两类 adversarial negative/positive 对照。

因此本轮不是已有机制换皮，满足提交条件。

## 11. 下一轮风险候选

本轮使用 `zn / xn`，下一轮不得连续使用这两个十元。

当前建议优先检查：`nz vs x并z`。

高风险自然语言：“开放入口”“给你留门”“随时可以回来”“保留通道”。解释器需要进一步拆：

- `nz`：对象特异的现实回返/修复资格；
- `x并z`：第三方可稳定识别和调用的公共入口/外壳。

重点债务是“入口存在”到底是 **给原对象的回返权**，还是 **给公共第三方的寻址接口**，应继续用 `object_layer + caller_identity + reentry_right + path_set` 做分账。
