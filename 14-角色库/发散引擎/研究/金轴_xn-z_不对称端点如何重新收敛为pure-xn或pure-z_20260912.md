# 金轴｜不对称端点如何重新收敛为 pure xn 或 pure z

## 0｜本轮只解决一个问题

上一轮确认：正向成立权仍分布、但单一中心拥有 universal negative veto 时，不应强塞 pure xn / pure z，而应标记 `METAL_ASYMMETRIC_ENDPOINT_SPLIT`。

本轮只测试：这个 split 状态最小改变什么，才会重新收敛为 pure xn 或 pure z。

## 1｜current criterion

```text
xn = 运行权/判断权分布到顺序、规则、记录、节点与流程
z  = 判断权与结构重心收束到单一最高中心或最终裁定点
```

解释器必须分账：

```text
positive_authorization
negative_veto
aggregate_override
reopen_reset_right
final_adjudication
```

不能因为有 veto 就判 z，也不能因为有多人节点就判 xn。

## 3｜nearest-neighbor 最小差异

### S0｜不对称 split

```text
2-of-3 达标 -> 可形成 PASS
负责人 -> 可无条件单方面 FAIL
负责人不能单独形成 PASS
```

判定：

```text
pure xn: FAIL / insufficient
pure z: FAIL / insufficient
result: METAL_ASYMMETRIC_ENDPOINT_SPLIT
confidence: 0.96
```

### S1｜split -> pure xn

只删除一个权利：

```text
universal_negative_veto: ON -> OFF
```

负责人若仍可 veto，只能在预定义条件触发，且不能覆盖合法 aggregation output。

```text
PASS 由规则生成
FAIL 也由规则/绑定节点生成
无单一自由终止中心
```

判定：

```text
xn PASS 0.98
z FAIL 0.96
```

最小变化不是“增加更多节点”，而是：

```text
negative endpoint 从单中心自由控制
-> 回到规则约束的分布生成
```

### S2｜split -> pure z

保留 universal negative veto，只新增：

```text
positive_authorization: center_can_unilaterally_PASS = true
aggregate_override: center_can_override_vote_result = true
```

即同一中心可：

```text
想批就批
想否就否
必要时覆盖票型/阈值结果
```

判定：

```text
z PASS 0.99
xn FAIL 0.98
```

## 4｜最小判别式

```text
ASYMMETRIC SPLIT -> pure xn
= 收回单中心 universal endpoint control
+ PASS/FAIL 都回到绑定节点与规则
+ 无同层自由覆盖者
```

```text
ASYMMETRIC SPLIT -> pure z
= 同一中心取得 tested final state 两个方向的终止控制
+ 可独立形成 PASS 与 FAIL，或可自由覆盖聚合结果
```

关键变量：

```text
endpoint_control_symmetry
```

而不是：

```text
参与人数
流程长度
签字数量
职位名称
```

## 5｜removal test

### 对 S1

拿掉“负责人”这个职位名，只保留所有节点的真实权利，若所有 PASS/FAIL 都由规则和绑定节点生成，xn 仍成立。

### 对 S2

拿掉“CEO/主席/导演”等身份词，只保留“一个节点可自由批准、否决、覆盖聚合结果”，z 仍成立。

结论不依赖职业/身份。

## 6｜reverse test

```text
pure xn
+ 添加单中心 universal negative veto
-> asymmetric split
+ 再添加单中心 positive authorization / aggregate override
-> pure z
```

反向：

```text
pure z
- 删除单中心 positive authorization，但保留 universal negative veto
-> asymmetric split
- 再把 negative veto 约束回规则节点
-> pure xn
```

这形成连续状态机：

```text
PURE_XN
<-> ASYMMETRIC_ENDPOINT_SPLIT
<-> PURE_Z
```

## 7｜freeze-third-factor

冻结：

- 节点数量
- 人员身份
- 票数
- 流程步骤
- 项目风险
- 结果输赢
- 是否最终上线
- 情绪与组织文化

只改变：

```text
positive_authorization
negative_veto_scope
aggregate_override
```

判定随 endpoint control 改变而变化。

## 8｜positive / negative controls

### pure xn 正控

```text
3 个独立 binding 审核节点
2-of-3 直接决定 PASS/FAIL
任何单节点都不能自由覆盖
```

### pure z 正控

```text
委员会只提供输入
单一负责人可自由批准、否决、覆盖
```

### split 正控

```text
2-of-3 可形成 PASS
单一负责人可无条件否决
但不能单独批准
```

### negative control｜强 gate 不是 split

```text
安全节点只能在“检测失败”这一规则条件成立时阻止
条件满足后不能自由否决
也不能单独批准
```

仍是 xn 内的 bounded gate，不升 split。

## 9｜失败类型

```text
ANY_SINGLE_VETO_AS_SPLIT
= 任意局部/条件 veto 都误判为不对称 split

ASYMMETRIC_SPLIT_FORCED_TO_Z
= 负向终点集中但正向仍分布，却强塞 pure z

ASYMMETRIC_SPLIT_FORCED_TO_XN
= 只看到多人投票，忽略 universal negative center

POSITIVE_AUTHORIZATION_IGNORED
= 判 z 时只看否决，不检查单中心能否形成正向终点

AGGREGATE_OVERRIDE_IGNORED
= 单中心虽不能表面“直接批准”，但可任意翻转聚合结果，却仍判 xn

ROLE_NAME_AS_ENDPOINT_CONTROL
= 因 CEO/主席/导演名称直接推导最高裁定
```

## 10｜本轮裁定

```yaml
new_mechanism: endpoint_control_symmetry_gate
state_machine:
  - PURE_XN
  - METAL_ASYMMETRIC_ENDPOINT_SPLIT
  - PURE_Z
minimum_difference_verified: true
l1_change_required: false
sync_debt_created: false
maturity_effect: metal_closer_to_interpreter_ready
```

结论：

> 金轴不能只做二元标签。解释器应先构造 rights ledger，再根据正向 endpoint 与负向 endpoint 是否同源、是否存在同层自由覆盖，判 `PURE_XN / ASYMMETRIC_ENDPOINT_SPLIT / PURE_Z`。不对称态不是理论故障，而是案例层真实中间配置。

## 11｜下一断点

下一次金轴轮到时优先压：

```text
reopen_reset_right 是否足以改变 final adjudication 分类？
```

即某节点不能改变本轮 PASS/FAIL，却能无限重开、撤销或要求重审时，它是 xn 流程节点、z 的时间性最终中心，还是另一个独立 rights ledger 维度。
