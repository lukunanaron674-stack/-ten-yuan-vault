# 金轴 xn↔z｜最终动作节点与现实约束力来源分账

> L4 research-only。只补强金轴判别门，不修改 L1/L2 canonical、信息卡、准度卡、正式关系卡或行为 evidence。

## 0｜本轮缺口

已有 `DISTRIBUTED-RUN-vs-FINAL-CENTER-v0.1` 已经确认：

```text
xn：运行权/判断权分布到规则、顺序、记录、节点与流程。
z：判断权与结构重心收束到单一最高中心或最终裁定点。
```

但解释器仍有一个实际误判入口：

> 最后执行“签字、发布、宣告、盖章、发送、录入”的节点，常被误读为 final adjudication center。

真正缺少的是对 **“现实约束力从哪里产生”** 的追踪。

因此新增候选判据：

```text
BINDING-EFFECT-LOCUS-v0.1
```

核心不是“最后谁动作”，而是：

> 哪个节点的判断一旦成立，就使同层竞争判断失去继续产生有效结果的资格？

这个节点才可能进入 z gate。

---

## 1｜新增 IR 分账

在现有字段不变的前提下，研究层增加三个派生审计字段：

```yaml
binding_effect_source: unknown | distributed_rule | shared_vote | single_final_center | external_constraint
execution_right: 谁执行/发布/签署/录入结果
adjudication_right: 谁决定哪个同层结果有效
counterfactual_override: 执行节点能否在不重新经过原裁定结构的情况下改写最终结果
```

这三个字段是 research-only 派生字段，不修改当前正式 Semantic IR schema。

### 分账纪律

```text
execution_right ≠ adjudication_right
last_action_node ≠ final_adjudication_center
```

若某节点只能执行已经形成的决定：

```text
execution_right = yes
adjudication_right = no
counterfactual_override = no
```

则该节点本身不得因“最后动作”进入 z。

## 2｜最小差异对

### A｜假最高裁定点：最后签字，但无改判权

输入：

> “三名评审按规则分别评分，系统按预先设定阈值自动确定唯一通过方案。部门负责人最后必须在发布单上签字，但他不能改成别的方案，也不能否决系统已经生成的结果。”

IR：

```yaml
actor: 部门负责人
object: 唯一通过方案
object_layer: 最终结果生效层
current_window: 三评审评分 -> 系统按阈值生成结果 -> 负责人签字发布
changed_variable: adjudication_center_distribution
relation_source: procedural_execution_after_rule_result
relation_shape: distributed_input_rule_resolution_then_ceremonial_execution
decision_right: not_at_signer
path_set:
  - reviewer_A_score
  - reviewer_B_score
  - reviewer_C_score
  - threshold_rule
reentry_right: signer_cannot_reopen_same_round
future_endpoint: result_published
reality_anchor: 负责人签字前结果已由规则唯一确定；负责人不能改写或否决
binding_effect_source: distributed_rule
execution_right: signer_has_execution_only
adjudication_right: signer_none
counterfactual_override: no
```

判定：

```text
负责人：z FAIL
整体结构：优先检查 xn / rule-distributed structure
```

原因：现实约束力来自评分 + 阈值规则，不来自最后签字者。

---

### B｜真 z：最后签字者同时拥有改判/终止权

只改一个变量：负责人不再是被动签字者，而是拥有最终覆盖权。

输入：

> “三名评审按规则分别评分并给出建议。部门负责人可以在三个候选中任选一个作为唯一通过方案，也可以全部否决；他的签字一旦完成，其余候选立即退出本轮资格。”

IR：

```yaml
actor: 部门负责人
object: 唯一通过方案
object_layer: 最终结果生效层
current_window: 三评审建议 -> 负责人最终选择/否决 -> 其余候选退出
changed_variable: adjudication_center_distribution
relation_source: institutional_final_override
relation_shape: distributed_advice_to_single_binding_center
decision_right: single_final_center
path_set:
  - signer_final_selection
reentry_right: no_reentry_within_current_round
future_endpoint: one_or_zero_candidate_remains
reality_anchor: 负责人可覆盖评审建议；其决定直接改变本轮有效候选集合
binding_effect_source: single_final_center
execution_right: signer_yes
adjudication_right: signer_yes
counterfactual_override: yes
```

判定：`z candidate PASS`，置信度 0.97。

### 最小差异

```text
A：最后动作节点不能改写同层结果
→ 只是 execution node
→ z FAIL

B：最后动作节点能覆盖同层输入，并直接决定哪些结果仍有效
→ binding-effect locus = single final center
→ z PASS
```

真正决定 z 的变量不是“签字”，而是：

```text
counterfactual override / exclusion power
```

## 3｜removal test

### 对 A

拿掉负责人签字，假设系统仍可由另一个行政节点完成发布：

```text
最终方案内容不变
→ 负责人不是裁定中心
→ z 继续 FAIL
```

### 对 B

拿掉负责人最终覆盖权，只保留机械签字：

```text
唯一最终方案改由评审规则直接决定
→ z 从负责人节点消失
→ 结构回到 distributed/rule-based
```

这说明真正支撑 z 的不是动作顺序，而是排他裁定权。

---

## 4｜reverse test

保留全部词面：

```text
“最终”
“批准”
“签字”
“负责人”
```

但令负责人无权改写、否决、重开、替换结果。

结果：

```text
z 必须 FAIL
```

反过来，删除“最终、批准、签字”等所有关键词，只保留：

> “该节点一旦选中方案 B，A/C 立即失去本轮有效资格，任何其他节点都不能在本轮覆盖它。”

结果：

```text
z 仍应 PASS
```

因此关键词对 z 不是必要条件，也不是充分条件。

---

## 5｜freeze-third-factor

冻结以下条件不变：

- 候选数 = 3
- 评审人数 = 3
- 负责人身份不变
- 最后动作仍然是签字
- 发布结果仍唯一

只改变：

```text
负责人是否拥有 counterfactual_override
```

若判定随该变量稳定从 FAIL→PASS，则支持：

> `binding_effect_source` 比 `last_action_node` 更接近 z 的真实现实锚点。

## 6｜正反控制

### Positive control｜单一现实终止权

> 三个设计方案都完成评审，但总导演可直接指定其中一个进入成片，其他方案当场退出本轮制作资格，任何部门无权覆盖。

预期：`z PASS`。

### Negative control 1｜形式发布

> 总导演只是按制作委员会已通过的方案在发布文件上署名，不能改方案。

预期：总导演节点 `z FAIL`。

### Negative control 2｜自动规则唯一化

> 三套方案按预先固定权重自动计算总分，最高分直接进入生产，无人拥有改判权。

预期：不因“最后只剩一个方案”判 z；优先检查 rule-distributed / xn 结构。

### Negative control 3｜建议权

> 顾问只能建议采用方案 B，制作组可以完全不采纳。

预期：`z FAIL`。

## 7｜nearest-neighbor

### z vs xn

```text
xn：现实有效性由多个节点/规则/顺序共同持续产生。
z：现实有效性最终依赖一个可覆盖同层竞争判断的单一中心。
```

### z vs x

若节点只是拥有“对对象进行处分/调用”的权利，不等于它就是同层最终裁定中心。

```text
处分对象 ≠ 裁定哪个判断最终有效
```

### z vs zx

一个职位依法拥有最终裁定权，可以 z，但不自动 zx。

zx 仍需检查：主体是否自己生成并占据方向，并把该方向通过现实权能压入外部结构。

## 8｜失败类型

新增候选失败标签：

```text
FALSE_FINAL_CENTER_LAST_ACTION
```

触发条件：

```text
模型因为某节点最后签字/发布/盖章/宣告/录入，就把它判为 z；
但 counterfactual_override=no，且 binding_effect_source 位于规则、共享投票或其他节点。
```

辅助失败标签：

```text
EXECUTION_ADJUDICATION_COLLAPSE
```

表示解释器把 execution_right 与 adjudication_right 合并成一个字段理解。

---

## 9｜本轮最小判别式

```text
z 不问“谁最后做动作”，先问：

如果这个节点改成相反决定，现实结果能否在不重新经过原裁定结构的情况下被它直接改写？

能，并且它的决定会让同层竞争判断退出本轮有效位置
→ z candidate PASS。

不能，它只能执行/宣布/记录已经由别处产生的结果
→ 该节点 z FAIL。
```

可压缩为：

```text
final action ≠ final center
binding effect + override + exclusion = z gate
```

## 10｜本轮结论

本轮新增的不是更多 z 正例，而是一个解释器可执行的反误判门：

> **BINDING-EFFECT-LOCUS-v0.1：追踪现实约束力来源，并用 counterfactual override 区分执行节点与最高裁定中心。**

它补上现有 `decision_right` 的操作化缺口：过去知道“要看谁有最终裁定权”，现在进一步给出测试方法：

```text
让最后动作节点尝试反向改判：
能直接改写现实有效结果 → 可能 z；
不能，只能执行既定结果 → 不是该节点的 z。
```

## 下一断点

继续金轴时，优先验证另一侧误判：

> **假分布流程**：表面存在多个评审/步骤/记录节点，但所有节点都只能提供信息，真实 binding-effect locus 从始至终只有一个中心。此类结构不应因“多步骤”自动判 xn。
