# 土轴 n↔x并z｜自然语言对象指代不得自动升格父级：对象锚定先于判元 v0.1

> L4 research-only。只处理一个执行级缺口：自然语言里 parent system、child object、输入对象与公共壳常共享“它/这个服务/这个平台/这件事”等指代。若解释器在判元前先把 tested object 绑错层级，后续 per-object resolver 与 SPLIT_IR 即使正确也会建立在错误对象上。

## 0｜本轮唯一缺口

现有土轴已确认：

1. `n` 要证明外部对象进入内部并形成持续现实负荷；
2. `x并z` 要证明内部对象通过稳定公共壳被第三方持续识别、调用、归因、代表或进入；
3. 同句存在两条因果箭头时必须 SPLIT_IR；
4. shared shell 的对象可解析性必须逐 tested object 记账。

本轮补一个更前置的门：

```text
object anchoring
must precede
axis classification
```

即：

```text
parent-level public shell evidence
!= child-object x并z evidence

child-level carrying evidence
!= parent-object n evidence
```

尤其禁止自然语言主语或最近名词把证据自动“升格/降格”到错误 object layer。

新增：

```text
EARTH-OBJECT-ANCHOR-BEFORE-AXIS-GATE-v0.1
EARTH-NO-PARENT-CHILD-REFERENT-BACKFILL-v0.1
```

## 1｜最小自然语言压力测试

原句：

> 平台A把用户提交的故障单D接进来持续处理，它同时有一个公开状态页，用户可以一直查看这个服务的处理情况。

这句话至少包含四个候选 object token：

```text
A-system = 平台整体
D        = 故障单
S        = 内部故障处理服务
P        = 公开状态页/公共壳
```

危险点在“它”“这个服务”。如果解释器只按最近名词或主语延续，很容易得到错误 IR：

```text
D 有公开状态页
=> x并z(D)

A 接进D持续处理
=> n(A)
```

正确做法是先锚定 tested object，再收证据。

## 3｜两端判定

### S0｜对象锚定错误：把 parent shell 证据绑给 D

```text
n(D): PASS 0.99
x并z(A-system): PASS 0.98
x并z(D): FAIL / insufficient 0.99
x并z(S): insufficient until resolver proven 0.97
n(A-system): OFF / not evidenced 0.98
```

### S1｜只增加 S 的稳定对象级 resolver

例如：

```text
P/service/S -> same S
```

则：

```text
x并z(S): PASS 0.98
```

而：

```text
n(D): unchanged PASS
x并z(D): unchanged FAIL/insufficient
```

最小翻转变量不是“句子里出现公开页面”，而是：

```text
tested_object_anchor(S)
+
object_specific_resolver(S)
```

```text

```

结果：

```text

```

Pair B：

只增加：

```text
P/S -> stable same S
```

结果：

```text
x并z(S) PASS
```

Pair C：

只把自然语言改成：

> 用户可以查看故障单D的公开详情页，但该页只是平台展示副本，不能通过它重新进入D、补充D或把请求稳定送回D。

结果：

```text
public visibility(D) PASS
x并z(D) insufficient
```

说明 object token 正确也不能跳过既有 shell grounding/callability gate。

## 5｜Removal

### Removal A｜删除对象级锚定

若解释器把所有“它/这个服务”统一继承为最近 parent：

```text
per-object ledger loses meaning
```

因为 ledger key 本身已经错。

### Removal B｜保留对象锚定，删除 S resolver

```text
x并z(S) PASS -> insufficient
x并z(A-system) remains PASS
```

### Removal C｜删除 D 的持续处理

```text
n(D) PASS -> FAIL
x并z(A-system) unchanged
```

证明两条箭头不互补。

## 6｜Reverse

```text
ambiguous pronoun
-> explicit object anchor
-> correct parent/child split
```

仅此一步不必改变判元结果，但会阻止错误证据传播。

随后：

```text
S anchor + no resolver
-> x并z(S) insufficient

S anchor + stable resolver
-> x并z(S) PASS
```

反向撤销 resolver：

```text
x并z(S) PASS -> insufficient
```

而 parent `x并z(A-system)` 可继续成立。

## 8｜跨域正反控制

### Positive control｜工程

> 公司统一监控台公开显示整个系统健康状态；支付服务另有稳定 `/service/pay` 路由。

```text
x并z(system) PASS
x并z(payment-service) PASS
```

### Negative control｜工程

> 公司统一监控台公开显示系统健康，但搜索服务只是内部池中一个未公开节点。

```text
x并z(system) PASS
x并z(search-node) insufficient
```

### Positive control｜制度

> 政务大厅有统一入口，同时“许可证续期”有稳定事项编号与专属办理映射。

```text
x并z(hall/system) PASS
x并z(renewal-service) PASS
```

### Negative control｜组织

> 工作室公开账号稳定存在，内部三名画师混合发布且作品不署名、无个人入口。

```text
x并z(studio) PASS
x并z(individual-artist) insufficient
```

### Negative control｜承载方向

> 平台把投稿稿件M接入内部持续编辑。

```text
n(M) PASS
n(platform) not inferred
```

carrier 不是 inbound object。

## 9｜失败类型

新增执行级 failure：

```text
FAILURE_PARENT_OBJECT_PROMOTION
```

含义：parent/system 的公共壳证据被错误提升为当前 child tested object 的证据。

```text
FAILURE_CHILD_EVIDENCE_BACKFILLS_PARENT
```

含义：child 的承载或接口证据倒灌到 parent。

```text
FAILURE_PRONOUN_REFERENT_AS_AXIS_EVIDENCE
```

含义：解释器未先做对象消歧，仅凭“它/这个服务/该平台”等表面指代延续关系。

```text
FAILURE_CARRIER_AS_INBOUND_OBJECT
```

含义：因为“平台接进对象”，把 carrier 本身误判成 `n` 的被纳入对象。

## 11｜最小判别式

```text
先问：这条证据到底在说哪个对象？
再问：它跨边界的方向是什么？
最后才问：n 还是 x并z？
```

形式化：

```text
resolve(tested_object, object_layer)
-> bind(evidence, tested_object)
-> classify(bound_relation)
```

禁止：

```text
classify(sentence)
-> guess object afterward
```

## 12｜与旧研究的边界

本轮不是重复 `SPLIT_IR`：

- SPLIT_IR 解决“一句话有两条因果箭头时证据不得互倒”；
- 本轮解决“箭头拆对了，但箭头两端 object token 一开始就绑错了”。

本轮也不是重复 `per-object resolver ledger`：

- per-object ledger 假设 `tested_object_id` 已经正确；
- 本轮给它补前置条件：先把 object anchor 做对，否则 ledger 会精确地记录错误对象。

因此本轮有独立信息增益。
