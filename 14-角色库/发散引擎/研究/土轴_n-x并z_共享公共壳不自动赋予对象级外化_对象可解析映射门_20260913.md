# 土轴 n↔x并z｜共享公共壳不自动赋予对象级外化：对象可解析映射门 v0.1

> L4 research-only。只补解释器级边界，不修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮唯一缺口

既有土轴已经确认：

```text
x并z 需要 stable public shell/interface
且 shell 与 tested internal object 之间必须有真实 outward mapping causality。
```

但仍有一个未闭合风险：

> 如果一个稳定公共壳真实连接到内部，但它同时挂载多个内部对象，而第三方无法从该壳稳定解析“究竟是哪一个对象被识别、调用、归因、代表或进入”，能否把壳级 x并z 自动回填给每个内部对象？

本轮新增：

```text
EARTH-OBJECT-RESOLVABLE-SHELL-MAPPING-GATE-v0.1
```

核心纪律：

```text
shell_to_internal_system_grounding
!=
object_specific_resolvable_mapping
```

一个公共壳可以真实属于某系统/组织，但只要第三方无法稳定解析到 tested object，本轮就不能把“系统级外化”自动下放为“对象级 x并z”。

---

## 1｜current criterion 不变

```text
n     = 外 -> 内纳入真实承载并持续处理现实负荷
x并z  = 内 -> 外形成稳定公共壳/接口，使第三方可持续识别、调用、归因、代表或进入内部对象/关系/能力
```

本轮只细化 x并z 的对象级要求：

```text
stable public shell
+ causal grounding
+ object-specific resolvability
```

三者缺一，不能锁 tested object 的 x并z。

---

## 2｜完整 IR

最小案例：团队 A 对外只有一个稳定公共入口 `portal-A`，入口后同时连接内部服务 S1 与 S2。

### S0｜共享壳存在，但对象不可解析

```yaml
actor:
  internal_actor: 团队A
  third_party_user: 用户U

object:
  tested_object: 内部服务S1
  neighboring_object: 内部服务S2

object_layer:
  tested: S1_as_publicly_resolvable_internal_capability

current_window:
  portal-A稳定存在
  portal-A真实连接A内部
  但U无法稳定判断/指定/归因到S1还是S2

changed_variable:
  object_specific_resolvability: false

relation_source:
  internal_system_A
  -> grounded shared public shell portal-A
  -> ambiguous internal dispatch {S1,S2}

relation_shape:
  U
  -> portal-A
  -> A internal system
  -> unresolved {S1 or S2}

decision_right:
  A:
    controls internal dispatch
  U:
    can call portal-A
    cannot reliably select or identify S1

path_set:
  - portal-A
  - opaque_dispatch

reentry_right:
  U can repeatedly call portal-A
  but cannot repeatedly return to S1 specifically

future_endpoint:
  stable system-level public access

reality_anchor:
  - portal-A真实稳定存在
  - A承认并维护portal-A
  - 请求真实进入A
  - S1与S2都可能承接
  - U无法稳定识别/指定/归因到S1
  - 删除S1后portal-A仍可继续由S2工作
```

判定：

```text
x并z(A-system): PASS 0.98
x并z(S1): FAIL / insufficient 0.96
n(S1): OFF / not evidenced 0.97
```

### S1｜增加对象级稳定解析

冻结 portal-A、A、S1、S2、请求类型、第三方群体，只增加：

```text
stable route / object id / explicit mapping
portal-A/S1 -> S1
```

```yaml
changed_variable:
  object_specific_resolvability: false -> true

relation_source:
  S1
  -> maintained object-specific mapping
  -> portal-A/S1

relation_shape:
  U
  -> portal-A/S1
  -> S1

reentry_right:
  U can repeatedly identify/call/attribute S1 specifically

reality_anchor:
  - S1有稳定对象标识
  - 第三方能重复定位同一S1
  - 请求与归因不会在S1/S2之间随机漂移
```

判定：

```text
x并z(S1): PASS 0.98
n(S1): OFF / not evidenced 0.97
```

真正 changed variable 是：

```text
object_specific_resolvability
```

不是：

```text
public_shell_exists
```

```text
系统功能

```

```text
第三方能否从同一公共壳稳定解析到S1
```

```text
portal-A -> opaque {S1,S2}
=> x并z(A-system) PASS
=> x并z(S1) insufficient
```

Pair 1：

```text
portal-A/S1 -> stable S1
=> x并z(S1) PASS
```

## 4｜removal

### Removal A｜拿掉 object id

保留公共壳与内部接线，但让 S1/S2 再次不可区分：

```text
x并z(S1) PASS -> insufficient
x并z(A-system) remains PASS
```

### Removal B｜拿掉 shell causal grounding

即使保留一个写着“S1”的外部标签，如果请求/归因不真实接回S1：

```text
x并z(S1) FAIL
```

说明对象可解析性不能替代 causal grounding。

## 5｜reverse

```text
shared grounded shell
+ opaque internal dispatch
=> system-level x并z only

+ stable object-specific resolver
=> object-level x并z ON
```

反向删除 resolver：

```text
object-level x并z ON -> insufficient
system-level x并z may remain ON
```

因此：

```text
higher-level shell persistence
!=
child-object x并z persistence
```

## 7｜positive / negative controls

### Positive control A｜工程域

同一 API Gateway 承载多个服务，但 `/service/s1` 稳定映射到 S1，第三方可重复调用和归因 S1：

```text
x并z(S1) PASS
```

### Negative control A｜工程域

统一入口只写“提交请求”，内部随机派给 S1/S2，用户无法选择或识别具体服务：

```text
x并z(system) PASS
x并z(S1) insufficient
```

### Positive control B｜制度域

统一政务大厅里，每个事项有稳定事项编号与责任部门映射，第三方能持续按编号进入同一事项：

```text
x并z(该事项) PASS
```

### Negative control B｜组织域

公司只有统一邮箱，来信由内部随机分给两个团队，外部无法稳定定位其中某一团队：

```text
x并z(company interface) PASS
x并z(team-1) insufficient
```

### Positive control C｜创作流程

作品合集页下每个项目有稳定作品ID、版本入口与责任归因：

```text
x并z(project-X) PASS
```

### Negative control C｜人物域

工作室只有一个公共账号，多位创作者轮流发布且不署名，公众只能稳定识别工作室，不能稳定归因到某位创作者：

```text
x并z(studio) PASS
x并z(creator-C) insufficient
```

## 8｜最小判别式

```text
IF
stable grounded public shell exists
AND third party can repeatedly use the shell
BUT
tested object is one of multiple internal candidates
AND shell does not stably resolve identification/callability/attribution/representation/entry to tested object
THEN
higher-level x并z may PASS
object-level x并z = insufficient
```

```text
IF
stable grounded public shell exists
AND tested object has a stable object-specific resolver/mapping through that shell
AND third party can repeatedly identify/call/attribute/represent/enter the same tested object
THEN
object-level x并z = PASS candidate
```

简式：

```text
能进入“这个系统”
!=
能进入“这个对象”
```

## 10｜新增 failure types / guards

```text
FAILURE_SHARED_SHELL_BACKFILLS_ALL_OBJECTS:
一个公共壳挂多个对象，却把x并z自动下放给每个对象。

FAILURE_SYSTEM_LEVEL_XZ_AS_OBJECT_LEVEL_XZ:
系统级可调用被误当作对象级可调用。

FAILURE_OPAQUE_DISPATCH_AS_OBJECT_RESOLUTION:
请求确实进了内部，就误以为第三方能稳定进入指定对象。

FAILURE_SHARED_ACCOUNT_AS_MEMBER_EXTERNALIZATION:
组织统一账号存在，就自动给每个成员判x并z。

GUARD_EARTH_OBJECT_RESOLUTION_01:
判对象级x并z前，必须验证 public shell 是否能稳定解析到 tested object。

GUARD_EARTH_OBJECT_RESOLUTION_02:
允许 higher-level x并z PASS 与 child-object x并z insufficient 同时成立，不得互相倒灌。
```

## 11｜与既有土轴卡关系

上一张 `EARTH-PUBLIC-SHELL-CAUSAL-SOURCE-GATE-v0.1` 解决：

```text
这个壳是否真的接回内部？
```

本轮解决：

```text
即便真的接回内部，它是否稳定接到“当前 tested object”？
```

两道门顺序为：

```text
shell exists
-> causal grounding
-> object-specific resolvability
-> object-level x并z candidate
```

本轮不修改 `n` criterion，不修改双箭头 SPLIT_IR 规则。
