# 十元语义解释器｜x vs n：处分控制边界与持续承载负荷分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖或修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮目标与翻译债务

本轮处理 `x ↔ n`。

current L1 对两端的上位约束分别是：

```text
x：对象进入主体的掌握、调用、调配、排除或处分边界。
n：外部对象进入内部，并由内部跨阶段持续承载。
```

自然语言里最危险的不是“拥有”或“照顾”这些显词，而是以下高频模糊表达：

```text
这个人归我管。
这个项目我接手了。
以后我负责。
我养着他们。
这个账号/团队/设备都在我这里。
```

这些句子可能表示：

1. actor 对 object 有直接调配/冻结/排除/转交权；
2. actor 只是承担 object 留下的持续成本、风险、护理、维护或协调负荷；
3. 两者同时存在；
4. 两者都没有，只是身份、称谓或责任宣言。

因此新增解释器规则：

`CONTROL-SCOPE-vs-SUSTAINED-CARRYING-LOAD-v0.1`

并增加三个强制审计：

```text
DISPOSITION-RIGHT_AUDIT_REQUIRED
LOAD-BEARER_AUDIT_REQUIRED
CONTROL-EVENT-vs-CARE/MAINTENANCE-EVENT_AUDIT_REQUIRED
```

核心不变量：

```text
can control object != is carrying object's recurring load
is carrying object's recurring load != can dispose/control object
ownership/title != current executable x
care/responsibility words != n without recurring reality anchor
```

## 2｜自然语言 → IR 的结构还原规则

禁止先看“管理/负责/接手/养/归我”关键词贴十元。先还原以下结构：

1. `actor`：谁被判定。
2. `object`：被控制或被持续承载的具体对象，禁止直接写“整件事”。
3. `object_layer`：至少区分 `current_disposition_control_layer` 与 `sustained_carrying_load_layer`。
4. `current_window`：只取控制权当前有效、或负荷当前跨阶段持续发生的窗口。
5. `changed_variable`：优先写 `current_control_scope`、`sustained_carrying_load` 或 unknown；禁止 `responsibility` 这种未拆词。
6. `relation_source`：institutional_delegation / ownership / emergency_admission / care_obligation / maintenance_assignment / shared / external / unknown。
7. `relation_shape`：direct_control_boundary / recurring_internal_carrying / tolerated_presence / symbolic_responsibility / unknown。
8. `decision_right`：必须明确 actor 是否可以现实调配、冻结、排除、转交、撤销、改变对象状态；无证据写 null/unknown。
9. `path_set`：x 写 control actions；n 写跨阶段 recurring load actions。两类动作不得混在同一个 path_set。
10. `reentry_right`：仅当对象退出后存在再进入问题时填写；不得靠“归我管”补。
11. `future_endpoint`：只有文本明确给出终点时填写。
12. `reality_anchor`：x 看 actor 的控制动作可现实执行；n 看对象留下的成本/护理/维护/风险/协调真实由 actor 跨阶段承担。

### 新 IR 约束 A｜同一句“负责”必须拆变量

```text
changed_variable: responsibility
```

视为未完成解析。

必须继续拆成至少一种：

```text
current_control_scope
sustained_carrying_load
final_adjudication_right
external_permission_dependency
unknown
```

### 新 IR 约束 B｜control action 与 carrying action 不得共用 path_set

x path_set 成员示例：

```text
allocate
freeze
revoke
exclude
transfer
assign
release
```

n path_set 成员示例：

```text
feed
monitor
maintain
repair
pay_recurring_cost
staff_night_shift
coordinate_followup
store_and_safeguard
```

若同一 artifact 同时有两类关系，必须 `SPLIT_IR`。

## 3｜标准输入

> 洪水后，市救助站接收了二十名临时安置居民。站长林澈可以决定谁分到哪间宿舍、冻结违规门禁卡、调整公共物资配额，也可以把空置床位重新分配。与此同时，居民入住后三周内，夜间值守、餐食、药品冷藏、清洁、慢病登记和转诊联络全部由救助站持续承担。规定明确：站长不能随意取消居民的法定安置资格，也不能把居民本人当作可处分资产转交给其他机构。

该句必须 `SPLIT_IR`。

### IR-A｜x

```yaml
actor: 林澈
object: 救助站内部宿舍床位、门禁访问与公共物资配额
object_layer: current_disposition_control_layer
current_window: 居民入住 -> 林澈持续拥有床位/门禁/物资直接配置权 -> 当前权限仍有效
changed_variable: current_control_scope
relation_source: institutional_delegated_operational_authority
relation_shape: internal_resources_inside_actor_direct_control_boundary
decision_right: actor_can_allocate_beds + freeze_access_cards + adjust_shared_supply_quota
path_set:
  - allocate_bed
  - reassign_vacant_bed
  - freeze_access_card
  - adjust_shared_supply_quota
reentry_right: frozen_access_requires_rule_based_reactivation
future_endpoint: null
reality_anchor: 林澈无需逐次向其他人申请即可现实改变床位归属、门禁状态与公共物资配额
```

判定：`x candidate PASS`。

注意：x 的 object 是床位、门禁和公共物资配额，不是“二十名居民本人”。文本明确否定了站长对居民人格/法定安置资格的处分权。

### IR-B｜n

```yaml
actor: 市救助站
object: 二十名临时安置居民及其持续生活与医疗支持需求
object_layer: sustained_carrying_load_layer
current_window: 居民入住 -> 连续三周留站 -> 夜间值守/餐食/药品/清洁/登记/转诊持续发生
changed_variable: sustained_carrying_load
relation_source: emergency_admission_and_continuing_care
relation_shape: admitted_people_remain_inside_while_recurring_load_is_actually_borne
 decision_right: bounded_care_execution_not_person_disposition
path_set:
  - night_staffing
  - meal_provision
  - medicine_refrigeration
  - sanitation
  - chronic_condition_registry
  - referral_coordination
reentry_right: null
future_endpoint: residents_exit_when_safe_rehousing_or_transfer_is_completed
reality_anchor: 居民连续三周留在站内，值守、餐食、药品冷藏、清洁、登记与转诊联络由救助站每天真实承担
```

判定：`n candidate PASS`。

这里故意保留一个校验点：`decision_right` 并非 n 的正门字段，甚至可以是 bounded；只要 recurring load 的现实承载成立，n 不依赖完整处分权。

## 4｜Positive decision gates

### x candidate gate

```text
X1 actor/object/object_layer/current_window 明确；
X2 tested object 已进入 actor 的现实控制边界；
X3 decision_right 至少包含一种可执行的调配/冻结/排除/转交/处分动作；
X4 actor 改变 tested object 状态时不需要每次重新向另一个最终控制者请求许可；
X5 reality_anchor 证明 control action 当前真实可执行；
X6 removal 掉该 control right 后，actor 对 tested object 的状态改变能力出现现实缺口；
X7 “负责/拥有/领导/管理”词本身不得 positive。
```

### n candidate gate

```text
N1 actor/object/object_layer/current_window 明确；
N2 object 已真实进入/留在内部关系；
N3 object 的继续存在带来可命名 recurring load；
N4 load 不是一次性动作，而是跨阶段重复或持续；
N5 能命名 load bearer；
N6 reality_anchor 证明 bearer 已现实承担成本/风险/护理/维护/协调之一；
N7 removal 掉 bearer 后，object 的持续存在出现可命名承载缺口；
N8 actor 是否拥有完整处分权不是 n 的必要条件。
```

## 5｜nearest-neighbor 最小差异

### 差异一｜有控制、无持续承载

```text
仓库主管可冻结设备账号、调拨机器、转移库存；
设备维护和费用全部由外包商承担。
```

预期：tested 设备控制层 `x PASS`；仅凭“主管负责仓库”不得补 `n`。

### 差异二｜有持续承载、无处分权

```text
寄养家庭每天供餐、陪诊、夜间照护儿童；
但无权取消儿童身份、转卖、永久转交或决定监护归属。
```

预期：持续照护层 `n PASS`；不能因“孩子住在我家、我养着”就把人格对象写成 x。

### 差异三｜同一事件可双层成立

```text
养老院管理员可调床位/门禁；
养老院同时承担老人每日护理与医疗协调。
```

预期：床位/门禁层 x + 老人持续照护层 n，必须 SPLIT_IR。

### 其他邻居

- `x vs z`：处分对象状态 vs 哪个判断具有 binding final validity。
- `n vs xn`：持续承担 object 留下的负荷 vs 主体主动组织运行机制。
- `n vs x并z`：外部对象进入内部承载 vs 内部对象通过公共壳向外被调用。

## 6｜false-positive guards

1. “归我管”只触发 IR 提取，不触发 x。
2. “我负责到底”只触发 responsibility disambiguation，不触发 n。
3. 所有权/职位头衔没有 current executable decision_right，不足以 x positive。
4. 一次性帮忙、一次性付款、一次性搬运，不足以 n positive。
5. 对人提供照护不等于拥有对人的处分权。
6. 能分配围绕某人的资源，不等于能处分“这个人本人”。
7. 承担维修费不等于控制设备；可能是付费义务而非 disposition scope。
8. 控制设备不等于承担设备长期维护；可能完全外包。
9. object 在内部出现，不自动 n；必须有 recurring load 与 bearer。
10. actor 有 responsibility title，不自动 x；必须有 tested object + executable right。
11. `x FAIL` 不推出 `n PASS`；`n FAIL` 不推出 `x PASS`。
12. 情感亲密、牺牲程度、悲惨程度、职业身份不得补 decision_right 或 carrying load。

## 7｜Removal / Reverse / Same-layer / Current-window

### Removal A｜移除控制权，保留承载负荷

把标准输入改为：床位和门禁由市级系统自动分配，救助站只能执行；但餐食、值守、药品、清洁仍由救助站每天承担。

预期：

```text
林澈 x ↓
救助站 n 保持
```

### Removal B｜保留控制权，移除承载负荷

把全部餐食、值守、医疗、清洁和转诊外包给另一机构；林澈仍可直接配置床位、门禁和物资配额。

预期：

```text
x 保持
原救助站 n ↓
```

### Reverse

将“我每天照护但无权转交”改成“我可调拨/冻结/转交设备，但不承担维护”，应得到 `n↓ / x↑`；反向改写应得到 `x↓ / n↑`。mutation 后必须重新抽取 IR，禁止继承旧字段。

### Same-layer

必须避免以下串账：

```text
控制床位
!= 控制居民人格/身份

承担居民照护
!= 拥有居民处分权

支付设备维护费
!= 控制设备归属
```

只有在同一 tested object_layer 上有独立证据时，才允许双端比较。

### Current-window

去年站长有床位调配权，今年已改为系统自动分配：旧 x 不得续贴。

去年居民住站三周，今年已经全部搬离：旧 n 不得续贴。

历史所有权、历史承载记录都不能跨 current_window 自动继承。

## 8｜Adversarial tests

### T1｜关键词诱导
输入：“这个团队都归我管，我负责到底。”除此之外没有任何权限、成本、维护或执行事实。
预期：`x/n UNKNOWN`。关键词不能补 IR。

### T2｜题材/职业/情绪诱导
输入：“慈爱的院长像父亲一样照顾所有人”，但文本没有任何跨阶段负荷或 decision_right。
预期：不得从慈爱、院长、照顾语气倒推 x/n。

### T3｜对象层错位
输入：“IT 主管可冻结医护账号；医院则持续承担病人的住院护理。”
预期：账号层查 x，病人照护层查 n；不得把“病人本人”纳入 IT 主管 x。

### T4｜时间窗错位
输入：“去年仓库经理可直接调拨机器且负责维护，今年调拨权已移交总部、维护也完全外包。”
预期：当前窗口旧 x/n 都不得继承。

### T5｜同关系词异对象层
A：“他管理老人”＝每天供餐、陪诊、夜间照护，但无身份处分权。
B：“他管理养老院设备”＝可冻结、调拨、报废设备，但护理由其他部门承担。
预期：A 优先查 n；B 优先查 x。同一个“管理”不能直接映射同一十元。

### T6｜对端不存在不等于本端成立
输入：“项目无人负责，也没人有调配权，服务器只是暂时开着。”
预期：`x FAIL/UNKNOWN + n FAIL/UNKNOWN`。没有 x 不会凭空生成 n。

### T7｜控制伪承载
输入：“投资人可随时冻结项目预算、撤负责人，但项目日常维护由第三方承担。”
预期：预算/项目控制层 x 可 PASS；投资人 n 不自动成立。

### T8｜承载伪控制
输入：“护理员每天给住户喂药、翻身、记录生命体征，但无权决定床位归属、转院或资格取消。”
预期：护理承载层 n PASS；不得把住户本人写成 x。

### T9｜所有权伪当前 x
输入：“设备法律登记在甲公司名下，但因法院冻结，甲当前不能使用、调拨、出售或排除他人使用。”
预期：产权词不能替代 current executable x；当前 x 降级/UNKNOWN。

### T10｜一次性帮助伪 n
输入：“朋友替我付了一次维修费，此后所有维护与风险仍由我自己承担。”
预期：朋友不因一次付款获得 n。

### T11｜同事件双层成立
输入：“寄宿机构可配置房间和门禁，同时每天承担儿童食宿、夜间值守和就医协调。”
预期：资源控制层 x + 持续承载层 n；必须 SPLIT_IR。

### T12｜最小 mutation
版本 A：

```text
管理员能调床位、冻结门禁；所有照护外包。
```

→ `x↑ / n↓`

版本 B：

```text
管理员不能改床位和门禁；机构每天承担餐食、护理、药品和转诊。
```

→ `x↓ / n↑`

必须重新抽取 `object/object_layer/changed_variable/decision_right/path_set/reality_anchor`。

## 9｜状态迁移规则

### CONTROL-SCOPE

```text
symbolic_title_only
→ bounded_use_right
→ allocation/exclusion_right
→ transfer/freeze/disposition_right

= x evidence ↑
```

### SUSTAINED-CARRYING

```text
object_merely_present
→ one_time_help
→ recurring_named_load
→ multi-stage persistent_load_with_identifiable_bearer

= n evidence ↑
```

两条状态轨独立：

```text
x ↑ != n ↑
n ↑ != x ↑
```

只有文本同时证明同一 actor 对相关对象拥有现实控制边界，并实际跨阶段承担其 recurring load，才允许 `SPLIT_IR: x + n`。

## 10｜成功门

本轮不是重复“x=控制、n=承载”的定义，而是新增以下翻译约束：

1. `responsibility` 必须二次拆变量；
2. control action 与 carrying action 禁止共用 `path_set`；
3. “围绕某人的资源可控”禁止越层推出“这个人本人可处分”；
4. n 明确不要求完整 disposition right；
5. x 明确不要求 recurring load；
6. removal 可独立让 `x↓/n保持` 或 `n↓/x保持`；
7. 新增 12 个 adversarial negatives / mutations。

因此达到提交门。
