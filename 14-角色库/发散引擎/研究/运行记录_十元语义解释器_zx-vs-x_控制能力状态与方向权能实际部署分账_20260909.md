# 十元语义解释器｜zx vs x：控制能力状态与方向权能实际部署分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究。本文件不得修改或覆盖 L1/L2 canonical、十元信息卡、准度卡、正式关系卡、行为 evidence 正本。

## 0｜本轮目标与翻译债务

本轮不扩张案例库，只补一个高频翻译债务：

```text
“资源在我手里”
“最后由我调配”
“我有权限”
“我把这条路线推成了”
“我动用了手里的资源让对方退让”
```

自然语言里“有权”“掌控”“推动”“说了算”经常混写，模型容易把 **能力状态** 与 **权能实际部署事件** 粘在同一 IR。

本轮新增规则：

```text
CONTROL-STATE-vs-DIRECTIONAL-DEPLOYMENT-v0.1

CONTROL-SCOPE_AUDIT_REQUIRED
EXERCISE-EVENT_AUDIT_REQUIRED
DIRECTIONAL-EFFECT_AUDIT_REQUIRED
```

核心不变量：

```text
拥有资源/权限 != 已经用该权能改变方向分布

control capability state != directional power exercise event

x evidence can exist without zx
zx evidence cannot be inferred merely from possession
```

解释器必须先问两套问题：

```text
A. tested object 当前是否进入 actor 的掌握/调用/调配/处分边界？
B. actor 是否实际使用自身权能，把自己的方向压进现实，并改变竞争方向/环境的现实效力？
```

若 A 与 B 同时成立，也必须按 object_layer / changed_variable 拆成两个 IR，而不是一条 IR 双贴。

## 1｜自然语言 → IR 的结构还原规则

### 1.1 先找“被掌握对象”，再找“被推进方向”

对包含“控制、资源、预算、权限、地盘、渠道、投票权、冻结权、配置权、决定权”等表达的句子，不得直接判 x 或 zx。

先抽取：

```text
control_target = 到底什么对象/资源/权限当前由 actor 直接掌握？

direction_target = actor 想让哪一个方向/路线/方案在现实中获得更强效力？
```

若两者无法分别指认：

```text
UNKNOWN / NEEDS_MORE_STRUCTURE
```

不得靠“老板”“强势”“推进”“掌控”等词补字段。

### 1.2 `decision_right` 必须区分持有权与使用结果

禁止只写：

```yaml
decision_right: actor_has_power
```

至少还原为可审计类型之一：

```text
actor_can_use_resource
actor_can_allocate_resource
actor_can_exclude_others
actor_can_transfer_or_freeze_object
actor_can_configure_priority
actor_can_bind_competing_direction
actor_can_only_recommend
actor_has_formal_right_but_not_exercised
```

其中前四类首先是 x 证据；只有当权能被真实部署到一个方向冲突/环境反应上，并产生 directional effect，才进入 zx 审计。

### 1.3 `changed_variable` 必须分账

```text
x candidate:
changed_variable = control_scope / disposition_scope / possession_boundary

zx candidate:
changed_variable = directional_power_distribution / actor_effective_influence_over_competing_direction
```

若同一句话同时出现“预算归我调配”与“我把预算全部转向A方案并使B方案失去同等推进能力”，必须 `SPLIT_IR`。

### 1.4 `reality_anchor` 的证据类型不同

x 的 reality anchor 要证明：

```text
actor 现在确实能直接使用、调配、冻结、排除、转移或处分 tested object
```

zx 的 reality anchor 要证明：

```text
actor 已实际使用权能
→ actor 自身方向取得更强现实效力
→ 竞争方向 / 他者 / 环境被迫重新反应
```

“有权限但没动用”只能支持 x，不足以支持 zx。

## 2｜标准输入

> 公司给产品负责人林澈一笔 300 万专项预算、一组 12 人研发团队和首页配置权限。制度上这些资源都由林澈当前直接调配，他可以决定谁加入项目、预算花在哪，也可以撤掉普通成员的首页编辑权限。前三个月他只是保留这些权限，没有改变 A/B 两条产品路线的资源比例。第四个月，林澈明确选择 A 路线，把 220 万预算和 9 名研发人员转到 A，取消 B 的同等首页冻结权，并立即把 A 设为唯一首页主推。B 负责人因此不能按原规模继续推进，只能重新申请资源。

必须 `SPLIT_IR`。

## 3｜完整 IR-A：x｜控制能力状态

```yaml
actor: 林澈
object: 300万专项预算、12人研发团队与首页配置权限
object_layer: current_resource_and_permission_control_layer
current_window: 林澈取得专项资源 -> 前三个月持续直接调配资格存在 -> 权限未被撤销
changed_variable: current_control_and_disposition_scope
relation_source: institutional_delegated_control_authority
relation_shape: resources_and_permissions_inside_actor_direct_control_boundary
decision_right: actor_can_allocate_budget + actor_can_assign_team + actor_can_revoke_ordinary_editor_access
path_set:
  - allocate_project_budget
  - assign_or_remove_team_members
  - grant_or_revoke_ordinary_homepage_edit_access
reentry_right: revoked_member_requires_new_authorization
future_endpoint: null
reality_anchor: 林澈无需逐次向他人申请即可直接调配专项预算、团队成员与普通首页编辑权限；即使前三个月没有改变A/B方向，这些控制权仍现实存在
```

判定：

```text
x PASS
zx 在前三个月不能仅凭这些权限成立
```

## 4｜完整 IR-B：zx｜方向权能实际部署

```yaml
actor: 林澈
object: A路线相对于B路线的现实推进效力
object_layer: competing_product_direction_power_layer
current_window: A/B原本并行 -> 林澈选择A -> 预算/人员向A迁移 -> B失去同等首页冻结权 -> A成为唯一首页主推
changed_variable: directional_power_distribution
relation_source: actor_exercised_controlled_resources_and_configuration_authority
relation_shape: competing_directions_to_actor_selected_direction_with_binding_resource_and_priority_advantage
decision_right: actor_can_bind_resource_reallocation_and_homepage_priority
path_set:
  - actor_selects_direction_A
  - move_220w_budget_to_A
  - move_9_engineers_to_A
  - remove_B_equal_homepage_freeze_right
  - set_A_as_unique_homepage_priority
reentry_right: B_requires_new_resource_approval_to_regain_previous_scale
future_endpoint: A_remains_dominant_while_current_allocation_and_priority_hold
reality_anchor: 林澈实际动用预算、人员和首页配置权，使A获得唯一主推与主要资源，B失去按原规模继续推进的现实能力并被迫重新申请资源
```

判定：

```text
zx PASS
```

关键不是“林澈资源很多”，而是这些资源已被 **部署** 到一个明确自身方向，并改变了竞争方向的现实效力。

## 5｜Positive decision gates

### 5.1 x gate

只有以下条件同时满足，才进入 x candidate：

```text
1. tested object 可明确指认；
2. object_layer 是归属 / 掌握 / 使用 / 调配 / 排除 / 处分边界；
3. actor 当前拥有可执行 control/disposition right；
4. control 不依赖每次外部临时特批；
5. reality_anchor 能指出 actor 现在可以直接改变 tested object 的使用、配置、访问、归属或处分状态。
```

不要求 actor 公开显现，不要求竞争方向发生变化，也不要求 actor 已经最大化使用权力。

### 5.2 zx gate

只有以下条件同时满足，才进入 zx candidate：

```text
1. actor 有明确自身方向；
2. 存在可被比较的竞争方向 / 环境约束 / 他者有效位置；
3. actor 有现实可执行权能；
4. actor 实际使用该权能，而非仅持有；
5. changed_variable 是方向效力 / 影响范围 / 竞争权力分布；
6. reality_anchor 显示竞争方向、他者或环境被迫重新反应；
7. 拿掉这次权能部署，方向分布变化应明显减弱或消失。
```

## 6｜Nearest-neighbor 最小差异

### 6.1 x vs zx：持有但未部署

```text
预算、团队、域名、投票权都在我手里
但我没有用它改变任何竞争方向
→ x PASS
→ zx FAIL / 不足
```

### 6.2 x vs zx：同资源发生部署

```text
同样的预算和团队
被我实际全部转向A方案
并使B方案失去同等推进能力
→ x 可保持
→ zx ↑
```

### 6.3 zx vs xn

```text
把资源压到A方向并迫使B退让
→ 查 zx

把资源安排成登记、排程、审核、重试节点长期运行
→ 查 xn
```

### 6.4 x vs z

```text
谁掌握对象/资源的使用处分边界
→ x

多个同层判断里谁拥有 binding final validity
→ z
```

## 7｜False-positive guards

以下都不能单独推出 zx：

```text
有很多资源
有最终配置权限
拥有公司 / 地盘 / 账号
是老板 / 国王 / CEO
能冻结预算
别人知道他很有权
一句“我来负责推进”
```

以下也不能单独推出 x：

```text
公开强势推进
赢了竞争
让别人退让
站在中心位
拥有高身份
临时借到一次资源
只有建议权但没有直接调配权
```

特别锁死：

```text
x FAIL != zx PASS
zx FAIL != x PASS

actor 使用别人的临时授权完成一次方向推进
→ zx 可独立审计
→ 但不自动证明 tested resource 已进入 actor 的稳定 x 边界
```

## 8｜Adversarial tests

### T1｜关键词诱导

输入：

> “所有资源都在我手里，这次一定听我的。”

但没有说明资源是什么、是否可直接调配、是否真的部署、竞争方向是否改变。

预期：

```text
x UNKNOWN
zx UNKNOWN
```

禁止从“资源在我手里”“听我的”直接补 IR。

### T2｜题材 / 职业 / 情绪诱导

输入：

> 威严的年轻国王愤怒地坐在王座上，所有人都害怕他。

无资源处分事实，无具体自身方向，无竞争方向变化。

预期：

```text
x FAIL/UNKNOWN
zx FAIL/UNKNOWN
```

身份、服装、情绪、恐惧感不得倒推十元。

### T3｜对象层错位

输入：

> IT主管能冻结员工账号，但公司产品路线由董事会决定；主管公开支持A路线。

预期：

```text
账号控制层：IT主管 x 可 PASS
产品方向层：仅公开支持不足，zx FAIL/弱
```

账号控制不能跨 object_layer 给产品方向补权能。

### T4｜时间窗错位

输入：

> 去年林澈掌握预算并把A路线推成主线；今年预算权已移交，但他仍口头支持A。

预期：

```text
current x：旧控制权不得继承
current zx：去年部署结果不得自动继承为今年新的 zx 事件
```

必须重建 current_window。

### T5｜同关系词异对象层

输入：

> “最终配置由林澈决定。”

事实 A：决定服务器 CPU 配额。  
事实 B：决定 A/B 产品哪条获得唯一首页主推。

预期：

```text
A：首先审 x（资源/配置对象控制）
B：若实际使用并改变竞争方向，审 zx
```

同一“决定”不得跨层共用。

### T6｜对端不存在不等于本端成立

输入：

> B路线自己因负责人离职而停止，A没有新增资源，也没人掌握B的资产。

预期：

```text
B不存在 != A zx
x 也不得因 zx 缺席自动成立
```

两端均需自身正证据。

### T7｜幕后控制强但未显权推进

输入：

> 投资人长期掌握全部股权和预算冻结权，但一年内没有介入A/B产品竞争。

预期：

```text
x PASS
zx 不因“权很大”自动 PASS
```

### T8｜一次借权推进伪稳定 x

输入：

> 项目经理临时获得董事长一次性授权，把会议厅和广告位全部让给A方案，B方案被迫延期；授权第二天失效。

预期：

```text
zx 可 PASS（实际方向部署与竞争效应存在）
x 只能按该瞬时/一次性权限层审计，不得扩写成长期稳定掌握整个资源池
```

### T9｜资源使用但无竞争方向变化

输入：

> 负责人把自己控制的预算按原比例给A/B各一半，双方能力不变。

预期：

```text
x PASS
zx 不因“实际花钱”自动成立
```

权能使用 != 定向扩权。

### T10｜结果看似胜利但不是 actor 权能造成

输入：

> A方案最后胜出，因为监管突然禁止B；负责人虽然一直支持A，但没改变任何资源或规则。

预期：

```text
A胜利 != 负责人 zx
```

必须审 causally effective power deployment。

### T11｜同一事件双层成立

输入：

> 创始人既直接掌握宣传预算和官网管理员，又把全部宣传预算转向A并撤销B的首页编辑权，使A成为唯一主推。

预期：

```text
控制对象层：x PASS
竞争方向层：zx PASS
强制 SPLIT_IR
```

### T12｜最小 mutation

固定：

```text
actor = 林澈
object family = 项目预算与A/B路线
relation_source = delegated_project_authority
```

Mutation A：

```text
林澈能调预算，但连续三个月维持A/B原比例
→ x ↑ / zx ↓
```

Mutation B：

```text
林澈实际把主要预算转向A并撤掉B同等冻结权
→ x 可保持 / zx ↑
```

Mutation 后必须重新从自然语言抽取 IR，不得继承旧 `changed_variable` / `reality_anchor` 偷过 gate。

## 9｜Removal / reverse / same-layer / current-window

### 9.1 Removal：删 control right

把林澈的预算、团队和首页权限全部移交财务委员会，但保留一句“林澈强烈支持A”。

预期：

```text
x ↓
zx 必须重新审计；若没有其他现实权能部署，不成立
```

### 9.2 Removal：保 control right，删 directional deployment

恢复 A/B 原资源比例和同等首页冻结权，但林澈继续掌握全部预算和配置权限。

预期：

```text
x 保持
zx ↓
```

### 9.3 Reverse：资源重新分配回来

若此前 A 获得 220 万和 9 人，之后林澈把资源恢复成 A/B 对等：

```text
x holder 可不变
方向权能分布发生反向变化
→ zx 状态重新计算
```

说明 x 看 holder/control boundary，zx 看 power exercise 对方向分布的作用。

### 9.4 Same-layer check

禁止：

```text
预算控制层 x
直接拿去证明产品方向层 zx
```

必须出现跨层桥：

```text
controlled_resource
→ actual deployment
→ direction-specific effect
```

没有这条桥，zx 不成立。

### 9.5 Current-window check

```text
历史上拥有资源
!= 当前 x

历史上曾经压过对手
!= 当前窗口新的 zx
```

除非 current_window 明确显示控制关系或方向效应仍现实持续。

## 10｜状态迁移规则

### 10.1 CONTROL-SCOPE STATE｜x

```text
no_direct_control
→ bounded_use_right
→ allocation/exclusion_right
→ transfer/freeze/disposition_scope

= x evidence ↑
```

### 10.2 DIRECTIONAL-DEPLOYMENT STATE｜zx

```text
preference_only
→ executable_power_available
→ power_exercised_toward_actor_direction
→ competing_direction/environment_forced_to_react

= zx evidence ↑
```

核心锁定：

```text
x ↑ != zx ↑
zx ↑ != x ↑ automatically
```

只有当 actor 对 tested resource 的 x 控制 **被实际部署**，并且该部署改变了同一 current_window 中竞争方向的现实效力时，才允许观察：

```text
x capability
→ deployment bridge
→ zx effect
```

这是一条因果桥，不是符号自动迁移。

## 11｜本轮成功门判定

本轮不是重复 canonical 的“x 有权、zx 显权”一句话，而是新增以下可执行翻译约束：

1. `control_target` 与 `direction_target` 分离；
2. `decision_right` 区分权能持有类型与方向约束类型；
3. `changed_variable` 强制拆为 control scope vs directional power distribution；
4. `reality_anchor` 强制区分 capability-state evidence vs exercise-event evidence；
5. 新增 `controlled_resource → actual deployment → direction-specific effect` 跨层因果桥；
6. 新增“权能使用但未改变竞争方向” adversarial negative；
7. 新增“一次借权完成方向推进但不等于稳定 x” adversarial negative；
8. 新增独立的 x / zx 状态迁移轨。

因此：

```text
PASS
新增翻译规则 = yes
新增 IR 字段约束 = yes
新增判定门 = yes
新增 adversarial negatives = yes
```

## 12｜下一轮翻译风险候选

本轮占用 zx / x，下一轮不得连续选择二者。

优先检查：

```text
n ↔ x并z
```

高风险自然语言：

```text
“这个空间把人接进来，也把里面的信息对外展示。”
“门店既容纳顾客，又是品牌对外入口。”
“平台把外部对象纳入内部，同时把内部状态映射出去。”
```

下一轮应主攻：

```text
boundary_crossing_direction
carrier_vs_shell
inside_object_vs_external_caller
relation_shape
reality_anchor
```

防止解释器只因出现“进入 / 出口 / 门 / 平台”就把土轴两端混在一起。
