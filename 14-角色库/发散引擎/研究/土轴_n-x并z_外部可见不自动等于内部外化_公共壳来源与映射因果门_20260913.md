# 土轴 n↔x并z｜外部可见不自动等于内部外化：公共壳来源与映射因果门 v0.1

> L4 research-only。只补解释器级边界，不修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮唯一缺口

既有土轴已经要求：

```text
n     = object -> inside -> sustained real load
x并z  = third_party -> stable public shell/interface -> identifiable/callable internal object
```

但仍有一个未显式拆开的风险：

> 如果第三方自己给某内部对象建立稳定公开页面、编号、标签或目录，使公众长期可以“识别/归因”它，是否仅凭公共可见性就足够判原对象发生 x并z？

本轮新增：

```text
EARTH-PUBLIC-SHELL-CAUSAL-SOURCE-GATE-v0.1
```

核心纪律：

```text
PUBLIC_VISIBILITY
!=
INTERNAL_TO_PUBLIC_EXTERNALIZATION
```

`x并z` 不要求公共壳物理上由内部主体自己托管，但要求：

```text
internal object/relation/capability
-> causally grounded stable mapping / authorized representation / accepted ingress
-> public shell/interface
-> third-party repeatable identification/callability/attribution/representation/entry
```

如果公共壳只是外部观察者单方面贴出的标签，而内部对象没有对该壳形成真实映射、授权代表、接受入口或持续对应关系，则不能把“外部可见”倒推成该内部对象的 x并z。

---

## 1｜current criterion

土轴核心变量保持不变：

```text
n     = 外 -> 内纳入真实承载并持续处理现实负荷
x并z  = 内 -> 外形成稳定公共壳/接口，使第三方可持续识别、调用、归因、代表或进入内部对象/关系/能力
```

本轮只把 `relation_source` 压细：

```text
x并z 需要的不只是 shell exists，
还要 shell 与 tested internal object 之间存在真实 outward mapping causality。
```

不从“官网、平台、登记页、公共编号、媒体报道、排行榜”等名词判元。

## 2｜完整 IR

最小案例：第三方行业登记站 R 为软件团队 A 的内部服务 S 建立稳定公开页面 `R/S-204`。

### S0｜第三方单方面登记

```yaml
actor:
  internal_actor: 软件团队A
  external_registry: 第三方登记站R
  third_party_user: 用户U

object:
  internal_service: 服务S

object_layer:
  tested: S_as_publicly_mapped_internal_capability

current_window:
  R长期保留S页面
  但A未承认该页面为官方映射/入口/代表

changed_variable:
  public_shell_causal_grounding: false

relation_source:
  external_observer_classification_only

relation_shape:
  R observes S
  -> R creates public page about S
  -> U can identify that R claims S exists

  but:
  S/A -X-> page as official mapping
  page -X-> accepted ingress into S


decision_right:
  R:
    controls page wording and listing
  A:
    does not authorize page as official representation
    does not accept requests through page

path_set:
  - public_registry_page
  - external_reference_id

reentry_right:
  U can revisit R page
  but cannot thereby re-enter/call S

future_endpoint:
  page may remain a stable external reference

reality_anchor:
  - 页面真实稳定存在
  - 第三方可重复看到同一编号
  - A没有把编号声明为官方对象标识
  - 页面不是A接受请求/调用/归因责任的入口
  - 删除R页面不改变S内部运行与A对外正式接口
```

判定：

```text
x并z(S): FAIL / insufficient 0.96
n(S): OFF / not evidenced 0.97
external public visibility: PASS 0.99
```

### S1｜同一外部页面被内部对象正式接线

保持 R 页面、编号、公众可见度全部不变，只改变：

```text
A正式声明 R/S-204 = S 的稳定公共标识
A接受经该页面发起的请求/归因
页面持续映射到S当前真实能力
```

```yaml
changed_variable:
  public_shell_causal_grounding: false -> true

relation_source:
  internal_capability
  -> authorized_external_mapping
  -> stable_public_shell

relation_shape:
  S/A
  -> authorized mapping R/S-204
  -> U identifies/calls/attributes S through stable shell

reentry_right:
  U可重复通过同一映射重新定位/进入S

reality_anchor:
  - A承认该映射
  - 映射持续对应同一S
  - 经映射发生的请求真实进入S或被A接受为正式归因入口
```

判定：

```text
x并z(S): PASS 0.98
n(S): OFF / not evidenced 0.97
```

所以真正 changed variable 不是：

```text
public page exists
```

而是：

```text
public_shell_causal_grounding
```

## 3｜nearest-neighbor 最小差异对

冻结：

```text
actor A
object S
registry R
public URL
public ID
页面内容
页面寿命
第三方访问量
服务S内部功能
```

只改：

```text
A是否把R页面接成S的正式稳定映射/代表/入口
```

### Pair 0

```text
R单方面登记
A不承认、不接线、不接受归因
=> external visibility PASS
=> x并z FAIL
```

### Pair 1

```text
同一R页面
A正式承认并持续映射S
经页面进入的请求/归因被A现实接受
=> x并z PASS
```

最小差异足以翻转 x并z。

## 4｜removal

### Removal A｜拿掉公共可见性

```text
A存在正式 outward mapping
但任何第三方都无法稳定识别/调用/归因/进入
```

结果：

```text
x并z FAIL / insufficient
```

说明内部“想公开”本身不够。

### Removal B｜拿掉 causal grounding

```text
公共页面、编号、可见度全部保持
但A不承认映射、不接受入口、不承担代表关系
```

结果：

```text
x并z FAIL / insufficient
```

说明“大家都看得到”本身也不够。

## 5｜reverse

从 S0：

```text
external-only public reference
```

只增加：

```text
authorized / causally maintained mapping to S
```

得到：

```text
x并z OFF -> ON
```

从 S1 反向撤销：

```text
A停止承认映射
不再接受经R进入的请求/归因
```

即使第三方页面仍保留多年：

```text
x并z ON -> OFF/insufficient
external visibility remains ON
```

因此：

```text
shell persistence != x并z persistence
```

## 6｜freeze-third-factor

冻结以下因素：

- 页面是否漂亮
- 是否官方域名
- 是否由第三方托管
- 是否收费
- 是否有很多访问量
- 排名高低
- 主体名气
- 页面是否真实描述S
- S本身质量
- 用户是否喜欢S

只改变：

```text
public_shell_causal_grounding
```

结论随该变量翻转。

## 7｜positive / negative controls

### Positive control A｜制度域

行业协会托管统一执业名录，但机构主动登记、持续更新、承认该编号为正式身份，并接受第三方按该编号进行正式归因/查询：

```text
x并z PASS
```

托管在外部服务器不影响判定，关键是内部对象与公共壳有稳定真实映射。

### Negative control A｜人物域

粉丝站长期给某创作者建百科页、标签和作品编号，创作者从未把它作为官方身份、入口或代表关系：

```text
public visibility PASS
x并z(创作者自身外化) insufficient
```

不能因为“大家都能搜到”就自动判 x并z。

### Positive control B｜工程域

云平台托管 API Gateway，但内部服务正式把 gateway route 绑定为稳定公共入口，第三方请求经 route 真实进入服务：

```text
x并z PASS
```

### Negative control B｜工程域

外部搜索引擎抓取并缓存内部服务的旧说明页；缓存稳定可见，但请求不进入当前服务，内部也不维护该映射：

```text
x并z FAIL / stale external reference
```

### Positive control C｜创作流程

外部发行平台托管作品页，但制作组把该页作为正式版本标识、发布入口与权利归因壳：

```text
x并z PASS
```

### Negative control C｜组织域

媒体长期用一个外号指代某内部团队，公众也能稳定识别，但团队没有把外号形成正式可调用/可代表/可归因的公共壳：

```text
stable nickname != automatically x并z
```

## 8｜最小判别式

```text
IF
public shell exists
AND third party can repeatedly see/reference it
BUT
shell-to-internal-object relation is only external observer attribution
AND internal object does not authorize/maintain/accept the mapping
THEN
external_visibility = true
x并z = insufficient
```

```text
IF
stable public shell exists
AND shell is causally grounded in the tested internal object/relation/capability
AND third parties can repeatedly identify/call/attribute/represent/enter through that grounded mapping
THEN
x并z = PASS candidate
```

简式：

```text
可见 != 外化
外部替你命名 != 你已经形成公共壳
托管在外部 != 不可算x并z
关键看：壳是否真实接回内部对象
```

## 10｜新增 failure types / guards

```text
FAILURE_PUBLIC_VISIBILITY_AS_XZ:
第三方长期可见就直接判x并z

FAILURE_EXTERNAL_LABEL_AS_INTERNAL_EXTERNALIZATION:
外部观察者单方面命名/编号被倒推成内部对象主动外化

FAILURE_HOST_LOCATION_AS_RELATION_SOURCE:
因为壳托管在外部就误判不能是x并z，或因为托管在内部就自动判x并z

FAILURE_STALE_REFERENCE_AS_LIVE_INTERFACE:
旧缓存/旧目录仍可见，被误判为当前稳定公共接口

FAILURE_PUBLIC_ATTRIBUTION_WITHOUT_GROUNDING:
公众能归因，但内部对象从未承认、维护或接受这条映射

GUARD_EARTH_SHELL_SOURCE_01:
先判 shell-to-object causal grounding，再判x并z

GUARD_EARTH_SHELL_SOURCE_02:
物理托管位置不是判元变量；真实映射因果才是
```

## 11｜与既有土轴卡关系

本轮不替代 `EARTH-DUAL-ARROW-SPLIT-IR-GATE-v0.1`。

既有门解决：

```text
同一句有 n 与 x并z 两条箭头时，必须分账，禁止证据倒灌。
```

本轮解决：

```text
即使 x并z 侧看起来已经有“公共壳”，也必须检查该壳的 relation_source / shell-to-object causal grounding。
```

因此是新增边界，不是同义重复。

未发现与 current canonical 的直接冲突；无需登记 sync debt。
