# 十元语义解释器｜n vs xn｜持续负荷承载与主动运行结构分账

> 本文件仅为 L4/L5 research candidate，用于“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜翻译债务

自然语言中的“每天照顾、安排、管理、处理、维护、轮班、登记”会同时触发 n 与 xn 的表面词汇，但两者改变的变量不同：

- n：对象进入内部后，主体/结构持续承担该对象带来的现实负荷；
- xn：主体主动把行动组织为顺序、规则、记录、节点、资源分配等可持续运行结构。

最大误判是把“重复发生”直接翻成 xn，或把“有流程”直接翻成 n。重复负荷可以完全靠临场应对而没有新运行结构；运行结构也可以围绕设备、数据或工程任务成立而不存在被承载对象。

## 2｜新翻译规则：LOAD-CARRYING-vs-ACTIVE-RUN-STRUCTURE-v0.1

### STEP 1｜冻结 tested object_layer

先问本句在测什么：

- 被接住并持续占用资源/风险/照护的位置？→ 承载层；
- 谁主动决定“怎样持续运行”，并把分散动作组织成可重复结构？→ 运行结构层。

若一句话同时包含二者，必须 SPLIT_IR，不得共用一个 changed_variable。

### STEP 2｜changed_variable 分流

```text
internal_position_continuity / sustained_load_carrying
→ 查 n

execution_structure / operational_coordination_structure / procedure_generation
→ 查 xn
```

### STEP 3｜重复性不是 xn 的充分证据

“每天做同一件事”“一直照顾”“每周登记”只证明 current_window 中重复存在。只有当 actor 主动决定顺序、节点、规则、记录方式、资源配置或异常处理，并使其可复用/积累时，才给 xn 正证据。

### STEP 4｜流程存在不是 xn 的充分证据

若流程由上级、法律、软件或既有制度预先给定，actor 只是照着执行，则 `relation_source` 应记录 external/existing structure；不得因为 path_set 有多个节点就自动判 xn。

### STEP 5｜负荷对象与运行结构不得互相代填

- n 的 `reality_anchor` 要证明对象留下以后，actor/structure 现实承担时间、空间、照护、风险、资源或协调负荷；
- xn 的 `reality_anchor` 要证明 actor 主动生成/重排的运行结构改变了执行方式，并能跨阶段继续发挥作用。

## 3｜标准输入与完整 IR

输入：

> “临时安置点接收二十名受灾居民连续住一个月，工作人员每天提供床位、餐食、药物登记和冲突处理。第三天负责人发现临场处理开始漏项，于是主动把工作拆成早晚两班，建立药物登记表、交接清单和夜间异常上报节点，之后按这套结构持续运行。”

必须 SPLIT_IR。

### IR-A｜n：持续负荷承载

```yaml
actor: 临时安置点
object: 连续居住的二十名受灾居民
object_layer: 安置点内部居住与现实负荷承载层
current_window: 接收入住 -> 一个月持续居住 -> 每日床位餐食药物与冲突处理
changed_variable: sustained_load_carrying
relation_source: internal_carrier
relation_shape: admitted_then_carried_across_repeated_days
decision_right: admission_and_internal_support_within_site_rules
path_set:
  - bed_support
  - meal_support
  - medication_handling
  - conflict_handling
reentry_right: unknown
future_endpoint: end_of_temporary_residency
reality_anchor: 居民持续留下并现实占用床位、餐食、药物处理与协调资源，安置点每天承担这些负荷
```

判定：**n candidate PASS**。

### IR-B｜xn：主动运行结构生成

```yaml
actor: 安置点负责人
object: 安置点日常支持工作的运行方式
object_layer: 工作流程、交接、记录与异常处理结构层
current_window: 临场漏项 -> 主动拆班 -> 建表 -> 建交接与上报节点 -> 持续按结构运行
changed_variable: operational_coordination_structure
relation_source: actor_generated
relation_shape: ad_hoc_handling_to_structured_repeatable_operation
decision_right: actor_on_operational_design
path_set:
  - morning_shift
  - evening_shift
  - medication_register
  - handoff_checklist
  - night_exception_reporting_node
reentry_right: null
future_endpoint: stable_repeatable_daily_operation
reality_anchor: 负责人主动生成并维护的新顺序、记录和节点替代原临场处理，并在后续多日持续被调用
```

判定：**xn candidate PASS**。

## 4｜Positive decision gates

### n candidate gate

至少要求：

1. actor/object/object_layer/current_window 明确；
2. 对象真实进入内部并获得持续位置；
3. 对象留下形成现实负荷；
4. actor/structure 跨阶段承担处理、保护、补给、照护或内部协调；
5. reality_anchor 证明“对象继续存在”依赖该承载；
6. 一次帮助、一次救援、物理关押、纯流程执行均不足。

### xn candidate gate

至少要求：

1. tested layer 是运行方式而非被承载对象本身；
2. actor 主动决定怎样安排，而非只遵守既有流程；
3. path_set 出现至少两个由 actor 组织的顺序/节点/规则/记录/资源配置元素；
4. changed_variable 指向 execution/coordination structure；
5. 结构跨至少两个阶段被继续调用、积累或维护；
6. removal 后执行方式应退回临场、碎片化或无法按原结构持续运行；
7. “每天重复”本身不能替代 2-6。

## 5｜nearest-neighbor 最小差异

### n vs xn

```text
n：对象留下以后，谁持续承担它造成的现实负荷？
xn：主体怎样主动把重复行动组织成可持续运行结构？
```

最小差异：

- 每天亲自给五个人做饭但始终临场处理：可 n 强，xn 未必成立；
- 无人被“接住”，但工程师主动搭建部署流程、检查表与回滚节点：可 xn 强，n 不成立。

### xn vs nx

```text
xn：actor_generated operational structure。
nx：external/existing route 已给定，主体沿其推进。
```

有复杂 SOP 不代表 xn；若只是照现成 SOP 执行，应优先查 nx/既有结构。

### n vs x

```text
n：承担对象留下后的负荷。
x：掌握、调用、排除或处分 tested object。
```

拘禁、扣留、封闭管理可能强化控制，但不能因为“长期在内部”判 n。

## 6｜false-positive guards

1. **关键词诱导**：“每天安排、每天管理”只触发抽取，不自动 xn。
2. **重复诱导**：重复执行既有动作 ≠ 主动生成运行结构。
3. **照护诱导**：照顾得很辛苦 ≠ xn；先看是否真的组织了流程变量。
4. **流程诱导**：存在流程 ≠ actor 的 xn；必须追 `relation_source`。
5. **管理职业诱导**：经理、护士长、项目经理、班主任等身份不提供标签。
6. **题材/情绪诱导**：灾难、家庭、温暖、责任感、忙乱、沉着均不得倒推 n/xn。
7. **对象层护栏**：居民负荷层的 n 与工作人员排班层的 xn 必须分账。
8. **时间窗护栏**：去年建立的流程今年已废弃，不得沿用旧 xn；去年承载过对象也不代表当前 n 在线。
9. **对端缺席护栏**：n FAIL 不推出 xn；xn FAIL 不推出 n。
10. **结果诱导**：事情最终运行顺利，不证明是 xn；对象最终留下，也不证明其负荷被真实承载。

## 7｜removal / reverse / same-layer / current-window

### n removal

拿掉持续补给、照护、保护与负荷处理。如果对象仍物理在场但其现实负荷不再由 tested actor/structure 承担，n 应下降。

### xn removal

保留对象与全部日常负荷，拿掉 actor 主动生成的排班、记录、节点和流程。如果工作退回临场处理但承载仍继续，则 xn 下降、n 可保持。

### reverse

- 保留“每天管理”字样，但改成完全照总部 SOP 执行：xn 应下降，不能被关键词救回；
- 保留新流程，却让居民当天全部转出、不再形成持续内部负荷：n 应下降，xn 可继续存在；
- 保留高强度照护，但每件事都即时决定、无记录无节点无可复用结构：n 可 PASS，xn FAIL/UNKNOWN。

### same-layer

只有当 n 与 xn 都针对可比较 object_layer 时才讨论关系变化。居民承载层与排班流程层可以同时成立，但不能把两者合并成一个 IR 后重复计证据。

### current-window

- 过去建立但当前已废弃的流程，不算当前 xn；
- 过去承载但当前对象已转移，不算当前 n；
- 若从“临场承载”发展到“主动提炼流程”，应记录 lifecycle transition，而不是把此前 n 重新命名为 xn。

## 8｜Adversarial tests

### T1｜关键词诱导
输入：“她每天安排老人吃饭、吃药，但所有时间表和步骤都是医院系统自动给出的，她只逐项执行。”
- n：若她/机构真实持续承担老人照护负荷，可 PASS。
- xn：FAIL/弱；“安排”字样不足，运行结构来源不是 actor。
- 结果：PASS。

### T2｜题材/职业/情绪诱导
输入：“冷静的项目经理在灾区很有责任感，但只按总部下发的值班表执行，灾民也由其他机构安置。”
- tested actor n：FAIL。
- tested actor xn：FAIL/UNKNOWN。
- 结果：PASS。

### T3｜对象层错位
输入：“托儿所持续照护儿童；园长另外主动重做三班交接与事故上报流程。”
- 儿童承载层：n candidate。
- 运行结构层：xn candidate。
- 禁止整句单标签。
- 结果：PASS。

### T4｜时间窗错位
输入：“去年她设计过药品交接表，今年系统更换后她只照新系统执行；病人仍由病区持续照护。”
- 当前 xn：不得沿用去年证据。
- 当前 n：若负荷仍被病区承担，可 PASS。
- 结果：PASS。

### T5｜同关系词异对象层
输入A：“她安排孩子每天住在这里并照护。”
输入B：“她安排服务器每天凌晨自动备份并设置失败重试节点。”
- A 的“安排”需先查承载/照护层 n，不能因词锁 xn。
- B 若主动设计重复运行结构，可 xn；不存在被承载对象则 n 不成立。
- 结果：PASS。

### T6｜对端不存在不等于本端成立
输入：“办公室无人值守，流程也被暂停。”
- n：FAIL/UNKNOWN。
- xn：FAIL/UNKNOWN。
- 结果：PASS。

### T7｜重复动作伪 xn
输入：“父亲十年每天给孩子做晚饭，但从不建立计划、记录、分工或可复用流程，都是当天临时处理。”
- n：若持续负荷与内部位置成立，可 PASS。
- xn：不能仅因十年重复而 PASS。
- 结果：PASS。

### T8｜复杂 SOP 伪 xn
输入：“仓库员按公司既定十二步 SOP、扫码节点和固定排班工作，没有修改、重排或主动设计任何运行结构。”
- xn：FAIL/弱；复杂度不替代 actor-generated。
- nx/既有结构另查。
- 结果：PASS。

### T9｜xn 强而 n 弱
输入：“工程师主动设计发布列车、回滚节点、监控表和每周复盘机制，处理的是软件版本，不存在成员进入内部并被持续接住。”
- xn：PASS。
- n：FAIL。
- 结果：PASS。

### T10｜状态迁移
输入：“起初志愿者每天临场分发物资；人数增长后负责人开始按家庭编号、时间窗、领取记录和异常节点组织分发。”
- 前段：可有 n/承载负荷，xn 证据弱。
- 后段：若 actor-generated 结构现实在线，xn 上升。
- 新规则：`repeated_load != xn`，但 `repeated_load -> active structuring` 可形成 n→xn 的解释器状态迁移记录；该迁移不得反写 canonical 关系定义。
- 结果：PASS。

## 9｜本轮新增资产与成功门

本轮不是重复已有定义，新增：

1. `repetition != active structuring` 的解释器硬门；
2. `relation_source` 成为 xn 判定的必要分流字段：existing/external workflow 不得冒充 actor-generated；
3. `sustained_load_carrying` 与 `operational_coordination_structure` 的 changed_variable 分账；
4. n/xn 双向独立 removal；
5. `repeated_load -> active structuring` 的解释器 lifecycle transition 记录规则。

因此达到成功门，允许作为 L4/L5 candidate 提交。

## 10｜下一轮翻译风险候选

下一优先建议：`xn vs nx` 的 **existing workflow / actor-generated workflow** 精细分账。

原因：本轮已经发现 `relation_source` 是高价值字段，而自然语言里的“他负责安排、执行流程、按计划推进”仍会把“主动组织”与“沿既有安排”混淆。下一轮应重点拆：

```text
external goal + actor-generated local workflow
vs
external goal + external workflow faithfully executed
```

并测试同一 actor 在不同 object_layer 上可同时出现 nx 与 xn 的条件。
