# 金轴｜议程设置与候选集裁剪：不能把“谁决定能被选什么”直接等同“谁决定最终选什么”

## 0｜本轮只解决一个问题

固定最终投票与裁定仍由多个 binding 节点按规则完成，只改变一个中心对议程或候选集的控制。

问题：

> 单一中心拥有 `agenda_control` / `candidate_set_control`，是否自动构成 pure z？

本轮结论：

```text
agenda_control != final_adjudication
candidate_set_control != automatically pure_z
```

但若同一中心可以自由、排他、无独立复核地决定“哪些选项有资格进入最终裁定”，则会在上游对象层形成真实单中心控制：

```text
choice_set_formation = z-like center
choice_within_set = xn possible
```

必须 `SPLIT_IR_BY_DECISION_STAGE`。

若候选集控制进一步强到可以任意压成 singleton，且最终流程不能拒绝/补入其他选项，则：

```text
candidate_set_control -> outcome_determinacy
```

此时所谓分布式投票已不再提供独立 substantive choice，whole-case 可升级为 strong z candidate。

新增 guard：

```text
AGENDA-CONTROL-NOT-FINAL-ADJUDICATION-GATE-v0.1
CANDIDATE-SET-CONTROL-GATE-v0.1
SET-TO-OUTCOME-COLLAPSE-GATE-v0.1
```

## 1｜current criterion

```text
xn = 运行权/判断权分布到顺序、规则、记录、节点与流程
z  = 判断权与结构重心收束到单一最高中心或最终裁定点
```

本轮扩展 rights ledger，但不修改 canonical：

```text

candidate_exclusion_right
candidate_reentry_right
candidate_set_override
```


## 3｜nearest-neighbor 最小差异

冻结：委员会成员、投票权重、2-of-3 规则、候选内容质量、最终票型、时间窗、执行权、职位名称。

只改变：

```text
candidate_set_control_scope
candidate_reentry_right
```

### S0｜客观 eligibility filter：pure xn

所有候选按预定义规则进入/退出候选集；被排除者满足条件即可独立复入。

```text
xn PASS 0.98
z FAIL 0.96
```

### S1｜单中心只控制顺序：仍可 pure xn

中心可以决定：

```text
先讨论A
后讨论B
把C排到下午
```

但不能永久排除任何合格候选，所有合格候选在 current window 内最终都会进入 binding vote。

```text
xn PASS 0.96
z FAIL 0.95
```

因此：

```text
agenda_ordering_power != candidate_set_control
```

### S2｜单中心可自由排除候选：对象层 split

只改一项：

```text
center_can_discretionarily_exclude_candidate = true
independent_candidate_reentry_path = false
```

中心仍不能决定 A/B 中谁获胜；委员会仍真实投票。

判定：

```text
eligible_candidate_set:
  z-like single-center control PASS 0.97

final_choice_within_set:
  xn PASS 0.96

whole_case:
  SPLIT_IR_BY_DECISION_STAGE
```

### S3｜候选集可压成 singleton：effective z

在 S2 基础上只增加：

```text
center_can_exclude_all_but_one = true
committee_cannot_reopen_candidate_set = true
```

此时投票虽然仍存在，但 substantive choice space 已被上游中心压成 1。

```text
effective_outcome_control:
  z strong candidate 0.98

xn substantive final choice:
  FAIL / hollowed 0.94
```

不是因为“中心没投票却神秘拥有最终票”，而是因为：

```text
who_controls_reachable_option_set
can control outcome
when option_set cardinality can be forced to 1
```

## 4｜最小判别式

```text
unilateral agenda ordering
+ all eligible options remain inevitably reachable
+ no exclusion power
-> xn-compatible
```

```text
unilateral discretionary candidate exclusion
+ no independent reentry path
+ final vote still has >=2 real options
-> upstream z-like / downstream xn
-> SPLIT_IR_BY_DECISION_STAGE
```

```text
single center can force candidate_set_size = 1
+ downstream cannot reopen/add alternatives
-> choice-set control collapses into effective outcome control
-> strong z candidate
```

因此必须分别问：

```text
谁决定讨论顺序？
谁决定谁有资格进入候选集？
谁能把被排除项重新放回来？
谁决定候选集内最终胜者？
谁能把真实可选空间压到只剩一个？
```

## 5｜removal test

### removal A｜拿掉排除权

保留议程排序，但所有合格候选必然进入 vote：

```text
upstream z-like center disappears
-> xn remains
```

### removal B｜保留排除权，但恢复独立复入

中心可以暂时排除，但候选满足公开规则后可绕过中心复入：

```text
candidate-set center significantly weakens
-> pure/sufficient xn candidate rises
```

### removal C｜保留单中心候选集控制，但禁止压成singleton

规则强制最终至少保留两个独立候选，并允许委员会拒绝整个候选集：

```text
SPLIT_IR remains possible
but whole-case pure z no longer follows
```

## 6｜reverse test

```text
PURE_XN

-> SPLIT_IR_BY_DECISION_STAGE
```

## 8｜positive / negative controls

### xn 正控｜学术评审

候选论文按公开硬条件筛选；主席只安排评审顺序，所有合格项都必须进入委员会 binding vote。

→ xn。

### split 正控｜创作提案

制片人不能决定候选集中哪个方案获胜，但可以无理由阻止某方案进入终审，且没有独立申诉/复入路线；剩余两个方案由委员会真实投票。

→ candidate-set 层 z-like；final-choice 层 xn。

### z 正控｜组织任命

负责人可以把候选集任意裁到只剩自己指定的一人，委员会不得增补、退回或重新开放候选集，只能对该唯一候选走形式流程。

→ effective z。

### negative control｜主持人排期

主持人决定先后顺序，但不能剔除候选，且所有候选在窗口内都必须被裁定。

→ 不能因“控制议程”就判 z。

## 9｜失败类型

```text
ANY_AGENDA_CONTROL_AS_Z
= 谁排议程就直接判z

ORDERING_AS_EXCLUSION
= 把先后排序误当成有资格/无资格裁剪

CANDIDATE_SET_CONTROL_IGNORED
= 只看最终多人投票，忽略上游单中心决定谁能被投

UPSTREAM_Z_BACKFILLS_DOWNSTREAM_Z
= 候选集层集中，就倒推出候选集内最终选择也由中心直接决定

DOWNSTREAM_XN_ERASES_UPSTREAM_CENTER
= 因最终票分布，就忽略候选资格已被单中心垄断

FORMAL_MULTICANDIDATE_AS_REAL_CHOICE
= 名义多个候选，实际只有一个可达/可胜，仍误判充分xn

SINGLETON_VOTE_AS_DISTRIBUTED_ADJUDICATION
= 只有一个真实候选仍因多人举手而判实质xn

TEMPORARY_EXCLUSION_AS_PERMANENT_GATE
= 可依公开规则自动复入，却误判中心拥有完整candidate-set控制

ROLE_NAME_AS_AGENDA_POWER
= 用主席/导演/负责人头衔倒推实际权利
```

## 10｜跨域复验

### 制度域

委员会按规则投票；秘书长只排议程，不能排除合格案：xn-compatible。

若秘书长可自由决定某案永不进入投票，且无独立复入：上游 candidate-set z-like / 下游 vote xn。

### 工程域

多个技术方案由评审节点投票；release manager 只排序测试批次：xn。

若 manager 可任意禁止某技术方案进入最终 benchmark，且无法通过客观规则复入：对象层 split。

若 manager 可把最终 benchmark 只留一个方案：有效结果控制向 z 收束。

### 创作流程域

委员会决定最终角色稿；主创只决定展示顺序：xn-compatible。

主创可任意扣住某稿不让进入终审：candidate-set z-like。

主创可只递交一个稿且终审不得退回重开：effective z。

跨域保持同变量：

```text
reachable_choice_set formation
vs
choice within reachable set
```

结论：

> 金轴不能只看“最后谁投票”。议程排序本身不足以构成 z；单中心若能自由、排他地裁剪谁有资格进入最终选择，则在 `eligible_candidate_set` 对象层形成真实中心化，而候选集内仍可能保持 xn。只有当该中心能把真实候选空间压到 singleton，且下游没有重新开放/增补的独立权利时，候选集控制才会塌缩成有效结果控制，whole-case 才能升为 strong z candidate。
