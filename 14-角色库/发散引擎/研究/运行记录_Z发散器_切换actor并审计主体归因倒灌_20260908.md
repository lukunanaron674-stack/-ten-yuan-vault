# Z发散器｜OP-008 SWAP_ACTOR｜切换解释主体并审计主体归因倒灌

> research-only。Z 只改变查询坐标，不替十元语义解释器下结论。本文件不得修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本；测试只验证 operator，不累计为 xn 或其他十元案例。

## 0｜本轮问题

OP-007 `REVERSE_RELATION` 改现实关系方向；OP-008 刻意做正交操作：**现实关系拓扑不变，只改变“当前被解释的主体是谁”**。

高风险错误不是人物换皮，而是 subject attribution leakage：

```text
组织拥有路径 → 倒灌成成员个人拥有路径
审批者拥有 veto → 倒灌成申请者拥有 veto
一方拥有 reentry 接受权 → 倒灌成另一方也拥有同等 reentry right
上级拥有 final decision → 倒灌成执行者拥有 final decision
系统有 fallback → 倒灌成某个 actor 可自行调用 fallback
```

因此本 operator 的信息增益在于：把同一现实结构分别投影到不同主体的 Semantic IR，检验哪些字段必须发生主体特异重建。

## 1｜operator contract

```yaml
operator_name: SWAP_ACTOR
mutation_type: swap_actor
input_ir_prerequisites:
  required:
    - actor
    - object
    - object_layer
    - current_window
    - changed_variable
    - reality_anchor
  preferred:
    - relation_source
    - relation_shape
    - decision_right
    - path_set
    - reentry_right
    - future_endpoint
mutated_fields:
  - actor
frozen_fields:
  - object
  - object_layer
  - current_window
  - changed_variable
  - source_event_or_problem
  - objective_relation_topology
conditionally_rederived_fields:
  - relation_source
  - relation_shape
  - decision_right
  - path_set
  - reentry_right
  - future_endpoint
  - reality_anchor
validation_hook: REINTERPRET_WITH_CURRENT_TEN_YUAN_SEMANTIC_INTERPRETER
```

说明：`objective_relation_topology` 是 research-local freeze，不新增 Semantic IR schema 字段。它只表示底层现实事件、接口和权力边保持不变；主体切换后，subject-relative IR 字段必须重新提取，不能复制原 actor 的值。

## 2｜query_template

```text
给定 baseline Semantic IR：
actor={A}
object={object}
object_layer={object_layer}
current_window={current_window}
changed_variable={changed_variable}
relation_source={relation_source}
relation_shape={relation_shape}
decision_right={decision_right}
path_set={path_set}
reentry_right={reentry_right}
future_endpoint={future_endpoint}
reality_anchor={reality_anchor}

执行 SWAP_ACTOR：
1. 冻结 object / object_layer / current_window / changed_variable 与底层现实关系拓扑。
2. 选择同一现实结构中的另一个真实参与者 B；不得新造职业皮肤或替换故事。
3. 仅把解释主体 A 改为 B。
4. 对 B 重新提取 relation_source / relation_shape / decision_right / path_set / reentry_right / future_endpoint / reality_anchor。
5. 明确列出 A_IR 与 B_IR 的字段 delta；任何字段都不得因为“处在同一组织/关系/场景”而继承。
6. 做 subject-removal：移除 A 后，B 的字段是否仍由独立 reality anchor 支持；反之亦然。
7. 若只有姓名/职业变化而 IR 完全照抄，标 REJECTED_RESKIN 或 ACTOR_ATTRIBUTE_COPY。
8. 若只是要求更多类似主体，标 REJECTED_RETRIEVAL_ONLY。
9. 若切换 actor 必须改 object_layer / changed_variable / current_window 才能成立，返回 ACTOR_SWAP_REQUIRES_REEXTRACTION。
10. 不判十元；将 B 的重建 IR 重新送入 current 十元语义解释器。
```

## 3｜expected xn activation

`SWAP_ACTOR` 常能把 AI 已知的流程知识从“系统层”拆回主体特异接口：谁接收 handoff、谁只能执行、谁能触发 fallback、谁持有 approval、谁依赖上游 route、谁拥有 retry/reentry 接口。

这会提高对 sequence / delegation / routing / approval / dependency / handoff 等 xn-near 结构的召回，但**不得因为出现流程词就自动判 `xn`**。主体切换后仍必须经过 Semantic IR 与十元解释器。

## 4｜关键 guards

```text
same organization ≠ same actor rights
same event ≠ same actor IR
system path_set ≠ individual path_set
holder's decision_right ≠ participant's decision_right
one-side reentry_right ≠ bilateral symmetric reentry_right
mediator route ≠ endpoint actor route
executor access ≠ final authority
observer knowledge ≠ actor callable reality
state absence in A ≠ opposite-pole presence in B
```

新增执行 guard：

### `SUBJECT-SPECIFIC-ATTRIBUTION-v0.1`

每次 actor swap 后，以下字段必须逐项重新锚定到新主体：

```text
relation_source
decision_right
path_set
reentry_right
reality_anchor
```

不能找到 subject-specific reality anchor 的字段一律 `unknown/null`，禁止从原 actor 复制。

### `ACTOR_ATTRIBUTE_COPY`

若 B 的 IR 只是把 `actor=A` 改成 `actor=B`，其余 subject-relative 字段机械继承，则 operator 失败。

## 5｜跨领域测试

> 下列样本仅验证 operator 能否打开不同结构空间，不进入任何十元 evidence 统计。

### T1｜《红楼梦》鸳鸯拒婚：鸳鸯 ↔ 贾母

冻结：

```text
object = 鸳鸯婚配去留
object_layer = personal-consent / immediate decision interface（保持当前测试层）
current_window = 贾赦求娶至公开拒绝得到现实阻断
changed_variable = 谁对当前婚配结果拥有可执行的同意/阻断接口
```

A=鸳鸯时，应检索她自己的拒绝、公开表达、求助接口与自身 consent reality anchor。

B=贾母时，不能复制鸳鸯的“个人 consent”字段；必须重新问贾母是否拥有上位 veto / final blocking authority、其权力来自何处、对同一婚配结果如何生效。

**结果：PASS。** 同一事件与对象不变，主体一换，decision_right / relation_source / reality_anchor 明显分化。证明 actor 不是装饰字段。

### T2｜《西游记》悟空回返：悟空 ↔ 唐僧

冻结：

```text
object = 重返师徒共同关系
object_layer = bilateral-reentry
current_window = 被逐后至现实回返接口重新打开
changed_variable = 当前关系回返是否现实可调用
```

A=悟空：重点是他是否有 request / approach / mediated route，以及这些路径是否能现实调用。

B=唐僧：必须重建为 acceptance / refusal / recognition 等另一侧接口；不能因为悟空“有回返路径”就自动赋予唐僧同一种 path_set，也不能因为唐僧可接受就说悟空已拥有成功 reentry。

**结果：PASS。** 打开 `request path ≠ acceptance right`，并形成 reentry 的主体特异分账。

### T3｜工程：生产发布工程师 ↔ 安全审批者

冻结：

```text
object = 同一生产版本发布
object_layer = release-control
current_window = 发布申请至最终上线/阻断
changed_variable = 当前版本是否可被现实放行到生产环境
```

A=release engineer：可拥有执行、提交、部署接口，但未必有 final approval。

B=security approver：可持 security veto/approval，但未必能直接执行 deploy。

**结果：PASS。** 同一 release topology 下，executor access 与 decision_right 不可互相倒灌；AI 可进一步检索 handoff、approval、break-glass 的主体边界。

### T4｜制度：采购申请人 ↔ 财务审批人

冻结：

```text
object = 同一采购申请
object_layer = approval-routing
current_window = 提交至批准/驳回
changed_variable = 采购是否取得当前层必要批准
```

A=申请人：拥有发起、补件、撤回等路径；审批权若无 reality anchor 应为空。

B=财务审批人：拥有特定额度/范围的 approve/reject 接口，但不自动拥有申请人的补件/撤回路径。

**结果：PASS。** path_set 与 decision_right 都随主体投影改变，而 objective workflow 不变。

### T5｜现实运维：服务所有者 ↔ 值班工程师

冻结：

```text
object = 同一故障服务恢复
object_layer = incident-recovery
current_window = 故障检测至恢复
changed_variable = 当前恢复动作与 fallback 是否现实可执行
```

A=service owner：可能拥有策略优先级、风险接受或最终业务取舍权。

B=on-call engineer：可能拥有 restart/failover/runbook 执行接口，但不必拥有业务风险最终决策权。

**结果：PASS。** 暴露“系统有 fallback”与“这个主体可调用 fallback”的差异。

### T6｜反例：同一双人协作中的真正对称接口

设 A/B 对同一个共享文档拥有完全相同的 confirmed edit permission，且 reality anchor 明确支持相同 scope。

actor swap 后 subject-relative `path_set/decision_right` 可以保持同构。

**结果：PASS-CONTROL。** operator 不要求“换 actor 就必须出现差异”；只要求重新验证。若现实真对称，允许 `NO_STRUCTURAL_DELTA_BUT_REVALIDATED`，避免把 mutation 变成强行制造差异的机器。

## 6｜防退化 probes

### Probe-R1｜职业换皮

```text
项目经理 A → 项目经理 B
```

若只是名字变了、现实关系与主体权利也被机械复制，且没有 subject-specific anchor：

**REJECTED_RESKIN。**

### Probe-R2｜只搜更多主体

```text
“再找 20 个处于同样审批流程的人”
```

没有做当前结构中的 actor 投影变换：

**REJECTED_RETRIEVAL_ONLY。**

### Probe-R3｜组织权利倒灌

```text
“公司拥有管理员 override，所以所有员工都拥有 override。”
```

**ACTOR_ATTRIBUTE_COPY / REJECTED_SUBJECT_LEAKAGE。**

### Probe-R4｜对称性强填

```text
A 能拒绝 B，所以 B 必然能以同样接口拒绝 A。
```

若无独立 reality anchor：

**REJECTED_FALSE_SYMMETRY。**

## 7｜failure_mode

```yaml
failure_modes:
  - ACTOR_ATTRIBUTE_COPY: 新 actor 机械继承旧 actor 的 relation/rights/path/reentry 字段
  - SUBJECT_LEAKAGE: 组织或另一主体的能力倒灌给当前主体
  - FALSE_SYMMETRY: 因为 A 对 B 有接口就假设 B 对 A 有镜像接口
  - ACTOR_SWAP_REQUIRES_REEXTRACTION: 必须改变 object_layer/changed_variable/current_window 才能继续
  - OBSERVER_KNOWLEDGE_LEAK: 分析者知道某路径存在，但新 actor 实际不可调用
  - SYSTEM_TO_INDIVIDUAL_LEAK: 系统级 path_set 被当成个人 path_set
  - MEDIATOR_ENDPOINT_COLLAPSE: 中介的 route 被当成关系端点自己的 route
  - RESKIN_ONLY: 只换名字/职业
  - RETRIEVAL_ONLY: 只扩大同类主体样本
```

## 8｜stop_condition

出现任一情况即停止：

1. 新 actor 不是同一 frozen reality topology 中的真实参与者；
2. actor swap 必须修改 object/object_layer/changed_variable/current_window；
3. subject-specific reality anchor 无法确认，相关字段保持 unknown 后已无更多结构可审；
4. 已完成一次 A→B 投影并得到至少一个真实 IR delta，或完成对称控制并确认无 delta；
5. 继续 swap 只是在遍历更多参与者而不产生新的字段约束，停止以避免退化为 retrieval-only。

## 9｜when_not_to_use

- 要改变现实关系方向时，使用 `REVERSE_RELATION`，不要用 actor swap 冒充反向关系；
- 要改变 authority holder 本身时，使用 `REPLACE_DECISION_HOLDER`；
- 要枚举所有可调用路径时，使用 `ENUMERATE_PATH_SET`；
- 要测试生命周期差异时，使用 `EXPAND_SHRINK_CURRENT_WINDOW`；
- 只有一个现实 actor，或第二主体只是抽象群体且无 reality anchor 时不使用；
- 目标只是替换职业/题材/人物名时直接拒绝。

## 10｜validation hook

```text
baseline A_IR
→ freeze object/object_layer/current_window/changed_variable/objective topology
→ mutate actor A→B
→ rebuild B subject-specific IR
→ mark provenance = z_mutation_research
→ run SUBJECT-SPECIFIC-ATTRIBUTION-v0.1
→ send B_IR to current ten-yuan semantic interpreter
→ independently judge symbol / nearest-neighbor / false-positive guards
→ only interpreter output may enter downstream candidate review
```

禁止：

```text
A 被解释为某十元
→ actor 改成 B
→ 直接继承 A 的十元标签
```

## 12｜下一最高价值 mutation

`SAME_NOUN_DIFFERENT_STRUCTURE`。

理由：OP-001~008 已覆盖对象层、跨域、路径、决策持有者、条件、时间窗、关系方向、主体投影；下一类最高风险不是继续改实体，而是攻击 AI 对**同一个名词自动继承同一结构**的倾向。
