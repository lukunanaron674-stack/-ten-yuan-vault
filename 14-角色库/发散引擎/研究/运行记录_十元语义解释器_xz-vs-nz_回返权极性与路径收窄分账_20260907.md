# 十元语义解释器｜xz vs nz｜回返权极性与路径收窄分账

> 研究层候选。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得写入十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮翻译债务

上一轮已把 `reentry_right` 降为证据字段，明确“以后还能回来”本身既不等于 xz，也不等于 nz。但解释器仍缺一个更细的 polarity gate：

```text
谁拥有 reentry_right？
它是否对象特异？
是否双方/被测主体都能现实调用？
是否无需第三方临时施舍？
是否在 current_window 内真实可执行？
若曾关闭，是否被恢复或重建？
```

若不拆这六项，模型会把“门还在”“他说可以回来”“合同上允许回来”“我希望他回来”全部误判成 nz；也会把“当前不能回来”粗暴倒推成 xz。

新增解释器规则：

```text
reentry_right 必须结构化为 polarity evidence：
none / one-sided / third-party-dependent / bilateral-executable / restored / rebuilt / progressively-lost

nz positive 不能只靠 reentry_right 非空；
必须至少达到 object-specific + reality-executable，关系型 stable nz 还需 bilateral 或可信双方性。

xz positive 不能只靠 reentry_right = none；
必须证明 same-layer path_set 随 current_window 持续收窄、汇流或失去重入接口。
```

## 2｜自然语言 → IR 还原规则

遇到“回来、回去、复合、重返、恢复、回归、再进、门还开着、没路了、越来越回不去”等语言时，按顺序抽取：

1. `actor`：谁在被判定；
2. `object`：回返的是哪一个具体关系/位置/资格/路径；
3. `object_layer`：关系重入、职位复职、场所访问、系统权限或未来路线不得混层；
4. `current_window`：从退出/分离/路径变化开始，截到当前可验证状态；
5. `changed_variable`：优先在 `real_option_set_contraction` 与 `object_specific_reentry_space` 间分流；
6. `relation_source`：回返权来自双方关系、合同、制度、第三方许可、单方承诺还是未知；
7. `relation_shape`：记录 `closing / converging / preserved / restored / rebuilt / one-sided-memory`；
8. `decision_right`：谁能现实允许、阻断或直接执行回返；
9. `path_set`：列当前真实可走的返回/替代路径，不把愿望、口号、历史旧路当在线路径；
10. `reentry_right`：必须记录可调用性与极性，不只写 yes/no；
11. `future_endpoint`：只有结构上真实存在的终点才填；
12. `reality_anchor`：xz 看路径是否真实减少；nz 看回返接口是否真实能被对象特异主体调用并完成重新进入/修复。

## 3｜标准输入与完整 IR

输入：

> “两位合伙人因路线冲突暂时分开。合同保留双方各自离开项目后三十天内无条件重新加入原项目的权利，代码库账号不会注销，任何一方重返都不需要另一方批准；他们第一次分开后，甲已按该条款重新加入并恢复原协作节奏。与此同时，公司另一个旧产品正进入关停期：每周关闭一组 API、取消一个迁移回退窗口，到月底旧产品所有入口都会汇入新平台，已经关闭的接口不能恢复。”

### IR-A｜对象特异回返空间

```yaml
actor: 两位合伙人
object: 原项目共同协作关系
object_layer: 项目成员退出后的对象特异重入与协作修复层
current_window: 双方分开 -> 三十天重入窗口保持 -> 甲实际重返并恢复协作
changed_variable: object_specific_reentry_space
relation_source: bilateral_contractual_boundary
relation_shape: preserved_then_executed_reentry
Decision_right: each_party_direct_reentry_without_other_approval
path_set:
  - party_A_direct_reentry
  - party_B_direct_reentry
reentry_right: bilateral-executable-within-30-days
future_endpoint: null
reality_anchor: 甲已无需对方批准重新加入，原账号保持有效并恢复原协作节奏
```

判定：**nz candidate PASS**。

注意：不是因为文本出现“回来”，而是对象特异、双方性、现实可调用、实际执行都在线。

### IR-B｜未来路径持续关闭

```yaml
actor: 旧产品迁移体系
object: 旧产品继续运行或回退的现实路径
object_layer: 旧产品迁移期的未来可选路径与回退接口层
current_window: 关停开始 -> API逐周关闭 -> 回退窗口逐个取消 -> 月底全部汇入新平台
changed_variable: real_option_set_contraction
relation_source: migration_shutdown_program
relation_shape: progressive_closure_and_convergence
Decision_right: program_governance
path_set:
  - remaining_old_api_routes
  - remaining_rollback_windows
  - migrate_to_new_platform
reentry_right: progressively-lost-and-nonrestorable-for-closed-interfaces
future_endpoint: all_traffic_on_new_platform
reality_anchor: 每周真实关闭一组接口并取消一项回退能力，已关闭接口不能恢复
```

判定：**xz candidate PASS**。

同一句可以出现 `nz + xz`，但必须是两个对象层、两个 changed_variable、两套 reality anchor。

## 4｜Positive decision gates

### nz candidate gate

```text
NZ1 object 与 object_layer 对象特异且可识别；
NZ2 current_window 包含现实分离/退出/冲突或曾关闭阶段；
NZ3 relation_source 不是纯单方愿望；
NZ4 reentry_right 至少是 reality-executable，而不是 symbolic / aspirational；
NZ5 path_set 中至少有一条当前真实可调用的对象特异回返路径；
NZ6 若判 stable relation nz，需双方性：bilateral right、双方现实响应，或等价可信共同重入结构；
NZ7 reality_anchor 证明“离开后仍能回来 / 关闭后被恢复或重建”；
NZ8 单方怀念、死者遗愿、第三方一次施舍、纸面许可但不可执行均不足。
```

### xz candidate gate

```text
XZ1 object_layer 是未来路径/可逆空间/回退接口层；
XZ2 current_window 至少覆盖两个可比较阶段；
XZ3 future_endpoint 已对当前结构形成现实约束；
XZ4 path_set 在同层随阶段真实减少或汇流；
XZ5 reentry_right 若涉及本案，呈 progressively-lost / closure / nonrestorable，并且这种变化由现实事件触发；
XZ6 removal 收窄机制后，原 convergence 应明显减弱；
XZ7 单纯“现在回不去”、一次拒绝、一次断绝、从一开始就无入口，均不足。
```

## 5｜nearest neighbors

### xz vs nz

```text
xz：同一可逆/路径空间在 current_window 内持续减少、汇流、关闭。
nz：对象特异回返空间被保存、恢复或重建，并且现实可调用。
```

最小差异不是“能不能回来”一句话，而是 **reentry state 的动态方向**：

```text
open -> fewer -> closed        = xz strong candidate
closed/separated -> reopened   = nz strong candidate
open and stably callable       = nz candidate，但需对象特异/双方性门
none from start                = neither by itself
```

### nz vs nx

```text
nz：回返接口属于被测对象特异关系/位置，并保留真实重新进入资格。
nx：主体仍需沿外部安排、许可或第三方 route 才能进入。
```

“经领导批准才能复职”可能是 nx 式外部 route；只有当该批准是稳定、对象特异且构成可信回返结构时，才进一步查 nz，不能见“复职”即 nz。

### xz vs z

```text
z：一个关键裁定/终止节点。
xz：多个阶段中路径持续朝该节点收窄。
```

“今天终止会员资格”可以只是节点；若此前没有逐步关闭回返接口，不能自动 xz。

## 6｜false-positive guards

1. **关键词诱导**：“欢迎你随时回来” ≠ nz；若门禁已注销且无人有恢复权限，reality-executable = false。
2. **单方愿望诱导**：“我一直等他回来” ≠ stable nz；必须审计对方现实重入资格与双方性。
3. **第三方施舍诱导**：某高层临时特批一次回归 ≠ 稳定 nz；先标 `third-party-dependent`。
4. **当前封闭诱导**：现在回不去 ≠ xz；没有阶段性收窄轨迹时最多是 closed state。
5. **不可逆词诱导**：“永远不能回来” ≠ xz；若是一次瞬时删除且无前置收束过程，xz 不足。
6. **对端缺席护栏**：nz FAIL 不推出 xz；xz FAIL 不推出 nz。
7. **历史接口诱导**：以前能回来 ≠ 当前 nz；current_window 内接口若已撤销必须重判。
8. **对象替换诱导**：能回到“任何类似团队” ≠ 对象特异 nz；被测对象必须是原关系/原位置或明确同一对象层。

## 7｜removal / reverse / same-layer / current-window

### Removal

- nz：拿掉对象特异 reentry path。若主体仍能以完全等价方式重返原对象，原归因不足；若重返立即变成不可能或只能依赖第三方临时施舍，则 nz 证据下降。
- xz：拿掉逐步关闭机制。若路径数量不再减少、回退窗口不再消失，则收窄机制有现实归因；若仍然一样收束，需寻找第三因素。

### Reverse

- 把“欢迎回来”保留，但让账号已注销、合同无重入权、对方明确拒绝且无现实恢复接口：nz 应 FAIL。
- 把“已经不能回来”保留，但让它从一开始就是固定规则、期间没有任何路径从多到少：xz 应 FAIL/UNKNOWN。
- 把 closed state 改为“第三周恢复一条对象特异返回接口并被现实调用”：xz 应下降，nz restoration candidate 上升。

### Same-layer

“关系重入资格”和“公司旧产品技术回退接口”可以同句出现，但必须拆 IR。关系上的 nz 不能证明技术层 nz；技术路径关闭的 xz 也不能倒灌人物命运。

### Current-window

- 历史上曾可回返，但当前已撤销且没有恢复接口，不得继续贴 nz。
- 历史上曾持续收窄，但当前已重建多条真实路径，不得继续贴 xz。
- xz/nz 都是动态空间变量，必须尊重阶段迁移，禁止永久人物标签覆盖当前结构。

## 8｜adversarial tests

### T1｜关键词诱导
输入：“主管笑着说‘随时欢迎你回来’，但离职当天账号永久注销，合同没有重聘条款，主管本人也无权恢复。”
预期：**nz FAIL**。关键词不覆盖 reality anchor。

### T2｜题材/职业/情绪诱导
输入：“战争结束后老兵极度思乡，每天哭着说一定会回故乡，但边境封锁且没有任何现实通行接口。”
预期：**nz FAIL/UNKNOWN；xz 也不因悲剧和思乡成立**。需另查 path-set 是否阶段性收窄。

### T3｜对象层错位
输入：“员工还能无条件回到原项目组，但他的旧系统权限正在每周关闭一类接口并最终清零。”
预期：关系/成员资格层 **nz candidate PASS**；系统权限路径层若满足阶段性关闭则 **xz candidate PASS**。禁止混层。

### T4｜时间窗错位
输入：“去年分手后双方可以自由复合且实际复合过；今年双方签署永久断联协议并注销共同账号。”
预期：去年 nz 证据不能自动延续到今年；当前窗口重新判。

### T5｜同关系词异对象层
输入A：“我可以回到原团队，不需要重新审批。”
输入B：“系统可以回滚到昨天版本，但该回滚窗口今晚关闭。”
预期：A 查对象特异关系/资格 reentry，可能 nz；B 是技术回退窗口，若持续关闭则查 xz，单个今晚 deadline 不足。

### T6｜对端不存在不等于本端成立
输入：“门从建成起就是焊死的，从未存在入口，也没有任何逐步关闭过程。”
预期：**nz FAIL；xz FAIL**。没有回返不等于持续收窄。

### T7｜第三方依赖伪 nz
输入：“他每次回公司都必须由董事长破例特批，普通规则没有重入资格，董事长也可随时拒绝。”
预期：`reentry_right = third-party-dependent`；**stable nz FAIL/弱候选**，先查 nx/x 权限结构。

### T8｜单方记忆伪 nz
输入：“她保留旧房间二十年，但对方已死亡。”
预期：对象特异意义可以很强，但 bilateral executable reentry 不存在；**stable nz FAIL**。

### T9｜一次删除伪 xz
输入：“管理员突然一次性永久删除账号。”
预期：若此前没有终点前置与路径逐步收窄，**xz FAIL**；可另查 x/z/xn 等当前对象层。

### T10｜lifecycle transition
输入：“前三个月返岗需层层审批，第四个月合同改为双方都可无条件直接重入，第五个月甲实际重返并恢复原协作。”
预期：前段 `third-party-dependent` 不足以锁 stable nz；规则改写后 `bilateral-executable`，且被实际调用，**nz candidate 上升**。这是本轮新增的 reentry polarity transition。

## 9｜本轮新增翻译规则

新增：`PATH-CONTRACTION-vs-EXECUTABLE-REENTRY-v0.1`

核心新增 IR 约束：

```text
reentry_right 不再作为自由文本 yes/no 字段理解；
解释器必须在语义上至少区分：
none
one-sided
third-party-dependent
bilateral-executable
restored
rebuilt
progressively-lost

并将其与 path_set / relation_source / decision_right / reality_anchor 联合判定。
```

这不是修改 Semantic IR 固定字段，只是对既有 `reentry_right` 字段增加 L4/L5 解释器约束。
