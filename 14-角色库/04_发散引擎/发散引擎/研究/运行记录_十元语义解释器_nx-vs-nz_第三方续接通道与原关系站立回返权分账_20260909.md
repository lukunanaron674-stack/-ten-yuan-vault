# 十元语义解释器轮转校准｜nx vs nz

## 0｜本轮问题

本轮不扩张案例池，只处理一个翻译债务：

```text
“我靠他的关系还能回去。”
“只要领导点头，我就还能回原岗位。”
“我离开以后，原位置仍然属于可恢复关系。”
```

这三类句子都可能出现“关系 / 回去 / 许可 / 老位置 / 帮忙”等表面词，但结构并不相同。

current canonical：

```text
nx：主体不占最终方向，沿别人、关系、流程、秩序或现状已经给出的方向 / 权限 / 解决通道继续行动。

nz：对象特异关系形成可信停靠；自由离开、分离或冲突后，仍存在真实可调用的回返、修复与重新接近位置。
```

本轮新增的解释器差异不是“有没有关系词”，而是：

```text
CONTINGENT_EXTERNAL_ROUTE
vs
STANDING_OBJECT_SPECIFIC_REENTRY_RIGHT
```

即：

```text
nx 问：
当前这次推进 / 返回是否必须借用一个不属于 tested relation 自身的外部通道、许可、身份或他者权能？

nz 问：
即使具体执行通道换人或换接口，原对象特异关系本身是否仍保存站立的、现实可执行的回返资格？
```

# 1｜本轮新增翻译规则

## 1.1 `ROUTE-OWNERSHIP-vs-REENTRY-OWNERSHIP-v0.1`

自然语言先不要问“谁帮我回来”，而要拆两种所有权：

```text
route ownership：
这一次把事情办成 / 把人送回去的许可、联系人、身份、流程、钥匙或借力通道是谁的？

reentry ownership：
“原关系仍允许我回到原对象位置”这一资格，是关系自身稳定保存，还是仅由某个第三方当前愿意帮忙才临时出现？
```

判定纪律：

```text
外部人物愿意帮一次
→ 只能先形成 nx route evidence
→ 不得自动填写 nz.reentry_right

原对象关系保存可执行回返资格
→ 可形成 nz evidence
→ 不要求返回者自己拥有全部执行资源
```

## 1.2 `STANDING-RIGHT-vs-PER-INSTANCE-DISCRETION_AUDIT_REQUIRED`

把“可以回来”继续拆成：

```text
standing reentry right：
条件满足时，原参与者本身就有恢复原关系的资格；
执行者原则上只能核验条件，不能逐次重新决定“喜不喜欢你回来”。

per-instance discretion：
每次能不能回去，都要依赖外部人物重新决定、重新求人、重新借力或重新开一条关系通道。
```

前者支持 `nz`；后者优先支持 `nx`。

注意：

```text
需要提交表单 / 刷卡 / 核验身份
!= per-instance discretion
```

如果行政接口只执行一个已经存在的站立回返权，不能因为“还得走流程”就把 nz 降成 nx。

## 1.3 `GATE-REMOVAL-vs-RIGHT-REMOVAL_AUDIT_REQUIRED`

对“回去”必须分别做两个 removal：

```text
A. 拿掉当前联系人 / 领导 / 中间人 / 行政接口
B. 拿掉原关系本身保存的回返资格
```

若 A 消失后只是换另一合法接口仍可恢复原关系：

```text
nz 可保持
原接口 nx 下降
```

若 A 一消失就再无任何资格或路径，且原关系没有独立 standing right：

```text
nx 强
nz 弱 / FAIL
```

若 B 被删除，即使仍有人愿意托关系把 actor 塞回去：

```text
nz ↓
nx 仍可能 PASS
```

## 1.4 `SAME-OBJECT-RETURN-vs-NEW-ACCESS-v0.1`

“回来”必须审计 object identity：

```text
回到原关系 / 原席位 / 原对象特异位置
→ 才能查 nz

借关系拿到一个相似新岗位 / 新团队 / 新入口
→ 可以是 nx
→ 不得把“又进了同一家公司”写成 nz
```

## 1.5 与最新 reinterpretation gate 的接口

本轮 adversarial mutation 不允许把候选 IR 字段直接继承到新自然语言。

凡从：

```text
“每次靠主任重新批准”
```

突变到：

```text
“离职60天内本人有权直接恢复原席位，任何值班员只能核验期限”
```

必须重新从生成句抽取：

```text
relation_source
relation_shape
decision_right
path_set
reentry_right
reality_anchor
```

若新句没有提供这些结构，状态只能是 `NEEDS_MORE_STRUCTURE`，不能沿用候选字段强行通过。

# 2｜标准输入句

> 研究员林澈去年主动离开A实验室。实验室并没有给离职成员保留自动恢复资格；林澈若想回来，必须先请仍在校的导师周宁替他向主任提交特别申请，主任可以每次重新决定是否批准。上个月周宁替他递交申请，主任批准后林澈恢复了原实验室门禁。另一个制度中，B实验室章程规定成员主动退出后，原项目席位保留六十天；六十天内原成员本人提交恢复请求即可回到原项目，值班秘书只能核验身份和期限，无权逐次否决。陈岚离开三周后已经按该规则恢复原项目席位。

# 3｜完整 Semantic IR

## 3.1 IR-A｜nx：第三方关系通道续接

```yaml
actor: 林澈
object: 恢复A实验室原门禁与参与资格这一当前推进事项
object_layer: external_permission_and_relation_route_layer
current_window: 已离开A实验室 -> 无站立恢复资格 -> 请求周宁帮忙 -> 周宁向主任特别申请 -> 主任本次批准 -> 林澈恢复门禁
changed_variable: external_route_activation_for_current_return_attempt
relation_source: external_existing_relationship_and_authority_network
relation_shape: actor_without_standing_reentry_right_to_intermediary_to_discretionary_approver_to_current_access
 decision_right: intermediary_can_request_but_not_bind + director_per_instance_discretion
path_set:
  - actor_requests_help_from_mentor
  - mentor_uses_existing_internal_relationship
  - director_redecides_return_for_this_instance
  - access_restored_only_after_current_approval
reentry_right: null
future_endpoint: null
reality_anchor: 没有周宁的关系通道和主任本次批准，林澈没有可自行执行的恢复资格；下一次是否可回仍需重新申请
```

格式规范化：上面 `decision_right` 字段首行实际应解释为一个字段值，不得把空格当新字段。解释器实现侧只接收固定 12 字段。

判定：

```text
nx candidate PASS
nz FAIL / weak for standing relation reentry
```

原因：当前返回是借外部既有关系和他者权限完成；原关系没有独立、站立的 `reentry_right`。

## 3.2 IR-B｜nz：原关系站立回返权

```yaml
actor: 陈岚与B实验室原成员关系
object: 陈岚退出后仍可恢复的原项目席位
object_layer: object_specific_standing_reentry_layer
current_window: 原成员在项目 -> 主动退出 -> 原项目席位保留60天 -> 本人提交恢复 -> 核验身份期限 -> 恢复原项目席位
changed_variable: standing_object_specific_reentry_recoverability
relation_source: standing_relation_rule
relation_shape: previous_participant_exit_then_condition_bound_same_object_reentry
 decision_right: former_member_has_standing_reentry_right_with_nondiscretionary_verification
path_set:
  - voluntary_exit
  - retain_original_project_seat_for_60_days
  - former_member_submits_restore_request
  - secretary_verifies_identity_and_deadline_only
  - same_project_seat_restored
reentry_right: executable_to_same_object_specific_relation_within_60_days_without_per_instance_discretion
future_endpoint: reentry_window_expires_after_60_days
reality_anchor: 陈岚离开三周后无需求人或重新竞聘，秘书无权重新决定是否接纳，本人已按原资格恢复原项目席位
```

同样，`decision_right` 为固定字段值。

判定：

```text
nz candidate PASS
nx not required merely because an administrative interface exists
```

# 4｜自然语言 → IR 结构还原顺序

遇到“帮我回去 / 还能回来 / 找人恢复 / 留了后路 / 重新进去”时固定按以下顺序，不得从关键词贴标签：

```text
Step 1｜actor
谁是正在测试的推进者 / 返回者 / 关系主体？

Step 2｜object
回去的到底是什么：原关系、原岗位、原账号、原项目，还是仅一个同类新机会？

Step 3｜object_layer
当前测的是：
- 外部许可 / 人情 / 身份 route
还是
- 原对象关系的 standing reentry

Step 4｜current_window
必须明确：
曾在关系内？
是否真实离开？
本次返回如何发生？
当前规则是否仍有效？

Step 5｜relation_source
路径来自：
- external existing relationship / authority network
还是
- standing object-specific relation rule

Step 6｜decision_right
谁可以逐次重新说“不”？
谁只能核验既定条件？
返回者是否已有站立资格？

Step 7｜path_set
是：求人→中间人→审批者→本次放行
还是：退出→资格保留→本人请求→非裁量核验→原位恢复

Step 8｜reentry_right
只有对象特异、退出后仍可执行的原关系恢复资格才填写。
第三方“愿意帮你问问”不得写成 reentry_right。

Step 9｜reality_anchor
必须证明当前路径 / 权利真的能改变现实，不接受口号、怀念、承诺或关系称谓。
```

# 5｜Positive decision gate

## 5.1 nx gate

在本轮 tested layer 上，`nx` 至少要求：

1. actor 当前要推进一个明确事项；
2. actor 不拥有该事项的最终方向 / 权限 / 解决通道；
3. `relation_source` 明确来自 actor 外部既有关系、权限网络、流程或安排；
4. `path_set` 至少出现一个真实 external route node；
5. 外部 route 对结果有因果必要性或显著推动力；
6. actor 的主动求人、协调、递材料不能因此变成 zx/xn；
7. 若测试“回去”，不能把第三方可请求权误写成 actor 的 `reentry_right`。

最短门：

```text
方向 / 权限 / 通道在外部
+ actor 沿它继续
+ 没有该 route 当前事项就出现可命名缺口
→ nx candidate
```

## 5.2 nz gate

在本轮 tested layer 上，`nz` 至少要求：

1. actor / object 曾真实处于对象特异关系；
2. 发生真实退出、分离或关系受损；
3. 返回目标是原对象 / 原关系位置，不是同类新机会；
4. `reentry_right` 是 standing 且现实可执行；
5. 该权利不依赖某个外部人物每次重新喜欢、同情或批准；
6. 行政核验可以存在，但不能拥有无约束的逐次否决权；
7. `reality_anchor` 证明恢复已经发生，或权利现在真实可调用；
8. 稳定关系 nz 仍遵守 canonical 的对象特异、双方性 / 可信共同关系约束。

最短门：

```text
原关系真实存在
+ 真离开
+ 原位置仍有 standing reentry right
+ 同条件下不需逐次重做人情交易
→ nz candidate
```

# 6｜Nearest-neighbor 最小差异

## 6.1 nx vs nz｜本轮主差异

```text
nx：
“我这次能不能办回去，取决于谁愿意替我开通道 / 给许可 / 借权限？”

nz：
“即使具体办事员换人，我作为原参与者的原关系回返资格是否仍站立？”
```

最小 mutation A：

```text
每次都要主任重新特批
→ nx ↑ / nz ↓

主任只能核验‘离开未满60天’，无权任意拒绝
→ nz ↑ / 该主任 nx ↓
```

最小 mutation B：

```text
回到同公司一个新岗位
→ 可查 nx
→ 原岗位 nz 不成立

恢复原项目原席位
→ nz 可查
```

## 6.2 nx vs zx

```text
nx：借外部已有关系 / 权限 / 通道推进。
zx：以自身权能生成并压入现实方向。
```

求人很积极也仍可能是 nx；主动不是 zx 的充分条件。

## 6.3 nz vs n

```text
n：对象现在进入内部后，现实负荷被持续承载。
nz：对象真实离开以后，原对象特异关系仍可回返 / 修复。
```

回来以后被好好接住，可以另测 n；不能用接住本身证明先前存在 standing reentry right。

## 6.4 nz vs x并z

恢复一个公开账号入口，只证明公共接口重新可用，不自动恢复原私人 / 成员对象特异关系。

# 7｜False-positive guards

1. “我有人” ≠ nx，必须证明该关系 route 进入当前行动链。
2. “他能帮我回来” ≠ nz。
3. “欢迎回来” ≠ nz。
4. “领导批准复职” ≠ nz；若每次自由裁量，优先查 nx route。
5. “还可以申请” ≠ standing reentry right。
6. “有绿色通道” ≠ nz；先审 object identity 与 decision_right。
7. 需要形式审核 ≠ nx；无裁量核验可能只是 nz 的执行接口。
8. 有 standing reentry right ≠ 返回过程不存在任何 nx；若 actor 另需借外部资源才能实际到达，可分层并存。
9. 回到同类新对象 ≠ nz。
10. 单方怀念、单方预留 ≠ 稳定 nz。
11. external relation_source ≠ 自动 nx；外部关系若未真实改变当前推进，不得判。
12. nz FAIL ≠ nx PASS；可能两端都失败。
13. nx FAIL ≠ nz PASS；没有第三方 route 不等于原关系具有回返权。
14. 职位、亲密称谓、家族身份、悲惨程度、情绪强度不得补 IR 字段。

# 8｜Adversarial tests

## T1｜关键词诱导

句：

> “放心，我一定帮你回去，那里永远是你的家。”

已知只有这句话，无历史成员关系、无当前规则、无可执行路径。

预期：

```text
nx = UNKNOWN / FAIL
nz = UNKNOWN / FAIL
```

原因：“帮 / 回去 / 家”只触发抽取，不生成结构。

## T2｜题材 / 职业 / 情绪诱导

句：

> 落魄骑士跪求老国王让自己重返骑士团，国王很念旧，但制度与权限未知。

预期：

```text
不得因骑士、国王、跪求、念旧判 nx/nz
```

若无 decision_right、route、reentry 结构：两端 UNKNOWN。

## T3｜对象层错位

句：

> 校友可通过导师关系进入校园参加讲座，但离开实验室后不能恢复原项目席位。

预期：

```text
校园访问层：可查 nx
原项目关系层：nz FAIL
```

不得用“又进校园”给“原实验室席位”补 nz。

## T4｜时间窗错位

句：

> 去年离职者90天内可自动复职；今年规则已取消。甲今年离职后只好托前领导重新申请。

预期：

```text
current nz = FAIL
current nx = candidate PASS
```

历史 standing right 不得续贴当前。

## T5｜同关系词异对象层

句：

> “通过老关系回来”：老关系一方面指前同事帮忙递申请，另一方面公司章程独立保存原股东60天恢复席位权。

预期：

```text
前同事递申请 = nx route layer
股东原席位 standing right = nz layer
强制 SPLIT_IR
```

## T6｜对端不存在不等于本端成立

句：

> 原团队解散；没有任何人能帮忙，也不存在原席位恢复制度。

预期：

```text
nx FAIL
nz FAIL
```

## T7｜私人特批伪 nz

句：

> 甲每次离职后都能靠叔叔找老板特批回来，但公司没有任何离职回返规则，老板也可以随时拒绝。

预期：

```text
nx PASS
nz FAIL / weak
```

高成功率的人情 route 仍不等于 standing relation right。

## T8｜行政核验伪 nx

句：

> 研究所规定原成员退组45天内本人有权恢复原席位；行政员只核验身份证与日期，符合即必须恢复。

预期：

```text
nz PASS
行政员存在本身不推出 nx
```

## T9｜换接口不伤 nz

句：

> 原成员恢复规则不变；旧秘书离职，新秘书接任，同样只能核验条件。

预期：

```text
nz 保持
old-secretary-specific nx 不成立 / 消失
```

## T10｜同类新岗位伪 nz

句：

> 甲离开A组后，朋友推荐他进入同公司的B组，职位名称相同。

预期：

```text
nx 可 PASS
A组 nz FAIL
```

## T11｜两端并存但不同层

句：

> 乙依法保有离职30天恢复原工位的权利，但办公楼受封控，他必须托物业经理安排特殊通行才能实际进入。

预期：

```text
原工位关系资格层：nz PASS
当前物理进入通道层：nx candidate PASS
必须 SPLIT_IR
```

此例用于锁住：`nz PASS` 不等于所有执行过程都不含 nx。

## T12｜reinterpretation 最小突变

Base：

> 甲没有复职权，每次都要找主任重新批准。

Mutation：

> 甲离职60天内依法拥有恢复原席位的权利；主任只核验期限，无权拒绝。

冻结：

```text
actor
object
current_window 的事件骨架（在岗→离开→尝试返回）
```

允许突变：

```text
relation_source
relation_shape
decision_right
path_set
reentry_right
reality_anchor
```

预期：

```text
Base: nx ↑ / nz ↓
Mutation: nx ↓ / nz ↑
```

并要求 `semantic_ir_reinterpretation_v0.1` 从 Mutation 自然语言重新抽取；若字段缺失，则 `NEEDS_MORE_STRUCTURE`，不得直接继承 Base IR。

nx route ↓

预期：

```text
nz 保持
具体秘书不构成必要 nx
```

## Removal C｜拿掉 standing right，保留熟人关系

B实验室废除60天恢复条款，但老导师愿意帮陈岚逐次求主任。

预期：

```text
nz ↓
nx 可上升
```

# 10｜Reverse checks

## Reverse A

原句：“需要主任每次批准”。

反转为：“主任不得自行拒绝，只能核验既定资格”。

预期：

```text
per-instance external route evidence ↓
standing nz evidence ↑
```

## Reverse B

原句：“恢复原项目席位”。

反转为：“朋友推荐进入一个全新项目”。

预期：

```text
nz ↓
nx 可保持
```

# 11｜Same-layer check

禁止以下偷换：

```text
“能进入同一栋楼”
→ 推出“能恢复原成员关系”

“能找原领导说话”
→ 推出“原席位仍属于可回返关系”

“原席位仍可恢复”
→ 推出“当前物理交通 / 签证 / 门禁不需要任何外部协助”
```

同一自然语言中的“回来”至少可能包含：

```text
physical_access_layer
administrative_permission_layer
employment_membership_layer
object_specific_relationship_layer
public_interface_layer
```

解释器必须先定 `object_layer` 再判符号。

# 12｜Current-window check

`nx` 与 `nz` 都禁止历史继承：

```text
去年靠主任特批
!= 今年仍 nx

去年有自动恢复权
!= 今年仍 nz
```

current window 必须重读：

- 当前 external gate 是否仍存在；
- 当前谁拥有裁量；
- 当前 standing reentry right 是否仍有效；
- 当前返回目标是否仍是同一对象；
- 当前 reality anchor 是否仍可调用。

# 13｜状态迁移规则

## 13.1 `EXTERNAL-ROUTE-DEPENDENCY`

```text
no usable external route
→ external helper available
→ helper activates existing authority/network
→ current result depends on external gate

= nx evidence ↑
```

若 actor 后来取得自己的站立资格，外部帮助变成纯行政传递：

```text
nx evidence ↓
```

## 13.2 `OBJECT-SPECIFIC-REENTRY`

```text
relationship exists while present
→ actual exit
→ no standing return qualification
→ standing same-object return qualification created/preserved
→ reentry exercised

= nz evidence ↑ after exit/reentry variables become testable
```

## 13.3 两轨可独立变化

```text
nx ↑ != nz ↑
nz ↑ != nx ↓ automatically
```

只有当 tested layer 完全相同，并且“外部逐次裁量”被“关系自身 standing right”替代时，才允许观察：

```text
nx ↓ / nz ↑
```

若 standing right 存在，但物理执行仍必须借外部特殊通道，则应 `SPLIT_IR`，不能强迫互斥。

# 16｜下一轮翻译风险候选

本轮使用 `nx / nz`，下一轮必须避开两者。

当前候选高风险：

```text
z vs x
```

危险语言：

```text
“最终决定权在我。”
“这东西最后归我说了算。”
“我可以拍板，也可以直接处置。”
```

待拆变量：

```text
z：哪个同层判断 / 标准取得 binding final validity
x：哪个对象 / 资源进入 actor 的调用、调配、排除或处分边界
```

重点应审计：

```text
decision_target
object_layer
changed_variable
decision_right
reality_anchor
```

避免把“说了算”这种人类万能词同时当成裁定中心和处分权。
