# 十元语义解释器｜x并z vs nx｜公共接口与主体借道推进分账

> research-only。current canonical 永远高于本文件。本文件只服务于 `自然语言 -> Ten-Yuan Semantic IR -> 十元判定 -> Z 发散器` 的翻译稳定性，不得反向覆盖 canonical。

## 0｜本轮翻译债务

高危自然语言：

- “这是我们的官方渠道。”
- “我通过这个渠道把事情办了。”
- “找这个窗口就能进去。”
- “我只能走这个窗口。”
- “他有关系，可以从这个口子进去。”
- “这是唯一入口。”

这些句子同时包含“渠道 / 入口 / 窗口 / 接口”，但至少有两种不同语义角色：

```text
x并z：接口本身作为稳定公共壳，使外部第三方知道如何识别、调用、归因、代表或进入某内部对象。

nx：tested actor 不占最终方向或权限来源，沿别人、既有关系、既有权限或现成通道推进自己的当前事项。
```

因此禁止：

```text
出现“渠道/入口/窗口/关系”关键词
=> 直接判 x并z 或 nx
```

本轮新增解释器规则：

```text
INTERFACE-ROLE-vs-ROUTE-USAGE-v0.1
PUBLIC-CALLER-vs-TESTED-ACTOR_AUDIT_REQUIRED
INTERFACE-OBJECT-vs-ACTION-OBJECT_AUDIT_REQUIRED
ROUTE-EXISTENCE-vs-ROUTE-DEPENDENCY_AUDIT_REQUIRED
```

核心不变量：

```text
stable public interface exists
!=
tested actor depends on that interface to act

actor uses an existing route
!=
that route is a stable public shell

third parties can find/call/enter through shell
!=
actor has surrendered direction ownership
```

## 1｜自然语言 -> IR 的结构还原规则

遇到“入口 / 渠道 / 窗口 / 平台 / 账号 / 关系 / 门面 / 联系人 / 中介”等词，先禁止贴十元，依次回答：

1. `actor`：当前被判定的是谁？是接口运营方、内部对象、第三方调用者，还是借道办事者？
2. `object`：被测对象是“公共接口本身”，还是 actor 当前想推进的事项？
3. `object_layer`：公共识别/调用层，还是外部方向/权限依赖层？
4. `current_window`：接口是否跨场景稳定存在？actor 是否在当前这一轮行动里真的依赖它？
5. `changed_variable`：变化的是公共可识别/可调用性，还是 actor 的行动通路依赖？
6. `relation_source`：接口来自稳定名称/身份/职位/账号/前台，还是行动路径来自别人、关系网络、既有权限或现状？
7. `relation_shape`：是 `external caller -> shell -> represented internal object`，还是 `tested actor -> external route/permission holder -> current action`？
8. `decision_right`：接口运营者是否只有 interface-operation 权而没有内部最终决定权？借道者是否没有最终方向权？
9. `path_set`：成员是 external identification/call/entry paths，还是 tested actor 实际借用的 relation/permission routes？禁止混装。
10. `reentry_right`：除非原关系回返确实存在，否则不要因为“入口可再次使用”填 nz 型 standing reentry。
11. `future_endpoint`：x并z 可记录接口撤销/续期后的公共可调用状态；nx 可记录当前事项沿既有方向完成或外部路线变化后的跟随终点。
12. `reality_anchor`：必须给出现实第三方调用事实，或 tested actor 的真实借道依赖事实。

### 新增字段约束：`path_set` 语义成员类型

```text
x并z.path_set member_type
= external_identification_path | external_call_path | external_entry_path | attribution_path | representation_path

nx.path_set member_type
= borrowed_relation_route | existing_permission_route | superior_given_direction | existing_order_route
```

若一个 `path_set` 同时含“官网入口”和“我去求人拿审批”，必须 `SPLIT_IR`。

### 新增字段约束：`relation_shape` 的方向

```text
x并z canonical shape:
external_third_party -> stable_shell -> represented_internal_object

nx canonical shape:
tested_actor -> existing_external_route/authority/network -> current_action_result
```

方向反了，不得因为都叫“入口”而强行同判。

## 2｜标准输入句

> 市实验中心对外只有“联合服务台”这个稳定官方入口。企业、学校和个人都通过同一网站与热线提交检测需求；服务台会把请求映射到内部不同实验室，外部无需知道具体实验员是谁。研究员林澈自己想临时调用一台不归他管理的质谱仪时，没有直接调配权，他必须请设备平台主管周宁使用既有权限替他开放本次预约；若周宁不批准，林澈当前就不能走这条设备通路。

必须 `SPLIT_IR`。

## 3｜完整 IR-A：x并z

```yaml
actor: 市实验中心对外服务结构
object: 联合服务台网站与热线作为内部实验服务的稳定公共入口
object_layer: public_identification_call_and_entry_interface_layer
current_window: 多类外部请求跨场景持续通过同一服务台进入 -> 服务台稳定映射到内部实验室
changed_variable: stable_public_identifiability_and_callability
relation_source: institutionally_maintained_public_service_shell
relation_shape: external_third_party_to_stable_shell_to_internal_service_object
decision_right: interface_operator_can_route_requests_but_need_not_hold_internal_final_scientific_decision_right
path_set:
  - website_submission_entry
  - hotline_submission_entry
  - public_service_identity_lookup
  - request_routing_to_internal_lab
reentry_right: null
future_endpoint: public_requests_remain_callable_through_shell_while_interface_is_valid
reality_anchor: 企业、学校和个人跨场景通过同一网站或热线识别并调用实验中心服务，外部无需知道内部具体实验员
```

判定：`x并z PASS`。

关键：公共接口是否存在，不取决于林澈本人是否正在借它办事。

## 4｜完整 IR-B：nx

```yaml
actor: 林澈
object: 当前临时调用不归自己管理的质谱仪这一事项
object_layer: external_permission_and_existing_route_dependency_layer
current_window: 产生设备需求 -> 无直接调配权 -> 请求周宁 -> 周宁使用既有平台主管权限开放本次预约 -> 林澈沿批准后的通路使用设备
changed_variable: current_action_dependency_on_external_permission_route
relation_source: existing_equipment_authority_and_interpersonal_request_route
relation_shape: tested_actor_without_direct_authority_to_external_permission_holder_to_current_access
decision_right: actor_has_no_final_allocation_right_on_instrument; platform_manager_controls_current_permission
action_path_set:
  - request_platform_manager_help
  - platform_manager_uses_existing_equipment_permission
  - booking_is_opened_for_current_instance
  - actor_uses_instrument_under_granted_route
path_set:
  - borrowed_relation_route_to_platform_manager
  - existing_permission_route_for_equipment_booking
reentry_right: null
future_endpoint: current_equipment_use_completes_or_route_fails_if_permission_is_not_granted
reality_anchor: 林澈不能直接调配该质谱仪；周宁若不批准，本次设备调用即无法沿该通路继续
```

判定：`nx PASS`。

## 5｜Positive decision gate

### 5.1 x并z positive gate

以下必须满足：

1. 明确 `shell/interface object`；
2. 至少一个外部第三方能通过它稳定识别、调用、归因、代表或进入内部对象；
3. 接口不是一次性动作；
4. 壳与内部对象存在稳定映射；
5. removal 壳后，第三方公共识别/调用路径出现可命名缺口。

因此：

```text
只有私人熟人知道的秘密电话
!= stable public x并z automatically
```

“公共”不是要求全世界公开，而是接口对于其目标第三方群体具有稳定、可重复的识别/调用资格。

### 5.2 nx positive gate

以下必须满足：

1. tested actor 有明确当前推进事项；
2. 方向、权限或解决通道至少一项不归 tested actor 自己最终建立/掌握；
3. actor 现实沿既有他者/关系/权限/秩序路线推进；
4. removal 外部通道后，当前行动出现可命名缺口；
5. 外部方向/权限改变时，actor 的当前行动路径会随之改变或失败。

因此：

```text
看见一个公共入口
!= nx
```

只有 actor 的行动真实依赖那个既有外部通道，才进入 nx 审计。

## 6｜Nearest-neighbor 最小差异

### 差异 A：同一个官网，不同 tested role

```text
客户通过官网稳定找到并调用实验中心
→ tested object = 官网作为公共壳
→ x并z ↑

员工因为自己无权限，只能通过主管在官网后台替他开通本次资格
→ tested actor = 员工
→ external permission dependency
→ nx ↑
```

同一个物理网站可以同时出现在两端，但 `actor/object/object_layer/relation_shape` 不同，必须分 IR。

### 差异 B：私人关系通道 vs 公共接口

```text
只有我认识某副院长，托他私下打电话放行
→ nx candidate
→ x并z 不自动成立

任何合格申请人都可凭统一账号进入同一官方申请入口
→ x并z candidate
→ 使用该入口的普通申请人不自动 nx
```

### 差异 C：x并z vs xn

```text
门户让外部知道怎样提交
→ x并z

提交之后内部经过登记/审核/排队/复核
→ xn
```

### 差异 D：nx vs x

```text
设备权限在别人手里，我求人借用
→ nx

设备权限当前直接归我调配
→ x
```

## 7｜False-positive guards

禁止以下直判：

```text
“官方渠道” -> x并z PASS
“走渠道” -> nx PASS
“联系人” -> x并z
“找关系” -> nx
“唯一入口” -> x并z
“只能从这里办” -> nx
```

必须检查：

- 是否真的存在稳定第三方识别/调用功能；
- tested actor 是否真的不占方向/权限位置；
- 被测的是接口，还是使用接口的人；
- route 是公共可调用壳，还是私人借力路线；
- “只能”来自现实接口规范、外部权限依赖，还是只是叙述修辞；
- 同一词是否跨 object layer 使用。

新增负例：

```text
x并z FAIL != nx PASS
nx FAIL != x并z PASS
公共接口很强 != 每个使用者都高 nx
actor 很依赖关系 != 该关系自动成为公共 x并z
```

## 8｜Removal 检查

### Removal A：移除公共壳，保留私人关系

删掉联合服务台网站和热线，但林澈仍能私下找周宁开设备权限：

```text
x并z ↓
nx 保持
```

### Removal B：移除外部依赖，保留公共壳

设备正式转入林澈直接调配范围，但官网/热线仍供外部调用：

```text
nx ↓
x并z 保持
```

### Removal C：换接口运营人员

服务台员工换人，但同一官网、热线、名称、映射规则继续：

```text
x并z 可保持
```

说明 interface operator 不是 shell identity 本身。

## 9｜Reverse 检查

### Reverse A：公共入口 -> 私人一次性口子

若统一官网取消，只剩某熟人临时转发一次请求：

```text
stable x并z ↓
某 actor 的 nx 可另审
```

### Reverse B：借权 -> 自持权限

若林澈从“请求周宁开放”变为“本人拥有稳定直接设备调配权”：

```text
nx ↓
x candidate ↑
```

不能因为仍使用同一个预约页面而保留原 nx。

## 10｜Same-layer 检查

必须锁定：

```text
public_interface_layer
!=
actor_action_dependency_layer
```

以及：

```text
interface operator
!=
represented internal object
!=
external caller
!=
route-dependent actor
```

自然语言经常用一个“我们平台”把四个角色揉成一团。Semantic IR 不陪这种省字段行为。

## 11｜Current-window 检查

- 去年存在公共官网，今年已撤销：不得继承旧 x并z。
- 去年林澈需要求人，今年设备已归他直接调配：不得继承旧 nx。
- 官网仍存在，但当前 outage 导致第三方实际上无法调用：当前状态 x并z 强度需降级或标 unknown，不能只看历史登记。
- actor 过去曾求人一次，但当前事项无需借道：不得把历史 nx 行为贴成当前 nx 状态。

## 12｜Adversarial tests

### T1｜关键词诱导

输入：
> “这是我们最重要的官方渠道，我也一直走这个渠道。”

缺少稳定第三方调用事实、tested actor 权限位置与 current action dependency。

预期：`x并z UNKNOWN / nx UNKNOWN`。

### T2｜题材/职业/情绪诱导

输入：
> 落魄外交官在雨夜求老朋友“帮我走个特殊通道”，场面悲凉。

若只证明一次私人求助：`nx candidate`；不得因“外交官/特殊通道/悲凉”补 x并z。

### T3｜对象层错位

输入：
> 医院官网让患者统一预约；医生本人却通过院长私人许可借用研究设备。

预期：
- 医院公共预约层：`x并z candidate/PASS`；
- 医生设备调用层：`nx candidate/PASS`；
- 强制 `SPLIT_IR`。

### T4｜时间窗错位

输入：
> 去年所有供应商必须通过统一门户，今年门户已经关闭；采购员今年仍靠旧同事私下帮忙完成一次采购。

预期：当前旧门户 `x并z FAIL`；当前采购员行为可查 `nx`。

### T5｜同关系词异对象层

输入：
> “渠道”一处指任何客户都能使用的官方服务入口；另一处指员工找副总特批的私人路径。

预期：前者审 `x并z`，后者审 `nx`；禁止共用一个 `path_set`。

### T6｜对端不存在不等于本端成立

输入：
> 公司没有稳定公共入口，员工也没有任何可借用的关系或权限路线，事情直接搁置。

预期：`x并z FAIL/UNKNOWN`，`nx FAIL/UNKNOWN`。不得因一端不存在推出另一端。

### T7｜公共接口强但使用者非 nx

输入：
> 开发者通过公开 API 调用自己本来就拥有完整权限的账户资源，API 稳定且任何授权开发者都能使用。

预期：API 层 `x并z PASS`；该开发者不因“使用接口”自动 nx。

### T8｜私人借力强但无 x并z

输入：
> 林澈只有一个私交很深的监管员联系人，每次都请对方在内部替他协调，没有公开名称、统一入口或第三方调用资格。

预期：`nx PASS/candidate`；公共壳 `x并z FAIL`。

### T9｜接口运营权伪最终权

输入：
> 前台可以接单并转交，但无权决定实验结论、价格或是否最终批准。

预期：可支持 `x并z` interface function；不得把前台升级为 z/x/zx。

### T10｜“唯一入口”伪 nx

输入：
> 法定电子申报系统是所有纳税人的唯一入口，但纳税人依法直接拥有申报资格，无需求人或借外部权限。

预期：系统层 `x并z PASS`；纳税人不自动 `nx`。

### T11｜同事件双成立

输入：
> 官方基金平台是稳定公共申请入口；林澈本人不具签字资格，只能请学院负责人用既有授权替他提交。

预期：
- 平台 `x并z PASS`；
- 林澈当前提交行为 `nx PASS`；
- 必须 `SPLIT_IR`。

### T12｜最小 mutation

A：
> “任何合格用户都可通过统一平台直接申请，本人已有法定资格。”

预期：`x并z ↑ / nx 不自动成立`。

B：
> “没有统一平台；我无直接资格，只能请一个有权限的熟人替我办。”

预期：`x并z ↓ / nx ↑`。

mutation 后必须重新抽取全部 IR，不得继承 A 的 `object_layer/path_set/relation_source`。

## 13｜状态迁移候选

### x并z：PUBLIC-INTERFACE-STABILITY

```text
ad_hoc mention
-> stable named shell
-> repeatable third-party identification
-> repeatable call/entry/attribution
-> cross-scene stable public interface

= x并z ↑
```

### nx：EXTERNAL-ROUTE-DEPENDENCY

```text
self-sufficient action
-> external route becomes necessary
-> actor follows existing permission/relation
-> route owner can enable/deny current action

= nx ↑
```

两条轨独立：

```text
x并z ↑ != nx ↑
nx ↑ != x并z ↑
```

只有当同一自然语言事件同时给出“稳定公共壳”与“tested actor 对既有外部路线的现实依赖”时，两端才可分层并存。

## 14｜成功门检查

本轮不是重复 canonical 的“x并z 是接口、nx 是沿通道”一句话，而是新增以下解释器资产：

1. `PUBLIC-CALLER-vs-TESTED-ACTOR_AUDIT_REQUIRED`；
2. `INTERFACE-OBJECT-vs-ACTION-OBJECT_AUDIT_REQUIRED`；
3. `ROUTE-EXISTENCE-vs-ROUTE-DEPENDENCY_AUDIT_REQUIRED`；
4. `relation_shape` 方向约束；
5. `path_set` member type 分型；
6. 公共接口存在与 actor 路线依赖的双 removal；
7. “唯一入口但依法直接有资格” adversarial negative；
8. “私人强关系但无公共壳” adversarial negative；
9. mutation 后禁止继承旧 object_layer/path_set/relation_source。

结论：满足“出现新的翻译规则、IR 字段约束、最近邻差异、adversarial negative 或状态迁移规则才提交”的成功门。

## 15｜下一轮候选债务

本轮使用 `x并z / nx`；下一轮不得连续使用二者。

建议优先扫描：

```text
z vs nz
```

高危语言：

> “最终还是他决定我能不能回来。”

需要拆：

```text
z：谁拥有当前同层 binding final adjudication？
nz：原对象特异关系是否存在 standing / credible reentry structure？
```

“某人有最终审批权”与“我本来就有可回返位置”可以同时存在，也可以彼此独立，不能把 gatekeeper 的存在直接当成 reentry right。
