# 十元语义解释器｜zn vs xn：独立端点保存与保障机制运行分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得修改 L1/L2、信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1. 本轮翻译债务

高风险自然语言：

```text
制度保障你的独立性。
这套规则确保每个人都能保留自己的决定权。
我们建立流程，保证任何一方都不能吞并另一方。
委员会有一套机制保护各组自主权。
```

这些句子经常把两个不同 tested variable 压在同一个“制度/保障/规则”表面词里：

```text
zn：other endpoint 是否现实保存为独立对象继续成立？
xn：使事务跨阶段运行的规则、记录、节点、顺序、复核机制是否被主动组织并持续调用？
```

本轮新增解释器规则：

```text
ENDPOINT-PRESERVATION-vs-ENFORCEMENT-MECHANISM-v0.1

PRESERVED-ENDPOINT_AUDIT_REQUIRED
MECHANISM-BEARER_AUDIT_REQUIRED
RIGHT-STATE-vs-IMPLEMENTATION-PATH_AUDIT_REQUIRED
```

核心不变量：

```text
mechanism exists != zn
other endpoint preserved != xn

rule protects autonomy
→ 必须拆问：
  1) autonomy 本身是否成为现实可执行的独立 endpoint？
  2) 是否存在跨阶段运行机制来记录/检查/路由/复核这个 endpoint？
```

特别禁止：

```text
“写进制度” → 自动 zn
“保障独立” → 自动 xn
“有流程” → 自动证明 other endpoint 被保存
“other 有权利” → 自动证明存在主动组织的跨阶段机制
```

## 2. 自然语言 → IR 的结构还原规则

遇到“制度/规则/流程保障某人的独立权”时，先禁止直接贴十元，依次抽取：

```text
Step A｜找 endpoint
谁的哪一个具体选择/发展/决定位置被测试？
该位置是否与 actor/self endpoint 同层？
other 能否现实拒绝 actor 吞并、改写、撤销？

Step B｜找 mechanism
谁主动组织保障机制？
机制是否包含可重复的节点、顺序、记录、复核、handoff、触发条件？
它是否跨 current_window 多阶段运行？

Step C｜分开状态与实现
独立资格本身 → endpoint state
保障它的流程 → implementation path
不得把二者写进同一 changed_variable。
```

若文本只说“制度保护独立”，但没有 endpoint 的现实拒绝权，也没有机制节点结构，则：

```text
zn = UNKNOWN
xn = UNKNOWN
```

不得靠“制度”“独立”两个词脑补。

## 3. 标准输入

> 联合研究院由甲组和乙组组成。章程规定：甲组负责人不能改写乙组课题、撤乙组预算或取消乙组发表资格；乙组负责人可以直接拒绝甲组越权指令。为了让这条边界长期生效，研究院另设季度权限登记、预算变更双签、越权申诉队列和独立复核节点；每季度系统自动生成权限表，预算变更必须经过本组负责人和独立秘书双签，申诉未结案时任何跨组修改自动冻结。去年一次越权修改被乙组拒绝并进入申诉队列，复核后修改被撤回。

必须 `SPLIT_IR`。

## 4. 完整 IR-A｜zn：other endpoint 被现实保存

```yaml
actor: 甲组负责人
object: 乙组对自身课题、预算与发表资格的独立决定位置
object_layer: same_layer_independent_endpoint_preservation
current_window: 双组并存 -> 甲组尝试跨组修改 -> 乙组拒绝 -> 乙组原决定位置继续有效
changed_variable: other_independent_endpoint_preservation
relation_source: shared_constitutional_boundary
relation_shape: self_endpoint_exists_while_other_endpoint_remains_independently_valid_and_nonabsorbable
decision_right: self_on_self_group + other_final_on_other_group_with_effective_refusal
path_set:
  - self_group_decides_self_research
  - other_group_decides_own_topic
  - other_group_decides_own_budget
  - other_group_can_refuse_cross_group_override
reentry_right: null
future_endpoint: null
reality_anchor: 乙组已经现实拒绝甲组越权修改，拒绝后乙组原课题决定继续有效，甲组不能单方撤预算或取消发表资格
```

判定：`zn PASS`。

这里 `zn` 的 anchor 是 **other endpoint 本身仍有现实效力**，不是“存在申诉流程”。

## 5. 完整 IR-B｜xn：保障机制被主动组织并跨阶段运行

```yaml
actor: 联合研究院制度设计与运营方
object: 跨组权限边界被持续执行的运行机制
object_layer: governance_operation_mechanism_layer
current_window: 权限登记 -> 预算双签 -> 越权触发冻结 -> 进入申诉队列 -> 独立复核 -> 记录回写 -> 下一季度继续调用
changed_variable: distributed_operational_coordination_structure
relation_source: actor_generated_governance_workflow
relation_shape: multi_stage_rule_record_queue_review_cycle
decision_right: mechanism_design_and_routing_distributed_across_defined_nodes
path_set:
  - quarterly_permission_registry
  - budget_change_dual_signature
  - overreach_complaint_queue
  - automatic_freeze_while_case_open
  - independent_review_node
  - result_written_back_to_permission_record
reentry_right: unresolved_case_returns_to_review_queue_if_required
future_endpoint: governance_cycle_repeats_next_quarter
reality_anchor: 权限表、双签、冻结、申诉队列和复核节点已被实际调用，并跨季度重复维护跨组边界
```

判定：`xn PASS`。

这里 `xn` 的 anchor 是 **机制如何跑**，不是“乙组最终有没有独立权”。

## 6. Positive decision gates

### zn positive gate

```text
1. self endpoint 与 other endpoint 均明确；
2. 二者处于同一 tested object_layer；
3. other 拥有现实可执行的选择/拒绝/继续成立资格；
4. actor 不能单方吞并、撤销或改写 other endpoint；
5. reality_anchor 能证明 other 的独立决定在冲突中真实生效；
6. 去掉保障机制的具体实现后，只要该独立资格仍现实存在，zn 可以继续成立。
```

### xn positive gate

```text
1. tested object 是“运行机制”，不是权利本身；
2. actor/structure 主动组织运行方式，而非只被动遵守；
3. 至少有两个以上可指认的节点/顺序/记录/规则/handoff；
4. current_window 跨阶段，机制可重复调用；
5. 删除关键节点会造成可命名的运行缺口；
6. 即使最终保护的 endpoint 改成别的内容，只要机制仍跨阶段组织运行，xn 可保持。
```

## 7. Nearest-neighbor 最小差异

### 差异 A｜权利状态 vs 实现机制

```text
乙组拥有现实拒绝权，但只有一句简单章程，没有队列/复核/记录机制
→ zn 可 PASS
→ xn 不自动成立
```

```text
有复杂申诉、登记、复核流程，但最终院长可随时覆盖乙组决定
→ xn 可 PASS
→ zn FAIL/弱
```

### 差异 B｜改 endpoint，不改 workflow

```text
同一套季度登记+双签+申诉流程
原本保护“乙组独立选题权”
改为保护“设备安全审计”

→ xn 可保持
→ 原 zn object 必须下降/重测
```

### 差异 C｜保 endpoint，简化 workflow

```text
乙组独立权改为不可单方撤销的直接章程权利
删除全部季度登记、申诉队列与复核节点

→ zn 可保持
→ xn ↓
```

## 8. False-positive guards

```text
“制度保障独立” != 自动 zn + xn
“有章程” != xn
“有流程” != zn
“允许发言” != 独立 endpoint
“设置申诉渠道” != 申诉方最终拥有独立决定权
“对方暂时没被干涉” != zn
“流程很复杂” != 该流程主动保护了 tested endpoint
“最终保护成功” != xn，可能只是一次临时决定
“规则存在很多年” != 人物本体 xn；先审 actor/bearer
zn FAIL != xn PASS
xn FAIL != zn PASS
```

## 9. Adversarial tests

### T1｜关键词诱导

句子：`公司有一套“独立保障制度”。`

事实：没有说明谁独立、能拒绝谁、有哪些运行节点。

预期：`zn UNKNOWN / xn UNKNOWN`。

### T2｜题材 / 职业 / 情绪诱导

句子：`德高望重的院长温和地说：“我尊重每个研究者的自由。”`

事实：院长仍可随时撤项目；无任何运行机制。

预期：`zn FAIL / xn FAIL`。不得由职业、温和情绪、自由主题倒推。

### T3｜对象层错位

事实：教授有独立选题权；学校另有设备维修工单流程。

预期：选题层可查 `zn`；维修流程可查 `xn`；维修 workflow 不能给选题层补 xn，选题权也不能给维修层补 zn。

### T4｜时间窗错位

事实：去年存在独立申诉委员会；今年委员会取消，院长可直接覆盖各组。旧流程文档仍在。

预期：当前 `zn ↓`；当前治理 `xn` 必须按今年机制重测，不能继承去年状态。

### T5｜同关系词异对象层

句子都使用“保障”：

```text
A. 保障乙组可以拒绝跨组改题
B. 保障每份预算申请都有登记和复核
```

预期：A 查 endpoint-preservation `zn`；B 查 operation `xn`；不得共用 changed_variable。

### T6｜对端不存在不等于本端成立

事实：院长取消复核流程，同时也取消乙组独立决定权。

预期：`zn FAIL / xn FAIL`。xn 不存在不推出 zn；zn 不存在也不推出 xn。

### T7｜复杂制度伪 zn

事实：有五级审批、三份记录、自动提醒和复核队列，但最终院长可随时覆盖乙组所有决定。

预期：`xn PASS / zn FAIL`。

### T8｜简单边界伪 xn

事实：合伙协议只有一句有效条款：双方各自产品线不可被另一方单方撤销；实际发生冲突时乙方拒绝后甲方必须停止。没有额外流程。

预期：`zn PASS / xn FAIL或弱`。

### T9｜申诉渠道伪独立端点

事实：员工可以申诉，但申诉结果只是建议，老板可无视。

预期：申诉 workflow 可形成部分 `xn`；员工独立 endpoint 不足，`zn FAIL`。

### T10｜机制保护别的变量

事实：独立审查委员会只检查财务合规，不处理选题自主权。

预期：财务机制可查 `xn`；不能拿它支持选题层 `zn`。

### T11｜同一事件双层成立

事实：乙组拒绝越权修改，系统自动冻结请求并进入独立复核，复核确认越权后撤回修改。

预期：

```text
独立拒绝权继续有效 → zn PASS
冻结/队列/复核/回写 → xn PASS
```

但必须 `SPLIT_IR`。

### T12｜最小 mutation

冻结：`actor/object family/relation_source/current_window`。

Mutation A：

```text
删除乙组有效拒绝权
保留全部登记/队列/复核节点
最终院长可覆盖
```

预期：`zn ↓ / xn 保持`。

Mutation B：

```text
恢复乙组不可被单方撤销的拒绝权
删除登记/队列/复核，只保留直接边界条款
```

预期：`zn ↑ / xn ↓`。

mutation 后必须重新从自然语言抽取 IR；若结构不足返回 `NEEDS_MORE_STRUCTURE`，不得继承旧候选字段。

## 10. Removal / reverse / same-layer / current-window

### Removal A｜拿掉机制，保留独立权

删除季度登记、双签、申诉队列、复核节点，但章程直接赋予乙组不可被甲组单方撤销的独立权，且现实仍可拒绝越权。

```text
zn 保持
xn ↓
```

### Removal B｜拿掉独立 endpoint，保留机制

保留全部登记、双签、冻结、复核节点，但最终院长可覆盖乙组任何决定。

```text
xn 保持
zn ↓
```

### Reverse

```text
“复杂流程 + 可被最高权随时覆盖”
不能反向读成 zn。

“独立权无需复杂机制即可直接生效”
不能反向读成 xn。
```

### Same-layer

必须区分：

```text
independent_endpoint_layer
!=
governance_operation_mechanism_layer
```

同一份章程可以同时承载两个关系，但 Semantic IR 不得因此合并 object_layer。

### Current-window

历史上的独立权与历史流程都不得跨 current_window 自动继承；每轮必须重验：

```text
other endpoint 当前是否仍可现实拒绝/继续？
mechanism 当前是否仍实际运行？
```

## 11. 新状态迁移规则

### OTHER-ENDPOINT-PRESERVATION

```text
other_exists_incidentally
→ explicit_other_right
→ actor_cannot_unilaterally_revoke
→ other_exercises_effective_refusal_or_choice

= zn evidence ↑
```

### PROTECTION-MECHANISM-OPERATION

```text
ad_hoc_manual_handling
→ explicit_rule_or_record
→ multi_node_handoff/review
→ repeated_cycle_with_state_persistence

= xn evidence ↑
```

两条轨道独立：

```text
zn ↑ != xn ↑
xn ↑ != zn ↑
```

只有在文本同时给出“other endpoint 真实独立”与“跨阶段机制真实运行”的独立证据时，才允许 `SPLIT_IR: zn + xn`。

## 12. 本轮信息增益判断

本轮不是重复已有“zn=原则 / xn=流程”的旧机制，而是新增：

1. `PRESERVED-ENDPOINT_AUDIT_REQUIRED`；
2. `MECHANISM-BEARER_AUDIT_REQUIRED`；
3. `RIGHT-STATE-vs-IMPLEMENTATION-PATH_AUDIT_REQUIRED`；
4. “保障结果”与“保障机制”的双层 SPLIT_IR 规则；
5. `zn↑/xn↓` 与 `zn↓/xn↑` 的最小 mutation；
6. 复杂制度伪 zn、简单边界伪 xn 两类 adversarial negative。

因此满足成功门，允许提交。

## 13. 下一轮翻译风险候选

本轮使用 `zn / xn`，下一轮必须避开二者。

优先候选：`n ↔ z`。

高风险表达：

```text
“这件事最后由我负责。”
“出了问题我承担，但最终决定不是我做。”
“我拍板，但后续负担由另一个部门接住。”
```

下一轮应主审：

```text
load_bearer
vs
final_adjudicator
```

重点字段：`object_layer / changed_variable / decision_right / path_set / reality_anchor`。
