# Z发散器｜OP-009 SAME_NOUN_DIFFERENT_STRUCTURE｜同名词跨结构解耦并审计词义诱导

> research-only。Z 只改变“什么值得被检索”，不替十元语义解释器下结论。本文件不得修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本；以下测试只验证 operator，不累计为 xn 或任何十元案例。

## 0｜本轮问题

最新 interpreter 研究刚把“留位置/保留资格”拆成两套不同结构：当前仍在关系内的独立 endpoint，与真实离开后的对象特异 reentry。表层词完全相同，但 `object_layer / current_window / changed_variable / decision_right / path_set / reentry_right` 可以完全不同。

因此本轮不是做同义词扩写，而是反过来：**固定同一个表层名词或短语，强制生成至少两套不可互换的 Semantic IR 结构候选。**

目标是让 AI 已有的大量流程、权限、handoff、fallback、membership、repair、routing 知识不再被“同一个词应该只有一个结构”绑死。

核心纪律：

```text
same noun != same object layer
same noun != same changed variable
same noun != same decision topology
same noun != same Ten-Yuan result
```

```text

1. lexical_anchor 字面保持完全不变，不换同义词、不换题材、不换职业。
2. 列出该词在当前同一事件/制度中可能指向的最多 4 个现实 object_layer；禁止凭词典义自由发散。
3. 每个 layer 必须指定一个不同且可检验的 changed_variable。
4. 对每个候选独立重建 object/current_window/relation_source/relation_shape/decision_right/path_set/reentry_right/future_endpoint/reality_anchor。
5. 做 PAIRWISE-NONINTERCHANGEABILITY TEST：任意两个候选的 IR 若可逐字段互换而不影响现实判断，则合并，视为同一结构。
6. 做 REMOVAL TEST：移除某候选独有的 reality anchor 后，该结构是否消失，而其他候选是否仍可成立。
7. 如果只是换“安排/规划/部署”等同义词，REJECTED_RESKIN。
8. 如果只是找更多含同一词的案例，REJECTED_RETRIEVAL_ONLY。
9. 如果候选差异只能靠换作品/职业/颜色/情绪制造，REJECTED_GENRE_OR_PROFESSION_LURE。
10. 不判十元；每个重建 IR 必须分别经过 current 十元语义解释器。
```

## 3｜expected xn activation

这个 operator 对 xn 的价值不在于“搜更多流程案例”，而在于把同一个词背后的不同运行对象拆开。例如“安排”可能对应：

```text
一次 final adoption node
持续 execution sequence
资源排程
外部 route activation
权限分配
```

词不变，真正值得检索的机制会变。模型因此可以调用已有的 scheduling / routing / approval / handoff / sequencing / retry / fallback / dependency 知识，但任何候选都不得因出现流程语言而自动判 `xn`。

## 4｜新增 guards

### `LEXEME-STRUCTURE-DECOUPLING-v0.1`

```text
lexical identity cannot fill object_layer
lexical identity cannot fill changed_variable
lexical identity cannot fill decision_right
lexical identity cannot fill reentry_right
lexical identity cannot inherit Ten-Yuan label
```

### `PAIRWISE-NONINTERCHANGEABILITY-REQUIRED`

两个候选若真是不同结构，至少满足一项：

```text
object_layer differs with independent reality anchors
changed_variable differs in a testable way
decision_right membership differs
path_set membership differs
reentry_right status differs
current_window phase requirement differs
```

否则不是新结构，只是解释措辞变长。

### `NOUN-LURE-IS-QUERY-TRIGGER-NOT-EVIDENCE`

“授权、接纳、安排、关系、位置、回归、控制、保护”等名词只允许触发候选拆分，不允许直接填十元或 IR 判定字段。

## 5｜跨领域测试

> 测试只验证 operator 是否打开新结构空间，不进入十元 evidence。

### T1｜《红楼梦》“留位置”

lexical_anchor = `留位置`

同一贾府关系语境中至少拆出：

A. `current_independent_endpoint_layer`
- changed_variable = 当前仍在关系内时，自己的独立资格是否现实有效
- decision_right = 当前同层独立选择/拒绝接口
- reentry_right = null/unknown if no exit

B. `post_exit_object_specific_reentry_layer`
- changed_variable = 真实离开后，原对象特异资格能否恢复
- decision_right = former participant 的回返调用资格
- reentry_right = 必须独立证明

**结果：PASS。** 同一句“给你留位置”不能再同时给两套结构自动贴标。最新 nz↔zn interpreter 的 relation-phase audit 可直接作为 validation hook 的外部 guard。

### T2｜《西游记》“安排”

lexical_anchor = `安排`

同一取经任务语境可拆：

A. `mission-adoption/assignment layer`
- changed_variable = 谁确认任务方向/成员安排
- decision_right = 一次 adoption / assignment right

B. `execution-sequence layer`
- changed_variable = 已确认任务如何按阶段、路线、handoff 运行
- path_set = 具体执行 sequence / fallback / reroute

**结果：PASS。** “安排了取经”与“安排每天怎么走”表面同词，结构不可互换；能防止一次 z-like decision node 与持续 xn-near process 粘连。

### T3｜《三国演义》“控制”

lexical_anchor = `控制`

同一城防事件拆：

A. `resource-possession/control layer`
- changed_variable = 兵力、城门、粮道等对象是否在主体可调用/处分边界
- path_set = current controllable resources

B. `decision-authority layer`
- changed_variable = 谁拥有最终战术/战略裁定权
- decision_right = final / delegated / veto / override

C. `routing-bottleneck layer`
- changed_variable = 某道路/关口是否成为推进依赖
- path_set = alternate routes / removal gap

**结果：PASS。** “控制街亭/控制兵权/控制道路”不能靠同一个“控制”直接映射同一 IR。

### T4｜工程发布系统“授权”

lexical_anchor = `授权`

同一 production release 语境拆：

A. `permission-grant layer`
- changed_variable = actor 是否获得某 API/deploy scope
- decision_right = grant/revoke holder

B. `one-time-approval layer`
- changed_variable = 当前版本是否通过一次放行节点
- decision_right = approver/veto

C. `delegated-execution layer`
- changed_variable = 已批准动作是否由另一 actor 代执行
- path_set = delegation/handoff route

**结果：PASS。** permission、approval、delegation 三者共享“授权”表面词但路径和权力拓扑不同。

### T5｜制度/现实组织“接纳”

lexical_anchor = `接纳`

同一成员/机构语境拆：

A. `stable-carrying layer`
- changed_variable = 对象进入内部后是否获得持续位置并由主体承担持续负荷
- reality_anchor = 床位/资源/责任/持续承载

B. `membership-admission layer`
- changed_variable = 对象是否通过资格 gate 进入组织
- decision_right = admission holder / eligibility gate

C. `shared-domain-coexistence layer`
- changed_variable = 多对象是否在同一场域并置/共存，而非谁持续承载谁
- relation_shape = coexistence/shared-domain

**结果：PASS。** “接纳一个人”可指入会 gate、长期承载或仅共处；同词不等于同 Ten-Yuan 候选。

### T6｜反例控制：工程术语“重试”

若当前系统中 `重试` 只有一个被明确实现的 retry API，同一 object_layer、changed_variable、decision_right、path_set、reality_anchor 均唯一，无第二结构锚点。

**结果：PASS-CONTROL / NO_SECOND_STRUCTURE。** operator 不强制每个名词都必须多义；若拆不出独立 reality anchor，应停止而不是制造“重试文化”“重试精神”之类概念泡沫。

## 7｜failure_mode

```yaml
failure_modes:
  - RESKIN_ONLY: 只换同义词/职业/题材，不改 IR 结构
  - RETRIEVAL_ONLY: 只搜更多含同一词案例
  - LEXICAL_LABEL_INHERITANCE: 从名词直接继承十元标签
  - FAKE_POLYSEMY: 为了满足 operator 强造没有 reality anchor 的第二义
  - VARIABLE_DUPLICATION: 声称两个结构不同，但 changed_variable 可互换
  - LAYER_ALIASING: object_layer 名称不同，现实接口完全相同
  - WINDOW_SMUGGLING: 为造差异偷偷把 current_window 扩成另一事件
  - DOMAIN_DRIFT: 需要换题材才能证明所谓第二结构
  - GENERATED_AS_FACT: AI 生成的结构候选未经现实锚点确认即写入 IR
```

## 8｜stop_condition

出现任一情况即停止：

1. 已得到 2-4 个 pairwise non-interchangeable 的结构候选；
2. 候选需要换 domain/actor/source event 才能继续，停止；
3. 连续两个候选只有 layer 命名变化，没有 reality anchor / changed_variable / decision-right / path-set delta；
4. 当前 lexical_anchor 在该语境只有一个 confirmed 结构，返回 `NO_SECOND_STRUCTURE`；
5. 后续只是继续枚举更多词义而不产生新的 IR 约束，停止以避免 retrieval-only。

## 9｜when_not_to_use

- 已知问题是“换 actor 看主体归因”，用 OP-008 `SWAP_ACTOR`；
- 已知问题是“同一结构跨 domain 是否稳定”，用 `HOLD_CHANGED_VARIABLE_REPLACE_CONTEXT`；
- 需要从一个 object layer 上移/下移，用 OP-001 `SHIFT_OBJECT_LAYER`；
- 需要枚举同一层完整路线，用 OP-003 `ENUMERATE_PATH_SET`；
- 源文本没有稳定 lexical anchor，只是抽象主题时禁止使用；
- 当前词在该现实语境明确单义且已有唯一现实锚点时，不要为了形式完整强拆。

## 10｜validation hook

每个候选必须独立执行：

```text
candidate structure
-> rebuild full Semantic IR
-> enforce current-window locality
-> preserve unknown/null where unsupported
-> run current Ten-Yuan semantic interpreter
-> run current decision gate if available
-> compare candidate labels only after interpretation
```

禁止：

```text
same noun -> same Ten-Yuan label
same noun -> opposite Ten-Yuan label
```

二者都必须由完整结构重新解释。

## 12｜下一最高价值 mutation

下一轮优先：`COUNTEREXAMPLE_SEARCH`。

但其定义必须禁止“找一个反例故事”这种 retrieval-only 退化。真正值得做的是：

```text
freeze claimed structural rule
-> mutate one required IR predicate to false
-> keep nearest possible neighbors true
-> ask AI for a reality-grounded configuration that still survives
-> determine whether the claimed guard is necessary / overbroad / invalid
```

也就是把 counterexample 变成**guard falsification operator**，而不是案例搜索器。
