# 十元语义解释器｜xn vs x并z：内部运行编排与公共调用界面分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1. 本轮目标与翻译债务

目标混淆对：`xn vs x并z`。

高风险词：平台、系统、门户、工作台、中台、入口、调度中心、服务台、控制台、协作空间。

同一个名词经常同时包含两种完全不同的结构：

- `xn`：主体主动组织节点、顺序、handoff、记录、规则、资源，使行动跨阶段持续运行；
- `x并z`：稳定公共壳使第三方可以识别、调用、归因、代表或进入内部对象。

因此本轮新增候选规则：

`INTERNAL-ORCHESTRATION-vs-EXTERNAL-ADDRESSABILITY-v0.1`

以及强制审计：

```text
CALLER-POPULATION_AUDIT_REQUIRED
INTERFACE-DIRECTION_AUDIT_REQUIRED
PATH-SET-SEMANTIC-TYPE_AUDIT_REQUIRED

internal operator != external caller
workflow handoff != public entry
stable UI != xn automatically
multi-step workflow != x并z automatically
```

关键新增：解释器必须把“平台”拆成 **who calls it / from where / for what transition / which variable changes**。

## 2. 自然语言 → Semantic IR 结构还原规则

固定先抽 IR，再判十元：

1. `actor`：xn 优先抽“谁设计/维护内部运行结构”；x并z 优先抽“谁维护公共壳或被公共壳映射的对象”。不得因为同一公司拥有平台就共用 actor。
2. `object`：xn 写“内部任务/流程如何持续运行”；x并z 写“外部第三方如何识别/调用/进入的公共对象”。
3. `object_layer`：强制区分 `internal_operation_orchestration_layer` 与 `public_addressability_interface_layer`。
4. `current_window`：xn 需要内部多阶段实际运行；x并z 需要外部 caller 当前可重复调用。仅历史上线或仅设计图不算。
5. `changed_variable`：xn 优先 `operational_coordination_structure`；x并z 优先 `public_mapping_or_addressability`。不知道则 unknown，不因“系统”一词补全。
6. `relation_source`：xn 检查 actor-generated/shared-generated workflow；x并z 检查 stable public shell / public mapping / certified interface。
7. `relation_shape`：xn 优先 `multi_stage_internal_orchestration`；x并z 优先 `external_caller_to_stable_shell_to_internal_object`。
8. `decision_right`：xn 可只是 workflow-design / routing / scheduling right；x并z 的 interface operator 可以没有内部最终决策权。不得把“能操作界面”升级成处分或裁定权。
9. `path_set`：xn 只能填内部 procedure elements / handoff nodes / records / queues；x并z 只能填 external identification / entry / call / routing paths。禁止混装。
10. `reentry_right`：只有对象特异离开后回返才填；登录、重新打开网页、重复访问都不是 nz reentry。
11. `future_endpoint`：若内部流程明确到达某工作结果可填；公共接口长期存在本身不产生终点。
12. `reality_anchor`：xn 必须证明内部运行因这些节点而跨阶段持续；x并z 必须证明预先无私人关系的第三方可稳定找到并调用该壳。

### 新 IR 约束 A：CALLER-POPULATION AUDIT

```text
CP1 caller 是内部已授权操作者，还是外部/公共第三方？
CP2 caller 是否必须先已经属于内部结构？
CP3 如果移除内部身份，仍能找到/调用该界面吗？
CP4 如果移除公共入口，内部流程还能继续吗？
```

- 只有内部成员可见、用于推进任务的控制台：优先查 xn，不因“门户”自动 x并z。
- 无需既有私人关系，第三方可通过稳定壳识别/提交/查询：优先查 x并z，不因存在多个页面自动 xn。

### 新 IR 约束 B：INTERFACE-DIRECTION AUDIT

```text
inside -> inside transition orchestration = xn evidence
outside -> stable shell -> internal object mapping = x并z evidence
```

界面方向必须显式写入 `relation_shape`；“平台连接很多人”信息不足。

### 新 IR 约束 C：PATH-SET TYPE CHECK

```text
xn path element types:
queue / schedule / review / handoff / record / retry / allocation / state-transition

x并z path element types:
identify / search / public-call / submit / enter / attribute / quote / public-route
```

若一个自然语言同时出现两组类型，必须 `SPLIT_IR`。

## 3. 标准输入与完整 IR

输入：

> “城市救助中心上线了一套‘救助平台’。内部工作人员先在待处理队列接单，再分派给街区社工，社工上传处置记录，值班主管审核后进入复查队列；未通过的任务自动退回原处理人。这个内部流程每天重复运行。与此同时，任何第一次接触救助中心的市民都可以通过公开网页提交求助编号并查询办理状态；市民不需要认识任何工作人员，也不能看到内部队列、审核意见和分派过程。”

必须拆两个 IR。

### IR-A｜xn：内部运行编排层

```yaml
actor: 城市救助中心平台运营与流程设计方
object: 救助任务从接单到复查的内部运行方式
object_layer: internal_operation_orchestration_layer
current_window: 待处理队列 -> 分派 -> 上传记录 -> 审核 -> 复查/退回，按日重复
changed_variable: operational_coordination_structure
relation_source: actor_generated_internal_workflow
relation_shape: multi_stage_internal_orchestration_with_retry
 decision_right: workflow_design_and_internal_routing
path_set:
  - intake_queue
  - assign_to_district_worker
  - upload_case_record
  - supervisor_review
  - recheck_queue
  - failed_case_return_to_previous_handler
reentry_right: null
future_endpoint: case_reaches_reviewed_or_reopened_state
reality_anchor: 内部任务每天依赖队列、分派、记录、审核和退回节点持续跨阶段运行
```

判定：`xn candidate PASS`。

### IR-B｜x并z：公共调用界面层

```yaml
actor: 城市救助中心公共网页维护方
object: 救助中心对公众的求助提交与状态查询入口
object_layer: public_addressability_interface_layer
current_window: 公开网页持续可用 -> 首次市民访问 -> 提交求助编号/查询状态
changed_variable: public_mapping_or_addressability
relation_source: stable_public_shell
relation_shape: external_caller_to_public_shell_to_internal_service
 decision_right: interface_only_nonfinal
path_set:
  - public_identifies_official_page
  - first_time_citizen_submits_request_id
  - citizen_queries_case_status
reentry_right: null
future_endpoint: null
reality_anchor: 不需要既有私人关系的市民可稳定找到并调用官方页面，但不能看到或控制内部流程
```

判定：`x并z candidate PASS`。

注意：同一个软件产品可以同时承载两套结构，但必须按 object_layer 与 caller population 分账，不能因为“都是同一个平台”而一个 IR 双贴。

## 4. Positive decision gate

### xn positive gate

同时满足：

1. tested object 是内部运行方式，而不是公共入口本身；
2. `current_window` 至少出现两个不同类型的内部状态/节点；
3. `path_set` 存在真实 handoff / queue / review / record / retry / allocation 等程序元素；
4. actor 对这些节点存在生成、编排、维护或重组作用，而不是单纯沿外部固定 SOP；
5. 机制在 current window 被重复调用，或至少形成明确跨阶段可持续结构；
6. removal 一个关键内部节点会使运行连续性、状态转移或责任交接出现可命名缺口。

### x并z positive gate

同时满足：

1. tested object 是稳定公共壳/公共映射/对外入口；
2. caller population 至少包含无需预先私人关系的第三方；
3. `relation_shape` 明确为 external caller -> stable shell -> internal object/service；
4. `path_set` 至少存在 identify / call / submit / enter / attribute / public-route 之一；
5. 公共壳可重复依赖，不是一次私人转发、临时二维码或偶然口碑；
6. interface operator 不需要拥有内部最终裁定、处分或流程设计权。

## 5. nearest-neighbor 最小差异

### xn vs x并z

```text
xn：这个系统怎样让内部工作跨阶段持续跑下去？
x并z：外部第三方怎样通过稳定壳找到、调用或进入这个对象？
```

最小差异 1：

```text
只有内部员工登录的任务控制台
+ 队列/审核/退回稳定运行
→ xn ↑
→ x并z 不因“控制台”成立
```

最小差异 2：

```text
公开网页只有“提交/查询”两个动作
+ 内部全部人工临时处理，无固定流程
→ x并z ↑
→ xn FAIL/弱
```

### xn vs nx

```text
xn：主体生成/重组内部运行结构。
nx：主体不占最终方向，沿外部已有路线、许可或通道推进。
```

### x并z vs n

```text
x并z：内 -> 外映射，使对象被外部识别/调用/进入。
n：外 -> 内纳入承载，使对象进入内部并持续被承担。
```

## 6. false-positive guards

1. “平台/系统/门户/工作台/中台”都是名词诱导，不产十元。
2. 有 UI 不等于 x并z；纯内部 UI 可以只是 xn 载体。
3. 有多步骤页面不等于 xn；若只是公共表单分页，不代表内部运行结构。
4. 公共网页被大量访问不等于 xn。
5. 内部流程复杂不等于 x并z。
6. 登录账号不等于公共 caller；预绑定员工账号通常是内部身份。
7. “用户”一词必须先区分内部 operator / 已注册成员 / 任意第三方。
8. “服务台”若靠人工逐次私人接洽、没有稳定公共 mapping，不自动 x并z。
9. “自动化”不自动 xn；一次自动按钮不构成跨阶段运行结构。
10. `x并z FAIL` 不推出 `xn PASS`；`xn FAIL` 不推出 `x并z PASS`。
11. 去年有公开入口、今年仅内网，不继承旧 x并z。
12. 去年有完整工作流、今年改为临时聊天，不继承旧 xn。

## 7. adversarial tests

### T1｜关键词诱导

输入：“这是我们的统一工作台，所有事情都在这里办。”

事实：只有一个静态链接页，内部靠微信群临时协调，外部也不可访问。

预期：`xn FAIL/UNKNOWN`；`x并z FAIL`。

### T2｜题材/职业/情绪诱导

输入：神秘情报局拥有“中央情报平台”，操作员神情冷酷、全天值守。

事实：平台只显示静态公告，既无任务状态流转，也无公共第三方入口。

预期：题材、职业、气氛均不得倒推；两端 FAIL/UNKNOWN。

### T3｜对象层错位

输入：医院内部护士使用排班/交接/复核系统；病人通过官网查询门诊地址。

预期：内部工作层查 `xn`；公共地址映射层查 `x并z`；禁止共用 object_layer。

### T4｜时间窗错位

输入：去年官网开放公众报修并有自动工单流转；今年官网关闭，只保留员工内网工单流程。

预期：当前 `xn` 可保持；当前 `x并z` 不得继承去年状态。

### T5｜同关系词异对象层

输入：“进入平台”A=员工进入任务审核队列；B=陌生市民进入公开报修页。

预期：A 只触发内部运行层审计；B 只触发公共调用层审计。“进入”不能共享标签。

### T6｜对端不存在不等于本端成立

输入：旧门户下线，旧流程也停用，所有请求改成电话临时处理。

预期：`xn FAIL/UNKNOWN`；`x并z FAIL/UNKNOWN`。一端消失不证明另一端成立。

### T7｜稳定内部平台伪 x并z

输入：银行内部风控台稳定运行十年，只有预绑定员工可登录，拥有队列、复核、退回和记录。

预期：`xn PASS`；仅凭“稳定平台”不得锁 x并z。

### T8｜稳定公共壳伪 xn

输入：博物馆官网允许任何游客查询开放时间和下载地图，内部排班全靠馆长每天口头安排。

预期：`x并z PASS`；`xn FAIL/弱`。

### T9｜多页面伪 xn

输入：保险官网理赔表单有十页，但提交后由一个员工手工处理到底，无内部状态、handoff、复核或记录结构。

预期：页面步骤多不等于 xn；可查 x并z，xn FAIL/弱。

### T10｜内部账号伪公共 caller

输入：供应链“供应商门户”只有已签约并预绑定的供应商账号可见，且每家账号由内部管理员逐个开通；系统主要组织内部审批链。

预期：caller population 不是开放第三方，x并z 证据弱；内部审批链可查 xn。

### T11｜同平台双功能

输入：城市救助平台既有公开求助入口，又有内部队列/分派/审核/退回。

预期：强制 `SPLIT_IR`；公共层 x并z PASS，内部层 xn PASS；理由与 path_set 不得共用。

### T12｜最小 mutation

冻结 `actor/object/current_window` 的业务事件身份，仅改变 `object_layer + relation_shape + path_set + reality_anchor`：

A：
```text
internal_operation_layer
inside->inside handoff
queue/review/retry
→ xn ↑ / x并z ↓
```

B：
```text
public_addressability_layer
outside->stable shell->service
identify/submit/query
→ x并z ↑ / xn ↓
```

若模型因“都是平台”而同时维持双端分数，视为解释器失败。

## 8. removal / reverse / same-layer / current-window

### Removal A：删除公共入口

保留内部队列、分派、审核、退回，只关闭公开网页。

预期：

```text
xn 保持
x并z ↓
```

### Removal B：删除内部编排

保留官网提交/查询，但后台改成一个员工从头人工处理，无队列、handoff、复核。

预期：

```text
x并z 保持
xn ↓
```

### Reverse check

- “系统有十个模块”但全部只是公共信息页面：不得因模块多判 xn。
- “内部流程每天自动跑”但任何外部第三方无法识别/进入：不得因系统稳定判 x并z。

### Same-layer check

```text
public entry layer != internal orchestration layer
```

同一软件、同一品牌、同一域名不代表同一 object_layer。

### Current-window check

必须以当前仍实际运行/可调用的层为准。历史门户与历史工作流分别过期，禁止沿名称继承标签。

## 9. 状态迁移规则

新增两条独立状态轨：

```text
INTERNAL-ORCHESTRATION:
ad_hoc_manual_coordination
→ explicit_queue_or_state_nodes
→ repeated_handoff_and_recording
→ resilient_retry/review_cycle
= xn evidence ↑
```

```text
PUBLIC-ADDRESSABILITY:
private_or_ambiguous_contact
→ stable_public_shell
→ repeatable_external_call
→ third_party_reliance_on_public_mapping
= x并z evidence ↑
```

核心不变量：

```text
xn ↑ != x并z ↑
x并z ↑ != xn ↑
shared software artifact != shared semantic IR
```

## 10. 本轮成功门判断

本轮不是重复已有机制，新增至少四项解释器资产：

1. `CALLER-POPULATION_AUDIT_REQUIRED`；
2. `INTERFACE-DIRECTION_AUDIT_REQUIRED`；
3. `PATH-SET-SEMANTIC-TYPE_AUDIT_REQUIRED`；
4. 同一软件 artifact 强制按 `public entry layer / internal orchestration layer` 拆 IR 的状态与 removal 规则。

因此：`PASS`。
