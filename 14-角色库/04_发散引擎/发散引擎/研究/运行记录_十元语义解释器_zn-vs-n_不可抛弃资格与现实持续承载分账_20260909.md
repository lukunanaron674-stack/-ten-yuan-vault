# 十元语义解释器｜zn vs n｜不可抛弃资格与现实持续承载分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0｜本轮成功门

现有 canonical 已有概念级最近邻：`zn`回答“什么不可被抛下、为什么”，`n`回答“谁被接住并怎样留下”。本轮若只重复这句话则失败。

本轮新增价值限定为：

1. 把自然语言中的“接纳 / 照顾 / 尊重 / 不抛弃 / 留下”拆成 Semantic IR 的不同证据角色；
2. 新增 `PROTECTED-STATUS-vs-CARRYING-LOAD` 分账；
3. 规定 `path_set` 在 `zn` 与 `n` 中的成员语义类型不得混装；
4. 规定“受保护对象”“现实承载对象”“负荷承担者”必须分别审计，不能默认同一主体；
5. 增加 removal / reverse / same-layer / current-window 与 adversarial negatives。

若以上不能成立，本轮不得提交。

## 1｜翻译债务

高危自然语言：

```text
“我接纳你。”
“我不会抛下你。”
“我会一直照顾你。”
“我尊重你，所以让你留下。”
“这里永远有你的位置。”
“无论多麻烦，我都得管你。”
```

这些句子至少可能落到四种结构：

```text
A. 原则上认定某对象不可被抛弃 / 不应因利益变化失去资格
   → normative protected status / conflict ranking
   → 查 zn

B. 对象现实进入内部并跨阶段占用空间、时间、资源、照护、风险或协调成本
   → sustained carrying load
   → 查 n

C. 只有礼貌、情绪、态度、口号，没有现实权利或负荷事实
   → UNKNOWN / NEEDS_MORE_STRUCTURE

D. 同一事件同时存在 A 与 B
   → SPLIT_IR
```

新增硬约束：

```text
normative_non_abandonment
!=
operational_admission_and_carrying

protected_status
!=
internal_position

moral_or_internal_reason
!=
recurring_load_bearer
```

## 2｜自然语言 → IR 结构还原规则

### 2.1 先问“句子里的对象到底被改变了什么”

若 changed variable 是：

```text
对象是否仍值得被保留 / 不应被抛弃 / 在冲突中仍有资格进入判断
```

优先构造 `zn` IR。

若 changed variable 是：

```text
对象是否真实进入内部、获得位置、并产生被持续处理的现实负荷
```

优先构造 `n` IR。

以下写法一律视为未完成解析：

```yaml
changed_variable: acceptance
changed_variable: care
changed_variable: respect
changed_variable: responsibility
changed_variable: relationship_quality
```

必须继续拆成具体结构。

### 2.2 PROTECTED-OBJECT / CARRIED-OBJECT / LOAD-BEARER 三分

新增审计：

```text
PROTECTED-OBJECT_AUDIT_REQUIRED
CARRIED-OBJECT_AUDIT_REQUIRED
LOAD-BEARER_AUDIT_REQUIRED
```

解释器不得默认：

```text
被原则保护的对象
=
现实进入内部的对象
=
承担负荷的人
```

例：一个医生坚持“病人不能因贫困被拒诊”，这可支持原则层 `zn`；但若病人实际由另一家医院住院、供药、值守，则当前医生/机构未必有 `n`。

### 2.3 path_set 成员类型

`zn.path_set` 应描述**冲突行动候选及原则排序**，例如：

```text
abandon_patient_for_cost_saving: normatively_rejected
continue_treatment_despite_cost: principle_preferred
```

`n.path_set` 应描述**持续承载通道**，例如：

```text
bed_space
night_shift
meal_supply
medicine_storage
referral_coordination
```

新增约束：

```text
NORMATIVE-ALTERNATIVE-RANKING
!=
RECURRING-LOAD-CHANNELS

一个 Semantic IR 的 path_set 不得把“为什么不能抛下”和“每天具体承担什么负荷”混成同一成员类型。
```

同一事件同时成立时必须 `SPLIT_IR`。

### 2.4 reality_anchor 证据类型分账

`zn` 的现实锚点优先要求：

- 无奖励、无观众、无外部强迫时仍调用原则；
- 在真实利益冲突中，原则改变候选排序；
- 暂时无法执行时，仍保留未来指导资格。

`n` 的现实锚点优先要求：

- 对象真实进入并留在内部；
- 存在跨阶段 recurring load；
- 能指出谁支付时间、空间、资源、风险、护理、维护或协调成本。

一次口头承诺不能替代任一端完整 reality anchor。

## 3｜标准输入句

> 洪水后，社区中心接收八名无处安置的独居老人。负责人林澈一直坚持“不能因为他们麻烦、没钱或没有家属就把他们赶出去”；即使上级没有表扬、媒体也不在场，他仍拒绝了“先清退最费资源老人”的方案，并认为以后遇到同类情况仍应按这一标准判断。与此同时，八名老人连续四周住在中心，夜间值守、餐食、药品冷藏、清洁、慢病登记和转诊联络都由中心持续承担。

必须 `SPLIT_IR`。

## 4｜完整 IR-A：zn

```yaml
actor: 林澈
object: “不能因麻烦、贫困或无家属而把已接纳老人清退”这一内部原则
object_layer: internal_principle_and_protected_status_layer
current_window: 原则已存在 -> 资源压力上升 -> 出现清退高负荷老人的候选 -> 无媒体/奖励时仍拒绝 -> 未来仍保留调用资格
changed_variable: protected_status_and_future_principle_guidance_eligibility
relation_source: actor_internalized_nontransferable_principle
relation_shape: internal_principle_preserves_protected_status_and_ranks_competing_actions_under_cost_pressure
decision_right: principle_has_internal_conflict_ranking_and_future_guidance_eligibility
path_set:
  - clear_high_cost_elderly_first: normatively_rejected
  - retain_equal_non_abandonment_standard: principle_preferred
reentry_right: null
future_endpoint: 同类资源冲突再次发生时该原则仍有资格进入判断
reality_anchor: 没有媒体、奖励或上级表扬时，林澈仍拒绝按成本清退老人，并明确该标准以后仍应继续指导同类决策
```

判定：`zn PASS`。

注意：这里不是因为“老人真的住了四周”而判 `zn`，而是因为**原则在真实冲突中保存了对象不可随成本变化被抛弃的资格，并保留未来指导权**。

## 5｜完整 IR-B：n

```yaml
actor: 社区中心
object: 八名已进入中心的独居老人及其持续生活与医疗支持需求
object_layer: sustained_internal_carrying_layer
current_window: 老人入住 -> 连续四周留在中心 -> 每日食宿/值守/药品/清洁/登记/转诊持续发生
changed_variable: sustained_internal_carrying_load
relation_source: emergency_admission_and_continuing_support
relation_shape: admitted_people_remain_inside_while_recurring_named_load_is_actually_borne
decision_right: bounded_care_execution_without_person_disposition_right
path_set:
  - night_staffing
  - meal_provision
  - medicine_refrigeration
  - sanitation
  - chronic_condition_registry
  - referral_coordination
reentry_right: null
future_endpoint: 安全安置或正式转介完成后结束当前承载
reality_anchor: 八名老人连续四周真实住在中心，值守、餐食、药品、清洁、登记与转诊成本每天由中心持续承担
```

判定：`n PASS`。

注意：这里不是因为“负责人认为老人不可抛弃”而判 `n`，而是因为对象**现实进入内部且持续制造可命名负荷，并存在明确 bearer**。

## 6｜positive decision gate

### 6.1 zn positive gate

至少同时满足：

```text
1. 原则命题 / 意义对象明确；
2. tested actor 内部认为其不可轻易让渡；
3. 存在真实冲突候选；
4. 原则实际排序候选，而非只说好听的话；
5. 拿掉奖励、观看、称赞或当前利益后，原则仍进入判断；
6. 条件变化后仍保有 future guidance eligibility；
7. reality_anchor 指向“原则怎样改变选择”，而不是只指向“对象被照顾”。
```

### 6.2 n positive gate

至少同时满足：

```text
1. carried object 明确；
2. 对象真实进入主体/结构内部；
3. 获得跨阶段位置而非一次停留；
4. 产生可命名 recurring load；
5. load bearer 明确；
6. bearer 现实处理该负荷；
7. reality_anchor 指向跨阶段资源/时间/风险/护理事实，而不是只指向“不抛弃”的宣言。
```

## 7｜nearest-neighbor 最小差异

### 差异 1：原则存在，但对象不由本主体承载

```text
医生坚持“任何急症病人都不能因没钱被拒绝”
但该病人实际住在另一家医院，由另一院持续供药与护理
```

- 医生原则层：`zn` 可查；
- 当前医生/机构对病人的 `n`：不能因此成立。

最小变化是**现实 bearer 改变**，原则可完全不变。

### 差异 2：对象被持续承载，但没有稳定不可抛弃原则

```text
旅馆按合同连续30天安置灾民，提供餐食、清洁和夜间值守；
合同到期后经营者认为“谁付费就接谁”，不存在不可抛弃标准。
```

- 现实承载：`n` 可 PASS；
- 稳定 `zn`：不能由“照顾得很久”自动生成。

最小变化是**原则资格不存在**，但 recurring load 可以完整存在。

### 差异 3：一次拒绝清退 vs 跨阶段承载

一次投票反对清退可作为 `zn` 行为证据，但不足以单独证明 `n`；一次把人收进来住一晚，也不足以稳定 `n`。

## 8｜false-positive guards

```text
“我接纳你” != n
“我尊重你” != zn
“我不会抛下你” != zn（若无冲突排序与未来资格）
“我会照顾你” != n（若无真实进入与 recurring load）
对象长期留在内部 != zn
存在强原则 != n
善良 / 温暖 / 家庭感 != zn 或 n
一次救援 != stable n
一次牺牲 != stable zn
承担很多成本 != 自动证明“不可抛弃”原则
认为某人不可抛弃 != 自动证明自己正在承担其现实负荷
zn FAIL != n PASS
n FAIL != zn PASS
```

## 9｜Removal / Reverse / Same-layer / Current-window

### 9.1 Removal：删原则，保留承载

把林澈的原则改成：

> “只要政府合同继续付费就接，合同结束即可全部转走。”

但四周食宿、药品、值守仍真实发生。

预期：

```text
zn ↓ / UNKNOWN
n 保持
```

### 9.2 Removal：删承载，保留原则

社区中心当天把老人安全转给长期护理院，不再承担后续食宿与护理；林澈仍坚持并持续实践“不因贫困拒绝老人”的原则。

预期：

```text
当前中心对老人 n ↓
林澈原则层 zn 可保持
```

### 9.3 Reverse

把“清退高成本老人 = normatively rejected”反转成“成本过高即可优先清退”，若该变化是稳定原则改判，则旧 `zn` evidence 下降；但老人若仍由中心实际住养两周，`n` 可暂时保持。

反过来，护理负荷从高降到低甚至转交，只影响 `n` 当前承载强度，不自动重写原则正确性。

### 9.4 Same-layer

强制区分：

```text
internal_principle_and_protected_status_layer
!=
sustained_internal_carrying_layer
```

同一对象“老人”在物理世界是同一批人，Semantic IR 仍必须按**对象被赋予的关系角色**拆层。

### 9.5 Current-window

去年长期照护过某人，不证明今年仍有 `n`；去年坚持“不抛弃”但今年已经稳定改判，也不应继承旧 `zn`。

历史情感与历史服务都不能替代 current-window 重新抽取。

## 10｜Adversarial tests

### T1｜关键词诱导

输入：
> “我永远接纳你、照顾你、尊重你，绝不抛弃。”

无进入、负荷、冲突排序或未来资格事实。

预期：`zn UNKNOWN / n UNKNOWN`。

### T2｜题材 / 职业 / 情绪诱导

输入：
> 慈祥修女在孤儿院抱着孩子落泪，说“这里就是你的家”。

没有跨阶段负荷和真实原则冲突事实。

预期：不得因修女、孤儿院、温情判 `zn/n`。

### T3｜对象层错位

输入：
> 医生坚持不能拒诊贫困患者；患者随后由另一医院住院并承担全部照护。

预期：医生原则层 `zn candidate/PASS` 需完整证据；当前医生/本院对该患者 `n FAIL/UNKNOWN`。

### T4｜时间窗错位

输入：
> 去年中心连续照护居民三个月；今年中心已经关闭，也明确取消原“不抛弃”政策。

预期：当前窗口不得继承旧 `n` 或旧 `zn`。

### T5｜同关系词异对象层

输入：
> “我们要接住他”：第一句指“即使他失败也不能取消成员资格”；第二句指“让他住进宿舍并承担每日护理”。

预期：第一句优先查 protected-status / `zn`；第二句优先查 carrying / `n`；强制 `SPLIT_IR`。

### T6｜对端不存在不等于本端成立

输入：
> 社区既没有原则，也没有真正收留，只把求助者转给外部热线。

预期：`zn FAIL/UNKNOWN` 且 `n FAIL`。不能因一端不存在反推另一端。

### T7｜长期合同承载伪 zn

输入：
> 商业机构按付费合同连续半年提供住宿、餐食、护理，但明确“欠费即按合同转出”，不存在不可抛弃原则。

预期：`n PASS` 可成立；`zn` 不自动成立。

### T8｜强原则伪 n

输入：
> 律师长期坚持“不让任何未成年人失去申诉资格”，但所有儿童都住在各自家庭，律师不承担食宿、照护或内部位置。

预期：原则层 `zn` 可查；`n FAIL`。

### T9｜一次救援伪 n

输入：
> 一名路人把伤者从路边送到医院后离开。

预期：一次帮助不足以稳定 `n`；也无稳定 `zn` 证据。

### T10｜一次高成本牺牲伪 zn

输入：
> 负责人临时多花十万元救助一名成员，但事后说“以后成本太高就直接放弃”。

预期：高成本行为不自动证明稳定 `zn`；若对象确实跨阶段被持续承载，可另查 `n`。

### T11｜同事件双层成立

输入：
> 主体无监督时拒绝按成本清退成员，并连续六周真实承担成员食宿与治疗。

预期：`zn PASS + n PASS`，但必须两个 IR，不得共享 changed_variable/path_set。

### T12｜最小 mutation

A：
> “原则保持不变，但后续全部照护转给独立机构。”

预期：原主体 `zn` 可保持；当前 `n ↓`。

B：
> “照护完全不变，但主体稳定改为‘成本高即可优先清退’。”

预期：`n` 可保持；旧 `zn ↓`。

mutation 后必须重新抽取完整 IR，不得继承旧字段值。

## 11｜状态迁移规则

### 11.1 zn 轨

```text
mere_kindness_or_slogan
→ explicit_internal_principle
→ principle_ranks_real_conflict
→ no_reward_still_guides
→ future_guidance_eligibility_persists

= zn evidence ↑
```

### 11.2 n 轨

```text
object_outside
→ admitted_once
→ stable_internal_position
→ recurring_named_load
→ persistent_load_with_identifiable_bearer

= n evidence ↑
```

关键不变量：

```text
zn ↑ != n ↑
n ↑ != zn ↑

principle protects object
!=
actor currently carries object

actor carries object
!=
actor regards object as normatively non-abandonable
```

## 12｜本轮结论

通过成功门。新增内容不是案例扩张，而是 Semantic IR 约束：

1. `PROTECTED-OBJECT / CARRIED-OBJECT / LOAD-BEARER` 三分审计；
2. `zn.path_set = normative alternative ranking`，`n.path_set = recurring load channels`；
3. “接纳/照顾/尊重/不抛弃”不得直接进入 `changed_variable`；
4. 同一实体不同关系角色必须 SPLIT_IR；
5. 原则资格和现实承载具备可独立 removal / reverse 的状态轨。

## 13｜下一轮候选风险

本轮占用 `zn` 与 `n`，下一轮不得连续选择这两个十元。

下一高风险候选建议优先检查：`x并z vs nx`。

高危自然语言：

> “外面的人都通过这个入口来找我 / 我也一直靠这个入口和关系办事。”

需要区分：

```text
x并z：内部对象是否通过稳定公共壳被外部第三方识别、调用或进入？

nx：tested actor 是否不占最终方向，沿既有外部关系、权限或通道续接推进？
```

两者都会出现“接口 / 通道 / 入口”词，但一个是**公共映射结构**，另一个是**行动依赖结构**。必须重点审 `actor + relation_source + relation_shape + decision_right + path_set`。
