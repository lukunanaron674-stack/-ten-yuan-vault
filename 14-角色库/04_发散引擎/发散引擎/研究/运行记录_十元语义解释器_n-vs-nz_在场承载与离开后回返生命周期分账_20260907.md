# 十元语义解释器｜n vs nz｜在场承载与离开后回返生命周期分账

> 研究层候选。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不得修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1｜本轮翻译债务

现有解释器已经分别锁过：

- `n`：对象进入内部后，被跨阶段持续承载；
- `nz`：对象特异回返空间必须现实可执行，不能靠“欢迎回来”或单方怀念。

但两者中间仍缺一个阶段边界。自然语言里的“接住、一直留位置、每次都回来、永远有家、周末回来、反复返回”会让模型把以下三种结构混成一件事：

```text
A. 对象一直处于承载结构内部，只是内部阶段变化；
B. 对象真实自由退出了承载/关系边界，回返资格仍在线；
C. 对象离开后只能重新申请、靠第三方批准或进入新对象，并非回到原对象特异关系。
```

因此本轮新增解释器规则：

**n 的 primary evidence 位于 `present/inside` 阶段；nz 的 primary evidence 必须跨越 `voluntary_exit -> reentry_available/restored -> return/repair` 边界。**

“反复回来”只有在真实跨出被测对象层之后才可给 nz 加证据；同一承载系统内部的房间切换、短时离床、轮班、转区、暂存，不得伪装成 nz lifecycle。

## 2｜新翻译规则：PRESENT-CARRYING-vs-EXIT-REENTRY-LIFECYCLE-v0.1

固定 Semantic IR 字段不扩展。本轮只规定如何在现有字段中编码阶段状态。

### STEP 1｜先冻结对象层

先回答：

- 被测试的是“内部承载关系”本身，还是“离开后重入原关系/位置的资格”？
- 离开是否真的跨出该 `object_layer`？

如果只是同一医院从病房转检查室、同一家庭成员去上班后回家、同一系统账号短时离线，不能因为字面“离开/回来”自动切到 nz。

### STEP 2｜从 current_window 提取生命周期边界

允许在 `current_window + relation_shape + path_set + reentry_right` 中编码以下状态，不新增 IR 字段：

```text
OUTSIDE
ADMITTED
INSIDE_CARRIED
VOLUNTARY_EXIT
REENTRY_AVAILABLE
REENTRY_RESTORED
RETURN_EXECUTED
RELATION_REPAIRED
```

关键分流：

```text
OUTSIDE -> ADMITTED -> INSIDE_CARRIED
= n primary lifecycle

INSIDE_CARRIED -> VOLUNTARY_EXIT
-> REENTRY_AVAILABLE / RESTORED
-> RETURN_EXECUTED / RELATION_REPAIRED
= nz primary lifecycle
```

### STEP 3｜changed_variable 分流

```text
internal_position_continuity / sustained_load_carrying
-> 查 n

object_specific_reentry_space / repairable_relation_position
-> 查 nz
```

若一句话横跨两段，则 `SPLIT_IR`，不要把 n 的“仍给床位/饭”当作 nz 的“离开后可自由返回”，也不要把 nz 的“可回返”倒推成当前内部一定有人持续承载。

### STEP 4｜自由退出硬门

`nz` 不是“没被赶走”，而是被测对象在 current window 中存在真实退出或可验证自由退出资格，并且退出后回返关系仍不被自动毁灭。

若退出会遭惩罚、失去生存条件、被扣资源、必须重新竞争一个新位置，优先查 `x/xn/zx/nx` 等结构，不能把“最后又回来了”自动写成 nz。

### STEP 5｜重复返回归属审计

同样是“每天回来”：

- 每天结束外部活动后回到长期家庭关系，若家庭关系从未因离开而失去，且双方自由性与对象特异性有证据，可查 nz（日常停靠型）；
- 医院病人每天从病房去治疗室再回床位，仍在同一照护边界内，主要仍是 n；
- 临时工每天重新经过经理批准才能进场，更像外部许可 route，不能仅凭“回来”锁 nz。

### STEP 6｜reality_anchor 分账

```text
n reality_anchor:
对象在 inside/present 阶段持续占用并获得时间、空间、资源、照护、风险或协调处理。

nz reality_anchor:
对象跨出被测关系/位置后，原对象特异 reentry path 仍可现实调用，或冲突后被真实恢复/重建并完成重新接近。
```

## 3｜标准输入与完整 IR

输入：

> “青年公寓接收十二名实习生连续住三个月，工作人员每天维护床位、餐食、门禁和冲突协调。实习生周末可以自由离开，不会因此失去原房间和成员资格；任何一人周日晚都能直接刷原门禁回来，不需要重新申请，阿青已经多次这样离开后返回。”

必须 SPLIT_IR。

### IR-A｜在场持续承载

```yaml
actor: 青年公寓运营方
object: 连续居住的十二名实习生
object_layer: 公寓内部居住与持续负荷承载层
current_window: 入住 -> 三个月持续居住 -> 每日床位餐食门禁与冲突协调
changed_variable: sustained_load_carrying
relation_source: internal_carrier
relation_shape: admitted_then_carried_across_present_stages
decision_right: admission_and_internal_support_within_program_rules
path_set:
  - assigned_bed
  - daily_meal_support
  - active_access_control
  - conflict_coordination
reentry_right: not_primary_for_inside_phase
future_endpoint: end_of_residency_term
reality_anchor: 实习生在住期间持续占用床位、餐食、门禁和协调资源，运营方每日现实处理这些负荷
```

判定：**n candidate PASS**。

### IR-B｜自由退出后的对象特异回返

```yaml
actor: 实习生与青年公寓之间的成员关系
object: 原房间与原成员关系的回返资格
object_layer: 周末离开后的原成员位置重入层
current_window: INSIDE_CARRIED -> 周末自愿离开 -> 原资格保持 -> 周日晚直接返回 -> 阿青多次完成重入
changed_variable: object_specific_reentry_space
relation_source: standing_membership_boundary
relation_shape: voluntary_exit_then_direct_reentry_to_same_relation_position
decision_right: each_member_direct_reentry_within_valid_membership
path_set:
  - leave_freely_for_weekend
  - retain_original_room_and_membership
  - direct_reentry_with_original_access
reentry_right: object-specific-direct-executable-during-valid-term
future_endpoint: null
reality_anchor: 离开不取消原房间或成员资格，阿青无需重新申请即可多次刷原门禁返回
```

判定：**nz candidate PASS**。

同一机构可以同时有 n 与 nz，但证据必须来自不同生命周期段：

```text
在里面时被持续接住 -> n
真实离开后原关系仍可直接回来 -> nz
```

## 4｜Positive decision gates

### n candidate gate

至少要求：

1. actor/object/object_layer/current_window 明确；
2. 对象真实进入内部并获得可持续位置；
3. inside/present 阶段跨至少两个时间点，或存在重复现实负荷；
4. path_set 中存在现实处理/补给/保护/照护/内部协调；
5. reality_anchor 证明对象留下导致的负荷由 actor/structure 持续处理；
6. 物理在场、拘禁、一次接待、一次救援均不足。

### nz candidate gate

至少要求：

1. 对象特异关系/位置明确；
2. current_window 含真实 `VOLUNTARY_EXIT`，或有可验证自由退出资格，而不是被迫留置；
3. 离开不自动销毁原对象特异关系位置；
4. `reentry_right` 是 reality-executable，不是单方愿望、礼貌承诺或第三方一次施舍；
5. path_set 中存在回到**原对象/原关系层**的现实路径，而非申请一个新对象；
6. stable relation nz 仍需双方性/可信共同关系证据；
7. reality_anchor 证明返回或修复真实发生，或重入权已被现实可调用地保持；
8. `n PASS` 本身不能替代 NZ2-NZ7。

## 5｜nearest-neighbor 最小差异

### n vs nz

```text
n：对象在里面时，结构是否持续接住并承担其负荷？
nz：对象可以真实离开以后，原对象特异关系/位置是否仍允许可信返回与修复？
```

最小差异：

- “住得很好但一离开资格作废”可 n 强、nz 弱/FAIL；
- “平时不提供持续照护，但成员离开后可随时回到原合作关系”可 nz 强、n 不一定成立。

### nz vs nx

```text
nz：原对象特异 reentry path 已经稳定属于关系结构，主体可现实调用。
nx：回返仍必须沿第三方批准、临时安排或外部许可 route。
```

“领导每次特批你回来”不能因为最后成功返回就自动 nz。

### n vs x

```text
n：主体承担对象留下后的负荷，使对象能继续在内部存在。
x：主体掌握对象的使用、调用、排除或处分边界。
```

禁止对象退出、扣证件、扣资源可以造成“长期留在里面”，但那不是 n 的自由承载，更不是 nz 的可信停靠。

## 6｜false-positive guards

1. **关键词诱导**：“家永远接住你”“随时回来”都只是触发抽取，不是标签。
2. **反复返回诱导**：在同一 object_layer 内移动后回来，不等于 nz。
3. **持续照护诱导**：n 很强不自动推出 nz；若自由退出后资格即失效，nz 可 FAIL。
4. **回返成功诱导**：一次靠高层特批回来，不等于 stable nz。
5. **预留位置诱导**：一直留一张床，但离开者没有现实重新进入资格，不足以锁 nz。
6. **物理内部诱导**：被关押、扣留、无法退出，不等于 n 或 nz。
7. **对象替换诱导**：离开原团队后可去任何相似团队，不是回到原对象特异关系。
8. **对端缺席护栏**：n FAIL 不推出 nz；nz FAIL 不推出 n。
9. **历史连续性诱导**：以前长期承载/以前能返回，不代表当前窗口仍在线。
10. **关系词诱导**：“家人、成员、朋友、病人、住客”都不能替代 `path_set + reality_anchor`。

## 7｜removal / reverse / same-layer / current-window

### n removal

拿掉 inside 阶段的 recurring support/carrying paths：若对象仍物理在场，但床位、餐食、风险、照护、协调等负荷不再由 actor 处理，则 n 应显著下降；nz 另判。

### nz removal

拿掉 voluntary-exit 后的 original-object reentry path：若对象离开后必须重新申请、重新竞争、靠第三方临时特批，原 nz attribution 应下降；inside 阶段的 n 可以完全不受影响。

### reverse

- 保留“这里永远是你的家”，但一旦离开即注销成员资格：可 n PASS（在住阶段），nz FAIL。
- 保留高质量长期承载，但禁止自由退出：n 需继续检查是否其实是控制/拘禁，nz FAIL。
- 保留“每周回来”字样，但所有移动都发生在同一照护结构内部：主要查 n，不得用字面 return 判 nz。
- 让内部资源支持全部停止，但保留双方对象特异、可自由离开并直接回到原关系的权利：n 下降，nz 可继续 PASS。

### same-layer

不得把“住在公寓期间的内部支持层”和“周末离开后的成员回返资格层”揉成一个 changed_variable。可以同 actor、同 object family，但生命周期问题不同，应 SPLIT_IR。

### current-window

- n 必须看当前 inside/present 阶段，过去被接住不能永久贴标；
- nz 必须看当前离开/重入结构，过去可以回来但现已注销资格不得沿用；
- 若 current_window 只覆盖在场阶段，`reentry_right` 缺证据时保持 unknown，不准因“家”猜 nz；
- 若 current_window 只覆盖离开后的回返资格，不能因关系亲密反推当前有持续负荷承载 n。

## 8｜Adversarial tests

### T1｜关键词诱导
输入：
> “经理说这里永远是你的家，随时欢迎回来。”但员工离职即永久注销原岗位，重新入职必须参加公开招聘。

预期：**nz FAIL**；“家/回来”只是词，原对象特异 reentry path 已消失。若在职期间有持续内部承载，n 另判。

### T2｜题材/职业/情绪诱导
输入：
> 慈祥的养老院院长每天拥抱老人，但该院只做一日活动，下午全部送走，不提供持续位置；离开后下次需重新抽签。

预期：**n FAIL；nz FAIL**。慈祥、养老、拥抱都不提供结构证据。

### T3｜对象层错位
输入：
> 住院病人每天被医院持续照护；白天从病房去影像科，检查后回病房。

预期：**n PASS candidate；nz 不由“回病房”成立**。移动仍发生在同一医院照护边界内，没有真实跨出被测关系层。

### T4｜时间窗错位
输入：
> 去年宿舍允许毕业生三个月内直接刷卡回来取物，今年门禁政策改为毕业即注销，必须预约访客。

预期：当前窗口 **旧 nz 不得沿用**；是否有当前 n 取决于当前住户承载，不由去年政策决定。

### T5｜同关系词异对象层
输入：
> “孩子每天回家吃饭”与“维修工程师每天回服务器机房值班”。

预期：两句都有“回”。前者若存在对象特异家庭停靠、自由离返和现实关系证据，可查 nz；后者通常是工作排班/访问权限层，不能因“回”判 nz，需另查 xn/x/nx 等结构。

### T6｜对端不存在不等于本端成立
输入：
> 废弃宿舍已经关闭，里面没人住，旧住户也没有任何返回资格。

预期：**n FAIL；nz FAIL**。没有内部承载不等于存在回返关系，没有回返也不等于存在承载。

### T7｜持续承载但无自由回返
输入：
> 封闭训练营连续三个月提供食宿和医疗，但成员离营就永久失去资格，不能重返。

预期：若成员可自由离营且在营期间确有持续负荷处理，可 **n candidate PASS / nz FAIL**；若连自由退出都被禁止，则 n 还需排除拘禁/控制伪正例。

### T8｜第三方特批伪 nz
输入：
> 员工离职后原岗位取消；半年后董事长临时特批新设一个同名岗位让他回来。

预期：**stable nz FAIL/弱**。这是 third-party-dependent new route，需证明是否真为原对象特异关系重入；不能只因“回公司”判 nz。

### T9｜nz 强而 n 不足
输入：
> 两位自由职业者平时各自居住和工作，不互相提供持续照护；他们保留共同项目账号与双方无条件重返资格，分开数月后任一方都可直接重新加入原项目，且已实际发生。

预期：**nz candidate PASS；n 不由此成立**。有可信重返，不等于存在内部持续负荷承载。

### T10｜内部往返伪生命周期
输入：
> 护理院住客每天从房间到花园，再回房间，照护连续不断，成员资格从未中断。

预期：主要是 **n candidate**；`VOLUNTARY_EXIT` 未跨出被测护理关系层，不能把日常空间往返写成 nz reentry。

## 9｜通过/失败与信息增益

10 个 adversarial tests 均按预期完成结构分流。

本轮真实新增的信息增益不是新案例，而是：

1. **生命周期边界规则**：`n` primary evidence 位于 `inside/present`；`nz` primary evidence 必须跨 `voluntary_exit -> reentry/repair` 边界。
2. **同层返回伪正例护栏**：只有真实跨出被测 object_layer 的 exit，后续 return 才可作为 nz reentry evidence。
3. **连续承载与回返资格可独立存在**：n PASS 不推 nz；nz PASS 不推 n，并给出双向 removal。
4. **重复回来归属规则**：先审计“是否离开了关系层”，再解释“回来”；禁止把内部移动、排班回场、临时转区当 nz。
5. **原对象硬门**：回到新岗位/新团队/同类对象，不等于回到原对象特异关系。

以上属于新的 IR 字段约束、最近邻差异与 adversarial negative，满足成功门。

## 10｜给后续解释器/Z 发散器的接口摘要

```text
若 current_window 主要是：
OUTSIDE -> ADMITTED -> INSIDE_CARRIED
优先查 n：internal_position + recurring_load + reality_anchor。

若 current_window 主要是：
INSIDE/RELATION -> VOLUNTARY_EXIT -> REENTRY_AVAILABLE/RESTORED -> RETURN/REPAIR
优先查 nz：object-specific original relation + executable reentry + freedom + reality anchor。

若所谓“离开”没有跨出 tested object_layer：
不要把 return 词当 nz evidence。

若回来必须重新申请、重新竞争或第三方临时特批：
优先标 external/new-route，stable nz 降级；另查 nx/x 等。
```
