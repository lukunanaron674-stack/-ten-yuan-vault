# 十元解释器｜跨十元对抗测试 L4

> 只研究自然语言 → Semantic IR → 十元候选判定的翻译边界。不得覆盖 current canonical，不写行为 evidence，不直接写 Canvas。

## Audit 01｜n vs nx：承载对象 ≠ 沿外部方向推进

### 为什么当前风险最高

最近解释器研究刚锁定 `relation_source=external` 不能单独推出 nx，但仍缺少一个对 n 的交叉门。自然语言中的“接任务、接人、跟着安排、靠组织、留下、照顾”会让模型把两个完全不同的 changed_variable 混在一起：

- `n` 测：对象是否进入内部、获得持续位置、主体是否承担其持续负荷；
- `nx` 测：主体是否在 current_window、same object_layer 内真实沿外部方向/许可/关系通道推进。

最危险的不是二选一，而是同一 actor 同一事件可出现 **上位 nx + 下位 n**。因此必须禁止 whole-sentence collapse。

### 新 decision gate｜N-NX-LAYER-SPLIT-v0.1

```text
先问 changed_variable，再问 relation_source。

若 changed_variable = internal_admission / internal_position / sustained_burden / protection_continuity：
  转入 n gate；外部任务来源只作背景，不能把 n 吞成 nx。

若 changed_variable = direction_source / permission_route / external_solution_path / external_gate：
  转入 nx gate；“接住了人/物”只作背景，不能把 nx 吞成 n。

若同一 raw_input 同时存在两层：
  必须拆成两个 IR slice；禁止整句只出一个十元。
```

### 字段硬约束

```text
n-positive 最少要求：
- object_layer = internal membership / containment / care / load-bearing layer
- object 真实进入内部
- internal_position 可持续，而非一次经过
- reality_anchor 能证明持续负荷被主体处理
- removal internal position/continued handling -> n 显著下降

nx-positive 最少要求：
- object_layer = direction / permission / routing / task-progression layer
- relation_source ∈ {external, shared-with-external-gate}
- external path 在 current_window 内真实 activated
- decision_right 在 tested layer 非纯 self，或外部 gate 能现实卡住结果
- removal external route -> 同层推进出现现实缺口

禁止推理：
external source present -> nx
object stayed inside once -> n
n absent -> nx
nx absent -> n
```

## adversarial cases

### MP1｜同一句“接”字，changed_variable 最小差异

A. “社区按上级命令接收二十名灾民，负责人给每人安排床位、三餐和连续两周医疗照护。”
- task layer: relation_source=external, activated order=true → nx candidate
- resident layer: internal_position=true, sustained_burden=true → n candidate
- 预期：**分层双判**，不可只判 nx。
- error target: false-negative(n)

B. “社区按上级命令让二十名灾民在大厅登记后当天全部转送别处，本社区不提供持续床位或照护。”
- task layer nx 仍可成立；n 缺少持续内部位置/负荷。
- 预期：nx candidate / n FAIL。

最小差异：只移除 `内部持续位置 + 持续负荷`。

### MP2｜外部命令存在，但是否承接最小差异

A. “领导让小周负责仓库盘点，小周接受任务并按领导给定范围推进，缺领导确认就不能结项。”
- external route activated；reality_anchor=确认卡住结项。
- 预期：nx PASS；n 不因‘负责仓库’出现。

B. “领导让小周负责仓库盘点，小周当场拒绝并退出项目，之后没有沿任何领导给的路径推进。”
- external order present but not activated。
- 预期：nx FAIL/UNKNOWN；n FAIL。

最小差异：`task issued` 与 `task accepted/activated`。

### MP3｜同一收容空间，强制扣留 vs 承载

A. “避难所允许居民自由出入，长期提供床位、食物、药品，并在物资紧张时继续维持基本供给。”
- internal_position + sustained burden + non-coercive stay。
- 预期：n PASS；无外部推进证据则 nx UNKNOWN/FAIL。

B. “拘留点把人锁在房间里，不许离开，只提供最低限度看守。”
- inside=true，但 forced detention；不是 n。
- 预期：n FAIL；是否 x/其他另查。

最小差异：`被允许留下并承载` vs `被强制扣留`。

### MP4｜同 actor：上位 nx，下位执行不等于 n

A. “将军奉皇帝命令守城；他按命令守城，同时自己排兵、修墙、轮换岗哨。”
- task/direction layer: nx candidate
- execution structure: 转查 xn
- 没有‘对象进入内部并被持续承载’变量。
- 预期：n FAIL。

B. “将军奉皇帝命令守城；城外难民进入城内后，他给他们固定住处并持续承担粮食与医疗。”
- task layer nx；refugee load layer n。
- 预期：nx + n 分层并存。

最小差异：新增真正 `internal admission + burden`。

### MP5｜同样“靠关系”，路径是否进入行动链

A. “她认识院长，但本次住院按公开急诊流程完成，院长没有介入，也不能改变床位结果。”
- historical relation not in current path_set。
- 预期：nx FAIL；医院收治若仅一次处置，不足 n。

B. “她联系院长后，院长实际调配床位并批准进入专科病房；没有该接口当晚无法入院。”
- external route activated + removal gap。
- 预期：nx candidate；病房是否形成 n 要另查持续位置/负荷。

最小差异：`relation exists` vs `relation activated with reality anchor`。

### T6｜keyword lure：‘跟着别人’

“他每天跟着师父走路，但路线、目的和训练内容其实全由他自己决定，师父只是同行。”
- relation_source=self at tested direction layer；external actor merely present。
- 预期：nx FAIL。
- 若模型因“跟着师父”判 nx = false-positive。

### T7｜noun/genre lure：家庭 ≠ n

“这是一个温暖的大家庭，但成员遇到长期疾病时都会被立即送走，家里不承担照护、空间或资源负荷。”
- family noun/emotion lure；internal burden continuity absent。
- 预期：n FAIL。
- 错误型：false-positive(n)。

### T8｜profession lure：秘书 ≠ nx

“她是秘书，但项目预算、供应商选择和发布日期均由她最终决定；上级只能提供无约束建议。”
- decision_right=self；external advice non-blocking。
- 预期：nx FAIL。
- 错误型：false-positive(nx)。

### T9｜false-negative challenge：主动执行不能抹掉 nx

“董事会已锁定必须迁址，经理必须按该方向推进；经理随后独立设计搬迁流程、供应商和排期。”
- 高层 direction layer external gate = nx candidate；局部 execution structure 可 xn。
- 预期：不能因经理很主动而漏判 nx。
- 错误型：false-negative(nx)。

### T10｜false-negative challenge：外部任务不能抹掉 n

“护士按医院排班接手一名长期卧床病人；排班来源是外部，但她在病区连续数周承担喂养、翻身、伤口处理和风险监测。”
- assignment layer nx candidate；care/load layer n candidate。
- 预期：分层并存。
- 错误型：若只判 nx，则 false-negative(n)。

### T11｜shifted-window trap

“去年他靠朋友介绍进入团队；今年朋友已离开，他当前仍持续为三名成员提供固定工位、预算和风险兜底。”
- current_window=今年；旧 external route 不得永久 nx。
- 当前 team-load layer 可检 n。
- 预期：nx current FAIL；n candidate。
- 错误型：false-positive(nx) + possible false-negative(n)。

### T12｜state absence ≠ opposite-pole presence

“仓库没有长期接住这批货物，货物当天就被退回；同时也没有任何外部命令、许可或关系路径被主体沿用。”
- n=false；nx=unknown/false。
- 预期：不得因 n 缺席自动推出 nx。
- 错误型：false-positive(nx)。

### T13｜counterexample：一次救援不是稳定 n

“救援队把伤员从水里拉上来，五分钟后交给医院，此后不承担床位、治疗或持续风险。”
- rescue action true；sustained internal position false。
- 预期：稳定 n FAIL；不能从‘接住’动词锁 n。
- 错误型：false-positive(n)。

### T14｜ambiguous：shared decision + temporary hosting

“合作方要求项目组临时接收三名工程师一周，共同处理事故；项目组可拒绝部分任务，但不能单方面终止事故响应。”
- direction/permission topology=shared-with-external-gate；nx 有候选证据
- hosting only one week，是否 n 取决于是否形成可持续内部位置、持续负荷与压力下保持接收
- 预期：nx candidate；n 保持 ambiguous，不因‘接收三人’直接 positive。
- 错误型：ambiguous。

## 错误统计（本轮 14 cases）

按每个 case 的主要攻击目标计：

- false-positive targets: 7
- false-negative targets: 5
- ambiguous targets: 2
- minimal-difference pairs: 5（MP1–MP5）

本轮不是统计模型实际错误率，而是对抗集的错误槽设计。

## removal / reverse / counterexample hooks

### Removal

- 拿掉 `external route` 后，同层任务推进仍完全成立：nx 下降；n 不受影响。
- 拿掉 `internal position + sustained burden` 后，对象只经过/转交：n 下降；nx 不受影响。

### Reverse

- 保留“领导/师父/关系/命令”名词，但让外部节点无法阻止结果：nx 不得 positive。
- 保留“家庭/医院/避难所/接收”名词，但对象无持续位置或被强制扣留：n 不得 positive。

### Counterexample

同一 actor 可在同一事件中：

```text
上位任务方向：nx=ON
下位对象承载：n=ON
局部执行组织：xn 另查
```

因此 `n vs nx` 不是整个人物标签争夺，而是 object_layer + changed_variable 的分层问题。

## 新 guard｜CARRIER-vs-ROUTE-v0.1

> **先判断主体是在“接住一个对象并承担它”，还是在“沿一个外部接口推进自己”。前者检查 carrier/inside/load，后者检查 route/source/gate。相同的“接、跟、靠、安排、留下”词汇不得跨过 changed_variable 直接触发十元。**

执行式：

```text
IF object receives durable internal_position
AND actor/structure bears sustained burden
THEN evaluate n

IF actor follows activated external direction/permission/path
AND removal of that route creates same-layer progression gap
THEN evaluate nx

IF both conditions occur at different object_layers
THEN SPLIT_IR
ELSE IF decisive fields are unknown
THEN KEEP_UNKNOWN

NEVER:
  n=false => nx=true
  nx=false => n=true
  external_actor_present => nx=true
  inside_once => n=true
```

## validation hook

所有对抗样本先重建 `ten-yuan-semantic-ir-v0.1` 的 12 个字段，再送入十元语义解释器；本文件不给案例 evidence 定级，也不得把 adversarial expected label 写回 canonical。

## 本轮结论

`CARRIER-vs-ROUTE-v0.1` 形成真实新 guard：它不是“n 很像 nx 但不同”的文字说明，而是增加一个 **changed_variable-first + object_layer split** 的 decision gate，并明确 `SPLIT_IR / KEEP_UNKNOWN` 两个动作。

下一最高风险：`xn vs z`。自然语言中“安排、决定、定计划、设节点”极易把一次 final-decision node 与跨阶段 execution structure 混成同一类；下一轮应优先用 same actor / same object / shifted window 的最小差异做审计。
