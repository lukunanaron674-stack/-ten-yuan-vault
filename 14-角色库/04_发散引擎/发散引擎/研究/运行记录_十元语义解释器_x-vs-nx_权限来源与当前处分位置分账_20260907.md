# 十元语义解释器轮转｜x vs nx：权限来源与当前处分位置分账

> 本文件仅为 L4/L5 research candidate，用于“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0. 轮转约束与选题

上一轮为 `n vs xn`，因此本轮不得继续选择包含 `n` 或 `xn` 的目标。当前未被该约束占用、且仍存在高翻译债务的最近邻之一是 `x vs nx`。

current canonical：

- `x`：对象、资源、地盘、权限或关系进入“归我 / 我方掌握”的边界，主体取得现实占有、使用、调配或控制位置。
- `nx`：主体不占最终方向决定位置，沿别人、关系、流程、秩序或现状已经给出的方向、权限或解决通道继续推进。

本轮不改写上述定义，只补自然语言到 IR 的结构分账。

## 1. 翻译债务

自然语言经常把以下两类句子写得几乎一样：

```text
“公司给了她权限，她现在可以直接调配预算。”
“公司给了她权限，但每次花钱仍要财务逐笔批准。”
```

两句都出现：公司、给权限、预算、批准、使用。

若解释器只看 `relation_source=external` 或只看“有权限”，都会误判。尤其最新 `semantic_ir_decision_v0.1` 的结构接口当前只验证 required_fields 是否非空；研究层不能因此把“字段存在”误当成“字段值与候选 gate 兼容”。

本轮新增的是 **字段值兼容约束 + 权限生命周期分账**：

```text
right_origin（权限从哪里来）
≠
current_control_locus（当前谁能直接拨动对象）
```

固定 IR 不新增字段；用现有字段组合表达：

- `relation_source`：权限/通道来源或当前依赖来源；
- `decision_right`：tested object_layer 上当前决定位置；
- `path_set`：当前现实可调用路径；
- `reentry_right`：离开/失效后是否需要再次经外部接口取得；
- `reality_anchor`：谁的一次现实拨动能改变同层对象状态。

## 2. 新规则｜VESTED-CONTROL-vs-MEDIATED-ACCESS-v0.1

### 2.1 核心分流

```text
外部授予
+ 当前窗口内主体无需逐次再批准
+ 主体可在明确 scope 内直接使用/调配/冻结/排除
→ relation_source 可以是 institutional_conferral
→ 但 current control locus 已落在 actor
→ x candidate 可成立

外部授予/名义拥有
+ 每次关键动作仍需外部节点逐次放行
+ 外部拒绝即可阻断同层结果
→ current operative path 仍是 mediated external route
→ nx candidate 优先
```

因此：

```text
relation_source = external / institutional_conferral
不自动推出 nx；

“权限来自别人”
也不自动否定当前 x。
```

### 2.2 字段存在 ≠ 值兼容

候选 gate 在解释器研究层必须区分：

```text
required field present
vs
required field value compatible with symbol
```

例如：

```yaml
relation_source: external
decision_right: actor_direct_within_granted_scope
path_set:
  - direct_allocate_budget
  - direct_freeze_subaccount
reentry_right: external_permission_required_after_term_expiry
```

这些字段全部非空，但当前窗口并不能仅凭 `relation_source=external` 判 nx；`decision_right + path_set + reality_anchor` 反而说明明确 scope 内主体已拥有直接控制位置。

研究层候选纪律：

```text
NON_NULL_GATE_IS_NECESSARY_NOT_SUFFICIENT
VALUE_PATTERN_COMPATIBILITY_REQUIRED
```

该纪律只作为 L4/L5 翻译校准，不修改现有实现或 canonical。

## 3. 自然语言 → IR 结构还原顺序

遇到“给权限 / 有资源 / 找领导 / 能调用 / 要审批 / 授权 / 借用”时：

1. `actor`：当前被判主体是谁。
2. `object`：被使用、调配、冻结、取得或借用的具体对象是什么。
3. `object_layer`：必须把“已授予 scope 内的直接控制”与“超出 scope 的升级审批”拆层。
4. `current_window`：只判当前权限有效/失效/申请中的窗口，历史授予不永久在线。
5. `changed_variable`：优先区分 `current_control_scope` 与 `external_route_activation`。
6. `relation_source`：记录权限来源，但禁止让来源字段吞掉当前控制位置。
7. `relation_shape`：记录 `vested-direct-control` 或 `mediated-per-action-access` 等现实形状。
8. `decision_right`：同层关键动作由 actor 直接决定，还是 external gate 逐次决定。
9. `path_set`：只列现实可调用路径；“理论上能找某人”不算 activated path。
10. `reentry_right`：权限到期/退出后能否自行恢复，或必须重新申请。它描述生命周期，不回写当前窗口。
11. `future_endpoint`：没有长期终点证据则 null。
12. `reality_anchor`：用“actor 单独拨动是否改变状态 / external refusal 是否阻断”做现实校验。

## 4. 标准输入

> “公司给林澈一个季度的项目账户管理权限。十万元以内她可以直接付款、冻结子账户和重分额度，不需要财务逐笔批准；超过十万元必须提交 CFO 审批，CFO 不批准就不能支付。季度结束后全部权限自动收回，再使用要重新申请。”

这里不能整句单判，必须至少按权限 scope 拆成两个 IR。

## 5. 完整 IR-A｜已授予 scope 内的当前直接控制

```yaml
actor: 林澈
object: 项目账户十万元以内的资金与子账户权限
object_layer: 已授予额度内的当前资金使用与处分层
current_window: 季度权限生效 -> 主体直接使用 -> 季度结束自动回收前
changed_variable: current_control_scope
relation_source: institutional_conferral
relation_shape: vested-direct-control-within-bounded-scope
decision_right: actor_direct_within_granted_scope
path_set:
  - direct_payment_under_100k
  - direct_freeze_subaccount
  - direct_reallocate_quota
reentry_right: external_permission_required_after_term_expiry
future_endpoint: permission_expires_at_quarter_end
reality_anchor: 在十万元以内，林澈无需财务再次批准即可直接改变账户支付、冻结和额度状态
```

判定：**x candidate PASS**。

理由：权限来源确实是公司，但 current window 与 tested scope 内，资源已进入主体可直接调用/处分边界；`relation_source` 的历史/制度来源不能覆盖 `decision_right + path_set + reality_anchor` 所证明的当前控制位置。

## 6. 完整 IR-B｜超额支付的外部逐次放行

```yaml
actor: 林澈
object: 超过十万元的项目支付
object_layer: 超额支付的审批与执行通道层
current_window: 提交超额支付 -> CFO审批 -> 获批后支付或拒绝后停止
changed_variable: external_route_activation
relation_source: external
relation_shape: mediated-per-action-approval-gate
decision_right: external_final_on_over_cap_payment
path_set:
  - submit_to_CFO
  - CFO_approval_gate
  - payment_after_approval
reentry_right: external_permission_required_for_each_over_cap_action
future_endpoint: null
reality_anchor: CFO拒绝即可阻断该笔超额支付，林澈不能单独完成同层结果
```

判定：**nx candidate PASS**。

## 7. Positive decision gates

### 7.1 x candidate

```text
X1 object_layer 明确；
X2 current_window 明确；
X3 changed_variable 指向 current possession / use / allocation / disposition / control scope；
X4 decision_right 在 tested scope 内落到 actor 或 actor-side；
X5 path_set 至少有一条 actor 无需逐次外部批准即可现实调用的 direct control path；
X6 reality_anchor 证明 actor 单独拨动即可改变对象同层状态；
X7 relation_source 即使是 external/institutional-conferral，也不能单独否定 X4-X6；
X8 未来可撤销/到期只限制 scope 与 current_window，不自动抹掉当前 x。
```

### 7.2 nx candidate

```text
NX1 object_layer 明确；
NX2 current_window 明确；
NX3 changed_variable 指向 external direction / permission / solution-route activation；
NX4 relation_source 为 external 或 shared-with-effective-external-gate；
NX5 path_set 至少有一条当前已激活、主体实际沿用的 external route；
NX6 decision_right 在该 tested layer 不由 actor 单独占据；
NX7 reality_anchor 证明 external refusal / non-cooperation 能阻断或实质改变同层结果；
NX8 仅仅“权限最初由别人给”不满足 NX5-NX7。
```

## 8. nearest-neighbor 最小差异

### 8.1 x vs nx

最小差异不是“有没有别人”，而是：

```text
x：当前 tested scope 内，主体已经能直接拨动对象。
nx：当前 tested action 仍必须穿过外部节点才能完成。
```

同一权限生命周期可以发生：

```text
申请中：nx 候选
→ 授予并稳定落入直接调用 scope：x 候选
→ 到期失效、重新申请：nx 候选再次上升
```

这是本轮新增的 **状态迁移规则**。

### 8.2 x vs zx

```text
x：对象/权限归我掌握，不要求公开压过他者。
zx：主体自身方向与权能公开扩大、压入现实并凌驾竞争方向。
```

直接控制预算可以 x；公开越权取消其他部门的否决并扩大自身决定范围，才另查 zx。

### 8.3 nx vs xn

这里只作邻居护栏，不作为本轮目标：

```text
nx：外部目标/通道仍在决定关键路径。
xn：主体自己搭运行顺序、节点、记录和流程。
```

外部目标 + actor 自己搭局部流程可分层并存；不得因为本轮 x/nx 分账而重写 xn canonical。

## 9. False-positive guards

1. **“给了权限” ≠ x**：若每次关键动作仍需他人逐次批准，当前控制位置没有真正落给主体。
2. **“权限来自外部” ≠ nx**：已稳定授予且 current scope 内直接可调用时，来源字段不能吞掉当前控制位置。
3. **“老板/Boss/负责人” ≠ x**：职业与头衔不能代替现实 control path。
4. **“去审批” ≠ nx**：若审批只是备案、无法阻断同层结果，不足以形成 effective external gate。
5. **未来撤回 ≠ 当前无 x**：到期/撤权属于 current_window 与 reentry_right，不得逆写现在。
6. **一次借用成功 ≠ x**：若对象始终在别人控制下、每次都要重新开口借，优先查 nx 关系功能。
7. **x FAIL ≠ nx PASS**：资源被冻结且无人能调，也可能两端都不成立。
8. **nx FAIL ≠ x PASS**：外部接口无效不代表资源自动归主体掌握。
9. **字段非空 ≠ gate 成立**：required_fields 全部存在，也必须检查值组合与 reality_anchor。
10. **跨 scope 偷换禁止**：十万元内的 x 不能外推到十万元以上；超额支付的 nx 也不能倒灌全部账户权限。

## 10. Removal / reverse / same-layer / current-window

### Removal｜x

移除 actor 的 direct control path，例如把“直接付款”改成“每次都需 CFO 批准”。若主体不能再单独改变同层对象状态，则 x 证据应下降。

### Removal｜nx

移除 effective external gate，例如 CFO 仅备案、拒绝也不能阻断支付。若主体仍可照常完成同层结果，则 nx 证据应下降。

### Reverse

- 保留“公司授权”字样，但把现实结构改成每次逐笔审批：若模型仍因“有权限”判 x，说明关键词污染。
- 保留“审批”字样，但把审批改成无阻断力备案：若模型仍判 nx，说明把关系名词当成 effective path。

### Same-layer

必须在同一 tested scope 比较 current control locus。禁止拿“十万元以内直接处分”与“十万元以上审批”合成一个模糊的权限层。

### Current-window

```text
历史上有 x ≠ 当前 x；
未来会失去 x ≠ 当前没有 x；
过去依赖外部审批 ≠ 当前仍 nx；
未来重新申请 ≠ 当前已 nx。
```

## 11. Adversarial tests

### T1｜关键词诱导

输入：“公司说‘你有审批权限’，但她每次付款都必须先让 CFO 点确认，否则系统不会执行。”

IR：`relation_source=external`；`decision_right=external_final_on_payment`；`path_set=[CFO_gate]`；`reality_anchor=CFO refusal blocks payment`。

结论：**x FAIL；nx candidate PASS**。词面“有权限”不能替代 direct control。

### T2｜题材/职业/情绪诱导

输入：“他是令人畏惧的集团老板，但法院已冻结全部涉案账户，他本人和下属当前都不能转账、处分或解冻。”

IR：职业=Boss 但不进入固定 IR 判据；`path_set=[]/blocked`；`decision_right=external_court_constraint`；current direct control 不成立。

结论：**x FAIL/UNKNOWN；不能因身份判 x**。是否存在 nx 还需看他是否实际沿外部解冻通道推进，不能自动补。

### T3｜对象层错位

输入：“她在部门预算十万元以内可直接调配，超过十万元必须董事会批准。”

结论：额度内 object_layer → **x candidate**；超额 object_layer → **nx candidate**。禁止整句一锅判。

### T4｜时间窗错位

输入：“去年他有服务器管理员权限；本月权限已过期，现在每次操作都必须重新申请临时授权。”

current_window=本月；旧 direct path 不在线；当前 external temporary-grant route 在线。

结论：**不得沿用历史 x；当前操作层查 nx**。

### T5｜同关系词异对象层

输入A：“她有仓库权限，刷自己的长期卡即可开门、调货。”
输入B：“她有仓库权限，但每次开门都由保安远程确认后才解锁。”

A：direct executable control path → x 证据强。
B：mediated-per-action gate → nx 证据强。

结论：同样“有权限”，结构相反。

### T6｜对端不存在不等于本端成立

输入：“账户被冻结，负责人不能动，财务也没有解冻权，目前没人拥有可执行的支付或解冻路径。”

IR：`path_set=[]`；`decision_right=unknown/external-unresolved`；`reality_anchor=null`。

结论：**x FAIL/UNKNOWN；nx FAIL/UNKNOWN**。没有本端不能推出对端。

### T7｜外部授予但当前 x 已落位

输入：“研究院给她三个月实验设备管理员权限；三个月内她可直接分配时段、禁用账号和调整配额，不需再找院长。”

IR：`relation_source=institutional_conferral`；`decision_right=actor_direct_within_scope`；direct path 多条。

结论：**x candidate PASS；不得仅因权限来源外部判 nx**。

### T8｜一次借用伪 x

输入：“他借朋友的摄影棚拍一天；每次进棚、换灯、延长时间都要朋友单独同意，朋友可以随时拒绝。”

结论：tested resource control 未稳定落给 actor；**x FAIL/弱，nx 关系功能 candidate 更强**。

### T9｜未来撤权伪当前 nx

输入：“她目前能直接管理项目账户，但合同写明下月全部权限自动收回。”

current_window=权限仍有效的现在；`future_endpoint=permission_expiry`；当前 direct path 在线。

结论：**当前 x candidate PASS**。未来到期不能反向覆盖现在。

### T10｜审批词伪 nx

输入：“制度要求提交审批单，但审批人只有备案权，负责人先支付也不会被系统阻断，过去十次拒签都未改变支付结果。”

IR：`relation_source=external-formal`；`decision_right=actor-in-effect`；`reality_anchor=refusal does not block`。

结论：**nx FAIL**；若资源本身确实处于负责人 direct disposition scope，可另查 x。

## 12. 状态迁移规则

本轮新增生命周期：

```text
external application / per-action gate
→ nx candidate

stable grant enters actor direct callable scope
→ x candidate rises

scope expires / grant revoked
→ current x falls

reacquisition requires external gate again
→ nx candidate rises again
```

关键纪律：迁移必须由 `current_window + decision_right + path_set + reentry_right + reality_anchor` 共同证明，不能从“授权/撤权/重新申请”等词直接贴标签。

## 13. 与最新 IR 判定接口的兼容建议（research-only）

当前 P0-4 `semantic_ir_decision_v0.1` 已正确做到：关键词不直接产出 symbol、缺结构时返回 `NEEDS_MORE_STRUCTURE`、多个结构 gate 同时满足时返回 `AMBIGUOUS`。

本轮新增研究债务是下一层：

```text
required_fields presence check
之后还需要
symbol-specific value compatibility check
```

对本轮至少应概念上满足：

```text
x:
  decision_right ~ actor-direct
  path_set ~ direct-control paths
  reality_anchor ~ actor-alone changes object state

nx:
  relation_source ~ effective external
  path_set ~ activated mediated path
  decision_right ~ not actor-alone on tested layer
  reality_anchor ~ external refusal can block
```

这只是解释器研究候选，不在本轮修改实现代码。

## 14. 成功门

本轮存在真实新增，不是重复已有机制：

1. 新增 `right_origin ≠ current_control_locus` 翻译约束；
2. 新增 `NON_NULL_GATE_IS_NECESSARY_NOT_SUFFICIENT`；
3. 新增 x/nx 的字段值兼容模式；
4. 新增 `nx -> x -> nx` 的权限生命周期迁移；
5. 新增跨 scope 禁止倒灌规则；
6. 新增外部授予但当前 x 已落位的 adversarial positive/negative 分流。

因此：**PASS，可提交 research-only candidate。**

## 15. 下一轮最高翻译风险

由于本轮涉及 `x` 与 `nx`，下一轮不得连续选择包含这两者的目标。

优先债务候选：**`z vs x并z`**。

理由：自然语言里的“代表、官方、唯一、入口、中心、发布、对外口径”很容易混淆：

```text
x并z：内部对象通过稳定公共壳被第三方识别、调用、归因或进入；
z：同一对象层的裁定重心收束到单一最高/最终裁定点。
```

两者都会出现“官方/唯一/代表”，但 changed_variable 分别更接近 `public_interface` 与 `final_adjudication_center`。下一轮应继续利用“字段非空 ≠ 值兼容”规则做最小差异校准。
