# 十元语义解释器｜nz vs x并z：对象特异回返者与公共调用者入口分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖 L1/L2 canonical，不得修改十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 1. 本轮目标与翻译债务

目标混淆对：`nz vs x并z`。

已有研究已经分别锁定：`nz` 不是“有门”而是对象特异关系中的可信回返/修复；`x并z` 不是“在里面”而是内部对象通过稳定公共壳被第三方识别、调用、归因、代表或进入。最新 P0-6 adversarial fixtures 又把 `reentry_right = recoverable` 与 `none` 做成了版本化对抗项。

剩余翻译债务是：**解释器知道“入口可恢复”，却还没强制判断“谁正在使用入口，以及这个人是否拥有与该对象的历史关系状态”。**

高风险自然语言包括：“门一直给你留着”“任何人都可以从这里进入”“老成员可以直接回来”“官网有返回入口”“欢迎回来”“重新加入”“公开报名入口”。这些句子都包含入口/返回词，但结构可能完全不同。

本轮新增候选规则：

`RETURNING-PARTICIPANT-vs-PUBLIC-CALLER-v0.1`

以及强制审计：

```text
CALLER-IDENTITY-AND-HISTORY_AUDIT_REQUIRED
ENTRY-SEMANTIC-TYPE_AUDIT_REQUIRED

previously-related participant -> same object-specific relation -> reentry/repair
= nz candidate path

unspecified/public third party -> stable shell/interface -> identify/call/enter internal object
= x并z candidate path
```

关键新增纪律：**入口本身不是判定对象，入口的调用者身份、历史关系状态和到达的 object_layer 才决定它属于“回返”还是“公共接口”。**

## 2. 自然语言 → Semantic IR 结构还原规则

固定字段不变，只增加字段值约束：

1. `actor`：明确谁维持关系回返资格，或谁维持公共壳；不得把“回来的人”和“入口维护者”混成同一 actor。
2. `object`：nz 写原对象特异关系/原成员位置；x并z 写被公共壳映射、识别或进入的内部对象/服务。
3. `object_layer`：强制区分 `object_specific_reentry_layer` 与 `public_addressability_or_entry_interface_layer`。
4. `current_window`：nz 至少覆盖“曾在关系内/拥有原位置 -> 离开或分离 -> 当前回返资格/实际回返”；x并z 覆盖“稳定公共壳有效 -> 第三方识别/调用/进入”。
5. `changed_variable`：nz 优先 `object_specific_reentry_space` / `repairable_relation_position`；x并z 优先 `public_addressability` / `public_entry_interface`。
6. `relation_source`：nz 追 standing relationship boundary / bilateral or equivalent reentry rule；x并z 追 stable public shell / institutional interface。
7. `relation_shape`：nz 写 `previous-participant_exit_then_same-relation_reentry`；x并z 写 `external-caller_to_stable-shell_to_internal-object`。
8. `decision_right`：nz 写回返是否由原参与者可直接执行或仍依赖第三方批准；x并z 可以是 `interface_only_nonfinal`，不要求公共接口拥有最终裁定权。
9. `path_set`：nz 的 path 必须至少有一条“原参与者 -> 原关系位置”的对象特异回返路径；x并z 的 path 必须至少有一条“公共/未预先绑定第三方 -> 稳定壳 -> 内部对象”的可重复调用路径。
10. `reentry_right`：只回答“离开原对象关系后，原参与者能否回到原对象层”。**公共首次进入能力不得填作 nz 的 reentry_right。**
11. `future_endpoint`：仅明确存在结构性未来终点时填写；“以后一直欢迎”不能臆造永久 endpoint。
12. `reality_anchor`：nz 要证明历史参与者的原资格在离开后仍可现实恢复/调用；x并z 要证明陌生/第三方调用者无需既有私人关系也能通过公共壳到达对象。

### 新 IR 约束 A：CALLER-HISTORY AUDIT

解释器遇到“入口/回来/加入/访问”时，必须先问：

```text
CH1 caller 是否曾经处于当前 tested object_layer 内？
CH2 如果是，离开后回到的是原对象/原关系位置，还是一个新对象/新资格？
CH3 如果不是，caller 是否属于未预绑定的公共第三方？
CH4 同一入口是否同时支持 public first-entry 与 former-member reentry？若是，必须 SPLIT_IR。
CH5 入口存在是否依赖私人特批？若依赖，不得拿公共性补 x并z，也不得拿成功回来补 stable nz。
```

### 新 IR 约束 B：FIRST-ENTRY != REENTRY

```text
public first-entry capability != object-specific reentry right
former-member reentry path != stable public interface automatically
```

这条约束直接补 P0-6 当前只区分 recoverable/none、尚未区分 caller history 的翻译缺口。

## 3. 标准输入与完整 IR

输入：

> “创作社对外有一个长期公开报名页，任何第一次接触创作社的人都可以通过页面提交资料，页面只负责登记和转交。老成员退出后，原成员账号会保留六十天；六十天内本人可用原账号直接恢复原项目组资格，不需要重新公开报名，也不需要负责人逐次批准。林澈上月退出后，本月已经按原账号恢复到原项目组。”

必须拆两个 IR。

### IR-A｜x并z：公共调用/首次进入接口层

```yaml
actor: 创作社公共报名系统
object: 创作社对外报名与资料转交服务
object_layer: public_addressability_or_entry_interface_layer
current_window: 公开报名页持续有效 -> 第三方首次访问 -> 提交资料 -> 登记转交
changed_variable: public_entry_interface
relation_source: stable_public_shell
relation_shape: external-caller_to_stable-shell_to_internal-object
decision_right: interface_only_nonfinal
path_set:
  - public_first_time_visitor_identifies_portal
  - public_submit_materials
  - interface_registers_and_routes
reentry_right: null
future_endpoint: null
reality_anchor: 与创作社没有既有成员关系的第三方也能稳定找到并调用该页面
```

判定：`x并z candidate PASS`。

### IR-B｜nz：原成员对象特异回返层

```yaml
actor: 原成员与创作社之间的成员关系
object: 林澈在原项目组的原成员资格
object_layer: object_specific_reentry_layer
current_window: 原成员在组 -> 自愿退出 -> 六十天资格保留 -> 使用原账号恢复原项目组
changed_variable: object_specific_reentry_space
relation_source: standing_membership_boundary
relation_shape: previous-participant_exit_then_same-relation_reentry
decision_right: former_member_direct_reentry_within_60_days
path_set:
  - voluntary_exit
  - retain_original_member_account
  - direct_restore_original_project_membership
reentry_right: executable_to_same_object_specific_relation_within_60_days
future_endpoint: reentry_window_expires_after_60_days
reality_anchor: 林澈无需重新公开报名或逐次特批，已用原账号恢复到原项目组
```

判定：`nz candidate PASS`。

## 4. Positive decision gates

### nz candidate gate

```text
NZ1 caller/returning party 可证明曾处于 tested object_layer；
NZ2 current_window 含真实离开/分离，不能只是同一层内部移动；
NZ3 object 指向原对象特异关系/原成员位置，而不是同类新对象；
NZ4 reentry_right 对原参与者现实可执行，且不是纯口头欢迎；
NZ5 path_set 至少有一条 former participant -> same relation position 的真实路径；
NZ6 若每次回返都需第三方临时特批，stable nz 下降并转查 external route；
NZ7 reality_anchor 证明资格被保留、恢复或关系被修复；
NZ8 公共首次进入能力不能替代 NZ1-NZ7。
```

### x并z candidate gate

```text
XPZ1 tested layer 是公共识别/调用/归因/代表/进入接口；
XPZ2 caller 不要求预先拥有对象特异私人关系，公共/未预绑定第三方可调用；
XPZ3 存在 stable shell/interface 与内部对象的稳定映射；
XPZ4 path_set 至少含 external caller -> shell -> internal object 的可重复路径；
XPZ5 public shell 的 decision_right 可为 null/nonfinal/interface-only；
XPZ6 current_window 内接口真实在线并被可重复调用；
XPZ7 removal 公共壳后，第三方寻址/调用方式发生现实变化；
XPZ8 老成员能回来本身不能替代 XPZ2-XPZ7。
```

## 5. nearest-neighbor 最小差异

### nz vs x并z

```text
nz：曾经属于这段对象特异关系的人，离开后还能回到原位置吗？
x并z：没有预先私人关系的第三方，能否通过稳定公共壳找到/调用/进入这个对象？
```

最小对照：

- 只有老成员凭旧账号回原组，陌生人没有任何公开入口：`nz` 可 PASS，`x并z` 不成立。
- 官网公开接受所有新申请，但离职成员回来也必须从零竞聘：`x并z` 可 PASS，`nz` FAIL。

### nz vs n

`n` 查“进入后是否被持续承载”；`nz` 查“离开原关系后是否仍有对象特异回返”。公共入口或成员回返后是否被长期承载，是另一层问题。

### x并z vs x

公共接口让第三方找到/进入对象，不等于 caller 或接口维护者拥有内部对象的直接处分权；处分边界仍应另查 `x`。

## 6. False-positive guards

1. “欢迎回来”只触发回返 IR，不直接产 nz。
2. “入口/门户/通道”只触发 path 抽取，不直接产 x并z。
3. 陌生人的首次报名成功不得填成 `reentry_right`。
4. 老成员凭私人联系人特批回来，不得因为“回来了”锁 stable nz。
5. 只有会员能看到的私人后台，不因界面稳定就自动是公共 x并z。
6. 公开官网存在，但只展示信息、不能稳定识别/调用/进入内部对象，不足以锁 x并z。
7. 回到同类新岗位/新团队，不等于回到原对象特异关系。
8. 同一建筑“从门进去”与离职后“回到原组织关系”必须拆 object_layer。
9. x并z FAIL 不推出 nz；nz FAIL 也不推出 x并z。
10. 题材、职业、情绪、身份、颜色、胜负、悲惨程度均不得倒推两端。

## 7. Adversarial tests

### ADV-1｜关键词诱导

“门永远为你敞开。”没有说明 caller 是否曾是成员、门通向哪个对象层、是否现实可用。

预期：`nz UNKNOWN/FAIL`；`x并z UNKNOWN/FAIL`。关键词不补结构。

### ADV-2｜题材/职业/情绪诱导

“温柔的老旅店老板总说欢迎回家。”旅店只接受熟人电话预约，且每次由老板临时决定；无稳定公共接口，也无原对象特异资格保留。

预期：不得因温柔/旅店/回家判 nz/x并z。

### ADV-3｜对象层错位

大学有公开访客预约网站；毕业生校友卡则允许本人回原实验室资料库。

预期：访客网站层查 `x并z`；校友对象特异资料库回返层查 `nz`；必须 SPLIT_IR。

### ADV-4｜时间窗错位

去年老员工离职后三个月可直接恢复账号，今年政策取消；官网报名页今年仍公开有效。

预期：当前 `nz` 不得继承去年；当前 `x并z` 可继续按官网结构检查。

### ADV-5｜同关系词异对象层

“重新进入”：陌生申请人重新打开公开报名页面，只是再次调用公共接口；前成员重新进入原项目组，则涉及对象特异 reentry。

预期：同词不得共用十元标签。

### ADV-6｜对端不存在不等于本端成立

旧会员后台已关闭，公开报名页也已下线，目前只能等通知。

预期：`nz FAIL/UNKNOWN + x并z FAIL/UNKNOWN`；一端不存在不产生另一端。

### ADV-7｜公共首次进入伪 nz

任何陌生人都可从官网申请加入，但原成员离职后必须与所有人一样重新竞聘，旧资格完全不保留。

预期：`x并z candidate PASS`；`nz FAIL`。

### ADV-8｜私人回返伪 x并z

秘密研究组没有官网、门牌或公开联系方式；老成员离开后三十天可用原密钥恢复原席位。

预期：`nz candidate PASS`；`x并z FAIL/UNKNOWN`。

### ADV-9｜第三方特批伪 nz

前员工每次想回来都要创始人重新批准，创始人拒绝即可阻断，原资格并未保留。

预期：stable `nz FAIL/弱`；成功一次不等于对象特异可执行 reentry。

### ADV-10｜稳定界面但非公共调用者

内部员工门户十年不变，但只有现职员工预绑定账号可进入，陌生第三方无法识别或调用任何内部服务。

预期：不能仅凭“稳定界面”锁公共 `x并z`；需另查其是否承担 current canonical 所需公共壳功能。

### ADV-11｜同一入口双功能

协会官网对陌生人提供新会员申请，同时对退会九十天内的原会员提供“恢复原会员号”。

预期：必须拆两个 IR；新申请层 `x并z candidate`，恢复原会员号层 `nz candidate`。不得单 IR 双贴理由。

### ADV-12｜回到新对象伪 nz

演员离开剧团后通过公开招聘进入另一支同名巡演组，职位相似但原合同、原团队和原成员资格均未恢复。

预期：公开招聘可查 `x并z`；原关系 `nz FAIL`。

## 8. Removal / reverse / same-layer / current-window 检查

### Removal A｜移除公共壳

保留原成员六十天直接恢复资格，但撤掉公开报名页。

预期：`nz` 可保持；`x并z` 明显下降。

### Removal B｜移除对象特异回返

保留公开报名页，但规定退出成员回来必须与陌生人一样重新公开申请，原账号/原项目组资格全部作废。

预期：`x并z` 可保持；`nz` 明显下降。

### Reverse

- 保留“欢迎回来”字样，但改成所有人重新竞聘：nz 必须下降。
- 保留“公共入口”字样，但只有预绑定内部人员能用：x并z 必须重新审计并可下降。

### Same-layer

`public application interface` 与 `former-member reentry position` 禁止塞进同一 object_layer。一个页面同时承载两种功能时，按 caller history 拆 IR。

### Current-window

历史 reentry policy 不续贴当前；历史官网也不续贴当前。必须以当前是否在线、是否可执行、当前 caller 的历史关系状态判定。

## 9. 新状态迁移规则

新增两条独立状态轨：

```text
CALLER_RELATION_STATE:
never-related/public-caller
-> enters via public shell
-> may later become member
```

这条轨主要服务 `x并z` 的 public caller 分析。

```text
MEMBERSHIP_REENTRY_STATE:
inside/member
-> voluntary exit/separation
-> original position retained/recoverable
-> same-relation reentry executed
```

这条轨主要服务 `nz`。

关键纪律：

```text
public caller becomes member
!= nz automatically

former member reenters
!= x并z automatically
```

只有在不同 current_window 中满足各自 gate，才允许状态迁移后分别判定。

## 10. 成功门审计

本轮不是重复“nz 是回返、x并z 是公共壳”的已有定义，而是新增以下解释器资产：

1. `CALLER-IDENTITY-AND-HISTORY_AUDIT_REQUIRED`；
2. `ENTRY-SEMANTIC-TYPE_AUDIT_REQUIRED`；
3. `FIRST-ENTRY != REENTRY` 的 IR 字段约束；
4. `reentry_right` 禁止承载公共首次进入能力；
5. 同一入口按 caller history 强制 `SPLIT_IR`；
6. public caller 与 former-member 两条独立状态迁移轨；
7. “内部稳定界面但仅预绑定人员可用”这一 adversarial negative。

因此满足“新的翻译规则 / IR 字段约束 / 判定门 / adversarial negative / 状态迁移规则”成功门，可提交。

## 11. 下一轮最高翻译风险

本轮占用 `nz / x并z`，下一轮不得继续使用两者。

当前建议优先检查 `xz vs z`：自然语言中的“最终只剩一个”“最后只能这样”“唯一终局”容易把 **路径集合随阶段持续收窄到单一 future endpoint（xz）** 与 **多个判断位置收束到单一最高裁定中心（z）** 混在一起。下一轮应重点用 `future_endpoint + decision_right + path_set.scope + current_window` 做“终点唯一 vs 裁定唯一”的字段值兼容审计。
