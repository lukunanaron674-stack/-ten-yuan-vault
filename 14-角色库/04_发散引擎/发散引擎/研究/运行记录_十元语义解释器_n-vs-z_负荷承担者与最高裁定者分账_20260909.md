# 十元语义解释器｜n vs z：负荷承担者与最高裁定者分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究；不得覆盖或修改 L1/L2 canonical、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0. 本轮为什么值得做

高风险自然语言：

```text
这件事最后由我负责。
出了问题我承担。
最终还是我说了算。
我签完字以后，后面的烂摊子他们处理。
负责人必须对结果负责，但没有最终决定权。
```

中文“负责”同时可能压入两种完全不同的结构：

```text
n：谁在对象进入内部后，持续承担它继续存在造成的现实负荷？
z：谁在多个同层判断/标准仍可能有效时，拥有 binding final adjudication？
```

因此本轮不是补“负责人”案例，而是新增可执行分账：

```text
LOAD-BEARER-vs-FINAL-ADJUDICATOR-v0.1

RESPONSIBILITY-SENSE_AUDIT_REQUIRED
DECISION-TARGET_AUDIT_REQUIRED
POST-DECISION-LOAD_AUDIT_REQUIRED
```

核心不变量：

```text
being accountable for outcome != final adjudicator
final adjudicator != sustained load bearer

“最后负责”必须重写成：
- 最后谁承担后续现实负荷？
或
- 最后谁的判断取得 binding validity？
```

禁止直接把“负责 / 总负责 / 最终负责 / 一把手 / 背锅 / 拍板”映射为十元。

## 1. Canonical precedence guard

current L1/L2 对本轮具有最高权威：

```text
n：外部对象进入内部并被持续承载。
z：判断权与结构重心收束到单一最高中心或最终裁定点。
```

`【z信息量卡v2.2】`仍带有旧“认可主体”措辞；本轮只读取其历史/辅助信息，不允许其覆盖 L1/L2 的 current z 定义。

解释器若遇到：

```text
“老板认可了我”
“观众看见了我”
```

不得仅凭旧卡 wording 生成本轮 current-z；必须重新寻找同层候选判断 + binding final adjudication。若不存在，z 为 FAIL/UNKNOWN。

## 2. 自然语言 → IR 的结构还原规则

遇到“负责 / 最终负责 / 我来承担 / 我说了算 / 最后签字”时按以下顺序抽取，不得先贴标签：

### 2.1 先抽 object 与 object_layer

必须问语义结构到底在说：

```text
A. 一个对象/成员/任务进入内部以后谁持续接住？
B. 多个答案/方案/判断里谁决定哪个最终有效？
```

若 A/B 同时存在，强制 `SPLIT_IR`。

### 2.2 抽 changed_variable

```text
n candidate:
  sustained_internal_load_distribution
  carrying_continuity
  support_burden_distribution

z candidate:
  adjudication_center_distribution
  binding_validity_distribution
```

`responsibility` 本身不是合法的 changed_variable。

### 2.3 抽 decision_right

必须把模糊“负责人”继续还原：

```text
load_execution_only
care_and_support_scope
incident_accountability_without_final_choice
actor_final_adjudicator
shared_nonfinal_review
recommendation_only
```

只有 `actor_final_adjudicator` 等能证明本层 binding final validity 的结构才可进入 z positive gate。

### 2.4 抽 path_set 的语义类型

```text
n path_set：
  feeding / staffing / funding / maintenance / monitoring / repair / cleanup / risk handling / recurring coordination

z path_set：
  candidate judgments / competing answers / review positions / final override node / binding decision
```

同一个事件里可以既有 decision path 又有 burden path，但不得写进一个未分层 IR 后双贴。

### 2.5 抽 reality_anchor

n 的 anchor 必须回答：

```text
对象持续留下以后，谁实际花时间、空间、资源、照护、维护或风险成本接住它？
```

z 的 anchor 必须回答：

```text
在裁定前仍有多个同层有效判断时，谁的判断能最终覆盖/终止竞争并决定本轮哪个结果 binding 生效？
```

若只有“名义负责”，没有现实后果，字段保持 unknown/null。

## 3. 标准输入

```text
城市应急中心发生大型仓储火灾。处置方案先由消防、安监和物流三个部门分别提出；总指挥林澈拥有本次处置方案的最终裁定权，可以覆盖三个部门意见，并决定“先封仓再分区清理”为唯一有效方案。

方案确定后，现场后勤组连续七天负责安置撤出的工人、提供饮水和床位、登记伤员、补充防护物资、处理夜间突发需求，并承担临时安置点的持续资源与风险负荷。后勤组无权改变总指挥已经裁定的处置方案。
```

必须 `SPLIT_IR`。

## 4. 完整 IR-A｜z：最高裁定者

```yaml
actor: 林澈
object: 本次仓储火灾的最终处置方案
object_layer: same_layer_final_incident_adjudication
current_window: 消防/安监/物流三个方案并存 -> 总指挥终审 -> 一个方案成为本轮唯一binding方案
changed_variable: adjudication_center_distribution
relation_source: institutional_final_command_authority
relation_shape: multiple_valid_operational_judgments_to_single_binding_final_adjudicator
decision_right: actor_final_adjudicator
path_set:
  - fire_department_proposal
  - safety_department_proposal
  - logistics_department_proposal
  - commander_final_override
reentry_right: rejected_proposal_requires_new_incident_review_or_reopening
future_endpoint: one_binding_incident_plan_for_current_window
reality_anchor: 林澈可以覆盖三个部门的同层处置意见，其裁定决定本轮哪个方案获得最终执行效力
```

判定：

```text
z PASS
n 不得仅凭“总指挥对事故负责”成立
```

## 5. 完整 IR-B｜n：持续负荷承担者

```yaml
actor: 现场后勤组
object: 撤出工人与临时安置点产生的持续照护、资源和风险负荷
object_layer: internal_sustained_support_and_carrying_layer
current_window: 工人撤入安置点 -> 连续七天住宿/供给/登记/补给/夜间处理 -> 安置结束或转移

  - allocate_beds
  - provide_water_and_food
  - register_injured_workers
  - replenish_protective_supplies
  - handle_night_emergencies
  - maintain_temporary_site
reentry_right: null

```

判定：

```text
n PASS
z FAIL for 后勤组 on incident-plan layer
```

## 6. Positive decision gate

### 6.1 n positive gate

全部满足才进入稳定 n：

```text
1. object 真实进入 actor/structure 内部处理范围；
2. current_window 跨越至少两个阶段/重复周期，而非一次动作；
3. object 留下造成可识别的持续现实负荷；
4. actor/structure 反复处理该负荷；
5. reality_anchor 能指向实际时间/空间/资源/照护/维护/风险成本；
6. relation_shape 不是单纯拘押、一次转交或名义负责。
```

`decision_right` 可以很低；n 不要求 actor 拥有对象所在事务的最终裁定权。

### 6.2 z positive gate

全部满足才进入稳定 z：

```text
1. object_layer 是判断、标准、方案、答案、结果有效性的同层裁定；
2. 裁定前存在至少两个仍具现实竞争资格的同层候选判断/方案；
3. actor 是 tested final adjudicator，而不是负荷执行者、建议者或名义责任人；
4. decision_right 能覆盖/终止同层竞争，并产生 binding final validity；
5. changed_variable 是 adjudication/binding-validity distribution，而不是资源负荷分配；
6. reality_anchor 证明改变 actor 的裁定会改变“哪个判断最终有效”。
```

## 7. Nearest-neighbor 最小差异

### 7.1 n vs z｜最小差异一：谁承担 vs 谁裁定

```text
负责人A无权选择治疗方案，但必须连续两周安排床位、营养、护理和夜间风险处理
→ n candidate
→ z FAIL on treatment-decision layer

主任B不负责日常护理，但拥有三方案最终治疗裁定权
→ z candidate
→ n 不自动成立
```

### 7.2 n vs z｜最小差异二：结果责任 vs 判断效力

```text
“出了问题由我承担赔偿”
但方案由独立委员会最终决定
→ accountability 可形成其他结构证据
→ 不足以证明 z
→ 若赔偿/修复形成持续内部负荷，可再审 n

“最终方案由我决定”
但执行后所有照护/维护交给另一团队
→ z 可成立
→ n 不随之成立
```

### 7.3 n vs xn

```text
n：持续承担对象/成员留下造成的现实负荷
xn：主动组织使事务跨阶段持续运行的规则、节点、记录与流程
```

### 7.4 z vs xn

```text
z：裁定重心收束到最终中心
xn：运行/判断资格分布到多个规则节点与流程
```

## 8. False-positive guards

1. “总负责” ≠ z。
2. “背最终责任” ≠ z。
3. “出了问题我赔” ≠ z。
4. “最后由我善后” ≠ z。
5. “最后由我签字”若签字只是登记/见证/执行确认，不足以 z。
6. “有最终决定权” ≠ n。
7. 一次性接手残局 ≠ stable n。
8. 长期处理某事 ≠ n，除非存在真实进入内部的对象/负荷与持续承担。
9. 领导/主任/总指挥/家长/医生/法官等职业身份不能倒推 z 或 n。
10. 悲惨、辛苦、牺牲、被迫背锅等情绪/命运词不能倒推 n。
11. z FAIL 不推出 n PASS；n FAIL 不推出 z PASS。
12. legacy “被认可/被看见” wording 不得覆盖 current L1/L2 z gate。

## 9. Removal / reverse / same-layer / current-window

### 9.1 Removal A｜拿掉最终裁定权

将标准输入改为：

```text
林澈只汇总三个部门意见，最终由三部门多数决决定方案；后勤负荷不变。
```

预期：

```text
林澈 z ↓
后勤 n 保持
```

### 9.2 Removal B｜拿掉持续负荷

将后勤改为：

```text
后勤只在第一小时把撤离工人登记后立即转交外部机构，不再承担住宿、补给或风险处理；林澈终审权不变。
```

预期：

```text
后勤 n ↓
林澈 z 保持
```

### 9.3 Reverse A｜只交换头衔，不交换结构

```text
把后勤组长称为“事故总负责人”，但仍无处置方案最终裁定权
→ z 不得上升
```

### 9.4 Reverse B｜交换真实结构

```text
让后勤组长取得最终方案裁定权，同时把七天安置负荷移交独立机构
→ 后勤组长 z ↑
→ 其 n ↓/需重判
```

### 9.5 Same-layer check

严格禁止把：

```text
incident_plan_adjudication_layer
```

与：

```text
temporary_shelter_support_layer
```

混成一个“事故负责层”。

同一 actor 若两个层都成立，必须 `SPLIT_IR`：

```text
某院长既最终决定治疗方案
+ 又亲自组织并持续承担病区床位/护理资源
```

可分别产生 z 与 n，但不能用同一个 reality_anchor 双贴。

### 9.6 Current-window check

```text
去年某人有最终裁定权，今年只负责善后
→ 当前 z 不继承

上一阶段某组长期承载，本阶段已全部转交
→ 当前 n 不继承
```

历史职位、历史责任、历史负荷只能作为 prior state，不可直接写入当前判定。

## 10. Adversarial tests

### T1｜关键词诱导

输入：

```text
“这个项目我最终负责。”
```

无进一步结构。

预期：

```text
n UNKNOWN
z UNKNOWN
```

理由：`负责`不能提供 changed_variable、decision_right 或 path_set。

### T2｜题材/职业/情绪诱导

输入：

```text
一名疲惫的急诊主任独自承担所有骂名，人人看起来都觉得他是“最后负责人”，但治疗方案由自动协议决定，病人转入其他病区后也不是他持续照护。
```

预期：

```text
n FAIL/weak
z FAIL
```

职业、疲惫、背锅、悲惨程度均不能产十元。

### T3｜对象层错位

输入：

```text
CEO最终决定是否停产；厂区保障组随后连续一个月安置工人并处理设备封存维护。
```

预期：

```text
CEO：停产裁定层 z candidate
保障组：安置/维护负荷层 n candidate
必须 SPLIT_IR
```

不得用保障组的辛苦证明 CEO n，也不得用 CEO 权力证明保障组 z。

### T4｜时间窗错位

输入：

```text
去年院长拥有最终裁定权；今年权力已转委员会，院长只负责长期收治和资源协调。
```

预期：

```text
当前院长 z FAIL
当前院长 n 可查
```

### T5｜同关系词异对象层

输入：

```text
“王主任负责这个病区。”
具体事实：他负责床位/护理资源；治疗方案由学术委员会最终裁定。
```

预期：

```text
病区负荷层 n candidate
治疗裁定层 z FAIL for 王主任
```

### T6｜对端不存在不等于本端成立

输入：

```text
没有任何人拥有最终裁定权，系统也没有持续承载对象，只是任务因预算取消。
```

预期：

```text
z FAIL
n FAIL
```

`z` 不存在不能自动推出 `n`；反之亦然。

### T7｜赔偿责任伪 z

输入：

```text
合同规定项目失败由承包商承担全部赔偿，但是否验收通过由第三方认证机构最终裁定。
```

预期：

```text
承包商 z FAIL on acceptance layer
第三方认证机构 z candidate
承包商赔偿若只是一次付款，不足以 stable n
```

### T8｜拍板伪 n

输入：

```text
基金会主席拥有最终拨款裁定权，但批准后项目执行、人员安置和风险维护全部由受资助机构承担。
```

预期：

```text
主席 z candidate
主席 n FAIL/unknown on project-carrying layer
```

### T9｜签字语义歧义

输入：

```text
护士长每天最后签字确认护理记录完整，但无权改变治疗方案；同时她持续安排床位、夜班和耗材。
```

预期：

```text
签字不产 z
持续负荷可支持 n
```

### T10｜终审者同时承载

输入：

```text
小型诊所医生本人在三种治疗方案中最终裁定一种，同时连续十天亲自提供床位、换药、观察和夜间急救。
```

预期：

```text
SPLIT_IR
治疗裁定层 z PASS
持续照护层 n PASS
```

### T11｜同一词“承担”反向测试

输入 A：

```text
“我承担所有后果”，实际只承担名誉责任，没有持续资源/照护负荷，也无最终裁定权。
```

预期：两端 FAIL/UNKNOWN。

输入 B：

```text
“我承担所有后果”，实际指连续三个月负责修复、补给、人员安置和风险处理，但方案由委员会决定。
```

预期：n ↑，z 不随之上升。

### T12｜最小 mutation / reinterpretation

冻结：

```text
actor
object family
current incident
```

Mutation A：

```text
从：actor 只承担连续七天后勤负荷，无最终方案权
到：actor 不再承担后勤负荷，但取得多个方案的 binding final override
```

必须重新抽取 IR，不允许继承旧字段。

预期：

```text
n ↓
z ↑
```

Mutation B：

```text
从：actor 拥有最终方案权、不承担后续负荷
到：actor 失去最终权，但开始跨阶段接住人员、资源与风险负荷
```

预期：

```text
z ↓
n ↑
```

## 11. 新增 IR 字段约束

本轮新增以下约束，不改变 Semantic IR 字段集合：

### 11.1 `changed_variable`

禁止：

```yaml
changed_variable: responsibility
```

因为“责任”没有说明是负荷还是裁定。

必须细化到：

```yaml
changed_variable: sustained_internal_load_distribution
```

或：

```yaml
changed_variable: adjudication_center_distribution
```

### 11.2 `decision_right`

`n` 可以是：

```text
load_execution_only
care_and_support_scope
incident_accountability_without_final_choice
```

`z` 至少需要：

```text
actor_final_adjudicator
```

或同义的 binding final override 结构。

### 11.3 `path_set`

不得把：

```text
bed / food / maintenance / monitoring
```

与：

```text
proposal_A / proposal_B / final_override
```

混成一个无类型列表。

解释器必须先判定 path_set 属于：

```text
carrying_path
adjudication_path
```

若两者都有，强制 SPLIT_IR。

### 11.4 `reality_anchor`

```text
“他是负责人”
```

不是合法 reality anchor。

必须是可以反事实移除的现实事实：

```text
移除他的资源投入后，谁不再被持续接住？
移除他的裁定权后，哪个判断不再由他最终决定？
```

## 12. 状态迁移规则

### 12.1 LOAD-BEARER-STATE

