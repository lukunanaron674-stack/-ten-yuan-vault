# 十元语义解释器｜x vs xn：对象状态处分与流程拓扑拥有分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元判定 → Z 发散器”。current canonical 永远高于本研究；本文件不得覆盖 canonical，也不得作为关系正本。

## 0｜本轮为何值得做

仓库已有 canonical 最近邻：`x = 什么归我掌握`，`xn = 我怎样组织它持续运行`；也已有 `xn↔nx`、`x↔zn` 等解释器分账。本轮不重复“掌握 vs 组织”的口号，而补一个更容易在自然语言翻译时出错的 schema 层问题：

```text
能改变某个具体对象/案件当前状态
!=
能改变承载这些对象/案件的流程拓扑

能维护/重排流程拓扑
!=
能处分流经流程的具体对象
```

高危词：`负责、管理、审批、系统、流程、权限、控制、运营`。这些词都不能直接映射十元。

新增解释器约束：

```text
CONTROLLED-OBJECT-STATE-vs-PROCESS-TOPOLOGY-OWNERSHIP-v0.1
OPERATED-OBJECT-vs-OPERATING-SCHEMA_AUDIT_REQUIRED
STATE-CHANGE-vs-TOPOLOGY-CHANGE_AUDIT_REQUIRED
INSTANCE-ADMIN-vs-SCHEMA-OWNER_AUDIT_REQUIRED
PATH-MEMBER-SEMANTIC-TYPE_AUDIT_REQUIRED
```

## 1｜自然语言 → IR 结构还原规则

遇到“我负责/管理这个系统、流程、项目、设备”时，不先判 x/xn，依次还原：

1. **切 tested object**：句子在说一件具体资产/账号/案件/权限状态，还是跨实例重复运行的流程 schema？
2. **切 current action**：主体能做的是 `freeze/reassign/reclaim/approve one instance`，还是 `add/remove/reorder node, change retry/record/handoff rule`？
3. **切 decision_right 所属层**：权利落在具体 object state，还是流程 topology？禁止用“有审批权”混写。
4. **切 path_set 语义类型**：
   - `x.path_set` 只能记录对明确对象状态的占有/使用/调配/冻结/回收/处分动作；
   - `xn.path_set` 只能记录流程节点、顺序、记录、handoff、retry/review edges、资源调度结构。
5. **做跨实例测试**：一个决定若只改变当前单件/单案，不足以凭此判 xn；一个规则若改变后续多批实例运行方式，优先进入 xn 检查。
6. **做对象处分测试**：能改流程不等于能碰里面的物；能碰里面的物不等于能改流程。
7. 字段仍不充分则填 `unknown/null`，禁止从“负责人/主管/系统管理员”等身份词补事实。

## 2｜标准输入

> 市展览中心的资产主管林澈可以冻结单件设备、调拨展柜、回收工作证，也能批准个别物品出库；但全馆借展申请流程由流程治理组维护，固定经过登记→保险核验→文保审查→运输确认→归档，林澈无权增删节点或改退回规则。流程治理负责人周宁不能直接处置任何一件藏品或设备，却可以修改流程节点、变更必填记录、调整退回/复核路径，并让之后所有申请按新拓扑运行。

必须 `SPLIT_IR`。

### 2.1 x IR

```yaml
actor: 林澈
object: 单件设备、展柜、工作证与个别物品出库状态
object_layer: current_object_state_disposition_layer
current_window: 当前展览运营授权有效期内
changed_variable: current_object_state_and_bounded_control_scope
relation_source: delegated_asset_management_authority
relation_shape: specified_assets_and_access_states_inside_actor_direct_control_boundary
decision_right: actor_can_freeze_reassign_reclaim_or_approve_release_of_specified_current_objects
path_set:
  - freeze_device
  - reassign_display_case
  - reclaim_work_badge
  - approve_individual_item_release
reentry_right: frozen_access_or_asset_state_may_require_rule_based_reactivation_if_applicable
future_endpoint: current_disposition_scope_ends_when_delegation_or_project_scope_ends
reality_anchor: 林澈无需逐案请示即可改变这些明确对象的当前状态，但无权增删借展流程节点或修改退回规则
```

判定：`x PASS`，只在明确对象状态层。

### 2.2 xn IR

```yaml
actor: 周宁与流程治理组
object: 全馆借展申请的跨实例重复运行流程拓扑
object_layer: repeatable_workflow_topology_layer
current_window: 当前流程治理期内，多批借展申请持续运行
changed_variable: process_schema_topology_and_transition_rules
relation_source: formally_delegated_workflow_governance_authority
relation_shape: actor_maintains_and_redesigns_named_nodes_records_handoffs_retry_and_review_edges_across_instances
decision_right: actor_can_add_remove_reorder_process_nodes_and_change_record_retry_review_rules_within_governance_scope
path_set:
  - registration_node
  - insurance_verification_node
  - conservation_review_node
  - transport_confirmation_node
  - archive_node
  - retry_edges
  - review_edges
reentry_right: workflow_retry_to_named_node
future_endpoint: subsequent_applications_run_under_the_current_maintained_topology
reality_anchor: 周宁修改节点、必填记录或退回复核路径后，后续多批申请按新流程运行；但他不能直接冻结、调拨或处分任何具体藏品设备
```

判定：`xn PASS`。

## 3｜Positive decision gate

### x

```text
明确 tested object / controlled aspect
+ actor 当前有现实可执行的占有、使用、调配、冻结、回收、转交或处分动作
+ decision_right 精确落在同一 object_layer
+ reality_anchor 证明具体对象状态现在真的可被改变
+ removal 该处分权后，该对象状态控制能力出现现实缺口
```

`repeatable workflow` 不是 x 的必要条件。

### xn

```text
明确 tested process schema
+ 存在可识别的顺序、节点、记录、handoff、retry/review 或资源调度结构
+ actor 主动创建、维护、重排或授权重组运行方式
+ 改动对后续多个实例/阶段持续生效，而非只改单案结果
+ reality_anchor 证明该结构现实重复运行
+ removal schema-maintenance/redesign right 后，主体失去维护或重排持续运行结构的能力
```

`can dispose the items flowing through the process` 不是 xn 的必要条件。

## 4｜Nearest-neighbor 最小差异

### 差异 A：单案审批 vs 流程改版

```text
按既定规则批准这一次物品出库
→ 改的是 current case/object state
→ x candidate

把“文保审查”移到“保险核验”之前，并让今后所有申请都照新顺序运行
→ 改的是 process topology
→ xn candidate
```

### 差异 B：资产控制 vs schema 控制

```text
可以冻结设备、调拨展柜
但不能改借展流程
→ x PASS / xn 不自动成立

可以改流程节点、记录、retry edge
但不能处分任何设备
→ xn PASS / x 在资产层 FAIL
```

### 差异 C：同一 actor 双层成立

同一负责人既有资产处分权，又维护跨实例流程时，不做单标签替换，必须 `SPLIT_IR`：对象状态层查 x，流程拓扑层查 xn。

## 5｜False-positive guards

```text
“我负责这个系统” != xn
“所有设备归我管理” != x，除非具体处分边界可验证
“我能审批” != xn；可能只是改变一个当前案件状态
“我能改规则” != x；规则权不等于对象处分权
“流程经过我” != xn
“资源都在系统里” != 流程 owner 对资源拥有 x
职位叫主管/运营/管理员 != x 或 xn
x FAIL != xn PASS
xn FAIL != x PASS
```

特别禁止：把同一个 `decision_right: approval_authority` 同时当作 x 与 xn 正证据。必须先回答它是**单实例状态决定权**还是**跨实例规则/拓扑维护权**。

## 6｜Removal / Reverse / Same-layer / Current-window

### Removal-A

移除林澈冻结、调拨、回收、单件出库权限，但周宁的流程维护权不变：

```text
x ↓
xn 保持
```

### Removal-B

移除周宁增删节点、改记录和 retry/review rule 的权限，但林澈仍可处分明确资产：

```text
xn ↓
x 保持
```

### Reverse

把“只能批准当前单案”改成“不能决定单案资产状态，但可修改适用于后续所有申请的规则和节点”，必须**重新抽取 object/object_layer/changed_variable/decision_right/path_set**，禁止机械 `x → xn` 换标签。

### Same-layer

```text
current_object_state_disposition_layer
!=
repeatable_workflow_topology_layer
```

同一自然语言词“管理/审批/控制”跨这两层时不得共享 IR 正证据。

### Current-window

过去拥有流程改版权，不等于当前仍有 xn；过去拥有资产处分权，也不等于当前仍有 x。权限撤销、项目结束、治理角色迁移后必须重建 current_window。

## 7｜Adversarial tests

1. **关键词诱导**：`“整个系统我负责，所有设备都归我管。”` 没有实际 rights/object layer → `NEEDS_MORE_STRUCTURE`，不得判 x/xn。
2. **题材/职业/情绪诱导**：`“强势运营总监掌控全局，所有人都怕他。”` 无处分权或流程维护事实 → 不判。
3. **对象层错位**：IT 管理员可冻结员工账号，但 onboarding 流程由法务固定且他不能改 → 账号层 x 可查，xn 不补。
4. **时间窗错位**：某人去年是流程架构师，今年只按既定规则审核单案 → 旧 xn 不继承；当前 x 仅在有可验证单案状态权时查。
5. **同关系词异对象层**：`“管理设备”` 指冻结/调拨，`“管理流程”` 指节点/记录/retry 维护 → 两个“管理”必须拆 IR。
6. **对端不存在不等于本端成立**：普通录入员既不能改变物品状态，也不能修改流程 → x FAIL/UNKNOWN，xn FAIL/UNKNOWN。
7. 固定 SOP 有二十步，执行员每天完整跑完但无维护/重排/设计权 → 不因步骤多判 xn。
8. 流程架构师可重排全部节点，但每件藏品的调拨冻结由独立资产主管决定 → xn PASS，藏品层 x FAIL。
9. 审核员可以依据固定规则批准一个当前案件，但无规则、节点、记录结构维护权 → 单案状态 x candidate；xn FAIL。
10. 流程 owner 可增加必填记录和复核节点，却不能冻结、调拨、占有任何设备 → xn PASS；设备层 x FAIL。
11. 同一 actor 既可直接处分资产，又可重排适用于后续全部实例的流程 → `x + xn`，必须双 IR，证据不得复用。
12. **Mutation**：保留 schema 设计权、删除所有具体对象处分权 → `xn保持/x↓`；转交流程维护权但保留具体对象控制 → `x保持/xn↓`。mutation 后必须重新抽 IR。

## 8｜状态迁移轨

### x

```text
view_only
→ bounded_use
→ allocate/freeze/reclaim
→ transfer/disposition
= current object control scope ↑
```

### xn

```text
one_time_sequence
→ repeatable_named_nodes
→ records/handoff/retry
→ maintenance/reordering
→ cross_instance_schema_redesign
= running-structure organization ↑
```

两轨独立：

```text
x ↑ != xn ↑
xn ↑ != x ↑
```

## 9｜成功门结论

`PASS`。

本轮相对于已有 `x vs xn` canonical 最近邻口径，新增了：

- `single-instance object state` vs `cross-instance process topology` 的翻译规则；
- `decision_right` 必须标注作用层，禁止泛化 `approval_authority`；
- `path_set` 成员按对象状态动作 vs 流程结构元素分型；
- removal 两轨独立测试；
- reverse 后必须重新抽取 IR，而非标签替换；
- 12 个 adversarial negatives / mutations。

因此达到研究提交门；未修改任何 protected canonical/evidence 正本。
