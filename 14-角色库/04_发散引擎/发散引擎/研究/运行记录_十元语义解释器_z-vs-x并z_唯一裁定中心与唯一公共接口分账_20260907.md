# 十元语义解释器轮转｜z vs x并z：唯一裁定中心与唯一公共接口分账

> research-only。只服务“自然语言 → Ten-Yuan Semantic IR → 十元候选判定 → Z 发散器”。不得覆盖 current canonical，不修改 L1/L2、十元信息卡、准度卡、正式关系卡或行为 evidence 正本。

## 0. 轮转约束与选题

上一轮为 `x vs nx`，因此本轮不再选择 `x` 或 `nx`。当前高翻译债务最近邻选择 `z vs x并z`。

current canonical：

- `z`：运行权与裁定重心收束到单一最高中心或最终裁定点；把一个目标、自我、答案或标准置为最高裁定中心。
- `x并z`：内部对象映射到外部并形成稳定公共可识别、可调用、可归因、可代表、可进入或可保护的接口。

本轮不重定义二者，只解决自然语言中“官方、唯一、统一、代表、最终口径、唯一入口”造成的跨变量误译。

## 1. 翻译债务｜唯一性落在哪个变量上

自然语言常出现：

```text
“这是唯一官方入口。”
“这是唯一最终决定者。”
“所有人都只能从这里提交。”
“所有意见最后都以这里为准。”
```

四句都有“唯一/官方/都以这里”为表面形状，但结构变量不同：

```text
unique addressability / interface mapping
≠
unique adjudicative authority / final center
```

本轮新增解释器纪律：

```text
UNIQUENESS_TYPE_AUDIT_REQUIRED
```

看到“唯一、官方、统一、代表、口径”时，禁止直接判 z 或 x并z；必须先问：

1. 唯一的是“第三方怎样找到/调用/进入对象”的接口吗？
2. 还是“多个判断/候选最终由谁拍板”的裁定中心？
3. 二者是否在同一句中落在不同 object_layer，需要 SPLIT_IR？

## 2. 新规则｜UNIQUE-ADDRESS-vs-FINAL-AUTHORITY-v0.1

### 2.1 x并z 分流

```text
第三方
→ 通过稳定名称/账号/前台/接口/身份壳
→ 找到、提交给、调用、归因、代表或进入内部对象
```

若唯一性主要发生在 `public addressability / routing interface`，即使该接口没有最终决定权，也优先检查 `x并z`。

### 2.2 z 分流

```text
多个候选 / 判断 / 标准 / 意见
→ 当前同一对象层
→ 收束到一个最终有效裁定中心
```

若唯一性主要发生在 `final adjudicative authority`，并且该中心能让竞争判断失去同等最终效力，优先检查 `z`。

### 2.3 固定 IR 字段映射

不新增字段，用现有字段表达：

- `changed_variable`：`public_addressability` / `interface_mapping` vs `adjudication_center_distribution`；
- `relation_source`：稳定公共壳的维持来源 vs 最终裁定中心来源；
- `relation_shape`：`many_callers_to_one_stable_interface` vs `many_candidates_to_one_final_center`；
- `decision_right`：x并z 可为 `null/nonfinal/interface_only`；z 必须证明 tested layer 的 final decision right；
- `path_set`：x并z 列第三方可调用/进入路径；z 列候选判断及最终收束路径；
- `reality_anchor`：拿掉接口后第三方是否仍能稳定调用；拿掉最终中心后是否仍存在同等有效终局。

## 3. 自然语言 → IR 结构还原顺序

遇到“唯一官方入口 / 统一口径 / 官方账号 / 最终解释权 / 代表 / 唯一标准 / 所有申请都从这里走”时：

1. `actor`：被判主体或结构节点是谁。
2. `object`：到底是“对外接口对象”还是“被裁定的答案/候选/标准”。
3. `object_layer`：接口层与裁定层必须分开；禁止把“唯一入口”写成“唯一裁定”。
4. `current_window`：只判当前接口和当前裁定权是否在线，历史官方身份不永久继承。
5. `changed_variable`：先做 `public_addressability` vs `adjudication_center_distribution` 分流。
6. `relation_source`：壳来自登记、事实索引、组织规则或持续认证；裁定权来自何种有效中心。
7. `relation_shape`：是 callers→interface，还是 candidates/judgments→final center。
8. `decision_right`：尤其检查接口是否只是转交，不拥有最终决定权。
9. `path_set`：分别列可调用路径与裁定路径，不得共用一个 path_set 偷换变量。
10. `reentry_right`：本轮通常可为 null/unknown，除非文本真实涉及接口恢复或重新进入。
11. `future_endpoint`：若没有未来终点结构证据则 null。
12. `reality_anchor`：必须验证“撤接口影响调用”与“撤中心影响最终有效性”是两个不同后果。

## 4. 标准输入

> “基金会规定所有项目申请只能通过官网唯一入口提交，官网只负责登记、校验和转交，没有权决定是否资助；申请进入后由三名评审分别打分，最终主席可以推翻所有评分并确定唯一资助结果。官网撤掉后外部申请人无法正常提交，但换一个登记入口不会改变主席的最终裁定权。”

必须 SPLIT_IR。

## 5. 完整 IR-A｜唯一公共接口

```yaml
actor: 基金会官网
object: 基金会项目申请服务
object_layer: 对外申请识别、提交与转交接口层
current_window: 官网入口有效 -> 申请人提交 -> 登记校验 -> 转交评审
changed_variable: public_addressability
relation_source: institutional_interface
relation_shape: many_external_callers_to_one_stable_submission_interface
decision_right: interface_only_nonfinal
path_set:
  - identify_official_application_portal
  - submit_application
  - validate_and_register
  - route_to_review
reentry_right: null
future_endpoint: null
reality_anchor: 撤掉官网入口后，第三方无法按原稳定方式提交和被基金会识别，但官网本身不能决定资助结果
```

判定：**x并z candidate PASS**。

## 6. 完整 IR-B｜唯一最终裁定中心

```yaml
actor: 基金会主席
object: 项目是否获得资助的最终结果
object_layer: 同一批申请的最终资助裁定层
current_window: 三名评审分别打分 -> 主席终审 -> 唯一资助结果生效
changed_variable: adjudication_center_distribution
relation_source: institutional_final_center
relation_shape: distributed_reviews_to_single_final_adjudicator
decision_right: single_final_center_can_override_reviewers
path_set:
  - reviewer_A_score
  - reviewer_B_score
  - reviewer_C_score
  - chair_final_adjudication
reentry_right: null
future_endpoint: one_effective_funding_result
reality_anchor: 主席可以推翻所有评分并使唯一结果生效；撤掉主席最终权后，三名评审结果不再自动收束为同一最终终局
```

判定：**z candidate PASS**。

## 7. Positive decision gates

### 7.1 x并z candidate

```text
XZB1 object_layer 为公共识别/调用/归因/代表/进入/保护接口层；
XZB2 至少一个第三方能通过壳稳定找到或调用内部对象；
XZB3 relation_shape 是 caller/observer -> shell/interface -> internal object；
XZB4 path_set 至少有一条可重复、跨场景/时间的 public-address path；
XZB5 reality_anchor 证明撤掉接口会改变第三方调用/归因/进入方式；
XZB6 decision_right 可以为空或非最终，不能因为接口“官方”就臆造裁定权；
XZB7 “唯一”只要是唯一地址/入口，不自动转成 z。
```

### 7.2 z candidate

```text
Z1 object_layer 为判断、答案、标准、候选或终局裁定层；
Z2 current_window 内确实存在可比较的多个判断/候选中心或潜在竞争终局；
Z3 changed_variable 指向 adjudication_center_distribution / final authority；
Z4 decision_right 现实收束到一个 single final center；
Z5 relation_shape 是 multiple candidate/judgment nodes -> one final adjudicator；
Z6 reality_anchor 证明该中心能让其他判断失去同等最终效力；
Z7 只有统一入口/统一账号/统一代表而无 final decision right，不得判 z。
```

## 8. nearest-neighbor 最小差异

### 8.1 z vs x并z

```text
x并z：唯一的是“世界从哪里找到/调用/进入我”。
z：唯一的是“最后谁/什么说了算”。
```

最小对照：

- “所有申请只能从官网提交，但官网不能决定结果” → x并z 强，官网 z FAIL。
- “申请可从多个渠道进入，但主席有最终一票决定” → z 强，不因多入口否定 z。

### 8.2 x并z vs xn

```text
x并z：公共入口本身让第三方稳定寻址与调用。
xn：内部运行怎样被流程、记录、节点持续组织。
```

一个官网可以只是入口；后台审核工作流是否 xn 要另拆 object_layer。

### 8.3 z vs zx

```text
z：既定裁定层内最终效力收束到单一中心。
zx：主体生成并占据自身方向，以权能压退竞争方向。
```

主席依法终审可 z；不能因为结果排他就自动 zx。

## 9. False-positive guards

1. “官方” ≠ z。
2. “唯一入口” ≠ z。
3. “统一账号/统一前台/统一窗口” ≠ z。
4. “最终”字样 ≠ z；必须查 final decision right 与同层竞争中心是否退出。
5. “唯一”字样 ≠ x并z；唯一答案若不是公共接口不算 x并z。
6. 高知名度 ≠ x并z；必须存在稳定调用/归因/进入接口。
7. 接口负责登记/转交 ≠ 接口拥有最终裁定权。
8. 最终裁定中心存在 ≠ 自动存在唯一公共接口。
9. x并z FAIL 不推出 z；z FAIL 不推出 x并z。
10. 同一机构同时拥有官网与终审权时，必须按 object_layer 拆 IR，禁止机构名把两层粘死。

## 10. Adversarial tests

### T1｜关键词诱导

“官方唯一窗口负责收材料，结果由五人匿名多数决，窗口无投票权。”

预期：窗口 `x并z PASS`；窗口 `z FAIL`。

### T2｜题材/职业/情绪诱导

“威严的最高法院新闻办公室是全国统一发言入口，但办公室不能改判决。”

预期：新闻办公室可查 x并z；“最高法院/威严”不使办公室自动 z。

### T3｜对象层错位

“学校只有一个招生官网；录取最终由校长单人决定。”

预期：官网接口层 `x并z`；录取裁定层 `z`；必须 SPLIT_IR。

### T4｜时间窗错位

“去年官方账号是唯一入口且董事长终审；今年开放三个入口并改为委员会多数决。”

预期：不得沿用去年 x并z 的唯一入口状态，也不得沿用旧 z 单中心状态。

### T5｜同关系词异对象层

“统一口径”A：所有记者只从一个账号获取新闻；“统一口径”B：所有部门意见最终以总裁决定为准。

预期：A 优先查 x并z；B 优先查 z。

### T6｜对端不存在不等于本端成立

“旧官网已停、主席终审权也被撤销，临时由多个邮箱收件且评审无最终中心。”

预期：`x并z/z` 都 FAIL 或 UNKNOWN，不能一端掉了就给另一端补位。

### T7｜唯一结果伪 z

“三个候选因两个自动失效，只剩一个；无人拥有最终裁定权。”

预期：结果唯一不等于 z。

### T8｜统一品牌伪 x并z

“所有产品包装完全统一，但客户无法通过品牌稳定找到、调用、归因或进入任何服务对象。”

预期：仅视觉统一，x并z FAIL。

### T9｜多入口仍可 z

“申请可从网页、邮件、线下三处提交，但终审委员会主席有唯一最终否决权。”

预期：多入口不影响裁定层 z；不能因 x并z 唯一入口不成立而否定 z。

### T10｜唯一接口不拥有内容权

“API Gateway 是唯一外部调用地址，但它只路由请求，业务决定由后端多个服务共同完成。”

预期：gateway 可查 x并z；gateway z FAIL。

## 11. Removal / reverse / same-layer / current-window

### removal

**x并z removal**：移除唯一官网/账号/前台，但保持主席终审权不变。若第三方寻址与提交方式改变而最终裁定仍相同，则证明接口变量与裁定变量独立。

**z removal**：保留官网唯一入口，但把主席改为无终审权的备案人。若第三方仍能通过官网稳定调用，而最终结果不再由单中心决定，则 z 下降而 x并z 可保持。

### reverse

- 保留“官方唯一”字样，却让该节点只能转交，z 必须掉。
- 保留“最终”字样，却没有任何竞争判断被它现实压成唯一有效终局，z 必须掉。
- 保留“统一品牌”却失去稳定第三方寻址/调用映射，x并z 必须掉。

### same-layer

比较 z 与 x并z 时不能把“提交接口层”与“资助裁定层”混成一个 object_layer。若一句话同时包含两者，必须 SPLIT_IR；只有同层证据才允许讨论该层是否兼具接口与裁定功能。

### current-window

历史上曾是官方唯一入口或曾有最终裁定权，不得永久贴到当前。接口开放/撤销、权限改制、委员会改组都必须重新抽取 current_window。

## 12. 状态迁移规则

本轮新增两类独立迁移：

```text
多个非稳定入口
→ 一个稳定公共地址被建立
→ x并z candidate 上升

一个稳定公共地址
→ 拆成多个仍可稳定调用的入口
→ “唯一接口”证据下降，但 x并z 本身未必消失
```

以及：

```text
多个同等判断中心
→ 单一终审中心取得最终效力
→ z candidate 上升

单一终审中心
→ 改为多节点共同终审 / 无单一最终中心
→ z candidate 下降
```

因此“接口是否唯一”与“裁定是否单中心”必须独立追踪，不能共用一个 uniqueness flag。

## 13. 成功门

本轮不是重复已有机制，新增解释器资产包括：

1. `UNIQUENESS_TYPE_AUDIT_REQUIRED`；
2. `public_addressability` vs `adjudication_center_distribution` 的 changed_variable 分流；
3. `decision_right` 对 x并z 的非必要最终性约束；
4. caller→interface 与 candidates→final-center 的 relation_shape 分账；
5. “唯一接口变化”与“唯一裁定变化”的双状态迁移规则；
6. 10 个 adversarial negatives / minimal pairs。

结论：**PASS，可提交 research-only candidate。**

## 14. 下一轮风险

本轮占用 `z` 与 `x并z`，下一轮不得连续选择这两个十元。

当前下一高翻译风险候选：`zn vs nx`。

原因：自然语言里的“我尊重你自己决定 / 我不干涉你 / 你自己去找别人解决 / 我给你自由”容易把“真实保存他者独立成立资格（zn）”与“主体不占最终方向、沿外部既有路线续接（nx）”混在一起。下一轮应优先审计 `decision_right + relation_source + other_independent_path`：不占方向不等于主动保存他者成立资格。
