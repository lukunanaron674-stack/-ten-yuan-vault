# 十元发散引擎 · 研发蓝图 v1

## 核心转向（一句话）

> 中心从「生成一个结果」换成「**制造发散路径**」。

原来的"输入 `zn少女` → 抽一条 mapping → 输出卡"**保留，但只算末端工具**。
真正的核心是——输入**除了十元以外的任何东西**：一个对象 / 一个题材 / 一个故事 / 一个卡点 / 一个问题。
系统**不先判断它属于哪个十元**，而是把它同时放到十个透镜下。

## 为什么这么转向

旧流程：
```text
十元 → mapping → 输出        （数据库→抽卡，越做越大，智力不增）
```
新流程：
```text
十元 → 提问模板 → 变量发现 → 发散操作 → 分支
                              │
mapping（降级为分支时调用的参考，不再驱动答案）：
  分支生成参考案例 / 边界检查 / 反例检查 / 具象化参考
```
一句话：**mapping 不再驱动答案，mapping 服务推理。**哪怕仓库没素材，十组操作成熟后它自己也能长树。

## 主流程（五层）

输入例：`普通校园偶像少女`

### 第一层 · 问题拆解（可完全不用十元）
拆"普通"普通在哪：身份普通 / 目标普通 / 出道路径普通 / 队友关系普通 / 学校机制普通 / 竞争方式普通 / 失败代价普通 / 成长方式普通 / 结局普通…
> 如果连"哪里普通"都没找到，十元只会对空气挥拳。

### 第二层 · 十元扫描变量
同取"出道路径普通"：不贴性格标签，而是同一个问题的**三个不同可变变量**——
- `zx`：谁有权改变最终方向？(选秀→改规则→自创舞台→夺决定权→让非偶像也能参加)
- `nx`：哪些方向/权限/资源已在别人手里？(要老师推荐/借前辈/接退团位/沿学校制度/借别人资格账号)
- `xn`：流程本身怎么重新组织？(一年一次/每周积分淘汰/先巡演再定正式/失败改下一轮流程/演出·学习·训练冲突排程)

### 第三层 · 继续分叉（不许"抽到就停"）
选了 `xz → 出道窗口只剩三个月`，还须追问第二层第一层：为什么只剩三个月？→（年龄上限/毕业/社团解散/撤资/主唱转学/场馆拆除/身体状态）
再选"社团解散"再追：为什么解散？→（政策/人数不足/经费/内讧/老师离职/要改别的社）
> 这才叫发散树；"抽到 XZ-W-003"玩两次就产生现代的空虚。

### 第四层 · 十元交叉
取 `nx 只能沿学校偶像制度选拔` + `xz 只剩毕业前三个月` + `zn 公司要她放弃原创曲` →
> 一个只能沿学校既有选拔制度前进的少女，只剩毕业前三个月，而唯一给资格的公司在逼她放弃坚持多年的原创曲。
再叠 `nz 唯一能补齐完整阵容的是她曾决裂的搭档`——立刻再长一层。

### 第五层 · 淘汰假发散（收敛）
用已有的检验法：nearest neighbor / removal test / reverse test / counterexample / evidence。
删除标准：**改变变量后，故事结构真的发生变化**。
当面删的假发散：
- "她很努力"（形容词，不是结构变量）
- "她穿红衣服，所以 zx"
- "她很惨，所以 xz"

## 三个引擎（这就是组合工作流）

| 引擎 | 职责 | 例 |
|---|---|---|
| ① 变量发现器 | 东西里有哪些"能量变"的量 | 偶像故事→ 权限/资源/时间/关系/资格/流程/身份/回返/不可逆窗口 |
| ② 十元变换器 | 从某十元方向改变此变量会怎样 | 变量"出道资格"：zx 夺资格定义权 / z 确认者定资格是否成立 / nx 借既有资格入口 / xn 多阶段形成资格 / xz 窗口关闭 / nz 失去后能否回来 |
| ③ 组合收束器 | 把 zx+xz+zn 分支组合成完整故事结构 | 然后评分：新鲜度/结构差异/冲突强度/十元纯度/是否只换皮/能否继续长 |

## ⭐ 现在最重要的事不是代码

先把**十个"发散操作"定出来** —— 每个十元对**任意对象**能执行哪些"变换操作"。粗定义：

| 十元 | 发散操作（改什么/问什么） |
|---|---|
| zx | 改**谁拥有最终方向权** |
| nx | 改**谁必须接入既有方向/权限** |
| zn | 改**什么原则还能进入未来判断** |
| x | 改**什么真正归谁处置** |
| n | 改**什么进入后必须被持续承载** |
| x并z | 改**什么内部结构转成稳定对外接口** |
| xn | 改**运行流程/阶段/节奏/组织方式** |
| z | 改**谁确认什么成立** |
| xz | 改**哪些回头路正在关闭** |
| nz | 改**哪些关系/位置还能真实回返** |

> 这比再加 100 个世界观 mapping 值钱。十组操作一旦成熟，**哪怕仓库是空的它也能自己长树**。

## 新总结构（角色退居成应用之一）

```text
十元发散引擎
│  输入：一个对象/题材/故事/卡点/问题（不预贴十元）
├─ 问题拆解 → 锁定"普通在哪"
├─ ? 三引擎：变量发现 / 十元变换 / 组合收束
└─ 产出应用：
   角色发散 故事发散 题材发散 世界观发散
   关系发散 场景发散 游戏机制发散 创作卡点解决
```
少女生成器 = `十元发散引擎 → 角色应用`。层级至此才顺。
