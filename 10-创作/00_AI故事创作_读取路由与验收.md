# AI故事创作｜先锁对象，再读有限文件，最后解释十元

> 本文只负责**创作任务的文件路由、对象锚定和交付验收**（L3），不新增十元定义、不解冻关系。任何 AI（包括不自动读取 AGENTS.md 的网页模型）必须在任务开始时显式载入此页。

## 0｜先消除歧义：这是创作，不是理论百科问答

用户刚让 AI 写了一个故事，接着问「十元构成是」「故事里的十元呢」「你写的那个」：**默认引用最近一份具体故事或作品**。回答应先给这部故事的主次构成、人物行动与三幕动态链，不能先泛讲「三元、十元、五轴」的定义。

先确认五元组：
`TASK_MODE / STORY_ID / EXACT_SOURCE_PATH / SOURCE_VERSION_OR_SHA / USER_LOCKED_CONSTRAINTS`。

- `TASK_MODE` 取 `WRITE_STORY`、`EXPLAIN_STORY`、`REVISE_STORY`、`ADAPT_SOCIAL`、`THEORY_AUDIT` 之一。
- `STORY_ID` 是本轮确切故事名，不是泛称「故事骨架」；同名文件多版本时逐一辨认，不能选搜索排序第一条。
- `EXACT_SOURCE_PATH` 是已读到正文的真实文件，不是 AI 猜测的路径。外部模型的临时文件/未同步文件不可冒称已在 GitHub main 或 Obsidian 本地存在。
- `USER_LOCKED_CONSTRAINTS`（人物十元主次、五维主题、结局、世界规则等）属于**作者的创作约束**；可在本作品沿用，但不得偷换成「理论正本／观众实测」。
- 如果缺少正文，明确说「未获取该稿」；仅可根据当前对话提供的原文做**有范围的草案分析**，不得假装通读了全文件。

## 1｜双序列：文件权力和任务读取不是一回事

**文件治理优先级（不改）**：L0 `AGENTS.md` → 任务适用的 L1 → L2 理论正本 → L3 路由 → L4 证据 → L5 项目事实/作者设计 → L6 历史。

**具体创作任务的检索/阅读链**：
1. 完成 L0 的最低启动和任务分类：记录 main SHA，读 `00-中枢索引/AI文件权力与任务总览.md`、`00-中枢索引/总入口.md` 和本路由；若属于专项十元链/动态链审计再读对应 L1。
2. **先定位唯一工作对象**：当前会话的作者指令、真实的故事稿、故事项目的已锁定世界/人物/事件卡、上个版本差异。优先精确文件名/路径，不做全库「故事骨架」宽泛检索。
3. **只按实际问题读取相关 L2**：涉及感受语义，读 `01-十元系统/三元十元感受模型_核心正本_v1.0_20261007.md`、`R3A`、`R3B`；涉及生克补合法性，再读关系总控与单条关系卡。故事结构/自媒体改写不需要遍历十元全部信息卡。
4. 需要文字横纵构图才读 `07-Codex大脑库/skills/story-horizontal-vertical-text/SKILL.md`；改 `.canvas` 才读 `obsidian-canvas-layout/SKILL.md`；涉及具体十元链可读 `ten-yuan-chain/SKILL.md`。Skill 管格式/生产，不代替理论。
5. **先交付用户问的具体对象，再给最小必要依据**；不因读了 L2 就将创作问题改答为理论课程。

默认一次创作任务以**1 个确切故事＋相关项目资料＋必要正本**为范围，不预读整库。遇到阻塞只报告影响此任务的缺口。

## 2｜三个绝不能混的层

| 分账 | 允许回答 | 不允许冒充 |
|---|---|---|
| 故事构成／作者设计 | 人物想要什么、谁阻止、世界规则、五维主题、用户指定的十元主次、起点→变化→终点、代价回收 | 把创作符号当作对象的永恒本体或 L2 已证机制 |
| 十元感受预测【H】 | `刺激+观察者+语境+时间窗` 可能激活的十元方向、可见诱发手段、反例 | 把旧端点结构变量直接冒充十元 L1 感受核；AI 自评分说成真人实测 |
| 理论/证据审计 | 查当前 L2 正本、单条关系卡、冻结状态、冲突和证据等级 | 因五轴相反就推导生克补；因「像家人」就锁 N；因「危险」就锁 XZ |

特别注意：R3B 现行三层是 `L1感受核 → L2诱发机制 → L3领域表现`，**与仓库的文件等级 L0–L6 不同名、不同对象**。三元 X/Z/N 有最小感受核，七个复合十元尚未全面冻结 L1 体验定义，统一保留 `FEELING_CORE_PENDING`；复合端点的数值是设计目标或 AI 假设，不写为真人感受报告。

**角色十元作者锁定不因感受模型迁移自动作废**：在故事图中照写作者锁定符号，注明 `【USER-设计约束】`；分析观众感受时另行标 `【H-感受预测】`。不因理论迁移擅自删掉作者已经设计的角色与关系。

## 3｜事件必须先成立，十元才有作用位置

按此顺序制作或检查故事：

```text
作者目标／题材／世界规则／已锁人物
  ↓
人物需求与冲突对象（谁想要什么，谁有能力阻止）
  ↓
E1 起点：可观察的限制／拥有／缺失
  ↓ 具体主体做了什么，哪个变量被改变
E2 变化：新信息/行为 → 约束变化 → 代价
  ↓ 变化必须成为下一事件的前提
E3 终点：选择与后果 → 残留/回收
  ↓
五维与十元设计符号【USER/H分开】
  ↓
观众十元感受预测【H】→ 用户/真实观众反馈【实测】
  ↓
剧本/分镜/小红书改编（按请求单独生产）
```

每个关键事件最少记录：
`actor → action → changed_variable(before→after) → affected_object → consequence → next_event`。
删去一个事件后，若后续照样成立，则此事件可能只是气氛卡，不应宣称因果链已经构成。

## 4｜按任务分流，固定第一屏的答案对象

- **EXPLAIN_STORY（用户问「故事十元构成」）**：先给 `故事一句话主结构＋人物十元【USER/H】＋三幕事件变化`；再给 `生/克/补? 的可见行动/变量/状态`；最后一句话写未锁理论项。**禁止**先输出十元全局百科表。
- **WRITE_STORY**：先构成可发生的事件与人物选择；对候选写因果和删卡测试；未确认前保留【H】，不擅自写入正本。可选 1–10 目标感受谱，但不得用它代替事件。
- **REVISE_STORY**：先读现稿，说明本次只改哪些事件/角色；保持其他已确认设定。输出前后差异。
- **ADAPT_SOCIAL**：从**已确定或明确标记候选的故事稿**改写小红书等文案；保留虚构作品说明；不把社媒钩子或改编当故事 canon 的直接改写。不强行重开 L2 审计。
- **THEORY_AUDIT**：这时才完整走 L1/L2、信息卡、关系卡、冻结清单与二审对照；不要当成每次写故事必需的长流程。

## 5｜已知冲突，不静默裁决

`01-十元系统/【xz信息量卡v2】.md`（内部 v2.2）与 `01-十元系统/01-十元信息卡/【xz信息量卡v2】.md`（内部 v2.0）**都标 `canonical-current`**，但描述存在差异。即使日期不同，也不能凭名称或新旧单方面宣布覆盖：在理论判断处标 `待二审`，查治理索引与后续裁决；若故事写作不依赖该冲突，继续产出【H】事件，不借冲突强行锁 XZ 理论。不得修改 L2 来掩盖冲突。

## 6｜每次只做可验证的最小交付

返回前五项核对：
- [ ] 回答的是**当前故事/具体问题**，不是系统泛论。
- [ ] 指明实际读取的 `source_path + version/SHA`；没有就写「未获取」。
- [ ] 作者设计、AI预测、真人证据分账；L2关系冻结/冲突显式标。
- [ ] 至少三个关键事件有动作、变量与后果；能通过删卡反事实检查（若任务涉及创作）。
- [ ] 未改 L2、未制造重复 Canvas、未把未完成写成完成。

**停止条件**：本轮目标问题已回答、所需证据已标记、创作交付已完成即结束；不因发现整个库里更多历史分歧而无限扩展。

## 7｜发给千问/其他模型的极短启动指令

> 你操作的是我的 Obsidian 创作库。先按 `AGENTS.md` 的 L0 开始，读取 `00-中枢索引/总入口.md` 和 `10-创作/00_AI故事创作_读取路由与验收.md`。此次模式是【填写 WRITE_STORY/EXPLAIN_STORY/REVISE_STORY/ADAPT_SOCIAL】，当前对象是【填写故事名与真实文件路径】。先报告你实际读取的文件路径，再先回答这个故事的事件构成与作者锁定十元，不要先讲十元通论。L2只按需读；用户设计约束、AI预测、真人感受分账，含 z/zn 关系冻结与 XZ 同级冲突标待二审。若原稿未访问到，就说未访问到，绝不声称已写回或已读完。结束时按 §6 自检，不扩大任务。
