# 《三国演义》关羽过五关斩六将｜zx↔nx 外部通关权限存在但未走通道压力测试

## 结论先行

本轮锁定：

> **外部通关权限明确存在，但主体没有实际沿该权限通道推进，因此不能只凭“权限在别人手里”判 nx；关羽在当前过关阶段以自身公开权能直接改写通行结果，形成 zx 当前状态高显影。**

本轮不把“关羽能打”“过五关斩六将很威风”直接判 zx。真正成立的是：守关节点明确提出“无曹操文凭则需回报丞相后方可放行”，关羽知道该通道存在，却拒绝等待，把“能否继续通行”的实际决定改由自身武力公开压入现场，并使关口原有拒绝结果失效。

因此核心结构为：

```text
外部许可：曹操文凭 / 守关回报接口
→ 关羽明确知道
→ 不等待、不请求补发、不沿该接口
→ 公开强制过关
→ 守关方原拒绝无法维持
= zx 当前状态高显影
≠ nx 当前通道功能
```

---

## 1｜剧情事实

### 触发

关羽得知刘备在河北，挂印封金，护送二位嫂嫂离开曹营寻兄。曹操本人后来允许其离去，但关羽启程时没有取得正式通关文凭。

### 对象

本轮只看第二十七回中过关权限与实际通行方式，不把关羽整体忠义人格、曹操送行态度或后续古城相会混入。

### 明确动作

1. 东岭关孔秀询问关羽是否持有曹操文凭。
2. 关羽明确回答因行期仓促，没有取得文凭。
3. 孔秀提出：既无文凭，应先派人禀报曹操，得到允许后方可放行。
4. 关羽拒绝等待，理由是回报会耽误行程。
5. 孔秀坚持法度，并进一步提出留下家眷为质。
6. 关羽公开动武，杀孔秀，直接通过东岭关。
7. 随后洛阳、汜水关、荥阳、黄河渡口继续出现阻拦、设伏或拒绝通行，关羽仍以自身行动强行突破，最终实际渡过黄河。

### 结果

- 关羽没有通过曹操补发文凭或逐关审批完成通行。
- 原关口体系的“不放行”无法维持。
- “能否继续北行”的现场结果由关羽自身行动直接改写。

## 2｜zx 判断

### 支持 zx 的证据

现行 zx 要求的不只是动作强，而是：

```text
主体自身方向明确
+ 权能公开进入现实
+ 他者 / 环境被迫响应
+ 主体当前作用与决定范围上升
```

本段满足：

- 关羽自己占据“立即继续寻兄”的方向；
- 在守关明确拒绝时公开使用自身强制权能；
- 原本能阻断其通行的守关节点被直接压破；
- 关羽把自己从“无文凭、原则上不能通行者”变成现实中实际通过关口的人。

因此锁定：

`zx_current_state_stage: evidence-locked`

只锁当前状态 / 行为功能 / 关系位置，不锁稳定人物本体。

### 为什么不是“杀人所以 zx”

若只保留杀将而没有：

```text
外部拒绝通行
→ 主体不沿许可通道
→ 公开改变通行结果
```

则只能证明战斗行为，不能独立证明 zx。

---

## 3｜nx 判断

本阶段 `nx` 排除。

外部权限当然存在：曹操文凭、守关体系及“禀丞相后方可放行”都是清楚的现实权限节点。

但 nx v2.5 要求主体**实际沿既有关系、权限或解决通道推进**。本段关羽恰恰拒绝这么做：

- 不等待守关回报；
- 不请求补发文凭；
- 不把自己的通行结果交给曹操再次裁定；
- 不沿守关体系取得许可。

所以：

> **权限外置，只能证明权限位置不在主体；主体实际沿外部接口推进，才激活 nx 关系功能。**

正式记录：

`nx_in_passage_execution_layer: rejected`

---

## 4｜关键压力

本轮压力是：

```text
护送二嫂
+ 急于寻兄
+ 没有通关文凭
+ 曹操辖区关卡具有真实阻断权
```

压力本身不直接判 zx 或 nx。

真正决定分类的是：关羽面对这个外部权限障碍后，是进入权限通道，还是拒绝通道并用自身权能直接改写结果。

---

## 5｜拿掉测试

### 拿掉“关羽武艺高强”标签

只保留：

```text
无文凭
→ 守关提出回报审批
→ 主体拒绝等待
→ 直接使拒绝结果失效并通过
```

zx 结构仍在，所以不是“强者 = zx”。

### 拿掉“曹操允许关羽离开”的背景

只看关口对象层，守将仍然把正式文凭或回报批准当作放行前置条件；关羽仍没有实际沿该接口取得通行。

因此 nx 排除仍成立。

### 拿掉关羽的实际强制突破

如果关羽最后停下等待孔秀回报曹操、取得批准后再走，则当前 zx 会显著下降，nx 通行关系功能上升。

---

## 6｜反向测试

### 反向成 nx

```text
关羽无文凭
→ 接受孔秀“先禀曹操”
→ 等待外部批准
→ 获准后通行
= nx 权限关系功能
```

### 反向成 x

若关羽本来就持有覆盖五关的正式通行文凭，且守关者必须直接承认，则通行权限已进入他的稳定可调用边界，应优先检查 x，而不是 nx。

### 反向成伪 zx

若关羽公开冲突得很激烈，但最终仍被关口阻断、必须回到曹操审批接口后才能通行，则“动作强”不足以锁 zx。

---

## 7｜最近邻排除

### zx vs x

关羽并没有既有、稳定的五关通行处分权；恰恰因为缺文凭才发生冲突。因此不是普通调用已有 x。

### zx vs xn

护送二嫂、选择路线、连续过关有行动组织成分，但核心变量不是排程和流程，而是遇到拒绝后谁成为实际通行结果的作用权来源。

### nx vs xn

若关羽主动规划绕路、等待时间、设置多个通关节点，属于 xn；本轮 nx 只问是否沿曹操 / 关卡已有许可通道推进。答案是否定的。

### nx vs zx

本案不是“外部权限存在所以 nx + 强行动所以 zx”两端并存。当前同一通行对象层上，两条路径是竞争的：

```text
沿许可接口取得通过 → nx
拒绝许可接口、公开压过阻断 → zx
```

本桥段实际选择后者。

## 8｜第三因素冻结

以下均冻结，不参与木轴主判：

- 关羽忠义；
- 是否历史真实发生过五关斩将；
- 曹操是否故意不给文凭；
- 孔秀等守将的善恶；
- 关羽武力强弱；
- 刘备是否值得追随；
- 最终能否古城相会。

本轮只判《三国演义》文本内：**通关权限在哪里、主体是否实际使用该通道、最后谁让通行结果生效。**

---

## 9｜补关系检查

严格 `zx ↔ nx` 补关系不成立。

原因：本对象层里 nx 并未实际激活，第一道“两端独立成立”就失败。不能因为“外部许可本来存在”就把一个未被主体实际使用的 nx 端硬焊进来。

---

本轮可靠结论：

> **外部权限存在 ≠ nx 自动成立。nx 还必须看到主体实际沿该外部权限 / 关系 / 流程通道推进。若主体明确拒绝该通道，并以自身公开权能直接使原阻断失效，则当前同对象层应转查 zx。**
