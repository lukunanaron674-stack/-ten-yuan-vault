# 《三国演义》关羽｜荆州失守至麦城的 zx-nx / x 延迟退出压力测试

## 1｜本轮只测试一个窄问题

> 当人物原本拥有真实局部 `x` 控制时，外部势力开始夺回 / 切断该对象，`x` 是否一定在第一条“撤回 / 索回 / 失守”信息出现时立即归零？

本轮只锁关羽本人的现场局部控制与其逐步退出过程。

特别禁止把刘备集团早年“借荆州”的 `nx` 许可关系机械转记到关羽个人：那是更高集团层的历史关系。本例只把它与刘备、韩信两案做对象层控制比较。

## 2｜剧情事实

第75回，关羽仍在樊城前线拥有真实军队、军寨与军令调用；荆州后方则由其体系中的烽火台、城门、守将、家属与粮源支撑。

吕蒙实施白衣渡江后，并非只发一句“荆州归吴”的名义通知，而是连续切断关羽 `x` 所依赖的现实接口：

1. 先骗过并控制沿江烽火台，切断预警接口；
2. 利用已获守军赚开城门，吴军实际进入并占领荆州；
3. 孙权随后进入荆州，继续接管地方官吏与治理；
4. 公安傅士仁、南郡糜芳相继降吴，关羽失去后方城池与粮源；
5. 第76回关羽使者回营后，将士得知家属在荆州受吴方安抚，军心开始离散；
6. 关羽回取荆州途中遭吴军多路夹击，本部将士不断逃回荆州；
7. 最后部众锐减，只能退守麦城。

因此真正状态不是：

```text
荆州被东吴宣布索回
→ 关羽所有现实控制同一瞬间归零
```

而是：

```text
原局部 x 真实存在
→ 预警接口被切
→ 城池接口被夺
→ 后方守将 / 粮源退出
→ 家属与军心被对手重新绑定
→ 部众持续离散
→ 可调用对象越来越少
→ 原局部 x 延迟退出
```

## 3｜x 判断

正式锁：

`x_prior_local_command_and_support_boundary: evidence-locked`

`x_control_exit_is_delayed_not_instant: evidence-locked`

关羽原本不是空有“镇守荆州”头衔。其军队、烽火、城池后方、粮源、将士家属与守将共同构成真实可运行的控制系统。

吕蒙袭荆州以后，这个 `x` 也不是靠一句名义变化消失，而是随着现实调用接口被逐步切断而退出。

所以本例支持：

> **`x` 的退出应检查现实调用边界是否还存在，而不能只看许可、诏令或名义状态。**

## 4｜zx 判断

正式排除：

`zx_in_narrow_stage: rejected_as_primary`

关羽得知荆州失守后仍愤怒、拒降、催军回取荆州，并不等于 `zx`。

本阶段没有看到：

- 关羽把决定范围继续向外扩大；
- 新的城池、人员或权限被稳定纳入自身决定边界；
- 对手秩序被迫承认一个新增的关羽最高接口。

相反，当前最显著的是已有控制边界持续收缩。

因此：

> **强硬、拒降、继续战斗 ≠ zx；决定范围在缩小时尤其不能把“意志强”偷换成扩权。**

## 5｜nx 判断

本窄阶段不以 `nx` 为主判。

关羽并没有因为荆州失守，就在当前核心对象层重新沿东吴许可 / 关系通道续接；他主要尝试以自身既有军队回取荆州。

后续麦城求援刘封、孟达可单独检查 `nx` 救援关系功能，但不倒灌到本轮“既有 `x` 如何退出”的主判。

同时再次声明：刘备集团早年的“借荆州许可”属于集团层旧关系，不自动变成关羽个人 `nx` 本体或关系功能。

## 6｜关键压力

真正压力不是“关羽打输了”，而是：

> **对手连续切断原 `x` 成立所依赖的现实接口。**

包括：预警、城池、后方守将、粮源、家属安全绑定、军心与兵员。

这让 `x` 从“仍能运行”逐步走向“无法维持”。

## 7｜拿掉测试

### 7.1 拿掉吕蒙对白衣渡江后的现实接管

如果东吴只宣布“荆州应归我”，却没有控制烽火、城门、官吏与军队，那么不能高纯锁定关羽原 `x` 已退出。

### 7.2 拿掉傅士仁、糜芳投降与粮源断裂

关羽仍可能已失荆州城，但后方军政支持链的崩坏程度会下降，`x` 退出速度与范围需要重判。

### 7.3 拿掉将士离散

若关羽仍拥有完整主力并稳定服从，其“前线军队调用 `x`”仍可继续存在，即使“荆州城池控制 `x`”已经退出。

这正说明 `x` 退出也必须按对象层拆分，不能整个人一次性归零。

## 8｜反向测试

### 8.1 反向成“许可变化但 x 长期持续”

```text
东吴索还 / 宣称所有权
→ 但荆州城池仍由关羽体系控制
→ 烽火、粮源、将士、守将均不变
= 许可 / 主张变化，x 仍持续
```

这更接近此前刘备荆州第56回控制。

### 8.2 反向成“x 立即退出”

```text
更高 / 外部节点一行动
→ 同时夺城、收兵、换将、断粮、切指挥链
→ 主体当刻失去全部调用
= x 立即退出
```

这更接近《史记》韩信修武被刘邦夺印符、易置诸将、夺军。

### 8.3 反向成 zx

```text
东吴开始夺取
→ 关羽反而公开夺得新的城池 / 部众 / 军政接口
→ 决定范围扩大
→ 对手或现实秩序承认新增边界
= 才继续检查 zx
```

本轮没有。

## 9｜最近邻排除

### x vs zx

- `x`：当前对象还能否被主体稳定调用。
- `zx`：主体是否把决定范围继续公开推大。

关羽当前是旧 `x` 收缩，不是 `zx` 扩张。

### x vs nx

- `x`：城池、军队、粮源、守将当前是否仍在主体调用边界。
- `nx`：关键权限 / 资源在别人手里，主体是否实际沿其通道借用或续接。

本轮核心是前者的逐步退出。

### nx vs xn

关羽如何撤军、回救、求援、布置麦城可以出现 `xn` 或局部 `nx` 邻近，但不能替代“原 `x` 到底什么时候真实失效”的问题。

## 10｜第三因素冻结

冻结：

- 关羽是否骄傲；
- 吕蒙是否善谋；
- 孙权夺荆州是否正当；
- 糜芳、傅士仁忠奸评价；
- 历史史实与小说差异；
- 关羽最后生死；
- 樊城之战胜负。

只看：

1. 原现实控制是否真实存在；
2. 对手是否实际切断其调用接口；
3. 切断是否一次完成还是分阶段传播；
4. 当前决定范围是扩大还是收缩。

答案为：是 / 是 / 分阶段 / 收缩。

## 11｜与刘备、韩信两案形成的三档

```text
刘备荆州第56回：
外部许可撤回
→ 现实 x 暂时持续

韩信修武：
上位授权撤回
+ 同时夺印符 / 易置诸将 / 夺军
→ 旧 x 立即退出

关羽荆州失守：
外部开始现实夺取
→ 城池、粮源、守将、军心、部众逐层退出
→ 旧 x 延迟退出
```

因此可以形成案例级候选：

> **授权 / 许可变化与 `x` 退出不是同一个变量；`x` 的退出时间取决于现实调用接口何时被实际切断。它可以暂存、即时退出，也可以分层延迟退出。**

目前三档虽已形成，但只有刘备与关羽属于同一文学作品，韩信属于历史材料；本轮不据此修改 L1 或新建待审议。
