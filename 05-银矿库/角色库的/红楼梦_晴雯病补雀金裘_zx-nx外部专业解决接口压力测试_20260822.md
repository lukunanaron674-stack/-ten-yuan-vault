# 红楼梦｜晴雯病补雀金裘｜zx-nx 外部专业解决接口压力测试

## 0｜结论先行

本段锁为：**在“雀金裘已经烧破、宝玉需要把同一件衣裘恢复到可穿状态”这一修复对象层，存在高纯 `nx` 专业解决接口关系功能。**

关键不是晴雯告诉宝玉“孔雀金线可以补”，而是晴雯本人掌握怡红院当前其他人不具备的界线织补能力，并亲自拆里子、固定破口、分经纬、依原纹织补，最终把同一件雀金裘补到不留心几乎看不出的程度。

因此本例可作为“外部信息输入 ≠ nx解决通道”待审议的第二个跨作品高纯反向控制：

```text
只给修补知识
≠ 自动 nx 解决通道

外部主体掌握当前缺失的真实专业操作能力
+ 主体/问题实际接入该接口
+ 同一个破损对象被直接修复
→ nx 关系功能显著成立
```

本段不锁晴雯稳定纯 nx 本体，不锁 zx，不锁严格 zx↔nx 补关系。

## 1｜事实链

宝玉的雀金裘被烧出破口，需要在次日继续使用。晴雯查看后判断可用孔雀金线按界线方法密补；麝月明确指出“这里除了你，还有谁会界线”，直接说明当前关键修补能力集中在晴雯身上。

晴雯此时正在生病，仍实际坐起操作：拆开里子，以小竹弓固定破处，将破口边缘整理松散，再分出经纬，依原衣纹路来回织补。她中途多次因头晕、气喘停下休息，最终在夜里完成修补；麝月与宝玉检查后确认成品已很难看出破绽。

对象、动作、结果闭合：

```text
对象：同一件雀金裘破损
触发：烧洞，现有衣物状态无法正常使用
外部接口：晴雯独有/稀缺的界线织补专业能力
动作：判断材料→拆里→固定→分经纬→依纹织补→整理绒毛
结果：同一件雀金裘恢复到基本可正常穿用
```

## 2｜nx 判断

这里的 `nx` 只锁在“宝玉/当前问题必须接入晴雯的专业修补接口”这一关系功能层，不锁晴雯整个人物是 nx。

在“怎样让这件已经烧破的雀金裘恢复可用”这一对象层：

- 决定性织补能力并不在宝玉稳定调用范围；
- 麝月明确确认当前在场者里晴雯会该技法；
- 晴雯提供的不只是事实或建议，而是亲自完成决定性操作；
- 同一个破损对象由该专业接口直接被修复。

所以：

```yaml
nx_professional_solution_relation: evidence-locked
external_professional_solution_interface: evidence-locked
same_problem_directly_repaired_by_external_interface: true
```

如果从晴雯主体视角切换对象层，她当然是在输出自己的专业 `x/xn` 能力；但对“宝玉如何修复雀金裘”这个木轴关系对象而言，解决接口明显外置在晴雯。

## 3｜zx 判断

本修补窗口排除 `zx` 主判。

晴雯病中硬撑、敢于承担困难修补任务，都不能证明：

- 她因此取得新的怡红院公共处分范围；
- 宝玉、麝月或其他人开始承认一个新增的晴雯最高决定接口；
- 她的现实决定位置超出原有技能/丫鬟关系边界。

修好一件原本破损的衣服，是问题修复，不是公共权能扩张。

```yaml
zx_in_repair_stage: rejected_as_primary
```

## 4｜xn 最近邻排除与主体切面

从晴雯作为“专业解决者”自身看，她确实主动设计并执行了修补流程：选择孔雀线、拆里、固定、分经纬、依原纹织补。因此 `xn` 可作为**提供者一侧的运行组织邻近**。

但本轮研究的是 `zx↔nx` 的关系接口：宝玉当前缺失的是“能把雀金裘修好”的专业能力，他实际必须接入晴雯这一既有专业节点。

所以不能因为外部专业者自己会设计操作流程，就把需求方的 `nx` 关系功能吃掉。

```yaml
xn_in_repair_stage: evidence-locked_as_provider_side_neighbor_only
```

## 5｜关键压力

压力包括：雀金裘次日要用、破口明显、晴雯本人病重。

但“着急”“病中拼命”都不判十元。真正的判据是：当前同对象修复能力是否外置、是否被实际调用、是否直接改变同一个对象。

## 6｜拿掉测试

### 拿掉晴雯专业接口

保留宝玉的修复目标、孔雀线材料与衣裘本身，如果没有等价掌握界线织补的人，原事实链中无法完成同等修复。

→ nx 专业接口是真缺口。

### 拿掉“晴雯亲自织补”，只保留修补知识

如果晴雯只告诉宝玉“用孔雀线按界线法补”，随后由宝玉或其他既有人员独立完成，则会退回“外部信息/方案输入是否足以构成 nx”的灰区。

原文不是：晴雯本人承担并完成决定性操作。

### 拿掉恢复结果

如果晴雯尝试后衣裘仍无法穿用，则最多锁“外部专业接口被调用”，不能锁“同问题被该接口直接修复”。

## 7｜反向测试

### 仅信息型

```text
晴雯只说修补方法
→ 宝玉/麝月自行完成
→ 优先检查信息输入 + 自有执行能力
→ 不自动锁高纯 nx 解决接口
```

### 高纯专业接口型

```text
当前对象无法由需求方自行修复
→ 外部专业者掌握关键操作能力
→ 实际接入
→ 外部专业者直接处理同一对象
→ 当前瓶颈被修复
= nx关系功能强成立
```

本例属于后一种。

## 8｜最近邻排除

- `nx vs 信息输入`：晴雯不是只说方法，而是亲自完成决定性修补。
- `nx vs xn`：晴雯一侧可以有 xn 专业流程组织，但不否定宝玉/问题侧的 nx 外部接口关系。
- `nx vs x`：该织补能力没有进入宝玉的稳定调用边界；衣服修好后，他也不会因此获得晴雯的织补技能。
- `nx vs zx`：修复旧对象不等于扩大公共决定范围。
- `nx vs 强弱/职业`：不是“丫鬟会针线所以 nx”，而是当前同对象的决定性专业能力实际集中在外部节点。

## 9｜第三因素冻结

冻结：晴雯性格刚烈、宝玉对晴雯的感情、主仆身份、病情戏剧性、雀金裘贵重程度、后续人物命运。

只检查：

```text
当前具体问题是什么？
谁掌握直接解决能力？
问题是否真实接入该接口？
外部接口是否直接改变同一个对象？
```

结论不变。
