# 《水浒传》张顺救张横｜zx-nx 入口拒绝后实际续接正向控制

## 0｜本轮问题

当前 pending-review 已确认：口头接受、领命、进入流程不能单独证明 nx；真正执行/结果窗口是否仍沿外部方向推进，证据权重更高。

上一轮刘备“三让徐州”未能成为纯正向控制，因为从拒绝到接受之间发生陶谦死亡、治理权力真空、官民再推举等结构变化。

本轮专门寻找：

```text
同一任务
+ 条件基本不变
+ 主体入口拒绝
+ 没有新增命令、处罚、授权或资源结构变化
+ 最终仍实际沿外部提出的方向行动
```

## 1｜剧情事实

### 触发

张横不听张顺苦谏，擅自劫关胜营寨，被关胜擒获并装入陷车。

张顺回到水寨，把张横被擒的消息告诉阮小二、阮小五、阮小七。

### 外部提出的方向

阮小七提出：不能等，应立即去救张横；阮小二、阮小五赞同。

### 张顺的入口拒绝

张顺明确表示：

```text
未得宋江将令
→ 不敢轻动
```

因此入口处并不是口头接受，而是真实提出了相反的程序判断：应等待主帅将令。

### 条件冻结

从这次拒绝到张顺改变行动之间，没有出现：

- 宋江新将令；
- 新的组织授权；
- 新的处罚或强制；
- 新的兵力、资源或救援条件；
- 张横位置或被俘事实的结构性变化。

发生的只是三阮在同一事实条件下继续强调兄弟救援与时间紧迫，张顺最终被说服。

### 明确动作与结果

张顺没有继续坚持“等将令”，而是实际随三阮行动。当夜四更，水寨出动船只杀奔关胜营寨；三阮在前，张顺在后，真实进入救援行动。

这次救援最终失败、阮小七又被擒，但胜负不影响木轴判断：张顺在真正执行窗口确实沿三阮提出的“立即救人”方向推进。

## 2｜nx 判断

### 结论

```text
nx_actual_continuation_behavior = evidence-locked
```

这里锁的是**当前行为功能**，不是张顺稳定人物本体。

### 为什么成立

本桥段的对象层是：

> 是否在未得到宋江将令时，立即出动救张横。

方向的提出者是三阮。张顺入口处有自己的反向意见“等将令”，但在条件没有结构变化的情况下，他没有重新建立第三条路线，也没有继续占据最终否决位置，而是被关系与群体方向说服，随后真实进入三阮已经提出的行动路线。

因此：

```text
入口拒绝
≠
后段永久非 nx

真正执行窗口重新观察
→ 张顺实际沿外部提出方向推进
→ nx 行为功能上升
```

本例直接补 current pending-review 缺少的“条件基本不变、入口拒绝但实际续接”正向控制。

## 3｜为什么不是纯 nx 人物本体

本轮只有一个窄场景。

而且张顺在前段明确拥有自己的程序判断，并敢提出“不待将令不轻动”。这不能证明他长期没主见。

因此：

```text
stable_essence_locked = false
```

不得由本例反推：

> 张顺 = 稳定纯 nx。

## 4｜zx 判断

### 结论

```text
zx_in_narrow_stage = rejected_as_primary
```

张顺后来参与救援、冲击关胜营寨，不等于 zx。

没有证据显示：

- 张顺获得新的梁山军令权；
- 三阮或水寨秩序围绕张顺新增的决定接口重排；
- 张顺的决定范围公开扩大；
- 他从跟随救援变成新的最高方向来源。

而且本次行动最后失利。胜败本身不是 zx 判据，但文本同样没有“公开扩权”的独立证据。

## 5｜最近邻排除

### nx vs xn

三阮主张立即出救，张顺随后跟随行动。文本没有给出张顺自行设计救援流程、时间表、诱敌结构或资源配置的强证据。

所以：

```text
张顺如何参与执行
≠ 足以锁 xn
```

`xn_local_execution_neighbor` 只记 low/not locked。

### nx vs nz

兄弟关系、同生同死、救张横当然是强动机邻近，但 nz 只能解释为什么张顺被说动，不替木轴回答“最后的行动方向来自哪里”。

因此只记：

```text
nz_kinship_loyalty_neighbor = present_not_formally_locked
```

### nx vs x

张顺没有获得“未得将令即可调动整个水寨”的稳定军令处分权，本次不能锁 x。

## 6｜拿掉测试

### 拿掉兄弟情感词

只保留：

```text
A提出立即行动
→ 张顺先拒绝
→ 条件不变
→ A继续说明原事实的紧迫性
→ 张顺放弃原否决并实际跟随行动
```

nx 当前行为结论仍成立。

### 拿掉最后救援胜负

即使这次救援成功或失败，只要张顺最终实际沿三阮提出的方向出动，nx 判断不变。

### 拿掉入口拒绝

若张顺一开始就直接答应，则仍可能是普通 nx 行为，但本例作为 pending-review“入口拒绝后仍实际续接”的特殊价值消失。

## 7｜反向测试

### 反向成非 nx

如果三阮继续劝说以后，张顺仍坚持等待宋江将令，拒绝出动，那么当前执行层 nx 应排除。

### 反向成 xn

如果张顺拒绝三阮原方案，却自行提出另一套完整救援路线，组织船只、时间、节点并按自己的方案执行，则 xn 上升、当前 nx 下降。

### 反向成 zx

如果张顺通过此次冲突公开取得此前没有的水寨最高军令处分权，使三阮及水寨以后围绕他的新增决定接口运行，才进一步检查 zx。

## 8｜第三因素冻结

以下全部不作为 zx/nx 直接判据：

- 张横是张顺亲哥哥；
- 三阮的义气评价；
- 张顺水战能力；
- 关胜强弱；
- 救援最后失败；
- 阮小七被擒；
- 梁山好汉身份。

冻结以后仍留下：

```text
外部提出方向
→ 主体入口拒绝
→ 条件基本不变
→ 主体后来实际沿该方向推进
```

## 9｜对 pending-review 的增量

本例补足此前缺失的高纯正向控制：

```text
入口拒绝
+ 条件冻结
+ 无新增强迫/命令/授权
+ 最终实际续接
→ 后段仍可锁 nx 行为功能
```

因此候选纪律可以更精确地表达为：

> **nx 不由入口态度决定。入口接受或拒绝都只是弱证据；在条件基本冻结的前提下，真正执行/结果窗口是否沿外部方向推进，权重更高。**

但这仍只补 pending-review 证据，不修改 L1、zx/nx 信息卡、准度卡或 zx补nx 补卡。
