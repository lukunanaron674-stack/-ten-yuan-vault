# 《水浒传》吴用智取大名府｜上位任务与运行骨架分层压力测试

## 结论先行

本轮锁定：

> **“攻打北京、救出卢俊义与石秀”这一上位战役行动需要宋江这一梁山最高军令节点确认，吴用实际在该授权关系内推进，故任务/授权层存在 `nx`；但“元宵潜伏—城内埋伏—城外军进—翠云楼放火为号—里应外合破城”的决定性运行骨架主要由吴用主动组织，故运行方案层 `xn` 高显影。**

> **外部给目标/批准战役，不等于外部已经给出运行方案；同一事件可以同时存在上位 `nx` 与下位 `xn`，但不同对象层不能互相吞并。**

本轮不锁吴用稳定人物本体，不锁严格 `zx↔nx` 补关系。

## 1｜剧情事实、触发、对象、动作与结果

### 触发

宋江病愈后得知卢俊义、石秀仍被留在北京大名府，随即提出催趱军马下山攻打北京。

### 吴用提出运行方案

吴用没有要求宋江逐项告诉自己怎样攻城，而是利用“元宵节北京年例大张灯火”这一条件，提出：

```text
先令城中埋伏
+
外面驱兵大进
+
里应外合
→ 破城
```

宋江明确表示计策可行，并让吴用继续发落。

### 关键节点进一步具体化

吴用指出“城中放火为号”最要紧。时迁自告奋勇并提出利用自己熟悉北京的经验，选择翠云楼作为火号位置；吴用接受这一具体地点，并进一步规定正月十五夜一更放火。

随后整个行动围绕：

```text
元宵窗口
→ 人员分批潜入城内
→ 城外军队按部署推进
→ 翠云楼起火为统一触发号
→ 城内外同步行动
→ 劫牢、破城、救卢俊义与石秀
```

展开。

### 结果

元宵夜时迁按约放火，城内大乱，梁山内外力量同时发动，大名府被破，卢俊义、石秀获救。

## 2｜nx 判断

### 任务/战役授权层：成立

本轮不是从“宋江是首领”这个身份词直接推 nx，而是看真实决定接口：

```text
宋江决定当前梁山要发动攻北京行动
→ 吴用提出方案
→ 宋江明确认可并让吴用发落
→ 吴用在这一战役授权关系内组织执行
```

因此在“梁山是否正式发动这场战役、让军队进入大名府行动”这一对象层，吴用没有脱离宋江/梁山最高军令接口自行发动整支组织。

锁：

`nx_campaign_authorization_relation: evidence-locked`

这属于任务/权限关系功能，不等于吴用没主见。

## 3｜xn 最近邻

### 运行骨架层：高显影

吴用主动组织了决定性运行结构：

- 利用元宵灯会作为行动时间窗口；
- 提出城内先埋伏；
- 提出城外军队同时推进；
- 设定“火起”为统一触发信号；
- 把城内与城外两个行动面编成里应外合结构；
- 接纳时迁提出的翠云楼具体火点后，进一步锁定一更时点。

所以在“这场战役具体怎样运行”这一层，不是沿宋江已经给好的完整方案执行，而是吴用主动搭建节点、时序、信号与协同接口。

锁：

`xn_operational_scheme_design: evidence-locked`

### 时迁的局部贡献不推翻吴用的xn主判

时迁提出“翠云楼”这一具体火号地点，是局部关键实现贡献；但更高的：

```text
元宵窗口
城内埋伏
外军大进
火号触发
里应外合
```

骨架在时迁发言前已经由吴用提出。

因此本轮不能写成“全部细节都由吴用单独发明”，但足以锁吴用为总体运行结构组织者。

## 4｜zx 检查

吴用的计策被宋江采纳并取得成功，不足以证明 `zx`。

没有证据显示本桥段使吴用：

- 取得宋江原有的梁山最高军令权；
- 把梁山是否开战的最终决定接口转移到自己名下；
- 获得超过原军师职责的新公共处分范围；
- 使梁山组织从此围绕一个新增的“吴用最高权力接口”运行。

所以：

`zx_in_narrow_stage: rejected_as_primary`

> **方案强、能调度、最后成功，都不能替代 zx 的“决定范围真实扩大”。**

## 5｜关键压力

压力包括：

- 卢俊义、石秀仍在大名府控制之下；
- 正面多次攻城成本高；
- 元宵节形成非常规渗透窗口；
- 城内外必须同步，否则单点行动容易失败。

这些压力只是让“谁定战役、谁搭运行骨架”更容易被观察，不能直接判十元。

## 6｜拿掉测试

### 拿掉宋江的真实战役确认

如果吴用无需宋江/梁山最高军令接口，就能自行决定整支梁山军是否攻打大名府、独立调用所有人马，那么任务/授权层的 nx 会明显下降，应重新检查 `x/zx`。

### 拿掉吴用的运行方案设计

如果宋江已经规定：

```text
元宵行动
城内埋伏
城外推进
翠云楼火号
一更触发
里应外合
```

吴用只负责照单传令，则当前运行层 `xn` 会显著下降，转向更纯的 `nx` 执行。

### 拿掉时迁的翠云楼提案

吴用原有“元宵—城内埋伏—外军推进—放火为号—里应外合”骨架仍成立；只是具体火号落点需要另找等价节点。

因此时迁贡献重要，但不是吴用 `xn` 成立的唯一支柱。

### 拿掉最终胜利

即使破城失败，只要上述方向来源和运行骨架来源事实不变，nx/xn 分类仍不变。

## 7｜反向测试

### 更纯 nx

宋江把目标、时间、人员、信号、里应外合结构全部规定好；吴用只负责传达与督执行。

### 更纯 xn

宋江只给“救卢俊义石秀”这个最低终点，并明确把战役是否发动、人员与全部资源调度都完整交给吴用；吴用独立搭建全套运行结构。

### zx

吴用原本没有梁山最高军令处分范围，却通过本次行动公开取得“是否发动大战、调用全寨力量”的新增最终决定权，并使宋江与全军以后稳定承认这一新接口。

原文没有。

## 8｜最近邻排除

### nx vs xn

```text
nx：整场战役仍在宋江/梁山最高军令授权关系内启动。
xn：吴用决定这场已获授权的战役具体怎样运行。
```

两个判断属于不同对象层，可同时成立。

### nx vs x

若“是否攻打北京、整支梁山军是否出动”的稳定处分边界本来就归吴用本人，则应优先 `x`。本桥段没有这种证据。

### xn vs zx

搭出复杂、高效甚至成功的方案仍是“怎么运行”；只有实际取得更大的最终决定范围，才进入 `zx`。

### 第三因素冻结

冻结以下因素后结论不变：

- 吴用“智多星”名号；
- 宋江首领身份标签本身；
- 谁更聪明；
- 时迁个人技能；
- 大名府最终是否攻破；
- 梁山立场与人物道德评价。

只保留：

```text
谁确认整场战役进入组织执行？
谁搭决定性运行骨架？
局部贡献是否改变总体骨架归属？
主体是否因此获得新增最高决定范围？
```

## 9｜严格 zx↔nx 补关系检查

本轮不锁严格补关系。

理由：

- `nx` 在战役授权/组织接口层成立；
- `xn` 在运行结构设计层成立；
- 没有独立成立的吴用 `zx` 端点。

因此严格补卡第一道“两端独立成立”就不过，不能因为“宋江批准 + 吴用出计”把普通组织协作焊成 `zx↔nx`。

## 11｜下一轮建议

优先寻找另一部作品中更纯的“外部只给最低终点/合法入口，主体自行建立完整运行骨架”样本，并特别检查：

```text
外部最高节点是否只是批准/给目标？
主体是否真正决定关键节点、时序、人员、资源和成功条件？
如果外部从未实际否决主体方案，是否还能锁任务层nx，还是更应判委派后的x？
```

优先从《西游记》或《红楼梦》寻找最小差异，避免继续在吴用同类军师桥段上堆重复样本。
