# 《水浒传》宋江救柴进：zx-nx 旧恩回报伪 nx 压力测试

## 0｜结论先行

本轮只检查宋江与柴进这一条既有关系在两个阶段承担的功能是否相同。

仓库已有第二十二回正式案例：

```text
宋江杀阎婆惜后被追捕
→ 自己缺少安全落脚与庇护
→ 柴进掌握庄院、收留许可与保护能力
→ 宋江沿旧交/声望关系去投奔
→ 柴进决定接纳
= nx 关系功能高显影
```

第五十二回关系位置反转：

```text
柴进被高廉拘押，性命危急
→ 柴进本人变成被救对象
→ 宋江明确表示与柴进旧来有恩，主动替晁盖领兵下山
→ 破高唐后第一时间寻找、救出柴进
= 当前关系主要承担救援/回报旧恩功能
≠ 宋江沿柴进权限或资源通道解决自己的缺口
```

因此本轮锁定：

> **同一条关系过去曾承担 nx 求助通道，不代表以后每次发生关系行为都自动还是 nx。必须重新检查：当前事件里，对方究竟是“我借用的外部解决接口”，还是“我要保护、回报、维系的关系对象”。**

本轮不跨轴正式锁 `nz`，只记录其为最近邻候选。

---

## 1｜剧情事实

### 触发

李逵从高唐州返回梁山后，说明自己打死殷天锡并连累柴进。戴宗随后带回更明确消息：柴进已经被捕入狱，一家人口家私被抄，且“性命早晚不保”。

这把当前问题明确成：

```text
柴进陷狱
+ 生命与家产处于高风险
→ 是否组织救援
```

### 宋江的明确动作

晁盖先表示柴进一直对山寨有恩，应亲自下山营救。宋江立即提出：晁盖是山寨之主，不宜轻动；自己与柴进“旧来有恩”，愿意替晁盖下山。

随后吴用配置前锋与策应，宋江作为主帅与诸头领率军赴高唐州。

因此本段不是：

```text
柴进向宋江提出方案
→ 柴进掌握关键权限
→ 宋江沿柴进通道推进
```

而是：

```text
宋江得知关系对象受难
→ 自己接受并承担救援方向
→ 使用梁山已有组织能力推进
```

### 结果核验

高廉被杀、梁山进入高唐州后，宋江先下令不得伤害百姓，随后明确要求去大牢救柴进。发现柴进不在普通牢房后继续追问，最后由李逵下井把柴进救出；宋江安排医生、车辆与人员护送柴进及家小回梁山。

这证明“救柴进”不是战前口号，而是实际持续到结果端点的行动方向。

---

## 2｜nx 判断

结论：`nx_relation_function_toward_chai_jin_in_rescue_stage: rejected_as_primary`。

现行 nx 关系功能要求：

```text
主体有一个自己不能直接解决的缺口
→ 关键权限、资源或解决通道在他者手里
→ 主体进入既有关系网络
→ 请求、借力、托关系
→ 沿他者拥有的接口把事情办成
```

第二十二回宋江投柴进完全符合：柴庄、收留许可与庇护能力都属于柴进。

第五十二回却不同：

- 柴进没有掌握宋江此次救援所需的外部许可；
- 柴进无法为宋江提供此次军事行动的关键资源通道；
- 柴进本人正处于失去自由、等待被救的位置；
- 宋江不是向柴进“借”什么，而是在对柴进采取救援行动。

所以：

> **关系对象存在 ≠ nx。**
> **过去求过这个人 ≠ 以后与这个人的全部行为永久 nx 化。**

---

## 3｜zx 判断

结论：`zx_in_narrow_stage: rejected_as_primary`。

宋江主动领兵、最后也攻破高唐州，但这不能直接锁 zx。

本轮截取的核心对象是“宋江与柴进的关系功能变化”。宋江使用的是梁山当时已有的军事组织与主帅接口；文本没有证明他因为“救柴进”第一次取得了此前不存在的更高决定范围。

因此：

```text
主动领兵
+ 最后救成功
≠ 自动 zx
```

若要锁 zx，还必须看到：

```text
原本无此决定范围
→ 宋江以自身权能公开取得并扩大
→ 组织或秩序围绕新增接口重新排列
```

本窄阶段不以此为主变量。

---

## 4｜关键压力

本轮外部压力是：

```text
柴进被拘押
+ 性命早晚不保
+ 高唐州官府掌握拘押与杀害能力
```

压力只负责触发救援，不直接决定 zx/nx。

尤其不能写成：

```text
危机很大
→ 宋江很主动
→ zx
```

也不能写成：

```text
宋江和柴进关系很深
→ nx
```

真正要检查的是当前关系在解决结构中的角色。

---

## 5｜最近邻排除

### nx vs nz

现行 nx 准度卡给出的边界是：

```text
nx：不占方向，沿外部通道推进。
nz：关系可停靠、退出、回返，但不必交出判断资格。
```

本轮不修改水轴理论，也不正式锁宋江此段为 nz；但“念旧恩、关系对象受难后反向救援”明显更接近关系本身持续有价值、发生回返与回报的邻近结构，而不是把柴进当作当前外部解决通道。

因此只记录：`nz_reciprocity_relation_neighbor: present_not_formally_locked`。

### nx vs x

宋江在梁山已有一定军令与组织调用边界，因此军事行动中存在 `x/xn` 邻近；但本轮不由此锁人物本体。

### nx vs xn

吴用负责大量具体兵力配置，宋江也参与军事推进。路线、兵力、战斗节点属于组织运行问题，可检查 `xn`；但它们不能把“柴进是否是宋江的外部解决接口”这个关系问题改写成 nx。

### zx vs x

如果宋江只是在已有梁山主帅/头领权限内调动兵马，应优先检查 `x/xn`；只有他的现实决定边界进一步公开扩大，才锁 zx。

## 6｜拿掉测试

### 拿掉柴进此前曾收留宋江

若拿掉第二十二回旧恩，本轮“回报旧恩”的证据会显著下降；但仍不能因此自动变成 nx。要成立 nx，仍需要找到：宋江当前必须借用柴进掌握的权限、资源或解决通道。

### 拿掉最后攻破高唐州

即使救援最终失败，只要本轮仍是：

```text
柴进是被救对象
→ 宋江主动组织救援
→ 不沿柴进权限通道求人办事
```

“对柴进这条关系不应判 nx 关系功能”的结论仍成立。

因此胜负不是本轮分类支柱。

### 拿掉宋江的梁山身份

如果换成任何主体，只要当前关系对象处于被救位置，主体并非借其权限/资源解决自己的问题，就不能因为“二人有关系”直接锁 nx。

---

## 7｜反向测试

### 反向成高纯 nx

若当前结构改为：

```text
宋江自己遇到新的安全/资源/许可缺口
→ 只有柴进仍掌握关键庄院、官面关系或资源
→ 宋江再次去请求柴进
→ 必须由柴进决定是否提供
```

则重新回到第二十二回的 nx 关系功能结构。

### 反向成 zx

若宋江在救柴进过程中原本无权调用某一更高组织接口，却通过自身公开权能夺取并扩大该决定范围，并使现实秩序承认新增边界，才进一步锁 zx。

---

## 8｜第三因素冻结

冻结以下因素：

- 宋江“及时雨”名号；
- 柴进“小旋风”身份；
- 两人讲义气或是否感人；
- 李逵闯祸；
- 晁盖与宋江谁更适合领兵；
- 高廉是否残暴；
- 公孙胜后续破妖法；
- 梁山最后是否攻破城池；
- 宋江全书其他阶段是否强势。

只检查：

```text
当前关系对象是谁？
他是主体必须借用的外部解决接口，还是被保护/回报的对象？
关键资源与许可是否仍由这个关系对象掌握？
主体是否正沿这个人的既有权限通道求人办事？
```

结论仍是：柴进在本轮救援阶段不承担宋江的 nx 外部解决接口。

---

## 9｜与“宋江投柴进”的同关系最小差异

```text
【第二十二回｜投柴进】
宋江缺安全落脚
→ 柴进掌握庄院、庇护、接纳许可
→ 宋江沿旧交网络请求
= nx 关系功能

【第五十二—五十四回｜救柴进】
柴进自己失去自由并陷入危机
→ 宋江以旧恩为明确理由主动领兵救援
→ 柴进不提供宋江当前解决接口
= 对柴进这条关系的 nx 退出
```

这与《红楼梦》刘姥姥“一进求助 → 二进回礼探访”的案例共同支持一个更窄的跨作品边界：

> **关系过去曾承担 nx 解决通道，不代表关系本身永久等于 nx；每个阶段都必须重新检查当前关系功能。**

当前只有《红楼梦》《水浒传》两部独立作品形成该同类边界，不建立待审议问题。

## 10｜结论

正式结论：

```text
宋江救柴进阶段
= 旧恩回报/救援关系中的伪 nx 反例

同一关系历史上曾是 nx 通道
≠ 当前关系仍自动是 nx

当前对象若已经从“可借用的权限/资源节点”变成“被救、被保护、被回报的关系对象”
→ 必须重新判定关系功能
→ 不得从“有关系、讲人情、过去投奔过”直接锁 nx
```

本轮不锁人物稳定本体，不锁严格 `zx↔nx` 补关系，不正式锁 nz。
