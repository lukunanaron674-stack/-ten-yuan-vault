# 《史记·淮阴侯列传》韩信｜修武军权被刘邦收回后的 zx-nx / x 边界压力测试

## 1｜事实窗口

本轮只测试一个非常窄的问题：

> 当主体已经真实拥有局部军队调用 `x` 时，更高最终授权节点撤回授权，什么时候只是“许可层变化”，什么时候会继续传导到现实控制层，使旧 `x` 真正退出？

《史记·淮阴侯列传》记载：韩信、张耳在赵地领军并不断发兵支援汉王。汉王刘邦从成皋脱身后到修武，清晨自称汉使进入赵军营垒，趁张耳、韩信未起，直接进入卧内夺其印符，随后用印符召集诸将并“易置之”。韩信、张耳起床后才知道汉王已经来到，史文紧接着明确写“汉王夺两人军”。

刘邦随后不是简单把韩信永久废置，而是重新分配：张耳备守赵地；韩信被拜为相国，另“收赵兵未发者击齐”。

所以本轮存在一个少见而干净的动态：

```text
旧阶段：
韩信真实统率既有军队
→ 印符 / 将领 / 军队调用接口在当前层可由韩信运行
= 局部 x

修武撤回：
刘邦直接夺印符
→ 以印符召诸将
→ 易置诸将
→ 明文“夺两人军”
= 更高最终授权节点不仅撤许可，而且切断现实调用链

结果：
旧军队控制 x 真正退出

随后：
刘邦重新给韩信“收赵兵未发者击齐”任务
→ 新上位方向来自刘邦
= nx 新任务入口

新兵力进入韩信实际统率以后
→ 新局部军队调用边界重新形成
= 新 x
```

## 2｜样本类型

正式锁定：

> **上位授权回收真实传导到局部既有 `x` 退出的正向控制。**

这与《三国演义》刘备“东吴索还荆州，但刘备当前城池、驻军和粮草控制并未立即退出”的案例形成直接反向差异。

本轮不锁韩信稳定人物本体，只锁当前军权关系与状态切换。

## 3｜旧 x 为什么成立

正式锁：

`x_prior_army_command_boundary: evidence-locked`

在刘邦进入修武军营以前，韩信并非只有一个空头将军名号。

文本明确表现：

- 韩信、张耳拥有当前军队；
- 赵地兵力持续由其调动并发往汉王方向；
- 诸将处于这套现实军令系统中；
- 印符是当前军令与调动接口的重要现实凭据。

因此这里首先是高纯局部 `x`：

> **军队、诸将与当前调用边界已经真实进入韩信可运行范围。**

不能因为刘邦是更高君主，就倒写成“韩信手里的军队从来都只是 nx，没有 x”。

## 4｜撤回为什么真的让旧 x 退出

正式锁：

`external_final_reassignment_authority: evidence-locked`

`x_prior_command_boundary_revoked_and_exited: evidence-locked`

关键不在刘邦嘴上说“兵权收回”，而在他连续改变了 `x` 成立所依赖的现实调用接口：

1. **夺印符**：切断军令凭据；
2. **召诸将**：直接把将领调用接口接到自己这里；
3. **易置诸将**：重新配置原指挥链；
4. **夺两人军**：史文本身明确确认旧军队控制已被拿走。

所以这次撤回不是纯法律 / 名义 / 关系层变化，而是：

> **更高权限节点实际切断主体对人员、军令凭据与部队的持续调用。**

因此旧 `x` 不能继续维持。

## 5｜nx 判断

本轮不能把“刘邦能收韩信军”直接写成“韩信 = nx”。

真正可锁的 `nx` 是撤回后的**新任务入口**：

`nx_new_campaign_assignment_entry: evidence-locked`

刘邦重新决定：

> 韩信为相国，收赵兵未发者，击齐。

这里“接下来打谁、重新调给哪一批兵”来自刘邦这一上位方向节点；韩信重新进入这条外部任务 / 授权通道。

所以应切成：

```text
旧局部军权怎么运行
= x

旧军权能否被最终回收
= 更高授权关系位置

回收后新的上位任务从哪里来
= nx 新入口

新部队真正重新进入韩信调用后
= 新 x
```

这比把整个将帅关系粗暴写成“有皇帝所以永远 nx”精确得多。

## 6｜zx 判断

正式排除：

`zx_in_revocation_stage: rejected_as_primary`

本轮没有看到韩信：

- 把原有军权继续向外扩张；
- 抵抗刘邦回收并迫使汉廷承认新增权限；
- 取得超出重新授予范围的更高决定接口；
- 让现实秩序围绕一个新增的韩信最高权限重新排布。

相反，当前最显著的是**旧决定范围被收缩 / 重分配**。

因此不能因为韩信是强将、此前战功巨大或后来仍能领兵，就偷判 `zx`。

## 7｜关键压力

本轮关键压力不是“楚汉战争很紧张”，而是：

> **刘邦作为更高最终军政授权节点，直接进入韩信现有军令系统，并把旧军队、印符和诸将调用接口重新接管。**

它正好测试：

> 上位授权撤回是否能真实传导到已形成的局部 `x`。

## 8｜拿掉测试

### 8.1 拿掉“夺印符 / 易置诸将 / 夺两人军”

如果刘邦只是口头说“以后不许你继续领这支军”，但韩信仍实际掌握：

- 印符；
- 诸将；
- 部队；
- 军令调用；

那么只能证明上位许可被撤回，不能高纯锁定旧 `x` 已经退出。

这会更接近刘备荆州案例：许可撤回，但现实控制暂存。

### 8.2 拿掉刘邦的更高最终处分位置

如果刘邦无权重置诸将、收回印符和军队，那么同一动作就不能解释为稳定授权回收，而需另查夺权 / zx / 军变等结构。

### 8.3 拿掉后来“重新授韩信收赵兵击齐”

旧 `x` 退出的结论仍然成立。

后续重新授兵只用于证明：

> **旧 x 退出以后，可以通过新的 nx 上位任务入口再形成新的局部 x。**

它不是旧军权从未退出的证据。

## 9｜反向测试

### 9.1 反向成“许可撤回但 x 暂存”

```text
刘邦宣布收回兵权
→ 但韩信仍掌印符
→ 诸将仍只听韩信
→ 军队仍由韩信稳定调用
= 上位许可变化，但旧 x 现实控制暂存
```

这正是与刘备荆州案例的核心差异。

### 9.2 反向成 zx

```text
刘邦试图收回旧军权
→ 韩信公开抵抗
→ 反而把更多诸将 / 军队纳入自身决定范围
→ 汉廷或现实秩序被迫承认新增韩信接口
= 才继续检查 zx
```

史文没有这种结构。

### 9.3 反向成纯 nx 执行

如果韩信从来没有真实军队调用权，只是代传刘邦逐项命令，那么旧阶段就不应先锁 `x`。

史文“夺其印符”“易置诸将”“夺两人军”本身反证旧现实控制确实存在。

## 10｜最近邻排除

### nx vs x

- `nx`：上位任务 / 最终授权接口来自刘邦；
- `x`：当前具体军队、诸将、军令凭据是否已经进入韩信稳定调用边界。

两者可以分层同时存在。

### x vs zx

- `x`：已有军权正常调用；
- `zx`：把决定范围公开继续推大。

本轮恰好是 `x` 被回收，不是 `zx` 扩张。

### nx vs xn

新任务“击齐”由刘邦给出；韩信之后如何组织具体战役可以另查 `xn`，不能用他的军事谋略倒写当前上位任务来源。

### 授权撤回 vs 现实控制退出

本轮最重要：

> **撤回是否传导到 x，必须看现实调用接口有没有被切断。**

不能只看诏令、名义或一句“收回”。

## 11｜第三因素冻结

冻结：

- 韩信军事能力；
- 韩信功劳大小；
- 刘邦是否猜忌韩信；
- 刘邦夺印符手段是否厚道；
- 后来韩信封齐王、楚王及最终结局；
- 对楚汉人物的道德评价。

本轮只看：

1. 旧军队是否真在韩信当前调用边界；
2. 更高节点是否真实拥有回收 / 重配接口；
3. 撤回时是否切断印符、诸将、军队调用；
4. 旧 `x` 是否因此实际退出；
5. 新任务是否另经上位接口重新建立。

答案为：是 / 是 / 是 / 是 / 是。

## 12｜严格 zx↔nx 补关系复核

不锁：

`strict_zx_nx_complement_locked: false`

本轮研究的是：

> **上位授权关系变化如何传导到已有局部 x。**

没有同时证明高纯 zx 与 nx 双端之间存在双向缺口修复，因此不能因为“韩信领兵 + 刘邦重新授兵”就拼成严格对子。

## 13｜与刘备荆州形成的最小差异

### 《三国演义》刘备荆州

```text
nx 借用许可被东吴撤回
↓
城池 / 驻军 / 粮草仍在刘备集团当前调用边界
↓
x 暂时继续
```

### 《史记》韩信修武

```text
更高军权授权被刘邦直接收回
↓
夺印符 + 召诸将 + 易置诸将 + 夺军
↓
现实调用接口同步被切断
↓
旧 x 退出
```

所以本轮可靠新增可以压成：

> **外部许可 / 授权撤回是否使既有 `x` 退出，不取决于“撤回”这个词本身，而取决于撤回节点是否真实切断主体对对象、资源、人员和调用凭据的现实接口。**

这是案例级边界控制；目前只有《三国演义》刘备与《史记》韩信这一组直接最小差异，不新建待审议，不修改正本。

## 14｜结论

正式锁定：

> **韩信在修武之前真实拥有局部军队控制 `x`；刘邦作为更高最终军政授权节点，不只撤回名义许可，而是通过夺印符、召诸将、易置诸将、夺两人军，实际切断旧军令接口，因此旧 `x` 真正退出。随后刘邦重新给韩信“收赵兵未发者击齐”的上位任务，形成新的 `nx` 任务入口；新兵力再进入韩信实际统率后形成新的局部 `x`。本窄阶段不锁 `zx`。**

最短机制：

```text
上位撤回
≠ 自动 x 退出

上位撤回
+ 现实调用接口被实际切断
→ 旧 x 退出

重新授权新任务
→ nx 新入口
→ 新局部 x 可重新形成
```
