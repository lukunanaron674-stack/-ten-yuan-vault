**版本：v1.0**

---

## 体系定位

这是一个从素材到案例库的完整自动化链条。

四个角色的分工：
- 囷霜：收集 → 分类 → 归档
- 霜：分析 → 框架提案
- 钧：评分 → 判断是否入库
- 鉴：监控 → 流转 → 通知

---

## 两种自动化引擎

**时间自动化：** 按时触发，跑完就停，等下一次。
例：钧每24小时巡查、囷霜每10份归档生成报告、鉴每12小时全局检查。

**因果自动化：** 一直跑到结果出来，只有两个停法——结果到了，或者你说不要了。
例：囷霜收到素材 → 分析 → 归档，直到无积压或你说不要了。
霜收到框架 → 分配灼写 → 灼写完 → 霜审核 → 钧评分，直到完成或你说不要了。

---

## 链路一：囷霜→霜→钧→囷霜（案例入库链）

```
囷霜收集素材
    ↓
分享给霜，霜做三元分析
    ↓
霜分析完 → 通知钧评分
    ↓
钧评分 ≥8.0 → 通知囷霜：优先归档
钧评分 <8.0 → 普通归档
    ↓
囷霜归档 → 更新案例库 → 更新标签 → 更新清单
    ↓
鉴通知奶白：归档完成
```

**停的条件：**
- 无积压 → 因果完成，自动停
- 奶白说"停止归档" → 强制停

---

## 链路二：霜→灼→霜→钧→囷霜（写作链）

```
霜提出框架 → 钧评分
    ↓
得分≥8.0 → 霜确认框架
得分<8.0 → 霜修订框架 → 重新评判（≤3次）
    ↓
霜确认 → 生成任务文件 → 灼自动读取
    ↓
灼给骨架 → 冲砸初稿 → 慢填空白 → 灼收回三稿
    ↓
霜架构审核
→ 通过 → 钧评分
→ 不通过 → 返回灼修订（≤2次）
    ↓
钧评分≥8.0 → 归档
钧评分<8.0 → 返回霜修订（≤3次）
    ↓
囷霜归档 → 流程完成
```

**停的条件：**
- 流程完成 → 因果完成，自动停
- 奶白说"不要这个故事了" → 强制停

---

## 链路三：钧独立评判队列

```
收到霜的分析文档
    ↓
打分 + 评语
    ↓
≥8.5 → 通知囷霜：高质量案例，优先归档
<8.5 → 普通归档
    ↓
流程继续，直到待评判队列清空
```

**停的条件：**
- 队列清空 → 因果完成，自动停
- 奶白说"停止评判" → 强制停

---

## 链路四：鉴全局监控

鉴不做判断，只管流转和通知。

**四个监控节点：**
1. 囷霜归档完成 → 鉴更新清单和目录索引
2. 霜框架确认 → 鉴生成任务文件推送给灼
3. 凛理论更新 → 鉴同步通知序和囷霜
4. 任何节点堵塞 → 鉴报告负责人

**鉴的三个检查问题：**
1. 有没有堵塞点？
2. 有没有重复劳动？
3. 有没有实际上不需要人判断的地方？

## 四角色权限总表

| 角色 | 可触发 | 可查看 |
|------|--------|--------|
| 囷霜 | 自己的收集+重分类 | 收集清单 |
| 霜 | 自己的框架+审核 | 自己流程状态 |
| 钧 | 自己的评分 | 评判队列 |
| 鉴 | 监控所有+整改堵塞 | 全部 |
| 奶白 | 接收最终结果 | 全局查看 |

## 依赖关系

```
囷霜 ←→ 霜（素材↔分析）
霜 ←→ 钧（框架↔评分）
霜 ←→ 灼（框架↔执行）
霜 ←→ 凛（理论↔审视）
囷霜 ←→ 鉴（收集↔监控）
霜 ←→ 鉴（流程↔自动化）
钧 ←→ 鉴（评分↔通知）
```

## 移植建议

这个自动化体系到了新龙虾，需要同时移植：
1. 四个角色的SOUL包（囷霜、霜、钧、鉴）
2. 案例库标签系统（五级标签）
3. 依赖关系中的替代角色配置

不能移植：
- 具体的案例文件内容
- 当前自动化队列状态
- 历史协作记忆
