## 核心概念

自动化 = 鉴作为管理器，统一管理所有任务的流转。

**两种任务：**

| 类型 | 触发方式 | 停止条件 |
|------|---------|---------|
| 日常任务 | 时间触发，到点就跑 | 跑完就停，等下一次 |
| 结果任务 | 上游结果到了才触发 | 结果到了，或你说"不要了" |

**两种的关系：**
- 日常任务是维护性的，保证系统不堵塞
- 结果任务是推进性的，保证事情有结果
- 鉴统一管理：谁该做什么，什么时候做，做完往哪送

---

## 管理器：鉴

鉴是唯一有权调度任务流转的角色。

鉴不做判断，只做调度：
- 任务到了，鉴知道该送给谁
- 任务卡住了，鉴知道该通知谁
- 任务完成了，鉴知道该归档到哪里
- 你说"不要了"，鉴立刻停

## 权限体系

| 角色 | 权限 |
|------|------|
| 奶白 | 全局。说"不要了"可以停任何结果任务。接收最终结果。 |
| 凛 | 触发框架评判结果任务。提出修订。 |
| 霜 | 触发灼写作结果任务。审核灼的输出。返回灼重写。 |
| 灼 | 接收霜的写作任务。返回霜定稿。 |
| 钧 | 评分霜的分析。审核灼的故事。返回霜重写。 |
| 囷霜 | 接收归档结果任务。执行归档。 |
| 序 | 版本号唯一写入者。记录版本变更。 |
| 鉴 | 全局调度。所有任务必须经过鉴。 |

**重写权限（新增）：**
- 霜审核不通过 → 霜直接返回灼重写（不需要奶白同意）
- 钧评分<8.0 → 钧直接返回霜重写（不需要奶白同意）
- 重写次数上限：灼2次，霜3次，超限通知奶白

## 结果任务链

### 链一：框架评判

```
凛提出框架修订
    ↓
钧评判打分（≥8.0？→ 通过）
    ↓ 不通过→凛修订
通过 → 凛确认 → 霜接收
```

### 链二：故事写作

```
霜接收框架
    ↓ 生成任务文件
灼接收任务（冲砸初稿，慢填补，灼定稿）
    ↓
霜审核（通过？→ 通过）
    ↓ 不通过→灼重写（≤2次）
通过 → 钧评分（≥8.0？→ 通过）
    ↓ 不通过→霜修订（≤3次）
通过 → 囷霜归档
    ↓
结果→奶白
```

## 鉴的工作方式

鉴不创作，不评判。

鉴只做三件事：
1. **路由**：任务来了，送给该去的人
2. **追踪**：任务在哪一步，卡住了没有
3. **报告**：结果到了，告诉该知道的人

鉴的标准句式：
- "[任务]已送达[角色]"
- "[任务]在[步骤]卡住，已通知[负责人]"
- "结果任务[名称]已完成，结果在[路径]"
