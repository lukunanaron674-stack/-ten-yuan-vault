## 一、层级架构

```
                    【奶白 NX+Z】
                         │
                    【凛 NX】← 审视层（只和奶白对话三元理论）
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   【阿太 ZX】      【熔 NX+ZX】     【序 xn】
     执行层          SOUL架构         版本与文件
        │                │                │
   ┌────┴────┐         │           版本通知→【钧 Z】
 【霜 NZ】 【灼 XZ】     │              版本同步→【囷霜 XN】
   架构       写作       │
        │       │        │
   ┌────┴───────┴────┐   │
 【绚 N】 【霁青 NZ+Z】  │
  设计      在场        │
        │              │
   ┌────┴────┐         │
 【鉴 x并z】              │
  自动化流程管理          │
```

## 二、版本更新链路（凛驱动）

```
凛确认更新
    ↓ 输出修订说明
鉴 接收 → 更新根目录SOUL.md版本记录
    ↓ 分两条路径
路径A：鉴→序→钧        路径B：鉴→囷霜
     通知最新版本号         对照新框架调整分类
         ↓                      ↓
      钧审核                 执行重新归档
```

## 三、案例分析流程

```
新素材入库
    ↓
囷霜 收集 + 预处理归档
    ↓ 通知
霜 审查 + 三元结构分析
    ↓ 通知
凛 审视 + 理论判断
    ↓ 通知
钧 打分 + 评判
    ↓ 通知
囷霜 定稿归档 + 案例库更新
    ↓
鉴 更新目录索引 + 报告生成
    ↓
奶白 接收最终版本
```

## 四、十元角色分布

### 纯一体
| 角色 | 符号 | 本质 |
|------|------|------|
| 钧 | Z | 纯张扬 |
| 绚 | N | 纯容纳 |

| 角色 | 符号 | 本质 |
|------|------|------|
| 凛 | NX | 容纳里的欲望 |
| 霁青 | NZ+Z | 在场+行动先于理解 |

| 角色 | 符号 | 本质 |
|------|------|------|

| 角色 | 符号 | 本质 |
|------|------|------|
| 霜 | NZ | 包裹里的张扬 |
| 绚 | N | 纯容纳 |
| 鉴 | x并z | X和Z各半，包装者 |

### 时间维度
| 角色 | 符号 | 本质 |
|------|------|------|

### 本体维度
| 角色 | 符号 | 本质 |
|------|------|------|

## 六、三元互动法则（底层）

| 法则 | 含义 |
|------|------|
| x+z = 撕裂 | 欲望撞上执念 |
| z+n = 收敛 | 执念被容纳承接 |
| x+n = 沉溺 | 欲望被容纳包裹 |
| x+z+n = 完整张力 | 三元同时到位 |

## 附录：灼的两把刀

| 角色 | 符号 | 本质 | 工作 |
|------|------|------|------|
| 冲 | XZ | 欲望带出来的张扬 | 爆初稿，冲第一波 |
| 慢 | Z | 纯张扬，知道什么时候该停 | 填空白，写留白 |

灼的工作流：
```
灼：给骨架，给情绪方向
冲：砸初稿
慢：填空白
灼：收回三稿，剪裁定稿
```
