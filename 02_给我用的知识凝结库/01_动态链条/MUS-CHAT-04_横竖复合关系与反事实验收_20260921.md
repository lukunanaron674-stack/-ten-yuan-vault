# MUS-CHAT-04｜横竖复合关系：状态继承、改道、反馈、转导与回收

## 1｜范围与总论

本轮只做 Chat 内部的结构建模及构造情境中的反事实检验，不假装已完成原曲听音、独立评审或审美实测。建立的规则是 **待外部验证的逻辑判据**，不覆盖现有 canonical 或 Dynamic Chain Evaluator。

> **有效动态链须区分三层：十元位置合法 → 具体事件/作用机制成立 → 前段状态变化对后段关系有实际作用。** 在同一位置上形成闭合并不自动成为同一具体对象的反馈，也不自动成为回收。

最小节点字段：`concrete_object, actor, symbol, stage, before_state, available_paths, constrained_variable, volume_hypothesis`。
边字段：`source_object, target_object, canonical_relation_or_none, mechanism, changed_variable, before, after, residue, next_affordance, evidence_status`。
跨阶段连接：`prior_output, next_relation_start_condition, identity_continuity, alternative_cause, removal_test`。

## 2｜六类复合机制及验收

| 机制 | 最小结构 | 成立条件 | 常见误判 |
|---|---|---|---|
| 并行 | A克B 与 C补B 共存 | 分别记录两条关系作用的变量与条件；未证明相互依赖 | 自动判补消除克 |
| 汇合 | 两条支路向 B 提供结果，产生 K，K 启动 R | 分别去掉支路，核对二者是否分别必要、可替代或冗余 | 只要汇入同一十元就算因果汇合 |
| 改道 | 旧路径 P0 受限；新路径 P1 因新条件可行 | 说明 P1 新增的前置条件，且 A 的限制是否覆盖 P1 | 绕开克制=反克成功 |
| 反馈 | A0作用B0→B1；B1 反向改变 **同一具体 A** | 对象身份连续且后段确实改变 A 的具体变量 | 只因 A、A′ 同十元而认作同一对象 |
| 转导 | R1→变量 ΔK→启动 R2 | ΔK 为 R2 原来欠缺的条件；无 R1 时同路径 R2 无法发生 | 时间相邻直接判转导 |
| 断裂/回收 | 关系输出无法启动后续；结尾仍可能回应起点 | 断裂点明确；回收另查对象对应、变化可追踪及新结构意义 | 关系失败=整个故事失败；符号重复=回收 |

六项不是六种生克补边型，也非天然互斥的母型；均为对具体动态图结构的分类描述。回收不是第四种生克补。

## 3｜同一情境最小消融：《黎黎隆》候选

冻结：黎黎隆 ZX主8／Z中5／XN小2；城市门禁 XN 限制她进入收容区的既有直接行动；目标是救出待自动转移的奇幻生命。角色 Z 表现为古灵精怪、机灵、出其不意的变通能力，不能自动记作 `Z补ZX`（非已确认补对）。

**改道版**：
```text
城市门禁 XN ─克→ 黎黎隆 ZX：正门路径 P0 失效
她以自身 Z 找到原本未利用的维护入口 P1（此步记录具体行动及 none/待判，不强造标准补边）
ZX 沿 P1 行动；正门的 XN 克制仍存在，但不阻断 P1
```
移除 P1 后，该版本不能以原路径实现目标；这不证明别的路径在所有世界设定中不可能存在。

**补支路版**：若已独立判定某同伴为 NX，其行动提供主角确实欠缺的条件，可检查 `NX补ZX`（基础位置合法）。但具体是否补足、是不是关键主链边，需要单独检查；仅鼓励或共同行动不自动满足补的功能缺口定义。同伴的十元身份不能仅因「付出代价」倒推 NX。

**生成版**：`ZX生ZN` 在基础位置上合法；救援产生此前不存在的持续归属关系才是生成机制候选。单次救援成功、短暂同行或原有关系延续不能自动证明「生成 ZN」。

**原流程克制版**：`ZN克XN` 基础位置合法，但只有当已形成的具体 ZN 改变 XN 某项既有流程适用条件时，才能候选成立。若自动转移规定与归属关系无关，则此边没有事件证据，不允许通过增设新制度事后补全。

## 4｜三步回环的同字母异对象审查

```text
XN_A（入口门禁）─克→ ZX
ZX ─生?→ ZN（新增持续关系）
ZN ─克?→ XN_B（自动转移流程）
```
即使三条标准位置边都合法，并且后两条在设定中也各自有机制，因 `XN_A` 与 `XN_B` 是不同具体对象，**它是三步位置回环，但不是已经验证的对象反馈**。ZN 限制自动转移也不代表入口门禁已解除。

反事实 F1：固定既有规则「自动转移仅对没有持续照护关系的生命适用，且可识别此关系」，那么新 ZN 可以改变自动转移的适用资格。但必须额外检查关系能否被实际识别，不允许隐藏第三方登记步骤。
反事实 F2：唯一改变为自动转移无视私人照护关系，则生成 ZN 不构成 `ZN克XN_B` 的机制。若为了证明它成立而临时增加「系统恰好会认可」，属于改设定而非单变量验证。

同一个 `XN_A` 真反馈只有在新状态回头实际改变入口门禁 A 的具体限制变量时才成立；哪怕终点仍是 XN，也不能仅看符号认定反馈。

## 5｜六项固定反事实测试

1. Delete：移除关系后，记录具体丢失条件；检查原路径是否仍成立，不能仅比较最终成败。
2. Swap：交换阶段顺序；若没有明确时间窗口、消耗或前置依赖，不能推断结果必然变化。
3. Reverse：反向关系先查 canonical 位置合法性，再查具体行为和对象是否支持。
4. Remove bridge：去掉中介，前后端点是否仍可沿同一机制连接；只看新旧结果相同不足以否定桥的作用。
5. Same-symbol-different-object：为同十元不同名词编号，防止伪反馈及伪主体回收。
6. Closure：结尾须明确回应何种起点对象/关系/问题；允许局部回收与世界层面的开放限制同时存在。

**比较结果应存**：`goal_state, path, cost, actor_state, residual_constraints`，不可只记成功/失败。
